# 写作规范（STYLE.md）—— 所有章节作者（含 AI 代理）必须遵守

> 本文件不属于书稿（不在 src/ 下、不进 SUMMARY），仅供撰写时统一风格。

## 1. 读者与定位

- 读者：**机器视觉零基础的小白**，但目标是成为**专家级**开发者。
- 书名：《用 Rust 玩转机器视觉：从入门到精通》。
- 语言：**简体中文**正文；代码注释用中文；专业术语**首次出现**给通俗解释 + 英文原词，例如"卷积（convolution）"。
- 语气：像一位耐心、幽默的师兄带你入门。多用**生活化类比**，先讲直觉再上公式。绝不上来堆术语吓人。
- 硬约束：**纯 Rust 生态，禁止使用 OpenCV / `opencv` crate**。凡是纯 Rust 生态暂缺的能力，要**诚实说明**并给替代方案（自己实现 / 用 ONNX 模型推理 / 等）。

## 2. 每章统一结构

每章替换对应的占位文件（保留第一行 `# 第 N 章 ……` 标题，不要改章号/标题文字）。正文按以下骨架：

1. **本章导读**（开头，用引用块）：一句话说明"学完能做什么"，列 2–4 个要点。
2. **场景引入**：用一个真实场景/问题把读者带进来（例："监控画面里怎么自动数有几个人经过？"）。
3. **原理讲解**：先直觉类比 → 再图示（ASCII 图 / 表格 / 文字示意）→ 最后必要的公式。公式用 MathJax：行内 `\\( ... \\)`，独立 `\\[ ... \\]`。
4. **动手写代码**：给**完整、可运行**的纯 Rust 示例。标出所需 `Cargo.toml` 依赖、如何运行；关键行有注释。优先用**代码合成输入图**（渐变/几何图形/噪声）使示例自包含；若需外部图，用占位路径 `assets/xxx.jpg` 并提示读者替换。
5. **常见坑与提示**：用引用块，emoji 开头（见 §4）。
6. **本章小结**：`## 本章小结`，bullet 回顾要点。
7. **动手练习**：`## 动手练习`，2–4 个由易到难的题，鼓励读者上手。
8. （可选）**延伸阅读 / 下一章预告**。

## 3. 深度与篇幅

- 每章要**充实、具体、有例子**，宁深勿浅。正文目标约 1500–3500 字中文（含代码），概念重的章可更长。
- **拒绝灌水**：不要空泛地重复"很重要""很强大"。每个论点配例子、代码或数字。
- 由浅入深：入门章重直觉与能跑通；进阶章可加原理推导、性能与工程权衡。

## 4. 排版约定（务必一致）

- 标题：章 `#`；节 `##`；小节 `###`。
- 代码块语言标注：Rust 用 ` ```rust `，命令行用 ` ```bash `，配置用 ` ```toml `，输出/示意用 ` ```text `。
- **提示框统一用「引用块 + emoji」**（不要用 `> [!NOTE]` 语法，保持全书一致）：
  - `> 💡 **提示**：……`（有用的小技巧）
  - `> ⚠️ **注意**：……`（容易出错/需要小心）
  - `> 🕳️ **坑**：……`（真实踩过的坑）
  - `> 📖 **术语**：……`（术语解释）
- 行内代码用反引号：函数名、类型名、文件名、命令、crate 名。
- 章节间交叉引用用**相对路径**链接，例如：见 [第 15 章 边缘检测](../p03-classic/ch15-edges.md)。
- 图：本书不内嵌二进制图片。需要图示时用 ASCII 图 / 表格 / 文字描述；确有必要可在 `assets/` 放 **SVG**。

## 5. 代码质量红线

- **只用纯 Rust crate**。核心依赖版本以 `API_NOTES.md` 为准，不要臆造版本号。
- **不要编造不存在的函数/类型/字段**。image、imageproc 的 API 一律以 `API_NOTES.md` 的签名为准；拿不准就用 `API_NOTES.md` 里列出的确定 API。
- 代码应能编译通过（`cargo check`）。示例应给出可运行入口（`fn main` 或 `cargo run --example`）。
- 深度学习/推理章：若 crate（candle/burn/tract/ort）接口可能随版本变动，**在代码前注明所依据的版本**，并以"讲清结构与思路 + 尽量真实的 API"为准；不确定处宁可写清"当前版本大致如此，具体以官方文档为准"，也不要瞎编能跑但错误的 API。

## 6. 一致的示例与命名

- 配套代码工程在仓库 `code/`（crate 名 `cv_examples`），依赖已配置。正文中"如何运行"可写 `cargo run --example chNN_xxx`（示例文件可选择性提供）。
- 术语中英统一（详见附录 C）：图像 image、像素 pixel、通道 channel、卷积 convolution、特征 feature、目标检测 object detection、分割 segmentation、关键点 keypoint、跟踪 tracking、标定 calibration……
- 变量/函数命名遵循 Rust 习惯（snake_case），类型 CamelCase。

## 8. mdbook 渲染坑（实测，务必避开）

本书 `book.toml` 开启了 `mathjax-support` 与 `smart-punctuation`，据此有两条硬规则：

- **公式尽量写成单行。** display 数学块 `\\[ ... \\]` 里如果**某一行只有一个 `=`**（等号顶格独占一行），CommonMark 会把它误当成 setext 一级标题，公式就崩了。把多行公式压成一行，或用 `\begin{cases}`/`\begin{aligned}` 包起来。
- **数学里不要出现裸的单引号 `'`。** `smart-punctuation` 会把 `'` 变成弯引号 `’`，破坏 `f'`、prime 等记号。需要"撇号/导数"时改用 `u, v, w`、下标或 `\prime`，别直接敲 `'`。
- 提示框用连续多个 `>` 引用块时，块之间留一个空行即可正常渲染成独立小框（markdownlint 的 MD028/MD032 是误报，忽略）。
