# 全书写作规范（Writing Guide）—— 写作子任务必读

> 你正在参与写一本书：《机器视觉工程实战：用 Rust 看懂图像与模型》。
> 这份文件是**全书统一规范**。你负责其中的某一章，必须严格遵守这份规范，
> 你写的章节才能和其他章节风格一致、拼成一本连贯的书。**动笔前先完整读一遍。**

---

## 1. 读者画像（写给谁）

- 会**基础 Rust**：能写函数、结构体、`enum`，看得懂 `Result`/`Option`、所有权与借用。
- 但机器视觉**完全零基础**：不知道一张 JPG 在内存里长什么样，没听过 NMS、letterbox、ONNX、卡尔曼滤波。
- **不懂**线性代数和深度学习理论。凡是用到数学（均值、方差、矩阵乘、Softmax、IoU 等），都要**先打生活比喻，再用一组小数字手算一遍**给读者看。
- 目标是**从入门到精通**，且是**工程视角**（部署/推理侧，不是训练侧）。

## 2. 语言与语气

- 简体中文，通俗易懂，**多打生活化比喻**（第 1 章的"人眼→相机、大脑→算法"就是范例）。
- **工程第一**：讲"真实项目里怎么做"、"为什么这么做"、"新手常踩什么坑"、"上线代码会怎么优化"。
- 英文术语**首次出现**给中文解释，例如："letterbox（等比缩放后用灰边填充到目标尺寸）"。
- 不啰嗦、不喊口号。每讲一个概念，都配一个**具体例子**或一段**可运行的小代码**。

## 3. 每章统一结构（务必遵守）

1. 一级标题：`# 第 N 章 · 标题`，必须和 `SUMMARY.md` 里的文字**完全一致**。
2. 紧跟一段**本章导读**引用块：`> **本章导读**：……`，说明本章解决什么问题、读完能做什么。
3. 正文用 `## N.1`、`## N.2` …… 编号小节（N=章号）；需要时再用 `### ` 三级标题。
4. 倒数第二节固定为 `## N.x 小结`，用 3~6 条 bullet 概括本章要点。
5. 最后一节固定为 `## N.y 练习`，给 2~4 道动手练习（难度适中，能让读者发现"以为懂了其实没懂"的点）。
6. **衔接**：开头可以呼应上一章，结尾可以预告下一章，让全书像一条线。

## 4. 排版规范

- 对比、参数表、映射关系**优先用 Markdown 表格**。
- 流程、系统结构、数据流、内存布局用 ```text``` 代码块画 ASCII 图（参考第 1 章的画法）。
- Rust 代码用 ```rust```；shell 命令用 ```bash```；张量形状/程序输出/示意用 ```text```。
- 重要术语**首次出现加粗**。
- 数学可用 MathJax（行内 `$...$`，独立 `$$...$$`），但永远先"打比方 + 小数字演算"，再上公式。

## 5. 代码规范

- **Rust 2021 edition**。代码优先"**看得懂**"，其次才是性能；关键行加简短中文注释。
- 完整示例尽量带 `use`；很长的示例可省略样板，但要用文字说明省略了什么。
- 工程优化（零拷贝、SIMD、并发、错误处理）在合适处用"**工程上通常会……**"点一句，不喧宾夺主。
- 涉及的 crate（版本以读者 `cargo add` 拉到的最新为准，正文不纠结小版本号）：

  | crate | 用途 |
  | --- | --- |
  | `image` | 读写 JPG/PNG，基础图像操作 |
  | `ndarray` | 多维数组（张量），Rust 版 NumPy |
  | `imageproc` | 图像算法（画框、滤波、边缘、轮廓） |
  | `fast_image_resize` | 高性能缩放 |
  | `tract-onnx` | 纯 Rust 的 ONNX 推理引擎 |
  | `ort` | ONNX Runtime 的 Rust 绑定（性能更强，支持 GPU/NPU） |
  | `opencv` | OpenCV 的 Rust 绑定（视频解码、丰富算法），编译重，可选 |
  | `nalgebra` | 线性代数（卡尔曼滤波等可用） |

## 6. 贯穿全书的例子与统一约定（**极重要，所有章节共用**）

- **主线任务**：目标检测（"一张照片/一帧里有哪些物体、在哪"），后半程逐步扩展到**视频分析**（跟踪 + 业务过滤器 + 多模型协同）。
- **主模型**：**YOLOv8 风格检测器**。输入张量 `1×3×640×640`（RGB、像素值归一化到 `0~1`、经过 letterbox）；输出张量 `float32[1, 84, 8400]`（84 = 4 个框坐标 + 80 个类别分数，8400 个候选）。**第 1 章已经这么设定，务必保持一致。**
- **类别**：COCO 80 类。举例够用即可：`person=0`、`bicycle=1`、`car=2`、`cat=15`、`dog=16`。
- **坐标约定**：后处理最终还原到**原图像素坐标**；边界框统一用**左上角-右下角** `(x1, y1, x2, y2)`。
- **统一核心数据类型**：凡涉及这些概念，**复用下面的同名同字段结构体**，不要另起炉灶换名字：

```rust
/// 边界框：左上-右下像素坐标
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct BBox {
    pub x1: f32,
    pub y1: f32,
    pub x2: f32,
    pub y2: f32,
}

/// 一个检测结果
#[derive(Clone, Debug)]
pub struct Detection {
    pub bbox: BBox,
    pub score: f32,      // 置信度 0~1
    pub class_id: usize, // COCO 类别号
}

/// 带跟踪 ID 的目标（第 21 章起使用）
#[derive(Clone, Debug)]
pub struct Track {
    pub id: u64,
    pub bbox: BBox,
    pub class_id: usize,
    pub score: f32,
}
```

- `BBox` 常用方法（需要时可复用或扩展，命名保持一致）：`width()`、`height()`、`area()`、`center() -> (f32, f32)`、`iou(&self, other: &BBox) -> f32`。

## 8. 跨章引用规则

- 引用别章写"（详见第 N 章）"或"第 N 章会讲到"，用上面的新编号，**不要**用任何旧编号。
- **不要**大段重复别章的核心内容，点到为止 + 指路即可。
- 如果本章要用到"上一章造好的东西"，直接假设它已存在并复用统一类型（第 6 节），不必重新推导。

## 9. 篇幅要求

- 每章正文要**充实、面面俱到**，通常相当于 200~400 行 Markdown（检测、跟踪、实战等大主题可以更长）。
- **宁可详细，不要空泛**：每个知识点都要落到"是什么→为什么→怎么做（代码）→坑在哪"。
- 附录可以短小精悍，够查即可。
