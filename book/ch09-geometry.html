机器视觉工程实战：用 Rust 看懂图像与模型

第 9 章 · 几何变换：缩放、旋转、仿射与透视

本章导读：第 7、8 两章我们一直在“改像素的值“——降噪、锐化、找边缘、做形态学，像素始终待在原地。本章换一个维度：不动像素的值，只把它搬到新位置，这就是几何变换。你会先搞懂缩放绕不开的“插值“（并亲手算一遍双线性），再顺着“平移 → 旋转 → 仿射 → 透视“一路加码，直到能把“拍歪的车牌/文档掰正“。这些正是喂给模型前最常做的空间操作；其中“等比缩放 + 补边“的 letterbox 是重中之重，本章打好地基，第 10 章把它拼成完整的预处理流水线。

学习目标：

  • 分清“改像素值“（滤波，第 7、8 章）与“改像素位置“（几何变换，本章）两类操作
  • 说清最近邻 / 双线性 / 双三次三种插值的取舍，并能手算一次双线性
  • 会用 image 的 resize 选不同 FilterType、用 imageops 做翻转与整数倍旋转
  • 看懂仿射（2×3）与透视（3×3）矩阵，知道透视比仿射“多“了什么，会用 4 点做透视矫正
  • 理解为什么实现都用“反向映射“，并用 imageproc、fast_image_resize 落地

9.1 几何变换是什么：把像素“搬家“

前两章的滤波、边缘、形态学，本质都是改像素的值：一个像素还待在 (x, y) 这个格子里，只是亮度从 120 被算成了 95。几何变换（geometric transformation）反过来——像素的值不变，改的是它所在的位置：

滤波 / 边缘 / 形态学（第 7、8 章）：位置不动，值改变
    (x, y) 的值 120  ──►  (x, y) 的值 95      像素原地不动，亮度被改写

几何变换（本章）：值不动，位置改变
    (x, y) 的值 120  ──►  (x', y') 的值 120   同一个值，搬到了新坐标

所有几何变换，说到底都是一个坐标映射：告诉你原图的点 (x, y) 应该搬到输出的哪个位置 (x', y')。缩放、平移、旋转、仿射、透视，区别只在这个映射的“公式“长什么样——从最简单的“坐标乘个倍数“，到最复杂的“矩阵乘完还要做除法“。本章就沿着这条由简到繁的线走一遍。

搬家会带来一个滤波从没遇到过的新麻烦：像素搬到新位置后，坐标常常不再是整数（比如落在第 2.3 列、第 1.7 行），可屏幕上只有整数格子。这个“两格之间的值到底填多少“的问题，就是插值，也是缩放绕不开的第一道坎。

9.2 缩放与插值：新像素的值从哪来

缩放（resize）就是把图放大或缩小。放大好比把一张邮票印成海报——原图没那么多像素，中间“凭空多出来“的格子，值从哪来？缩小则相反，好几个原像素要挤进一个格子，留谁？答案都是插值（interpolation）：根据周围已知的像素，猜出中间位置该有的值。

具体地说：放大 2 倍时，输出第 4 列的像素，反算回原图大约在第 2 列；输出第 5 列反算回原图在第 2.5 列——落在原图第 2、3 列之间，没有现成的值。怎么猜，就分出了三种常用算法：

  • 最近邻（nearest neighbor）：四舍五入到最近的整数格，直接抄那个像素的值。最快，但放大后一格一格的，边缘有明显马赛克 / 锯齿。
  • 双线性（bilinear）：取周围最近的 4 个像素，按“离得近权重大“加权平均。质量与速度的平衡点，工程默认选它。
  • 双三次（bicubic）：取周围 16 个像素，用三次曲线拟合，过渡更平滑、边缘更锐利，但更慢。

手算一次双线性

双线性是最该吃透的一个。假设缩放后，输出某个像素反算回原图的位置是 (x=2.3, y=1.7)（第 2.3 列、第 1.7 行，落在四个整数像素正中间）。它周围最近的 4 个像素（用灰度值方便手算）是：

          列2       列3
 行1    Q11=10    Q21=20
 行2    Q12=30    Q22=40

小数部分： dx = 2.3 − 2 = 0.3    （离左边"列2"有多远）
           dy = 1.7 − 1 = 0.7    （离上边"行1"有多远）

双线性 = 先横着插两次，再竖着插一次：

第 1 步 横向（上、下两行各插一个值）：
    上行 top = Q11 + dx·(Q21 − Q11) = 10 + 0.3×(20−10) = 13
    下行 bot = Q12 + dx·(Q22 − Q12) = 30 + 0.3×(40−30) = 33

第 2 步 纵向（在 top 与 bot 之间插）：
    结果 = top + dy·(bot − top) = 13 + 0.7×(33−13) = 13 + 14 = 27

也可以写成“四邻居加权“的等价形式（每个权重就是它对角那块小矩形的面积，四个权重加起来正好等于 1）：

$$ \text{result} = (1{-}dx)(1{-}dy),Q_{11} + dx(1{-}dy),Q_{21} + (1{-}dx),dy,Q_{12} + dx,dy,Q_{22} $$

$$ = 0.7{\times}0.3{\times}10 + 0.3{\times}0.3{\times}20 + 0.7{\times}0.7{\times}30 + 0.3{\times}0.7{\times}40 = 2.1 + 1.8 + 14.7 + 8.4 = 27 $$

两种算法结果一致，都是 27。直觉检验一下：dy=0.7 更靠近下面那行（值 30、40），所以结果 27 明显偏向下行——合理。这就是双线性“越近权重越大“的朴素含义。

三种插值怎么选

插值算法参考邻居数速度质量典型用途
最近邻1最快有锯齿/马赛克掩码/标签图缩放（不能“混色“）、极致提速
双线性4快平滑，够用模型预处理默认、实时视频
双三次16慢更锐利平滑出图、对画质敏感的离线处理

插值好坏为什么影响模型精度

预处理里的缩放插值，直接改写了喂给模型的每一个像素值——它不是“无所谓的小细节“。两个常见的坑：

  • 训练和推理用了不同插值：训练时用双线性、上线推理时图库用了最近邻，喂进模型的像素分布就和训练时对不上，检测框会莫名偏移、置信度掉点。经验法则：推理侧的插值方法尽量和训练时保持一致（通常是双线性）。
  • 下采样时用了太糙的插值：把一张 4K 图缩到 640，最近邻会直接“跳采样“，产生锯齿和摩尔纹，把远处小车、小人脸这类小目标的细节抹掉——而小目标本来就最难检。缩小场景优先双线性甚至 Lanczos。

这是“预处理不一致“这个大坑最常见的来源之一，第 10 章会系统展开。先记住结论：插值不是随便选的。

用 image 的 resize 试遍四种插值

image 的 DynamicImage::resize 用 FilterType 选插值算法，一次把四种都存出来对比：

use image::{open, imageops::FilterType};

fn main() -> anyhow::Result<()> {
    let img = open("test.jpg")?;   // DynamicImage

    // 同一张图缩到 320×320 的盒子里，换不同插值各存一张对比
    let cases = [
        ("nearest",  FilterType::Nearest),    // 最近邻：最快，放大后马赛克/锯齿
        ("bilinear", FilterType::Triangle),   // 双线性：速度与质量的平衡点，最常用
        ("bicubic",  FilterType::CatmullRom), // 双三次：更锐利平滑，慢一些
        ("lanczos3", FilterType::Lanczos3),   // 高质量：最慢，缩小时细节最好
    ];
    for (name, filter) in cases {
        // resize 是"等比"缩放：结果塞进 320×320 且不变形（可能一边不足 320）
        let out = img.resize(320, 320, filter);
        out.save(format!("resize_{name}.png"))?;
    }

    // 若强行拉伸到精确尺寸（会变形：圆被压成椭圆），用 resize_exact
    img.resize_exact(320, 320, FilterType::Triangle).save("stretch.png")?;
    Ok(())
}

注意 image 的命名：Triangle 就是双线性、CatmullRom 是一种双三次。放大一张小图分别看 nearest 和 lanczos3，锯齿差异一目了然。

9.3 裁剪、翻转与旋转

有些几何操作根本不需要插值，因为像素只是“整格搬家“，落点仍是整数格——这类操作无损且极快：

  • 裁剪（crop）：抠出感兴趣区域（ROI），本质是坐标平移一下、范围外丢掉。第 3 章的 crop_imm 已经见过，抠图、数据增强常用。
  • 翻转（flip）：水平镜像就是 x' = w−1−x，垂直翻转就是 y' = h−1−y。训练时“左右翻转“是最常用的数据增强。
  • 90° 整数倍旋转：rotate90/180/270 也只是像素重排，无损。
use image::{open, imageops};

fn main() -> anyhow::Result<()> {
    let img = open("test.jpg")?.to_rgb8();   // RgbImage

    // 下面几个只是把像素重新排位置，不插值 —— 无损、极快
    imageops::flip_horizontal(&img).save("flip_h.png")?; // 左右镜像（增强常用）
    imageops::flip_vertical(&img).save("flip_v.png")?;   // 上下翻转
    imageops::rotate90(&img).save("rot90.png")?;         // 顺时针 90°
    imageops::rotate180(&img).save("rot180.png")?;
    Ok(())
}

任意角度旋转就没这么便宜了。把一张照片钉在桌面上转 15°，想象每个像素沿着一段圆弧滑到新位置。要算新坐标，就得请出三角函数——绕原点旋转角度 $\theta$ 的公式是：

$$ x’ = x\cos\theta - y\sin\theta, \qquad y’ = x\sin\theta + y\cos\theta $$

不用背，直觉记法：“转动后的新横坐标，是原横、原纵各’贡献’一部分，贡献多少由 $\cos$、$\sin$ 决定。“拿 $\theta=90°$（$\cos90°{=}0,\ \sin90°{=}1$）快速验一下：点 $(1,0)$ 变成 $(0,1)$——原来在正右方的点，转到了正上方，对（数学习惯是逆时针；图像里 $y$ 轴朝下，看起来就是顺时针）。

任意角度旋转后，像素几乎必然落在非整数格 → 又要回到 9.2 的插值；而且转完四角会甩出画面、边角露出空白 → 需要指定“空白填什么颜色“。真正的旋转 API 放在 9.7 用 imageproc 演示。

9.4 仿射变换：一个 2×3 矩阵统一四件事

平移、缩放、旋转、错切（shear，把矩形推成平行四边形）看着是四件事，其实能被一个 2×3 矩阵统一表达——这就是仿射变换（affine transformation）。矩阵形式是：

$$ \begin{bmatrix} x’ \ y’ \end

\begin{bmatrix} a & b & c \ d & e & f \end{bmatrix} \begin{bmatrix} x \ y \ 1 \end{bmatrix} \quad\Longrightarrow\quad \begin{cases} x’ = a,x + b,y + c \ y’ = d,x + e,y + f \end{cases} $$

坐标末尾那个多出来的 1 是个小技巧（叫齐次坐标）：平移本来是“加法“，塞不进纯粹的“矩阵乘法“，补个 1 之后，c 和 f 就能承担平移量，于是加法也被装进了一次矩阵乘里（矩阵基础见附录 A）。四种基本变换的矩阵长这样：

变换[a b c] / [d e f]效果
平移 $(t_x, t_y)$[1 0 tx] / [0 1 ty]整体挪位置
缩放 $(s_x, s_y)$[sx 0 0] / [0 sy 0]放大缩小
旋转 $\theta$[cosθ −sinθ 0] / [sinθ cosθ 0]绕原点转
错切 $sh_x$[1 shx 0] / [0 1 0]推成平行四边形

手算一个“平移 + 缩放“

把“放大 2 倍，再向右移 5、向下移 3“打包进一个矩阵，就是 $s_x{=}s_y{=}2,\ t_x{=}5,\ t_y{=}3$：

$$ M = \begin{bmatrix} 2 & 0 & 5 \ 0 & 2 & 3 \end{bmatrix} $$

拿原图上的点 $(x{=}10,\ y{=}20)$ 代进去：

x' = 2×10 + 0×20 + 5 = 25
y' = 0×10 + 2×20 + 3 = 43

所以 $(10, 20) \to (25, 43)$。验证直觉：先缩放 2 倍得到 $(20, 40)$，再平移 $(+5, +3)$ 得到 $(25, 43)$，一次矩阵乘就把两步合成了——这正是“用一个矩阵统一表达“的威力。

仿射有两条重要的“守恒律“，记牢它俩就懂了仿射的能力边界：

  • 直线还是直线：变换前是直线，变换后仍是直线（不会弯）。
  • 平行还是平行：原本平行的两条线，变换后依然平行。

所以仿射能表达“正着拍的图“的任意缩放、旋转、错切组合，但表达不了“近大远小“——因为那会让平行的铁轨在远处汇聚，破坏“平行保平行“。想做到这一点，就得升级到透视。顺带一个有用的数字：仿射矩阵有 6 个可调参数（a~f），即 6 个自由度，所以用 3 组点对应就能唯一确定一个仿射变换。

9.5 透视变换：把“拍歪的矩形“掰正

站在铁轨正中间拍照，两条本该平行的铁轨会在远处汇聚到一个点（灭点）。仿射永远做不到这件事（平行保平行），**透视变换（perspective transformation，又叫单应变换 / homography）**可以。它用一个 3×3 矩阵，坐标同样补 1，但乘完得到的是三个数 $(X’, Y’, W’)$，最后要除以 $W’$ 才是真实坐标：

$$ \begin{bmatrix} X’ \ Y’ \ W’ \end

\begin{bmatrix} h_{11} & h_{12} & h_{13} \ h_{21} & h_{22} & h_{23} \ h_{31} & h_{32} & 1 \end{bmatrix} \begin{bmatrix} x \ y \ 1 \end{bmatrix}, \qquad x’ = \frac{X’}{W’}, \quad y’ = \frac{Y’}{W’} $$

透视比仿射“多“出来的，就是最后一行和那个除法。 仿射矩阵的最后一行永远是 [0 0 1]，所以 $W’$ 恒等于 1，那个除法等于没做，平行线自然保平行。透视的最后一行 [h31 h32 1] 里 $h_{31}, h_{32}$ 不为 0，$W’$ 就会随着 $(x, y)$ 变化——同一个物体在不同位置被除以不同的数，于是“近大远小“出现了，平行线也能汇聚。这个“随位置变化的缩放“，就是透视的全部魔力所在。

代价是自由度更多：透视有 8 个自由度（右下角归一化为 1），所以要 4 组点对应才能确定——这正好解释了为什么“矫正一个矩形“需要四个角点。核心套路是：

原图里"拍歪的矩形"(斜四边形)          想要的"正矩形"
        A′                             A────────B
       ╱  ╲                            │        │
      ╱    B′        ──掰正──►          │        │
    D′      ╲                          │        │
      ╲      C′                        D────────C
   量出 4 个角 (A′B′C′D′)          指定它们该落到 (ABCD)

指定“原图四角 → 输出四角“这 4 组对应，解出单应矩阵，再做变换，斜四边形就被拉成了正矩形。典型应用一大把：车牌矫正（斜拍的车牌掰正再送去识别）、文档 / 名片扫描（把桌上斜拍的 A4 拉成规整矩形）、二维码矫正、白板 / PPT 拍照矫正、球场“鸟瞰图“变换等等。具体代码见 9.7。

9.6 正向映射 vs 反向映射：为什么遍历输出像素

有了坐标映射公式，真要写代码搬像素，有两种方向，选错了输出会出“洞“。

正向映射（forward mapping）：遍历原图每个像素 (x, y)，用变换公式算出它去输出的哪个位置 (x', y')，把值搬过去。听起来最自然，却有两个致命问题：一是 (x', y') 通常是小数，落在输出两个格子中间，不知道该写进哪个；二是放大时输出格子比原图多，有些输出格子没有任何原图像素映射过来，就成了空洞（黑点、摩尔纹）。

反向映射（backward / inverse mapping）：反过来——遍历输出每个像素 (x', y')，用逆变换算出它在原图对应的位置 (x, y)，在原图那个（往往是小数的）位置插值取值填回来。

正向映射（遍历原图，把像素"抛"到输出）——放大 2 倍时：
    原图像素:   ●   ●   ●          每个 ● 抛到输出某处
    输出格子:  ● ○ ● ○ ● ○         中间的 ○ 没人抛过来 → 空洞

反向映射（遍历输出，回原图"取"值）——同样放大 2 倍：
    输出格子:  □ □ □ □ □ □          每个 □ 都问："我在原图对应哪？"
    原图位置:  取回后落在整数间 → 插值(9.2) → 每格都有值，绝不空洞

反向映射的好处是：每个输出像素都被访问且只被访问一次，绝不空洞；落在小数位置的问题，交给 9.2 的插值搞定。所以 OpenCV、image、imageproc 等几乎所有库，底层都用反向映射。这也解释了一个 imageproc 里“反直觉“的点（下一节就会遇到）：你传给 warp 的矩阵描述的是“输入 → 输出“的正向映射，但库内部会自动求逆、按反向映射采样。你只管按“我想把输入搬到哪“来描述变换即可（前提是变换可逆——仿射、透视矩阵都可逆）。

9.7 用 imageproc 做旋转、仿射与透视

imageproc::geometric_transformations 把上面几种变换都实现好了。核心是 Projection（一个 3×3 投影，仿射是它的特例）和 warp（按反向映射 + 插值真正搬像素）。Interpolation 选插值（Nearest / Bilinear / Bicubic），Border 指定越界处怎么填。

use image::{open, Rgb, RgbImage};
use imageproc::geometric_transformations::{
    rotate_about_center, warp, Border, Interpolation, Projection,
};

fn main() -> anyhow::Result<()> {
    let img: RgbImage = open("test.jpg")?.to_rgb8();

    // (1) 绕图像中心旋转任意角度：角度用弧度；越界处填黑；双线性插值
    let rotated = rotate_about_center(
        &img,
        15f32.to_radians(),          // 转 15°
        Interpolation::Bilinear,
        Border::Constant(Rgb([0, 0, 0])), // 转完四角露出的空白填黑
    );
    rotated.save("rotate15.png")?;

    // (2) 仿射：缩放 2 倍再平移 (+5,+3)。Projection 相乘 "P*Q = 先做 Q 再做 P"，
    //     所以 translate * scale 表示"先缩放、再平移"，正对应 9.4 手算的 (10,20)->(25,43)
    let affine = Projection::translate(5.0, 3.0) * Projection::scale(2.0, 2.0);
    let warped = warp(&img, affine, Interpolation::Bilinear, Border::Constant(Rgb([0, 0, 0])));
    warped.save("affine.png")?;

    // (3) 透视矫正：把原图里"斜四边形"的 4 个角，映射到输出里"正矩形"的 4 个角
    //     src = 拍歪的车牌/文档四角(左上,右上,右下,左下)，按你的图实测坐标填
    let src = [(120.0, 80.0), (520.0, 130.0), (500.0, 360.0), (90.0, 300.0)];
    let (rw, rh) = (400.0, 130.0);                  // 想要的正矩形尺寸
    let dst = [(0.0, 0.0), (rw, 0.0), (rw, rh), (0.0, rh)];
    // from_control_points 解出单应矩阵：把 src 四点映射到 dst 四点(输入->输出)
    let h = Projection::from_control_points(src, dst).expect("四点不共线才有解");
    let rectified = warp(&img, h, Interpolation::Bilinear, Border::Constant(Rgb([0, 0, 0])));
    // warp 输出尺寸与原图相同，正矩形落在左上角，用 crop 抠出那块即可
    let doc = image::imageops::crop_imm(&rectified, 0, 0, rw as u32, rh as u32).to_image();
    doc.save("rectified.png")?;
    Ok(())
}

几个工程要点：warp 的第二个参数（Projection）表达的是“输入 → 输出“，库内部自动求逆做反向采样（呼应 9.6）；from_control_points(from, to) 正是“给 4 组角点对应、解单应矩阵“的一步到位写法，是车牌 / 文档矫正的主力；Border::Constant 之外还有 Replicate（复制最边缘像素）和 Wrap（平铺重复），按需要选。

9.8 高性能缩放：fast_image_resize

缩放是预处理里最耗时的步骤之一——一张 4K 图缩到 640×640，通用实现并不快；视频每秒几十帧时，这点开销会被放大。fast_image_resize（常简称 fir）用 SIMD 指令专门优化缩放，往往比通用实现快好几倍到十几倍，是上线代码的常客。它不认识“图片“，只吃裸字节，所以要手动把 RgbImage 的字节喂进去、再接回来：

use image::{open, RgbImage};
use fast_image_resize::{FilterType, PixelType, ResizeAlg, ResizeOptions, Resizer};
use fast_image_resize::images::Image;

fn main() -> anyhow::Result<()> {
    let img: RgbImage = open("test.jpg")?.to_rgb8();
    let (sw, sh) = img.dimensions();                 // (宽, 高)

    // 源图：把 RgbImage 的裸字节(HWC、packed)交给 fir，声明像素类型 U8x3(=RGB)
    let src = Image::from_vec_u8(sw, sh, img.into_raw(), PixelType::U8x3)?;

    // 目标：开一块 640×640 的空 buffer，同样 U8x3
    let (dw, dh) = (640u32, 640u32);
    let mut dst = Image::new(dw, dh, PixelType::U8x3);

    // 选"卷积 + 双线性"，尽量和模型训练时的插值保持一致(见 9.2 精度那段)
    let opts = ResizeOptions::new().resize_alg(ResizeAlg::Convolution(FilterType::Bilinear));

    let mut resizer = Resizer::new();   // 工程上复用 resizer 和 dst，别每帧新建
    resizer.resize(&src, &mut dst, &opts)?;

    // 取回字节 → 变回 RgbImage 存盘
    let out = RgbImage::from_raw(dw, dh, dst.buffer().to_vec())
        .expect("字节数 = 640×640×3，一定匹配");
    out.save("fir_640.png")?;
    Ok(())
}

工程上通常会：把 Resizer 和输出 dst buffer 建一次、反复复用（视频每帧新建会白白分配内存）；插值算法选 Convolution(FilterType::Bilinear) 对齐训练。注意这里的 resize_exact 语义——它直接把图拉到 640×640，不保证长宽比，会变形。要“等比 + 补边“不变形，就是下一节的 letterbox。

9.9 letterbox 预告

目标检测模型要固定尺寸输入（本书主线 YOLOv8 是 640×640，见第 1 章设定），可现实照片长宽比五花八门（16:9、竖屏、正方形……）。若像 9.8 那样直接拉到 640×640，圆会被压成椭圆、人会被压扁——模型没见过这种畸变，精度必掉。

正解是 letterbox（等比缩放后用灰边填充到目标尺寸）：先按长边等比缩放，短边不够的部分补上灰边（padding），凑齐目标尺寸。它其实就是缩放的一个特例——缩放部分用等比、空出来的地方用固定颜色填充：

原图 1920×1080 (16:9)             目标 640×640 (1:1)
┌────────────────────┐           ┌──────────────────┐
│                    │  按 640/1920 │░░░░░░ 补灰边 ░░░░░│ ← 补 140 行
│      画面内容       │  = 1/3 等比  ├──────────────────┤
│                    │  缩到 640×360 │     画面内容      │ 640×360
└────────────────────┘  ──────────► ├──────────────────┤
                                    │░░░░░░ 补灰边 ░░░░░│ ← 补 140 行
                                    └──────────────────┘

关键点：缩放比例（这里 1/3）和补边量（上下各 140）必须记下来——因为模型输出的框坐标是在 640×640 上的，后处理要把它逆变换还原回原图像素坐标（呼应 9.6 的反向思路，也是第 16 章画框的前提）。letterbox 的完整实现——含坐标还原、0~1 归一化、HWC→CHW 张量组装——留给第 10 章系统拆解。到这里，你其实已经攒齐了它需要的全部零件：等比 resize（9.2 / 9.8）、补边的思路，以及“坐标怎么还原“的反向映射心法。

9.10 小结

  • 几何变换 = 把像素搬到新位置（值不变），和第 7、8 章“改像素值“正好是两个维度；每种变换本质都是一个坐标映射 (x,y)→(x',y')。
  • 缩放绕不开插值：最近邻（快、有锯齿）、双线性（默认、4 邻居加权）、双三次（16 邻居、更平滑）；双线性可以手算——先横插两次再竖插一次。插值方法要和训练时一致，否则模型掉点。
  • 裁剪、翻转、90° 旋转是无损重排，不需插值；任意角度旋转要用三角函数，且会引入插值和空白边。
  • **仿射（2×3 矩阵）**统一了平移 / 缩放 / 旋转 / 错切，直线保直线、平行保平行，6 自由度、3 组点确定；**透视（3×3 矩阵）**多了“除以 $W’$“，能让平行线汇聚、把斜四边形掰成正矩形，8 自由度、4 组点确定，用于车牌 / 文档 / 二维码矫正。
  • 实现一律用反向映射（遍历输出、反算原图位置、再插值），避免正向映射的空洞；imageproc 的 warp 收“输入→输出“矩阵但内部自动求逆。
  • 落地工具：image 的 resize（选 FilterType）、imageproc 的 rotate_about_center / warp / Projection、高性能场景用 fast_image_resize。letterbox 是缩放的特例（等比 + 补边），完整流程见第 10 章。

9.11 练习

  1. 手算双线性变体：把 9.2 的坐标改成 (x=2.8, y=1.2)，四个邻居值不变（Q11=10, Q21=20, Q12=30, Q22=40），用“先横后竖“和“四邻居加权“两种方式各算一遍，确认结果一致。再回答：dx=0.8, dy=0.2 意味着结果应该最靠近哪个邻居？算出来验证一下。
  2. 看见插值差异：用 9.2 的代码把一张图先缩到 80×80、再放大回原尺寸，分别全程用 Nearest 和用 Lanczos3，肉眼对比锯齿。结合 9.2 那段，解释为什么“下采样太糙“对小目标检测特别不友好。
  3. 仿射矩阵：写出“绕原点旋转 90°、再向右平移 100“的 2×3 矩阵（用 9.4 的旋转、平移矩阵组合），对点 (0,0)、(10,0)、(0,10) 各手算变换后坐标；检验这三点变换后是否仍构成直角（验证“仿射保直线、保平行“）。
  4. 透视矫正实战：找一张斜拍的书或名片照片，量出它四个角在图里的像素坐标，用 9.7 的 from_control_points + warp 把它矫正成正矩形并存盘。再把 Interpolation 从 Bilinear 换成 Nearest，放大看文字边缘的锯齿差异，体会插值对可读性的影响。
