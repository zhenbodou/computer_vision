机器视觉工程实战：用 Rust 看懂图像与模型

第 1 章 · 机器视觉到底是什么

本章导读：在写任何代码之前，我们先建立一个整体地图。看完本章你会知道：机器视觉在解决什么问题、一个机器视觉系统由哪些硬件和软件组成、传统算法和深度学习算法有什么区别，以及为什么这本书选择 Rust。

1.1 从人的眼睛说起

想一想你自己是怎么“看“东西的？

光线照在一只猫身上，反射进你的眼睛，眼睛把光信号转换成神经电信号，传给大脑。大脑不是收到一堆“像素“然后愣住——它直接告诉你：“这是一只猫，在沙发上，大约两米远。”

机器视觉要做的就是这件事的仿生版：

        人：光线 → 眼睛 → 视神经 → 大脑 → "有只猫"
  机器：光线 → 相机 → 数据线缆 → 算法 → "cat, 位置(x,y,w,h), 置信度92%"

相机相当于眼睛，算法（运行在 CPU/GPU/NPU 上）相当于大脑。这本书讲的就是“算法“那一部分——从拿到相机的原始数据开始，到输出“看懂了什么“为止。

顺便说一个常见的词：CV（Computer Vision，计算机视觉）。日常交流中“机器视觉“和“计算机视觉“基本混用。严格来讲，“机器视觉”（Machine Vision）更多指工业场景里的视觉系统（质检、测量、定位），“计算机视觉“范围更广（含人脸识别、自动驾驶等）。本书不区分这两个词。

1.2 机器视觉能干什么

先建立直觉，看几个真实场景：

场景一：手机人脸解锁。 摄像头拍一张你的脸 → 算法从画面里找到脸的位置 → 把脸“编码“成一串数字 → 和手机里存的你的人脸数字比对 → 相似度够高就解锁。整个过程 0.5 秒内完成。

场景二：工厂质检。 传送带上流过一个个零件，相机每秒拍几十张 → 算法检查有没有划痕、缺角、尺寸偏差 → 发现不良品立刻通知机械臂剔除。一个现代工厂靠这个能代替几十个人工质检员，而且是 7×24 小时不疲倦的。

场景三：自动驾驶。 车载相机、激光雷达持续采集周围环境 → 算法实时识别出“前面的车、左边的行人、右边的车道线“ → 规划模块据此决定加速还是刹车。这里对速度的要求极端苛刻：从拍照到出结果通常只有几十毫秒。

场景四：扫码支付。 这个你可能没想到也是 CV——从摄像头画面里找出二维码的位置、纠正透视变形、解码出字符串。背后是另一套经典算法（不是深度学习）。

这四个场景代表了机器视觉的几大类任务：

任务类型干什么例子本书对应章节
分类（Classification）这张图里主要是什么？猫还是狗第 15 章
检测（Detection）图里有哪些物体、在什么位置？人脸检测、车辆检测第 16 章（主线）
分割（Segmentation）每个像素分别属于什么？医学影像抠肿瘤、自动驾驶车道线第 18 章
关键点（Keypoint）目标上的关键位置在哪？人体骨架、人脸五官第 17 章
特征识别（OCR/二维码等）从图里读出结构化信息扫码、车牌识别、文字识别第 1 章提到，不展开

1.3 一个机器视觉系统由什么组成

很多同学以为机器视觉就是“调模型“，其实工程上一个完整的系统是这样的：

┌─────────────────────────────────────────────────────────┐
│                    机器视觉系统                          │
│                                                          │
│  【硬件层】                                              │
│    相机 + 镜头 + 光源   ← 光源极其重要！打光不好全白搭   │
│         │                                                │
│  【采集层】                                              │
│    相机驱动 / 视频流读取（USB、GigE、RTSP 摄像头）       │
│         │  原始数据（MJPG / H.264 码流 / RAW）           │
│  【算法层】← 本书 90% 的内容在这里                       │
│    解码 → 预处理 → 推理 → 后处理                         │
│         │  结果（坐标、类别、置信度）                    │
│  【应用层】                                              │
│    画框显示 / 触发机械臂 / 存数据库 / 报警               │
└─────────────────────────────────────────────────────────┘

几个对初学者重要的认知：

1. 光源比算法重要。 工业界有句老话：“打光解决 80% 的问题。“同样的算法，光打得好（明暗均匀、目标突出）识别率 99%，光打得差（反光、阴影）可能不到 50%。这就是为什么你去工厂看视觉检测设备，都有专门的打光罩。

2. 相机不是只有“像素“一个参数。 帧率（每秒拍多少张）、快门方式（全局快门不会拍变形，卷帘快门会“果冻效应“）、接口带宽、传感器尺寸，都是选型的关键。这些属于硬件知识，本书不深入，但你要知道它们的存在。

3. 算法层是一条流水线，推理只是其中一环。 这是本书最想纠正的一个误解。一个真实项目里，“调模型“往往只占工作量的 20%，剩下 80% 是：把各种来源的图像数据稳定地解码出来、预处理做对、后处理调对、边界情况处理干净。这也是我们把解码、预处理、后处理各自用一整章来讲的原因。

1.4 传统算法 vs 深度学习

机器视觉算法分两大流派，现在工业界是混用的，你要知道两者的区别：

传统算法：人工设计规则。 比如“要检测画面里的瑕疵，就先用 Canny 边缘检测找出所有边缘，再筛选形状异常的连通域“。规则是人写的，人能解释每一步为什么这么做。优点是：不需要训练数据、在小而明确的场景里又快又准、结果可解释。缺点是：场景一复杂、目标一多变，人工规则就写不动了——你没法写一条规则描述“什么是猫“。

深度学习算法：从数据里学规则。 你给它看一万张标注了“猫在哪里“的照片，它自己总结出“什么是猫“。这就是“训练“。训练出来的产物叫模型（一个存了上亿个数字的文件），使用模型做预测叫推理。优点是：泛化能力强，能处理“什么是猫“这种说不清规则的问题。缺点是：需要大量标注数据、需要算力训练、结果不如传统算法好解释。

对应关系大概是这样的：

传统算法深度学习
规则谁定工程师手写从数据中学
典型工具OpenCV、自写算法PyTorch/TensorFlow 训练的模型
适合场景定位、测量、固定外观检测复杂识别、开放类别检测
部署开销极小需要推理引擎和模型文件
本书对应章节第 3、7~9 章第 11~20 章

一个现代工业项目里典型的做法是混合：用传统算法做图像增强（第 7~9 章的滤波器），用深度学习模型做识别，再用传统几何算法做定位测量——各取所长。

1.5 全流程预览：一张图片的“奇幻漂流“

把前面所有内容串起来，看看一张照片在机器视觉系统里会经历什么。这就是本书后半部分每一章要展开讲的一步：

1. 相机拍下照片，存成 JPG 文件（或视频流里的一帧）
        │
2. 【解码】JPG 是压缩格式，先解压成"每个像素的颜色"（第 5、6 章）
        │  得到：W×H×3 的原始像素数据
3. 【预处理】模型要求 640×640 的图，原图是 1920×1080——
   │         缩放、转色彩空间、归一化、排好内存布局（第 10 章）
   │  得到：符合模型输入要求的张量
4. 【推理】把张量喂给模型（第 13 章转换、第 14 章执行）
   │  得到：一组抽象的数字（张量）
5. 【后处理】把数字翻译成"有 3 个物体：猫(92%)在(100,50)，狗(88%)……"（第 16 章）
        │
6. 【应用】在原图上画框、保存、或触发后续动作（第 26 章起）

注意第 4 步的输出不是一张标好框的图片，而是一堆数字。把数字变成“几个框、什么类别、多大概率“是后处理的工作。很多初学者第一次跑模型，看到输出是 float32[1,84,8400] 这样的张量会一头雾水——别担心，第 16 章会把它解剖得明明白白。

1.6 为什么用 Rust 学机器视觉

机器视觉的教程 99% 是 Python 写的，为什么这本书用 Rust？

1. 工业部署端本来就不是 Python 的天下。 训练模型确实用 Python（PyTorch/TensorFlow），但真正部署到设备上——工控机、嵌入式板子、边缘盒子——跑的多半是 C++、Rust、或者厂商的 C SDK。用 Rust 学，你学的就是“最后一公里“的真实工程。

2. Rust 的性能和内存可控性正是视觉任务需要的。 一张 4K 图就是 2400 万个字节，一秒钟 30 帧就是 7 亿字节的数据流过内存。Rust 没有 GC 停顿，内存布局完全由你掌控，这对毫秒级响应的视觉系统很关键。

3. Rust 的机器视觉生态已经足够入门。 image/imageproc 处理图像，ndarray 操作张量，tract-onnx/ort 做推理，OpenCV 也有官方维护的 Rust 绑定。学完本书，这些你都能用。

4. 顺带练习 Rust。 图像数据天然是“大块字节 + 严格布局“，用 Rust 处理它，所有权、借用、unsafe 这些概念会自然而然地变熟练。

要承认的短板：Python 在“训练模型、数据分析“上生态无敌，这部分你不用 Rust（也几乎没人用）。本书涉及的模型转换工具（第 13 章）有不少只有 Python 版，到时候我们会把 Python 当“命令行工具“来用——你只负责跑命令，不需要会写 Python。

1.8 小结

  • 机器视觉 = 让计算机从图片/视频中提取信息，仿生学结构是“相机当眼睛、算法当大脑“。
  • 主要任务分几类：分类、检测、分割、关键点、特征识别；本书主线是目标检测，并会逐个讲解各类模型（第六部分）。
  • 完整系统 = 硬件（相机/镜头/光源）+ 采集 + 算法流水线（解码→预处理→推理→后处理）+ 应用。算法层每一环都是工作量，不是只有推理。
  • 算法分传统（手写规则）和深度学习（数据训练）两派，工业界混用。
  • 选 Rust 是因为它贴近真实部署场景、性能可控、生态够用。

  2. 在搜索引擎里搜“机器视觉 打光“，找两张工业打光设备的图片，理解“光源为什么比算法重要“。
  3. 想一个你工作/生活中能用到机器视觉的场景，试着画出它的流水线（模仿 1.5 节的图），后面的章节你会逐步把它实现出来。
