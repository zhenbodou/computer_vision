# 第 25 章 特征匹配与几何验证（RANSAC）

> **本章导读**
> - 学完你能：把两张图的描述子**配对**起来，并用**比率测试**剔掉大部分弱匹配。
> - 想清楚一件反直觉的事：即便做了比率测试，匹配里**仍然混着错**（外点 outlier）——这几乎不可避免。
> - 把 **RANSAC（随机采样一致性）** 彻底讲透：为什么它能在"一半是错的"数据里稳稳拟合出正确模型。
> - 动手：① 用 FAST+BRIEF 匹配两张图并画连线；② 手写 RANSAC 从一堆带外点的散点里拟合直线，亲眼看最小二乘怎么被带偏。

## 场景：两张照片，谁对应谁？

[第 24 章](ch24-descriptors.md) 我们学会了给每个关键点算一串**描述子**（比如 256 位的 BRIEF）。现在来了两张照片——同一个场景、稍微挪了下相机——每张都提取了几十上百个带描述子的关键点。问题来了：**A 图第 3 个点，对应 B 图的哪一个？**

这一步叫**特征匹配（feature matching）**。它是全景拼接、图像对齐、三维重建、目标识别的共同地基：只有先知道"哪个点是哪个点"，才谈得上后面求变换、算位姿。

思路很朴素：描述子就是一串数，**两个点越像，它们的描述子距离越近**。所以给 A 里的每个点，去 B 里找**描述子距离最近的**那个，配成一对。二进制描述子（BRIEF/ORB）算距离用的是 **汉明距离（Hamming distance）**——两串比特有多少位不同，一个异或加数 1 就得到，快得飞起。

## 最近邻不够：比率测试登场

只取最近邻有个大毛病：**哪怕根本没有真正的对应点，最近邻也总会给你返回"某一个"**——因为总有一个是相对最近的。这种"矬子里拔将军"的匹配，多半是错的。

David Lowe 在 SIFT 论文里给了一个极简又极有效的招：**比率测试（ratio test）**。对 A 的每个点，在 B 里同时找**最近**和**次近**两个候选，比较它们的距离：

\\[ \text{ratio} = \frac{d_{\text{最近}}}{d_{\text{次近}}} \\]

- 如果这是个**可靠**匹配：最近的那个应该"鹤立鸡群"，明显比次近的近，比值很小（比如 0.5）。
- 如果这是个**含糊**匹配：最近和次近半斤八两（比如都是某种重复纹理），比值接近 1。

于是我们只保留 \\( \text{ratio} < 0.8 \\) 左右的匹配，把"拿不准"的直接扔掉。一刀下去，能砍掉大量弱匹配。

> 📖 **术语**：**内点（inlier）与外点（outlier）**。符合真实几何关系的正确匹配叫**内点**；不符合的错误匹配叫**外点**。后面 RANSAC 的全部本事，就是从一堆混杂的匹配里把内点找出来。

## 关键真相：比率测试之后，还是有错

这里要给新手打个预防针：**比率测试是"减少"外点，不是"消灭"外点。** 重复纹理（一排一样的窗户）、相似角点，都可能骗过比率测试。我们待会儿的实测里，39 对通过比率测试的匹配中，仍有 **7 对是错的**。

7/39 ≈ 18% 的外点，听起来不多，但足以让任何"老实"的拟合算法翻车——因为最小二乘之类的方法会**平等对待每一个点**，几个离谱的外点就能把结果拽跑偏。所以，匹配之后必须再来一道**几何验证**：用一个几何模型（下一章的单应矩阵、或这里的直线）去检验哪些匹配自洽。这道关卡的主角，就是 RANSAC。

## RANSAC：在谎言里投票选真相

**RANSAC = RANdom SAmple Consensus，随机采样一致性。** 它的思想可以用一个类比秒懂：

> 一个班里，大部分同学说的是实话，混着几个爱撒谎的。你想知道真相，怎么办？**别去平均所有人的话**（会被谎言带偏）。而是：随机拉几个人组成一个"陪审团"，听他们的说法形成一个假设，然后去问全班"你同不同意"——**同意的人越多，这个假设越可能是真相**。多试几轮，采纳"支持者最多"的那个假设。

翻译成算法，RANSAC 循环做四件事：

```text
重复 N 次：
  ① 随机取【最小样本】       —— 拟合直线只需 2 点，单应矩阵只需 4 对点
  ② 用这几个点拟合出一个模型
  ③ 数内点：全体数据里，有多少点符合这个模型（离得足够近）
  ④ 若这次内点比历史最优还多，就记下这个模型
结束后：用【所有内点】重新精修一遍模型，得到最终结果
```

为什么它抗外点？因为**外点之间通常互不"自洽"**。当你随机采到的最小样本恰好全是内点时，拟合出的模型会得到一大票内点支持；而只要采样里混进外点，拟合出的模型东倒西歪，支持者寥寥。跑很多轮后，"内点最多"的那个模型，几乎必然来自一次干净的采样。

> 💡 **提示**：为什么取**最小**样本（2 点而不是 20 点）？因为采样点越少，**整组恰好全是内点的概率越高**。20 个点里只要混一个外点就废了；2 个点全中的概率则大得多。这是 RANSAC 反直觉却关键的设计。

### 要循环多少次？一个公式给你底气

设内点比例为 \\( w \\)，每次取 \\( s \\) 个点。那么"一次采样全是内点"的概率是 \\( w^s \\)；"这次至少踩到一个外点"是 \\( 1-w^s \\)；"连续 N 次都没采到干净样本"是 \\( (1-w^s)^N \\)。我们希望"N 次里至少有一次干净采样"的概率达到置信度 \\( p \\)（比如 0.99），即 \\( 1-(1-w^s)^N \ge p \\)，解出：

\\[ N = \frac{\log(1-p)}{\log(1-w^s)} \\]

这个公式的直觉全在两个变量上：**外点越多（\\( w \\) 越小）、需要的样本越大（\\( s \\) 越大），要跑的轮数 N 就指数级增长。** 比如 \\( w=0.67, s=2, p=0.99 \\) 时 \\( N\approx 8 \\)，跑几十次绰绰有余；但若 \\( w \\) 掉到 0.3、\\( s=4 \\)（求单应矩阵），N 会飙到上千。实践中我们通常直接设一个足够大的上限（几百上千次），既省心又保险。

## 动手一：FAST+BRIEF 匹配并画连线

先把 [第 23 章](ch23-corners.md) 的 FAST 角点和 [第 24 章](ch24-descriptors.md) 的 BRIEF 描述子串起来，匹配"同一张图平移后的两个版本"。`Cargo.toml` 只需 `image` 和 `imageproc`（完整文件见 `code/examples/ch25_matching_ransac.rs`，`cargo run --example ch25_matching_ransac` 即可跑）。

核心是**手写一个带比率测试的暴力匹配器**——用描述子自带的 `hamming_distance` 就能实现，最能讲清原理：

```rust
use imageproc::binary_descriptors::BinaryDescriptor;

/// 最近邻 + Lowe 比率测试（暴力 O(Na*Nb)，教学最清晰）
fn match_with_ratio<'a, T: BinaryDescriptor>(
    d1: &'a [T], d2: &'a [T], ratio: f32,
) -> Vec<(&'a T, &'a T)> {
    let mut out = Vec::new();
    for a in d1 {
        let (mut best, mut second, mut best_j) = (u32::MAX, u32::MAX, 0usize);
        for (j, b) in d2.iter().enumerate() {
            let dist = a.hamming_distance(b);      // 汉明距离：异或后数 1 的个数
            if dist < best { second = best; best = dist; best_j = j; }
            else if dist < second { second = dist; }
        }
        // 比率测试：最近邻要明显比次近邻更近，才算可靠
        if (best as f32) < ratio * (second as f32) {
            out.push((a, &d2[best_j]));
        }
    }
    out
}
```

计算描述子时有个**必须记住的坑**（下面单独列了）：两张图要用**同一套** BRIEF 测试点对，否则描述子根本没法比。做法是第一张图返回的 `pairs` 喂给第二张：

```rust
let (desc_a, pairs) = brief(&gray_a, &kp_a, 256, None)?;          // 生成随机测试点对
let (desc_b, _)     = brief(&gray_b, &kp_b, 256, Some(&pairs))?;  // 复用同一套！

let matches = match_with_ratio(&desc_a, &desc_b, 0.8);
// 库自带的匹配器（汉明阈值 + 局部敏感哈希 LSH）作对照：
let lib_matches = match_binary_descriptors(&desc_a, &desc_b, 64, Some(7));
```

因为两图只差一个已知平移 `(24, 12)`，我们可以据此判断每对匹配是不是几何内点（`a.x - b.x ≈ 24` 且 `a.y - b.y ≈ 12`）。运行输出：

```text
A 角点 60 个，B 角点 60 个
比率测试匹配 39 对，其中几何正确(内点) 32 对，误匹配(外点) 7 对
库 match_binary_descriptors 匹配 60 对
```

打开画出来的并排连线图：**绿线**是几何正确的匹配（几乎都是平行的、方向一致），**红线**是误匹配（东拉西扯、明显穿帮）。这张图把"比率测试后仍有外点"这件事画得明明白白——那几条红线，正是下一章要用 RANSAC 剔掉的。

> ⚠️ **注意**：`imageproc` 的 `match_binary_descriptors(d1, d2, threshold, seed)` 用的是**汉明距离阈值 + 局部敏感哈希（LSH）**加速，**不是**比率测试；`threshold` 是允许的最大汉明距离，`seed` 控制 LSH 的随机性。它更快，但不做比率过滤，所以返回的匹配更多、也更容易混入外点。要精细控制质量，自己写比率测试；要图省事、后面反正有 RANSAC 兜底，直接用它也行。

## 动手二：手写 RANSAC 拟合直线 vs 最小二乘

匹配的几何验证放到 [第 26 章](ch26-homography-stitching.md) 结合单应矩阵讲。这里先用一个**更纯粹**的例子把 RANSAC 吃透：从一堆"80 个贴着真实直线的内点 + 40 个乱撒的外点"里拟合直线。

RANSAC 的核心就三个小函数——拟合、算距离、循环：

```rust
// 点到“过 p1,p2 两点直线”的垂直距离
fn point_line_dist(q: (f64,f64), p1: (f64,f64), p2: (f64,f64)) -> f64 {
    let (dx, dy) = (p2.0 - p1.0, p2.1 - p1.1);
    let len = (dx*dx + dy*dy).sqrt().max(1e-9);
    ((q.0 - p1.0) * dy - (q.1 - p1.1) * dx).abs() / len
}

fn ransac_line(pts: &[(f64,f64)], thresh: f64, iters: usize, rng: &mut Rng)
    -> (f64, f64, usize)
{
    let n = pts.len();
    let mut best_inliers: Vec<usize> = Vec::new();
    for _ in 0..iters {
        // ① 随机取最小样本：直线只需 2 个点
        let i = rng.range(0, n as u32) as usize;
        let mut j = rng.range(0, n as u32) as usize;
        while j == i { j = rng.range(0, n as u32) as usize; }
        let (p1, p2) = (pts[i], pts[j]);
        if (p1.0-p2.0).abs() < 1e-6 && (p1.1-p2.1).abs() < 1e-6 { continue; } // 退化
        // ②③ 数内点：离这条线足够近的点
        let inliers: Vec<usize> =
            (0..n).filter(|&k| point_line_dist(pts[k], p1, p2) < thresh).collect();
        // ④ 保留内点最多的模型
        if inliers.len() > best_inliers.len() { best_inliers = inliers; }
    }
    // 用全部内点做最小二乘精修
    let inlier_pts: Vec<(f64,f64)> = best_inliers.iter().map(|&k| pts[k]).collect();
    let (m, c) = least_squares(&inlier_pts);
    (m, c, best_inliers.len())
}
```

（`least_squares` 是标准闭式最小二乘；`Rng` 是一个自包含的 xorshift 小随机数器，这样不必引入 `rand`。）运行结果一目了然：

```text
内点比例 w≈0.67，置信度 p=0.99，最小样本 s=2 → 理论迭代 N≈7.8 次
真实直线:      y = 0.500 x + 20.00
最小二乘(全部): y = 0.387 x + 44.88  <- 被外点带偏
RANSAC + 精修:  y = 0.497 x + 21.15  (找到 77 个内点)
```

结论掷地有声：**最小二乘**把 40 个外点也当真数据平等对待，拟合出的 `0.387x+44.88` 与真值 `0.5x+20` 差了十万八千里；而 **RANSAC** 先靠"投票"锁定 77 个内点、把外点挡在门外，再精修得到 `0.497x+21.15`，几乎完美复现真实直线。理论迭代次数只要约 8 次，我们跑了 200 次，稳如老狗。

## 常见坑与提示

> 🕳️ **坑**：**两张图必须用同一套 BRIEF 测试点对。** `brief` 若传 `None` 会**随机**生成测试点对——两张图各随机一套，算出的描述子驴唇不对马嘴，匹配全是噪声。务必把第一张返回的 `pairs` 用 `Some(&pairs)` 传给第二张。（还记得吗，BRIEF 不抗旋转缩放，所以这里只演示平移。）

> ⚠️ **注意**：**比率阈值和距离阈值都要调。** 比率阈值（0.7~0.8 常用）越小越严、匹配越少但越干净；RANSAC 的内点距离阈值 `thresh` 则取决于你的噪声量级——太小会把真内点也判成外点，太大则放外点进来。没有万能值，对着数据调。

> 🕳️ **坑**：**最小样本数 s 要用"恰好能定模型"的数目。** 直线 2 点、单应矩阵 4 对点、基础矩阵 7 或 8 点。取多了会拉低"整组全是内点"的概率，白白增加迭代次数；取少了模型定不下来。

> 💡 **提示**：**当心退化样本。** 随机采到两点重合（拟合不出直线）、或四点共线（[第 26 章](ch26-homography-stitching.md) 求单应矩阵会失败）——这些**退化**情形要在循环里判掉（我们代码里 `continue` 跳过），否则会得到无意义的模型甚至除零。

## 本章小结

- **特征匹配**：给 A 的每个描述子在 B 里找**最近邻**（二进制描述子用**汉明距离**）；只取最近邻不可靠，用 **比率测试**（最近/次近 < 0.8）滤掉含糊匹配。
- 比率测试只是**减少**而非消灭外点——实测 39 对匹配里仍有 7 对是错的，所以还需**几何验证**。
- **RANSAC** 反复"随机取最小样本 → 拟合模型 → 数内点 → 留内点最多者"，最后用全部内点精修，**天生抗外点**。
- 迭代次数 \\( N = \log(1-p)/\log(1-w^s) \\)：外点越多、样本越大，需要的轮数指数级上升；实践中直接设个大上限最省心。
- 实测：面对 33% 的外点，最小二乘被带偏得离谱，RANSAC 稳稳复现真值。

## 动手练习

1. **调比率阈值**：把 `match_with_ratio` 的 `ratio` 从 0.8 依次调到 0.6、0.9，观察匹配总数与内点/外点比例怎么变，体会"严"与"松"的取舍。
2. **验证迭代公式**：把 `ransac_line` 的 `iters` 从 200 一路降到 5、3、1，多跑几次，看它多久开始偶尔失手——和公式算出的 \\( N\approx 8 \\) 对比。
3. **加大外点比例**：把外点从 40 个加到 120 个（内点比例 \\( w \\) 降到 0.4），重新算理论 N，并把 `iters` 调够，确认 RANSAC 依然能拟合对。
4. **进阶**：给 `ransac_line` 加一个"提前退出"——一旦某次内点数超过总数的某个比例（如 90%）就跳出循环，省下无谓的迭代。
