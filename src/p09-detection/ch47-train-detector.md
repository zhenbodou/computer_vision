# 第 47 章 训练与微调检测器：数据闭环与受控实验

> **本章导读**
> - 学完你能：从零**训练**上一章那个小检测器，讲清检测的**损失三件套**（objectness + 类别 + 框回归）如何加权求和、如何反向；并用 **mAP@0.5 与平均 IoU** 量化质量。
> - 你会亲手做两个**"一次只改一个变量"的受控实验**：① **划分泄漏**——同一批数据用"随机划分"和"按场景分组划分"，看泄漏把 mAP **虚高 24 个百分点**；② **消融**——只把框回归权重 `λ_box` 从 1 改到 5，看 mAP **真实地** 从 0.598 涨到 0.705。
> - 你会建立专家级的**数据闭环**纪律：类别定义、漏标、划分、微调 vs 从零、单变量消融——**决定检测器上限的往往是数据与实验方法，而不是网络**。
> - 代码在本机 `cargo run --release` 实测，正文数字均为真实输出。

## 场景：模型没变，为什么"线下很好、线上拉胯"？

你把 [第 46 章](ch46-yolo-inference.md) 的检测器训出来，验证集上 mAP 0.94，兴冲冲上线——结果线上误报连连。模型明明没变，问题出在哪？

九成出在**数据与评估方法**上：类别定义含糊、有漏标、**验证集和训练集偷偷"串了味"**（同一段视频的相邻帧被随机分到了两边）。这一章我们不堆网络，而是把**训练的损失怎么算**讲透，再用**受控实验**把这些"看不见的坑"一个个量化出来——这正是 [第 45 章](ch45-detection-principles.md) 说的"瓶颈来自召回、定位、分类还是后处理"的实证版本。

## 原理：检测的"损失三件套"

分类只有一个损失（类别对不对）。检测要同时学三件事，于是有**三个损失**（[第 45 章](ch45-detection-principles.md)）：

\\[ L = L_{obj} + \lambda_{box} L_{box} + \lambda_{cls} L_{cls} \\]

- **objectness 损失 \\( L_{obj} \\)**：每个格子"有没有目标"，用**二元交叉熵（BCE）**，对**所有格子**算。难点是**正负极不平衡**——36 个格子里通常只有寥寥几个"有目标"，所以给正样本格子更大权重（本章 `pos_w = 6`），否则模型会偷懒地"全预测没有"。
- **框回归损失 \\( L_{box} \\)**：把框预测**解码成归一化的 \\( (c_x, c_y, w, h) \\)**，与真值做 **L1**，**只在"负责格"上算**。可选 smooth-L1 或 GIoU/DIoU/CIoU 等 IoU 类损失（[第 45 章](ch45-detection-principles.md)）。
- **类别损失 \\( L_{cls} \\)**：负责格里"是哪一类"，用 BCE（每类独立 logistic）或交叉熵，**只在负责格上算**。

三者**加权相加成一个标量**，再一次反向传播、一步更新——`λ_box`、`λ_cls` 就是它们的相对话语权。

> ⚠️ **注意**：**损失的"数值大小"不等于"梯度贡献"。** 你看到 `L_box = 0.01`、`L_cls = 0.6`，不代表框回归就不重要——它们的量纲、尺度天差地别。想知道某项到底在训练里占多大分量，要看**梯度范数**，或干脆做**消融**（本章实验二就是干这个的）。调权重别凭感觉，用实验说话。

数值稳定的 BCE（[第 44 章](../p08-classification/ch44-finegrained.md) 踩过坑：candle 自带的 `binary_cross_entropy_with_logit` 数值不稳、logit 一大就 `log(0)→NaN`）：

\\[ \mathrm{BCE}(x, y) = \max(x, 0) - x y + \log(1 + e^{-|x|}) \\]

对应的检测损失代码（三件套一目了然）：

```rust
fn compute_loss(out: &Tensor, obj_t: &Tensor, wgt: &Tensor, boxn_t: &Tensor, cls_t: &Tensor,
                num_pos: f32, cell_x: &Tensor, cell_y: &Tensor, lambda_box: f64, lambda_cls: f64)
    -> Result<(Tensor, f32, f32, f32)> {
    let obj_logit = out.narrow(1, 0, 1)?;   // [N,1,G,G]
    let box_raw   = out.narrow(1, 1, 4)?;    // [N,4,G,G]
    let cls_logit = out.narrow(1, 5, C)?;    // [N,C,G,G]

    // ① objectness：所有格子的加权 BCE（正样本极少，给更大权重 wgt）
    let l_obj = bce_elem(&obj_logit, obj_t)?.broadcast_mul(wgt)?.sum_all()?
        .affine(1.0 / (n * G * G) as f64, 0.0)?;
    // ② 框回归：解码成归一化 (cx,cy,w,h)，只在负责格(obj_t=1)上做 L1
    let pred_boxn = decode_boxes(&box_raw, cell_x, cell_y)?;      // 解码同第 46 章，完整代码见配套工程
    let l_box = pred_boxn.broadcast_sub(boxn_t)?.abs()?.broadcast_mul(obj_t)?.sum_all()?
        .affine(1.0 / (num_pos * 4.0) as f64, 0.0)?;
    // ③ 类别：只在负责格上做 BCE
    let l_cls = bce_elem(&cls_logit, cls_t)?.broadcast_mul(obj_t)?.sum_all()?
        .affine(1.0 / (num_pos * C as f32) as f64, 0.0)?;

    // 加权求和成一个标量 → 一次反向
    let total = l_obj.broadcast_add(&l_box.affine(lambda_box, 0.0)?)?
                     .broadcast_add(&l_cls.affine(lambda_cls, 0.0)?)?;
    Ok((total, l_obj.to_scalar()?, l_box.to_scalar()?, l_cls.to_scalar()?))
}
```

`narrow(1, start, len)` 把 `[N,A,G,G]` 沿通道切成 obj / box / cls 三段；`broadcast_mul(obj_t)` 是**掩码**——只让"负责格"贡献框和类别损失。真实训练曲线（分组划分、`λ_box=5`，200 轮）：

```text
    epoch   1  total=2.4113  obj=0.9899  box=0.1466  cls=0.6886
    epoch  60  total=0.4126  obj=0.2309  box=0.0236  cls=0.0636
    epoch 120  total=0.2134  obj=0.1162  box=0.0176  cls=0.0090
    epoch 180  total=0.1657  obj=0.0941  box=0.0133  cls=0.0050
```

三项一起稳稳下降。**但记住这条曲线只是"训练集上的表现"**——它漂亮，不代表模型泛化好。下面的实验一会给你当头一棒。

## 原理：怎么量化"检测得好不好"

分类看准确率，检测看 **mAP（mean Average Precision）**。一句话直觉：把检出框按分数从高到低排队，逐个判定"命中真值（IoU ≥ 0.5）还是误检"，画出**精确率-召回率曲线**，曲线下面积就是这一类的 **AP**；各类 AP 求平均就是 **mAP@0.5**（评估细节见 [第 48 章](ch48-metrics-annotation.md)）。本章还同时报告**命中框的平均 IoU**（定位有多准）、**召回率**（漏了多少）、**精确率**（误报多少）。这几个数放一起看，才不会被单一指标骗到。

## 实验一：划分泄漏——同一批数据，两种划分，天壤之别

**这是本章最重要的实验。** 我们造一批**"场景 + 近似重复帧"**的数据来模拟真实视频：

- 造 **16 个场景**（每个场景 = 一组固定布局的目标），每个场景渲染 **12 帧**——每帧给目标加 ±2px 抖动、随机亮度、像素噪声。**同一场景的 12 帧就是"近似重复"**，正如监控视频里相邻的帧。共 192 帧。
- **划分 A（正确·按场景分组）**：前 12 个场景（144 帧）做 train，后 4 个**全新场景**（48 帧）做 val。**val 的布局 train 从没见过。**
- **划分 B（错误·随机划分）**：把 192 帧打乱，随机切 144 / 48。**恶果**：几乎每个场景的帧都被同时切进 train 和 val——val 里全是 train 帧的"近似重复"。

诊断打印证实了泄漏有多严重：

```text
随机划分：48 个 val 帧里，有 48 帧的场景也在 train 中（近似重复→泄漏）
分组划分：val 全部来自 train 从未见过的 4 个场景（无泄漏）
```

**用完全相同的网络、相同的训练，只改划分方式**，在各自的 val 上评估：

```text
  划分方式         mAP@0.5       召回率       精确率     平均IoU
  随机(泄漏)         0.945     0.948     0.901     0.759
  分组(诚实)         0.705     0.824     0.631     0.704
  → 随机划分把 mAP 虚高了 24.0 个百分点（泄漏的代价）
```

**触目惊心：随机划分报出 mAP 0.945，而诚实的分组划分只有 0.705——虚高了整整 24 个百分点。** 精确率更是从 0.63 被吹到 0.90。原因很简单：随机划分下，模型在训练时已经见过每个 val 帧的"孪生兄弟"，于是 val 成绩衡量的是**"记住了没有"**，而不是**"能不能泛化到新场景"**。

回头看训练曲线——训练损失都降到 0.166 了，可诚实 val 只有 mAP 0.705，这中间的落差就是**过拟合**。而随机划分那份 0.945 的"高分"，会让你误以为万事大吉，直到上线撞墙。

> 🕳️ **坑（值一整章的教训）**：**同场景 / 同视频 / 同一批次的样本，绝不能跨 train/val 乱分。** 视频要**按片段或摄像头**分组，产线要**按批次 / 日期 / 设备**分组，让 val 里是训练**从没见过的**场景。本例场景越少、近似重复越多，泄漏越致命（真实监控视频每秒 25 帧、几乎帧帧近似，泄漏能让指标虚高到离谱）。**先划分、后一切**，并存一份不可变的 manifest（样本 id、来源、时间、标签版本、哈希），从源头杜绝泄漏。

## 实验二：单变量消融——只动 λ_box，看它值多少

想知道"框回归权重"到底重不重要？**在诚实的分组划分上，只把 `λ_box` 从 1 改到 5，其余一切不变**，再比一次：

```text
  λ_box        mAP@0.5       召回率       精确率     平均IoU
  1              0.598     0.769     0.546     0.659
  5              0.705     0.824     0.631     0.704
  分类别 AP@0.5（λ_box=1 → 5）：方块 0.643→0.761，横条 0.552→0.648
```

**只改这一个数，mAP@0.5 从 0.598 涨到 0.705，平均 IoU 从 0.659 涨到 0.704，两个类别的 AP 一起涨。** 结论清晰可信：在这个任务里，加大框回归权重让定位更准，更多框迈过了 IoU ≥ 0.5 的门槛，于是 mAP 也跟着涨。

**为什么必须"一次只改一个变量"？** 如果你同时改了 `λ_box`、学习率、又加了增强，结果变好了——你根本说不清是谁的功劳，下次也复现不了。受控实验的铁律：**固定其他一切，单独变一个因素**，收益才能归因。这和 [第 43 章](../p08-classification/ch43-finetune.md) 微调消融是同一套严谨。

> 💡 **提示**：**这套实验框架可以无脑复用。** 把"造数据 → 训练 → 评估 mAP/IoU"封装成一个函数 `run(train, val, λ_box, ...)`，想消融什么就把那个变量做成参数（学习率、增强强度、`pos_w`、冻结与否……），跑两遍一比即可。本章配套工程的 `run(...)` 正是这么写的——换个参数就是一个新实验。

## 常见坑与提示

> 🕳️ **坑**：**漏标会把真目标当背景来惩罚。** 训练时，没标注的目标落在某个格子里，objectness 的监督却是"这里没有"——模型被硬生生教成"看见了也说没有"，召回直接受损。对策：用已有模型的高置信预测和人工标注做**差集复核**，但**绝不能**把模型预测直接当真值写回去，否则会把模型的偏见固化进数据（[第 48 章](ch48-metrics-annotation.md)）。

> ⚠️ **注意**：**类别定义要先于标注写清楚。** 每个类的**包含 / 排除规则、遮挡与截断阈值、最小可见尺寸、框要多紧、困难样本怎么处理、哪些是忽略区**——这些没定义清楚，两个标注员标出来的框和类别就会打架。做法：让两人独立标同一批图，算**类别一致率**和**框 IoU 分布**，分歧大就说明规范还不够明确。

> 🕳️ **坑**：**微调 vs 从零，别一上来就全网猛训。** 数据少时，正确姿势是**站在预训练模型肩上**：像 [第 43 章](../p08-classification/ch43-finetune.md) 那样**冻结骨干、只换新头**建立基线，再逐段解冻。candle 里冻结几乎零成本——`from_mmaped_safetensors` 加载出的是常量张量（非 `Var`），天然不更新（[第 43 章](../p08-classification/ch43-finetune.md)）。检测器同理：骨干那套"认边缘 / 朝向 / 团块"的眼力可以直接复用，需要重训的只是检测头。

> ⚠️ **注意**：**checkpoint 要按"事先声明的验证指标"选，测试集只在方案冻结后结算。** 训练中记录各项损失、学习率、验证 mAP 和一组**固定的可视化样本**；拿验证集反复挑模型、调超参，本质上也是一种慢性泄漏——所以最终一定要在一份**从没参与过任何决策**的测试集（最好是新设备 / 新日期的数据）上结算，才算数。

> 💡 **提示**：**别让总体 mAP 掩盖关键类。** 类别不平衡时，要同时看**每类 AP 与召回**。本章实验二就分类别列了 AP（方块 / 横条各自的变化），这样才能发现"总体涨了，但某个要命的类其实退步了"这种被平均数藏起来的问题。

## 本章小结

- 检测训练是**损失三件套**的加权和：\\( L = L_{obj} + \lambda_{box} L_{box} + \lambda_{cls} L_{cls} \\)。objectness 用加权 BCE（治正负不平衡）对所有格子算；框回归用 L1、类别用 BCE，**只在"负责格"上算**；三者相加成一个标量后一次反向。
- 质量用 **mAP@0.5** 配**平均 IoU / 召回 / 精确率**一起看；单一指标容易骗人。
- **划分泄漏实测**：同一批"场景 + 近似重复帧"，随机划分报 mAP **0.945**、分组划分只有 **0.705**——**虚高 24 个百分点**。同场景 / 同视频样本**必须**按组划分，绝不能随机切。
- **单变量消融实测**：只把 `λ_box` 从 1 改到 5，mAP@0.5 **0.598→0.705**、平均 IoU **0.659→0.704**。受控实验一次只改一个变量，收益才能归因、才能复现。
- **专家心法**：决定检测器上限的，往往是**数据定义、划分严谨、错误分析和受控实验**，而不是网络本身。先数据、后模型。

## 动手练习

1. **复现泄漏**：把配套工程里 `frames_per_scene`（每场景帧数）从 12 改到 4，再改到 20，重跑实验一，看"近似重复越多、泄漏越狠"——找出让虚高差距最大的配置。
2. **再做一个消融**：仿照实验二，固定其他一切，只扫 objectness 正样本权重 `pos_w`（比如 3 / 6 / 12），看召回率和精确率怎么此消彼长，找出你数据上最合适的那个。
3. **画错误桶**：把分组划分 val 上的错误分类成"漏检 / 类间混淆 / 定位偏差（IoU<0.5）/ 误检"，统计各占多少——想清楚"先修哪一类错误"收益最大（[第 45 章](ch45-detection-principles.md) 的错误分析）。
4. **想一想（呼应 [第 43 章](../p08-classification/ch43-finetune.md)）**：你有一个在"方块/横条"上训好的检测器，现在要它检测一个新类别"圆盘"，但只有 50 张标注图。你会从零训练还是微调？冻结哪些层？验证集该怎么划分才不泄漏？

## 专家补强：把"训出一个检测器"升级为"经得起追问的数据闭环"

一次训练只是起点。专家级的检测项目是一个**多轮闭环**：每轮**冻结假设、改动和验收线**，把错误分桶（漏标、类间混淆、定位、小目标、遮挡、反光、模糊、域偏移、后处理误删），**每轮只针对主要的错误桶**去采集或修订数据，并保留上一版测试集**防止遗忘**。主动学习的采样要**混合**高不确定、模型分歧、嵌入多样性和随机样本——单用低置信度会一头扎进噪声。最后，真正的验收是：在**未参与开发的新设备 / 新日期数据**上评估，并解释**线下的提升是否真的转化成了业务误报 / 漏报成本的下降**。完整验收标准见 [附录 G](../appendix/g-expert-standard.md)。
