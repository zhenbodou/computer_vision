# 第 48 章 检测评估、标注质量与统计不确定性

> **本章导读**
> - 手写一套**纯 Rust 检测评估器**：PR 曲线、AP（11 点插值 + 全点积分）、mAP、混淆矩阵、每类召回，全程合成数据、`cargo` 实测。
> - 讲清 **mAP@0.5** 和 **mAP@[.5:.95]** 到底各自回答什么问题，为什么不能只比一个叫"mAP"的数字。
> - 学会给 mAP 报**置信区间**（bootstrap）——报数字不带不确定性是不专业的。
> - 用"注入 10% 漏标"的可运行实验，亲眼看**标注质量怎么毒化指标**。

## 场景引入：两个模型，谁更好？

你训了两个检测器：A 的 mAP 是 0.64，B 是 0.66。B 赢了，上线 B？——**慢着**。这 0.02 的差距，可能只是测试集这几张图恰好对 B 友好一点的**随机波动**；也可能 B 只是在某个大类上涨了、关键的小类反而跌了；甚至可能你的**测试集标注本身就有错**，两个数字都不可信。

"报一个 mAP 就完事"是新手做法。专家会追问：这个数字怎么算出来的（IoU 阈值？插值方式？）、它的**误差范围**多大、在**哪些切片**上好、标注**干不干净**。这一章，我们把这些追问一个个用代码落地。所有实验在一份合成数据集上跑（**24 张图、79 个 GT、82 个预测框、3 类**），运行：

```bash
cargo run --example ch48_metrics_annotation
```

完整代码在 `code/examples/ch48_metrics_annotation.rs`，只用 std，确定性可复现。预测框在真实项目里来自 [第 46](ch46-yolo-inference.md)/[47 章](ch47-train-detector.md) 的检测器，本章用合成的"模拟检测器输出"代替，好处是我们能**精确控制**并验证评估逻辑本身。

## 48.1 AP 计算对象

评估的第一步是**匹配**：把预测框和 GT 配对，判定每个预测是 **TP（真阳，命中）**、**FP（假阳，误报）**，以及每个没被检出的 GT 是 **FN（假阴，漏检）**。规则要钉死：

- **按类、按图**分别匹配：只在同一张图、同一个类别内配对；
- 一个预测在其图内找**同类、尚未被占用、IoU 最大且 ≥ 阈值**的 GT → 记为 TP，并**占用**该 GT；
- 找不到就是 FP；
- **一个 GT 只能被匹配一次**——同一目标的第二个高分框，只能算 FP。这条正是 **NMS 影响 AP 的根本原因**：NMS 没去干净，重复框就变成 FP 拉低精度。

匹配的核心代码（`pr_curve`）：

```rust
// 关键：把该类所有预测按分数从高到低排序，再逐个匹配
dets.sort_by(|a, b| b.0.partial_cmp(&a.0).unwrap());
let (mut cum_tp, mut cum_fp) = (0.0f32, 0.0f32);
for &(_, ii, pb) in &dets {
    let mut best_iou = 0.0f32; let mut best_j = None;
    for (j, g) in images[ii].gts.iter().enumerate() {
        if g.cls != cls || matched[ii][j] { continue; } // 同类且未被占用
        let iou = pb.iou(g.b);
        if iou > best_iou { best_iou = iou; best_j = Some(j); }
    }
    if best_iou >= iou_t {
        cum_tp += 1.0; matched[ii][best_j.unwrap()] = true; // TP，占用该 GT
    } else {
        cum_fp += 1.0; // FP
    }
    prec.push(cum_tp / (cum_tp + cum_fp));       // precision = TP/(TP+FP)
    rec.push(cum_tp / n_gt as f32);              // recall    = TP/GT 总数
}
```

**PR 曲线**：随着我们把置信度门槛一路调低（等价于从高分到低分逐个"接纳"预测），召回单调上升，精度则上下起伏。类别 C0（22 个 GT、24 个预测）的实测轨迹：

```text
  第 1个预测: recall=0.045  precision=1.000
  第 3个预测: recall=0.136  precision=1.000
  第 5个预测: recall=0.136  precision=0.600   ← 冒出 FP，精度掉了
  第 9个预测: recall=0.318  precision=0.778
  第15个预测: recall=0.500  precision=0.733
  第21个预测: recall=0.682  precision=0.714
  第24个预测: recall=0.682  precision=0.625   ← 最后几个全是 FP
```

**AP（Average Precision）就是这条 PR 曲线下的面积**。怎么求面积有两种主流约定，本章都实现了：

- **11 点插值（VOC2007）**：在 recall = 0, 0.1, …, 1.0 这 11 个点，各取"召回 ≥ 该点的最大精度"，再平均：

\\[ \text{AP} = \frac{1}{11}\sum_{r\in\{0,0.1,\dots,1.0\}} p_{interp}(r),\quad p_{interp}(r)=\max_{\tilde r\ \ge\ r} p(\tilde r) \\]

- **全点积分（VOC2010 / COCO）**：先把精度从右往左取后缀最大值、抹成单调不增，再按召回每一次跳变累加矩形面积。更精细，是现在的主流。

实测两种算法的 AP 和 mAP（三类平均）：

```text
  C0: 全点 AP=0.5505  11点 AP=0.5278  (GT=22)
  C1: 全点 AP=0.7459  11点 AP=0.7079  (GT=34)
  C2: 全点 AP=0.6173  11点 AP=0.6054  (GT=23)
  → mAP@0.5 全点=0.6379   11点=0.6137
```

看，同一批预测，**换个插值方式 mAP 就从 0.6379 变成 0.6137**。这就是为什么"报 mAP 必须同时说明 IoU 阈值、插值方式、面积区间、以及 ignore/crowd 规则"——不然两个数字根本没法比。

**mAP@0.5 vs mAP@[.5:.95]** 回答的是不同问题：

```text
  mAP@0.5      = 0.6379  （框只要「大致对」，IoU≥0.5 即算命中）
  mAP@[.5:.95] = 0.3413  （IoU 0.50→0.95 十档平均，对定位精度苛刻得多）
```

mAP@0.5 宽容，只问"找没找到"；mAP@[.5:.95]（COCO 主指标）把 IoU 门槛从 0.5 一路提到 0.95 取平均，**框歪一点就扣分**，同一个模型数字直接从 0.64 掉到 0.34。要测量精定位能力，就看后者。

> ⚠️ **注意**：**最大检测数（max detections）** 会截断密集场景的召回。COCO 默认每图最多取 100 个框，如果你的场景一图几百个目标，这个上限会让召回天花板压得很低。评估配置里这类"边界规则"（类别 id 从 0 还是 1、面积如何分桶、crowd 怎么处理）各家评估库都不同，**别只比一个 mAP 数字**。

## 48.2 阈值与业务成本

AP 衡量的是**排序质量**（把对的排前面的能力），它扫过了所有阈值。但真上线时，你必须**选定一个置信度阈值**来决定"报还是不报"。这时评估工具换成**混淆矩阵**——它是在某个**固定操作点**上，看模型把什么判成了什么。

本章的混淆矩阵用 class-agnostic 贪心匹配（IoU=0.5、conf≥0.5），行是真值、列是预测，多出来的 BG 行/列表示"背景"：

```text
        预测C0 预测C1 预测C2 预测BG
真值C0      15     3     0     4     ← 3 个 C0 被误判成 C1（类别混淆）
真值C1       0    26     4     4
真值C2       3     0    15     5     ← 5 个 C2 漏检（判成背景）
真值BG       4     1     2     0     ← 背景里冒出 7 个误报
  每类召回（对角/该行 GT 总数）:
    C0: 召回=0.682  精确率=0.682
    C1: 召回=0.765  精确率=0.867
    C2: 召回=0.652  精确率=0.714
```

对角线是判对的，非对角是**类别混淆**，`[某类][BG]` 是该类**漏检**，`[BG][某类]` 是**背景误报**。一眼就能看出问题：C2 漏检偏多（召回仅 0.652），C0 和 C1 之间有混淆。**每类召回/精确率**能揭示"总体 mAP 掩盖的关键类问题"——总分好看，可能恰恰是把某个要命的类学差了。

选阈值不该拍脑袋，而应绑定**业务成本**。设一次误报、一次漏检的成本为 \\( C_{FP}, C_{FN} \\)，在验证集上选择最小化总成本的阈值：

\\[ \theta^\star = \arg\min_{\theta}\ \big(C_{FP}\cdot FP(\theta) + C_{FN}\cdot FN(\theta)\big) \\]

安全类任务（如闯入报警）常有硬约束——"关键类召回不得低于 0.95"，那就先框定可行域，再在其中最小化误报。

> 💡 **提示**：混淆矩阵**依赖你选的 conf 阈值**（这里是 0.5），换个阈值整张表都会变；而 AP/mAP **不依赖单一阈值**（它扫过全部）。所以别拿"某阈值下的准确率"去和 mAP 相提并论，它们是两个层面的东西。部署前还要检查**置信度校准**——模型说 0.9 是不是真有九成对；分布变了要重新校准，但**绝不能拿线上未经审核的反馈直接当真值**回灌。

## 48.3 统计置信度

回到开头的问题：mAP 0.64 和 0.66，差距是真的吗？测试集就这么大，**0.02 的差异很可能只是抽样波动**。专家的做法是给 mAP 报**置信区间**。

**bootstrap（自助法）** 是最朴素好用的工具：把测试图像**有放回地重采样**很多次，每次重算一遍 mAP，得到 mAP 的一个分布，取它的 2.5% 和 97.5% 分位数就是 95% 置信区间。核心就几行：

```rust
for _ in 0..b_iter {                          // 重采样 2000 次
    let sample: Vec<&Sample> = (0..n)
        .map(|_| { let idx = (rng.unit()*n as f32) as usize % n; &imgs[idx] })
        .collect();                           // 有放回抽 n 张图
    vals.push(map_at(&sample, 0.5, false));   // 每次重算 mAP@0.5
}
vals.sort_by(|a, b| a.partial_cmp(b).unwrap());
let lo = vals[(0.025 * b_iter as f32) as usize];  // 2.5% 分位
let hi = vals[(0.975 * b_iter as f32) as usize];  // 97.5% 分位
```

实测（固定种子 → 完全可复现）：

```text
  点估计 mAP@0.5 = 0.6379
  bootstrap 均值=0.6458  标准误=0.0602  95% CI=[0.5244, 0.7585]
```

**真实 mAP 大概落在 [0.52, 0.76] 这么宽的区间里！** 回头看开头那 0.02 的差距——它比这个区间窄了一个数量级，几乎肯定淹没在噪声里。**报 0.64 而不报这个 CI，是不专业的。**

> ⚠️ **注意**：**bootstrap 必须按"独立采样单位"重采样。** 图像任务按图抽没问题；但**视频任务要按视频/片段抽，绝不能按帧抽**——同一段视频里相邻帧高度相关，按帧抽会把它们当独立样本，严重**低估方差**，给你一个假装很窄的置信区间。比较两个模型时用**配对 bootstrap**（每次重采样后两个模型在同一批样本上算，再比差值），因为它们本就在同一测试集上竞争。

切片（slice）维度至少应包括：类别、目标面积（大/中/小）、遮挡、光照、设备、地点、时间。**切片必须在看结果之前定义好**——否则你会忍不住事后专挑那个"提升明显"的分组来讲故事，这叫 cherry-picking，是自欺欺人。

## 48.4 标注质量审计

前面所有指标都默认了一件事：**GT 是对的**。可现实里标注常有漏标、错标、框松紧不一、类别定义含糊。**标注一脏，指标全乱**——而且往往是"模型没变，分数却掉了"，让人抓瞎。

我们做个可运行实验直接看：从干净数据集里**随机删掉一部分 GT**（模拟漏标），别的都不动，看 mAP 怎么变：

```text
  漏标  0%（删  0 个）: mAP@0.5 = 0.6379
  漏标  5%（删  4 个）: mAP@0.5 = 0.6205
  漏标 10%（删  8 个）: mAP@0.5 = 0.6056   ← 相对下降 5.1%
  漏标 20%（删 16 个）: mAP@0.5 = 0.5196
  漏标 30%（删 24 个）: mAP@0.5 = 0.4987
```

**只是漏标 10%，mAP 就从 0.6379 掉到 0.6056（相对降 5.1%）；漏标 30% 直接腰斩到 0.50。** 为什么模型没动分数却跌了？因为**被漏标的真实目标仍然被模型正确检出，却因为"查无此 GT"被评估器算成了误报（FP）**，白白拉低 precision。你以为模型退步了，其实是标注在背后捣鬼。错标、框松紧同理：都会制造冤假错案。

所以专家交付前会做**标注质量审计**，至少覆盖：

- **schema 检查**：类别是否越界、坐标是否越界、有没有负面积/零面积框、重复框、没有任何标注的孤立图片。
- **视觉抽检**：随机样本 + **高损失样本** + **模型与标注分歧大的样本** + 边界场景，人工过一遍。
- **一致性**：让两人独立标注同一批图（双标重叠集），算**类别一致率**、匹配框的 **IoU 分布**、**漏标率**；分歧高说明标注规范本身还不清晰。
- **版本追踪**：原标签**不可覆盖**，每次修订都记录**谁、为什么、何时、改了什么（diff）**。
- **泄漏检查**：用**感知哈希 / embedding 近邻**找出训练集和测试集里近乎重复的图，避免同一主体/视频/设备跨集造成"作弊式高分"。

> 🕳️ **坑**：**类别定义含糊是最隐蔽的毒药。** "自行车"算不算"电动车"？被截断一半的目标标不标？两个标注员理解不同，双标一致率就低，训练信号自相矛盾，指标也失去意义。**先把包含/排除规则、遮挡阈值、最小可见尺寸写成规范，再开始标**——这一步的投入回报率极高（详见 [第 47 章](ch47-train-detector.md)）。

## 常见坑与提示

> 🕳️ **坑**：**mAP 数字不可跨库直接比较。** COCO、VOC、YOLO 各家的 IoU 插值、类别 id 起点、面积分桶、crowd/ignore 规则都不一样。同一批预测在不同评估器上能差好几个点。写论文/报告时，把评估协议和代码版本一起钉死。

> ⚠️ **注意**：**空预测、空真值、边界要专门测。** 一张图没有任何 GT（纯背景）时，任何预测都是 FP；一张图模型没输出任何框时，所有 GT 都是 FN。评估器对这些退化情形不能崩、不能算错——给它们写单元测试。

> 💡 **提示**：**离线 mAP 涨了，不等于业务变好。** mAP 是排序质量的代理，线上真正花钱的是误报和漏检的**业务成本**。务必把离线指标的提升，翻译成"选定阈值后 FP/FN 降了多少、省了多少成本"再下结论。

> 📖 **术语**：**crowd / ignore 区域**——标注里标记为"一群密集目标，不逐个算"或"这块别管"的区域。评估时落在其中的预测既不算 TP 也不罚成 FP。忽略它的存在会莫名其妙多出一堆"误报"。

## 本章小结

- 检测评估从**匹配**开始：同类同图、IoU≥阈值、一个 GT 只配一次，判出 TP/FP/FN。
- **AP** 是 PR 曲线下面积，有 **11 点插值** 和 **全点积分** 两种约定，本章实测同批数据 mAP 分别为 0.6137 与 0.6379——**报数字必须说清协议**。
- **mAP@0.5**（0.6379）只问找没找到，**mAP@[.5:.95]**（0.3413）苛求定位精度，两者回答不同问题。
- **混淆矩阵 + 每类召回** 揭示总体 mAP 掩盖的关键类问题与类别混淆；选阈值应绑定**业务成本** \\( C_{FP}, C_{FN} \\)。
- **bootstrap 置信区间**：本章 mAP@0.5=0.6379，95% CI 却宽达 **[0.52, 0.76]**——不报 CI 就是不专业；视频任务要按视频（而非帧）重采样。
- **标注质量**直接毒化指标：仅漏标 10%，mAP 就掉 5.1%，30% 直接腰斩——被漏标的真检出会被冤枉成 FP。
- 交付前做**标注审计**（schema/抽检/一致性/版本/泄漏），预测框来自 [第 46](ch46-yolo-inference.md)/[47 章](ch47-train-detector.md)，匹配与 IoU 原理见 [第 45 章](ch45-detection-principles.md)。

## 动手练习

1. **换插值方式看差异**：把 `map_at` 的 `use_11` 在 true/false 间切换，确认 mAP@0.5 在 0.6137 与 0.6379 间变化，理解全点积分为何略高。
2. **加严 IoU**：把评估 IoU 阈值从 0.5 改到 0.75，观察 mAP 掉多少，体会 mAP@[.5:.95] 为什么比 mAP@0.5 低那么多。
3. **配对 bootstrap**：合成第二个"模型"的预测（把分数整体加一点噪声），实现配对 bootstrap，对两模型 mAP 的**差值**求 95% CI，判断差异是否显著。
4. **注入错标**：仿照 `inject_missing_labels`，写一个"把 10% 的 GT 类别改成邻类"的函数（模拟错标），看 mAP 和混淆矩阵怎么变，对比"漏标"与"错标"的破坏方式有何不同。

## 专家考核

从零实现一个小型 AP 评估器，并与权威实现（如 COCO API）对齐。测试必须覆盖：**重复预测、同分数、crowd 区域、空预测、空真值、边界框、最大检测数**。随后对两个模型执行**按视频配对 bootstrap**，报告总体、关键切片（至少含类别与目标面积）、置信区间和成本最优阈值；**没有统计证据时，必须明确写"无法确认提升"**，而不是把 0.64 vs 0.66 说成"B 更好"。最后做一轮标注审计，量化漏标率对 mAP 的影响，并给出修订与版本追踪方案。
