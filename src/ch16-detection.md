# 第 16 章 · 检测模型：YOLO 家族与 NMS 后处理

> **本章导读**：第 14 章我们把模型跑了起来，第 15 章解读了分类模型的输出。现在轮到全书的主角——**目标检测**。你会从推理引擎手里接过一个形状为 `float32[1, 84, 8400]` 的输出张量：70 多万个浮点数，密密麻麻，肉眼看不出任何"框"。本章只干一件事，但要干透：把这堆数字**完整解剖**成"图里有几个物体、分别是什么类别、各自框在哪、多大把握"。我们会逐维拆开 `[1, 84, 8400]`，讲清它那个坑人的内存布局，解码出每一个候选框，用置信度阈值砍掉绝大多数垃圾，再用 **NMS（非极大值抑制，Non-Maximum Suppression）** 去掉指向同一物体的重复框，最后把坐标从 640 的 letterbox 图一步步还原回原图像素。读完你能亲手写出一个可编译的 `postprocess` 函数——它是所有检测项目的心脏。

## 16.1 检测 vs 分类：多回答一个"在哪"

先分清两件事。

**分类（Classification）** 回答的是"**这张图是什么**"：喂进一张图，模型吐出"猫 92%、狗 5%、……"，一张图一个答案。这就像考试的单选题——整张图只给一个标签。第 15 章讲的就是它，模型通常先输出 logits，再由后处理用 Softmax 转成概率向量。

**检测（Detection）** 要同时回答两件事："**有什么**"+"**在哪**"。喂进一张监控画面，模型要告诉你："左上角有 1 个人（框在这），中间有 2 辆车（框在这、这），右下角有 1 条狗（框在这）"。它不是给整张图一个标签，而是给图里**每一个物体**一个"类别 + 位置框 + 置信度"。

打个比方：

- 分类像**门口的刷脸闸机**——只判断"是不是员工"，一个是非题。
- 检测像**保安巡逻点名**——扫一眼大厅，指出"那边站着 3 个人、门口停了 2 辆车"，每个都要圈出来、说清是什么。

多出来的这个"在哪"，就是本章所有麻烦的来源：模型没法只输出一个标签，它得输出**一大堆候选框**，我们再从中筛出真正的物体。位置用**边界框（Bounding Box，简称 bbox）** 表示，全书统一约定用**左上角-右下角** `(x1, y1, x2, y2)` 四个像素坐标（这个 `BBox` 类型最早见第 3.8 节）。本章的终点，就是把那 70 万个数字变成一小把干净的 `Detection`。

## 16.2 YOLO 家族简史：从"看两眼"到"看一眼"

检测算法早年是**两阶段（two-stage）** 的天下，代表是 **R-CNN** 系列（R-CNN → Fast R-CNN → Faster R-CNN）。它的思路很像人找东西：

1. 第一步**先圈出一堆"可疑区域"**（候选区域，region proposals）——"这几块看着像有东西"。
2. 第二步**再对每一块单独鉴定**——"这块是猫、那块是背景"。

准是准，但要"看两眼"（甚至上千次小分类），慢，难做到实时。

2015 年 **YOLO** 横空出世，名字就是它的宣言——**You Only Look Once（只看一眼）**。它是**单阶段（one-stage）** 检测器：一次前向传播，直接把整张图划成网格，**一口气输出所有位置的框和类别**，不再"先提议再鉴定"。快，能跑实时视频，这正是工程部署最看重的。我们全书的主模型 **YOLOv8** 就是这一脉。

| 维度 | 两阶段（R-CNN 系） | 单阶段（YOLO 系） |
| --- | --- | --- |
| 流程 | 先提候选区域，再逐个分类 | 一次前向直接出所有框 |
| 速度 | 慢 | 快，易实时 |
| 精度 | 早年略高 | 现已追平甚至反超 |
| 部署 | 流程重 | 简洁，本书主选 |

YOLO 自己也一路进化，这里只需知道大脉络（细节不是本章重点）：

- **v1（2015）**：把图划成网格，每格预测框——开创"看一眼"。
- **v2 / v3**：引入**多尺度**预测和 **anchor（锚框）**，小目标检出大幅改善。
- **v4 / v5**：工程集大成，训练技巧、速度、易用性拉满，v5 成为工业界事实标准之一。
- **v8（2023，Ultralytics）**：改用 **anchor-free（无锚框）** + **解耦检测头**，输出更简洁。这就是我们要解剖的 `[1, 84, 8400]`。

### anchor-based 与 anchor-free 的区别（简述）

早年的 v3~v5 是 **anchor-based（基于锚框）**：工程师预先设定好一批不同宽高比的"框模板"（比如瘦高的、扁宽的、方的），网络不直接预测框，而是预测"相对某个锚框模板要缩放/平移多少"。锚框的尺寸、数量都是要调的超参数，繁琐。

**YOLOv8 是 anchor-free（无锚框）**：干脆不要模板，网络**直接预测每个位置上框的中心和宽高**。少了锚框超参，输出也更干净——这正是为什么 v8 输出的那 84 个属性里没有锚框维度、也没有单独的 objectness 分数（下节详解）。你不用深挖锚框的数学，只要记住：**v8 拿到的框就是直接可用的中心宽高**。

> 推理引擎怎么把这个模型加载、跑出 output，见第 14 章；本章假设 `output` 已经握在手里了。

## 16.3 逐维解剖输出张量 `[1, 84, 8400]`

这是本章第一个重头。先把三个维度是什么摆出来：

```text
输出张量  float32[1, 84, 8400]
             │   │     └── 8400：候选框的个数（模型一共猜了这么多个框）
             │   └──────── 84  ：每个候选的属性数 = 4(框) + 80(类别分数)
             └──────────── 1   ：batch，一次处理一张图
```

### 8400 是怎么来的：三个尺度的网格之和

YOLOv8 在三个不同"粗细"的特征图上做预测（对应下采样步长 stride 8 / 16 / 32），密网格管小目标、疏网格管大目标：

```text
640×640 输入 → 三个检测头：

  stride 8  → 80×80 = 6400 格   网格最密，每格管 8×8 区域   → 小目标
  stride 16 → 40×40 = 1600 格   中等                        → 中目标
  stride 32 → 20×20 =  400 格   网格最疏，每格管 32×32 区域  → 大目标
  ────────────────────────────────────────────
  合计            6400 + 1600 + 400 = 8400 个候选
```

所以 **8400 = 80² + 40² + 20²**。每个网格位置（anchor-free 下每格出一个预测）贡献一个候选框，三张图拼起来正好 8400。你不需要知道某个候选具体落在哪张图的哪一格——后处理里我们平等对待这 8400 个候选，靠**置信度**和 **NMS** 去筛。

### 84 这一维：4 个框坐标 + 80 个类别分数

```text
第 0 个属性 : cx   ┐
第 1 个属性 : cy   │ 框：中心点 x/y + 宽 + 高（注意不是左上右下！）
第 2 个属性 : w    │
第 3 个属性 : h    ┘
第 4 个属性 : 类别0(person) 的分数
第 5 个属性 : 类别1(bicycle) 的分数
   ...
第 83 个属性: 类别79 的分数
```

**关键点 1：前 4 个是 `cx, cy, w, h`（中心 x、中心 y、宽、高），不是 `x1,y1,x2,y2`。** 这是新手第一个大坑，后面 16.5 专门转换。

**关键点 2：YOLOv8 没有单独的 objectness（有无物体）分数。** 对比一下：YOLOv5 的属性是 85 = 4 框 + **1 个 objectness** + 80 类，置信度要算 `objectness × 类别分`；而 v8 是 84 = 4 框 + 80 类。Ultralytics 常见导出的 ONNX 已在图内对类别 logits 做了 Sigmoid，后处理可**直接取 80 类里的最大分**当作这个候选的置信度。若使用其他导出链，先用 Netron 确认输出是否已经激活，避免漏做或重复做 Sigmoid。别把 v5 的公式套到 v8 上。

### 最坑的地方：内存布局

`[1, 84, 8400]` 在内存里是**行主序（C 连续）**排列的，也就是"**84 在外、8400 在内**"。摊平成一维数组后，是这样：

```text
内存里连续排列（属性优先，同一属性的 8400 个值挨在一起）：

  属性0(cx) : [ cx_0 , cx_1 , cx_2 , ... , cx_8399 ]  ← 连续 8400 个 cx
  属性1(cy) : [ cy_0 , cy_1 , cy_2 , ... , cy_8399 ]  ← 再连续 8400 个 cy
  属性2(w)  : [  w_0 ,  w_1 , ... ,               ]
  属性3(h)  : [  h_0 ,  h_1 , ... ,               ]
  属性4     : [ 类0的8400个分数 ...               ]
    ...
  属性83    : [ 类79的8400个分数 ...              ]

flat 下标： 0        1        ...   8399  8400   8401 ...
           └──────── 属性0 的 8400 个 ────┘└─ 属性1 开始 ─
```

这意味着：**同一个属性跨 8400 个候选是连续的；而同一个候选的 84 个属性是"竖着"散开的、彼此相隔 8400 个元素**。

想取"**第 i 个候选**"的第 c 个属性，正确的下标是：

```text
flat[c * 8400 + i]     ✅ 正确：先跳到第 c 个属性块，再偏移 i
flat[i * 84 + c]       ❌ 错误：这是 [1,8400,84] 布局的取法
```

用错这个下标，取出来的全是张冠李戴的乱数，框会飞得到处都是，还特别难 debug（不报错、只是结果不对）。记住口诀：**属性乘 8400，再加候选号**。

```rust,ignore
const NUM_ANCHORS: usize = 8400; // 候选框个数
const NUM_CLASSES: usize = 80;   // COCO 类别数
const NUM_ATTRS:   usize = 4 + NUM_CLASSES; // = 84

// output 是展平后的 [1,84,8400]，长度应为 84*8400
// 取“第 c 个属性、第 i 个候选”就这一行：
#[inline]
fn at(output: &[f32], c: usize, i: usize) -> f32 {
    output[c * NUM_ANCHORS + i] // 属性 c 的块起点是 c*8400，再偏移 i
}
```

> 极少数导出工具会把输出转成 `[1, 8400, 84]`（84 在最后一维），那时取法就变成 `flat[i*84 + c]`。上线前务必先打印一次 shape 确认布局（怎么读 shape / 元数据见第 12 章），别凭记忆写死。

## 16.4 解码一个候选框

有了正确的取值方式，解码单个候选就水到渠成了：取出 `cx,cy,w,h`，再在 80 个类别分里找最大值（**argmax**），最大值就是这个候选的**置信度**，对应的下标就是 **class_id**。

```rust,ignore
/// 从展平的 [1,84,8400] 里解码第 i 个候选
/// 返回 (cx, cy, w, h, class_id, score)，坐标此刻还在 640 letterbox 坐标系里
fn decode_one(output: &[f32], i: usize) -> (f32, f32, f32, f32, usize, f32) {
    // 框：cx, cy, w, h —— 每跳一个属性，下标要跨 8400 个元素
    let cx = output[0 * NUM_ANCHORS + i];
    let cy = output[1 * NUM_ANCHORS + i];
    let w  = output[2 * NUM_ANCHORS + i];
    let h  = output[3 * NUM_ANCHORS + i];

    // 80 个类别分里挑最大的：谁最大，这个候选就判给谁
    let mut class_id = 0usize;
    let mut score = 0.0f32;
    for j in 0..NUM_CLASSES {
        let s = output[(4 + j) * NUM_ANCHORS + i]; // 第 (4+j) 个属性
        if s > score {
            score = s;
            class_id = j;
        }
    }
    (cx, cy, w, h, class_id, score)
}
```

几个要点：

- **类别分就是置信度**：v8 无 objectness，`score` 直接是 80 类里的最大分，不用再乘任何东西。
- **argmax 给类别号**：最大分对应的 `j` 就是 COCO 类别号（`person=0`、`car=2`、`cat=15`、`dog=16` …）。
- **分数已经是 0~1**：标准 Ultralytics 导出的 ONNX **已经对类别分做过 Sigmoid**，框坐标也已解码到 640 尺度，所以我们拿到的分数可直接比较、坐标可直接用。若你用的是某些"裸"导出没做 Sigmoid，分数会是很大/很小的 logit，需要自己补一层 `1/(1+e^-x)`——同样，上线前确认一次。

这一步做完，8400 个候选每个都变成了一条 `(cx, cy, w, h, class_id, score)`。但它们大多是垃圾（分数极低的背景），而且坐标还在 640 的 letterbox 图里、还是中心宽高格式。接下来三节把它们收拾干净。

## 16.5 坐标反算：从 640 letterbox 回到原图像素

模型输出的 `cx, cy, w, h` 是在 **640×640 的 letterbox 图**坐标系里的，不是原图坐标。要还原，得把第 10 章预处理做的事**倒着做一遍**。

先回忆第 10 章：**letterbox（等比缩放后用灰边填充到目标尺寸）** 把原图按同一个比例 `scale` 缩放，再在短边两侧补灰边（padding）凑够 640×640。它给了我们两个关键数：

- `scale`：缩放比（原图 → 640，`scale = min(640/原宽, 640/原高)`）。
- `pad = (pad_x, pad_y)`：左侧、上方各填充了多少像素。

反算分两步：

**第一步：中心宽高 → 左上右下（仍在 640 坐标系）。**

$$x_1 = c_x - \frac{w}{2},\quad y_1 = c_y - \frac{h}{2},\quad x_2 = c_x + \frac{w}{2},\quad y_2 = c_y + \frac{h}{2}$$

**第二步：去掉 letterbox 的影响——先减填充，再除以缩放比。**

$$x_{\text{原}} = \frac{x_{640} - \text{pad\_x}}{\text{scale}},\qquad y_{\text{原}} = \frac{y_{640} - \text{pad\_y}}{\text{scale}}$$

直觉：预处理是"先缩放、再往右下推 pad"，那还原就得"先把 pad 推回来（减 pad）、再放大回去（除 scale）"。顺序反了或漏了一步，框就会整体偏移或缩放不对。

拿个小数字走一遍。设原图 1280×720，`scale = 640/1280 = 0.5`，缩放后是 640×360，上下各补 `(640-360)/2 = 140` 的灰边，于是 `pad = (0, 140)`。模型给出某框中心宽高 `cx=320, cy=180, w=100, h=200`（640 坐标系）：

- 转角点：`x1=270, y1=80, x2=370, y2=280`。
- 去 letterbox：`x1' = (270-0)/0.5 = 540`，`y1' = (80-140)/0.5 = -120`，`x2' = (370-0)/0.5 = 740`，`y2' = (280-140)/0.5 = 280`。

得到原图坐标 `(540, -120, 740, 280)`。注意 `y1` 成了负数——框顶超出了图像上边界，这在贴边物体上很常见，生产里会再 clamp（裁剪）到图像范围内。

统一用第 3.8 节引入的 `BBox`（左上右下），写出反算函数：

```rust,ignore
/// 边界框：左上-右下像素坐标（全书统一类型，见第 3.8 节）
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct BBox {
    pub x1: f32,
    pub y1: f32,
    pub x2: f32,
    pub y2: f32,
}

/// 把 640 letterbox 坐标系下的 (cx,cy,w,h) 还原成原图像素的 BBox
fn to_original_bbox(cx: f32, cy: f32, w: f32, h: f32, scale: f32, pad: (f32, f32)) -> BBox {
    // 第一步：中心宽高 → 左上右下（仍在 640 坐标系）
    let x1 = cx - w / 2.0;
    let y1 = cy - h / 2.0;
    let x2 = cx + w / 2.0;
    let y2 = cy + h / 2.0;
    // 第二步：减 padding、除以缩放比 → 原图像素坐标
    let (pad_x, pad_y) = pad;
    BBox {
        x1: (x1 - pad_x) / scale,
        y1: (y1 - pad_y) / scale,
        x2: (x2 - pad_x) / scale,
        y2: (y2 - pad_y) / scale,
    }
}
```

> 生产环境里通常还会把结果 **clamp 到 `[0, 原宽] × [0, 原高]`**，避免出现上面那种负坐标或超出右/下边界的框（那需要额外传入原图宽高，见本章练习）。这里先保持反算逻辑纯粹。

## 16.6 置信度阈值：先砍掉一大片垃圾

8400 个候选里，绝大多数是"这里啥也没有"的背景，分数极低（0.01、0.03……）。全部留着送进 NMS 又慢又没意义。所以解码时顺手做**置信度阈值过滤**：分数低于阈值（常用 `conf = 0.25`）的直接扔掉。

```rust,ignore
// 伪代码示意，完整版见 16.8
if score < conf {
    continue; // 这个候选不要了
}
```

这一刀通常能把 8400 个砍到几十到几百个，NMS 的负担骤降。阈值怎么定是个工程权衡：

| conf 阈值 | 后果 |
| --- | --- |
| 太高（如 0.6） | 弱小/遮挡目标被误杀，**漏检**增多 |
| 太低（如 0.05） | 一堆假框涌入，误检多、NMS 也变慢 |
| 常用 0.25 | 通用场景的经验起点，按业务再调 |

> 一个细节：跑精度评测（算 mAP）时会把阈值压到极低（如 0.001）以保留所有候选交给指标；而线上实际部署用 0.25 左右。别把评测阈值直接搬到线上。

## 16.7 NMS：一堆重叠框里选代表

这是本章第二个重头。过完置信度阈值，你会发现**同一个物体常被好几个框同时命中**——一条狗周围可能围着 5、6 个高度重叠、分数都不低的框。因为相邻的网格都觉得"这狗有我一份"，纷纷举手。我们要的是**一个物体一个框**，于是需要 **NMS（非极大值抑制）**。

生活比喻：**一群人举手争当"这个物体的代表"**。NMS 的做法是——先让**嗓门最大的**（置信度最高的框）当代表、保留下来；然后把**和他站得太近的**（重叠度太高的框）全都请下去（它们说的是同一个物体）；在剩下的人里再选下一个代表，如此反复，直到没人。

### IoU：怎么量"两个框有多重叠"

判断"站得近不近"，用 **IoU（交并比，Intersection over Union）**：两个框的**交集面积**除以**并集面积**。

$$\text{IoU} = \frac{\text{交集面积}}{\text{并集面积}} = \frac{A \cap B}{A \cup B}$$

IoU=0 表示完全不挨着，IoU=1 表示两个框完全重合。**手算一遍**才踏实——设两个框都在同一辆车上：

```text
框 A (score 0.92): (x1,y1,x2,y2) = (100, 100, 200, 200)   宽100 高100
框 B (score 0.85): (x1,y1,x2,y2) = (120, 100, 220, 200)   宽100 高100（右移了 20）
```

- 各自面积：`A = 100×100 = 10000`，`B = 100×100 = 10000`。
- 交集矩形：左上取两者较大者、右下取较小者
  - `ix1 = max(100,120) = 120`，`iy1 = max(100,100) = 100`
  - `ix2 = min(200,220) = 200`，`iy2 = min(200,200) = 200`
  - 交集宽 `= 200-120 = 80`，高 `= 200-100 = 100`
  - **交集面积 = 80 × 100 = 8000**
- 并集面积 `= A + B - 交集 = 10000 + 10000 - 8000 = 12000`
- **IoU = 8000 / 12000 = 0.667**

0.667 是个很高的重叠度——这俩框八成指着同一辆车。若 NMS 阈值取 0.5，B 就会被分数更高的 A 压制掉。反过来，如果两个框只是稍微擦边（IoU 0.1），说明是两个不同物体，谁也不该压制谁。

给统一类型 `BBox` 补上方法（`width/height/area/center/iou`）：

```rust,ignore
impl BBox {
    pub fn width(&self)  -> f32 { (self.x2 - self.x1).max(0.0) } // 退化框宽记 0
    pub fn height(&self) -> f32 { (self.y2 - self.y1).max(0.0) }
    pub fn area(&self)   -> f32 { self.width() * self.height() }
    pub fn center(&self) -> (f32, f32) {
        ((self.x1 + self.x2) / 2.0, (self.y1 + self.y2) / 2.0)
    }

    /// 交并比 IoU = 交集面积 / 并集面积
    pub fn iou(&self, other: &BBox) -> f32 {
        // 交集矩形：左上取较大、右下取较小
        let ix1 = self.x1.max(other.x1);
        let iy1 = self.y1.max(other.y1);
        let ix2 = self.x2.min(other.x2);
        let iy2 = self.y2.min(other.y2);
        // 不重叠时宽或高会 <=0，用 max(0) 归零
        let iw = (ix2 - ix1).max(0.0);
        let ih = (iy2 - iy1).max(0.0);
        let inter = iw * ih;
        if inter <= 0.0 {
            return 0.0;
        }
        let union = self.area() + other.area() - inter;
        inter / union
    }
}
```

### 标准 NMS 的四步

1. 把所有框**按置信度从高到低排序**。
2. 取出当前分数最高的框，作为"代表"**保留**。
3. 计算它与其余每个框的 **IoU**，把 IoU **超过阈值**的框全部删掉（它们和代表指向同一物体）。
4. 在剩下的框里回到第 2 步，直到没有框剩下。

用本章统一的 `Detection` 类型实现，写法上换个等价的贪心角度：**按分数降序遍历，每个框只和"已保留"的比，若和任一已保留框重叠过高就丢弃**（能丢它的一定分更高，逻辑等价、还更好读）：

```rust,ignore
/// 一个检测结果（从本章起供后续章节复用）
#[derive(Clone, Debug)]
pub struct Detection {
    pub bbox: BBox,
    pub score: f32,      // 置信度 0~1
    pub class_id: usize, // COCO 类别号
}

/// 标准 NMS：对“同一类别”的一组框做非极大值抑制，返回保留下来的框
fn nms_single_class(mut dets: Vec<Detection>, iou_thr: f32) -> Vec<Detection> {
    // 第 1 步：按分数从高到低排序（total_cmp 对 NaN 也安全，不会 panic）
    dets.sort_by(|a, b| b.score.total_cmp(&a.score));

    let mut keep: Vec<Detection> = Vec::new();
    'next: for det in dets {
        // 和每个已保留的“代表”比 IoU，太近就说明是同一物体，压掉
        for k in &keep {
            if det.bbox.iou(&k.bbox) > iou_thr {
                continue 'next; // 被压制，直接看下一个候选
            }
        }
        keep.push(det); // 没和任何代表冲突，它自己也当代表
    }
    keep
}
```

### 按类 NMS vs 全局 NMS

上面处理的是**同一类别**。为什么要分类别？想象一个人牵着一条狗，人框和狗框可能高度重叠（IoU 0.7）——但它们是**两个不同类别的真实物体**，绝不能因为重叠就删掉一个。所以通用检测都用**按类 NMS**：先按 `class_id` 分组，**每一类各做各的 NMS**，组间互不干扰。

```rust,ignore
use std::collections::HashMap;

/// 按类别分别做 NMS：不同类别的框互不抑制
fn nms_per_class(dets: Vec<Detection>, iou_thr: f32) -> Vec<Detection> {
    // 按 class_id 分组
    let mut groups: HashMap<usize, Vec<Detection>> = HashMap::new();
    for d in dets {
        groups.entry(d.class_id).or_default().push(d);
    }
    // 每组各自 NMS，再把结果合并
    let mut result = Vec::new();
    for (_class_id, group) in groups {
        result.extend(nms_single_class(group, iou_thr));
    }
    result
}
```

**全局 NMS（不分类别）** 只在特定场景用——比如"同一个位置物理上只可能有一个物体"，此时跨类别的重叠框也该去重。通用检测请默认按类。

### 顺带一提：Soft-NMS

标准 NMS 是"一刀切"：重叠超阈值就**直接删**。在极拥挤场景（一堆人挤在一起）里，两个真人的框本就重叠很高，硬删会**误杀**、导致漏检。**Soft-NMS** 改成"温柔一点"：不直接删，而是**按 IoU 给重叠框的分数打个折**（IoU 越大，分数衰减越多），让它降权而不消失，最后再靠分数阈值收尾。密集人群里能少漏几个。知道有这么个变体即可，工程上先用标准 NMS 起步。

## 16.8 完整后处理：四步串成一条流水线

现在把四步——**解码 → 置信度阈值 → 坐标还原 → NMS**——接成一条完整流水线：

```text
[1,84,8400]  ──解码 argmax──▶  8400 个 (cx,cy,w,h,class,score)
                                    │
                            置信度阈值 (conf=0.25)
                                    ▼
                            剩几十~几百个候选
                                    │
                        坐标还原 (减 pad / ÷ scale, cxcywh→xyxy)
                                    ▼
                        原图像素坐标的 Detection 列表
                                    │
                        按类别 NMS (IoU > iou_thr 去重)
                                    ▼
                    最终几个干净的框 → Vec<Detection>
```

对应任务给定的函数签名，一把梭：

```rust,ignore
const NUM_ANCHORS: usize = 8400;
const NUM_CLASSES: usize = 80;
const NUM_ATTRS:   usize = 4 + NUM_CLASSES; // = 84

/// 检测后处理全流程：解码 → 阈值 → 坐标还原 → NMS
/// - output : 展平的 [1,84,8400]（长度应为 84*8400）
/// - scale  : letterbox 缩放比（原图 → 640）
/// - pad    : letterbox 左/上填充量 (pad_x, pad_y)
/// - conf   : 置信度阈值，如 0.25
/// - iou_thr: NMS 的 IoU 阈值，如 0.45
fn postprocess(
    output: &[f32],
    scale: f32,
    pad: (f32, f32),
    conf: f32,
    iou_thr: f32,
) -> Vec<Detection> {
    assert_eq!(output.len(), NUM_ATTRS * NUM_ANCHORS, "输出长度和 84*8400 对不上");

    // 取“第 c 个属性、第 i 个候选”：核心就这一行，别写成 output[i*84+c]
    let at = |c: usize, i: usize| output[c * NUM_ANCHORS + i];

    let mut dets: Vec<Detection> = Vec::new();

    // 第一 + 第二步：逐候选解码 + 置信度过滤
    for i in 0..NUM_ANCHORS {
        // 80 类里取最大分（v8 无 objectness，最大分即置信度）
        let mut class_id = 0usize;
        let mut score = 0.0f32;
        for j in 0..NUM_CLASSES {
            let s = at(4 + j, i);
            if s > score {
                score = s;
                class_id = j;
            }
        }
        if score < conf {
            continue; // 绝大多数候选在这里被丢掉，省得后面白算
        }

        // 第三步：坐标还原（cx,cy,w,h @640 → 原图 x1,y1,x2,y2）
        let (cx, cy, w, h) = (at(0, i), at(1, i), at(2, i), at(3, i));
        let bbox = to_original_bbox(cx, cy, w, h, scale, pad);

        dets.push(Detection { bbox, score, class_id });
    }

    // 第四步：按类别 NMS 去重
    nms_per_class(dets, iou_thr)
}
```

把本章的 `BBox`（含 `impl`）、`Detection`、`to_original_bbox`、`nms_single_class`、`nms_per_class`、`postprocess` 放进一个模块就能编译。调用方拿到的 `Vec<Detection>`，每个都是**原图像素坐标、类别明确、去过重**的干净结果——可以直接画框（`imageproc` 画矩形）、送去跟踪（第 21 章）或喂给业务过滤器。一个典型调用：

```rust,ignore
// scale、pad 来自第 10 章 letterbox 预处理时记下的值；output 来自第 14 章推理
let dets = postprocess(&output, scale, pad, 0.25, 0.45);
for d in &dets {
    println!("class={} score={:.2} box=({:.0},{:.0},{:.0},{:.0})",
             d.class_id, d.score, d.bbox.x1, d.bbox.y1, d.bbox.x2, d.bbox.y2);
}
```

> 工程上通常还会在解码循环里用**预分配 + 迭代器**减少分配，或按类别用**数组分桶**替代 `HashMap` 提速；NMS 也有基于面积排序的加速写法。这些优化在候选量大、要跑高帧率时再上，先保证上面这版**正确、看得懂**。

## 16.9 工程坑位清单

检测后处理是全书最容易"跑通了但结果不对"的地方——不报错，框却乱飞。逐条对照排查：

| 坑 | 症状 | 正解 |
| --- | --- | --- |
| **cxcywh 当成 xyxy** | 框位置、大小全错，缩在左上角 | 前 4 维是中心宽高，先 `x1=cx-w/2` 转角点（16.5） |
| **内存布局取反** | 数值张冠李戴，框满天飞 | 用 `output[c*8400 + i]`，不是 `i*84 + c`（16.3） |
| **忘记减 pad / 除 scale** | 框整体偏移或大小不对，套不准原图 | 反算两步都要做，pad 只在填充那一侧（16.5） |
| **套用 v5 的置信度公式** | 分数偏低或多乘了不存在的通道 | v8 无 objectness，直接取 80 类最大分（16.4） |
| **忘了 Sigmoid（个别裸导出）** | 分数是很大/很小的 logit，阈值全失效 | 确认导出是否已激活，没有就自己补（16.4） |
| **全局 NMS 而非按类** | 重叠的人和狗被误删一个 | 按 `class_id` 分组分别 NMS（16.7） |
| **conf / iou_thr 调反或不调** | conf 太低→候选爆炸变慢；iou_thr 太小→密集目标漏检 | 通用起点 conf≈0.25、iou_thr≈0.45，按业务调（16.6/16.7） |
| **假设输出布局** | 换个导出版本结果就全乱 | 上线前打印 shape 确认是 `[1,84,8400]` 还是 `[1,8400,84]`（第 12 章） |

## 16.10 小结

- **检测 = 分类 + 定位**：不只回答"是什么"，还要回答"在哪"，所以输出是**一堆候选框**而非一个标签。
- **`[1,84,8400]` 逐维解读**：8400 = 80²+40²+20²（三尺度网格，管大中小目标）；84 = 4 个框(cx,cy,w,h) + 80 类分数；v8 **无 objectness**，取 80 类最大分即置信度。
- **内存布局是头号坑**：属性优先连续，取第 i 个候选的第 c 个属性要用 `output[c*8400 + i]`，写成 `i*84+c` 会全乱。
- **坐标反算**：`cx,cy,w,h → x1,y1,x2,y2`，再**减 pad、除 scale** 从 640 letterbox 图还原到原图像素（呼应第 10 章）。
- **两把筛子**：先用**置信度阈值**砍掉绝大多数垃圾候选，再用 **NMS**（按 IoU 去重、**按类别**分组）把同一物体的重复框收成一个。
- **`postprocess` 一条龙**：解码 → 阈值 → 还原 → NMS，产出原图坐标、去重后的 `Vec<Detection>`，就是所有检测应用的入口。

下一章（第 17 章）会把"框"升级成"骨架"——关键点与姿态估计；而拿到干净的框之后如何跨帧关联、给每个目标一个稳定 ID，是第 21 章多目标跟踪的主题。

## 16.11 练习

1. **手算并验证 IoU**：给两个框 `A=(10,10,50,50)`、`B=(30,30,70,70)`，手算它们的交集面积、并集面积和 IoU（提示：结果是 `1/7≈0.143`）。再用本章的 `BBox::iou` 写个测试对照，确认代码和手算一致。
2. **索引陷阱实测**：写一个函数从 `[1,84,8400]` 里取出"第 5000 个候选"的全部 84 个属性，返回 `Vec<f32>`；再故意用错误的 `output[i*84+c]` 取一遍，打印两者对比，直观感受布局取错会得到什么。
3. **给 `postprocess` 加 clamp**：新增 `orig_w`、`orig_h` 两个参数，把还原后的框裁剪到 `[0,orig_w] × [0,orig_h]`。想一想：为什么贴边的大目标常会出现 `x2 > orig_w` 或 `y1 < 0`？
4. **改造成 Soft-NMS**：把 `nms_single_class` 里"直接丢弃"改成"按 `score *= 1.0 - iou` 衰减分数、最后再按分数阈值过滤"，用几个高度重叠的框对比标准 NMS 与 Soft-NMS 的保留结果，体会密集场景下的差异。
