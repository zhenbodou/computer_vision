# 第 88 章 区域入侵、停留（dwell）与目标计数

> **本章导读**
> - 学完你能：在画面里圈一片区域（ROI），做出三条最常用的安防规则——**闯入**、**停留超时**、**区内人数统计**。
> - 闯入 = 脚点**进入 ROI 的那一刻**触发；停留 = 在区内**持续待够 T 秒**才告警；计数 = 实时数**此刻区内有几个目标**。
> - 停留时长**基于 `track` 历史**算：进区时间戳与当前时间戳一减即得，还要处理"短暂离开又回来"的 gap 容忍。
> - 站在[第 84 章](ch84-roi-filter.md) ROI（射线法点在多边形内）与[第 87 章](ch87-tripwire.md)过线思想之上；数据模型仍用[第 83 章](ch83-filtering-basics.md)的 `BBox` / `Track` / `Event`。

## 场景：保险柜前有人逗留、排队区人满为患

上一章的绊线管的是"经过"——过了线就记一笔。但很多安防需求关心的不是"经过"，而是"**进入并停留在某片区域里**"：

- **闯入**：仓库夜间布防，任何人踏进警戒区就立刻报警；
- **停留 dwell**：银行大厅里，有人在**保险柜前逗留超过 30 秒**——路过没事，赖着不走就值得警惕；
- **区内计数**：排队区里**同时超过 5 个人**就提示开新窗口；电梯轿厢超载预警也是同一类。

这三条规则都建立在同一个基础上：一片**感兴趣区域（ROI，Region of Interest）**，通常是画面里的一个多边形。判断"目标在不在区内"，我们复用[第 84 章](ch84-roi-filter.md)的**射线法**——把目标脚点 `bottom_center()` 丢进 `point_in_polygon`，在里面返回 `true`。本章的新东西，是把"在不在区内"这个**瞬时**判断，升级成"**何时进入**（闯入）、**待了多久**（停留）、**此刻几个**（计数）"这三种**带时间维度**的规则。

## 原理一：闯入 = 进入沿触发

"闯入"听起来就是"在区内"，但如果每一帧只要目标在区内就报一次，一个人站那儿不动，10fps 的画面一秒能报 10 次——这显然不行。正确的语义是**边沿触发（edge trigger）**：只在目标**从区外进到区内的那一刻**报一次，进来之后一直待着不再重复报。

这和[第 87 章](ch87-tripwire.md)的"过线"是同一个思想——我们关心的是**状态的跳变**（区外→区内），而不是状态本身。用一个"上一帧在不在区内"的记忆，比较它和这一帧，就能抓住这个上升沿。

```text
   区外 ──进入沿(报闯入!)──► 区内 ─── 区内 ─── 区内 ──离开── 区外
   inside=false            true      true      true          false
                ▲报一次                                  (整段只报这一次)
```

## 原理二：停留 dwell = 基于 track 历史算时长

停留时长怎么算？很简单：**记住目标进区的时间戳 `enter_ts`，用当前时间戳一减就是已停留时长**。

\\[ \text{dwell} = \text{ts\_now} - \text{enter\_ts} \\]

当 `dwell` 第一次 \\( \ge T \\)（比如 30 秒）就发一次停留告警。因为 `Track.history` 里存的正是一串按时间递增的 \\( (\text{ts\_ms}, \text{bbox}) \\)，这件事完全**基于轨迹历史**离线就能算——扫一遍历史，找到脚点进入 ROI 的那一点当 `enter_ts`，找到最后仍在区内的那一点当 `last_ts`，两者之差就是本次停留时长。

真正的坑在于**"短暂离开又回来"**。目标被别的东西挡了一下、或检测器漏了两帧，脚点会瞬间"离开"ROI 再"回来"。如果一出区就把 `enter_ts` 清零，那么一个在保险柜前站了半分钟、中间只是转了下身被挡一下的人，永远也攒不够 30 秒，停留告警就漏报了。解法是 **gap 容忍**：两个"在区内"的采样点之间，只要时间间隔不超过一个容忍阈值（比如 3 秒），就当作**同一次停留**，中间那点闪失既不清零计时、也不重复报闯入。

```text
  在区内:  ● ● ● ●   (漏检2帧)   ● ● ● ● ● ● ● ●
  ts:      3s ...   15.5s ┄┄ 17s ...              35.5s
                     └── gap=1.5s ≤ 容忍3s → 仍算同一次停留 ──┘
  dwell = 35.5s - 3s = 32.5s   ✅ 超过 30s，告警
  (若不容忍：被切成 12.5s + 18.5s 两段，都不够 30s → 漏报!)
```

## 原理三：区内计数 = 每个时刻数一次

计数最直接：对**每一个时间戳**，数一数有多少个**不同 `track_id`** 的脚点此刻落在 ROI 内。它是**瞬时**量，会随人进人出上下波动。要注意计数用的是"**此刻真的被检测到在区内**"（物理在场），这和停留用的"**逻辑在场**（gap 容忍内视作没走）"是两回事——漏检那两帧，计数会如实地少一个人，但停留计时不受影响。

## 动手写代码：闯入 + 停留 + 计数

示例**只用 std**，输入是合成的、带 `track_id` 的 `Vec<Track>`（时间戳自造递增值，2fps，不读系统时钟），可复现。运行：

```bash
cargo run --example ch88_intrusion_dwell
```

判"脚点在不在 ROI"直接搬[第 84 章](ch84-roi-filter.md)的 `point_in_polygon`（射线法），不再赘述。核心新逻辑是**把一条轨迹切成若干次"区内停留"**，gap 容忍就体现在这里：

```rust
/// 把 track 历史切成若干次「在 ROI 内的停留」：(进入 ts, 最后在区内 ts)。
/// 相邻两个「在区内」的采样点，时间间隔 ≤ gap_ms 就算同一次停留。
fn roi_visits(t: &Track, roi: &[(f32, f32)], gap_ms: u64) -> Vec<(u64, u64)> {
    let mut visits = Vec::new();
    let mut cur: Option<(u64, u64)> = None; // (enter_ts, last_in_ts)
    for &(ts, b) in &t.history {
        if !foot_in_roi(&b, roi) { continue; } // 出区的点不参与，间隔按“区内点之间”算
        match cur {
            Some((enter, last)) if ts.saturating_sub(last) <= gap_ms => cur = Some((enter, ts)),
            _ => { if let Some(v) = cur { visits.push(v); } cur = Some((ts, ts)); }
        }
    }
    if let Some(v) = cur { visits.push(v); }
    visits
}
```

有了每次停留的 `(enter, last)`，闯入和停留两条规则就水到渠成——每次停留的开始报一次闯入，时长够 T 就报停留：

```rust
for (enter, last) in roi_visits(t, roi, gap_ms) {
    events.push(Event { kind: "intrusion".into(), ts_ms: enter, /* 进入沿 */ .. });
    let dwell = last - enter;
    if dwell >= dwell_ms {              // dwell_ms = 阈值 T
        let fire_ts = enter + dwell_ms; // 计时第一次达到 T 的时刻
        events.push(Event { kind: "dwell".into(), ts_ms: fire_ts, /* 停留超时 */ .. });
    }
}
```

区内计数则按时间戳汇总——每个 `ts` 数一遍有几个脚点在区内，再找峰值、抓"人数达标"的上升沿报拥挤：

```rust
for t in &tracks {
    for &(ts, b) in &t.history {
        if foot_in_roi(&b, roi) { *count_at.get_mut(&ts).unwrap() += 1; }
    }
}
let peak = count_at.values().copied().max().unwrap_or(0);
```

合成的 5 条轨迹故意各有分工：track#7 在保险柜前逗留很久（还中途漏检 2 帧）、track#1 快速穿过、track#8 中等停留（卡在阈值下方）、track#2 短暂经过顶高人数、track#3 全程在区外（负样本）。运行输出（数字真实可复现）：

```text
== ①② 入侵 & 停留事件（gap 容忍 3s）==
  [intrusion] t=  3.0s track=7  track#7 进入 ROI
  [intrusion] t=  6.0s track=1  track#1 进入 ROI
  [intrusion] t= 11.0s track=8  track#8 进入 ROI
  [intrusion] t= 21.0s track=2  track#2 进入 ROI
  [dwell    ] t= 33.0s track=7  track#7 停留超时：本次共停留 32.5s（≥ 阈值 30s）
  小计：入侵 4 次，停留告警 1 次

== 各 track 在 ROI 内的停留时长（基于 history）==
  track#7 person: 进入 t=3.0s，停留 32.5s → 超过阈值，触发 dwell 告警 ✔
  track#1 person: 进入 t=6.0s，停留 3.0s
  track#8 person: 进入 t=11.0s，停留 19.5s
  track#2 person: 进入 t=21.0s，停留 6.0s
  track#3 person: 从未进入 ROI

== 坑：gap 容忍的重要性（track#7 中途漏检 2 帧）==
  开启 gap 容忍(3s)：track#7 视作一次停留 32.5s → 停留告警 1 次，入侵 1 次
  关闭 gap 容忍     ：漏检把停留切成两段(12.5s+18.5s)，都不够 30s → 停留告警 0 次，track#7 入侵被拆成 2 次

== ③ 区内实时人数（峰值 3 人）==
  人数变化时间线：1.0s:0人  3.0s:1人  6.0s:2人  9.5s:1人  11.0s:2人  16.0s:1人  17.0s:2人  21.0s:3人  27.5s:2人  31.0s:1人  36.0s:0人
  拥挤告警（人数 ≥ 3）：
    [crowd] t=21.0s  区内目标数达到 3 人（≥ 阈值 3）
```

读一读这份输出：4 个目标进区各报一次闯入；只有 **track#7 停留 32.5s 超过 30s 阈值**，触发 dwell 告警（在 33.0s、计时刚满 30s 那一刻发出），而停了 19.5s 的 track#8 差一口气、不报——阈值把"路过"和"逗留"清清楚楚分开了。人数时间线里那个 `16.0s:1人` 的凹陷，正是 track#7 漏检两帧的瞬间：**计数如实少了一人，但它的停留计时靠 gap 容忍并没有断**，最终仍算作连续的 32.5s。而一旦关掉 gap 容忍，track#7 的停留被漏检切成 12.5s + 18.5s 两段，**双双不够 30 秒，告警直接漏掉**，闯入也被误拆成 2 次——这就是 gap 容忍存在的意义。

## 常见坑与提示

> 🕳️ **坑**：**dwell 计时不能"一出区就清零"，要有 gap 容忍。** 遮挡、漏检会让脚点瞬间"离开"再"回来"。没有 gap 容忍，长时间逗留者永远攒不够时长，停留告警成片漏报（本例关掉容忍后 track#7 就漏了）。容忍阈值取多大看场景：几帧的漏检给 1～3 秒足矣，真离开了几十秒当然要当新的一次。

> ⚠️ **注意**：**闯入要用"进入沿"触发，别每帧都报。** 目标进区后会持续待在里面，逐帧判"在区内"会刷屏。记一个"上一帧在不在区内"的状态、只在 `false→true` 跳变时报一次；离开再进来才算新的一次（这点和第 87 章的过线上升沿、[第 85 章](ch85-temporal-window.md)的状态机确认是一脉相承的）。

> 🕳️ **坑**：**计数要按 `track_id` 去重，别数框。** 检测器可能把一个人吐成两个重叠框（见[第 86 章](ch86-cooldown-dedup.md)的同帧 NMS），不去重就会把 1 个人数成 2 个。以稳定的 `track_id` 为准，一个 id 此刻在区内只算一个人。

> 💡 **提示**：**"在不在区内"一律用脚点 `bottom_center()`。** 和过线、ROI 过滤一样：人站在地面上，脚点才是它真正占据的位置。用框中心会让还没踏进区域、只是身子探进来的人被误判为"已进入"——[第 84 章](ch84-roi-filter.md)专门演示过这个脚点 vs 中心的差异。

> ⚠️ **注意**：**停留计时用的是数据里的 `ts_ms`，不是系统时钟。** 离线分析录像时，时间必须来自帧的时间戳，`ts_now - enter_ts` 才准。只有真正跑实时流、且要和现实时钟对齐（比如告警里写"北京时间几点"）时，才另取 `std::time::SystemTime`——本部分示例一律用合成递增 `ts_ms`，保证可复现。

## 本章小结

- **ROI + 脚点**是三条规则的共同地基：把脚点 `bottom_center()` 丢进[第 84 章](ch84-roi-filter.md)的射线法 `point_in_polygon` 判断在不在区内。
- **闯入**用进入沿触发（区外→区内跳变报一次），承接第 87 章的"状态跳变"思想。
- **停留 dwell** 基于 `Track` 历史算：`dwell = 当前 ts − 进区 ts`，够 T 秒才告警；务必配 **gap 容忍**处理短暂离开/漏检，否则长时间逗留者会漏报（实测 track#7 停留 32.5s 触发告警，关掉容忍则漏）。
- **区内计数**逐时刻按 `track_id` 去重统计，是瞬时量；峰值、上升沿可驱动"拥挤/排队超限"告警（实测峰值 3 人）。

## 动手练习

1. **调阈值**：把停留阈值 `T` 从 30s 改成 18s，重新运行，看 track#8（停留 19.5s）是不是也开始触发 dwell 告警了——体会阈值如何划分"路过"与"逗留"。
2. **梯形 ROI**：把矩形 ROI 换成[第 84 章](ch84-roi-filter.md)那样的透视梯形（上窄下宽），确认射线法对凹凸多边形一样好用，脚点判定不受形状影响。
3. **改容忍**：把 track#7 中途漏检的帧数从 2 帧加到 8 帧，再分别用 3s 和 6s 的 gap 容忍跑一遍，观察什么时候停留会被"切断"——理解容忍阈值该怎么定。
4. **进阶——离开事件与净时长**：给每次停留补一个"离开"事件（`last_in_ts` 之后超过容忍仍没回来即判离开），并统计每个目标一天内在 ROI 的**累计**停留时长。这对"某人反复徘徊"的行为分析很有用。
