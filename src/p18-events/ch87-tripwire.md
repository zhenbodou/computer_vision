# 第 87 章 绊线检测（line-crossing）与方向计数

> **本章导读**
> - 学完你能：在画面上拉一条**有向绊线**，判断目标**有没有越过**它，还能分清是**从哪个方向**越过的（进 / 出）。
> - 核心两招：用**线段相交**判断"跨没跨"，用**叉积（cross product）的符号**判断"在哪一侧、朝哪个方向跨"。
> - 动手做出地铁闸口那样的"进 X 人 / 出 Y 人"双向计数器，并踩平"延长线误判""贴线抖动反复计数"两个大坑。
> - 数据模型沿用[第 83 章](ch83-filtering-basics.md)的 `BBox` / `Track` / `Event`；脚点用 `bottom_center()`，冷却去抖的思路承接[第 86 章](ch86-cooldown-dedup.md)。

## 场景：地铁闸口，进站多少人、出站多少人

你一定见过地铁站里那块屏幕："本站当前客流 12345 人"。它是怎么数出来的？最朴素也最可靠的做法，就是在闸口画一条线——**只要有人的脚从线的一侧迈到另一侧，就记一次；往里迈记"进"，往外迈记"出"**。周界安防里也一样：沿着围墙拉一条"警戒线"，有人翻过来就报警。

这条线，行话叫**绊线（tripwire / trip line）**，也叫**越线检测（line-crossing）**。它是所有安防规则里最直观、也最常用的一种。听起来简单，但真要写对，有几处特别容易翻车。这一章我们就把它彻底讲透。

它和上一层的关系是这样的：检测器（第九部分）给出每帧的框，跟踪器（[第 62 章](../p13-tracking/ch62-mot.md)）给每个目标一个稳定的 `track_id`，把框跨帧连成**轨迹**。绊线规则**只消费轨迹**——它盯着每个目标的脚点，看这一步有没有跨过那条线。

## 原理一：为什么必须看"两帧之间的位移"

新手的第一直觉往往是："判断脚点在线的上边还是下边，从上边变到下边不就越线了吗？"方向对，但**只看单帧的点是不够的**。

想象绊线是一条无限长的直线。某个目标这一帧在线上方、下一帧在线下方——它确实跨过去了。可问题是：**你怎么知道它是"跨过了这条线段"，而不是从线段端点外面绕过去的？** 一条真实的绊线是**有限长的线段** AB，不是无限长的直线。目标完全可能在 AB 的**延长线**那头晃悠，单看"它在直线的哪一侧"会把这种情况误判成越线。

所以正确的姿势是：**取目标连续两帧的脚点 `P_prev` 和 `P_curr`，把这一小段位移当成一条线段，判断它和绊线段 AB 有没有真正相交。** 这就把问题变成了经典的**线段相交（segment intersection）**判定。

```text
     P_prev ●                        ● 目标在端点外
             ╲  位移段                ┆   (只跨了 AB 的延长线)
              ╲                       ┆
   A ●━━━━━━━━━╳━━━━━━━━━● B          ┆
              ╱  ← 真正相交，算！      ┆← 与 AB 段不相交，不算！
       P_curr ●                       ●
```

## 原理二：叉积定"哪一侧"与"哪个方向"

判完"跨没跨"，还要判"朝哪个方向跨"。这就轮到**叉积**登场了。

给定绊线的两个端点 A、B 和任意一点 P，我们算这样一个量（二维叉积的 z 分量）：

\\[ \mathrm{cross}(A,B,P) = (B_x - A_x)(P_y - A_y) - (B_y - A_y)(P_x - A_x) \\]

它的**绝对值**是三角形 ABP 面积的两倍，但我们只关心它的**符号**：

- \\( \mathrm{cross} > 0 \\)：P 在有向线 A→B 的一侧；
- \\( \mathrm{cross} < 0 \\)：P 在另一侧；
- \\( \mathrm{cross} = 0 \\)：P 恰好落在直线上。

于是"从哪个方向越线"就有了干净的判据：**看出发点 `P_prev` 在哪一侧**。符号从 `+` 变到 `-` 是一个方向，从 `-` 变到 `+` 是相反方向。我们给这两个方向起个业务名字——比如地铁闸口，约定画面下方（y 大的一侧，`cross > 0`）是"门外"、上方（y 小的一侧，`cross < 0`）是"门内"：

```text
        门内 (- 侧, y 小, 画面上方)
                  ▲ 进 IN  (+ → -)
   A ●━━━━━━━━━━━━━━━━━━━━━● B      ← 有向绊线 A→B
                  │ 出 OUT (- → +)
                  ▼
        门外 (+ 侧, y 大, 画面下方)
```

> 📖 **术语**：**叉积（cross product）**。三维里两个向量叉乘得到一个垂直于它们的向量；二维里我们只用它的 z 分量 \\( u_x v_y - u_y v_x \\)，是一个标量。这里 \\( \mathrm{cross}(A,B,P) \\) 就是向量 \\( \vec{AB} \\) 与 \\( \vec{AP} \\) 的叉积 z 分量——它同时编码了"P 在 AB 的左边还是右边"和"三角形 ABP 的面积"。判方向、判线段相交、判点在多边形内（见[第 84 章](ch84-roi-filter.md)），底层都是它。

**线段相交怎么用叉积判？** 段 AB 与段 PQ（这里 PQ 就是 `P_prev→P_curr`）真正相交，当且仅当：P、Q 分居直线 AB 两侧（\\( \mathrm{cross}(A,B,P) \\) 与 \\( \mathrm{cross}(A,B,Q) \\) 异号），**并且** A、B 分居直线 PQ 两侧（\\( \mathrm{cross}(P,Q,A) \\) 与 \\( \mathrm{cross}(P,Q,B) \\) 异号）。两个条件都满足，交点才同时落在两条线段**内部**——这一步天然把"延长线相交"排除掉了。

## 动手写代码：定义绊线、合成轨迹、双向计数

这份示例**只用 std**，不需要任何第三方依赖。输入是合成的、带 `track_id` 的轨迹（`Vec<Track>`，时间戳 `ts_ms` 自己造递增值，不读系统时钟），因此完全可复现。运行：

```bash
cargo run --example ch87_tripwire
```

先是几何内核——叉积与线段相交。注意 `segments_intersect` 用**严格** `< 0`，既排除了共线/压线的退化情形，也顺手处理了"端点外的延长线不算"：

```rust
/// 叉积 z 分量：cross(A,B,P) = (B-A) × (P-A)。符号 = P 在有向线 A→B 的哪一侧。
fn cross(a: (f32, f32), b: (f32, f32), p: (f32, f32)) -> f32 {
    (b.0 - a.0) * (p.1 - a.1) - (b.1 - a.1) * (p.0 - a.0)
}

/// 段 AB 与段 PQ 是否"真正相交"：P、Q 分居 AB 两侧，且 A、B 分居 PQ 两侧。
fn segments_intersect(a: (f32, f32), b: (f32, f32), p: (f32, f32), q: (f32, f32)) -> bool {
    let d1 = cross(a, b, p);
    let d2 = cross(a, b, q);
    let d3 = cross(p, q, a);
    let d4 = cross(p, q, b);
    d1 * d2 < 0.0 && d3 * d4 < 0.0
}
```

绊线本身与"这一步跨了没、朝哪个方向"的判定：

```rust
struct Tripwire { a: (f32, f32), b: (f32, f32) }

impl Tripwire {
    /// 脚点从 p_prev 走到 p_curr：Some(true)=进, Some(false)=出, None=没跨。
    fn crossing_dir(&self, p_prev: (f32, f32), p_curr: (f32, f32)) -> Option<bool> {
        if !segments_intersect(self.a, self.b, p_prev, p_curr) {
            return None; // 位移段没跨过绊线段（含只跨了延长线的情况）
        }
        // 跨了：看出发点在哪侧。门外(+)出发 → 进；门内(-)出发 → 出。
        Some(cross(self.a, self.b, p_prev) > 0.0)
    }
}
```

主流程合成 4 条轨迹，故意把常见坑都塞进去，然后跑两遍计数——一遍不去抖、一遍按 `track_id` 冷却去抖（脚点一律取 `bottom_center()`）：

```rust
let wire = Tripwire::new((100.0, 300.0), (540.0, 300.0)); // 只在 x∈[100,540] 判定
// ① 正常进站  ② 正常出站  ③ 端点外(x=610)跨延长线  ④ 贴线来回抖动
let tracks = vec![t1, t2, t3, t4];

// A) 朴素：几何判定，不去抖
for t in &tracks {
    for w in t.history.windows(2) {
        if let Some(is_in) = wire.crossing_dir(w[0].1.bottom_center(), w[1].1.bottom_center()) {
            naive.add(is_in);
        }
    }
}
// B) 去抖：同一 track_id 触发后 cooldown_ms 内不再计数（冷却思路见第 86 章）
let recent = last_fire.get(&t.id)
    .map(|&t0| ts_curr.saturating_sub(t0) < cooldown_ms).unwrap_or(false);
if !recent { last_fire.insert(t.id, ts_curr); deb.add(is_in); /* 吐出 Event */ }
```

运行后终端打印（数字真实可复现）：

```text
== 逐条轨迹的原始跨线（仅几何，不去抖）==
  track#1 person: 进 1 / 出 0
  track#2 person: 进 0 / 出 1
  track#3 person: 进 0 / 出 0  (在端点外，跨的是延长线 → 不计数)
  track#4 person: 进 3 / 出 2  (贴线抖动，原始跨线次数虚高)

== 去抖后吐出的跨线事件（按 track_id 冷却 800ms）==
  [tripwire] t= 200ms track 1 进 IN（门外→门内）
  [tripwire] t= 200ms track 2 出 OUT（门内→门外）
  [tripwire] t= 100ms track 4 进 IN（门外→门内）

== 双向计数对比 ==
[不去抖] 进 4 人 / 出 3 人（被 track#4 的贴线抖动灌了水）
[去抖]   进 2 人 / 出 1 人（干净结果）
净流量（进 - 出）= 1
```

三件事一目了然：**track#3 在端点外**，跨的是绊线的延长线，几何判定直接给 0——不需要额外规则，线段相交本身就挡住了；**track#4 贴着线抖动**，原始判定跨了 5 次（进 3 出 2），把总数灌成了"进 4 / 出 3"；加上按 `track_id` 的冷却，同一个人 800ms 内只认一次，最终收敛成干净的"**进 2 人 / 出 1 人**"，净流量 `+1`。

这个"净流量"在真实项目里就是**当前在场人数**的增量：出入口累计"进 − 出"，就是"此刻里面还有多少人"，商场闭店清场、场馆限流全靠它。再往上一层，还可以**按类别分别计数**——把 `Track.label` 一并带进计数器，就能同时统计"进了几个人、过了几辆车"；这正是[第 104 章 客流 / 车流计数](../p20-projects/ch104-people-counting.md)项目的雏形。要让计数在嘈杂现场也稳，通常还会把绊线规则接在[第 85 章](ch85-temporal-window.md)的 N/M 确认之后——先用时间窗把偶发误检的"假轨迹"滤掉，再让确认过的稳定轨迹去撞线，虚警会明显更少。

## 常见坑与提示

> 🕳️ **坑**：**只看"当前点在线哪侧"必然出错，一定要用连续两帧的位移段。** 单帧的点无法区分"刚跨过来"和"本来就在这侧"，更挡不住从端点外绕过的目标。把 `P_prev→P_curr` 当线段、和绊线段做相交判定，才是对的。

> 🕳️ **坑**：**绊线是线段，不是无限直线——端点外的延长线不算数。** 这正是 `segments_intersect` 要同时检查"A、B 分居 PQ 两侧"的原因。少了这一条，目标在 AB 两侧的延长线上移动就会被误判成越线。本例 track#3 就是这个坑的现场。

> 🕳️ **坑**：**目标贴着线来回抖动会反复计数。** 检测框天生有几像素的漂移，脚点正好落在绊线附近时，一帧上、一帧下，能瞬间刷出好几次"越线"。解法是**按 `track_id` 做冷却（cooldown）**：同一个目标一次触发后，短时间内不再计数（见[第 86 章](ch86-cooldown-dedup.md)）。更稳的做法还可以叠加"必须离线一定距离才算真跨"的滞回，或先用[第 85 章](ch85-temporal-window.md)的 N/M 确认压掉偶发抖动。

> ⚠️ **注意**：**脚点选择很关键，用 `bottom_center()` 而不是中心。** 人站在地面上，判断"越没越线"看的是**脚踩在哪**。用框中心会让一个远处的高个子"提前"越线、近处的矮子"延后"越线。透视越强，这个偏差越大。落地点判定统一用脚点，是本部分的铁律（见[第 84 章](ch84-roi-filter.md)）。

> 💡 **提示**：**多目标必须按 `track_id` 各记各的。** 冷却状态、上一帧脚点都要以 `track_id` 为键分别维护——A 的抖动不能影响对 B 的计数。没有稳定 id（跟踪器缺位）时，绊线方向计数几乎没法做对，这也是为什么本规则强依赖第十三部分的跟踪。

> ⚠️ **注意**：**方向的"正负侧"取决于 A、B 的书写顺序。** 交换 A 和 B，所有 `cross` 的符号翻转，"进"和"出"就对调了。部署时务必和现场确认："A→B 的左手边是室内还是室外"，别把进出报反。

## 本章小结

- **绊线 / 越线检测**：在画面上定义一条**有向线段** AB，判断目标脚点的轨迹有没有跨过它，并区分方向。
- **判"跨没跨"用线段相交**：把连续两帧脚点 `P_prev→P_curr` 当线段，和 AB 做**真正相交**判定（两组叉积同时异号）；这一步自带"延长线不算"的正确行为。
- **判"哪个方向"用叉积符号**：看出发点 `P_prev` 在 AB 的哪一侧，符号 `+→-` 与 `-→+` 对应进 / 出两个方向。
- **工程化三件套**：脚点用 `bottom_center()`；贴线抖动用按 `track_id` 的冷却去抖压掉；多目标状态按 `track_id` 分开维护。实测把"进 4 / 出 3"的抖动虚高，收敛成干净的"进 2 / 出 1"。

## 动手练习

1. **反转方向**：把 `Tripwire::new` 的 A、B 端点对调，重新运行，观察"进"和"出"的数字是不是互换了——理解方向由端点书写顺序决定。
2. **斜绊线**：把绊线改成一条斜线（如 A=(120,120)、B=(500,340)），再合成一条斜穿它的轨迹，确认叉积判方向对斜线一样成立。
3. **加滞回**：给 `crossing_dir` 加一个"脚点必须离绊线超过 `d` 像素才算真的跨过来"的条件（用 `cross` 的绝对值除以 `|AB|` 得到点到线的距离），看它能不能在**不依赖冷却**的情况下也压住 track#4 的抖动。
4. **进阶——多绊线**：定义两条平行绊线，只有"先过线 1、再过线 2"才算一次有效通过（方向门 / tripline pair）。这能进一步过滤掉在单线附近徘徊的误触，是客流计数的常用增强。
