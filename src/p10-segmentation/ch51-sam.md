# 第 51 章 交互式分割与 SAM（Segment Anything）

> **本章导读**
> - 学完你能：讲清 **可提示分割（promptable segmentation）** 这个范式——用户给**点/框**提示，模型吐**掩码**；并动手实现两种能**一键跑通**的交互式分割。
> - 用纯 Rust 经典的**种子区域生长**做"点提示 → 掩码"，实测**点提示 IoU 1.000**，还会看到阈值这个旋钮太紧/太松时 IoU 怎么崩，以及**框提示**如何救场。
> - 用 **candle** 训一个"**点条件**"的迷你分割网络（迷你 SAM）：输入 = 图 + 点提示热力图，输出 = 该点所指物体的掩码；**同一张图、点不同物体 → 得到不同掩码**，测试前景 IoU **0.951**。
> - **诚实**：真实 SAM 用数百 MB~GB 级的大型 ViT 编码器，纯 Rust 一键 demo 跑不动；我们讲清"candle 有官方 SAM example，但需下载权重"这条真实路线。
> - 代码在本机 `cargo run --release` 实测（纯 CPU、约一分钟），正文数字均为真实输出、可复现。

## 场景：我不想训 100 个类别，我只想"点一下就把它抠出来"

[第 49 章](ch49-semantic-seg.md) 的语义分割很强，但它有个前提：**类别得预先定义好、模型得提前训练好**。可现实里常常是这样——你打开**任意**一张照片，看到某个东西（一只从没进过训练集的奇怪玩具、一片不规则的污渍），只想**用鼠标点它一下**，就把它的轮廓精确抠出来，根本不关心它"属于哪一类"。

这就是**交互式分割（interactive segmentation）**：**人给提示，模型出掩码**。2023 年 Meta 的 **SAM（Segment Anything Model）** 把这件事做到了惊人的程度——对着任意图、任意物体，点一下或框一下，它就能给出高质量掩码，而且是**零样本（zero-shot）**：不需要为你的图重新训练。本章我们就把这套范式的**直觉**和**能跑的最小实现**都拿下。

## 原理：从"全自动"到"可提示"

### 交互式分割 vs 全自动分割

| | 全自动分割（如 [第 49 章](ch49-semantic-seg.md)） | 交互式分割（本章 / SAM） |
|---|---|---|
| 谁决定分什么 | 模型独自决定每个像素的类别 | **人给提示**，模型据提示出掩码 |
| 类别 | 固定的预定义类别集合 | **不限类别**，能分没见过的物体 |
| 典型输入 | 一张图 | 一张图 + **点 / 框 / 涂鸦** |
| 用途 | 批量、无人值守（自动驾驶、监控） | 抠图、**辅助标注**、可迭代修正 |

交互式分割不是要取代全自动，而是补上"**人在环里（human-in-the-loop）**"的场景：省标注、处理长尾物体、结果可当场修。

### 可提示分割：SAM 的三件套

SAM 的架构可以拆成三块，理解了这个拆分，就理解了它为什么能**实时交互**：

```text
        （慢，每张图算一次）        （快，每次提示都能实时跑）
 图片 ─▶ 图像编码器(重, ViT) ─▶ 图像 embedding ─┐
                                                ├─▶ 掩码解码器(轻) ─▶ 掩码
 点/框提示 ─▶ 提示编码器(轻) ─▶ 提示 embedding ─┘
```

- **图像编码器**：又大又慢的 ViT，把整张图编码成一份 embedding。**每张图只跑一次**。
- **提示编码器**：把点/框这类提示编码成向量，非常轻。
- **掩码解码器**：把图像 embedding 和提示 embedding 一融合，吐出掩码，也很轻。

**关键**：图编码一次后缓存住，之后用户点来点去、改来改去，**只需重跑那两个轻量模块**，所以交互能做到实时。这也解释了 SAM 为什么"通用"：它在超大规模数据（SA-1B，1100 万张图、10 亿个掩码）上训练，学到的是"**把提示指向的东西从背景里分出来**"这件与具体类别无关的通用本领——所以能**零样本**迁移到任意新图、新物体。

> ⚠️ **注意（本章的诚实边界）**：真实 SAM 的图像编码器是重型 ViT，权重从 ViT-B 的约 350MB 到 ViT-H 的约 2.4GB——**纯 Rust 一键、免下载的 demo 跑不动它**。candle 官方**确实有** `segment-anything` 的 example，但它需要你**联网下载权重**、且推理不轻。这是真实可行的路线（和 [第 46 章](../p09-detection/ch46-yolo-inference.md) 跑真实 YOLO、[第 94 章](../p19-deploy/ch94-onnx.md) 用 tract 加载 ONNX 一个道理：**结构讲透、权重下载**），但不纳入本章的一键 demo。下面我们用两个**能立刻跑通**的东西来建立同款直觉。

## 动手 A：经典种子区域生长（点提示 / 框提示）

早在深度学习之前，**交互式分割**就已经存在，最经典的就是**种子区域生长（seeded region growing）**：用户点一个**种子点**，算法从它出发，把**颜色/灰度相似**且**连通**的邻居像素一圈圈"长"进来，直到长不动为止。它和 [第 18 章](../p03-classic/ch18-contours.md) 的连通域分析是近亲，但**由人给的点来驱动**——这正是"点提示 → 掩码"最朴素的形态。

> ⚠️ **注意**：本章代码基于 **candle 0.11.0**，纯 CPU。完整独立工程见 `code/dl_labs/ch51_interactive_seg/`，`cd` 进去 `cargo run --release` 即可复现。A 部分（区域生长）纯算法、瞬时；B 部分要训一个小网络（约一分钟）。

核心就是一个从种子点出发的广度优先搜索（BFS），把"与参考色平方距离小于阈值"的连通像素纳入掩码：

```rust
fn region_grow(img: &RgbImage, seed: (i32, i32), thr2: f32, bbox: Option<[i32; 4]>) -> Vec<bool> {
    let mut mask = vec![false; SZ * SZ];
    let ref_color = pixel_rgb(img, seed.0, seed.1);       // 参考色 = 种子像素颜色
    let mut q = VecDeque::new();
    mask[seed.1 as usize * SZ + seed.0 as usize] = true;
    q.push_back(seed);
    while let Some((x, y)) = q.pop_front() {
        for (dx, dy) in [(-1, 0), (1, 0), (0, -1), (0, 1)] {  // 4 邻域
            let (nx, ny) = (x + dx, y + dy);
            // inside() 检查边界；若给了 bbox（框提示），还要求落在框内
            if !inside(nx, ny, bbox) { continue; }
            let idx = ny as usize * SZ + nx as usize;
            if mask[idx] { continue; }
            if color_dist2(pixel_rgb(img, nx, ny), ref_color) < thr2 {  // 颜色够近就纳入
                mask[idx] = true;
                q.push_back((nx, ny));
            }
        }
    }
    mask
}
```

我们合成一张 28×28、带若干纯色物体（叠了噪声）的图，把点提示放到每个物体质心上，与真值掩码比 IoU。**真实输出**：

```text
[点提示] 阈值 = 70（颜色平方距离 < 70² 视为同物体），逐个物体点击：
  物体#0 点(13,21)：分割  70 像素（GT  70），IoU = 1.000
  物体#1 点( 7, 5)：分割  54 像素（GT  54），IoU = 1.000
  → 平均 IoU = 1.000（点在哪个物体上，就分割出哪个 → 这就是“点提示→掩码”）
```

**点在哪个物体上，就分割出哪个**——这就是"点提示 → 掩码"最直接的体现。程序会把"输入图（含黄色十字点标记）| 分割掩码 | GT 掩码"存成三联 PNG（`grow_obj*.png`）。

**但阈值这个旋钮很敏感。** 固定同一个点，只改相似度阈值：

```text
[阈值敏感性] 固定点在物体#0 的质心(13,21)，改变阈值：
  阈值=  15：分割    2 像素，IoU=0.029 （欠分割）
  阈值=  40：分割   38 像素，IoU=0.543 （欠分割）
  阈值=  70：分割   70 像素，IoU=1.000 （刚好）
  阈值= 150：分割   70 像素，IoU=1.000 （刚好）
  阈值= 300：分割  784 像素，IoU=0.089 （漏进背景/相邻物体）
```

阈值太紧（15）只圈住种子附近几个像素、**欠分割**；太松（300）直接**漏进背景**把整张图 784 个像素全吞了、IoU 崩到 0.089。这就是交互式分割里的**"提示工程"**：提示（点在哪）和参数（阈值多大）都得调。

**框提示怎么救场？** 给一个把目标圈住的**框（box prompt）**，即使阈值很松，生长也被**限制在框内**，漏不出去：

```text
[框提示] 同样的松阈值(300)，对比“无框” vs “框住物体#0”：
  无框：分割  784 像素，IoU=0.089
  框内：分割   70 像素，IoU=1.000
```

同样松到会泛滥的阈值，**加一个框就从 IoU 0.089 救回到 1.000**。框提示用**空间约束**兜住了区域生长——**这正是 SAM 支持点、框等多种提示的动机：不同提示各有各的"脾气"，框比裸点更能约束范围**。

## 动手 B：迷你 SAM——用 candle 训一个"点条件"分割网络

区域生长靠手调阈值，换张图就得重调。能不能让"**人点哪、就分割哪**"这件事**可学习**？能——把**点提示**也喂给网络，让它自己学会"根据点定位物体、再分割"。这就是 SAM 的缩影。

做法很直接：网络输入不再是 3 通道 RGB，而是 **4 通道**——多加一个**点提示热力图**通道（以点击处为中心的高斯亮斑），告诉网络"用户点在这儿"。输出是**该点所指物体**的掩码（2 类：前景/背景）。网络结构直接**复用 [第 49 章](ch49-semantic-seg.md) 的小 U-Net**，只把输入改成 4 通道、输出改成 2 类：

```rust
struct PromptSeg { /* enc1..head，同第 49 章 U-Net */ }
impl PromptSeg {
    fn load(vb: VarBuilder) -> Result<Self> {
        // ...
        Ok(Self {
            enc1: conv2d(4, 16, 3, c, vb.pp("enc1"))?,   // ← 4 通道输入：RGB + 点提示热力图
            // ...（编码器/解码器/跳跃连接与第 49 章一致）
            head: conv2d(16, 2, 1, c1, vb.pp("head"))?,  // ← 2 类：背景 / 前景
        })
    }
}
```

**训练数据的构造是关键**：每个样本随机挑一个物体，把点提示落在它的质心附近（加一点抖动，模拟点击不精确），目标掩码就是**那一个物体**。因为同一张图里有多个物体（还偶尔同色），网络**必须真的用点提示**来判断该分割哪一个——这就逼它学会"点条件"。**真实输出**：

```text
训练点条件分割网络（输入=RGB+点热力图，输出=该点物体掩码，AdamW lr=2e-3→5e-4）...
  epoch   1  loss = 0.6994
  epoch  60  loss = 0.0524
  epoch 120  loss = 0.0098
===== 测试集评估（48 个点提示样本）=====
逐像素准确率 = 99.57%
前景掩码 IoU = 0.951
```

测试集上**前景掩码 IoU 0.951**。最能说明"可提示"的是下面这个演示——**同一张图，把点放到不同物体上**：

```text
[可提示演示] 同一张图，把点提示放到不同物体上，看网络输出的掩码怎么变：
  点在物体#0(16, 7)：网络分割  79 像素（GT  90），IoU = 0.878
  点在物体#1( 4,16)：网络分割  53 像素（GT  56），IoU = 0.946
  点在物体#2( 6, 7)：网络分割  59 像素（GT  42），IoU = 0.712
```

**同一张图，点不同物体，网络给出完全不同的掩码**（对应 `sam_obj*.png`）——点提示真正"**条件**"住了输出。这就是 SAM 可提示分割最核心的直觉，只不过 SAM 用巨大的 ViT 和海量数据，把它做到了任意图、任意物体、零样本。存/取权重用的 `VarMap::save` + `unsafe from_mmaped_safetensors`，和加载真实 SAM 的 `.safetensors` 是**同一套 API**——差的只是模型大小和训练数据的量级。

> 💡 **提示**：注意物体#2 只有 IoU 0.712（网络把 42 像素的目标涨成了 59 像素）——**我们这个迷你网络远不完美**。这是诚实的：它只在狭窄的合成分布里学过，没有 SAM 的规模与泛化。它的价值是让你**亲手验证"点提示条件住输出"这件事真的能学**，而不是一个能替代 SAM 的东西。

## 常见坑与提示

> 🕳️ **坑**：**区域生长的"参考色"用单个种子像素，很脆。** 种子恰好落在噪点上，整片就长歪了。稳一点的做法是用种子**邻域的均值**做参考色，或边长边更新**区域动态均值**。本章为讲清原理用了单像素参考色——真实工程请用邻域均值。

> ⚠️ **注意**：**提示的坐标映射别搞错。** 用户在**原图 UI** 上点的坐标，喂给模型前要经过和图像预处理**完全相同**的变换（缩放、letterbox 填充、EXIF 方向……见 [第 46 章](../p09-detection/ch46-yolo-inference.md)）。点提示错几个像素，可能就点到隔壁物体上去了。SAM 这类模型尤其要用**统一的 transform**把 UI 坐标和模型输入坐标对齐。

> 💡 **提示**：**点、框、掩码提示各有适用。** 点提示最省事但最"飘"；框提示用空间约束更稳（本章数字为证：松阈值下框把 IoU 从 0.089 救到 1.000）；已有的粗掩码也能当提示做迭代精修。SAM 支持这几种提示的组合，正是为了让用户用最小的交互拿到最好的掩码。

> 📖 **术语**：**embedding 缓存**。SAM 的图像 embedding 只依赖图片本身（与提示无关），所以真实系统会**按图片内容哈希缓存**它：用户在同一张图上点十次，图像编码器只跑第一次，后面九次只跑轻量的提示编码器 + 掩码解码器。缓存键要带上**模型版本、预处理和输入尺寸**，否则会取到错的 embedding。

> ⚠️ **注意**：**模型给的"预测 IoU"不是业务真值。** SAM 一次会输出多个候选掩码并附一个自评的"预测 IoU"分数，那只是**模型内部的排序信号**，不代表真的对。用它做**辅助标注**时，务必保留**人工审核/拒绝**通道，并对困难样本单独抽查——否则只接受"模型容易生成的样本"会带来**选择偏差**。

> 🕳️ **坑**：**candle 0.11 的 CPU 后端不能 `set_seed`。** 和前几章一样，本章用自造的确定性初始化（固定种子 LCG 写权重）保证 loss、IoU 逐字可复现。

## 本章小结

- **交互式分割 = 人给提示、模型出掩码**，不限类别、能处理没见过的物体，是"人在环里"的抠图与辅助标注利器；与 [第 49 章](ch49-semantic-seg.md) 的全自动分割互补。
- **SAM 的可提示范式**把网络拆成"重的图像编码器（每图一次）+ 轻的提示编码器 + 轻的掩码解码器（每次提示实时）"，靠超大规模训练获得**零样本**通用分割能力。
- **经典种子区域生长**是"点提示 → 掩码"的祖师爷：实测点提示 IoU **1.000**，但阈值太紧欠分割、太松漏进背景（IoU 0.089）；**框提示**用空间约束把松阈值救回 **1.000**。
- **迷你 SAM**（点条件小网络）证明"点提示条件住输出"可学习：4 通道输入（RGB + 点热力图）、2 类输出，测试前景 IoU **0.951**，**同图不同点得到不同掩码**。
- **诚实边界**：真实 SAM 权重数百 MB~GB，纯 Rust 一键 demo 跑不动；务实路线是用 candle 官方 SAM example **下载权重**跑，或用 tract 加载导出的 ONNX（[第 94 章](../p19-deploy/ch94-onnx.md)）。

## 动手练习

1. **换参考色策略**：把 `region_grow` 的参考色从"单个种子像素"改成"种子 3×3 邻域均值"，重跑阈值敏感性表，看"刚好"的阈值区间是否变宽、对噪声是否更稳。
2. **多点提示**：给区域生长喂**两个**种子点（比如一个物体上点两下），把两次生长的掩码求并集，体会"多点提示"如何覆盖更完整的物体。
3. **考验点条件**：把合成场景改成**所有物体同色**，重训迷你 SAM。既然颜色不再能区分物体，网络就**只能靠点提示**定位——看前景 IoU 掉多少，验证它是不是真的在用点。
4. **负点提示（进阶）**：真实 SAM 支持"负点"（点在这里表示"**不要**这块"）。想一想：要让本章的迷你网络支持负点，输入该怎么改？（提示：再加一个"负点热力图"通道。）
5. **接真实 SAM（进阶）**：去 candle 官方仓库找 `segment-anything` example，下载 ViT-B 权重，对一张你自己的照片跑"点提示 → 掩码"，对比它和本章迷你网络的差距——尤其在**没见过的物体**上。
