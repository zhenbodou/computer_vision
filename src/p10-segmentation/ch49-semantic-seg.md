## 场景：把"这张图是什么"细化到"每个像素是什么"

[第 1 章](../p01-start/ch01-what-is-cv.md) 的任务地图里，分类（[第 42 章](../p08-classification/ch42-candle-classify.md)）回答"这张图**是什么**"，检测（[第 46 章](../p09-detection/ch46-yolo-inference.md)）回答"图里**有哪些东西、各在哪**（画框）"。但很多任务要的更细：**精确到每一个像素属于什么**。

- 人像抠图：把人从背景里一个像素不差地抠出来；
- 医学影像：把病灶区域沿边界勾出来，供医生测面积；
- 自动驾驶：把画面分成可行驶路面、车道线、行人、车辆……

这就是**语义分割（semantic segmentation）**：给图里**每个像素**都贴一个类别标签。输出不再是一个标签或几个框，而是一张和原图**同样大小的"类别图"**。本章我们就搭一个能真跑通的小型分割网络，把这件事从直觉做到数字。

## 原理：从"逐像素分类"到 U 形网络

### 第一步直觉：分割就是"给每个像素做分类"

还记得 [第 42 章](../p08-classification/ch42-candle-classify.md) 的分类网吗？它最后把整张图压成一个向量，输出 `[N, 类别数]`。分割只要改一件事：**别把空间压掉，让网络在每个像素位置都输出一份类别分数**。于是输出从 `[N, C]` 变成 `[N, C, H, W]`——每个空间位置 `(y, x)` 都有一份 `C` 维 logits，`argmax` 一下就是这个像素的类别。

这种"把分类头换成逐像素输出、全程只用卷积"的网络，就是分割的开山之作 **FCN（Fully Convolutional Network，全卷积网络）** 的核心思想。

> 📖 **术语**：**逐像素分类（dense prediction，稠密预测）**。普通分类一张图出一个结果，分割一张图出 `H×W` 个结果——每个像素一个。所以分割常被看成"把分类在每个像素上做一遍"，损失也就是"逐像素的分类损失"。

### 第二步：为什么要"先缩小、再放大"（编码器-解码器）

最朴素的想法是：全程用 `padding=1` 的 3×3 卷积保持分辨率，堆很多层直接出结果。但这样有两个致命问题：**感受野涨得太慢**（每层只 +2 像素，要"看懂"一大片区域得堆几十层），以及**算力和显存爆炸**（一直在原分辨率上算大特征图）。

解决办法是做成 **编码器-解码器（encoder-decoder）** 的沙漏形状：

```text
   编码器（下采样）           解码器（上采样）
 输入 28×28 ─conv─▶ e1 28×28 ┐               ┌▶ 28×28 ─┐
              │pool           │  跳跃连接 skip │          ▼
              ▼               └───────────────┘      logits
            14×14 ─conv─▶ e2 14×14 ┐        ┌▶ 14×14   [N,C,28,28]
              │pool                │  skip   │
              ▼                    └─────────┘
            7×7 ─conv─▶ 瓶颈 b 7×7（感受野最大、分辨率最低）
```

- **编码器**：不断"卷积 + 下采样（池化）"，把分辨率一半一半地降下去。分辨率降低意味着同样一个 3×3 卷积能覆盖原图更大的范围——**感受野迅速变大，网络得以"看懂"整片区域的语义**；同时特征图变小，算力可控。
- **瓶颈（bottleneck）**：分辨率最低、通道最多的地方，浓缩了全局语义。
- **解码器**：反过来不断**上采样**把分辨率恢复回原图大小，好在每个像素上给结论。

> ⚠️ **注意**：candle 0.11.0 里没有顺手的**转置卷积（transposed convolution）**算子。我们用**最近邻上采样 + 3×3 卷积**来实现解码器的放大（先把特征图按最近邻插值放大一倍，再用卷积把放大后的"马赛克"抹平）。这个组合和转置卷积效果相近、原理更好懂，[第 69 章](../p15-generative/ch69-autoencoder.md) 的自编码器解码器也是这么做的。

### 第三步：跳跃连接——丢掉的细节怎么找回来

编码器把 28×28 一路降到 7×7，语义是抓住了，但**精确的边界位置被糊掉了**：7×7 里的一个格子，还原到 28×28 要摊成一片 4×4 的区域，边界只能是"块状"的。只靠解码器硬猜，边界必然毛糙。

**跳跃连接（skip connection）** 的主意特别朴素：编码器里那些**还没被下采样糊掉的高分辨率特征**（图中的 `e1`、`e2`），干脆抄一条近道，直接送到解码器对应分辨率的地方，和上采样上来的特征**在通道维拼接（concatenate）**。这样解码器手里就同时有两样东西：

- 从瓶颈上采样上来的**"语义"**（这块大概是什么）；
- 从编码器抄近道过来的**"细节"**（边界到底在哪个像素）。

二者一拼，边界立刻就清晰了。这就是 **U-Net** 那个 U 形结构的精髓——左边编码器、右边解码器，中间一条条横线就是跳跃连接。本章末尾的消融实验会用真实数字告诉你：**关掉这几条线，mIoU 会腰斩还不止。**

### 第四步：逐像素交叉熵与 mIoU

**损失**就是把分类的交叉熵（[第 42 章](../p08-classification/ch42-candle-classify.md)）在每个像素上算一遍再平均。设一张图有 \\( N_{px} \\) 个像素，像素 \\( i \\) 的真值类别是 \\( y_i \\)、softmax 后该类的概率是 \\( p_{i,y_i} \\)：

\\[ L = -\frac{1}{N_{px}} \sum_{i} \log p_{i, y_i} \\]

工程上只要把 logits 从 `[N, C, H, W]` **摊平成 `[N·H·W, C]`**、真值摊平成长度 `N·H·W` 的类别向量，就能直接复用分类的交叉熵函数——分割在损失这一层，真的就是"把每个像素当一个样本的分类"。

**评估**分割不能只看**逐像素准确率（pixel accuracy）**，因为类别极不平衡：我们的合成图里背景占了 **78.3%**，一个"把所有像素都预测成背景"的废物模型也能拿到 78% 的准确率，可它对目标的 IoU 是 0。真正公允的指标是 **mIoU（mean Intersection-over-Union，平均交并比）**。对每个类别 \\( c \\)，设预测为该类的像素集合是 \\( P_c \\)、真值为该类的是 \\( G_c \\)：

\\[ \text{IoU}_c = \frac{|P_c \cap G_c|}{|P_c \cup G_c|}, \qquad \text{mIoU} = \frac{1}{C}\sum_{c=1}^{C} \text{IoU}_c \\]

交集除以并集，取值 0~1，越大越好；再对所有类别求平均就是 mIoU。它对每个类别一视同仁，小目标做砸了会立刻反映在分数上——这正是我们要的诚实。

## 动手：搭一个小 U-Net 做四类分割

> ⚠️ **注意**：本章代码基于 **candle 0.11.0**，纯 CPU。完整独立工程见 `code/dl_labs/ch49_unet_seg/`，**`cd` 进去 `cargo run --release`** 即可复现（首次编译 candle 较久，训练两个 U-Net 在纯 CPU 上约一分半）。

`Cargo.toml`：

```toml
[package]
name = "ch49_unet_seg"
version = "0.1.0"
edition = "2021"

[workspace] # 空表：让本工程独立，不被上层 code/Cargo.toml 收编

[dependencies]
candle-core = "0.11.0"
candle-nn = "0.11.0"
image = "0.25"
```

**合成数据**：我们造 28×28 的 RGB 图，随机放 2~3 个几何形状——**竖条**（窄而高）、**横条**（宽而矮）、**方块**——每类有各自的基色再叠高斯噪声（避免"颜色=类别"的平凡查表），后画的覆盖先画的，天然产生**遮挡边界**。同时生成一张**逐像素类别掩码**（0=背景，1/2/3=三类形状）作为真值。四个类别：

```rust
const SZ: usize = 28;                                 // 输入边长
const NC: usize = 4;                                  // 类别数
const CLASSES: [&str; NC] = ["背景", "竖条", "横条", "方块"];
```

**网络结构**（编码器 → 瓶颈 → 解码器，含两条跳跃连接）。注意 `use_skip` 这个开关：关掉时我们把跳跃连接**换成同形状的全零张量**送进去——这样两个模型的**权重形状完全一样**，是一次干净、公平的消融对比：

```rust
struct UNet {
    enc1: Conv2d, enc2: Conv2d, bott: Conv2d,        // 编码器 + 瓶颈
    up2: Conv2d, dec2: Conv2d, up1: Conv2d, dec1: Conv2d, // 解码器
    head: Conv2d,                                     // 1x1 逐像素分类头
    use_skip: bool,                                   // 跳跃连接开关（消融用）
}
impl UNet {
    fn load(vb: VarBuilder, use_skip: bool) -> Result<Self> {
        let c = Conv2dConfig { padding: 1, ..Default::default() }; // 3x3 保持边长
        let c1 = Conv2dConfig { padding: 0, ..Default::default() }; // 1x1 头
        Ok(Self {
            enc1: conv2d(3, 16, 3, c, vb.pp("enc1"))?,
            enc2: conv2d(16, 32, 3, c, vb.pp("enc2"))?,
            bott: conv2d(32, 64, 3, c, vb.pp("bott"))?,   // 瓶颈：通道最多、分辨率最低
            up2:  conv2d(64, 32, 3, c, vb.pp("up2"))?,    // 上采样后减通道
            dec2: conv2d(64, 32, 3, c, vb.pp("dec2"))?,   // 拼接 e2 后 32+32=64 → 32
            up1:  conv2d(32, 16, 3, c, vb.pp("up1"))?,
            dec1: conv2d(32, 16, 3, c, vb.pp("dec1"))?,   // 拼接 e1 后 16+16=32 → 16
            head: conv2d(16, NC, 1, c1, vb.pp("head"))?,  // → [N,NC,28,28]
            use_skip,
        })
    }
    fn forward(&self, x: &Tensor) -> Result<Tensor> {
        // 编码器：逐步下采样，e1/e2 留着做跳跃连接
        let e1 = self.enc1.forward(x)?.relu()?;          // [N,16,28,28]（细节层）
        let p1 = e1.max_pool2d(2)?;                      // [N,16,14,14]
        let e2 = self.enc2.forward(&p1)?.relu()?;        // [N,32,14,14]（中层）
        let p2 = e2.max_pool2d(2)?;                      // [N,32,7,7]
        let b  = self.bott.forward(&p2)?.relu()?;        // [N,64,7,7]（瓶颈）
        // 解码器：最近邻上采样 + 卷积；拼接编码器特征（跳跃连接）
        let u2 = b.upsample_nearest2d(SZ / 2, SZ / 2)?;  // 7→14
        let u2 = self.up2.forward(&u2)?.relu()?;         // [N,32,14,14]
        let skip2 = if self.use_skip { e2.clone() } else { e2.zeros_like()? };
        let c2 = Tensor::cat(&[&u2, &skip2], 1)?;        // 通道维拼接 → [N,64,14,14]
        let d2 = self.dec2.forward(&c2)?.relu()?;        // [N,32,14,14]
        let u1 = d2.upsample_nearest2d(SZ, SZ)?;         // 14→28
        let u1 = self.up1.forward(&u1)?.relu()?;         // [N,16,28,28]
        let skip1 = if self.use_skip { e1.clone() } else { e1.zeros_like()? };
        let c1 = Tensor::cat(&[&u1, &skip1], 1)?;        // → [N,32,28,28]
        let d1 = self.dec1.forward(&c1)?.relu()?;        // [N,16,28,28]
        self.head.forward(&d1)                           // [N,NC,28,28]，每像素一份 logits
    }
}
```

**逐像素交叉熵**：把 `[N, NC, H, W]` 换轴成 `[N, H, W, NC]` 再摊平成 `[N·H·W, NC]`，就能直接喂给 candle 的 `cross_entropy`（目标必须是 **U32**）：

```rust
fn pixel_ce(logits: &Tensor, target_u32: &Tensor) -> Result<Tensor> {
    let (n, c, h, w) = logits.dims4()?;
    let flat = logits
        .permute((0, 2, 3, 1))?   // [N,H,W,C]
        .contiguous()?            // permute 后内存非连续，reshape 前先连续化
        .reshape((n * h * w, c))?; // [N·H·W, C]
    let tgt = target_u32.reshape((n * h * w,))?; // [N·H·W]
    candle_nn::loss::cross_entropy(&flat, &tgt)  // 内部 log_softmax + nll
}
```

**训练**用 AdamW，后段降学习率（细节见 [第 41 章](../p07-dl-basics/ch41-training-tricks.md)）；`det_init` 是自造的确定性初始化（见"坑"）。训练主循环和 [第 46 章](../p09-detection/ch46-yolo-inference.md) 同一套路，真实输出：

```text
训练集 96 张 28x28 图，测试集 48 张。各类像素占比：
  背景    78.3%    竖条 5.7%    横条 6.8%    方块 9.1%
开始训练小型 U-Net（带跳跃连接，AdamW, lr=2e-3→5e-4，逐像素交叉熵）...
  epoch   1  逐像素交叉熵 loss = 1.3765
  epoch  40  逐像素交叉熵 loss = 0.2983
  epoch  80  逐像素交叉熵 loss = 0.0280
  epoch 100  逐像素交叉熵 loss = 0.0237
```

loss 从 1.38 稳稳降到 0.02。存权重、加载回来（`VarMap::save` + `unsafe from_mmaped_safetensors`，与 [第 42 章](../p08-classification/ch42-candle-classify.md) 加载真实模型**同一套 API**），再在测试集上算指标：

```text
===== 测试集评估（带跳跃连接）=====
逐像素准确率 = 99.35%
  IoU[背景] = 0.993   IoU[竖条] = 0.954   IoU[横条] = 0.965   IoU[方块] = 0.968
mIoU（各类 IoU 平均）= 0.970
```

**mIoU 0.970、逐像素准确率 99.35%**，四个类别（包括又细又难的竖条、横条）IoU 都在 0.95 以上。程序还会把每张测试图存成"**输入图 | 预测掩码 | GT 掩码**"的三联对照 PNG（`seg_0.png` .. `seg_4.png`），肉眼可见预测掩码和真值几乎重合，连细窄条的边界都恢复得很干净。

### 跳跃连接到底值多少？——一次真实消融

现在把 `use_skip` 关掉（跳跃连接送零），其余**完全不变**（同一初始权重、同数据、同轮数）再训一个，对比：

```text
===== 跳跃连接消融对比（skip on vs off，其余完全一致）=====
  有跳跃连接：逐像素准确率 99.35%   mIoU 0.970
  无跳跃连接：逐像素准确率 86.31%   mIoU 0.414
  → 跳跃连接把 mIoU 提升了 0.556（细节/边界靠它从编码器直送解码器恢复）
```

**mIoU 从 0.970 塌到 0.414。** 注意逐像素准确率只从 99.35% 掉到 86.31%（因为背景占大头，还是能"蒙"对不少），但 mIoU **腰斩还不止**——目标的边界一糊，交并比立刻崩。这组数字同时印证了两件事：**跳跃连接对恢复细节至关重要**，以及 **mIoU 比逐像素准确率诚实得多**。

## DeepLab 的空洞卷积：把感受野"撑大"而不丢分辨率

U-Net 靠"下采样再上采样"扩感受野，代价是中途丢了分辨率、要靠跳跃连接补回来。**DeepLab** 系列走了另一条路：**空洞卷积（atrous / dilated convolution，膨胀卷积）**——在卷积核的采样点之间"插洞"，让同样 3×3 的核去覆盖更大的范围，**既不增加参数、也不降低分辨率**。设核大小 \\( k \\)、膨胀率（dilation）\\( d \\)，它的一维感受野是：

\\[ \text{RF} = 1 + (k-1)\cdot d \\]

`k=3, d=1` 时感受野 3；`k=3, d=2` 时感受野涨到 5，但权重还是那 9 个。在 candle 里，这只是 `Conv2dConfig` 的一个字段（配上相应 `padding` 保持边长）。本章附了个能跑的最小演示，真实输出：

```rust
// 普通 3x3：padding=1 → 保持 8x8，感受野 3x3
let normal = conv2d(8, 8, 3, Conv2dConfig { padding: 1, ..Default::default() }, vb.pp("normal"))?;
// 空洞 3x3：dilation=2 → 感受野 5x5；配 padding=2 仍保持 8x8，参数量与普通 3x3 完全相同
let atrous = conv2d(8, 8, 3, Conv2dConfig { padding: 2, dilation: 2, ..Default::default() }, vb.pp("atrous"))?;
```

```text
  普通卷积  dilation=1：输出 [1, 8, 8, 8]，感受野 3x3，权重数 576
  空洞卷积  dilation=2：输出 [1, 8, 8, 8]，感受野 5x5，权重数 576
```

同样 576 个权重、同样 8×8 的输出分辨率，感受野却从 3×3 撑到了 5×5。DeepLab 正是用一组不同膨胀率的空洞卷积（叫 **ASPP，空洞空间金字塔池化**）在同一分辨率上"看"多个尺度的上下文。

> ⚠️ **注意（诚实边界）**：这里只是演示空洞卷积这**一个算子**和它的思想。真实的 DeepLabv3+ 用的是 ResNet/Xception 这样的大骨干 + ASPP + 在大规模数据集（如 Cityscapes、PASCAL VOC）上训练出的几十上百 MB 权重，纯 Rust 一键 demo 跑不动它的完整体。要在纯 Rust 里跑真实分割大模型，务实路线是**下载官方导出的 ONNX 权重**，用 `tract-onnx`（纯 Rust，见 [第 94 章](../p19-deploy/ch94-onnx.md)）加载推理——和 [第 46 章](../p09-detection/ch46-yolo-inference.md) 跑真实 YOLO 是同一条思路：**结构与预处理讲透，权重靠下载**。

## 常见坑与提示

> 🕳️ **坑**：**离散掩码缩放，必须用最近邻插值。** 图像可以双线性/三线性平滑缩放，但**类别掩码绝对不能**——双线性会在"类别 1"和"类别 3"的边界处插出个"1.8"，四舍五入成不存在的类别 2，凭空制造错误标签。缩放掩码一律用 `FilterType::Nearest`（本章画掩码 PNG 时正是这么做的）。

> 🕳️ **坑**：**`cross_entropy` 的目标必须是 U32，且形状要对齐。** 分割的 logits 是 `[N,C,H,W]`，得先 `permute` 成 `[N,H,W,C]`、`contiguous()` 后再 `reshape` 成 `[N·H·W, C]`，目标同步摊平成 `[N·H·W]` 的 U32 向量。忘了 `contiguous()`（permute 后内存非连续）会直接 reshape 报错；目标用了 F32 也会报类型错。

> ⚠️ **注意**：**别只盯着逐像素准确率。** 分割任务背景像素往往占绝对多数，准确率会被"蒙背景"严重虚高（本章无跳跃连接版准确率还有 86%，mIoU 却只有 0.41）。评估**必须报 mIoU 和各类 IoU**，尤其盯住小目标和边界那几类。

> 💡 **提示**：**candle 0.11 的 CPU 后端不能 `set_seed`。** 和 [第 42 章](../p08-classification/ch42-candle-classify.md)、[第 46 章](../p09-detection/ch46-yolo-inference.md) 一样，本章用自造的确定性初始化（固定种子的 LCG 写权重）保证每次 `cargo run` 的 loss、mIoU 逐字可复现。消融对比之所以公平，也正因为两个模型都从**同一份**确定性初始权重出发。

> 📖 **术语**：**转置卷积 vs 上采样+卷积**。转置卷积（也叫反卷积）是可学习的放大算子，但容易产生棋盘格伪影，且 candle 0.11 没提供顺手的接口。本章用**最近邻上采样 + 3×3 卷积**替代：先无参放大，再用卷积把"马赛克"抹平并学习细节。二者目的相同——把低分辨率特征图放大回去。

## 本章小结

- **语义分割 = 逐像素分类**：把分类网的输出从 `[N,C]` 变成 `[N,C,H,W]`，每个像素一份类别 logits，损失就是**逐像素交叉熵**（摊平成 `[N·H·W, C]` + U32 目标即可复用分类交叉熵）。
- **编码器-解码器**先下采样（抽语义、扩感受野、省算力）再上采样（恢复分辨率）；candle 无转置卷积，用**最近邻上采样 + 卷积**实现放大。
- **跳跃连接**把编码器的高分辨率特征抄近道送给解码器，恢复被下采样糊掉的边界。实测：关掉它 mIoU 从 **0.970 掉到 0.414**。
- **mIoU**（各类 IoU 平均）比逐像素准确率诚实得多，尤其在背景占大头的类别不平衡场景。本章小 U-Net 达到 **mIoU 0.970、准确率 99.35%**。
- **DeepLab 的空洞卷积**用膨胀率在核里"插洞"，同样参数、同样分辨率把感受野 3×3 撑到 5×5；真实 DeepLab 需大骨干 + 大权重，纯 Rust 务实路线是下载 ONNX 用 tract 推理。

## 动手练习

1. **调消融看曲线**：把训练轮数从 110 改成 40、70、110、160，各跑一遍，记录"有/无跳跃连接"两条 mIoU。你会发现无跳跃连接版**再怎么多训也追不上**——差距是结构性的，不是训练不够。
2. **换个上采样**：把 `upsample_nearest2d`（最近邻）换成 `interpolate2d`（双线性），重训看 mIoU 和边界 PNG 有无变化，体会两种上采样的差别。
3. **加一类、加难度**：把噪声标准差从 22 调到 40，或再加一类形状（`NC` 改成 5），重训，观察哪个类的 IoU 最先崩——通常是最细小的那类。
4. **手算一次 IoU**：挑一张 `seg_*.png`，对着预测和 GT 掩码，手数某一类的交集和并集像素数，验证程序算的 IoU 对不对——把公式变成肌肉记忆。
5. **想一想**：如果前景像素只占 1%（比如极小的缺陷检测），只用逐像素交叉熵训练会发生什么？该怎么办？（提示：类别加权，或引入 Dice 损失——见本章延伸。）

## 延伸阅读 / 下一章预告

- **Dice 损失**：前景极稀少时，交叉熵会被背景淹没。Dice 损失 \\( L_{Dice} = 1 - \frac{2\sum_i p_i y_i + \epsilon}{\sum_i p_i + \sum_i y_i + \epsilon} \\) 直接优化"交并"式的重叠，常和交叉熵加权组合使用，是医学分割的常客。
- **重叠滑窗推理**：大图分块推理时，块与块的接缝要对 **logits** 融合（而不是对 argmax 后的类别投票），边缘用平滑权重，才不会出现接缝。

本章把"每个像素属于**哪一类**"做通了。但很多场景还要区分"这是**哪一个**"——图里有三只羊，语义分割只会把它们涂成同一片"羊"，而**实例分割**要把三只分开。下一章我们就上**实例分割与全景分割**。👉 [第 50 章](ch50-instance-seg.md)
