# 第 50 章 实例分割与全景分割

> **本章导读**
> - 学完你能：讲清 **语义分割 vs 实例分割 vs 全景分割** 的区别，并亲手搭一个**教学版 Mask R-CNN**——**先检测每个实例（框 + 类别），再为每个实例预测一张掩码**。
> - 你会看到实例分割最关键的能力：**把同一类的不同个体分开**（两只羊、两个方块，各自一张掩码），这是 [第 49 章](ch49-semantic-seg.md) 语义分割做不到的。
> - 我们复用 [第 46 章](../p09-detection/ch46-yolo-inference.md) 的网格检测器 + [第 49 章](ch49-semantic-seg.md) 的小 U-Net 掩码头，在合成多目标场景上训练，报**真实数字**：检测率 **99.3%**、命中框平均 IoU **0.842**、每实例掩码 IoU（RoI 帧 **0.954** / 整图帧 **0.811**）。
> - **诚实边界**：真实 Mask R-CNN 用 RPN + FPN + RoIAlign + 大骨干，纯 Rust 从零到全量 CPU 不现实；务实路线是用 `tract` 加载导出的 ONNX（[第 94 章](../p19-deploy/ch94-onnx.md)）。
> - 代码本机 `cargo run --release` 实测（纯 CPU、约 2~3 分钟），数字均为真实输出、可复现。

## 场景：一群羊，怎么数清楚有几只

[第 49 章](ch49-semantic-seg.md) 的语义分割能把画面里所有"羊"像素涂成同一种颜色——但如果三只羊挨在一起，它涂出来是**一整片"羊"**，你根本数不出是三只。很多任务恰恰要区分**个体**：自动驾驶要分清"前面是**两辆**车还是一辆"，细胞计数要数清**每一个**细胞，抓取机器人要知道该抓**哪一个**零件。这就需要**实例分割（instance segmentation）**：不但要知道每个像素"是什么类"，还要知道它"属于**哪一个**个体"。

## 原理：三种"分割"到底差在哪

先把三个容易混的概念一次讲清（用一张"三只羊 + 草地天空"的画面来对照）：

| 分割类型 | 回答的问题 | 对"三只挨着的羊" | 对"草地/天空" |
|---|---|---|---|
| **语义分割**（[第 49 章](ch49-semantic-seg.md)） | 每个像素**是什么类** | 涂成一整片"羊" | 各涂一片 |
| **实例分割**（本章） | 每个像素属于**哪一个个体**（只管可数物体） | 分成**羊#1 / #2 / #3**，各一张掩码 | 通常不管 |
| **全景分割**（panoptic） | 上面两者**合体** | 可数物体（thing）分个体 | 不可数背景（stuff）涂类别 |

> 📖 **术语**：**thing 与 stuff**。可数、有明确个体边界的物体（人、车、羊）叫 **thing**；不可数、成片的背景（天空、草地、马路）叫 **stuff**。实例分割只处理 thing；全景分割（panoptic segmentation）把"thing 分个体 + stuff 涂类别"融合成一张**无重叠**的完整图，用 \\( PQ = SQ \times RQ \\) 衡量质量——\\( SQ \\)（分割质量）看匹配区域掩码有多准，\\( RQ \\)（识别质量）看个体检出得全不全。本章聚焦实例分割，全景分割一句带过。

### Mask R-CNN 的思想：先检测，再逐实例分割

怎么才能"区分个体"？**Mask R-CNN** 给了一个朴素又有效的答案：**既然检测器本来就能把每个个体框出来，那就先检测出每个实例（框 + 类别），再对着每一个框单独预测一张掩码。** 一个框对应一个个体，框里的分割自然就是**那一个个体**的掩码——个体区分的问题，被"检测"这一步顺手解决了。

它是**两阶段（two-stage）**结构：

```text
             ┌────────────────── 三个并列的头 ──────────────────┐
图 ─骨干─▶ 特征 ─RPN─▶ 候选框 ─RoIAlign─▶ 每个RoI固定尺寸特征 ─┬─▶ 分类头（是什么类）
                     (region proposal)   (对齐抠特征)          ├─▶ 框回归头（框微调）
                                                               └─▶ 掩码头（28×28 前景/背景掩码）
```

- **RPN（区域提议网络）**：先粗略提出一堆"这里可能有东西"的候选框。
- **RoIAlign**：把每个候选框对应的特征，**对齐并抠成固定尺寸**（比如 14×14），好送进后面统一大小的头。
- **三个头**：分类（这框是什么类）、框回归（把框修准）、**掩码头**（对这个 RoI 输出一张固定尺寸如 **28×28** 的掩码，只分"**本实例**前景 / 背景"两类）。

> 📖 **术语**：**RoIAlign**。候选框大小各异，但后面的头要求固定尺寸输入。RoIAlign 用**双线性采样**把任意大小的框区域重采样成固定的小特征图（如 14×14），且**不做取整**（这是它比老的 RoIPool 强的地方——避免半个像素的错位累积到掩码边界上）。

注意掩码头只做**前景/背景二分类**（类别已经由分类头给了），所以它对所有类别通用——这也是为什么 Mask R-CNN 的掩码头很小、很省。

## 动手：搭一个教学版 Mask R-CNN

> ⚠️ **注意（诚实的工程取舍）**：真实 Mask R-CNN 的 RPN + FPN + RoIAlign + Res101 骨干，从零在纯 CPU 上训到能用**不现实**。教学版我们抓住**"先检测、再逐实例掩码"**这个核心，把两阶段各自换成我们已经跑通的小模块：**检测**复用 [第 46 章](../p09-detection/ch46-yolo-inference.md) 的网格检测器（代替 RPN + 检测头），**掩码**复用 [第 49 章](ch49-semantic-seg.md) 的小 U-Net（对每个框裁一张 28×28 的 RoI 小图做前景/背景分割）。代码见 `code/dl_labs/ch50_maskrcnn/`，`cargo run --release` 即可复现（纯 CPU 约 2~3 分钟）。

**合成数据**：48×48 场景，随机放 2~4 个形状——**圆形、菱形、三角形**。这里特意用**不填满外接框**的形状（圆约占框的 78%、菱形/三角约 50%），这样掩码头才有**真活干**（否则掩码 = 整个框，太平凡、IoU 恒等于 1 就没意义了）。每个形状记下它的类别、外接框和**逐像素实例掩码**。允许同类多个个体（两个圆、两个菱形）——正是为了演示"区分个体"。

**检测阶段**直接搬 [第 46 章](../p09-detection/ch46-yolo-inference.md) 的做法（这里只提关键点，细节见该章）：

- 骨干三段"卷积 + 池化"把 48×48 降到 **6×6 网格**，1×1 卷积头每格输出 `A = 1(obj) + 4(框) + 3(类别) = 8` 个数；
- **框中心用"格号 + 格内偏移"注入格子坐标**（卷积平移不变，直接回归绝对坐标学不动）；
- objectness 和类别用**数值稳定的自写 BCE** `max(x,0) - x*y + log(1+exp(-|x|))`（别用 `binary_cross_entropy_with_logit`，会 NaN）；
- 训练中用 `AdamW::set_learning_rate` 后段降 lr 提锐度；推理用**类别感知 NMS** 去重。

**掩码阶段**是本章的新增。掩码头就是 [第 49 章](ch49-semantic-seg.md) 那个带跳跃连接的小 U-Net，只是输入是 **28×28 的 RoI 小图**、输出是 **2 类（背景 / 本实例前景）**：

```rust
struct MaskNet { /* enc1..head：3→8→16→32 的小 U-Net，输出 2 类 */ }
impl MaskNet {
    fn forward(&self, x: &Tensor) -> Result<Tensor> {           // 输入 [T,3,28,28]
        let e1 = self.enc1.forward(x)?.relu()?;                 // 细节层（供 skip）
        let p1 = e1.max_pool2d(2)?;                             // 28→14
        let e2 = self.enc2.forward(&p1)?.relu()?;               // 中层（供 skip）
        let b  = self.bott.forward(&e2.max_pool2d(2)?)?.relu()?;// 14→7 瓶颈
        let u2 = self.up2.forward(&b.upsample_nearest2d(M/2, M/2)?)?.relu()?; // 7→14（2× 整数）
        let d2 = self.dec2.forward(&Tensor::cat(&[&u2, &e2], 1)?)?.relu()?;   // 跳跃连接
        let u1 = self.up1.forward(&d2.upsample_nearest2d(M, M)?)?.relu()?;    // 14→28（2× 整数）
        let d1 = self.dec1.forward(&Tensor::cat(&[&u1, &e1], 1)?)?.relu()?;   // 跳跃连接
        self.head.forward(&d1)                                  // [T,2,28,28]
    }
}
```

训练时用 **GT 框**把每个实例裁成 28×28 小图喂掩码头（teacher forcing，正样本 RoI），掩码目标是该实例掩码裁到框内、resize 到 28×28。**掩码损失就是 [第 49 章](ch49-semantic-seg.md) 的逐像素交叉熵**（摊平 + U32 目标）。检测损失（obj/框/类别三件套）与掩码损失**加权求和、一起反向**——这就是 Mask R-CNN 的"多任务联合训练"。真实训练输出：

```text
训练集 112 张 48x48 图，共 326 个实例（平均每图 2.91 个）
  epoch    total      obj      box      cls     mask
      1   3.0321   0.9722   0.1328   0.6933   0.7025
     80   0.3278   0.1301   0.0229   0.0022   0.0809
    120   0.2206   0.0908   0.0123   0.0014   0.0671
```

四项损失一起稳稳下降。存权重、加载回来（`VarMap::save` + `unsafe from_mmaped_safetensors`，与加载真实 Mask R-CNN 权重**同一套 API**），分两个层次评估：

```text
===== 掩码头单独评估（用 GT 框，RoI 帧 28×28）=====
每实例掩码 IoU（RoI 帧）= 0.954（142 个实例）

===== 完整实例分割管线评估（检测 → 逐实例掩码）=====
真值实例 142 个，正确检出 141 个（检出率 99.3%）
命中框平均 IoU = 0.842
命中实例的整图掩码 IoU = 0.811
```

两个 IoU 的**差距很有讲头**：

- **RoI 帧掩码 IoU 0.954**：喂给掩码头**准确的 GT 框**时，它能把框里的实例形状分得很干净——这是**掩码头本身**的质量。
- **整图掩码 IoU 0.811**：完整管线里，框来自检测器（平均 IoU 0.842，不完美），框歪一点、掩码贴回整图时就会跟着歪。所以**端到端的实例掩码质量，被检测精度"卡"住了**——这正是真实 Mask R-CNN 里"掩码 AP 强烈依赖检测框质量"的缩影。

程序还会把每张测试图存成"输入 | 预测实例掩码 | GT 实例掩码"的三联 PNG，**每个实例涂一种不同的颜色**。你会清楚看到：输入里**两个同类（比如两个菱形）的个体，在掩码图里是两块不同颜色**——这就是实例分割相对语义分割的核心价值（语义分割会把两个菱形涂成同一种"菱形"色）。

> 💡 **提示**：PNG 里的颜色只用于**在同一张图内区分不同个体**，预测图和 GT 图之间颜色不必一一对应（预测按检测得分排序上色，GT 按生成顺序上色）。看的是"个体有没有被分开"，不是"颜色对不对得上"。

## 常见坑与提示

> 🕳️ **坑（本章真实踩到的 candle 0.11 限制）**：**`upsample_nearest2d` 的反向传播只支持整数、均匀的放大倍数，`upsample_bilinear2d` 干脆没有反向。** 这意味着"把任意大小的**特征**框 resize 到固定尺寸"（真正的 RoIAlign）在**训练时**会报 `backward not supported for non integer upscaling factors`。我们的绕法：把 RoI 的 resize 放在 **Rust 侧对图像**做（裁图 + `image::imageops::resize`，不进 autograd），掩码头内部只用 **2× 整数上采样**（7→14→28），反向就安全了。代价是掩码头没复用检测骨干的特征（真实 Mask R-CNN 靠 RoIAlign 共享骨干特征更高效）——这是教学版为了纯 CPU 可训做的诚实取舍。

> ⚠️ **注意**：**坐标链每一步都要对齐。** 原图 → 框 → RoI 固定网格（28×28）→ 掩码贴回原图，中间每次缩放都要保住浮点精度；**阈值化（argmax 成 0/1）要在 resize 到目标坐标之后做**，否则边界会有系统性偏差。这条坐标纪律和 [第 46 章](../p09-detection/ch46-yolo-inference.md) 的 letterbox 逆变换是一个道理。

> ⚠️ **注意**：**实例的 NMS 是按框还是按掩码，要想清楚。** 本章用**框级类别感知 NMS**（[第 46 章](../p09-detection/ch46-yolo-inference.md)）。但拥挤场景里两个个体**框高度重叠、掩码却可分**，框 NMS 会误删一个——这时**掩码 IoU 的 NMS** 更合适（代价是更贵）。按目标密度和延迟预算选。

> 💡 **提示**：**评估实例分割用 mask AP，不是像素 IoU。** 像素级 IoU 不反映"个体粘连、重复、漏检"。实例分割的标准指标是 **mask AP**（把 [第 48 章](../p09-detection/ch48-metrics-annotation.md) 检测的 AP 里"框 IoU"换成"掩码 IoU"），并按目标面积、拥挤度分桶分析。

> 🕳️ **坑**：**合成数据的"泄漏"会被卷积的平移等变性掩盖。** 我们的场景是随机生成的、天然不重复；但真做数据集时，同一目标的近重复帧若被同时分进训练和测试，会让指标虚高。要老实演示泄漏，得**减少场景多样性 + 放很多近重复帧 + 加难样本**（[第 47 章](../p09-detection/ch47-train-detector.md)）。

## 本章小结

- **语义分割**只分"是什么类"（同类个体不分开）；**实例分割**还要分"是**哪一个**个体"，各给一张掩码；**全景分割**是二者合体（thing 分个体 + stuff 涂类别，无重叠，用 \\( PQ=SQ\times RQ \\) 衡量）。
- **Mask R-CNN 的核心思想**：**先检测每个实例（框 + 类别），再对每个 RoI 用一个小掩码头预测固定尺寸（28×28）的前景/背景掩码**——个体区分被"检测"顺手解决。两阶段：RPN → RoIAlign → 分类/框/掩码三头。
- 我们的**教学版** = [第 46 章](../p09-detection/ch46-yolo-inference.md) 网格检测器 + [第 49 章](ch49-semantic-seg.md) 小 U-Net 掩码头。实测：检出率 **99.3%**、框 IoU **0.842**、掩码 IoU（RoI 帧 **0.954** / 整图帧 **0.811**）。**RoI 帧与整图帧的差距说明：端到端掩码质量被检测精度卡住**。
- **诚实边界**：真实 Mask R-CNN 需 RPN + FPN + RoIAlign + 大骨干，纯 Rust 全量 CPU 不现实；务实路线是 `tract` 加载导出的 ONNX（[第 94 章](../p19-deploy/ch94-onnx.md)）。candle 0.11 的 `upsample` 反向只支持整数倍，做特征级 RoIAlign 训练会踩坑，本章把 RoI 的 resize 放到 Rust 侧图像上绕过。

## 动手练习

1. **调 λ_mask 看权衡**：把掩码损失权重从 1.0 改成 0.3 和 3.0，重训，看检测指标和掩码 IoU 怎么此消彼长——体会多任务训练的平衡。
2. **换真掩码的形状**：把三角形换成"月牙"或"L 形"（掩码更不规则、离框更远），重训，看整图掩码 IoU 掉多少——越不规则的形状越考验掩码头。
3. **喂错框看崩坏**：推理时故意把检测框放大 1.3 倍再送掩码头，观察掩码 IoU 怎么降——亲手验证"检测框质量决定端到端掩码质量"。
4. **想一想**：如果两个同类个体紧挨着、框几乎重叠，框级 NMS 会怎样？该换成什么 NMS？（提示：掩码 IoU NMS。）
5. **接真实模型（进阶）**：找一个导出的 Mask R-CNN / YOLO-seg ONNX，用 [第 94 章](../p19-deploy/ch94-onnx.md) 的 `tract` 骨架加载，对一张真实照片跑实例分割；先 `println!` 出各输出张量的形状，确认"框 / 类别 / 掩码系数 / 原型"的布局再解码。
