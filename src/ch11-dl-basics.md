# 第 11 章 · 深度学习速成：神经网络与模型文件

> **本章导读**：第 10 章我们费了好大劲，把一张普通照片揉成了模型爱吃的 `1×3×640×640` 张量。可那个"模型"从第 1 章起就一直是个黑箱——我们只知道往里塞张量、接住一堆数字。本章掀开盖子看看里面：神经网络到底在算什么、模型文件里究竟存了什么。这是一章"够用就好"的速成课，**目标不是让你会训练神经网络**（那是另一条职业路线），而是让你作为部署工程师，看懂后面几章绕不开的三件事——推理在算什么、模型文件是什么、为什么还需要一个推理引擎。数学一律先打比方、再用小数字手算，绝不推导。

**学习目标**：

- 理解**前向传播（推理）**的本质就是一连串矩阵乘法 + 激活，并用 Rust 手写一遍
- 认识常见的层（卷积 / 池化 / 全连接 / 激活 / BatchNorm / Softmax）各自干什么
- 分清训练与推理，明白**本书全程只做推理**；看懂模型文件里的"计算图 + 权重"

## 11.1 从"人写规则"到"从数据里学规则"

第 1 章我们对比过两大流派，这里把那根线接上。传统算法（第 7~9 章）是**人写规则**：要找瑕疵，就先 Canny 找边缘、再筛形状异常的连通域——每一步为什么这么做，工程师都能说清楚。可一旦让你写一条规则描述"什么是猫"，你会立刻卡壳：尖耳朵？有胡须？可狐狸也有。规则根本写不完。

深度学习换了个思路：**不写规则，改喂例子**。你给它看一万张标好"这是猫 / 这不是猫"的图，让它自己去总结"猫长什么样"。这个"自己总结"的过程叫**训练（training）**，总结出来的产物就是**模型（model）**——本质是一大堆数字，存成一个文件。之后拿这个模型去判断新图片，叫**推理（inference）**。

```text
传统算法：  人类观察 → 人脑总结规则 → 写成代码 → 跑
深度学习：  喂大量带标签的例子 → 程序自己总结规则（=一堆数字）→ 拿这堆数字跑
```

关键的认知转变是：深度学习里"规则"不再是人能一条条读出来的 `if-else`，而是**藏在一大堆数字（权重）里的模式**。这堆数字是怎么组织、怎么参与计算的？这就要从最小的零件——神经元——讲起。

## 11.2 神经元：一次加权投票

神经网络的最小零件叫**神经元（neuron）**。别被"神经"两个字唬住，它做的事简单到一句话就能说完：**把每个输入乘上各自的权重，全部加起来，再加一个偏置，最后过一道激活函数。** 写成公式：

$$y = f(w_1 x_1 + w_2 x_2 + \cdots + w_n x_n + b)$$

打个比方——一个神经元就像一台**调音台**：

```text
  x₁ 人声 ──[旋钮 w₁]──┐
  x₂ 吉他 ──[旋钮 w₂]──┼─► 混音(求和) ─+底噪(偏置 b)─► [阀门 f] ─► 输出 y
  x₃ 鼓  ──[旋钮 w₃]──┘
```

- 每一路**输入** $x_i$ 是一路声音信号；
- 每个**权重** $w_i$ 是那一路的音量旋钮，决定这路信号有多重要（甚至可以调成负的，表示"这路越强我越反对"）；
- 把各路混在一起就是**加权求和**；
- **偏置** $b$ 是一个整体的偏移量，相当于"及格线"高低；
- 最后的**激活函数** $f$ 像一道阀门，决定这个混合信号要不要放行、以什么形态放行。

换成"投票"也一样：每个输入是一位评委的打分，权重是这位评委的话语权，偏置是预设的松紧尺度，激活函数决定最终"过还是不过"。

### 手算一个神经元

光看公式没感觉，我们**用小数字算一遍**。设：

```text
输入   x = [2.0, 1.0, 3.0]
权重   w = [0.5, -0.4, 0.3]
偏置   b = -0.2
激活   f = ReLU（负数归零，正数原样通过）
```

第一步，加权求和（每个输入乘对应权重再相加）：

```text
0.5×2.0  +  (-0.4)×1.0  +  0.3×3.0
 = 1.0   +   (-0.4)     +   0.9
 = 1.5
```

第二步，加偏置：`1.5 + (-0.2) = 1.3`。

第三步，过激活函数 ReLU：`ReLU(1.3) = max(0, 1.3) = 1.3`。

所以这个神经元输出 **1.3**。你看，全程只有乘、加、和一个"取正"，没有任何魔法。如果加权和算出来是负数（比如 -0.9），ReLU 会把它压成 0——这就是激活函数在"把关"。11.5 节我们会把这套手算原样翻译成 Rust。

> **激活函数为什么不可少？** 如果去掉它，纯加权求和叠再多层，最后还是等价于一次加权求和（一条直线套一条直线还是直线），网络就白深了。激活函数插入一点"非线性"，把直线掰弯，多层才有意义。你不用记公式，记住"**激活让多层网络真正有用**"就够了。常见的 ReLU、Sigmoid 后面 11.6 节还会照面。

## 11.3 把神经元堆成网络：层与"深度"

一个神经元只能做一次简单打分，本事有限。把**一排神经元**并起来，让它们各自盯着不同的模式，就成了一**层（layer）**；再把很多层**首尾相接**——上一层的输出当下一层的输入——就成了**神经网络（neural network）**。

```text
 输入层        隐藏层1        隐藏层2        输出层
 (像素)   →   (找边缘)  →   (找部件)  →   ("是猫吗")
  ○○○          ○○○○          ○○○○           ○○
```

所谓**深度学习（deep learning）**，"深"指的就是**层数多**。为什么层多有用？因为每一层都在前一层的基础上做更抽象的归纳，像认字一样层层递进：

```text
第 1 层：横线、竖线、斜线（笔画）
   ↓
第 3 层：格子、条纹、毛发（偏旁）
   ↓
第 5 层：耳朵、眼睛、车轮（部件）
   ↓
最后一层：猫、狗、汽车（整字）
```

低层看到的"笔画"本身没意义，一层层组合起来才拼出"这是一只猫"。你不需要知道每层具体怎么设计——那是训练侧的事——只要建立这个直觉：**网络 = 层的堆叠，深度 = 层数，信息从输入一路被提炼到输出。**

## 11.4 张量：网络里流动的数据

层与层之间传来传去的数据，统一叫**张量（tensor）**。这个词第 3 章已经见过，这里正式收编——它其实是你早就熟悉的东西的统称：

| 维数 | 叫法 | 例子 | 形状写法 |
| --- | --- | --- | --- |
| 0 维 | 标量（scalar） | 一个数 `3.14` | `[]` |
| 1 维 | 向量（vector） | 一行数 `[1, 2, 3]` | `[3]` |
| 2 维 | 矩阵（matrix） | 一张表格 | `[H, W]` |
| 3 维 | 三维数组 | 一张彩色图 | `[C, H, W]` |
| 4 维 | 四维数组 | 一批彩色图 | `[N, C, H, W]` |

一句话：**张量 = 任意维度的数字数组。** 在 Rust 里它就是第 3 章的 `ndarray`——`Array2` 是矩阵、`Array4` 是四维张量，`.shape()` 打印它的形状。

我们最关心的是**图像张量的形状 `[N, C, H, W]`**，四个字母务必记牢：

```text
[ N ,  C ,  H ,  W ]
  │    │    │    └── Width  图像宽（列数）
  │    │    └─────── Height 图像高（行数）
  │    └──────────── Channel 通道数（RGB=3，灰度=1）
  └───────────────── Number  批大小（一次喂几张图）
```

这正是我们全书主模型 YOLOv8 的输入形状 `1×3×640×640`：一次喂 1 张（N=1）、RGB 三通道（C=3）、640 高、640 宽。第 10 章把图排成"通道在前"（CHW）的布局、最前面插一个 batch 维，忙活的就是把一张图凑成这个 `[N, C, H, W]` 张量。而模型的输出也是张量——比如 YOLOv8 吐出的 `float32[1, 84, 8400]`（第 16 章专门解剖它）。

> 一个高频调试习惯（第 3 章也强调过）：拿到任何张量，第一句代码永远先打印 `shape`。绝大多数"喂不进模型 / 结果全错"的 bug，根子都是"张量形状和你以为的不一样"。

## 11.5 前向传播：推理到底在算什么

现在把零件拼起来，回答那个从第 1 章憋到现在的问题：**把张量喂进模型，它到底在算什么？**

答案朴素得惊人：**从输入层到输出层，数据被一层层往前推，每一层做的就是"矩阵乘法 + 激活函数"，如此反复。** 这个"数据从头流到尾"的过程叫**前向传播（forward propagation）**，也就是我们天天挂在嘴边的**推理（inference）**。

```text
输入张量 ─►[层1: 矩阵乘 + 激活]─►[层2: 矩阵乘 + 激活]─► … ─►[输出层]─► 输出张量
         （越往后越抽象，最后浓缩成"92% 是猫"这样的结论）
```

为什么一层能写成"矩阵乘法"？回忆 11.2：一个神经元是一次加权求和。一层有很多神经元，每个神经元对同一批输入各做一次加权求和——把这些加权求和**打包**，正好就是一次**矩阵乘法**（一堆点积并行做）。这就是为什么 GPU/NPU 这类"矩阵乘法加速器"能让推理飞快。

下面用 Rust 把它**从零写一遍**，不借任何模型、不借任何魔法，你会看到推理真的就是小学算术的堆叠。

### 手写一个迷你神经元和全连接层

先用最朴素的 `Vec<f32>` + 点积 + ReLU 实现单个神经元，再把一排神经元凑成一层"全连接层"：

```rust,ignore
/// ReLU 激活函数：负数归零，正数原样通过
fn relu(x: f32) -> f32 {
    x.max(0.0)
}

/// 一个神经元：加权求和 + 偏置 + 激活
/// inputs 与 weights 一一对应，长度必须相等
fn neuron(inputs: &[f32], weights: &[f32], bias: f32) -> f32 {
    // 点积：每个输入乘对应权重，再全部加起来
    let weighted_sum: f32 = inputs
        .iter()
        .zip(weights)
        .map(|(x, w)| x * w)
        .sum();
    relu(weighted_sum + bias) // 加偏置，再过激活
}

/// 一个全连接层（Fully-Connected / Dense）：n_out 个神经元
/// weights[i] 是第 i 个神经元的权重行，biases[i] 是它的偏置
fn dense_layer(inputs: &[f32], weights: &[Vec<f32>], biases: &[f32]) -> Vec<f32> {
    weights
        .iter()
        .zip(biases)
        .map(|(row, &b)| neuron(inputs, row, b)) // 每个神经元各算各的
        .collect()
}

fn main() {
    let x = [2.0_f32, 1.0, 3.0];

    // 单个神经元：复现 11.2 的手算，应得到 1.3
    let y = neuron(&x, &[0.5, -0.4, 0.3], -0.2);
    println!("单个神经元输出 = {y}"); // 1.3

    // 一层两个神经元：第 2 个神经元的加权和会是负数，被 ReLU 压成 0
    let w = vec![
        vec![0.5, -0.4, 0.3], // 神经元 0
        vec![0.1, 0.2, -0.6], // 神经元 1
    ];
    let b = [-0.2, 0.5];
    let out = dense_layer(&x, &w, &b);
    println!("这一层的输出 = {out:?}"); // [1.3, 0.0]
}
```

跑起来输出 `[1.3, 0.0]`：第一个神经元和我们 11.2 手算的完全一致；第二个神经元加权和是 `0.1×2 + 0.2×1 + (-0.6)×3 + 0.5 = -0.9`，被 ReLU 压成了 0。**这就是一层全连接的全部秘密**——没有任何你看不懂的东西。把这样的层一层接一层，就是一个（简化版的）神经网络在做推理。

### 用 ndarray 把"一层"写成一次矩阵乘法

上面的 `dense_layer` 是一个神经元一个神经元地循环算的，直观但慢。工程上会把整层打包成**一次矩阵乘法**，交给高度优化的库去算。用第 3 章的 `ndarray` 演示同一层：

```rust,ignore
use ndarray::{array, Array2};

fn main() {
    // 输入向量 x，看成 1×3 的行向量（1 个样本、3 个特征）
    let x: Array2<f32> = array![[2.0, 1.0, 3.0]]; // 形状 [1, 3]

    // 权重矩阵 W：每一列是一个神经元的权重
    // 3 个输入 → 2 个神经元，所以形状是 [3, 2]
    let w: Array2<f32> = array![
        [0.5, 0.1],
        [-0.4, 0.2],
        [0.3, -0.6],
    ];

    // 每个神经元一个偏置，排成 [1, 2] 好和输出对齐
    let b: Array2<f32> = array![[-0.2, 0.5]];

    // 核心一步：矩阵乘法 [1,3] · [3,2] = [1,2]，再加偏置
    let mut y = x.dot(&w) + &b;

    // 逐元素过 ReLU
    y.mapv_inplace(|v| v.max(0.0));

    println!("这一层的输出 = {y}"); // [[1.3, 0]]
}
```

结果和手写版数值一致：`[[1.3, 0]]`（`ndarray` 把 `0.0` 直接显示成 `0`）。区别只在于——`x.dot(&w)` 一次矩阵乘就并行算完了所有神经元的加权和。**记住这个等式：一层 ≈ 一次矩阵乘法 + 加偏置 + 过激活。** 把它串成几十上百次，就是一次完整推理。真实模型无非是把这里的 `[1,3]·[3,2]` 换成动辄上百万个数字的大矩阵，运算种类还是这几样。

## 11.6 常见的层，一句话认脸

真实网络里除了全连接，还有几种常见的层。你**不用会推导**，只要看到名字知道它大概干什么、后处理时才不慌。每种一句话 + 一个比喻：

| 层 | 干什么 | 打个比方 |
| --- | --- | --- |
| **卷积层（Conv）** | 一堆小滤波器在图上滑动，各自搜寻一种局部模式（边缘、色斑、纹理） | 就是第 7 章的卷积核，只不过核里的数字不是人手写的，而是**训练学出来的** |
| **池化层（Pooling）** | 在邻域里取个代表（最大或平均），把特征图缩小一半——降采样 | 把 4K 照片缩成预览缩略图，省算力还抗轻微位移 |
| **全连接层（FC）** | 每个神经元连接上一层全部输出，汇总所有信息打分 | 全体评委一起投票，得出最终结论（11.5 手写的就是它） |
| **激活层（ReLU/Sigmoid）** | 插入非线性，把直线掰弯 | 阀门：ReLU 是"负的一律关掉"，Sigmoid 是"压成 0~1 的把握度" |
| **BatchNorm** | 把每层数值拉回一个稳定范围，让网络更好训、更稳 | 调音台上的"自动音量平衡"，别让某路信号忽大忽小 |
| **Softmax** | 把最后一排分数变成"加起来等于 1"的概率 | 把各候选得票换算成百分比占比（第 15 章分类会展开） |

特别点一句**卷积层**，因为它是图像模型的主力：第 7 章你已经手写过卷积——一个固定的 3×3 核在图上滑窗、对应相乘再求和。卷积层的运算**一模一样**，唯一的区别是那 9 个（或更多）权重不是你填的，而是模型从数据里学出来的。所以你早就理解了 CNN 最核心的操作，只是当时没往"深度学习"上想而已。至于 Softmax 具体怎么把分数变概率、为什么要先减最大值防溢出，附录 A.10 有手算例子，第 15 章正式用它。

## 11.7 训练 vs 推理：本书只做后者

到这里可以把全书最重要的一组概念钉死了。神经网络的一生分两个阶段：

| | 训练（training） | 推理（inference） |
| --- | --- | --- |
| 干什么 | **调权重**：反复看例子，把每个 $w$、$b$ 慢慢调到能给出正确答案 | 权重**冻结不动**，只拿它算一遍预测 |
| 靠什么 | 海量带标签数据 + 反向传播（一种自动纠错的算法） | 一次前向传播（11.5 讲的那套） |
| 耗时 | 几小时到几周，通常要 GPU 集群 | 几毫秒，单台设备就行 |
| 谁来做 | 算法工程师，多用 Python | 部署工程师（**你**），本书用 Rust |
| 产物 | 一个模型文件 | 检测结果（框、类别、置信度） |

训练怎么"调"权重？一句话带过：拿当前权重预测一遍，和正确答案比差多少，再用**反向传播**把每个权重朝"能减小误差"的方向挪一小点，如此循环几十万次（想象蒙眼下山、每步都往最陡的下坡迈）。**这套本书完全不做**，所以反向传播、学习率、损失函数这些词你可以放心略过。

需要牢牢记住的只有一句：**所谓"参数"或"权重"，就是训练阶段学出来、最后存进模型文件里的那一大堆数字。** 我们做推理，就是拿这堆现成的数字，走一遍 11.5 的前向传播。**本书从头到尾只做推理**——权重是别人训练好的现成经验，我们负责把它在设备上高效、正确地跑起来。

## 11.8 模型文件里到底存了什么

既然推理就是"拿一堆固定的数字做一连串矩阵乘 + 激活"，那么一个模型文件，本质上就要存下这两样东西：

```text
┌─────────────── 模型文件 ───────────────┐
│  ① 计算图（结构）                       │
│     有哪些层、按什么顺序、怎么连线       │
│     —— 相当于一张"施工图纸 / 工序单"    │
│                                         │
│  ② 权重（参数）                         │
│     每一层里那一大堆学出来的数字         │
│     —— 相当于图纸要用的"零件和材料"     │
└─────────────────────────────────────────┘
```

- **计算图（computational graph）**：描述网络长什么样——先卷积、再 ReLU、再池化、最后全连接……每一层是什么类型、参数怎样、数据从哪流到哪。它是"骨架"。
- **权重（weights）**：每一层里具体的数字。现代模型动辄上百万到上亿个参数，一个 32 位浮点数占 4 字节，上亿参数就是几百 MB——所以第 13 章会讲"量化"来给它瘦身。它是"血肉"。

不同框架/厂商把这两样打包成不同格式，先混个脸熟，细节留给后面两章：

| 格式 | 谁的 | 一句话 |
| --- | --- | --- |
| `.pt` / `.pth` | PyTorch | 训练界最常见，和 Python 代码耦合较紧 |
| `.onnx` | 开放标准 | **部署界的"普通话"**，跨框架通用，本书主用（第 13、14 章） |
| `.tflite` | TensorFlow Lite | 手机 / 嵌入式端轻量格式 |
| `.pb` | TensorFlow | TensorFlow 的传统计算图格式 |
| `.rknn` 等 | 厂商专用（如瑞芯微 NPU） | 绑定特定芯片，为其 NPU 极致优化 |

现在只需知道"格式各异，但里面装的都是**计算图 + 权重**"。怎么打开一个模型文件、读出它的输入输出形状和元数据，是第 12 章的活；格式之间怎么转换、怎么量化瘦身、怎么跨平台适配，是第 13 章的活。

## 11.9 为什么还需要一个推理引擎

看到这你可能会问：模型文件里既然连"怎么算"（计算图）带"用什么算"（权重）都齐了，双击一下不就能跑吗？

不能。模型文件是**静态的图纸加一箱零件**，它自己不会动。要真把张量喂进去、按计算图一层层算出结果，得有个"施工队"照着图纸干活——这个施工队就是**推理引擎（inference engine）**。

```text
   模型文件（图纸 + 零件）  ✗ 自己不会算
              +
   推理引擎（施工队）        ✓ 读图纸、按工序、调用硬件把每一层算出来
              ↓
        输入张量 ──► 推理引擎 ──► 输出张量
```

推理引擎负责：解析模型文件、把每种层映射成真正的运算、调度 CPU/GPU/NPU 把矩阵乘法算得飞快、管好中间张量的内存。Rust 生态里就有现成的引擎——纯 Rust 的 `tract-onnx`、性能更强还能上 GPU/NPU 的 `ort`（依赖版本见附录 B 的 crate 表）。**第 14 章我们就用它们，把一个真实的 ONNX 模型在 Rust 里真正跑起来**，接住第一个真实的输出张量。

在那之前，第 12 章会先教你"读懂"一个模型文件：不急着跑，先把它的输入输出形状、数据类型、元数据看明白——就像施工前先把图纸看懂。

## 11.10 小结

- 深度学习的思路是"不写规则、喂例子"，让程序自己把规则总结成一大堆数字（权重）。
- **神经元** = 加权求和 + 偏置 + 激活函数，像一台调音台；手算过一遍就知道，全程只有乘、加和一个"取正"。
- 神经元排成层、层叠成网络，"**深度**"就是层多；层与层之间流动的数据统称**张量**，图像张量的形状是 `[N, C, H, W]`。
- **前向传播（推理）** 的本质就是一连串"矩阵乘法 + 激活"，我们用 `Vec<f32>` 和 `ndarray` 各手写了一遍验证。
- 常见的层（卷积 / 池化 / 全连接 / 激活 / BatchNorm / Softmax）各司其职；卷积就是第 7 章的卷积核，只是权重是学出来的。
- **训练调权重、推理用权重**，本书全程只做推理；模型文件里存的是**计算图 + 权重**，但还需一个**推理引擎**（第 14 章）才能真正跑起来。

## 11.11 练习

1. **手算 + 验证**：输入 `[1.0, -2.0, 4.0]`、权重 `[0.3, 0.5, -0.25]`、偏置 `0.4`，先用纸笔算出过 ReLU 后的输出，再用 11.5 的 `neuron` 函数跑一遍对答案。（提示：加权和加上偏置后是个负数，别忘了 ReLU 会把负数压成 0。）
2. **体会激活的作用**：把 11.5 `neuron` 里的 `relu(...)` 去掉、直接返回 `weighted_sum + bias`，再把两层串起来（第一层输出喂给第二层）。手动把两层的权重合并成一层，验证"没有激活函数时，两层等价于一层"这个结论。
3. **读形状**：一个模型的输入张量打印出来是 `[1, 3, 224, 224]`，输出是 `[1, 1000]`。分别说出输入每一维的含义，并猜猜这大概是个做什么任务的模型、输出的 1000 是什么。（对照 11.4 和第 1 章的任务分类表。）
4. **认格式**：在网上搜 `yolov8n.onnx` 的文件大小，已知它约有 320 万个参数、每个参数是 32 位浮点。估算"参数本身"占多少字节，再和你搜到的文件大小比一比，想想差出来的部分可能是什么（提示：11.8 说模型文件里除了权重还有另一样东西）。
