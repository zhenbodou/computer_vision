# 第 68 章 运动恢复结构 SfM 与视觉 SLAM 概览

> **本章导读**
> - 一张大图看懂 **SfM（Structure from Motion，运动恢复结构）** 的完整流水线：从一堆照片到一片 3D 点云。
> - 亲手实现 SfM/SLAM 的核心积木——**线性三角化（DLT）**：已知两个相机和它们对同一点的 2D 观测，反解出这个点的 3D 坐标。
> - 搞清 **视觉 SLAM** 的三线程结构，以及它和 SfM 的关系与区别；**诚实认识纯 Rust 三维重建/SLAM 生态的现状**。

## 场景引入：一圈照片如何"长"出一座雕像

你举着手机绕一尊雕像走一圈，拍了几十张照片。某些 App（或专业软件）就能把这些**二维照片**拼成一个可旋转观察的**三维模型**。它是怎么做到的？

直觉是这样的：同一个雕像上的鼻尖，在第 1 张和第 5 张照片里都出现了，只是位置不同。如果我们**知道这两张照片是从哪儿、朝哪个方向拍的**，那么"鼻尖在照片 A 的这个像素、在照片 B 的那个像素"这两条信息，就像两根从相机射出的光线——**两根光线在空间中的交点，就是鼻尖的 3D 位置**。把成千上万个这样的点都求出来，雕像的三维形状就浮现了。这个"从相机的运动中恢复场景结构"的过程，就是 **SfM**。

这一章是第十四部分的收尾。前面几章的积木——[第 64 章](ch64-calibration.md) 标定出的内参、[第 66 章](ch66-epipolar-pnp.md) 解出的相对位姿、[第 67 章](ch67-pointcloud.md) 的点云——将在这里被串成一条完整的流水线。我们会亲手写出其中最关键的一环：**三角化**。

## SfM 流水线全景

```text
 一堆无序照片
      │
      ▼
┌───────────────────┐   ①特征提取与匹配（第 24-25 章）
│ 每张图提特征点     │   找到"不同照片里的同一个点"
│ 两两匹配 + RANSAC  │   RANSAC 剔除误匹配
└─────────┬─────────┘
          ▼
┌───────────────────┐   ②两视图几何（第 66 章）
│ 由匹配点求         │   本质矩阵 E / 基础矩阵 F
│ 相机相对位姿 R,t   │   分解得到相机怎么动的
└─────────┬─────────┘
          ▼
┌───────────────────┐   ③三角化 ★本章核心★
│ 两条视线求交点     │   已知两相机 + 2D 观测 → 反解 3D 点
│ → 初始 3D 点云     │
└─────────┬─────────┘
          ▼
┌───────────────────┐   ④增量式加图
│ 新照片用 PnP 定位  │   PnP（第 66 章）：已知 3D 点在新图的
│ 再三角化出新点     │   投影，反求新相机位姿；再三角化新点
└─────────┬─────────┘
          ▼
┌───────────────────┐   ⑤光束法平差 BA
│ Bundle Adjustment  │   同时微调"所有相机位姿+所有 3D 点"，
│ 全局非线性优化     │   让总重投影误差最小
└─────────┬─────────┘
          ▼
   稠密/半稠密 3D 点云、相机轨迹
```

其中**③三角化**是把"2D 观测"变成"3D 结构"的那一步，也是 SfM 与视觉 SLAM 共同的心脏。我们这就把它写出来。

## 原理：线性三角化（DLT）

回忆 [第 6 章](../p01-start/ch06-camera-model.md) 的成像模型：一个 3D 点 \\(X\\)（齐次坐标，4 维）经相机投影矩阵 \\(P\\)（\\(3\times 4\\)）得到像素 \\((u, v)\\)：

\\[ \lambda \, [u,\ v,\ 1]^{T} = P X \\]

这里 \\(\lambda\\) 是未知的深度尺度。记 \\(P\\) 的三行为 \\(P_1, P_2, P_3\\)（每行 4 维）。把上式的尺度消掉（即 \\(u = (P_1 X)/(P_3 X)\\)、\\(v = (P_2 X)/(P_3 X)\\)），整理成关于 \\(X\\) 的线性方程，每个视图给出**两条**：

\\[ u\,(P_3 X) - (P_1 X) = 0, \qquad v\,(P_3 X) - (P_2 X) = 0 \\]

一个视图两条方程、未知的 \\(X\\) 有 3 个自由度（齐次 4 维差一个尺度）。所以**两个视图共 4 条方程**就够解了。把它们堆成一个 \\(4\times 4\\) 矩阵 \\(A\\)，问题变成求解齐次方程：

\\[ A X = 0 \\]

\\(X = 0\\) 是平凡解，我们要的是非平凡解。这正是 [第 30 章](../p05-numeric/ch30-nalgebra.md) 讲过的套路：**对 \\(A\\) 做 SVD，最小奇异值对应的右奇异向量就是 \\(A X = 0\\) 的最优解**（在 \\(\lVert X \rVert = 1\\) 约束下让 \\(\lVert AX \rVert\\) 最小）。解出的 \\(X\\) 是齐次坐标，除以第 4 维就得到 3D 坐标。这套"堆矩阵 + SVD 取零空间"的方法叫 **DLT（Direct Linear Transform，直接线性变换）**。

> 📖 **术语**：**三角化（triangulation）**——已知多个相机的位姿和它们对同一 3D 点的 2D 观测，反求该点 3D 坐标。名字来自测量学里"两个已知点观测同一目标、用三角形定位"的思想。

## 动手写代码：把 3D 点从两张"照片"里解出来

我们造一个完全可控的合成实验：给定内参 \\(K\\)、两个已知相机（相机 2 相对相机 1 向右平移 1m 并偏转 6°）、4 个已知 3D 点；把这些点投影到两个相机得到 2D 观测，再用 DLT 反解 3D 点，最后对比恢复值与真值。

运行：

```bash
cargo run --example ch68_sfm_slam
```

```rust
use nalgebra::{DMatrix, Matrix3, Matrix3x4, Vector2, Vector3, Vector4};

// 自包含小 RNG（xorshift64*），仅用于给观测加噪声，避免引入 rand
struct Rng(u64);
impl Rng {
    fn new(seed: u64) -> Self { Rng(seed | 1) }
    fn next_u64(&mut self) -> u64 {
        let mut x = self.0;
        x ^= x >> 12; x ^= x << 25; x ^= x >> 27;
        self.0 = x;
        x.wrapping_mul(0x2545F4914F6CDD1D)
    }
    fn uniform(&mut self) -> f64 { (self.next_u64() >> 11) as f64 / (1u64 << 53) as f64 }
    fn normal(&mut self) -> f64 { // 标准正态
        let (u1, u2) = (self.uniform().max(1e-12), self.uniform());
        (-2.0 * u1.ln()).sqrt() * (2.0 * std::f64::consts::PI * u2).cos()
    }
}

fn intrinsics() -> Matrix3<f64> { // 内参 K：焦距 800，主点 (320,240)
    Matrix3::new(800.0, 0.0, 320.0, 0.0, 800.0, 240.0, 0.0, 0.0, 1.0)
}

fn rot_y(theta: f64) -> Matrix3<f64> { // 绕 Y 轴旋转
    let (c, s) = (theta.cos(), theta.sin());
    Matrix3::new(c, 0.0, s, 0.0, 1.0, 0.0, -s, 0.0, c)
}

// 组装投影矩阵 P = K [R | t]，t = -R·C（C 为相机光心在世界系中的位置）
fn projection(k: &Matrix3<f64>, r: &Matrix3<f64>, center: &Vector3<f64>) -> Matrix3x4<f64> {
    let t = -r * center;
    let rt = Matrix3x4::new(
        r[(0,0)], r[(0,1)], r[(0,2)], t[0],
        r[(1,0)], r[(1,1)], r[(1,2)], t[1],
        r[(2,0)], r[(2,1)], r[(2,2)], t[2],
    );
    k * rt // (3×3)·(3×4) = (3×4)
}

fn project(p: &Matrix3x4<f64>, x: &Vector3<f64>) -> Vector2<f64> { // 3D 点 -> 像素
    let hom = p * Vector4::new(x.x, x.y, x.z, 1.0);
    Vector2::new(hom.x / hom.z, hom.y / hom.z) // 透视除法
}

// 往 A 填一个视图的两行： u·P3 - P1 = 0 , v·P3 - P2 = 0
fn fill_rows(a: &mut DMatrix<f64>, row: usize, p: &Matrix3x4<f64>, uv: &Vector2<f64>) {
    for c in 0..4 {
        a[(row, c)]     = uv.x * p[(2, c)] - p[(0, c)];
        a[(row + 1, c)] = uv.y * p[(2, c)] - p[(1, c)];
    }
}

// 线性三角化：两视图 -> 4 行方程，解 A·X=0 取最小奇异向量
fn triangulate(p1: &Matrix3x4<f64>, uv1: &Vector2<f64>,
               p2: &Matrix3x4<f64>, uv2: &Vector2<f64>) -> Vector3<f64> {
    let mut a = DMatrix::zeros(4, 4);
    fill_rows(&mut a, 0, p1, uv1);
    fill_rows(&mut a, 2, p2, uv2);
    let vt = a.svd(true, true).v_t.unwrap();         // v_t 最后一行 = 齐次解
    let xh = Vector4::new(vt[(3,0)], vt[(3,1)], vt[(3,2)], vt[(3,3)]);
    Vector3::new(xh.x / xh.w, xh.y / xh.w, xh.z / xh.w) // 齐次 -> 非齐次
}

fn main() {
    let k = intrinsics();
    let p1 = projection(&k, &Matrix3::identity(), &Vector3::zeros()); // 相机1 在原点
    let c2 = Vector3::new(1.0, 0.0, 0.0);                             // 相机2 向右 1m
    let p2 = projection(&k, &rot_y(6.0_f64.to_radians()), &c2);       // 并偏转 6°

    let truth = [ // 4 个已知 3D 点，都在两相机前方
        Vector3::new(0.0, 0.0, 5.0),  Vector3::new(0.5, 0.3, 6.0),
        Vector3::new(-0.4, 0.2, 5.5), Vector3::new(0.2, -0.3, 4.5),
    ];

    println!("==== 无噪声三角化 ====");
    let mut max_err = 0.0_f64;
    for (i, x) in truth.iter().enumerate() {
        let (uv1, uv2) = (project(&p1, x), project(&p2, x)); // 投影得观测
        let rec = triangulate(&p1, &uv1, &p2, &uv2);          // 再反解
        let err = (rec - x).norm();
        max_err = max_err.max(err);
        println!("点{i}: 真值({:+.3},{:+.3},{:+.3}) 恢复({:+.3},{:+.3},{:+.3}) 误差={err:.2e}",
                 x.x, x.y, x.z, rec.x, rec.y, rec.z);
    }
    println!("最大误差 = {max_err:.2e} m（接近机器精度）");

    println!("\n==== 加 0.5px 观测噪声 ====");
    let mut rng = Rng::new(2024);
    let (sigma, mut sum) = (0.5, 0.0_f64);
    for x in truth.iter() {
        let (mut uv1, mut uv2) = (project(&p1, x), project(&p2, x));
        uv1.x += rng.normal()*sigma; uv1.y += rng.normal()*sigma; // 每个坐标加噪
        uv2.x += rng.normal()*sigma; uv2.y += rng.normal()*sigma;
        sum += (triangulate(&p1, &uv1, &p2, &uv2) - x).norm();
    }
    println!("平均 3D 误差 = {:.4} m（{:.1} mm）", sum/4.0, 1000.0*sum/4.0);
}
```

本机实测输出（可复现）：

```text

点0: 真值(+0.000,+0.000,+5.000) 恢复(-0.000,+0.000,+5.000) 误差=1.54e-16
点1: 真值(+0.500,+0.300,+6.000) 恢复(+0.500,+0.300,+6.000) 误差=2.67e-15
点2: 真值(-0.400,+0.200,+5.500) 恢复(-0.400,+0.200,+5.500) 误差=3.64e-15
点3: 真值(+0.200,-0.300,+4.500) 恢复(+0.200,-0.300,+4.500) 误差=8.99e-16
最大误差 = 3.64e-15 m（接近机器精度）

==== 加 0.5px 观测噪声 ====

```

无噪声时误差在 \\(10^{-15}\\) 量级——**这就是机器浮点精度，说明 DLT 完全解对了**。一旦给观测加上 0.5 像素的噪声，平均 3D 误差就跳到约 2cm。这个跳变很有教育意义：**三角化对观测噪声敏感，且距离越远（深度 Z 越大）、基线越短，同样的像素误差放大成的 3D 误差越大**——这也是为什么后面要用 BA 做全局优化来压误差。

## 从 SfM 到视觉 SLAM

SfM 通常是**离线**的：拿到一堆照片，慢慢算，追求精度。而 **SLAM（Simultaneous Localization and Mapping，同时定位与建图）** 要在机器人/AR 设备**运动的同时、实时**地边定位自己边建地图。二者数学内核相通（都靠特征、位姿、三角化、BA），但 SLAM 多了"**实时**"这道紧箍咒。

经典视觉 SLAM（如 ORB-SLAM 的思路）通常拆成**三个并行线程**：

```text
┌──────────┐  当前帧特征匹配到地图点，
│ 跟踪线程 │  用 PnP 实时估计相机位姿（要快，每帧都跑）
└────┬─────┘
     │ 关键帧
     ▼
┌──────────┐  对关键帧三角化新点、做局部 BA，
│ 建图线程 │  维护和优化局部地图（可以慢一点）
└────┬─────┘
     │
     ▼
┌──────────┐  检测"我是不是回到了来过的地方"，
│ 回环线程 │  若是则做全局优化，消除累积漂移
└──────────┘
```

> 📖 **术语**：**BA（Bundle Adjustment，光束法平差）**——同时微调所有相机位姿和所有 3D 点，使全部观测的**重投影误差**（3D 点投影回图像与实际观测像素的差）总和最小。它是个大规模非线性最小二乘，用高斯牛顿/列文伯格-马夸尔特（LM）迭代求解，是 SfM/SLAM 精度的最后保障。

### 诚实说说纯 Rust 生态现状

这是本书一贯的态度：**不夸大、不伪造**。三维重建/SLAM 在纯 Rust 里的现状是——**积木有，整机还在路上**：

- **线性代数与优化**：`nalgebra`（本章一直在用）足以支撑手写三角化、PnP，甚至手写一个小规模高斯牛顿 BA。这条路完全走得通，只是要自己推导雅可比。
- **rust-cv 组织** 是纯 Rust CV 的主要探索者，提供了 `cv`、`akaze`（AKAZE 特征）、`arrsac`/`sample-consensus`（RANSAC 家族）、`nalgebra` 等积木，以及一些两视图几何、位姿估计的实现（各 crate 版本与成熟度不一，**用前务必 `cargo add` 验证**）。
- **成熟度**：截至本书写作（2026 年），**尚没有一个像 ORB-SLAM/COLMAP 那样开箱即用、久经考验的纯 Rust SLAM/SfM 整机**。要在真实项目里做重建，业界现实做法常是：用成熟的 C++ 方案（COLMAP、ORB-SLAM3）跑核心，或通过 FFI 调用——这就不再是"纯 Rust"了。

所以本章给你的是**能亲手跑通、真正理解的核心积木（三角化）**，而不是一份看起来能跑、实则拼凑的"假 SLAM"。理解了积木，你既能读懂论文与开源实现，也能在纯 Rust 生态成熟时快速上手。

## 常见坑与提示

> 🕳️ **坑：单目 SfM 的尺度不确定。** 只用单个相机的图，你恢复出的场景**差一个全局缩放**——雕像可能被重建成真实大小，也可能是它的 1/10，数学上无法区分。要拿到真实尺度，得靠额外信息：双目基线（[第 65 章](ch65-stereo-depth.md)）、已知尺寸的标定物、或 IMU。

> ⚠️ **注意：累积误差与尺度漂移。** SLAM 一帧帧往前推，位姿误差会**累积**，走一大圈回到原点可能对不上（尺度还会缓慢漂移）。解药是**回环检测（loop closure）**：认出"来过这里"，加一条约束做全局优化把误差摊平。

> 🕳️ **坑：初始化退化。** 两视图三角化时，如果两个相机**几乎没有平移**（纯旋转），两条视线近乎平行，交点极不稳定——深度会解得乱飞。SfM/SLAM 初始化要专门挑"基线足够、视差明显"的两帧。

> 💡 **提示：三角化前务必做 RANSAC。** 真实匹配里混着误匹配（外点），直接三角化会得到满天飞的错误点。先用 [第 25 章](../p04-features/ch25-matching-ransac.md) 的 RANSAC + 对极几何约束（[第 66 章](ch66-epipolar-pnp.md)）过滤，再三角化。

## 本章小结

- **SfM** 把无序照片重建成 3D 结构，流水线是：**特征匹配 → 两视图求相对位姿 → 三角化 → 增量加图 → BA 全局优化**。
- **三角化（DLT）** 是核心积木：每个视图给 2 条线性方程，两视图堆成 \\(A X = 0\\)，SVD 取最小奇异向量即齐次 3D 点。本章实测无噪声误差达机器精度、0.5px 噪声下约 2cm。
- **视觉 SLAM** 是 SfM 的实时版，经典结构为**跟踪 / 建图 / 回环**三线程；核心难点是累积误差、尺度（漂移/不确定）、初始化退化，靠回环与 BA 兜底。
- **纯 Rust 现状**：`nalgebra`、rust-cv 的 `akaze`/`arrsac` 等提供了扎实积木，但**暂无开箱即用的成熟纯 Rust SLAM/SfM 整机**——积木在手，整机待成。

## 动手练习

1. **多视图三角化**：给 `triangulate` 增加第三个相机与观测（构造 6 行的 \\(A\\)），观察在有噪声时 3D 误差是否比两视图更小。
2. **重投影误差**：把三角化恢复的 3D 点用 `project` 投影回两个相机，算它与输入观测的像素差——这正是 BA 要最小化的量。
3. **基线的影响**：把相机 2 的平移 `c2` 从 1.0 改成 0.1（基线变短），在同样 0.5px 噪声下重跑，验证"基线越短、3D 误差越大"这个坑。
4. **进阶（挑战）**：用 `nalgebra` 对单个 3D 点手写一个高斯牛顿迭代，以重投影误差为目标做一次"迷你 BA"精修，对比精修前后的误差——你就摸到了 SfM 最后一步的门槛。

## 第十四部分阶段验收：多视几何的可观测性

建立统一 `SE(3)` 约定与坐标系图，测试变换复合、逆和扰动 Jacobian。对标定、E/F、PnP、
三角化和 bundle adjustment 使用合成真值，并注入像素噪声、离群点、纯旋转、共面点、小
基线和错误内参；算法必须检测退化而非返回高置信答案。真实序列报告 ATE/RPE、尺度漂移、
重投影误差分布、跟踪丢失和回环误闭合。地图精度需用独立尺度或控制点验证。
