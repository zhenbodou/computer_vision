# 第 59 章 光流：假设、数值求解与失效诊断

> **本章导读**
> - 搞懂**光流（optical flow）**：视频里每个像素"往哪儿动、动多快"的运动矢量场。
> - 吃透两条基石：**亮度恒定假设**与 **Lucas-Kanade（LK）** 的 2×2 法方程，并亲手用 nalgebra 解出运动 (u, v)。
> - 直面**孔径问题（aperture problem）**：为什么在一条直边上你说不清它到底往哪动。
> - 学会**失效诊断**：用结构张量最小特征值、前后向一致性给每个点打"置信度"，宁可拒绝也不输出假精度。
> - 动手：合成两帧、在角点上把已知平移**逐点恢复出来**，再自实现稠密光流、画出光流箭头。

## 场景引入：视频里的"运动"怎么量出来

监控画面里一个人从左走到右。人眼一看就知道"他在往右移动"，可计算机拿到的是**两张几乎一样、只差一点点**的灰度图。它怎么知道每个像素移动了多少？

这就是**光流**要解决的问题：给定相邻两帧，为画面里的每个点（或一批关键点）估计一个二维运动矢量 \((u, v)\)——它在这一帧到下一帧之间往右挪了 \(u\) 像素、往下挪了 \(v\) 像素。光流是运动分析的地基：视频防抖、目标跟踪的运动预测、动作识别、乃至三维里的"运动恢复结构"，都建立在它之上。

## 原理：从"亮度不变"到一条方程

### 直觉：一个像素搬家，但"颜色"没变

光流最核心的假设朴素得可爱——**亮度恒定（brightness constancy）**：同一个物理点在相邻两帧里，虽然位置挪了，但**灰度值基本不变**。用公式说，位于 \((x, y)\) 的点在 \(t\) 时刻的灰度，等于它在 \(t+1\) 时刻挪到 \((x+u, y+v)\) 后的灰度：

\[ I(x, y, t) = I(x+u,\, y+v,\, t+1) \]

把右边做一阶泰勒展开（假设运动很小），整理后得到光流领域最著名的一行式子——**光流约束方程**：

\[ I_x\, u + I_y\, v + I_t = 0 \]

其中 \(I_x, I_y\) 是图像沿 x、y 方向的**空间梯度**（用 Sobel 算，见 [第 15 章 梯度与边缘检测](../p03-classic/ch15-edges.md)），\(I_t\) 是**时间梯度**，也就是两帧的差 \(I_t = I(t+1) - I(t)\)。

### 孔径问题：一个方程解不出两个未知数

麻烦来了：一行方程 \(I_x u + I_y v + I_t = 0\)，却有 \(u, v\) **两个未知数**——解不出唯一答案。这就是大名鼎鼎的**孔径问题**。

直觉上它长这样：透过一个小孔看一条斜着移动的直边，你只能看出它"垂直于边"的那部分运动，沿着边滑动的那部分你**根本察觉不到**：

```text
   透过小孔看一条向右下移动的直边：
   ┌───────┐        ┌───────┐
   │   ╱   │   →    │    ╱  │      你以为它"垂直于边"往右上动，
   │  ╱    │        │   ╱   │      但它其实可能在"沿着边"斜着滑
   └───────┘        └───────┘      —— 沿边方向的运动，孔里看不出来
```

### Lucas-Kanade：用一小片邻域凑够方程

Lucas-Kanade 的破解思路特别实在：**假设一个小窗口（比如 13×13）里所有像素运动都一样**。这样窗口里每个像素都贡献一行方程，几十上百行方程一起解两个未知数——用最小二乘，就得到一个稳稳的 2×2 线性方程组（称为**法方程**）：

\[ \begin{bmatrix} \sum I_x^2 & \sum I_x I_y \\ \sum I_x I_y & \sum I_y^2 \end{bmatrix} \begin{bmatrix} u \\ v \end{bmatrix} = -\begin{bmatrix} \sum I_x I_t \\ \sum I_y I_t \end{bmatrix} \]

左边那个 2×2 矩阵，正是 [第 23 章 角点检测](../p04-features/ch23-corners.md) 里 Harris 用过的**结构张量** \(M\)！它能不能解，取决于它的两个特征值 \(\lambda_1 \ge \lambda_2\)：

| 窗口内容 | 两个特征值 | 能否求解 |
|---------|-----------|---------|
| 平坦区（无纹理） | \(\lambda_1 \approx \lambda_2 \approx 0\) | 解不了，梯度全 0 |
| 直边（只有一个方向的梯度） | \(\lambda_1\) 大、\(\lambda_2 \approx 0\) | 只能定"法向"，孔径问题 |
| **角点**（两个方向都有梯度） | \(\lambda_1, \lambda_2\) 都大 | **能唯一求解** |

所以：**要跟就跟角点**。这也是为什么光流跟踪常和角点检测配套使用（业界叫 "good features to track"）。最小特征值 \(\lambda_2\) 越大，这个点越好跟——它是天然的"置信度"。

### 大位移与金字塔

泰勒展开只在**位移小于约 1 像素**时才准。位移一大，单次 LK 就会**系统性低估**。两个补救办法：一是**迭代**——按当前估计把第二帧"掰回来"重算残差，反复逼近；二是**图像金字塔（image pyramid）**（见 [第 21 章](../p03-classic/ch21-pyramids.md)）——先在缩小的图上估个大概（大位移在小图上就变小了），再逐层放大细化。本章代码用迭代法演示这一点。

### 合成两帧：把场景整体平移已知的 (dx, dy)

为了让示例**自包含、可复现**，我们不读外部视频，而是画一张带纹理的灰度图当第一帧，再用**双线性采样**把它整体平移已知的 \((dx, dy)\) 得到第二帧——这样光流真值就是 \((dx, dy)\)，可以拿来对答案。

```rust
// 双线性采样：在浮点坐标处取灰度（平移、迭代重采样都靠它）
fn sample(img: &GrayImage, fx: f32, fy: f32) -> f32 {
    let (w, h) = img.dimensions();
    let x = fx.clamp(0.0, (w - 1) as f32);
    let y = fy.clamp(0.0, (h - 1) as f32);
    let (x0, y0) = (x.floor() as u32, y.floor() as u32);
    let (x1, y1) = ((x0 + 1).min(w - 1), (y0 + 1).min(h - 1));
    let (ax, ay) = (x - x0 as f32, y - y0 as f32);
    let p = |xx, yy| img.get_pixel(xx, yy)[0] as f32;
    let top = p(x0, y0) * (1.0 - ax) + p(x1, y0) * ax;
    let bot = p(x0, y1) * (1.0 - ax) + p(x1, y1) * ax;
    top * (1.0 - ay) + bot * ay
}

// frame2(x,y) = frame1(x-dx, y-dy)：于是特征整体挪了 (dx,dy)，真值就是 (dx,dy)
fn shift(img: &GrayImage, dx: f32, dy: f32) -> GrayImage {
    GrayImage::from_fn(img.width(), img.height(), |x, y| {
        let v = sample(img, x as f32 - dx, y as f32 - dy);
        Luma([v.round().clamp(0.0, 255.0) as u8])
    })
}
```

### 梯度场：Sobel 记得除以 8

\(I_x, I_y\) 用 imageproc 的 Sobel 算。**这里有个致命细节**：imageproc 的 Sobel 输出是"真导数的 8 倍"（核系数绝对值之和是 8），而 \(I_t\) 是原始帧差（1 倍）。两者单位不一致，解出来的 \((u, v)\) 会整体差 8 倍！所以梯度必须 **/8** 归一化：

```rust
fn grad_field(img: &GrayImage) -> (Vec<f32>, Vec<f32>) {
    let (w, h) = img.dimensions();
    let gx = imageproc::gradients::horizontal_sobel(img); // Luma<i16>
    let gy = imageproc::gradients::vertical_sobel(img);
    let mut ix = vec![0.0f32; (w * h) as usize];
    let mut iy = vec![0.0f32; (w * h) as usize];
    for y in 0..h {
        for x in 0..w {
            let i = (y * w + x) as usize;
            ix[i] = gx.get_pixel(x, y)[0] as f32 / 8.0; // 关键：/8 才和 I_t 同单位
            iy[i] = gy.get_pixel(x, y)[0] as f32 / 8.0;
        }
    }
    (ix, iy)
}
```

### Lucas-Kanade 核心：算结构张量、解 2×2、迭代精修

下面是全章的心脏。先累加窗口里的结构张量 \(M\) 和最小特征值（判断好不好跟），再用 nalgebra 的 `Matrix2` 求逆解出增量；`iters=1` 就是经典单次 LK，`iters>1` 会把第二帧按当前估计采样回来重算残差 \(I_t\)，纠正大位移的低估。**矩阵奇异时 `try_inverse` 返回 `None`，我们直接放弃该点——这正是拒绝孔径问题点的第一道闸门。**

```rust
use nalgebra::{Matrix2, Vector2};

fn lk_track(f1: &GrayImage, f2: &GrayImage, ix: &[f32], iy: &[f32],
            px: i32, py: i32, radius: i32, iters: usize) -> Option<(f32, f32, f32)> {
    let (iw, ih) = f1.dimensions();
    let w = iw as usize;
    // ① 结构张量 M（只用 frame1 的梯度，窗口固定，只算一次）
    let (mut a11, mut a12, mut a22) = (0.0f64, 0.0, 0.0);
    for dy in -radius..=radius {
        for dx in -radius..=radius {
            let (x, y) = (px + dx, py + dy);
            if x < 0 || y < 0 || x >= iw as i32 || y >= ih as i32 { continue; }
            let idx = (y as usize) * w + x as usize;
            let (gx, gy) = (ix[idx] as f64, iy[idx] as f64);
            a11 += gx * gx; a12 += gx * gy; a22 += gy * gy;
        }
    }
    // 最小特征值：反映"可跟踪性"，≈0 就是孔径问题
    let tr = a11 + a22;
    let disc = (tr * tr / 4.0 - (a11 * a22 - a12 * a12)).max(0.0).sqrt();
    let min_eig = (tr / 2.0 - disc) as f32;
    let inv = Matrix2::new(a11, a12, a12, a22).try_inverse()?; // 奇异则放弃
    // ② 迭代：用当前 (u,v) 把 frame2 采样回来算残差 It，再解增量
    let (mut u, mut v) = (0.0f32, 0.0f32);
    for _ in 0..iters {
        let (mut b1, mut b2) = (0.0f64, 0.0);
        for dy in -radius..=radius {
            for dx in -radius..=radius {
                let (x, y) = (px + dx, py + dy);
                if x < 0 || y < 0 || x >= iw as i32 || y >= ih as i32 { continue; }
                let idx = (y as usize) * w + x as usize;
                let it = (sample(f2, x as f32 + u, y as f32 + v)
                          - f1.get_pixel(x as u32, y as u32)[0] as f32) as f64;
                b1 += ix[idx] as f64 * it;
                b2 += iy[idx] as f64 * it;
            }
        }
        let d = inv * Vector2::new(-b1, -b2); // 解 M·[du,dv]^T = -[b1,b2]^T
        u += d.x as f32; v += d.y as f32;
        if d.norm() < 1e-3 { break; }
    }
    Some((u, v, min_eig))
}
```

`main` 里我们造两帧（真值 \(u=2.0, v=1.0\)，各加一点噪声），用 `corners_fast9` 找角点当跟踪点，对每个点跑单次和迭代 LK。**还多做一步"失效诊断"——前后向一致性检查**：正向跟到落点后，再从落点往回跟一次，正向与反向的位移之和应当约等于 0；若残差偏大，说明这个点不可信，应当丢弃（这一步**不需要真值**，是真实工程里给光流打分的通用手段）。

### 实测输出

```text
== ① 稀疏 Lucas-Kanade（真值 u=2.0, v=1.0）==
角点数 10，窗口 13×13
  点(x,y)     单次LK(u,v)        迭代LK(u,v)       误差(迭代)
  (194,150)   ( 0.86, 1.06)     ( 2.00, 1.00)     0.003
  (170,152)   ( 0.95, 0.94)     ( 1.99, 1.00)     0.009
  ...
平均误差：单次 LK = 1.076 px，迭代 LK = 0.007 px
前后向一致性平均残差 = 0.000 px（无需真值也能自检：残差大就该丢弃该点）

== ② 孔径问题 ==
  直边点(40,54): M 奇异，无法唯一求解（沿边方向那一维彻底说不清）
  角点  (40,40): (u,v)=(2.00,1.00) min_eig=37056.25  <- 两个方向都有梯度，稳

== ③ 大位移：单次 LK 低估，迭代纠正 ==
  真值 u=  3: 单次 u= 0.99（低估），迭代 u= 3.00
  真值 u=  6: 单次 u= 0.96（低估），迭代 u= 6.00

== ④ 稠密光流：画了 20 支箭头，跳过 201 个弱纹理点
```

数字会说话：单次 LK 平均误差约 **1.08 像素**（2 像素的位移已经"太大"，被明显低估到约 1 像素），而**迭代 LK 把误差压到 0.007 像素**，几乎完美复原真值；前后向残差 0.000，说明这些角点极其可靠。孔径问题也如实上演——直边上矩阵 \(M\) 直接奇异（`try_inverse` 返回 `None`），角点处 `min_eig` 高达三万多，稳稳解出 \((2.00, 1.00)\)。第 ③ 组更直白：单次 LK 对 3、6 像素的位移都卡在 1 像素上不去，一迭代就精确复原。稠密光流则对整幅图逐网格点求解，只在纹理够强（`min_eig > 120`）的 20 个点画箭头，其余 201 个弱纹理点果断跳过——**这正是工程上该有的诚实**。

> 📖 **术语**：**稀疏光流 vs 稠密光流**。稀疏光流只在选出的少量关键点（如角点）上估运动，快、稳，跟踪常用；稠密光流为**每个像素**都估一个矢量，信息全但慢、平坦区不可靠。imageproc **没有内置光流**，本章的 LK 与稠密光流都是我们自己实现的——纯 Rust，一行 OpenCV 都没用。

## 常见坑与提示

> 🕳️ **坑：Sobel 的 8 倍缩放。** imageproc 的 `horizontal_sobel` / `vertical_sobel` 输出是真导数的 **8 倍**，而时间梯度 \(I_t\) 用的是原始帧差。不把梯度 /8，解出的 \((u,v)\) 会整体缩水 8 倍，且你还查不出哪错了。凡是要把空间梯度和帧差放进同一个方程，务必先统一单位。

> ⚠️ **注意：位移大就得上金字塔。** 单次 LK 只在亚像素位移下准确。真实视频里快速运动动辄十几像素，必须用**迭代 + 图像金字塔**：粗尺度先估大概、逐层细化。本章用迭代演示了纠偏，工程里请再叠一层金字塔。

> 💡 **提示：宁拒绝，勿假精度。** 光流一定要配"质量门"：结构张量最小特征值太小（无纹理/直边）就拒绝；前后向一致性残差过大（比如 > 1px）就丢弃；迭代不收敛或越界也丢弃。输出一个带"无效标记"的稀疏场，远比硬凑一个满屏乱飞的稠密场有用。

> ⚠️ **注意：亮度恒定很脆弱。** 光照突变、自动曝光、镜面反光都会破坏"灰度不变"，让 \(I_t\) 里混入并非运动引起的变化。缓解办法：先做光照归一化，或改用对光照更鲁棒的匹配代价。运动模糊、遮挡、非刚体形变同样会让假设失效——**知道它何时失效，和会用它一样重要**。

## 本章小结

- 光流是相邻两帧间**每个像素的运动矢量场**，根基是**亮度恒定假设**，推出光流约束方程 \(I_x u + I_y v + I_t = 0\)。
- 一个方程两个未知数 → **孔径问题**；Lucas-Kanade 假设小窗口内运动一致，凑成 2×2 法方程，用 nalgebra 一解即得。
- 能否求解由**结构张量的特征值**决定：角点最好跟，直边只能定法向（本章实测直接奇异），平坦区解不了。
- 单次 LK 只适合亚像素位移，**迭代 / 图像金字塔**才能对付大位移；实测迭代把 2 像素位移的误差从 1.08 px 压到 0.007 px。
- 工程落地必须做**失效诊断**：最小特征值 + 前后向一致性给每点打分，宁拒绝勿假精度。imageproc 无内置光流，全章自实现——注意 Sobel 的 8 倍缩放坑。

## 动手练习

1. **改位移与噪声**：把真值 \((u, v)\) 改成 \((1.5, -2.5)\)，再把噪声标准差从 1.5 调到 5.0，观察单次与迭代 LK 的误差、以及前后向残差怎么变。噪声大到多少时前后向检查开始报警？
