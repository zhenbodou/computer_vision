# 第 63 章 背景建模与运动检测

> **本章导读**
> - 学完你能：在**固定摄像头**画面里，不靠任何检测模型，直接把"正在动的东西"抠成前景掩码，并框出运动目标。
> - 搞懂三条经典思路：**帧差法**、**running-average 背景**、以及**高斯混合模型（MOG）**的多模态思想。
> - 亲手合成一段"视频"，跑通"背景减除 → 形态学去噪 → 连通域框目标"的完整流水线。
> - 认清运动检测的经典坑：鬼影、空洞、光照突变、"静止过久被学进背景"、动态背景。

## 场景引入：门口装个摄像头，怎么知道"有动静"

一个固定在墙角、一动不动的摄像头，对着空无一人的走廊。大部分时间，画面**每一帧都长得一模一样**——地板、墙、那盆永远不会动的绿植。直到有人走过，画面里才出现"变化"。

这里藏着一个特别省算力的洞察：**在固定摄像头下，"动的"才是我们关心的前景，"不动的"就是背景。** 我们根本不需要一上来就跑一个笨重的目标检测网络去"找人"；只要先算出"哪些像素相对背景变了"，就能廉价地回答"有没有动静、动的东西在画面哪个位置、有多大"。这类**运动检测**常被用作整条流水线的**触发器**：平时低功耗地盯着，一旦检测到运动，才唤醒后面昂贵的检测器（第九部分）和跟踪器（第 [62 章](ch62-mot.md)）。安防、周界告警、智能录像（有动静才录）……背后都是它。

> 📖 **术语**：**背景建模（background modeling）与背景减除（background subtraction）**。背景建模 = 从视频里**学出**"静止的背景长什么样"（一张背景图 \(B\)）；背景减除 = 用当前帧 \(I\) 减去背景 \(B\)，差异大的地方就是前景。本章讲的是"帧进、前景掩码出"，和第 [59 章光流](ch59-optical-flow.md)（估计每个像素怎么动）互为补充：光流关心"怎么动"，背景减除关心"哪里和背景不一样"。

## 原理：从"两帧相减"到"学一张背景"

### 帧差法：最朴素的"动没动"

最简单的想法：这一帧和上一帧**逐像素相减**，差得多的地方就是动了。

\\[ D_t(x, y) = \lvert I_t(x, y) - I_{t-1}(x, y) \rvert, \qquad \text{前景} = D_t > \tau \\]

\(\tau\) 是阈值（噪声会让静止区也有小的差，用阈值滤掉）。它的好处是**极简、零内存、对缓慢光照变化不敏感**。但坑也很致命——看这个匀色方块向右移动一点的例子：

```text
上一帧的方块          这一帧的方块（右移一点，两者大部分重叠）
   ███████               ███████
   ███████     ──▶       ███████
   ███████               ███████

|I_t − I_{t−1}| 只在「不重叠」的竖边上非零：
   ▓▓·····▓▓    ← 左带=方块「离开」处，右带=方块「新到」处
                  中间重叠区：前后两帧都是同一片亮色 → 差为 0 → 空洞！
```

两个毛病一目了然：**① 空洞**——匀色目标的内部，前后帧数值相同，差为 0，被判成背景，前景成了个"空壳"；**② 鬼影 / 拖影（ghosting）**——运动目标会留下"离开处"和"新到处"两条亮带，一个目标裂成两片。而且目标一旦**停下不动**，帧差立刻变 0，目标就"消失"了。

### running-average 背景：学出一张干净的背景图

要拿到**实心**的前景，就得和一张真正的"背景图"比，而不是和上一帧比。可背景图哪来？固定摄像头下，背景在大多数帧里都存在，我们用**指数滑动平均**把它一点点"熬"出来：

\\[ B_t = \alpha\, I_t + (1 - \alpha)\, B_{t-1}, \qquad \text{前景} = \lvert I_t - B_t \rvert > \tau \\]

\(\alpha \in (0,1)\) 是**学习率**。直觉：每来一帧，就把背景往当前帧"挪一点点"。前景目标（人、车）在每个像素上只停留很短的几帧，来不及被"熬"进背景；而真正的背景常驻，慢慢占据主导。于是 \(B_t\) 收敛到静止背景，\(\lvert I_t - B_t \rvert\) 就给出**完整实心**的前景。

\(\alpha\) 的权衡很关键：**太大**（如 0.5），背景更新太快，慢速目标会被迅速"吃"进背景（还没走完就成背景了）；**太小**（如 0.01），背景更新太慢，一旦真实光照变了（开灯、云飘过），背景半天跟不上，整片画面误报成前景。本章用 \(\alpha = 0.05\)，是个稳妥的折中。

### MOG（高斯混合）：应对会晃的背景

running-average 有个隐含假设：**每个像素的背景是"单一"的一个值**。可现实里背景常常是**多模态**的——一片在风里晃的树叶，某个像素时而是"叶子的绿"、时而是"天空的蓝"，来回横跳；水面波光粼粼也是。用单值背景去套，这些"正常晃动"会被当成前景，误报连连。

**高斯混合模型（Mixture of Gaussians，MOG）**的思路是：给**每个像素**维护 \(K\) 个高斯分布（比如 3~5 个），共同描述"这个像素正常情况下会出现哪些值"：

\\[ P(I) = \sum_{k=1}^{K} w_k\, \mathcal{N}(I;\ \mu_k,\ \sigma_k^2) \\]

树叶像素就会学出两个高斯（一个"绿"、一个"蓝"），只要当前值落在**任一个**背景高斯附近，就算背景。新来的值若不属于任何高斯，才判为前景，并可能新起一个高斯、按权重淘汰旧的。这样就能"容忍"背景的多模态晃动。MOG（及其改进 MOG2）是 OpenCV 里 `BackgroundSubtractorMOG2` 的算法内核；纯 Rust 生态暂无现成封装，但**原理不难，可按上式自己实现**（每像素存 \(K\) 组 \((w, \mu, \sigma)\)，逐帧匹配/更新）。本章先把思路讲清，动手部分聚焦更基础的 running-average。

三种方法对比：

| 方法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **帧差法** | 相邻帧相减 | 极简、零内存、对缓慢光照不敏感 | 匀色内部**空洞**、**鬼影拖影**、目标一停就消失 |
| **running-average** | 指数滑动平均学单值背景 | 前景**实心**、能容忍缓慢光照变化 | **单模态**、鬼影（初始/久停后再动）、\(\alpha\) 难调 |
| **MOG（高斯混合）** | 每像素多个高斯 | 应对**多模态背景**（树叶/水面）、更自适应 | 计算/内存更重、参数更多 |

## 动手写代码：合成一段"视频"，把动的方块抠出来

配套示例 `code/examples/ch63_background_motion.rs`。我们**合成**一段 24 帧的灰度"视频"：一张静态背景（左右渐变 + 一扇静止的"深色门" + 一块静止的"浅色地砖"）+ 一个 30×30 的亮方块（灰度 220）从屏幕左侧**移入**、每帧右移 8px + 每帧叠加高斯噪声（标准差 8，模拟真实传感器噪声）。让方块从画外进入，是为了让背景初始化时是**干净**的（这个细节埋着一个大坑，见后文）。

核心就三步。先造背景和每一帧（噪声用 `imageproc::noise::gaussian_noise`，每帧不同 seed，整体仍可复现）：

```rust
use imageproc::noise::gaussian_noise;

fn make_frame(bg: &GrayImage, f: usize) -> GrayImage {
    let mut img = bg.clone();
    let x0 = -SQ + 8 * f as i64; // 方块从屏幕外进入，每帧 +8px
    // ... 在 (x0, 65) 处画一个 30×30、灰度 220 的亮方块
    gaussian_noise(&img, 0.0, 8.0, 100 + f as u64) // 均值 0、标准差 8，seed 随帧变
}
```

然后逐帧维护 running-average 背景（用 `f32` 累加避免 `u8` 舍入漂移），**先减后学**——先用旧背景算前景掩码，再把当前帧学进背景，免得把当前前景立刻污染进背景：

```rust
// bg: Vec<f32>，初值 = 第 0 帧（此时画面里还没有方块，背景干净）
for (i, px) in cur.as_raw().iter().enumerate() {
    let px = *px as f32;
    if (px - bg[i]).abs() > THRESH as f32 {   // |I − B| > τ → 前景
        // ...在掩码对应位置置 255，前景计数 +1
    }
    bg[i] = ALPHA * px + (1.0 - ALPHA) * bg[i]; // B_t = αI_t + (1−α)B_{t-1}
}
```

最后对某一帧（第 14 帧）的前景掩码做**形态学开运算**去噪（先腐蚀后膨胀，清掉孤立噪点，见第 [17 章](../p03-classic/ch17-morphology.md)），再用**连通域**标记按面积过滤、框出运动目标（见第 [18 章](../p03-classic/ch18-contours.md)）：

```rust
use imageproc::morphology::open;
use imageproc::region_labelling::{connected_components, Connectivity};

let opened = open(&raw, Norm::LInf, 1);                 // 3×3 方形结构元素开运算
let labels = connected_components(&opened, Connectivity::Eight, Luma([0u8]));
// 遍历 labels 累加每个连通块的面积与包围盒，area >= 100 的才算运动目标
```

运行：

```bash
cargo run --example ch63_background_motion
```

逐字实测输出（节选）：

```text
== 逐帧前景像素数（阈值 30）==
帧 | 帧差法 | 背景减除   （方块面积理论值 = 900）
 1 |   517  |   520
 7 |   757  |  1394
14 |   766  |  1736
23 |   742  |  1533

== 第 14 帧：背景减除掩码去噪 + 连通域 ==
原始前景白像素   = 1736
开运算后白像素   = 900（噪声碎点被清掉）
连通块总数（含碎块）= 1，面积≥100 视为运动目标：
  运动目标#1: 包围盒=(82,65,30x30) 面积=900
检出运动目标数 = 1
对比帧差法(766白) vs 背景减除(1736白): 帧差只在方块前后沿留下「鬼影」条带，背景减除给出完整实心前景。
```

几个数字把原理钉死了：

- **帧差法始终在 ~750 白像素上下**，怎么都到不了方块的 900。因为它只逮住方块前后沿两条 8px 宽的亮带（鬼影）+ 一些噪点，方块内部是空洞。存出的 `out_ch63_framediff.png` 里你能清楚看到"两条竖带夹一片空"的拖影。
- **背景减除给出实心前景**：第 14 帧原始掩码 1736 白像素 = 方块本体 900 + 拖尾的淡淡鬼影 + 散点噪声。
- **开运算立竿见影**：1736 → **900**，正好是方块的 30×30！散点噪声和细窄的拖尾都被 3×3 开运算啃掉，只剩干净的方块本体。连通域随即框出**唯一**一个运动目标，包围盒 `(82, 65, 30×30)` 与方块真实位置分毫不差（第 14 帧方块左上角正是 \(x = -30 + 8\times14 = 82\)）。

程序还存了 5 张图供你对照：`out_ch63_frame.png`（输入帧）、`_framediff.png`（帧差鬼影）、`_bgsub_raw.png`（背景减除原始掩码，带噪）、`_bgsub_open.png`（开运算后干净掩码）、`_boxes.png`（框好运动目标的可视化）。

> 💡 **提示**：注意背景减除的前景像素数从第 1 帧的 520 一路爬到第 14 帧的 1736 才稳定——这是方块正在"驶入"画面、被逐渐完整看到的过程。这段自包含、可复现的合成数据，正是调试运动检测算法的好起点：真实视频里噪声、光照、抖动全混在一起，先用合成数据把算法逻辑跑对，再上真实数据。

## 常见坑与提示

> 🕳️ **坑：鬼影（ghost）**。有两种。① **帧差鬼影**：如上，运动目标裂成"前后两条亮带"。② **背景鬼影**：如果背景初始化时画面里**就有一个前景物体**（比如启动时画面里停着辆车），这个物体会被写进初始背景 \(B_0\)；等它开走，那个"它曾经在的位置"会因为 \(B\) 里还留着它、而当前帧已经没有它，被误报成前景，形成一团幽灵，要好多帧才被 \(\alpha\) 慢慢"忘掉"。本章特意让方块**从画外驶入**，就是为了让 \(B_0\) 干净、避开这个坑——你可以把方块起始位置改成"第 0 帧就在画面内"，亲眼看幽灵冒出来。

> 🕳️ **坑：静止过久的前景被"学进"背景**。running-average 会把见到的东西慢慢揉进背景。一个人**站着不动太久**，就会被当成背景（前景里慢慢"淡出"）；等他再动，原地又冒出鬼影。\(\alpha\) 越大淡出越快。工程上常用"前景像素不更新（或更慢更新）背景"的 selective update 来缓解。

> ⚠️ **注意：光照突变是最大杀手**。开关灯、云遮住太阳、自动曝光跳变——整幅画面亮度**瞬间**改变，而缓慢学习的背景 \(B\) 跟不上，于是**满屏都被判成前景**，彻底误报。对策：用对光照更鲁棒的特征（如只看梯度/边缘、或在 HSV 的色调通道上做差）、检测到全局突变时临时提高 \(\alpha\) 让背景快速追上，或干脆结合帧差（帧差对缓变光照不敏感）。

> 🕳️ **坑：动态背景（树叶、水面、喷泉、显示屏）**。这些区域的像素本就在"正常地"反复变化，单值背景必然把它们误报成前景。这正是 **MOG 多高斯**要解决的问题；退而求其次，也可以对已知的动态区域做 ROI 屏蔽（第 [84 章](../p18-events/ch84-roi-filter.md)），或提高这些区域的阈值。

> 💡 **提示：运动检测只是"起点"**。它给的是"哪里在动"的粗糙掩码，受噪声、阴影、遮挡影响很大（阴影让人"拖着一片黑"、粘连把两个人框成一个）。实战里它常与后续配合：形态学清理（第 17 章）、连通域（第 18 章）拿包围盒，再交给跟踪器（第 62 章）连成轨迹、事件层（第十八部分）变成告警。

## 本章小结

- 固定摄像头下，**"动的是前景，不动的是背景"**；背景建模就是学出静止背景，再用当前帧减背景得到前景。
- **帧差法**最简单（相邻帧相减），但有**空洞**（匀色内部差为 0）和**鬼影拖影**（前后沿两条带），且目标一停就消失。
- **running-average 背景**（\(B_t = \alpha I_t + (1-\alpha) B_{t-1}\)）能给出**实心前景**、容忍缓慢光照变化；\(\alpha\) 是学习率，需在"追光照"与"别把慢速目标学进背景"之间权衡。
- **MOG 高斯混合**给每个像素多个高斯，专治**多模态动态背景**（树叶、水面）；纯 Rust 无现成封装，但可按公式自实现。
- 我们实测跑通了"合成视频 → 背景减除 → 开运算去噪 → 连通域框目标"：第 14 帧原始前景 1736 像素经开运算变 900（正好方块本体），干净地框出唯一运动目标 `(82,65,30×30)`；帧差法则始终困在 ~750 的鬼影条带。
- 经典坑要牢记：鬼影、空洞、光照突变、静止过久被学进背景、动态背景。

## 动手练习

1. **调学习率 \(\alpha\)**：把 `ALPHA` 从 0.05 依次改成 0.5 和 0.005，重新观察逐帧前景像素数。大 \(\alpha\) 时方块会不会"追不上"、留下拖尾？小 \(\alpha\) 时前景是否更实心但对变化更迟钝？
2. **亲手造背景鬼影**：把方块起始位置改成第 0 帧就在画面内（例如起点 x=20）。运行后你会发现连通域框出了**两个**目标——一个真方块、一个赖在起点的幽灵。想想为什么，再试着让程序"预热"几帧（先用纯背景帧初始化 \(B\)）来消除它。
3. **模拟光照突变**：在合成时给第 12 帧起的所有帧整体加 40 的亮度，看背景减除是不是"满屏误报"，而帧差法基本不受影响。体会两种方法对光照的不同敏感度。
4. **（进阶）实现极简 MOG**：给每个像素维护 2 个高斯 \((w, \mu, \sigma)\)，让背景在两个灰度间周期性横跳（模拟晃动的树叶）。对比单值 running-average 和你的 2-高斯模型，看谁能不把"正常晃动"误报成前景。
