# 第 95 章 模型量化、剪枝与压缩：精度—性能共同验证

> **本章导读**
> - 学完你能：**亲手把一段 f32 权重/激活量化到 int8 再反量化**，算出 scale、量化误差，看懂"精度换体积/速度"这笔账（本机 `cargo run` 实测，数字真实可复现）。
> - 搞懂三件压缩利器：**量化**（f32 → int8/f16）、**剪枝**（去掉不重要的权重）、**蒸馏**（小模型学大模型）。
> - 吃透量化核心：**scale / zero-point、对称 vs 非对称、PTQ vs QAT、per-tensor vs per-channel**。
> - **诚实**认清纯 Rust 量化的能力边界：多数量化在训练框架侧做好再导出，Rust 侧负责加载推理。

## 场景：把模型塞进边缘盒子，还要跑得快

[第 94 章](ch94-onnx.md) 我们把模型跑起来了，但一个真实的 ResNet 动辄上百 MB、每帧推理几十毫秒。放到 [第 111 章](../p21-mastery/ch111-embedded.md) 那种内存只有几百 MB、还要实时处理视频的边缘盒子上，就显得又胖又慢。

**模型压缩**就是给模型"减肥增速"，让它能塞进受限设备、满足实时要求。主要有三条路：

- **量化（quantization）**：把 32 位浮点权重换成 8 位整数——体积直接砍到 1/4，整数运算还更快。
- **剪枝（pruning）**：删掉对结果贡献很小的权重或整个通道，网络变小。
- **蒸馏（distillation）**：让一个小模型去模仿大模型的输出，用小体积逼近大精度。

本章重点讲**最常用、收益最直接的量化**，并带你亲手写一遍，把量化的"精度换体积/速度"这笔账算得明明白白。

## 原理：量化就是给浮点数选一把整数标尺

**直觉**：一个 f32 占 4 字节、动态范围极大（能表示 \\( 10^{-38} \\) 到 \\( 10^{38} \\)）。但神经网络里的权重和激活，其实**挤在一个不大的区间里**（比如 \\( [-1, 1] \\)）。用 f32 存它们，就像用一把能量到光年的尺子去量一粒米——精度全浪费了。量化的想法很朴素：**选一把合适的整数标尺**，把这段浮点区间均匀刻成 256 格（int8），每个浮点数记成离它最近的那个格子编号。

这把标尺由两个数定义：

- **scale（缩放因子）** \\( s \\)：一格代表多少，即浮点步长。
- **zero-point（零点）** \\( z \\)：哪个整数编号对应浮点的 0。

### 对称量化 vs 非对称量化

**对称量化**（权重常用）：假设区间关于 0 对称，零点固定为 0。

\\[ s = \frac{\max(|x|)}{127}, \quad q = \mathrm{clip}(\mathrm{round}(x/s), -127, 127), \quad x \approx s \cdot q \\]

**非对称/仿射量化**（激活常用）：区间往往不对称（比如 ReLU 之后全为正），这时用零点 \\( z \\) 把区间"平移"到整数轴上，把 0~255 全部码位用满：

\\[ q = \mathrm{clip}(\mathrm{round}(x/s) + z, 0, 255), \quad x \approx s (q - z) \\]

### PTQ vs QAT，per-tensor vs per-channel

- **PTQ（训练后量化）**：模型训练完直接量化，成本低——只需拿一小批**校准数据**跑一遍，统计出激活的取值范围来定 scale。
- **QAT（量化感知训练）**：训练时就在计算图里**模拟量化误差**，让网络提前学着适应，精度更高，但要重新训练。
- **per-tensor**：整个张量共用一个 scale，简单但容易被**尺度最大的那些值主导**。**per-channel**：每个输出通道各用一个 scale，精度高得多，是权重量化的标配。这个差别有多大，等下的实验会给你一个惊人的数字。

### 剪枝与蒸馏

**剪枝**分两种：**非结构化剪枝**把接近 0 的**单个权重**置零，模型变"稀疏"，但普通 CPU/GPU 不一定能因此加速（要专门的稀疏 kernel）；**结构化剪枝**直接删掉**整个通道/卷积核**，是真能变小变快的，代价是掉精度更多，**剪完通常要微调（fine-tune）几轮才能恢复精度**。**知识蒸馏**则是让小模型（学生）去学大模型（教师）输出的"软标签"（概率分布比"对/错"硬标签信息更丰富），从而在小体积下逼近大模型的表现。

### 纯 Rust 现状（诚实边界）

> ⚠️ **注意**：**纯 Rust 的量化工具链远不如 Python 成熟。** 推理侧：**tract** 有一定的量化推理支持（能跑量化过的 ONNX），**candle** 能加载量化模型（如 GGUF 格式里的 int8/int4 大模型权重）。但**做量化**这一步——PTQ 的校准、QAT 的训练——纯 Rust 生态基本是空白，成熟工具都在 Python 那边（PyTorch、ONNX Runtime、TensorRT）。所以主流做法和 [第 94 章](ch94-onnx.md) 一脉相承：**在训练框架侧把模型量化好、导出量化后的 ONNX / GGUF，Rust 侧只负责加载推理**。本章我们**亲手实现量化的核心算法**，是为了让你彻底理解它在干什么——这份理解，无论量化在哪一侧做，都是你排查精度问题的底气。

## 动手：手写 int8 量化，把误差算出来

下面这个 demo **纯 `std`、无任何重依赖**，放在 `code/examples/ch95_quantization.rs`，`cargo run --example ch95_quantization` 即可跑，结果用固定随机种子**完全可复现**。核心量化函数就这么几行：

```rust
// 对称量化：scale = amax/127；q = clip(round(x/s), -127, 127)；反量化 x' = q*s
fn quantize_symmetric(x: &[f32], scale: f32) -> Vec<i8> {
    x.iter().map(|&v| (v / scale).round().clamp(-127.0, 127.0) as i8).collect()
}
fn dequantize_symmetric(q: &[i8], scale: f32) -> Vec<f32> {
    q.iter().map(|&qi| qi as f32 * scale).collect()
}
// 非对称（仿射）量化：q = clip(round(x/s)+z, 0, 255)；反量化 x' = s*(q-z)
fn quantize_affine(x: &[f32], scale: f32, z: i32) -> Vec<u8> {
    x.iter().map(|&v| ((v / scale).round() as i32 + z).clamp(0, 255) as u8).collect()
}
// 误差度量：均方误差 MSE 与最大绝对误差
fn mse(a: &[f32], b: &[f32]) -> f32 {
    a.iter().zip(b).map(|(x, y)| (x - y).powi(2)).sum::<f32>() / a.len() as f32
}
```

我们跑四组实验，逐一体会量化的关键权衡。**以下全部是真实运行输出**：

**实验 1：对称量化一段权重，看基本代价。** 造 4096 个近似正态的权重，塞两个离群值（±1.0）：

```text
[1] 对称量化 4096 个权重（含 2 个离群值 ±~1.0）
    amax = 1.1000, scale = amax/127 = 0.008661
    体积：f32 16384 字节 -> int8 4096 字节（1/4）
    量化 MSE = 6.031e-6, 最大绝对误差 = 0.00433
```

体积砍到 1/4，最大误差约 `0.0043`——正好是半个步长（`scale/2 ≈ 0.0043`），符合"四舍五入到最近格子"的预期。这就是量化的基本盘。

**实验 2：scale 策略——离群值如何"浪费"整数码。** 同一段权重，对比三种 scale：

```text
[2] scale 策略对比（std=0.0544, 截断阈值 3σ=0.1631）
    A max-abs   : scale=0.008661  全体MSE=6.031e-6  主体MSE=6.032e-6  最大误差=0.0043
    B 截断3σ    : scale=0.001285  全体MSE=3.473e-4  主体MSE=1.369e-7  最大误差=0.9369
    C 放大2x    : scale=0.017323  全体MSE=2.517e-5  主体MSE=2.517e-5  最大误差=0.0087
```

看策略 B：把范围**截断到 3 倍标准差**（放弃精确表示那两个离群值），scale 一下变小到 `0.0013`，**主体（占绝大多数的普通权重）的 MSE 从 `6e-6` 猛降到 `1.4e-7`——好了 40 多倍！** 代价是那两个离群值被"压扁"，最大误差飙到 `0.94`。这就是量化里最核心的**长尾权衡**：离群值逼着 scale 变大，浪费了整数码位的分辨率；适当截断能让主体精细得多，但要承受离群值的饱和误差。

**实验 3：per-tensor vs per-channel，差距有多大。** 造一个 3 通道矩阵，三个通道尺度悬殊（0.1 / 1.0 / 10.0）：

```text
[3] per-tensor vs per-channel（3 通道尺度 0.1/1.0/10.0）
    per-tensor : 一个 scale=0.229692  MSE=4.206e-3
    per-channel: 每通道各自 scale MSE=1.398e-3
      通道0(尺度 0.1): per-tensor MSE=4.115e-3  per-channel MSE=4.618e-7  改善 8911x
      通道1(尺度   1): per-tensor MSE=4.366e-3  per-channel MSE=5.832e-5  改善 75x
      通道2(尺度  10): per-tensor MSE=4.135e-3  per-channel MSE=4.135e-3  改善 1x
```

`per-tensor` 用一个全局 scale，被尺度最大的通道 2（尺度 10）主导，结果**小尺度的通道 0 被彻底压垮**——它的值只有 0.1 量级，却要用 0.23 的步长去量化，几乎全部塌成 0！换成 `per-channel`，通道 0 的误差**改善了 8911 倍**。这就是为什么权重量化几乎都用 per-channel。

**实验 4：对称 vs 非对称，量化一段带偏移的激活。**

```text
[4] 对称 vs 非对称（带偏移激活，范围 [-2.305, 5.342]，不以 0 对称）
    对称 int8 : scale=0.042059  MSE=1.489e-4（覆盖 [-amax,amax]，负半轴码位大量浪费）
    非对称 u8 : scale=0.029985, zero_point=77  MSE=7.466e-5
```

激活范围 `[-2.3, 5.3]` 不以 0 对称。对称量化被迫覆盖 `[-5.3, 5.3]`，负半轴一大截没数据、码位白白浪费；非对称量化用 `zero_point=77` 把标尺**精准贴合真实范围**，误差直接减半。若像 ReLU 输出那样**全为正**，对称会浪费整整一半码位，非对称优势更大。

## 常见坑与提示

> 🕳️ **坑**：**只量化、不测精度。** 量化必然引入误差（实验里都量给你看了）。有些任务对此不敏感，有些（尤其激活分布长尾、或对小数值敏感的回归任务）会明显掉点。**量化后必须在验证集上重测精度**，别拿体积变小当胜利。

> ⚠️ **注意**：**int8 乘法会溢出——累加器必须用 int32。** `int8 × int8` 最大约 `127×127 ≈ 16129`，早超出 int8 的 `[-128,127]`；一层卷积/矩阵乘要累加成百上千个这样的乘积。所以真实 int8 推理的**累加器是 int32**，最后再把结果重新量化回 int8。自己实现时这一步搞错，结果会诡异地翻车。

> 🕳️ **坑**：**zero-point 别丢、别处理错。** 非对称量化的 \\( z \\) 必须和权重一起存好，推理时严格按 \\( x \approx s(q - z) \\) 减回去；漏了或符号搞反，整个数值就偏了。

> 🕳️ **坑**：**结构化剪枝后不微调，精度回不来。** 删掉整个通道相当于给网络"动手术"，直接用往往掉点严重。标准流程是**剪枝 → 微调几轮 → 再评估**，让剩下的权重补偿被删部分。

> 💡 **提示**：**per-tensor 图省事，per-channel 保精度。** 实验 3 的 8911 倍差距不是特例。权重量化默认上 per-channel；激活因为要在线算 scale，才多用 per-tensor。

## 本章小结

- 量化 = **给浮点数选一把整数标尺**，由 **scale（步长）和 zero-point（零点）** 定义。**对称**（权重，\\( z=0 \\)）用 \\( s=\max(|x|)/127 \\)；**非对称/仿射**（激活）用 \\( q=\mathrm{clip}(\mathrm{round}(x/s)+z, 0, 255) \\) 把码位贴合真实范围。
- **PTQ** 成本低（只需校准数据），**QAT** 精度高（要重训）；**per-channel** 比 **per-tensor** 精度高得多（实测小尺度通道改善近 **9000 倍**）。
- 我们手写 int8 量化实测：体积砍 **1/4**；**截断离群值**让主体 MSE 好 40 多倍但离群值饱和（长尾权衡）；**非对称**比对称误差减半。
- **剪枝**（结构化才真加速，剪后要微调）、**蒸馏**（小模型学大模型软标签）是另外两条压缩路。
- **诚实边界**：纯 Rust 的量化**工具链**不成熟，主流是训练侧量化好、导出后由 tract/candle 加载推理。**坑**：只量化不测精度、int8 累加溢出、zero-point 处理错、剪枝不微调。

## 动手练习

1. **复现并调参**：`cargo run --example ch95_quantization` 复现上面四组数字。把实验 2 的截断阈值从 `3σ` 改成 `2σ` 和 `5σ`，观察主体 MSE 和最大误差怎么此消彼长。
2. **量化到 int4**：把对称量化的 `127` 改成 `7`（4 位整数范围 `[-7,7]`），重跑实验 1，看 MSE 涨了多少——体会"位数越低、越省但越糊"。
3. **模拟长尾**：给实验 1 的权重多塞几个更大的离群值（比如 ±5.0），看 max-abs 策略的主体 MSE 怎么被拖垮，再验证截断策略如何救场。
4. **想一想**：一个模型量化后**文件小了 4 倍，但在你的 CPU 上推理反而变慢了**，可能是什么原因？（提示：回顾"坑"——硬件有没有高效的 int8 kernel？）

## 专家补强：精度与性能，必须一起验证

量化的最大陷阱，是**只看文件大小就宣布成功**。真正可交付的压缩，要做到精度和性能的**共同验证**：

- **逐层测量、定位敏感层**：逐层比较量化前后的输出误差，找出**对量化最敏感的那几层**（常是首尾层或数值范围极端的层）。对策是**混合精度**——敏感层保留 f16/f32，其余上 int8，用最小的精度损失换最大的压缩。
- **系统比较校准与粒度**：对比 **per-tensor / per-channel**，以及不同**校准方法**（min-max、百分位截断、KL 散度最小化）在你的数据上的效果；校准集不必大，但**必须覆盖真实的设备、光照、尺度和极端值**，否则线上遇到没校准过的分布就会掉链子。
- **证明端到端收益，而非文件大小**：一定要测**真实的吞吐、P95 延迟、内存和目标精度**。关键一点：**硬件若没有高效的 int8 kernel，量化后可能反而更慢**（实验 4 的"坑"）——"变小"不等于"变快"。
- **按业务门限卡发布**：即使平均指标合格，只要**关键类别的召回或校准误差**超过预先冻结的门限，就应拒绝发布——平均值会掩盖对关键类的伤害。
