# 第 19 章 霍夫变换：检测直线与圆

> **本章导读**
> - 学完你能：讲清楚霍夫变换如何用**投票**从一堆散乱的边缘点里"拼"出直线，并用 `imageproc` 检测直线、把结果画回原图。
> - 理解一个核心技巧：为什么直线检测要在**参数空间**里做、为什么用极坐标 \\( \rho = x\cos\theta + y\sin\theta \\) 而不是我们熟悉的 \\( y = kx + b \\)。
> - 学会调 `vote_threshold`（投票阈值）——它太低会检出一堆假线，太高会漏检。
> - 顺带认识**霍夫圆检测**的思路（参数空间升到三维）。

## 场景：把散乱的边缘点"拼"成直线

上一章 [第 18 章 连通域与轮廓分析](ch18-contours.md) 我们学会了从二值图里抠出连通的区域。但很多任务关心的不是"块"，而是"线"：检测一张 A4 纸的四条边好做透视矫正、找出道路上的车道线、量一块钢板的边缘直不直、定位电路板上的走线……

你可能会想：这不简单吗，先用 [第 15 章](ch15-edges.md) 的 Canny 做边缘检测不就有线了？可惜没那么美。Canny 给你的是**一堆孤立的边缘像素点**——它只告诉你"这个像素在边缘上"，却不会告诉你"这些点连起来是一条直线"。更糟的是，真实图像里的边缘常常断断续续、还夹着噪声点。

> 📖 **术语**：**霍夫变换（Hough Transform）**。一种从边缘点集合中检测**几何形状**（直线、圆、椭圆等）的经典方法，1962 年由 Paul Hough 提出。核心思想是"投票"：让每个边缘点为"它可能属于哪条直线"投票，得票最多的直线就是真实存在的直线。它的最大优点是**抗断裂、抗噪声**——哪怕直线中间断了几截，只要总票数够，照样能检出来。

## 原理：换个空间来投票

### 难点：一个点属于无数条直线

先想想为什么直接找直线很难。给你图像上**一个**边缘点 \\( (x_0, y_0) \\)，问：它在哪条直线上？答案是——**穿过这个点的直线有无数条**（各种斜率都行）。单看一个点，什么也定不下来。

霍夫变换的高明之处在于**反过来想**：既然一个点对应无数条直线，那我就让每个点把"我可能所在的所有直线"都投一票。**如果好几个点恰好共线，那条真实的直线就会被反复投到，票数一骑绝尘。**

### 参数空间：点变曲线，共线变交点

关键操作是**换个坐标系**。我们平时看图用的是**图像空间**（横轴 \\(x\\)、纵轴 \\(y\\)）。霍夫变换引入一个**参数空间**：用描述一条直线所需的**参数**当坐标轴。

一条直线用什么参数描述？中学学的是斜截式 \\( y = kx + b \\)，用 \\((k, b)\\) 两个参数。于是：

- **图像空间里的一条直线** ↔ **参数空间里的一个点** \\((k, b)\\)；
- **图像空间里的一个点** \\((x_0, y_0)\\) ↔ 满足 \\( y_0 = k x_0 + b \\) 即 \\( b = -x_0 k + y_0 \\) 的**所有** \\((k,b)\\)，这在参数空间里是**一条直线**。

于是"图像空间中共线的多个点"，就变成了"参数空间中多条直线交于同一点"。**找图像里的直线 = 找参数空间里的交点**——而交点，正是被投票投出来的热点。

### 用极坐标避开"斜率无穷大"

斜截式有个致命毛病：**竖直线的斜率 \\(k\\) 是无穷大**，参数空间没法表示。工业和自然图像里竖直、水平的边缘又特别常见，这可不行。

解决办法是改用**极坐标（法线式）**来描述直线：

\\[ \rho = x\cos\theta + y\sin\theta \\]

它的几何含义是：从原点（图像左上角）向直线作垂线，\\( \theta \\) 是这条**垂线（法线）与 \\(x\\) 轴的夹角**，\\( \rho \\) 是**垂线的长度**（原点到直线的距离）。任何一条直线都能用一对 \\((\rho, \theta)\\) 唯一表示，且 \\( \theta \\) 只需在 \\([0°, 180°)\\) 内取值，\\( \rho \\) 可正可负——**再也没有无穷大了**。记两个特例：**竖直线** \\( \theta = 0° \\)，**水平线** \\( \theta = 90° \\)。

在这套参数下，投票的图景变成：

```text
   图像空间(x,y)                 参数空间(θ, ρ)
   三个共线的点                  每个点画一条正弦曲线
   ·A                            ╲A   ╱B  ╱C     三条曲线
      ·B          ──►             ╲  ╳  ╱        交于一点 ★
         ·C                        ╲╱ ★╲╱         → 那就是这条直线
                                   /    ╲         的 (θ, ρ)
```

**图像空间的每个点 → 参数空间里一条正弦曲线**（把点的 \\((x_0,y_0)\\) 代入，\\(\rho\\) 随 \\(\theta\\) 变化就画出一条 \\(\rho = x_0\cos\theta + y_0\sin\theta\\) 的正弦曲线）；**共线的点，它们的曲线交于同一个 \\((\theta, \rho)\\)**。哪个 \\((\theta,\rho)\\) 被最多曲线穿过，哪条直线就最"真"。

### 投票累加器

实际计算时，我们把参数空间离散成一个网格（\\(\theta\\) 每 1° 一格，\\(\rho\\) 每 1 像素一格），做一个二维计数器，叫**累加器（accumulator）**。算法就三步：

1. 累加器清零。
2. 对每个边缘点，遍历所有 \\(\theta\\)，算出对应的 \\(\rho\\)，给累加器格子 `acc[θ][ρ] += 1`（投一票）。
3. 找出票数超过阈值的格子，每个就是一条检测到的直线。

`imageproc` 的 `detect_lines` 内部干的正是这件事。

### 霍夫圆：把参数空间升到三维

同样的思路能推广到圆。一个圆要三个参数：圆心 \\((a, b)\\) 和半径 \\(r\\)，方程 \\( (x-a)^2 + (y-b)^2 = r^2 \\)。于是参数空间从二维 \\((\theta,\rho)\\) 升到**三维 \\((a, b, r)\\)**——每个边缘点在这个三维空间里投出一个"锥面"，圆心处票数最高。原理一模一样，只是累加器变成三维、计算量更大。

> ⚠️ **注意**：`imageproc` 0.27 的 `hough` 模块**只提供直线检测（`detect_lines`）**，没有现成的圆检测函数。要检测圆，你得自己实现三维累加器投票，或借助梯度方向缩小搜索。本章圆检测只讲思路，动手部分聚焦直线；圆的实现留作进阶练习。

## 动手写代码：合成图 → Canny → 检测直线 → 画回

我们合成一张"白底 + 黑色正方形 + 一条粗斜线"的图，先用 Canny 得到边缘图，再用霍夫检测直线，最后把检测到的直线用红色画回原图，并演示不同 `vote_threshold` 的效果。

`Cargo.toml` 依赖：

```toml
[dependencies]
image = "0.25"
imageproc = "0.27"
```

完整代码（`examples/ch19_hough.rs`）：

```rust
use image::{GrayImage, Rgb, RgbImage};
use imageproc::drawing::{draw_filled_rect_mut, draw_line_segment_mut};
use imageproc::edges::canny;
// 注意：draw_polar_lines_mut 在 hough 模块里，不在 drawing 里！
use imageproc::hough::{detect_lines, draw_polar_lines_mut, LineDetectionOptions};
use imageproc::rect::Rect;

/// 合成一张“照片”：白底 + 一个黑色正方形 + 一条粗斜线
fn make_scene(w: u32, h: u32) -> RgbImage {
    let mut img = RgbImage::from_pixel(w, h, Rgb([255, 255, 255]));
    // 黑色实心正方形：贡献左右两条竖边(θ=0°) + 上下两条横边(θ=90°)，四边等长票数对称
    draw_filled_rect_mut(&mut img, Rect::at(60, 70).of_size(150, 150), Rgb([30, 30, 30]));
    // 一条较粗的黑色斜线（画三条相邻线段模拟“粗”，Canny 更好检到）
    for d in -1..=1 {
        let dx = d as f32;
        draw_line_segment_mut(&mut img, (250.0 + dx, 40.0), (370.0 + dx, 260.0), Rgb([20, 20, 20]));
    }
    img
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let scene = make_scene(420, 300);
    let gray: GrayImage = image::DynamicImage::ImageRgb8(scene.clone()).to_luma8();

    // 关键一步：先用 Canny 得到边缘图，再喂给霍夫（不要直接喂灰度图！）
    let edges = canny(&gray, 50.0, 100.0);

    // 演示 vote_threshold 调参：太低→假线，合适→干净，太高→漏检
    for vt in [50u32, 120, 200] {
        let opts = LineDetectionOptions { vote_threshold: vt, suppression_radius: 8 };
        let lines = detect_lines(&edges, opts);
        println!("vote_threshold={vt} -> 检出 {} 条直线", lines.len());
        for l in &lines {
            println!("   ρ={:.1}, θ={}°", l.r, l.angle_in_degrees);
        }
    }

    // 用一个合适的阈值把直线画回原图（红色）
    let opts = LineDetectionOptions { vote_threshold: 120, suppression_radius: 8 };
    let lines = detect_lines(&edges, opts);
    let mut out = scene.clone();
    draw_polar_lines_mut(&mut out, &lines, Rgb([255, 0, 0]));

    edges.save("out_ch19_edges.png")?;
    out.save("out_ch19_lines.png")?;
    Ok(())
}
```

运行 `cargo run --example ch19_hough`，终端打印（数字真实可复现）：

```text
vote_threshold=50 -> 检出 7 条直线
   ρ=60.0, θ=0°
   ρ=209.0, θ=0°
   ρ=69.0, θ=90°
   ρ=219.0, θ=90°
   ρ=-196.0, θ=151°
   ρ=-206.0, θ=179°
   ρ=-56.0, θ=179°
vote_threshold=120 -> 检出 5 条直线
   ρ=60.0, θ=0°
   ρ=209.0, θ=0°
   ρ=69.0, θ=90°
   ρ=219.0, θ=90°
   ρ=-196.0, θ=151°
vote_threshold=200 -> 检出 0 条直线
```

逐条对号入座（看 `vote_threshold=120` 那五条，干净得很）：

- `ρ=60, θ=0°` 和 `ρ=209, θ=0°`：正方形的**左、右两条竖边**（\\(x=60\\) 和 \\(x=210\\)，\\(\theta=0°\\) 正是竖直线）；
- `ρ=69, θ=90°` 和 `ρ=219, θ=90°`：正方形的**上、下两条横边**（\\(y=70\\)、\\(y=220\\)，\\(\theta=90°\\) 是水平线，边缘落在 69/219 像素处）；
- `ρ=-196, θ=151°`：那条**斜线**。

而 `vote_threshold=50` 时冒出的两条 `θ=179°`，是竖直强边缘在"接近 180°"处漏出的**伪线**——这就是阈值太低的代价。阈值提到 200 又矫枉过正，一条都不剩。打开 `out_ch19_lines.png`，你会看到五条红线严丝合缝地压在正方形四边和那条斜线上。

## 常见坑与提示

> 🕳️ **坑**：**输入必须是边缘图（先 Canny），别直接喂原图或灰度图！** `detect_lines` 把**所有非零像素**都当作边缘点参与投票。如果你把一张灰度照片直接丢进去，成千上万个非零像素全在乱投票，累加器一片红海，结果全是垃圾。标准流程永远是：原图 → 灰度 → Canny（或其他二值化）→ `detect_lines`。

> 🕳️ **坑**：**`vote_threshold` 是最关键的旋钮，且票数正比于线段长度。** 一条直线得到的票数 ≈ 它在图里的**像素长度**。所以长线票多、短线票少。阈值太低 → 检出一堆假线和重复线（如上面的 179° 伪线）；太高 → 短线、断线被漏掉。实践中要**根据图像尺寸和目标线长来调**：先设低一点看看都检出了啥，再往上加到"只剩真线"。

> ⚠️ **注意**：**角度单位是"度"，范围 `0..180`；`ρ` 可以是负数。** `PolarLine { r: f32, angle_in_degrees: u32 }` 里 `angle_in_degrees` 是整数度、恒在 `[0, 180)`；`r`（即 \\(\rho\\)）按符号约定可正可负。别把它当弧度用，也别假设 `r` 非负。

> 💡 **提示**：**`suppression_radius` 做非极大抑制，防止"一条线检出一簇"。** 真实边缘有粗细、有抖动，一条直线在累加器里往往不是一个孤立峰、而是一小片高票区。`suppression_radius` 让程序在每个 `2r+1` 的邻域内只保留票数最高的那个，避免同一条线返回好几条几乎重合的结果。设为 `0` 则关闭抑制。

## 本章小结

- 霍夫变换用**投票**从散乱边缘点中检测直线，核心是**换到参数空间**：图像空间的点 → 参数空间的曲线，**共线的点 → 曲线交于一点**，交点票数最高。
- 用极坐标 \\( \rho = x\cos\theta + y\sin\theta \\)（\\(\theta\\) 是法线与 x 轴夹角、\\(\rho\\) 是原点到直线的距离）代替 \\(y=kx+b\\)，**避开竖直线斜率无穷大**的问题；竖直线 \\(\theta=0°\\)、水平线 \\(\theta=90°\\)。
- `imageproc` 用 `detect_lines(&edges, LineDetectionOptions{vote_threshold, suppression_radius})` 返回 `Vec<PolarLine>`，用 `draw_polar_lines_mut` 画回。**输入务必是边缘图**。
- `vote_threshold` 太低出假线、太高会漏检，票数正比于线长；霍夫圆思路相同但参数空间升到三维 \\((a,b,r)\\)，`imageproc` 未内置需自行实现。

## 动手练习

1. **调阈值找甜点**：把 `vote_threshold` 从 30 逐步加到 200，记录每个值检出的直线数，找到"恰好只剩 5 条真线"的区间，体会阈值的敏感性。
2. **换个场景**：把正方形换成一个**三角形**（用三条 `draw_line_segment_mut` 画出），看霍夫能否检出三条边，它们的 \\(\theta\\) 各是多少？
3. **按角度过滤**：只保留 `angle_in_degrees` 在 `85..=95` 的直线（即近似水平线），把车道线检测里"只要横向标线"这种需求实现出来。
4. **进阶——手写霍夫圆**：合成一张只有一个圆的边缘图，自己开一个三维累加器 `acc[a][b][r]`，对每个边缘点投票，找出票数最高的 \\((a,b,r)\\)，验证它就是那个圆的圆心和半径。
