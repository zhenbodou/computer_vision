# 第 16 章 阈值分割与二值化（Otsu、自适应）

> **本章导读**
> - 学完你能：把一张灰度图干净地切成**前景**和**背景**（二值化），并说清楚三种阈值方法各自的适用场景。
> - 理解**全局固定阈值**为什么一遇到**光照不均**就崩，以及 **Otsu** 如何自动挑阈值。
> - 掌握专治光照不均的**自适应阈值**——本章会用真实数字见证它在光照渐变下**完胜**固定阈值。
> - 认全 `ThresholdType` 五种模式，避开"黑白颠倒"这个新手必踩的坑。

## 场景：从光照不均的照片里抠出文字

设想你要做一个"拍照识别文档"的小工具：把手机拍的一页纸变成黑底白字（或白底黑字），好送去 OCR。第一步就是**二值化（binarization）**——把每个像素判成"前景"（文字，一类值）或"背景"（纸面，另一类值），整张图只剩黑白两色。

听起来简单："定个阈值，比它暗的是字、比它亮的是纸，不就行了？" 这就是**全局固定阈值**。可你一拍就发现：手机拍纸，左边挨着台灯特别亮、右边阴影里发暗。你定的那个阈值，在亮区把纸面也当成了字，在暗区又把字漏成了纸——**光照不均，一个阈值照顾不过来。** 这一章就来解决它。

> 📖 **术语**：**二值化 / 阈值分割（thresholding）**。设定一个或多个**阈值（threshold）**，把灰度值大于/小于阈值的像素分别赋成两个固定值（通常 0 和 255），从而把图像分成**前景（foreground）**和**背景（background）**两类。它几乎是所有"先分区域、再分析"任务的第一步。

## 原理：三种阈值策略，层层进阶

### 全局固定阈值：简单，但脆弱

最朴素的做法：全图用**同一个**阈值 \\( T \\)。以最常见的 `Binary` 模式为例：

\\[ \text{dst}(x,y) = \begin{cases} 255 & \text{if } \text{src}(x,y) > T \\\\ 0 & \text{否则} \end{cases} \\]

它快、直观，在**光照均匀、前景背景对比鲜明**时非常好用。但它的死穴是：**\\( T \\) 是全图一个值，没法适应局部明暗变化。** 当整张图存在光照渐变时，同一个 \\( T \\) 在这里合适、在那里就错——这正是我们场景里的困境。

### Otsu：让机器自动挑阈值

固定阈值还有个烦恼：\\( T \\) 该取多少？靠人肉试太笨。**Otsu（大津法）** 能**自动**从图像的**直方图**里算出一个最优阈值，思路特别漂亮：

> 一个好的阈值，应该让**分出来的前景和背景两拨像素"最泾渭分明"**。

怎么量化"泾渭分明"？Otsu 用**类间方差（between-class variance）**。它遍历每一个候选阈值 \\( t \\)，把像素分成"暗于 t"和"亮于 t"两类，算两类各自的占比 \\( w_0, w_1 \\) 和平均灰度 \\( \mu_0, \mu_1 \\)，然后计算：

\\[ \sigma_b^2(t) = w_0(t)\, w_1(t)\, \big(\mu_0(t) - \mu_1(t)\big)^2 \\]

这个值越大，说明两类的**均值差得越远**（分得越开）、且两类**都不至于太小**。**Otsu 选的就是让 \\( \sigma_b^2 \\) 最大的那个 \\( t \\)。** 直觉上，如果直方图有"两座山峰"（前景一峰、背景一峰），Otsu 会自动把阈值卡在两峰之间的山谷里。

但请注意：**Otsu 再聪明，本质仍是"全局单一阈值"**——它只是帮你自动选 \\( T \\)，并没有解决"一个 \\( T \\) 照顾不了全图"的根本问题。光照不均时，它照样力不从心，待会儿的数字会证明这一点。

### 自适应阈值：一人一策

真正专治光照不均的是**自适应阈值（adaptive threshold）**：**不再全图一个阈值，而是给每个像素单独定一个阈值**——这个阈值取自它**周围一小片邻域**的平均亮度。imageproc 的规则是：

\\[ \text{dst}(x,y) = \begin{cases} 255\ (\text{白}) & \text{if } \text{src}(x,y) \ge \text{局部均值} - \delta \\\\ 0\ (\text{黑}) & \text{否则} \end{cases} \\]

其中"局部均值"是以该像素为中心、半径 `block_radius` 的方块内的平均灰度，`delta` 是一个微调偏移。**关键在于阈值随"当地背景"水涨船高**：亮区的阈值自动变高、暗区自动变低。于是"比当地背景暗"的文字，无论落在亮区还是暗区，都能被稳稳判成前景。这就是它专克光照不均的原因。

```text
        全局固定阈值 T                自适应阈值（每点看邻域）
   亮区 ─────────────── T (太低,纸也算字)   亮区 ┈┈ 阈值↑ 只有真的暗才算字
   暗区 ─────────────── T (太高,字被漏掉)   暗区 ┈┈ 阈值↓ 稍暗即算字 ✔
```

## 动手写代码：固定 vs Otsu vs 自适应，三者对决

我们合成一张**光照不均**的图：背景从左到右由暗（40）渐亮到亮（210），上面立着三根**竖直暗条**（模拟文字/目标），每根都比它**当地的背景**暗 60。因为我们**知道暗条的确切位置**，就能用 **IoU（交并比）** 客观打分，看谁分割得准。

> 💡 **提示**：为什么用 IoU 而不用"准确率"？因为暗条只占约 10% 的像素，**把整张图全判成背景就有 90% 的准确率**——准确率在类别不均衡时会骗人。IoU（前景交集÷前景并集）只看前景分得准不准，才是分割任务的公道尺子。

`Cargo.toml`：

```toml
[dependencies]
image = "0.25"
imageproc = "0.27"
```

完整代码（`examples/ch16_threshold.rs`）：

```rust
use image::{GrayImage, ImageBuffer, Luma};
use imageproc::contrast::{adaptive_threshold, otsu_level, threshold, ThresholdType};

const W: u32 = 240;
const H: u32 = 180;

/// 背景光照（左暗右亮的线性渐变）：40 → 210
fn background(x: u32) -> i32 {
    40 + (x as i32 * 170 / (W as i32 - 1))
}

/// 三根竖直暗条（宽约 12 像素），模拟"局部比背景暗"的目标
fn is_bar(x: u32, y: u32) -> bool {
    if !(30..150).contains(&y) {
        return false;
    }
    (40..52).contains(&x) || (110..122).contains(&x) || (185..197).contains(&x)
}

/// 合成"光照不均 + 局部暗目标"的灰度图
fn make_scene() -> GrayImage {
    ImageBuffer::from_fn(W, H, |x, y| {
        let bg = background(x);
        if is_bar(x, y) {
            Luma([(bg - 60).clamp(0, 255) as u8]) // 比"当地背景"暗 60
        } else {
            Luma([bg.clamp(0, 255) as u8])
        }
    })
}

/// 前景 IoU（交并比）：前景=暗条
fn iou<F: Fn(u32, u32) -> bool>(detected: F) -> f32 {
    let (mut inter, mut union) = (0u32, 0u32);
    for y in 0..H {
        for x in 0..W {
            let (truth, det) = (is_bar(x, y), detected(x, y));
            if truth && det { inter += 1; }
            if truth || det { union += 1; }
        }
    }
    if union == 0 { 0.0 } else { inter as f32 / union as f32 * 100.0 }
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let scene = make_scene();

    // 打印几处像素，看"暗条亮度"与"别处背景亮度"如何重叠
    println!("左/中/右暗条像素值 ≈ {} / {} / {}",
        scene.get_pixel(45, 90)[0], scene.get_pixel(116, 90)[0], scene.get_pixel(190, 90)[0]);
    println!("最右侧背景像素值 ≈ {}", scene.get_pixel(238, 90)[0]);

    // ① 全局固定阈值：暴力扫描 0..=255，找"最优"全局阈值能达到的最高 IoU
    let (mut best_t, mut best_iou) = (0u8, 0.0f32);
    for t in 0u16..=255 {
        let v = iou(|x, y| scene.get_pixel(x, y)[0] as u16 <= t); // 暗于阈值 → 前景
        if v > best_iou { best_iou = v; best_t = t as u8; }
    }
    println!("最优全局固定阈值 T={}，前景 IoU={:.1}%", best_t, best_iou);

    // ② Otsu 自动阈值
    let level = otsu_level(&scene);
    println!("Otsu 阈值={}，前景 IoU={:.1}%",
        level, iou(|x, y| scene.get_pixel(x, y)[0] <= level));

    // ③ 自适应阈值（block 半径 15，delta 10）
    // 规则：pixel >= 局部均值-delta → 白(255)；"比当地背景暗"的暗条 → 黑(0)=前景
    let adap = adaptive_threshold(&scene, 15, 10);
    println!("自适应阈值 前景 IoU={:.1}%", iou(|x, y| adap.get_pixel(x, y)[0] == 0));

    // ④ ThresholdType 选反 → 黑白颠倒（两者白像素数互补）
    let bin = threshold(&scene, level, ThresholdType::Binary);
    let bin_inv = threshold(&scene, level, ThresholdType::BinaryInverted);
    println!("Binary 白像素={}, BinaryInverted 白像素={}（互补）",
        bin.iter().filter(|&&p| p == 255).count(),
        bin_inv.iter().filter(|&&p| p == 255).count());

    scene.save("out_ch16_scene.png")?;
    bin_inv.save("out_ch16_global.png")?;
    adap.save("out_ch16_adaptive.png")?;
    Ok(())
}
```

运行 `cargo run --example ch16_threshold`，终端打印（数字真实可复现）：

```text
左/中/右暗条像素值 ≈ 12 / 62 / 115
最右侧背景像素值 ≈ 209
最优全局固定阈值 T=16，前景 IoU=33.3%
Otsu 阈值=121，前景 IoU=18.8%
自适应阈值 前景 IoU=100.0%
Binary 白像素=20160, BinaryInverted 白像素=23040（互补）
```

这组数字把三者的高下讲得明明白白：

1. **暗条亮度自己就"打架"**：左暗条 `12`、中 `62`、右 `115`。而背景是 40→209 的渐变——**右暗条的 115，和图像中部某处的背景亮度撞了车**。这意味着：**世上不存在一个全局阈值能同时把三根暗条都挑出来又不误伤背景。**
2. **最优全局固定阈值 IoU 仅 33.3%**：哪怕我们暴力扫遍所有阈值挑最好的（`T=16`），也只能勉强抓住最暗的**那一根**左暗条，另外两根全丢——三分之一，正好对应 `33.3%`。
3. **Otsu 更惨，只有 18.8%**：Otsu 自动选了 `T=121`，试图把三根暗条都划进前景，代价是**把左半边大片偏暗的背景也误判成前景**，false positive 爆炸，IoU 反而更低。**这戳穿了一个误区：Otsu 不是万能的，它治不了光照不均。**
4. **自适应阈值 IoU = 100.0%，完胜**：因为它给每个像素用的是**当地邻域**的阈值——不管暗条落在亮区还是暗区，只要"比周围暗"就被抓住。三根暗条一根不落、背景一个不误。**这就是自适应阈值存在的全部意义。**

### 认全 `ThresholdType`

`threshold(&gray, T, ttype)` 的第三个参数决定"过阈值/不过阈值分别赋什么值"，共五种（`src` 是原值）：

| 模式 | `src > T` 时 | 否则 | 典型用途 |
|------|------------|------|---------|
| `Binary` | `255` | `0` | 标准二值化（亮的变白） |
| `BinaryInverted` | `0` | `255` | 反着来（暗的变白，抠暗色目标） |
| `Truncate` | `T` | `src` | 削顶，压制高光 |
| `ToZero` | `src` | `0` | 保留亮部、抹黑暗部 |
| `ToZeroInverted` | `0` | `src` | 保留暗部、抹黑亮部 |

代码里 `Binary` 得到 `20160` 个白像素，`BinaryInverted` 得到 `23040` 个——两者相加正好是 `240×180=43200`，即整张图，说明它俩把黑白**完全对调**了。选 `Binary` 还是 `BinaryInverted`，取决于**你的前景是亮的还是暗的**。

## 常见坑与提示

> 🕳️ **坑**：**光照不均是固定阈值的头号杀手。** 本章实测：光照渐变下，最优全局阈值 IoU 只有 33.3%、Otsu 更是跌到 18.8%，而自适应阈值 100%。凡是"背景亮度在图内明显变化"（打光偏、渐晕、阴影）的场景，**别犹豫，直接上自适应阈值**。想先救急，也可以先做一次[第 12 章](../p02-image-basics/ch12-histogram.md)的直方图均衡，但那治标不治本。

> 🕳️ **坑**：**`ThresholdType` 选反 → 黑白颠倒，后续全乱。** 你以为抠出了白色文字，结果得到白底黑字，送进后面的连通域/轮廓分析（[第 18 章](ch18-contours.md)）会把整个背景当成一个巨大前景。**记牢：前景亮用 `Binary`，前景暗用 `BinaryInverted`。** 拿不准就把结果存成图看一眼——前景该是白的（255）。

> ⚠️ **注意**：**自适应阈值的 `block_radius` 要比目标"笔画"更大。** 邻域必须足够大，才能"看到"目标周围的背景来估计当地亮度。如果 `block_radius` 比目标还小，方块整个落在目标内部，算出的"局部均值"就等于目标自身亮度，判断失效（目标内部会被误判成背景，出现空心）。经验：半径取"最粗笔画宽度"的 1~2 倍以上。本章暗条宽 12，取半径 15 稳妥。

> 💡 **提示**：**`delta` 调节松紧。** `delta` 增大 → 判为前景（黑）的条件更苛刻、前景变少（更干净但可能漏检）；减小甚至取负 → 前景变多（更敏感但易引入噪点）。它就是自适应阈值的"灵敏度旋钮"，配合 `block_radius` 一起调。

## 本章小结

- **二值化**把灰度图按阈值切成**前景/背景**两类，是"先分区域再分析"的第一步。
- **全局固定阈值**简单快，但**一个阈值照顾不了全图**；光照不均时（本章 IoU 仅 33.3%）无解。
- **Otsu** 用**类间方差最大** \\( \sigma_b^2 = w_0 w_1 (\mu_0-\mu_1)^2 \\) 自动选全局阈值，省去人肉调参；但它**仍是全局单阈值**，治不了光照不均（本章反而更差，18.8%）。
- **自适应阈值**给每个像素用**局部邻域**的阈值，专克光照不均（本章 100%）——`adaptive_threshold(&img, block_radius, delta)`，注意"比当地暗"的目标会变成**黑(0)**。
- `ThresholdType` 五种模式（Binary/BinaryInverted/Truncate/ToZero/ToZeroInverted）：**前景亮用 `Binary`、前景暗用 `BinaryInverted`**，选反就黑白颠倒。

## 动手练习

1. **验证 Otsu 的软肋**：把 `make_scene` 里的光照渐变去掉（`background` 恒定返回 `130`），重跑，观察 Otsu 的 IoU 是否飙升——印证"Otsu 在光照均匀时其实很好用"。
2. **调自适应参数**：把 `adaptive_threshold` 的 `delta` 从 10 改到 30、再改到 0，看前景 IoU 和输出图怎么变，体会"灵敏度旋钮"。
3. **半径踩坑**：故意把 `block_radius` 设成 3（比暗条还窄），观察暗条内部是否出现"空心"，亲手复现上面那个坑。
4. **进阶**：把 `is_bar` 换成几个**亮**方块（比背景亮 60），此时前景是亮的。改用 `Binary`（固定阈值那侧）、并思考自适应阈值该如何调整判据（提示：现在前景是"比当地背景亮"的像素）。
