# 第 34 章 传统目标检测：滑动窗口 + HOG + SVM

> **本章导读**
> - 深度学习普及之前，工业界怎么在一张图里**框出所有行人/物体**？本章还原这套经典范式。
> - 学完你能想通一条完整数据流：**滑动窗口**扫描 → 每个窗口提 [HOG 特征](../p04-features/ch27-handcrafted-features.md) → 送 **SVM** 判类 → 一堆重叠框用**非极大值抑制（NMS）** 合并成干净的结果。
> - 亲手写一个 **IoU + NMS** 函数（纯 Rust，主工程可跑），并实测"6 个框合并成几个"。
> - 直面这套方法的软肋，理解**它为何后来被深度学习取代**——但它的思想（多尺度、NMS）至今仍活在现代检测器里。

## 场景：把街景里的每一个行人都框出来

前面第八部分之前我们还没学分类器，但你已经有直觉了：给定一张 `64×128` 的小图，判断"里面是不是一个人"，这是个**分类**问题——[第 27 章](../p04-features/ch27-handcrafted-features.md) 的 HOG 特征加上一个分类器就能做。

可现实任务是"在一张 `1920×1080` 的街景图里，找出**所有**行人**在哪**"。这比"是不是"难在两点：**位置未知**（人可能在画面任何地方）、**大小未知**（近处的人大、远处的人小）。

2005 年 Dalal 和 Triggs 给出的经典答案朴素得让人拍腿：**既然我会判断"一个窗口里是不是人"，那我就把窗口挪遍全图、缩放遍所有尺寸，每挪一次就问一次不就行了？** 这就是**滑动窗口（sliding window）**。检测于是被巧妙地**化归成了成千上万次分类**。本章就把这条"滑窗 → HOG → SVM → NMS"的流水线走一遍。

## 原理：把"检测"拆成"到处做分类"

### 滑动窗口 + 图像金字塔

想象一个固定大小（比如 `64×128`，行人的经典长宽比）的"取景框"，从图像左上角开始，按固定**步长（stride）** 一格格向右、向下移动，每停一次就把框里的内容抠出来送去分类。这解决了"位置未知"。

那"大小未知"呢？窗口大小固定，可人有大有小。诀窍是反过来——**不改窗口，改图像**：把原图逐级缩小，形成一摞由大到小的图像，即 [第 21 章](../p03-classic/ch21-pyramids.md) 的**图像金字塔（image pyramid）**。同一个 `64×128` 窗口，在缩小的图上扫，相当于在原图上"看"了更大的范围——于是大人小人都能被某一层的窗口不多不少地框住。

```text
原图(大)           缩小 0.75          缩小 0.5
┌───────────┐      ┌────────┐        ┌─────┐
│ □→□→□→ ..  │      │ □→□→ .. │        │□→ ..│   □ = 固定大小窗口(64x128)
│ ↓         │      │ ↓      │        │↓    │   每层从左到右、从上到下滑动
│ □→□→ ..   │      │ □→ ..  │        │     │   同一个窗口在越小的图上
└───────────┘      └────────┘        └─────┘   相当于在原图看越大的范围
```

在每个窗口上，我们抽取它的 HOG 特征（回忆一下：`64×128`、cell `8×8`、block `2×2`、9 方向的经典配置得到 **3780 维**向量），再把这个向量交给一个**已经训练好的分类器**打分：分数高就认为"这里有个人"。

### 用 SVM 做那个"打分器"

分类器用什么？经典搭配是**支持向量机（SVM，Support Vector Machine）**。直觉上，SVM 要做的是：在高维特征空间里找一个**分界面**，把"行人"的 HOG 向量和"背景"的 HOG 向量尽量分到两边，并且让分界面离两类样本都尽量远（"最大间隔"）。行人检测里最常用**线性 SVM**——又快又够用，一次点积就能给一个窗口打分。SVM 的原理和 linfa 用法见 [第 33 章](ch33-linfa.md)，本章重点在检测流水线本身。

### NMS：把一堆重叠框收成几个

滑窗有个必然的"副作用"：一个真实的人身上，**相邻的好几个窗口**（位置差几像素、尺度差一档）都会被判为"是人"，于是同一个人身上叠了一摞高度重叠的框。我们要的是一个人一个框，怎么去重？答案是**非极大值抑制（NMS，Non-Maximum Suppression）**。

要谈"重叠"，先要能量化两个框有多重叠，这就是**交并比（IoU，Intersection over Union）**：

\\[ \text{IoU}(A, B) = \frac{\lvert A \cap B \rvert}{\lvert A \cup B \rvert} \\]

```text
   A ┌───────┐
     │   ┌───┼───┐ B     交集 = 两框重叠的面积
     │   │▓▓▓│   │       并集 = A面积 + B面积 − 交集
     └───┼───┘   │       IoU  = 交集 / 并集  ∈ [0,1]，越大越重叠
         └───────┘
```

有了 IoU，NMS 的贪心逻辑就三句话：

1. 把所有候选框按分数**从高到低**排序；
2. 取出当前分数最高的框，**保留**它；
3. 把还没处理的框里、与它 IoU 超过阈值（如 0.5）的**统统压制**（它们被认为是"同一个目标的重复框"）。重复第 2 步直到没有框剩下。

```text
NMS 前(一个人身上炸出一摞框)      NMS 后
   ┌─┬─┐                          ┌───┐
   ├─┴┐│  ← 分最高的留下            │   │  ← 只保留分数最高的，
   │┌─┴┤    与它 IoU 高的删掉        │   │     其余重叠框被抑制
   └┴──┘                           └───┘
```

## 动手写代码（一）：主工程里的 IoU + NMS + 滑窗

IoU、NMS、金字塔滑窗、HOG 提取都不依赖 linfa，可以直接在本书主工程 `code/` 里跑。`Cargo.toml` 沿用主工程依赖：

```toml
[dependencies]
image = "0.25"
imageproc = "0.27"
```

核心是这两个函数（完整示例见 `examples/ch34_sliding_window.rs`）：

```rust
/// 一个候选检测框：左上角 (x, y) + 宽高 (w, h) + 分数 score
#[derive(Clone, Copy, Debug)]
struct Det { x: f32, y: f32, w: f32, h: f32, score: f32 }

/// 交并比 IoU = 交集面积 / 并集面积，范围 [0,1]
fn iou(a: &Det, b: &Det) -> f32 {
    let (ax2, ay2) = (a.x + a.w, a.y + a.h);
    let (bx2, by2) = (b.x + b.w, b.y + b.h);
    let ix1 = a.x.max(b.x);      let iy1 = a.y.max(b.y);   // 交集左上角
    let ix2 = ax2.min(bx2);      let iy2 = ay2.min(by2);   // 交集右下角
    let iw = (ix2 - ix1).max(0.0); let ih = (iy2 - iy1).max(0.0);
    let inter = iw * ih;                                   // 不重叠时为 0
    let union = a.w * a.h + b.w * b.h - inter;             // 并集 = 面积和 − 交集
    if union <= 0.0 { 0.0 } else { inter / union }
}

/// 贪心 NMS：按分数从高到低，保留一个就压制掉与它 IoU 过高的其余框
fn nms(mut dets: Vec<Det>, iou_thr: f32) -> Vec<Det> {
    dets.sort_by(|a, b| b.score.partial_cmp(&a.score).unwrap()); // 分数降序
    let mut keep = Vec::new();
    let mut suppressed = vec![false; dets.len()];
    for i in 0..dets.len() {
        if suppressed[i] { continue; }        // 已被更高分的框压制
        keep.push(dets[i]);                   // 当前最高分，保留
        for j in (i + 1)..dets.len() {        // 压制与它重叠过多的后续框
            if !suppressed[j] && iou(&dets[i], &dets[j]) > iou_thr {
                suppressed[j] = true;
            }
        }
    }
    keep
}
```

示例里先造 6 个候选框：物体 A 附近 3 个重叠框、物体 B 附近 2 个、外加一个孤立的误检框，喂给 NMS。运行 `cargo run --example ch34_sliding_window`，前半段输出（数字可复现）：

```text
[NMS] 输入候选框 6 个
[NMS] 框0 与框1 的 IoU = 0.784（同一物体的两个框，应较大）
[NMS] 框0 与框3 的 IoU = 0.000（不同物体，应为 0）
[NMS] IoU 阈值 0.5 → 保留 3 个框：
      score=0.90 @ (30, 40) 80x80
      score=0.88 @ (150, 70) 72x88
      score=0.55 @ (240, 10) 40x40
```

6 个框合并成了 **3 个**：物体 A、物体 B 各收敛到一个最高分框，加上那个**孤立的误检框**——它不和谁重叠，NMS 当然不会动它。这是个重要提醒：**NMS 只负责去重，不负责去误检**；干掉低分误检是"分数阈值"的活。

接着示例合成一张 `256×192` 的图（两个深色矩形当"物体"），用 3 层金字塔（尺度 1.0 / 0.75 / 0.5）、步长 16 的窗口扫一遍，每个窗口用"深色像素占比"当**分数的替身**（真实场景这里是 SVM 打分），得到：

```text
[金字塔] 3 层 × 步长16 共扫描窗口 = 186 个
[金字塔] 分数>0.6 的原始命中 = 38 个
[金字塔] NMS(IoU>0.5) 后剩下 = 18 个
[金字塔] NMS(IoU>0.3) 后剩下 = 5 个
[金字塔] NMS(IoU>0.2) 后剩下 = 2 个
```

两个真实物体，滑窗炸出 **38** 个原始框。而 NMS 阈值定多少大有讲究：阈值 0.5 太宽松，只压掉一半（还剩 18 个）；一路收紧到 **0.2 才干净地收敛到 2 个**——正好对应两个物体。为什么这里要用偏小的阈值？因为多尺度会产出**大小不一**的框（同一物体在不同层被框成大框和小框），它们互相的 IoU 本就偏低，阈值太大压不动。这正是 NMS 调参的日常。

最后示例对一个"行人剪影"窗口提 HOG，打通到分类器的那一环：

```text
[HOG] 行人窗口 64x128 的 HOG 维度 = 3780（= 7*15*36）
[HOG] 特征 L2 范数 = 9.487，非零维数 = 950 / 3780
[HOG] 已写出一行样本到 out_ch34_hog_sample.csv（label + 3780 维特征）
```

注意最后一步：我们把 `Vec<f32>` 特征转成 `Vec<f64>` 并写成一行 CSV。这不是多此一举——它是打通下一步的关键，马上解释。

## 动手写代码（二）：SVM 训练为何要单开一个工程

到了训练 SVM 这一步，我们撞上一个**真实的生态摩擦**。纯 Rust 的经典机器学习库是 `linfa`，但——

> 🕳️ **坑**：**linfa 0.8 锁定 `ndarray 0.16`，而本书主工程用的是 `ndarray 0.17`。** 若在同一个 `Cargo.toml` 里同时写这两者，cargo 会拉入**两个不同版本**的 ndarray，你用 0.17 造的 `Array2` 和 linfa（0.16）要的 `Array2` 会被编译器当成**两个不同类型**，报一堆 `expected ArrayBase... found ArrayBase...`。

对策很实际：**把 SVM 训练放进一个独立的小工程**，那里的 `ndarray` 钉到 0.16、与 linfa 一致；主工程和它之间用**与 ndarray 版本无关的中间形式**（就是上面那个 `Vec<f64>` / CSV）来传递特征。数据流因此清清楚楚：

```text
主工程 code/ (ndarray 0.17)              独立工程 (ndarray 0.16 + linfa 0.8)
  HOG 提特征 → Vec<f64>  ──写成 CSV──▶  读 CSV → Array2<f64> → 训练 SVM → 打分
```

独立工程的 `Cargo.toml`（比如放在 `/tmp/linfa_svm_lab`）：

```toml
[dependencies]
ndarray = "0.16"     # 必须与 linfa 内部一致，不能用主工程的 0.17
linfa = "0.8"
linfa-svm = "0.8"
```

训练的关键代码（linfa-svm 0.8.1 实测签名）——二分类时目标类型是 `bool`（`true`=行人 / `false`=背景）：

```rust
use linfa::prelude::*;      // Fit / Predict / confusion_matrix
use linfa::Dataset;
use linfa_svm::Svm;
use ndarray::{Array1, Array2};

// x: Array2<f64> 每行一个样本的特征；y: Array1<bool> 标签
let train = Dataset::new(x_tr, y_tr);
let valid = Dataset::new(x_te, y_te);

let model = Svm::<_, bool>::params()
    .linear_kernel()               // 线性核，最贴近经典 HOG + 线性 SVM
    .pos_neg_weights(1.0, 1.0)     // 正/负类的软间隔惩罚 C（此处等权）
    .fit(&train)?;

let pred = model.predict(&valid);
let cm = pred.confusion_matrix(&valid)?;   // 混淆矩阵
println!("测试集准确率 = {:.3}", cm.accuracy());
```

> ⚠️ **注意**：linfa-svm 里 `.c_eps(...)` 这类方法是给**回归**（目标是浮点数）用的，二分类要用 `.pos_neg_weights(c_pos, c_neg)` 设置软间隔惩罚——用错会报 `bool: linfa::Float` 之类的 trait bound 错误。

为聚焦流程，示例用合成的"类 HOG"特征向量（正样本前半段幅值高、负样本后半段高，叠上噪声制造类间重叠）跑通训练。实测输出：

```text
训练样本 200 个，测试样本 80 个，特征维度 8
混淆矩阵:
classes    | true       | false
true       | 34         | 6
false      | 2          | 38
测试集准确率 = 0.900
```

到此，整条传统检测流水线就闭环了：**主工程滑窗 + HOG 提特征 → CSV → 独立工程用 SVM 学"行人 vs 背景" → 拿模型给每个窗口打分 → NMS 合并**。真实项目里，独立工程读的就是主工程导出的那些 3780 维 HOG 向量（正样本=行人窗口，负样本=大量背景窗口）。

## 常见坑与提示

> 🕳️ **坑**：**步长和尺度，是精度与速度的跷跷板。** 步长越小、金字塔层数越多，越不容易漏检，但窗口数量爆炸——上面一张小图 3 层就扫了 186 个窗口，换成 `1920×1080`、步长 8、十几层金字塔，轻松几十万个窗口，每个还要提一次 3780 维 HOG。这正是滑窗法**慢**的根源。工程上常靠"较大步长 + 图像金字塔 + 及早用简单分类器筛掉明显背景"来提速。

> 🕳️ **坑**：**HOG 特征维度必须训练/推理严丝合缝对齐。** 训练 SVM 时用的 `HogOptions`（cell/block/方向数）产出多少维，推理时每个窗口就必须产出**同样的维度**，否则点积都算不了。把 HOG 参数连同模型一起存档；窗口尺寸也要先 `resize` 到训练时的规格（如 `64×128`），别让 `cell_side` 除不尽（[第 27 章](../p04-features/ch27-handcrafted-features.md) 踩过这个坑）。

> ⚠️ **注意**：**NMS 的 IoU 阈值没有万能值。** 太大（如 0.7）会**欠合并**——同一目标残留多个框；太小（如 0.2）会**过合并**——两个挨得近的目标（并排的两个人）被误当成一个删掉一个。上面实测从 0.5 到 0.2 保留框数从 18 掉到 2，就是这种敏感性的写照。多尺度框大小不一时，往往要偏小一些。

> 🕳️ **坑**：**正负样本严重不均衡。** 一张图里"背景窗口"成千上万，"行人窗口"寥寥几个。若直接拿全部窗口训练，SVM 会偷懒——"全判背景"准确率就 99%（这也是[后面](#本章小结)要强调"别只看准确率"的原因）。实战里要做**难例挖掘（hard negative mining）**：先训一版，把它误报的背景框挑出来当"难负样本"补进训练集再训，循环几轮。

> 💡 **提示**：**这套方法为什么被深度学习取代了？** 三个硬伤：① HOG 是**人手工设计**的特征，抓形状还行，但表达能力有限，遇到姿态、遮挡、光照剧变就吃力；② 滑窗 + 多尺度**计算量巨大**；③ 特征提取和分类器是**两段拼接**、各自优化，不能端到端一起学。深度学习的检测器（YOLO 等）用卷积网络**自动学特征**、一次前向就在全图密集预测，精度和速度全面碾压。但请注意——**滑窗的"多尺度"、输出阶段的"NMS"，原封不动地活在今天的检测器里**。你现在手写的这个 NMS，YOLO 也在用。

## 本章小结

- 传统目标检测把"检测"化归为"到处做分类"：**滑动窗口**解决位置未知，**图像金字塔**解决尺度未知（呼应 [第 21 章](../p03-classic/ch21-pyramids.md)）。
- 每个窗口提 **HOG** 特征（经典 3780 维，见 [第 27 章](../p04-features/ch27-handcrafted-features.md)）送 **线性 SVM** 判"是不是目标"。
- 滑窗必然在一个目标上炸出许多重叠框，用 **IoU + NMS** 按分数贪心去重；IoU 阈值要按场景调，NMS 只去重不去误检。
- linfa 0.8 与主工程 ndarray 版本冲突，SVM 训练要**单开工程**（ndarray 钉 0.16），主工程用 `Vec<f64>` / CSV 中间形式把 HOG 特征传过去——一条清晰的跨工程数据流。
- 这套方法慢、依赖手工特征、非端到端，已被深度学习取代；但**多尺度**与 **NMS** 的思想被现代检测器完整继承（预告第九部分）。

## 动手练习

1. **改 NMS 阈值**：在示例里把金字塔那段的 IoU 阈值扫一遍（0.1、0.2、…、0.7），记录每个阈值下保留的框数，画出"阈值—保留框数"的趋势，体会它有多敏感。
2. **soft-NMS**：把 NMS 改成"软"版本——不直接删除高 IoU 的框，而是**按 IoU 给它降分**（分数乘以 `1 - iou`），最后再用一个分数阈值过滤。对比它和硬 NMS 在两个挨近目标上的表现。
3. **数窗口**：写个函数，输入图像尺寸、窗口尺寸、步长、金字塔层数与缩放比，算出总共要扫多少个窗口。代入 `1920×1080`、`64×128` 窗口、步长 8、缩放 0.8 共 10 层，感受一下这个数字有多吓人。
4. **进阶**：真的动手——在主工程里合成若干"有行人/无行人"的 `64×128` 窗口，各提 HOG 写进一个 CSV，再到独立 linfa 工程里训练线性 SVM，报测试集准确率。你就完整复现了 Dalal-Triggs 的流水线雏形。
