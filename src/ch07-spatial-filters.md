# 第 7 章 · 空间滤波：降噪、模糊与锐化

> **本章导读**：从这一章起我们进入"传统图像处理"。现实里拍到的图永远不干净——传感器有噪点、光线不均、镜头有灰。**空间滤波**就是图像世界的"洗洁精"和"放大镜"：用一个滑动的小窗口，把每个像素换成"周围邻居商量出来的更合理的值"。读完本章你会：彻底看懂**卷积**就是"加权求和"、能亲手算一次卷积、会用均值/高斯/中值/双边四种降噪法、会用 unsharp mask 把图变清晰、知道边缘处窗口探出去了该怎么补，并且能**自己手写一个 3×3 卷积函数**看清底层。至于边缘检测、形态学、轮廓，那是第 8 章的活；缩放旋转是第 9 章；喂给模型的预处理链在第 10 章。

## 7.1 空间滤波是什么

第 3 章我们做过"每个像素各干各的"操作：亮度 +50、反色、二值化——改一个像素只看它自己。这类叫**点运算（point operation）**。

但"降噪""模糊""锐化"这类需求，光看自己是做不到的。想一想给照片**磨皮**：皮肤上冒出一个特别亮的噪点，凭什么说它是噪点？因为它和**周围一圈皮肤**都不一样。要把它抹掉，就得参考周围邻居的状态。

> **空间滤波（spatial filtering）** = 根据一个像素**周围邻居**的值，重新计算这个像素。它属于**邻域运算（neighborhood operation）**。

"空间"两个字是相对"频域"说的：我们直接在像素排布的空间上动手，而不是先做傅里叶变换。本章全是空间滤波。它是后面几乎所有传统算法的地基——第 8 章的边缘检测，第一步就是先用高斯滤波降噪。

## 7.2 卷积：滑动的小图章

几乎所有空间滤波，底层都是同一个动作：**卷积（convolution）**。

先建立画面感。想象你有一个**小图章**（比如 3×3 那么大），图章上刻了 9 个数字（权重）。你把图章按在图像左上角，图章盖住的 9 个像素，各自乘上图章对应格子的数字，再全部加起来，得到一个结果，写进**中心那个像素**的输出。然后图章向右挪一格，再盖、再算、再写……盖满一行就换下一行，从左到右、从上到下，直到走遍整张图。

```text
    卷积核 K 在图像上滑动（★ 是当前落点的中心）

    图像                          每一步做的事：
    ┌─┬─┬─┬─┬─┐
    │ │ │ │ │ │                盖住的 9 个像素
    ├─┼─┼─┼─┼─┤                  ×
    │ │▓│▓│▓│ │   ← 图章在这     核里对应的 9 个权重
    ├─┼─┼─┼─┼─┤                  ↓
    │ │▓│★│▓│ │                加起来
    ├─┼─┼─┼─┼─┤                  ↓
    │ │▓│▓│▓│ │                写进 ★ 的输出像素
    └─┴─┴─┴─┴─┘
```

那个刻了数字的小图章，正式名字叫**卷积核（kernel）**，也叫**滤波核**。它通常是个 3×3、5×5 的小方阵（边长一般取奇数，这样才有明确的"中心"）。

一句话记住：**卷积 = 一个小窗口滑过全图，每到一处就把窗口盖住的像素按权重"加权求和"。** 换个更亲切的说法，它就是一种**加权平均**——邻居们投票决定中心像素的新值，图章上的数字就是每个邻居的"票数"。

> 顺便剧透一句：深度学习里**卷积神经网络（CNN）**名字里的"卷积"，就是这个卷积。区别只在于：本章的核是我们人手工设计的（比如均值、高斯），而 CNN 的核是模型从数据里"学"出来的（第 11 章会讲）。理解了本章，你就理解了 CNN 的一半。

## 7.3 手算一次卷积

光说不练看不透。我们拿最简单的**均值核**（9 个格子都是 1/9）手算一遍。取图像里某个 3×3 的小块：

```text
   图像块 I                     卷积核 K（均值核）
   10  20  30                  1/9  1/9  1/9
   40  50  60         *        1/9  1/9  1/9
   70  80  90                  1/9  1/9  1/9
                     （* 在这里表示"对应相乘再求和"，不是普通矩阵乘法）
```

中心像素当前是 50。卷积就是把对齐的格子相乘、再全部加起来：

```text
输出 = 10·(1/9) + 20·(1/9) + 30·(1/9)
     + 40·(1/9) + 50·(1/9) + 60·(1/9)
     + 70·(1/9) + 80·(1/9) + 90·(1/9)
     = (10+20+30+40+50+60+70+80+90) · (1/9)
     = 450 · (1/9)
     = 50
```

中心从 50 变成 50——没变。因为这块像素是平滑过渡的，"周围的平均"正好等于自己。这说明：**在平坦区域，均值滤波几乎不动图。**

现在把中心换成一个突然冒出来的亮点 200（模拟一颗噪点），其它不变：

```text
   10  20  30
   40 200  60      *  均值核  =  (10+20+30+40+200+60+70+80+90) · (1/9)
   70  80  90                  =  600 / 9  ≈  67
```

200 被拉回到 67——**噪点被邻居们"平摊"掉了**。这就是降噪的本质。当然代价也看得见：为了压噪点，周围一圈本来正常的像素也被搅进来平均了一下，图会变糊。**所有降噪滤波器都在"杀噪声"和"保细节"之间走钢丝**，不同的核就是不同的走法。

看懂这一步，本章后面就通了：**设计一个滤波器，本质就是设计核里那几个数字。**

## 7.4 边界处理：窗口探出去了怎么办

上面我们取的是图像**内部**的小块，3×3 窗口稳稳落在图里。可当中心像素在**最外圈**（第一行、第一列……）时，窗口会探出图像外——那外面的像素根本不存在，乘什么？

工程上有三种常见的补法，术语叫 **padding（填充）**。拿一行像素 `[a b c d e]` 举例，看看左右两边探出去的格子怎么补：

```text
补零   (zero)：       0 0 | a b c d e | 0 0        越界处一律当 0
复制   (replicate)：  a a | a b c d e | e e        越界处复制最近的边缘像素
镜像   (reflect)：    b a | a b c d e | e d        以边缘为镜子，把里面的像素反射出去
```

| 方式 | 越界像素取什么 | OpenCV 里的名字 | 特点 |
| --- | --- | --- | --- |
| 补零 zero | 一律取 0（黑） | `BORDER_CONSTANT` | 最简单，但边缘会发暗，甚至凭空造出一条假边 |
| 复制 replicate | 最近的边缘像素 | `BORDER_REPLICATE` | 最常用，视觉自然，不引入新灰度 |
| 镜像 reflect | 以边缘为轴反射 | `BORDER_REFLECT` | 边缘过渡最平滑，高斯模糊常用 |

新手最容易忽略边界，随手一个"跳过最外圈不处理"，结果图像四周留了一圈没滤波的毛边，或者用补零把边缘搞黑了还纳闷。**记住：边界必须处理，且处理方式会影响结果。** 下一节我们手写卷积函数时，就把这三种模式都实现出来。

## 7.5 手写一个 3×3 卷积函数

现在把 7.2~7.4 的道理落成一段能跑的代码。为了看清底层，我们**不依赖任何图像库**，直接对一个"行优先排列的灰度数组 `&[f32]`"做卷积，把边界处理也一并做对。

```rust
/// 边界填充方式：滑窗探出图像外时，用什么值补上（对应 7.4 的三种）
#[derive(Clone, Copy)]
enum Padding {
    Zero,      // 补 0（黑）
    Replicate, // 复制最近的边缘像素
    Reflect,   // 以边缘为镜面反射
}

/// 通用 3×3 卷积：对灰度图（行优先的 f32 数组）做"加权求和"。
/// - `src`   ：长度必须是 w*h 的灰度像素（一般取 0.0~255.0，但内部按 f32 算，不夹取）
/// - `w`,`h` ：图像宽、高
/// - `kernel`：3×3 卷积核，行优先排列 [左上,上,右上, 左,中,右, 左下,下,右下]
/// - `pad`   ：边界处理方式
/// 返回和输入等长的新数组（同样是行优先的 f32）
fn convolve3x3(src: &[f32], w: usize, h: usize, kernel: &[f32; 9], pad: Padding) -> Vec<f32> {
    assert_eq!(src.len(), w * h, "像素数必须等于 w*h");
    let mut out = vec![0.0f32; w * h];

    // 闭包 sample：把"想访问的坐标 (x,y)"按边界规则夹回图像内，返回那个像素值
    let sample = |x: i64, y: i64| -> f32 {
        let (mut sx, mut sy) = (x, y);
        match pad {
            Padding::Zero => {
                // 只要探出去，直接返回 0
                if sx < 0 || sy < 0 || sx >= w as i64 || sy >= h as i64 {
                    return 0.0;
                }
            }
            Padding::Replicate => {
                // 夹到最近的合法坐标（-1→0，w→w-1）
                sx = sx.clamp(0, w as i64 - 1);
                sy = sy.clamp(0, h as i64 - 1);
            }
            Padding::Reflect => {
                // 以边缘为镜：-1→0, -2→1；w→w-1, w+1→w-2
                if sx < 0 { sx = -sx - 1; }
                if sx >= w as i64 { sx = 2 * w as i64 - sx - 1; }
                if sy < 0 { sy = -sy - 1; }
                if sy >= h as i64 { sy = 2 * h as i64 - sy - 1; }
            }
        }
        src[sy as usize * w + sx as usize]
    };

    // 遍历每个输出像素（连最外圈也算，靠 sample 兜住越界）
    for y in 0..h as i64 {
        for x in 0..w as i64 {
            let mut sum = 0.0f32;
            let mut ki = 0;
            // 扫过中心像素周围的 3×3 邻域
            for dy in -1..=1 {
                for dx in -1..=1 {
                    sum += sample(x + dx, y + dy) * kernel[ki];
                    ki += 1;
                }
            }
            out[y as usize * w + x as usize] = sum;
        }
    }
    out
}
```

配两个和 `image` crate 打通的小工具，把灰度图和 `Vec<f32>` 互相转换（`GrayImage` 内部就是行优先的 `Vec<u8>`，正好对得上）：

```rust
use image::{GrayImage, Luma};

/// 灰度图 → f32 数组（顺带返回宽高）
fn gray_to_f32(img: &GrayImage) -> (Vec<f32>, usize, usize) {
    let (w, h) = img.dimensions();
    let data = img.as_raw().iter().map(|&p| p as f32).collect();
    (data, w as usize, h as usize)
}

/// f32 数组 → 灰度图（写回时夹到合法的 0~255，再四舍五入成 u8）
fn f32_to_gray(data: &[f32], w: usize, h: usize) -> GrayImage {
    let mut img = GrayImage::new(w as u32, h as u32);
    for (i, p) in img.pixels_mut().enumerate() {
        *p = Luma([data[i].round().clamp(0.0, 255.0) as u8]);
    }
    img
}
```

有了这台"卷积引擎"，接下来的滤波器**只是换核里的数字**而已。

## 7.6 均值滤波（box blur）

**均值滤波（mean filter / box blur，方框模糊）**就是 7.3 手算的那个核——9 个格子全是 `1/9`：

```text
 1/9  1/9  1/9
 1/9  1/9  1/9        每个邻居票数相同，结果 = 邻域的算术平均
 1/9  1/9  1/9
```

> 为什么是 1/9 而不是 1？因为要让**核里所有数字加起来等于 1**。这样滤波前后图像**整体亮度不变**（否则会整体变亮或变暗）。任何"模糊类"的核都遵守这条：权重之和为 1。

用我们的引擎跑一次均值滤波：

```rust
let (buf, w, h) = gray_to_f32(&gray);            // gray 是一张 GrayImage
let box_kernel = [1.0 / 9.0; 9];                 // 均值核
let blurred = convolve3x3(&buf, w, h, &box_kernel, Padding::Replicate);
f32_to_gray(&blurred, w, h).save("box_blur.png")?;
```

均值滤波的优点是**快、简单**，能压掉轻微的随机噪声。缺点也很直接：**所有邻居一视同仁**，包括那些本该保留的边缘像素——边缘正是"和邻居不一样"的地方，而均值最讨厌与众不同，一平均就把边糊掉了。所以均值滤波适合快速预览，不适合"既要降噪又要保住边"的正经场合。

## 7.7 高斯滤波（Gaussian blur）

均值核的毛病在于"正对着中心的邻居"和"斜对角的邻居"权重一样大——这不合直觉：离得越近的像素，显然越该说得上话。**高斯滤波（Gaussian blur）**修正了这一点：核里的权重按一座"小山"（钟形曲线）分布，**中间大、四周小、越远越小**。

一个常用的 3×3 高斯核长这样：

```text
 1  2  1
 2  4  2      ÷ 16      （16 = 1+2+1+2+4+2+1+2+1，除一下让权重和为 1）
 1  2  1
```

中心权重 4 最大，上下左右 2 次之，四个角落 1 最小。同样拿 7.3 的平滑块 `[10 20 30 / 40 50 60 / 70 80 90]` 手算：

```text
输出 = (10·1 + 20·2 + 30·1 + 40·2 + 50·4 + 60·2 + 70·1 + 80·2 + 90·1) / 16
     = (10 + 40 + 30 + 80 + 200 + 120 + 70 + 160 + 90) / 16
     = 800 / 16 = 50
```

平滑区依然是 50，但权重分配更"偏心"中央，所以模糊出来的过渡**比均值更自然**，不会有均值那种生硬的方块感（这也是"box blur"名字的由来——均值模糊会留下方形痕迹）。

控制高斯核胖瘦的参数叫 **σ（sigma，西格玛）**：

- **σ 越大**，这座"山"越矮越胖，远处邻居也能分到不小的权重 → **模糊越强**；
- **σ 越小**，山越尖，权重几乎全压在中心 → 几乎不模糊。

工程上通常不手填核里的数字，而是给一个 σ，让库去生成核。`imageproc` 直接提供了高斯模糊（内部按 f32 计算，精度好）：

```rust
use imageproc::filter::gaussian_blur_f32;

let gray = image::open("test.jpg")?.to_luma8();
let g = gaussian_blur_f32(&gray, 1.5);   // σ = 1.5，值越大越糊
g.save("gaussian.png")?;
```

高斯模糊是几乎所有视觉流水线的"开胃菜"：噪声是杂乱的高频信号，高斯这种"低通"正好把它压下去，同时又比均值温柔。第 8 章讲边缘检测时，第一步就是它。

## 7.8 中值滤波（median filter）

有一种噪声，均值和高斯都拿它没办法——**椒盐噪声（salt-and-pepper noise）**：图上随机撒的一撮**纯黑（0）和纯白（255）**的点，像撒了盐和胡椒，常见于老照片的霉斑、传感器坏点、信号传输误码。

为什么均值/高斯搞不定它？因为 255 这种极端值一旦参与"加权平均"，反而会把周围本来正常的像素一起**污染**成灰蒙蒙的一片。**中值滤波（median filter）**换了个思路，釜底抽薪：把窗口里的像素**排个序，取中间那个（中位数）**，直接扔掉平均。

```text
邻域 9 个像素排序后：[3, 5, 7, 8, 9, 9, 10, 12, 255]
                                    ↑
                              中位数 = 9         ← 那个 255 排在队尾，压根没被选中
```

极端的黑点白点总是排在队首队尾，取中位数时自动被"投票出局"，一点都影响不到结果。而且中值滤波是**非线性**的（没有一个固定的核矩阵能表示"排序取中"这个动作），它还天生**保边缘**：一条边两侧各自的中位数还是各归各，边不会被抹平。所以它是"去孤立噪点又不想糊图"的首选。代价是排序比乘加慢一些。

`imageproc` 提供了中值滤波，参数是 x、y 两个方向的**半径**，窗口大小是 `(2·x_radius+1) × (2·y_radius+1)`：

```rust
use imageproc::filter::median_filter;

let gray = image::open("salt_pepper.jpg")?.to_luma8();
let m = median_filter(&gray, 1, 1);   // 半径都取 1 → 3×3 窗口
m.save("median.png")?;
```

一句话对比：**高斯专治"细密的沙沙噪声"，中值专治"一撮黑白点"，且中值比高斯更保边。**

## 7.9 双边滤波（bilateral）

高斯滤波只看一个维度——**空间距离**：离中心越近，权重越大。可这样一来，隔着一条边缘的像素只要"离得近"也会被拉进来平均，于是边的两侧互相污染，脸被磨平了、眼睛也糊了。

**双边滤波（bilateral filter）**多加了一个维度：**颜色（亮度）差异**。它给每个邻居的权重是**两个高斯相乘**：

$$w = \underbrace{G_{\sigma_s}(\text{空间距离})}_{\text{离得近才有话语权}} \times \underbrace{G_{\sigma_r}(\text{颜色差})}_{\text{长得像才有话语权}}$$

平坦区域里邻居颜色都差不多，颜色项接近 1，退化成普通高斯，正常平滑；可一旦跨过边缘，两侧亮度差很大，颜色项被压到接近 0，那些"长得不像"的邻居几乎一票都投不出去——**边缘就被保护下来了**。

效果就是传说中的"**保边降噪**"：磨皮但不磨五官，皮肤变光滑而眼睛眉毛依旧锐利，这正是美颜相机的核心套路；工业上也常用它在保住轮廓的前提下抹平光照不均。代价是计算量大（每个像素都要现算颜色权重），比高斯慢不少。本章知道它"能保边降噪、比高斯贵"即可，工程上一般直接调现成实现（如 OpenCV 的 `bilateralFilter`）。

四种降噪法横向对比：

| 滤波器 | 线性？ | 保边缘 | 主治什么噪声 | 速度 | 典型场景 |
| --- | --- | --- | --- | --- | --- |
| 均值 box | 是 | 差 | 轻微随机噪声 | 快 | 快速预览 |
| 高斯 Gaussian | 是 | 中 | 细密的高斯噪声 | 快 | 通用平滑、边缘检测前置 |
| 中值 median | 否 | 好 | **椒盐噪声**、坏点 | 中 | 扫描件去斑、去孤立噪点 |
| 双边 bilateral | 否 | **最好** | 保边前提下的平滑 | 慢 | 美颜、光照均化 |

## 7.10 锐化（sharpen / unsharp mask）

前面都在"抹平"，锐化反过来——让**边缘更清楚**，看着更"精神"。它的思路很巧妙，行话叫 **unsharp mask（USM，非锐化掩模）**，名字很反直觉：**先把图模糊一下，反而能让它变清晰。**

拆开看：

1. 原图先模糊一份，得到"模糊图"。模糊图丢掉的正是**高频细节**（边缘、纹理）。
2. **原图 − 模糊图** = 被丢掉的那层细节（边缘处差得多，平坦处差不多为 0）。
3. 把这层细节**加倍还给原图**，边缘就被强调出来了：

$$\text{锐化图} = \text{原图} + \text{amount} \times (\text{原图} - \text{模糊图})$$

`amount` 是锐化强度。用 `imageproc` 的高斯模糊就能实现一版 USM：

```rust
use imageproc::filter::gaussian_blur_f32;
use image::{GrayImage, Luma};

/// USM 锐化：out = clamp( 原图 + amount·(原图 − 模糊图) )
fn unsharp_mask(gray: &GrayImage, sigma: f32, amount: f32) -> GrayImage {
    let blurred = gaussian_blur_f32(gray, sigma);       // 先模糊
    let (w, h) = gray.dimensions();
    let mut out = GrayImage::new(w, h);
    for y in 0..h {
        for x in 0..w {
            let o = gray.get_pixel(x, y)[0] as f32;      // 原图像素
            let b = blurred.get_pixel(x, y)[0] as f32;   // 模糊图像素
            let v = o + amount * (o - b);                // 把细节层加回去
            out.put_pixel(x, y, Luma([v.round().clamp(0.0, 255.0) as u8]));
        }
    }
    out
}
```

如果不想模糊两次，还有一个等价的"**一步到位**"锐化核，可以直接喂给 7.5 的 `convolve3x3`：

```text
 0  -1   0
-1   5  -1        中心 5、上下左右各 −1，权重和 = 5 − 4 = 1（亮度不变）
 0  -1   0
```

直觉：中心那个 5，可以拆成 `1（原图本身） + 4`，多出来的 `4·中心 − 4·邻居` 正是"中心比邻居突出多少"。平坦区邻居和中心一样，这一项为 0，不变；边缘处中心和邻居差得多，这一项就把差异放大，边缘随之凸显。

```rust
let (buf, w, h) = gray_to_f32(&gray);
let sharpen = [0.0, -1.0, 0.0, -1.0, 5.0, -1.0, 0.0, -1.0, 0.0];
let s = convolve3x3(&buf, w, h, &sharpen, Padding::Replicate);
f32_to_gray(&s, w, h).save("sharpen.png")?;
```

**坑提醒**：锐化本质是"高通"——它放大差异，也**连带放大噪声**。所以顺序通常是**先降噪、再锐化**；`amount` 也别开太大，否则边缘旁会出现一圈难看的白边（振铃 / halo）。

## 7.11 工程落地：降噪好用，但别糊掉小目标

降噪在真实项目里最常见的身份是**预处理的一环**：二值化之前、边缘检测之前（第 8 章）、模板匹配之前，先来一发轻度平滑，能少踩很多"噪点被当成目标"的坑。

但有一条铁律要刻在心里：**过度模糊会连小目标一起抹掉。**

设想我们主线的目标检测任务（YOLOv8，输入 `1×3×640×640`，详见第 10 章）。一张 1920×1080 的原图里，远处的一个小人可能只有二三十个像素高；letterbox 缩到 640 之后更小，也许就剩十几个像素。这时候你要是再来一记大 σ 的高斯，这个小目标就直接被糊成一坨看不出形状的灰斑——**模型还没看，你先把它抹没了。** 检测里"漏检小目标"，一部分锅就出在这种想当然的重度预处理上。

几条工程经验：

- **能不糊就不糊，要糊也用最小的力度。** 先明确"我到底在去什么噪声"，再挑对应的滤波器（椒盐用中值、细噪用小 σ 高斯），而不是无脑上一个大核。
- **深度学习检测/分类模型，一般不做重度降噪。** 模型是在带自然噪声的图上训练的，你把图洗得太干净，反而和训练分布对不上。传统算法流水线（阈值、边缘、模板匹配）才更依赖前置降噪。
- **降噪是"权衡"不是"越多越好"。** 每加一步平滑，都要问一句："我压掉的噪声，值不值得搭上这些细节？"

记住这句总纲：**滤波器是工具箱，不是万金油；先想清楚要解决什么问题，再决定用不用、用多重。**

## 7.12 小结

- **空间滤波 = 邻域运算**：拿一个滑动的小窗口（卷积核），把每个像素换成"邻居们加权求和"的结果；**卷积就是加权平均**。
- **设计滤波器 = 设计核里那几个数字**。模糊类的核，权重之和恒为 1（保住整体亮度）。
- 降噪四件套：**均值**（快但糊边）、**高斯**（默认平滑，σ 越大越糊）、**中值**（非线性，专治椒盐噪声且保边）、**双边**（同时看空间与颜色，保边降噪之王，但慢）。
- **锐化**走 unsharp mask 思路：`原图 + amount·(原图 − 模糊图)`，等价于一个中心为正、四周为负的锐化核；会放大噪声，先降噪再锐化。
- **边界必须处理**：补零、复制边缘、镜像三种 padding，选择会影响边缘结果。
- 降噪是常见预处理，但**过度模糊会抹掉小目标**——工程上要权衡，深度模型一般不重度降噪。
