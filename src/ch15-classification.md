# 第 15 章 · 分类模型：Softmax、Top-K 与多标签

> **本章导读**：从第 11 到第 14 章，我们已经把一个模型"跑起来"的整条链路走通了——认识神经网络（第 11 章）、查清输入输出（第 12 章）、转换格式（第 13 章）、用 Rust 执行推理（第 14 章）。从本章起进入"模型家族"部分，我们**逐个拆解各类模型的输出到底怎么读**。第一站是最简单、最基础的**分类模型**：输入一张图，输出"它最像哪个类别"。别小看它——把分类输出里的 **logits、Softmax、Top-K、多标签**搞懂，你就掌握了读懂一切模型输出的地基，连主线检测器每个候选框内部，其实都藏着一个"分类"子问题。本章还会反复敲一个大坑：**分类模型的预处理（ImageNet 均值方差）和主线检测器的 `/255` 不一样，搞混必翻车。**

**学习目标：**

- 说清分类模型"吃什么、吐什么"：`1×3×224×224` 进，`1×1000` 的 **logits** 出

- 会取 **Top-1 / Top-K**，用 Rust 实现 argmax 和 top-k
- 分清 **Softmax（互斥单标签）** 和 **Sigmoid（独立多标签）**，知道多标签分类该怎么做
- 记牢分类预处理的**均值方差归一化**坑，以及"类别顺序不能错"这条命脉

## 15.1 分类模型在干什么

想象你教一个小孩认卡片：举起一张卡片问"这是什么呀？"，小孩瞅一眼，答"猫！"。你再举一张，他答"狗！"。**分类模型（classification model）就是这个"举一张图、报一个名字"的小孩。**

它做的事情简单到只有一句话：**输入一张图，输出"它整体上最像哪个类别"。**

```text
分类：一张图  →  "这是猫"                  （只说 是什么）
检测：一张图  →  "左上角一只猫、右边一条狗"  （说 是什么 + 在哪，第 16 章）
```

对比一下就清楚了：分类模型**不告诉你物体在图里的哪个角落**，也不管图里有几个东西，它只对"整张图"给一个判断——最像哪一类。所以它是最基础的一类模型：没有框坐标、没有掩码、没有关键点，输出就是一串"像不像各个类别"的分数。**正因为输出最干净，它是我们理解一切模型输出的最佳起点。**（这也正是第 12 章末尾练习留的钩子：分类输出为什么比 YOLOv8 的 `[1,84,8400]` 好懂得多。）

分类模型在真实项目里到处都是：相册"这张是风景还是人像"、工业质检"这个零件合格还是有划痕"、审核"这张图是否含违规内容"。它常常也是更大系统里的一个零件——比如检测出一个框之后，再单独拿一个分类模型判断"这个人有没有戴安全帽"。

## 15.2 输入输出规格：224 与 1000

按第 12 章教的规矩，接手任何模型第一步都是查清输入输出。以最经典的 ImageNet 分类模型（ResNet、MobileNet 这类）为例：

```text
输入张量 "input"（分类模型常见规格）
   shape = [1, 3, 224, 224]   ← 注意：H/W 是 224，不是主线检测器的 640！
   dtype = float32
   布局  = NCHW（RGB、planar：先整个 R 通道，再 G，再 B）
   归一化 = 先 /255，再逐通道减均值除标准差（ImageNet）  ← ★ 和检测器不同，见 15.7
```

```text
输出张量 "output"
   shape = [1, 1000]          ← 1000 = ImageNet 的类别数
   dtype = float32
   内容  = 1000 个 logits（未归一化分数，可正可负、加起来 ≠ 1）
```

两处要专门敲黑板：

**① 输入是 224，不是 640。** 主线检测器输入是 `1×3×640×640`（第 1 章约定），而分类模型常见是 `1×3×224×224`。**输入尺寸不是全世界统一的，每个模型自己说了算**：分类网络历史上多用 224（ResNet、VGG、MobileNet 都是），Inception 用 299，检测器为了看清小目标和位置才用更大的 640。结论很简单——**别凭记忆填尺寸，按第 12 章查出来的 shape 准备数据。**

**② 输出是 `[1, 1000]`，内容是 logits，不是概率。** 这一维 `1000` 就是类别数（ImageNet 定义了 1000 类）。里面的 1000 个数字叫 **logits（未归一化的原始分数）**：它们可正可负、没有上下界、加起来也不等于 1。你不能直接说"第 285 个数是 7.2，所以有 7.2 的概率是埃及猫"——这既讲不通（概率哪有 7.2 的），也没法在类别之间比较。要变成人能读的概率，得过一道 **Softmax**（下一节）。

> 顺带一提：`[1, 1000]` 里的 `1` 还是 batch 维（一次一张图）。有的分类模型输出会带上无意义的空间维，长成 `[1, 1000, 1, 1]`，`reshape` 或 `squeeze` 一下当成 `[1, 1000]` 用即可。

## 15.3 Softmax：把 logits 变成概率

**为什么原始 logits 不能直接当概率？** 打个比方：logits 就像一场考试的"原始加权得分"，可能是 `-3`、`7`、`0.5`。你没法指着 `7` 说"我有 7 的概率考对这题"——概率得在 `0~1` 之间、而且（对"只能是一个类"的单标签任务）所有类加起来应该是 `1`（100%）。logits 三条都不满足：

- 可以是**负数**（概率不能负）；
- 没有**上界**（概率最大是 1）；
- 一组 logits **加起来不等于 1**（互斥单标签的概率总和应是 100%）。

所以要一个函数，把任意一组实数"挤"成一组"非负、且加起来正好等于 1"的数——这就是 **Softmax**。它的思路是：先用指数 $e^x$ 把每个数变成正数（并且拉大差距，大的更大），再除以总和做归一化，让它们凑成 100%。就像把全班同学的原始分先各自取指数、再换算成"占全班的百分比"。

公式（数学补漏见附录 A.6）：

$$\text{softmax}(x_i) = \frac{e^{x_i}}{\sum_{j} e^{x_j}}$$

**手算一遍**（本章统一用这组小数字 `logits = [2.0, 1.0, 0.1]`，假设只有 3 类）：

```text
第一步：每个数取指数 e^x
   e^2.0 ≈ 7.389
   e^1.0 ≈ 2.718
   e^0.1 ≈ 1.105

第二步：求总和
   7.389 + 2.718 + 1.105 = 11.213

第三步：各自除以总和 → 概率
   7.389 / 11.213 ≈ 0.659   ← 第 0 类
   2.718 / 11.213 ≈ 0.242   ← 第 1 类
   1.105 / 11.213 ≈ 0.099   ← 第 2 类
   ─────────────────────────
   加起来 = 1.000  ✓
```

结果 `[0.659, 0.242, 0.099]`：最大的 logit（`2.0`）拿到最大概率（约 66%），而且**优势被指数放大**了——原本 `2.0` 只比 `1.0` 高一点，概率却拉开到 66% vs 24%。这正是 Softmax 的特点：赢家通吃的倾向更强。

**数值稳定版（工程必须这么写）。** 上面的算法有个隐患：如果 logits 里有个 `100`，`e^100` 会大到 `float` 装不下（溢出成 `inf`），整个结果就烂了。标准解法是**先减去这组数里的最大值再算**——数学上可以证明结果完全不变：

$$\text{softmax}(x_i) = \frac{e^{x_i - m}}{\sum_j e^{x_j - m}}, \qquad m = \max_j x_j$$

还用 `[2.0, 1.0, 0.1]` 验证一遍，最大值 `m = 2.0`，先平移成 `[0.0, -1.0, -1.9]`：

```text
   e^0.0  = 1.000
   e^-1.0 ≈ 0.368
   e^-1.9 ≈ 0.150
   总和 = 1.518
   概率 = [1.000/1.518, 0.368/1.518, 0.150/1.518] ≈ [0.659, 0.242, 0.099]
```

和上面**一模一样**，但过程里再也不会出现 `e^100` 这种大数——最大的指数项永远是 `e^0 = 1`。用 Rust 实现就照这个稳定版来：

```rust
/// 数值稳定版 Softmax：把一组 logits 变成加起来为 1 的概率
fn softmax(logits: &[f32]) -> Vec<f32> {
    // ① 找最大值，用来平移，防止 exp 溢出
    let max = logits.iter().cloned().fold(f32::NEG_INFINITY, f32::max);
    // ② 每个数先减最大值再取 exp（最大的那项变成 e^0 = 1）
    let exps: Vec<f32> = logits.iter().map(|&x| (x - max).exp()).collect();
    // ③ 求和，逐个归一化
    let sum: f32 = exps.iter().sum();
    exps.iter().map(|&e| e / sum).collect()
}
```

> **要不要自己做 Softmax？** 看模型。多数分类模型的输出就是 logits，需要你自己过 Softmax；但有的模型在导出时把 Softmax "焊"进了计算图（Netron 里能看到输出前有个 `Softmax` 节点，第 12 章），那输出就已经是概率，你再做一次就错了。**先查清楚，别重复激活。**

## 15.4 Top-1 与 Top-K

有了 1000 个概率，怎么给出答案？两种常见取法：

- **Top-1**：取概率最大的那一个类别，就是模型"最笃定"的答案。取最大值的下标这个操作叫 **argmax**。
- **Top-K**：取概率最高的前 K 个（最常见是 **Top-5**），按分数从高到低列出来。

**为什么要 Top-5？** ImageNet 里有大量细分类（好几种猫、几十种狗），一张图里也常有不止一个东西。要求模型"第一个答案就完全命中"太苛刻，"正确答案排进前 5"是更宽容也更实用的评价——**Top-5 准确率**因此成了经典指标。工程上给用户看结果时，也常列 Top-3/Top-5 供参考（"最像埃及猫，其次虎斑猫"）。

Rust 实现。先是 argmax（Top-1）：

```rust
/// 返回最大值所在的下标（Top-1 类别号）
fn argmax(scores: &[f32]) -> usize {
    scores
        .iter()
        .enumerate()
        // total_cmp 能正确比较 f32（含 NaN），别用 partial_cmp().unwrap()
        .max_by(|(_, a), (_, b)| a.total_cmp(b))
        .map(|(i, _)| i)
        .unwrap_or(0)
}
```

再是 Top-K：

```rust
/// 取分数最高的 k 个，返回 (类别号, 分数)，按分数从高到低排列
fn top_k(scores: &[f32], k: usize) -> Vec<(usize, f32)> {
    // 把 (下标, 分数) 配成对
    let mut indexed: Vec<(usize, f32)> =
        scores.iter().cloned().enumerate().collect();
    // 按分数降序排（b 比 a，得到从大到小）
    indexed.sort_unstable_by(|a, b| b.1.total_cmp(&a.1));
    indexed.truncate(k.min(indexed.len())); // 只留前 k 个（k 过大也不越界）
    indexed
}
```

注意两个细节：比较 `f32` 一律用 **`total_cmp`**，别用 `partial_cmp().unwrap()`——万一分数里混进 `NaN`，`unwrap` 会直接 panic。另外，对 1000 个数做整排是够快的；**工程上通常会**在类别成千上万时改用 `select_nth_unstable`（只把前 k 个选出来、不全排），省掉不必要的排序开销。

把本章的零件串起来，一个分类模型的后处理就成型了（假设推理已拿到 `logits: &[f32]`，共 1000 个，怎么拿到见第 14 章）：

```rust
let probs = softmax(logits);          // logits → 概率
for (id, p) in top_k(&probs, 5) {     // 取 Top-5
    println!("{:>5.1}%  类别 {}", p * 100.0, id);
}
```

但打印出"类别 285"没人看得懂——还差一步：把类别号翻译成名字。

## 15.5 标签映射：从类别号到类别名

模型永远只吐**类别号**（0、1、2……），因为它内部只认数字。要变成"埃及猫""柯基犬"这种人话，得靠一个**标签文件（labels file）**做 `id → 名字` 的映射。

最常见的形式就是一个纯文本文件，**每行一个类别名，行号（从 0 数）就是类别号**：

```text
imagenet_classes.txt
─────────────────────
tench                 ← 第 0 类
goldfish              ← 第 1 类
great white shark     ← 第 2 类
...
（共 1000 行）
```

用 Rust 读进来就是一个 `Vec<String>`，下标即类别号：

```rust
use std::fs;

/// 从 labels.txt 加载类别表：每行一个名字，行号 = 类别号
fn load_labels(path: &str) -> std::io::Result<Vec<String>> {
    let text = fs::read_to_string(path)?;
    Ok(text.lines().map(|s| s.trim().to_string()).collect())
}
```

配上 15.4 的结果就能打印人话了（数值为示意）：

```rust
let labels = load_labels("imagenet_classes.txt")?; // 1000 行
for (id, p) in top_k(&probs, 5) {
    println!("{:>5.1}%  {}", p * 100.0, labels[id]); // 用类别号去查名字
}
```

```text
 65.9%  Egyptian cat
 24.2%  tabby cat
  9.9%  lynx
  ...
```

**坑就在这里：标签文件必须和模型训练时的类别顺序严丝合缝。** 同样是"ImageNet 1000 类"，不同来源的 labels 文件排序可能不同（有的按 WordNet ID 排、有的按别的顺序）；哪怕错位一行，你的"猫"就会被读成"狗"。有的模型把类别名存在了 ONNX 的 `metadata_props`（比如 YOLO 的 `names` 字段，第 12 章）里，**优先用模型自带的这份**，最不容易错。记住：**分数对不对看预处理，名字对不对看标签表。**

## 15.6 多标签分类：Softmax 还是 Sigmoid

前面都假设"一张图只属于一个类"——猫就是猫，不会同时是狗。这叫**单标签分类**，用 Softmax 正合适：它天生让所有类概率**加起来为 1**，即"这些类互相竞争、此消彼长"。

但很多场景不是这样。一张海边度假照，可以**同时**属于"户外""沙滩""人""晴天"好几个标签——它们**并不互斥**。这叫**多标签分类（multi-label classification）**。这时候再用 Softmax 就错了：Softmax 强行让总和为 1，"户外"分高了就会**压低**"沙滩"，可现实里这两个本该都高。

正确做法是**放弃 Softmax，改成逐类独立地过 Sigmoid，再各自和一个阈值比**。**Sigmoid**（附录 A.5）把**单个** logit 压进 `(0, 1)`，`σ(0)=0.5`，越大越接近 1：

$$\sigma(x) = \frac{1}{1 + e^{-x}}$$

每个类各算各的 Sigmoid，互不影响，超过阈值（比如 0.5）就判定为"命中"。一张图因此可以命中 0 个、1 个或多个标签。

Softmax 和 Sigmoid 的区别是本章的核心分水岭，用表格钉死：

| | **Softmax**（单标签 / 互斥） | **Sigmoid**（多标签 / 独立） |
| --- | --- | --- |
| 适用 | 一张图**只属于一个**类（猫 or 狗 or …） | 一张图**可同时属于多个**类（户外+沙滩+人） |
| 怎么算 | K 个 logit **一起**算，彼此竞争 | 每个 logit **单独**算，互不影响 |
| 输出性质 | K 个概率**加起来 = 1** | 每个概率各自在 0~1，**总和不定** |
| 怎么定结果 | 取最大（Top-1）或前 k（Top-K） | 每类和**阈值**比，过线就算命中 |
| 抬高某类的分 | 会**压低**其他类 | **不影响**其他类 |
| 典型场景 | ImageNet 1000 选 1、检测框内选唯一类别 | 图像打标签、属性识别、检测里的类别分数 |

多标签的 Rust 实现，比 Softmax 还简单——没有归一化，逐类算、逐类筛：

```rust
/// Sigmoid：把单个 logit 压到 (0, 1)
fn sigmoid(x: f32) -> f32 {
    1.0 / (1.0 + (-x).exp())
}

/// 多标签：逐类过 sigmoid，概率过阈值的都算命中
/// 返回所有命中的 (类别号, 概率)
fn multi_label(logits: &[f32], threshold: f32) -> Vec<(usize, f32)> {
    logits
        .iter()
        .enumerate()
        .map(|(i, &x)| (i, sigmoid(x)))    // 每一类独立算概率
        .filter(|&(_, p)| p >= threshold)  // 只保留过阈值的
        .collect()
}
```

一句话总结怎么选：**"这张图是哪一个？"用 Softmax；"这张图有哪些？"用 Sigmoid。**

## 15.7 工程坑：预处理必须和训练一致

这是本章最要命、也最容易让新手"能跑通但结果全乱"的坑，单独拎出来讲。

**模型是怎么被喂大的，推理时就得怎么喂它。** 训练时如果每张图都做了"减均值除标准差"，那推理时你也必须一模一样地做；差一点，输入数值的分布就和模型学到的对不上，输出的分数看着有模有样、其实全是错的——**不报错，但答案是错的**，这种坑最难查。

而分类模型和主线检测器的归一化方式**恰恰不一样**，这正是最坑的地方：

| | 主线检测器（YOLOv8） | 典型 ImageNet 分类模型 |
| --- | --- | --- |
| 输入尺寸 | 640×640（letterbox） | 224×224 |
| 归一化 | 只做 `/255`，到 `0~1` | `/255` 后**还要**逐通道减均值、除标准差 |
| 均值 mean | 无 | `[0.485, 0.456, 0.406]`（RGB） |
| 标准差 std | 无 | `[0.229, 0.224, 0.225]`（RGB） |

也就是说，检测器那套"读进来除以 255 就完事"的预处理，**直接套到分类模型上是错的**——你漏掉了 ImageNet 的均值方差这一步（这套统计值是在 ImageNet 训练集上算出来的，含义见附录 A.4）。分类模型正确的预处理片段（假设已把图缩放到 224×224、RGB、每像素 3 个 `u8`，缩放细节见第 10 章）：

```rust
// ImageNet 训练时的逐通道均值/标准差（RGB 顺序）
const MEAN: [f32; 3] = [0.485, 0.456, 0.406];
const STD:  [f32; 3] = [0.229, 0.224, 0.225];

/// 把一张 224×224 的 RGB 图做 ImageNet 归一化，
/// 并排成 NCHW 的 f32 张量：先整个 R 通道，再 G，再 B（planar）
fn imagenet_normalize(rgb: &[u8], w: usize, h: usize) -> Vec<f32> {
    let mut chw = vec![0.0f32; 3 * h * w];
    for c in 0..3 {                    // 通道：0=R, 1=G, 2=B
        for y in 0..h {
            for x in 0..w {
                let src = (y * w + x) * 3 + c;      // HWC 里的位置
                let v = rgb[src] as f32 / 255.0;    // ① 先 /255 到 0~1
                let v = (v - MEAN[c]) / STD[c];     // ② 再减均值、除标准差
                chw[c * h * w + y * w + x] = v;     // ③ 放到 NCHW 的位置
            }
        }
    }
    chw
}
```

和检测器预处理相比，就多了 `(v - MEAN[c]) / STD[c]` 这一步，但少了它结果就废。**另外三个连带的坑**：通道顺序（是 RGB 还是 BGR？OpenCV 系模型常是 BGR）、mean/std 是按 `0~1` 还是按 `0~255` 给的（本例是 `0~1`）、以及 15.5 说的类别顺序。这些约定和归一化一样，**模型文件里查不到，得翻 model card / 训练代码**（第 12 章反复强调过）。工程上最稳的自检办法：拿一张官方示例图，比对你的 Rust 结果和官方 Python demo 的 Top-5 是否一致——一致了，预处理才算真的对上了。

## 15.8 联系主线：检测框里藏着一个分类

学完分类，你其实已经看懂了主线检测器输出的"半壁江山"。回忆第 12 章解剖过的 YOLOv8 输出 `[1, 84, 8400]`，每个候选框有 84 个数字：

```text
84 = 4  (框坐标 cx, cy, w, h)
   + 80 (80 个 COCO 类别各自的分数)   ← 这 80 个，就是一个"框内分类"问题！
```

那 **80 个类别分数**，本质就是在问："这个框里的东西，属于 person / car / cat …… 这 80 类各自的可能性有多大？"——一个**框内部的分类子问题**，和本章讲的一模一样。区别只在于取法：

- 检测里这 80 个分数走的是**逐类 Sigmoid**（15.6 的多标签思路），**不是 Softmax**。原因是 YOLOv8 没有"背景"这个互斥类参与 softmax 竞争，且允许一个框对多个类给分，最后取分最高的类作为该框类别。
- 所以你可以把检测器理解成："先找出 8400 个候选框，再对每个框内部做一次 80 类的（Sigmoid 式）打分。"

换句话说，**本章的 Softmax/Sigmoid/取最大，就是检测后处理里"给框定类别、定分数"那一步的核心**。剩下的框坐标怎么解码、8400 个候选怎么用 NMS 去重、怎么逆 letterbox 还原到原图像素——那是**第 16 章**检测模型的完整戏码。带着"每个框里都有一个小分类器"这个认知去看第 16 章，会顺畅很多。

## 15.9 小结

- 分类模型是最基础的一类：**输入一张图，输出"整体最像哪个类别"**，不管物体在哪、有几个。它是读懂一切模型输出的起点。
- 输入常见 `1×3×224×224`（**注意和主线检测器的 640 不同**，尺寸由模型自己定，务必按第 12 章查）；输出 `1×1000` 是 **logits（未归一化分数）**，不是概率。
- **logits 不能直接当概率**（可负、无上界、和不为 1）。过 **Softmax** 才变成加起来为 1 的概率；工程必须用**数值稳定版**（先减最大值），结果不变但不溢出。
- **Top-1** 用 argmax 取最可能类别，**Top-K**（常见 Top-5）取前 k 个；比较 `f32` 一律用 `total_cmp`，别 `unwrap` 到 `NaN`。
- **Softmax vs Sigmoid** 是分水岭："这张图是哪**一个**？"用 Softmax（互斥单标签）；"这张图**有哪些**？"用逐类 Sigmoid + 阈值（独立多标签）。
- 两个必踩的坑：**预处理要和训练一致**（分类多做 ImageNet 均值方差，检测只做 `/255`，别混）；**标签表顺序要和模型对齐**（优先用模型自带的 names）。
- 主线呼应：检测器每个候选框内部的 80 类分数，就是一个"框内分类"（走 Sigmoid），第 16 章展开。

## 15.10 练习

1. **手算 + 验证 Softmax 的平移不变性**：对 `logits = [5.0, 4.0, -1.0]` 手算 Softmax（保留三位小数）；再把每个数都加 1 变成 `[6.0, 5.0, 0.0]`，重新算一遍。两组结果应当**完全一样**——说说这为什么正好印证了"数值稳定版先减最大值不改变结果"。
2. **实现并测试 Top-K**：用 15.4 的 `top_k` 处理一个长度 1000、值随机的分数数组，验证返回的确实是最大的 5 个且降序排列。再试两种边界：`k` 比数组还长会怎样？数组里有两个并列的最大值时 `argmax` 返回哪一个？
3. **Softmax 还是 Sigmoid**：判断下面三个任务各该用哪个，并说明输出层大小和后处理怎么写——(a) 判断一张 X 光片"是否肺炎"（是/否）；(b) 给风景照打标签，可多选"海/山/城市/夜景"；(c) 识别一张图是 1000 种动物里的哪一种。
4. **复现预处理翻车**：拿一个 ImageNet 分类模型，先**故意只做 `/255`、不做均值方差**跑一张猫图，记录 Top-5；再补上 15.7 的均值方差，重新跑。对比两次的类别和置信度，亲手体会一次"预处理必须和训练一致"——顺便想想：为什么这种错误"不报错"，反而最难排查？
