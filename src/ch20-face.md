# 第 20 章 · 人脸识别：检测、对齐、特征与比对

> **本章导读**：前几章我们已经能"找到并框出"图像里的物体（第 16 章），也能定位人脸上的关键点（第 17 章）。本章把这些能力串成一件日常又硬核的事——**人脸识别**。我们先分清"人脸检测"和"人脸识别"根本是两回事，再走完完整的四步流水线：**检测人脸 → 对齐 → 提取特征向量 → 比对**。你会亲手把一张脸"变成一串数字"（embedding），用**余弦相似度**判断"这是不是同一个人"，最后搭一个能注册、能检索的**人脸库**。这条流水线也是第 25 章"脸人绑定"的地基。

---

## 20.1 先分清：人脸检测 vs 人脸识别

新手最容易把这两个词混着用，但它们在工程里是完全不同的两步。打个生活比喻：**小区门禁的保安**做两件事——

1. 先**看到"有人来了"**，注意力落到那张脸上：这是**人脸检测（face detection）**，只回答"脸在画面哪个位置"，不关心是谁。
2. 再**认出"这是 3 号楼的张三，放行"**：这是**人脸识别（face recognition）**，回答"这张脸是谁 / 这两张脸是不是同一个人"。

用一张表把它们钉死：

| 维度 | 人脸**检测** | 人脸**识别** |
| --- | --- | --- |
| 回答的问题 | 脸在哪？有几张？ | 这是谁？是不是同一人？ |
| 本质 | 目标检测的一个特例（第 16 章） | 特征比对 |
| 输入 | 整幅图像 | 一张裁好、摆正的脸 |
| 输出 | 人脸框 + 关键点 | 特征向量 / 一个人名 |
| 典型模型 | RetinaFace、SCRFD | ArcFace |

请记住：**人脸检测就是"只检测'脸'这一个类别"的检测器**——第 16 章讲的框、置信度、NMS（非极大值抑制）在这里原封不动地适用，只是类别从 COCO 80 类缩成了"脸 / 不是脸"。而**识别**是本章的新东西，它要把"脸"这个图像块，变成能互相比较的"一串数字"。

## 20.2 完整流水线：从"一张脸"到"这是谁"

工程上的人脸识别不是一个模型搞定，而是一条**级联流水线**：前一步的输出，正好是后一步的输入。四步如下：

```text
        原始图像（可能有好几张脸）
              │
              ▼
   ┌──────────────────────────┐
   │ ① 人脸检测（RetinaFace）    │  找出每张脸在哪
   └──────────────────────────┘
              │  每张脸：BBox + 5 个关键点
              ▼
   ┌──────────────────────────┐
   │ ② 人脸对齐（仿射变换）       │  把歪脸摆正成 112×112 标准脸
   └──────────────────────────┘
              │  对齐后的"正脸"小图
              ▼
   ┌──────────────────────────┐
   │ ③ 特征提取（ArcFace）       │  编码成 512 维向量
   └──────────────────────────┘
              │  embedding: [f32; 512]
              ▼
   ┌──────────────────────────┐
   │ ④ 比对（余弦相似度）         │  和人脸库逐个比，取最像的
   └──────────────────────────┘
              │
              ▼
        "这是小王，相似度 0.87"
```

四步各司其职：**检测**负责"框出脸并给 5 个关键点"，**对齐**负责"把姿态各异的脸摆成统一的正脸"，**特征提取**负责"把正脸编码成向量"，**比对**负责"算两个向量像不像"。少了任何一步，精度都会明显掉——尤其是**对齐**，新手最容易漏，后面会专门讲它的威力。下面逐步拆开。

## 20.3 第一步 · 人脸检测：框 + 5 个关键点

人脸检测常用 **RetinaFace** 或更轻快的 **SCRFD**。和普通检测器相比，它多输出一样东西：每张脸的 **5 个关键点（landmarks）**——**左眼、右眼、鼻尖、左嘴角、右嘴角**。

为什么检测器要顺手吐出这 5 个点？因为下一步"对齐"正需要它们当"锚点"。这也呼应第 17 章：那里讲关键点模型的原理（热力图、坐标还原），这里我们只当**使用方**，直接拿它给的坐标。

框的部分我们**复用全书统一的 `BBox`**（左上-右下像素坐标，见第 3.8 节），只是外面再包一层带关键点的结构：

```rust,ignore
use crate::BBox; // 复用第 16 章的统一边界框：{ x1, y1, x2, y2 }

/// 人脸检测结果：框 + 置信度 + 5 个关键点
#[derive(Clone, Debug)]
pub struct FaceDetection {
    pub bbox: BBox,                  // 复用统一 BBox，坐标已还原到原图像素
    pub score: f32,                  // "是一张脸"的置信度 0~1
    pub landmarks: [(f32, f32); 5],  // 顺序：左眼、右眼、鼻尖、左嘴角、右嘴角
}
```

> **和第 16 章的关系**：人脸检测器的后处理（框还原、按置信度过滤、NMS 去重叠框）和第 16 章完全一致，这里不再重复。关键点坐标同样要跟着框一起从模型输入尺寸**还原到原图像素坐标**（letterbox 逆变换见第 10 章），否则后面对齐会全歪。

拿到 `FaceDetection` 后，一张图里的每张脸都独立走后面三步。

## 20.4 第二步 · 人脸对齐：把歪脸摆正

### 为什么必须对齐

同一个人，**正脸、侧头 15°、仰头、离镜头远近不同**，在像素层面差别巨大。如果直接把这些"原始裁剪"喂给识别模型，模型得同时操心"这是谁"和"这脸怎么摆的"，负担太重，精度会**暴跌**。

**对齐（alignment）** 就是先把姿态这个干扰因素消掉：用几何变换把每张脸都"摆正"到**统一的姿态、统一的大小、五官落在统一的位置**。这样识别模型每次看到的都是规规矩矩的"标准正脸"，只需专心回答"这是谁"。

打个比方：证件照要求"正脸、平视、居中"，就是为了让审核的人只比对长相，不被姿势干扰。对齐就是给每张脸自动拍一张"标准证件照"。

### 怎么对齐：5 个关键点 + 相似变换

做法呼应第 9 章的**几何变换**：我们定义一张 112×112 的"标准脸模板"，规定 5 个关键点**应该**落在哪里；再用检测得到的 5 个**实际**关键点，求一个**相似变换（similarity transform：只含旋转、等比缩放、平移，不改变脸的长宽比）**，把实际的 5 个点搬到模板位置上，整张脸也就跟着被摆正了。

标准模板点（insightface 约定的 112×112 坐标）如下：

```rust,ignore
/// 对齐后，5 个关键点在 112×112 图上"应该"落在的位置（业界通用模板）
const TEMPLATE_112: [(f32, f32); 5] = [
    (38.2946, 51.6963), // 左眼
    (73.5318, 51.5014), // 右眼
    (56.0252, 71.7366), // 鼻尖
    (41.5493, 92.3655), // 左嘴角
    (70.7299, 92.2041), // 右嘴角
];
```

有了"实际 5 点"和"目标 5 点"两组对应，就是解一个**超定方程组**（5 对点、未知数只有 4 个：旋转+缩放合成的 2 个参数 + 2 个平移），用**最小二乘**求出那个 2×3 仿射矩阵。思路骨架：

```rust,ignore
/// 由检测到的 5 个关键点，估计"把这张脸对齐到模板"的 2×3 仿射矩阵（骨架）
/// 返回 [[a, b, tx], [c, d, ty]]，含义见第 9 章：新点 = M · (x, y, 1)^T
fn estimate_align_matrix(src: &[(f32, f32); 5]) -> [[f32; 3]; 2] {
    // 目标：找相似变换 M，使 M · src[i] ≈ TEMPLATE_112[i]，误差平方和最小。
    // 数学上是经典的 Umeyama / least-squares similarity 求解：
    //   1) 分别算 src 和模板的质心，去中心化；
    //   2) 由两组去中心点算出旋转与统一缩放；
    //   3) 用质心反推平移量 tx, ty。
    // 工程上通常直接调现成实现：
    //   - OpenCV: cv::estimateAffinePartial2D(src, template)
    //   - 或用 nalgebra 自己实现上面三步（矩阵运算 <10 行）。
    todo!("解最小二乘相似变换，返回 2×3 矩阵")
}

/// 拿到矩阵后，把原图按仿射变换 warp 到 112×112 的对齐脸
fn align_face(image: &image::RgbImage, det: &FaceDetection) -> image::RgbImage {
    let m = estimate_align_matrix(&det.landmarks);
    // warp_affine 的实现见第 9 章：对目标图每个像素做逆映射 + 双线性采样
    warp_affine(image, &m, 112, 112) // 输出固定 112×112，正好喂给 ArcFace
}
```

关键点在于：**对齐用的是关键点，不是那个人脸框**。框只告诉你"脸大概在这块区域"，而 5 个关键点精确到"眼睛在哪、嘴在哪"，才能把脸真正摆正。对齐后所有脸都是 112×112 的标准正脸，尺寸和五官位置统一，这正是识别模型想要的输入。

## 20.5 第三步 · 特征提取：把脸变成一串数字

对齐好的 112×112 正脸，喂给**识别模型（如 ArcFace）**，它不输出类别、不输出框，而是吐出一个**定长特征向量（embedding，人脸嵌入）**——通常是 **512 维的 `f32`**。

这是整章的**核心思想**，务必理解透：**把"一张脸"压缩成"一串数字"**。而且这串数字有个神奇性质，是训练时刻意学出来的：

- **同一个人**的不同照片（不同光照、表情、角度）→ 得到的向量**方向很接近**；
- **不同人**的照片 → 得到的向量**方向差很远**。

于是"判断是不是同一个人"这个模糊的视觉问题，被翻译成了一个**精确的数学问题**："两个向量的方向像不像"。张量形状上：

```text
输入:  [1, 3, 112, 112]   对齐后的正脸（RGB、归一化，见第 10 章）
输出:  [1, 512]           这张脸的 embedding（512 个 f32）
```

推理这一步和别的模型没区别（第 14 章）：预处理成张量 → `tract-onnx`/`ort` 前向 → 拿到 512 维输出。真正的门道全在"拿到向量之后怎么用"，也就是下一步的**比对**。

## 20.6 第四步 · 比对：余弦相似度与阈值判定

### 余弦相似度：比"方向"，不比"长短"

现在每张脸都是一个 512 维向量。怎么衡量两个向量"像不像"？最常用的是**余弦相似度（cosine similarity）**。

先打比方：把每个向量想成从原点射出的一支**箭**。我们**不关心箭有多长，只关心两支箭的方向夹角**——夹角越小（越同向），两张脸越像。余弦相似度就是这个夹角的余弦值：**同向 = 1，垂直 = 0，反向 = −1**。

它的公式是"点积除以两个模长之积"：

$$
\cos(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a}\cdot\mathbf{b}}{\|\mathbf{a}\|\,\|\mathbf{b}\|}
= \frac{\sum_i a_i b_i}{\sqrt{\sum_i a_i^2}\,\sqrt{\sum_i b_i^2}}
$$

别被公式吓到，用一组 3 维小向量**手算一遍**就懂了（真实是 512 维，道理一模一样）。设小王的脸编码为 `a = [1, 2, 2]`，来比三张脸：

**① 另一张小王的照片 `b = [2, 4, 4]`**（正好是 a 的 2 倍，完全同向）

- 点积：`1×2 + 2×4 + 2×4 = 2 + 8 + 8 = 18`
- 模长：`‖a‖ = √(1+4+4) = √9 = 3`，`‖b‖ = √(4+16+16) = √36 = 6`
- 相似度：`18 / (3 × 6) = 18 / 18 = 1.0` → **完全同向，判定同一人**

**② 小王换了角度/光照 `d = [2, 2, 1]`**（方向接近但不完全一样）

- 点积：`1×2 + 2×2 + 2×1 = 2 + 4 + 2 = 8`
- 模长：`‖d‖ = √(4+4+1) = √9 = 3`
- 相似度：`8 / (3 × 3) = 8 / 9 ≈ 0.889` → **很接近，仍判同一人**

**③ 陌生人 `c = [2, -1, 0]`**

- 点积：`1×2 + 2×(−1) + 2×0 = 2 − 2 + 0 = 0`
- 相似度：`0 / (3 × √5) = 0` → **方向无关，判不同人**

看到没：同一个人不管长短怎么变，方向都稳在高位（0.89、1.0），陌生人直接掉到 0。翻成 Rust：

```rust,ignore
/// 余弦相似度：两个等长向量方向的接近程度，范围 -1~1
pub fn cosine_similarity(a: &[f32], b: &[f32]) -> f32 {
    assert_eq!(a.len(), b.len(), "两个向量维度必须相同");
    let (mut dot, mut na, mut nb) = (0.0f32, 0.0f32, 0.0f32);
    for i in 0..a.len() {
        dot += a[i] * b[i]; // 点积
        na += a[i] * a[i];  // a 的模长平方
        nb += b[i] * b[i];  // b 的模长平方
    }
    dot / (na.sqrt() * nb.sqrt() + 1e-8) // +1e-8 防止除以 0
}
```

### 顺带一提：欧氏距离

除了余弦，也有人用**欧氏距离（Euclidean distance）**——就是两个向量端点之间的直线距离 $\sqrt{\sum_i (a_i-b_i)^2}$，**越小越像**（和余弦"越大越像"方向相反）。有个好用的关系：若两个向量都做了 L2 归一化（模长为 1），则 $\|\mathbf{a}-\mathbf{b}\|^2 = 2 - 2\cos(\mathbf{a},\mathbf{b})$，两者本质等价。工程里余弦更常见，因为它天然落在 −1~1，阈值好设。

### 阈值判定：1:1 验证 vs 1:N 检索

有了相似度分数，还需要一条**阈值线**来做判决：

> **相似度 > 阈值 → 判为同一人；否则判为不同人。**

由此分出两种任务：

| 任务 | 问的问题 | 怎么算 | 例子 |
| --- | --- | --- | --- |
| **1:1 验证** | "你是不是你声称的那个人？" | 拿当前脸和**指定 1 个**存档比一次 | 刷脸支付、刷脸解锁 |
| **1:N 检索** | "你是库里的哪一个？" | 拿当前脸和**库里 N 个**逐一比，取最像 | 门禁认人、名单布控 |

阈值不是拍脑袋定的，而是拿验证集扫出来的经验值（余弦常见落在 0.4~0.6，随模型和场景变）。**阈值调高**→更严格，宁可认错为陌生人也不放错人（安防偏这边）；**阈值调低**→更宽松，宁可多放行也别拦住本人（考勤偏这边）。

## 20.7 人脸库：注册与 1:N 检索

1:N 检索需要一个**人脸库（feature gallery，特征底库）**：注册时把每个人的 id 和 embedding 存进去，识别时把当前脸的向量和库里**所有**向量算相似度，**取最大的那个**，再和阈值比。

数据结构就是最朴素的 **`id → Vec<f32>`** 映射。这里再补一个关键的工程细节：**入库前把向量做 L2 归一化**（缩放到模长 1）。归一化之后，余弦相似度就退化成简单的**点积**，检索时省一半算力；更重要的是，它避免了"忘了归一化导致相似度乱套"这个高频坑。

```rust,ignore
/// L2 归一化：把向量缩放到模长为 1；之后余弦相似度 == 点积
pub fn l2_normalize(v: &mut [f32]) {
    let norm: f32 = v.iter().map(|x| x * x).sum::<f32>().sqrt();
    if norm > 1e-8 {
        for x in v.iter_mut() {
            *x /= norm; // 每个分量同比例缩小
        }
    }
}

/// 人脸库：id -> 归一化后的特征向量
pub struct FaceGallery {
    entries: Vec<(String, Vec<f32>)>,
}

impl FaceGallery {
    pub fn new() -> Self {
        Self { entries: Vec::new() }
    }

    /// 注册：存入一个人的 id 和特征向量（入库前先归一化）
    pub fn register(&mut self, id: &str, mut embedding: Vec<f32>) {
        l2_normalize(&mut embedding);
        self.entries.push((id.to_string(), embedding));
    }

    /// 1:N 检索：返回库里最相似的 (id, 相似度)；库为空则 None
    pub fn search(&self, query: &[f32]) -> Option<(String, f32)> {
        let mut q = query.to_vec();
        l2_normalize(&mut q); // 查询向量也要归一化
        self.entries
            .iter()
            .map(|(id, emb)| (id.clone(), cosine_similarity(&q, emb)))
            .max_by(|a, b| a.1.partial_cmp(&b.1).unwrap()) // 取相似度最大的
    }
}
```

调用时再套上阈值，就是一个完整的识别判决：

```rust,ignore
let threshold = 0.45; // 经验阈值，需按你的模型和场景实测微调
match gallery.search(&query_embedding) {
    Some((id, sim)) if sim > threshold => {
        println!("识别为：{}（相似度 {:.3}）", id, sim);
    }
    Some((_, sim)) => {
        println!("陌生人（最高相似度 {:.3}，未过阈值 {}）", sim, threshold);
    }
    None => println!("人脸库为空"),
}
```

> **工程上通常会**在库很大（几十万人）时，把逐一点积换成向量检索引擎（如 faiss、hnsw 的近似最近邻）来提速；小库直接线性扫足够快。这里保持"看得懂"优先。第 25 章会把这套检索接到"脸人绑定"上，让每个人体目标关联上一个身份。

### 串起来：一次完整识别的代码

把前面四步拼成一个函数，你就能看清整条流水线的数据是怎么流动的。一张图里可能有多张脸，所以外层是个循环，每张脸独立走"对齐 → 提特征 → 检索"：

```rust,ignore
/// 对一整幅图做人脸识别，返回每张脸的 (框, 识别结果)
pub fn recognize_image(
    image: &image::RgbImage,
    gallery: &FaceGallery,
    threshold: f32,
) -> Vec<(BBox, String)> {
    let mut results = Vec::new();

    // ① 检测：一次拿到图里所有脸的框 + 5 关键点（内部含 NMS，见第 16 章）
    let faces: Vec<FaceDetection> = detect_faces(image);

    for det in &faces {
        // ② 对齐：用 5 关键点把这张脸摆正成 112×112
        let aligned = align_face(image, det);

        // ③ 提特征：对齐脸 -> 512 维 embedding（推理见第 14 章）
        let embedding: Vec<f32> = extract_embedding(&aligned);

        // ④ 比对：在人脸库里 1:N 检索，套阈值得出身份
        let name = match gallery.search(&embedding) {
            Some((id, sim)) if sim > threshold => id,
            _ => "陌生人".to_string(),
        };

        results.push((det.bbox, name)); // bbox 用于后续在原图上画标注
    }
    results
}
```

`detect_faces` 和 `extract_embedding` 内部都是"预处理 → ONNX 推理 → 后处理"的老套路（第 14 章），本章不再展开；重点是看清**四步如何交接**：检测给出框和关键点，关键点喂给对齐，对齐结果喂给特征提取，特征向量喂给库检索——每一步的输出都恰好是下一步的输入。

## 20.8 活体检测与工程避坑

**活体检测（liveness）** 这里一句话带过：光有识别还不够，得防着有人拿**照片、屏幕视频、面具**冒充本人——活体检测就是判断"镜头前是不是一个活人"。它在真实门禁/支付里是**必配**的一环，缺了它，一张打印照片就能骗过整套系统。

最后把新手最常踩的坑集中列一遍：

- **不对齐直接比对，精度暴跌**：这是头号坑。省掉 20.4 的对齐，同一个人换个角度相似度就可能跌破阈值。对齐的收益远比想象中大。
- **embedding 忘了 L2 归一化**：相似度分布乱掉，阈值怎么调都不对。注册和查询**两头都要归一化**。
- **阈值照搬别人的数值**：0.45 只是示例。换模型、换摄像头、换光照环境，都应该拿自己的验证集重新扫阈值。
- **光照 / 口罩 / 大角度 / 遮挡**：戴口罩、逆光、侧脸超过一定角度，embedding 质量会下降，识别变难。工程上常靠"多帧取质量最好的一帧再识别""检测阶段过滤掉太小/太侧的脸"来缓解。
- **坐标没还原**：关键点若没跟着框一起还原到原图像素坐标（第 10 章 letterbox 逆变换），对齐会整体偏移。

## 20.9 小结

- **人脸检测 ≠ 人脸识别**：检测是"脸在哪"（第 16 章检测器的特例，输出框 + 5 关键点），识别是"这是谁"（特征比对）。
- 完整流水线是四步级联：**检测 → 对齐 → 特征提取 → 比对**，前一步的输出是后一步的输入，缺一步精度都掉。
- **对齐**用 5 个关键点求相似/仿射变换（第 9 章），把姿态各异的脸摆正到 112×112 标准模板，是新手最容易漏、收益最大的一步。
- **特征提取**（ArcFace）把正脸编码成定长 **512 维 embedding**——把"脸"变成"一串数字"，让"像不像"变成可计算的数学问题。
- 比对用**余弦相似度**（比方向，不比长短），配一条**阈值**判决：1:1 是验证、1:N 是库内检索；embedding 入库和查询都要 **L2 归一化**。
- 工程上还要配**活体检测**防伪，并留意光照/口罩/角度/阈值随场景漂移这些坑。这套能力将在第 25 章接到脸人绑定。

## 20.10 练习

1. **手算 + 代码对照**：给定 `a = [3, 0, 4]`、`b = [4, 0, 3]`，先手算它们的余弦相似度（提示：两个模长都是 5，点积是 24，答案 0.96），再用本章的 `cosine_similarity` 跑一遍，确认结果一致。然后把 `b` 换成 `[-3, 0, -4]`，看相似度变成多少，解释它的几何含义。

2. **归一化的影响**：把 `a = [1, 2, 2]` 和 `b = [2, 4, 4]` 分别做 `l2_normalize` 后再点积，验证结果就等于它们的余弦相似度 1.0；再故意**跳过**归一化直接点积，观察数值差异，体会"忘了归一化"为什么会让阈值失灵。

3. **搭一个迷你人脸库**：用 `FaceGallery` 注册三个人（可以先用手写的 512 维随机向量假装 embedding），实现一个函数：输入一个查询向量和阈值，返回"识别为某人"或"陌生人"。再把阈值从 0.3 调到 0.7，观察判决结果怎么随阈值变化，理解"调高更严、调低更松"。

4. **对齐的必要性（思考 + 可选实现）**：假设一张脸整体旋转了 30°，用 `estimate_align_matrix` 的思路说明：为什么先对齐再提特征，会比直接把旋转的脸喂给识别模型得到更稳的相似度？如果有 ArcFace 的 ONNX 模型，拿"对齐 vs 不对齐"两版输入各跑一次，对比同一个人的相似度差多少。
