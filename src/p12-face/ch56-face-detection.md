# 第 56 章 人脸检测（MTCNN/RetinaFace）

> **本章导读**
> - 学完你能：把 [第 46 章](../p09-detection/ch46-yolo-inference.md) 的网格检测器改造成一个**单类"人脸"检测器**，并额外挂一个 **5 点关键点回归头**（两眼/鼻/两嘴角）——一次前向同时输出**人脸框 + 关键点**，正是 **RetinaFace** 的核心套路。
> - 你会真正理解**人脸检测 = 单类目标检测 + 关键点多任务**：objectness、框回归、关键点回归三个头共用一个骨干，复用 [第 47 章](../p09-detection/ch47-train-detector.md) 的数值稳定 BCE、L1 回归、NMS 与学习率衰减。
> - 我们用**小模型 + 合成"人脸"**（椭圆脸 + 两眼 + 鼻 + 嘴），在**纯 CPU、不下载任何模型**的前提下跑通全流程；正文每个数字都来自本机 `cargo run --release` 的真实输出。
> - 讲透两大经典人脸检测器：**MTCNN**（P/R/O 三级级联，逐级精修）与 **RetinaFace**（单阶段 anchor + 框 + 5 关键点多任务），并给出**诚实的"上真实模型"路线**。

## 场景：刷脸之前，先得"找到脸"

你举起手机对着屏幕，"叮"一声解锁了。这一步里其实藏着两件事：**先找到画面里的脸在哪**（人脸检测），**再判断这张脸是不是机主本人**（人脸识别，下一章的事）。门禁考勤、相机的人脸对焦、美颜 App 的"贴纸跟着脸跑"，第一步统统是**人脸检测**——在图像里框出每一张脸，往往还顺带标出**眼睛、鼻子、嘴**这几个关键点。

那为什么不直接用 [第 46 章](../p09-detection/ch46-yolo-inference.md) 那个通用检测器？完全可以——**人脸检测本质上就是"只检一个类别（人脸）的目标检测"**。但人脸有两个额外讲究：一是脸的尺度变化极大（自拍的大脸 vs 合影里的小脸），二是后续的**人脸对齐**（[第 54 章](../p11-keypoints/ch54-face-landmarks.md)）需要**关键点**——所以现代人脸检测器几乎都在检测框之外，**顺手回归 5 个关键点**。本章我们就把上一部分的检测器，改造成这样一个"框 + 关键点"的人脸检测器。

## 原理：从通用检测器到人脸检测器

### 单类检测 + 关键点多任务

回忆 [第 46 章](../p09-detection/ch46-yolo-inference.md)：把图切成 \\( G\times G \\) 网格，每个格子输出一个固定长度的预测向量。通用检测器每格预测 `obj + 框 + 各类别分数`。人脸检测只有**一个类别**，于是不再需要类别分支——**objectness 本身就是"这里是不是一张脸"的置信度**。省下的通道拿来干件更有用的事：**回归 5 个人脸关键点**。

我们的迷你人脸检测器：输入 **48×48** RGB，经三段"卷积 + 2×2 池化"降到 **6×6** 网格，再用一个 **1×1 卷积头**在每格输出 `A = 1 + 4 + 10 = 15` 个数：

```text
每个格子(i,j) 预测 15 个数：
┌──────────┬──────────────────────┬──────────────────────────────┐
│ obj 置信度│  tx, ty, tw, th (框)  │  5 个关键点 (x,y) 共 10 个数    │
│  1 个     │      4 个             │  左眼/右眼/鼻/左嘴角/右嘴角     │
└──────────┴──────────────────────┴──────────────────────────────┘
     ↑             ↑                            ↑
 是脸吗?     脸框在哪/多大               眼鼻嘴在哪(供对齐用)
```

这就是 **RetinaFace 的多任务思想**的最小版：一个骨干、三个头（人脸分类、框回归、关键点回归），一次前向全出。三个头共享骨干学到的"脸长什么样"的特征，彼此还能互相促进——知道眼睛在哪，框自然框得更准。

### 三件套损失：objectness + 框 + 关键点

训练目标沿用 [第 47 章](../p09-detection/ch47-train-detector.md) 的"损失三件套"，只是把"类别损失"换成"关键点损失"：

\\[ L = L_{obj} + \lambda_{box}\ L_{box} + \lambda_{lmk}\ L_{lmk} \\]

- **objectness**：所有格子的加权 BCE。人脸格是极少数（36 格里通常就 1 个），必须给正样本更大权重（本章 `pos_w = 8`），否则模型会偷懒地"全说没有"。用 [第 47 章](../p09-detection/ch47-train-detector.md) 那个**数值稳定的 BCE**：\\( \max(x,0) - x y + \log(1 + e^{-|x|}) \\)，别用 candle 自带那个会 NaN 的版本。
- **框回归**：解码成归一化 \\( (c_x, c_y, w, h) \\) 后做 L1，**只在负责格上算**。
- **关键点回归**：5 个点的 \\( (x, y) \\) 与真值做 L1，**只在负责格上算**。

### 一个关键的坑：1×1 卷积头回归不了"绝对坐标"

关键点该怎么编码？最自然的想法是"直接让网络吐出每个关键点的归一化图坐标"。**但这行不通，而且不报错、只是永远学不动**——这正是 [第 47 章](../p09-detection/ch47-train-detector.md) 那个"卷积平移等变"洞见的又一次现身。

1×1 卷积头对每个格子做的是**同一个函数**：它只看该格子那 64 维局部特征，**根本不知道自己是第几行第几列**。一个平移不变的函数，怎么可能吐出"绝对图坐标"这种和位置强相关的量？所以框中心要写成 `(格号 + 偏移)` 的形式——把格子坐标**显式注入**。关键点同理：

\\[ x_k = \Big(\frac{j + 0.5}{G} + \delta^x_k\Big)\cdot W, \qquad y_k = \Big(\frac{i + 0.5}{G} + \delta^y_k\Big)\cdot H \\]

即"**格子中心 + 网络回归的偏移**"。网络只需学"关键点相对本格中心的偏移" \\( \delta_k \\)，这是个平移不变的量，1×1 卷积能胜任。我第一版偷懒直接回归绝对坐标，关键点损失死死卡在 0.12（约 8 像素误差）纹丝不动；改成上面这种"格子中心 + 偏移"后，损失一路降到 **0.0066**、误差 **1.26 像素**。

> 🕳️ **坑**：**只要你的输出头是 1×1 卷积（对每格同一个函数），任何"绝对位置"类的量都必须显式注入格子坐标。** 框中心、关键点都躲不过。忘了注入，损失不动、模型不报错，最难查。

### 合成"人脸"

没有人脸数据集也能自包含地跑通：我们用几何图形合成"人脸"——一个**椭圆脸**（暖色肤色、随机亮度）、**两只眼睛**、**一个鼻子**、**一条嘴**，随机位置、随机尺度、叠加背景噪声。画五官时，**关键点坐标就是五官的中心**，天然对齐（完整 `make_image` 见配套工程）：

```rust
let le = (cx - 0.40 * a, cy - 0.22 * b); // 左眼
let re = (cx + 0.40 * a, cy - 0.22 * b); // 右眼
let no = (cx, cy + 0.08 * b);            // 鼻
let lm = (cx - 0.28 * a, cy + 0.48 * b); // 左嘴角
let rm = (cx + 0.28 * a, cy + 0.48 * b); // 右嘴角
fill_disk(&mut img, le.0, le.1, 0.14 * a + 0.8, dark); // 画眼睛……鼻、嘴同理
```

### 检测器：三段卷积 + 1×1 检测头

和 [第 46 章](../p09-detection/ch46-yolo-inference.md) 一模一样的骨干，只把头的输出通道改成 `A = 15`：

```rust
const A: usize = 1 + 4 + 2 * NL; // NL=5 个关键点 → 15
// 通道布局：[0]=obj  [1..5]=框  [5..10]=5点的 x  [10..15]=5点的 y
head: conv2d(64, A, 1, cfg0, vb.pp("head"))?, // 1x1 头 → [N,15,6,6]
```

关键点通道用**非交错布局**（前 5 个通道全是 x、后 5 个全是 y），这样加"格子中心"时能对 x 块、y 块整体广播，代码干净：

```rust
// ③ 关键点回归：预测 = 格子中心(归一化) + 线性偏移，只在负责格上做 L1
let ccx = cell_x.affine(1.0 / G as f64, 0.5 / G as f64)?; // (col+0.5)/G
let ccy = cell_y.affine(1.0 / G as f64, 0.5 / G as f64)?; // (row+0.5)/G
let pred_lx = lmk_x_raw.broadcast_add(&ccx)?; // 注入列坐标
let pred_ly = lmk_y_raw.broadcast_add(&ccy)?; // 注入行坐标
let pred_lmk = Tensor::cat(&[&pred_lx, &pred_ly], 1)?;
let l_lmk = pred_lmk.broadcast_sub(lmk_t)?.abs()?
    .broadcast_mul(obj_t)? // 掩码：只在负责格算
    .sum_all()?.affine(1.0 / (num_pos * 2.0 * NL as f32) as f64, 0.0)?;
```

objectness 的加权 BCE、框回归、safetensors 存取、解码、NMS 全部照搬 [第 46/47 章](../p09-detection/ch46-yolo-inference.md)（解码时把关键点按同样的"格子中心 + 偏移"公式还原成绝对像素）。**这就是复用的威力：换个任务，管线几乎不动。**

## 原理拓展：MTCNN 与 RetinaFace 是怎么做的

我们的迷你版讲清了"框 + 关键点"的骨架。工业界两大经典人脸检测器，是把这套思路做深、做实：

**MTCNN（Multi-task Cascaded CNN，多任务级联）——三级由粗到精。**

```text
原图 ──构建图像金字塔（多个缩放尺度，应对大小脸）──▶
  P-Net  (小网络, 全卷积扫全图)  → 海量候选框 + 粗定位     → NMS 去重
  R-Net  (中网络, 逐候选精修)    → 淘汰大量假阳 + 修框     → NMS
  O-Net  (大网络, 最后精修)      → 最终框 + 5 个关键点      → NMS
```

三级网络一个比一个大、一个比一个准：**P-Net** 快速海选（宁可错留），**R-Net** 大幅剔除假阳，**O-Net** 精修并吐出 5 关键点。级联的妙处是**用小网络处理绝大多数容易的负样本、把算力留给少数难样本**。每一级都是"人脸分类 + 框回归 + 关键点回归"的多任务——和我们的三个头一脉相承，只是拆成了三段。

**RetinaFace——单阶段、anchor、强多任务。** 它不搞级联，一次前向直接在多个尺度的特征图上、每个位置铺若干 **anchor**（预设框），每个 anchor 预测：人脸得分 + 框回归 + **5 个关键点** +（原版还有 3D 稠密回归）。配合特征金字塔（FPN）和上下文模块，它在小脸、遮挡上都很强。**我们的单格预测 = RetinaFace 的单 anchor 特例**；把"每格 1 个预测"扩展成"每个位置多个不同大小的 anchor、多个尺度的特征图"，就从玩具长成了 RetinaFace。

> 📖 **术语**：**anchor（锚框）**。在特征图每个位置预先放好的一批不同大小/长宽比的参考框，网络只需回归"真值框相对 anchor 的偏移"，比从零预测绝对框容易得多。人脸大多接近正方形，所以人脸检测的 anchor 长宽比通常比通用检测更集中。详见 [第 45 章](../p09-detection/ch45-detection-principles.md)。

### 诚实的边界：真实模型要下载权重

> ⚠️ **注意（诚实边界）**：**纯 Rust 生态里没有"内置权重、开箱即跑"的 MTCNN/RetinaFace。** 本章训的是玩具级检测器，用来讲透原理与管线。要用工业级精度的真实模型，得**下载预训练权重**：把官方 MTCNN/RetinaFace 导出成 **ONNX**，用纯 Rust 的 **`tract-onnx`**（[第 94 章](../p19-deploy/ch94-onnx.md)）加载推理；或找到 safetensors 权重用 **candle** 搭同构网络加载（[第 42 章](../p08-classification/ch42-candle-classify.md) 那套 API）。因为要联网下载，这条路线不纳入本章一键 demo——但 tract/candle 的加载骨架是真实可用的，**没跑过的真实模型，本书不替你编数字**。接上后务必先 `println!` 出模型的输入输出形状，按实际布局解码（关键点顺序、是否含 landmark 分支、框是 xywh 还是 xyxy，各家不同）。

## 常见坑与提示

> 🕳️ **坑**：**关键点/框中心这类"绝对位置"，1×1 卷积头必须显式注入格子坐标。** 直接回归绝对图坐标会导致损失卡住不动（本章亲测：卡在 0.12 vs 注入后降到 0.0066）。原因是卷积头平移不变、不知道自己在第几格——这是 [第 47 章](../p09-detection/ch47-train-detector.md) "平移等变"洞见的直接后果。

> ⚠️ **注意**：**单类检测的 NMS 不用分类别。** 通用检测器要做"类别感知 NMS"（只抑制同类框，[第 46 章](../p09-detection/ch46-yolo-inference.md)），人脸只有一类，直接按 objectness 排序、跨框抑制即可。别照搬带 `cls` 判断的版本——不是错，是多余。

> 💡 **提示**：**关键点是为对齐服务的，不是花架子。** 检测出的 5 点（两眼/鼻/两嘴角）能算出脸的朝向与倾斜，用相似变换把脸**摆正、缩放到统一尺寸**（[第 54 章](../p11-keypoints/ch54-face-landmarks.md) 的人脸对齐），再送去识别，能显著提升下一章比对的准确率。检测阶段多花几个通道回归关键点，是**为整条人脸流水线省事**。

> 🕳️ **坑**：**小脸与尺度是人脸检测的老大难。** 本章合成图里脸的尺度范围有限；真实场景从大头自拍到监控里的小脸，尺度跨度巨大。单尺度网格检测不了太小的脸——这正是 MTCNN 用**图像金字塔**、RetinaFace 用**多尺度特征图 + 多尺寸 anchor** 的原因。做真实系统时，务必按业务里最小人脸的像素尺寸，设计输入分辨率与 anchor/尺度。

> ⚠️ **注意**：**合成脸 ≠ 真脸，别高估这个 100%。** 本章的"人脸"是干净的几何图案，检出率自然漂亮。真实人脸有姿态、遮挡、光照、化妆、口罩、种族多样性等，评测必须用**真实、且划分无泄漏**的人脸数据集（[第 47 章](../p09-detection/ch47-train-detector.md) 的划分纪律同样适用：同一人/同一段视频的帧不能跨 train/val 乱分）。

## 本章小结

- **人脸检测 = 单类目标检测 + 关键点多任务**。把 [第 46/47 章](../p09-detection/ch46-yolo-inference.md) 的网格检测器的类别头换成"5 点关键点回归头"，就得到一个 RetinaFace 式的人脸检测器；objectness、框回归、数值稳定 BCE、NMS、学习率衰减全部原样复用。
- **1×1 卷积头回归不了绝对坐标**：框中心和关键点都必须写成"格子中心 + 网络回归的偏移"，把格子坐标显式注入，否则损失卡死不动。
- 我们实测：迷你人脸检测器在合成测试图上**检出率 100%、命中框平均 IoU 0.870、5 点关键点平均误差 1.26 像素**，NMS 把 14 个候选压到 8 个；`VarMap::save` / `from_mmaped_safetensors` 与加载真实模型是同一套 API。
- **MTCNN** 是 P/R/O 三级级联，配图像金字塔由粗到精、逐级精修并出关键点；**RetinaFace** 是单阶段、多尺度 anchor、强多任务（脸/框/5 关键点）。我们的单格预测就是 RetinaFace 单 anchor 的最小特例。
- **诚实边界**：纯 Rust 无开箱即用的权重版人脸检测器；上真实模型要下载权重，用 `tract-onnx` 或 candle 加载，并按模型实际输出布局解码。

## 动手练习

1. **关掉坐标注入，复现"损失卡死"**：把关键点解码里的 `ccx/ccy`（格子中心）去掉、直接回归 `sigmoid(raw)` 当绝对坐标，重训，观察关键点损失是不是纹丝不动——亲手体会平移不变的后果。
2. **调正样本权重**：把 `pos_w` 从 8 改成 3 和 16，看检出率与误检怎么变（呼应 [第 47 章](../p09-detection/ch47-train-detector.md) 的 objectness 正负不平衡）。
3. **加尺度挑战**：把合成脸的尺寸范围拉大（比如宽度 8~40），看单尺度检测器在小脸上是不是开始漏检——想清楚为什么需要图像金字塔或多尺度 anchor。
4. **接对齐（进阶，呼应 [第 54 章](../p11-keypoints/ch54-face-landmarks.md)）**：用检出的 5 个关键点估计一个相似变换，把每张检出的脸摆正、缩放到固定大小，存成对齐后的人脸 crop——这正是下一章识别的标准输入。
5. **接真实模型（进阶）**：`cargo add tract-onnx`，下载一个 RetinaFace 或 MTCNN 的 `.onnx`，用 [第 94 章](../p19-deploy/ch94-onnx.md) 的骨架跑一张真实照片；先打印输出形状，确认关键点顺序与框格式后再解码。
