# 第 57 章 人脸识别与比对（embedding、ArcFace、度量学习）

> **本章导读**
> - 学完你能：用 candle 训一个小 **embedding 网络**，把人脸图映射成一个 **L2 归一化的低维向量**，然后用**余弦相似度**判断"这两张脸是不是同一个人"。
> - 你会真正理解**度量学习**：识别的目标不是"分成第几类"，而是"**同人向量靠得近、异人离得远**"——并亲手用 **ArcFace 角度间隔 margin-softmax** 训练，对照普通 softmax，看间隔到底值多少。
> - 我们在**训练时从没见过的新身份**上评测（开集），报**真实数字**：同人/异人余弦相似度分布、验证准确率、TAR@FAR、类内/类间距离、1:N 识别准确率。
> - 讲透**注册-比对流程**：1:1 verification（是不是同一个人）与 1:N identification（这是谁），以及为什么 ArcFace 比普通 softmax 更利于比对。

## 场景：门禁凭什么认得出"是你"？

上一章我们把脸**框出来、摆正了**（[第 56 章](ch56-face-detection.md) 检测 + [第 54 章](../p11-keypoints/ch54-face-landmarks.md) 对齐）。现在的问题是：门禁怎么知道这张脸**是不是登记过的员工**？

你可能会想："训练一个分类器，每个员工一个类别不就行了？"——**大错特错**。公司来了个新员工，难道要重新训练整个网络？更别提有几万名用户的刷脸支付了。真实的人脸识别用的是另一套思路：**不直接分类，而是把每张脸变成一个"数字指纹"（一个向量），比对时只看两个指纹像不像。** 新员工来了，拍张照存下他的指纹向量即可，**根本不用重训模型**。

这个"数字指纹"就是 **embedding（嵌入向量）**，而"训练一个网络专门产生好用的指纹"，就是**度量学习（metric learning）**。本章我们就来训这样一个网络，并且验证：它对**训练时从没见过的人**，也能认出"同人 vs 异人"。

## 原理：把脸变成向量，用距离比对

### embedding + 余弦相似度

**直觉**：想象把每张脸映射到一个高维空间里的一个点。好的映射应该让**同一个人的不同照片聚成一小团、不同人的团彼此离得远**。识别时不再问"这是第几类"，而是问"这两个点近不近"。

我们让网络输出一个 \\( D \\) 维向量 \\( f \\)（本章 \\( D = 32 \\)），再做 **L2 归一化**把它放到单位球面上：\\( \hat{f} = f / \lVert f \rVert \\)。归一化后，两个向量的**余弦相似度**就等于它们的点积，取值在 \\( [-1, 1] \\)：

\\[ \cos(\hat{f}_a, \hat{f}_b) = \hat{f}_a \cdot \hat{f}_b \\]

相似度越接近 1，两张脸越像。**为什么用余弦（角度）而不是欧氏距离？** 因为归一化到球面后，只剩"方向"有意义——方向代表"是谁"，长度（可能受光照、清晰度影响）被归一化掉了。这也是几乎所有现代人脸识别系统都在**单位球面上比角度**的原因。

> 📖 **术语**：**embedding（嵌入 / 特征向量）**。把一个复杂对象（人脸图）压缩成的一个低维向量，使得"语义相近"对应"向量相近"。人脸 embedding 也叫 **face feature / faceprint（人脸指纹）**。一次注册就是"存下这个人的 embedding"，比对就是"算余弦相似度"。

### 度量学习：直接优化"远近"

怎么训练网络产生这样的 embedding？**度量学习**的核心是"直接对距离下手"：

- **对比损失（contrastive）**：给一对样本，同人就拉近、异人就推远（推到某个间隔之外）。
- **三元组损失（triplet）**：一次给三张脸——锚点 a、同人 p、异人 n，要求"a 到 p 比 a 到 n 近至少一个间隔 \\( \alpha \\)"：

\\[ L_{tri} = \max\big(0,\ d(a,p) - d(a,n) + \alpha\big) \\]

三元组损失很直观，但**难训**：绝大多数随机三元组都"太简单"（异人本来就离得远，损失为 0，没梯度），必须费心做**难样本挖掘**，还容易训崩。所以工业界更爱另一条路——**margin-softmax（间隔 softmax）**，其中最出名的就是 **ArcFace**。

### ArcFace：把"分类"改造成"利于比对"

ArcFace 的巧思是：**仍然用 softmax 分类来训练**（稳、好收敛），但动两处手脚，让学出的 embedding 天生适合"比距离"。

**第一处：归一化。** 把特征 \\( \hat{f} \\) 和每个类别的权重向量 \\( \hat{W}_j \\) 都 L2 归一化。这样分类打分 \\( \hat{W}_j \cdot \hat{f} = \cos\theta_j \\) 就是"特征与第 \\( j \\) 类中心的夹角余弦"——**训练用的度量（余弦）和比对用的度量（余弦）完全一致**。普通 softmax 用的是没归一化的内积，训练和比对对不上，这是它先天不利于比对的原因。

**第二处：角度间隔。** 对**真值类别**，把夹角**硬加上一个间隔** \\( m \\) 再算 softmax：

\\[ L = -\frac{1}{N}\sum_i \log \frac{e^{s\cos(\theta_{y_i}+m)}}{e^{s\cos(\theta_{y_i}+m)} + \sum_{j\ne y_i} e^{s\cos\theta_j}} \\]

其中 \\( s \\) 是缩放尺度，\\( m \\) 是角度间隔（本章 0.5 弧度）。因为要求"哪怕把真值角度**多掰开 \\( m \\)**、它仍是最大分"，网络被逼着把同类特征**压得更紧、把异类推得更开**。展开用 \\( \cos(\theta+m) = \cos\theta\cos m - \sin\theta\sin m \\)（\\( \sin\theta = \sqrt{1 - \cos^2\theta} \\)）即可算。\\( m = 0 \\) 时它退化成"归一化 softmax"（无间隔）——这正好给了我们一个**干净的对照实验**。

```text
普通 softmax：只要分对就行 → 同类可能松散、决策边界贴着样本
ArcFace：真值角度先 +m 再比 → 逼出“类内更紧、类间更宽”的余量
   类内  ● ● ●        ← softmax：够用就好
   类内  ●●●    间隔m  ← ArcFace：留出安全余量，比对时更稳
```

### 注册-比对：1:1 与 1:N

训好 embedding 网络后，实际使用分两种：

- **1:1 verification（验证）**：给两张脸，判断"是不是同一个人"（刷脸解锁、人证核验）。算余弦相似度，**过阈值就判"同人"**。
- **1:N identification（辨识）**：给一张脸，在一个 \\( N \\) 人的**注册库（gallery）**里找"这是谁"（门禁考勤、以脸搜人）。和库里每个人的 embedding 算相似度，**取最近的那个**（可再加阈值拒识陌生人）。

评价 verification 光看"准确率"不够，工业界更看 **TAR@FAR**：把**误接受率 FAR**（把异人误判成同人的比例）压到某个很低的水平（如 1%），再看**通过率 TAR**（同人被正确接受的比例）。门禁宁可偶尔让你多刷一次（TAR 低一点），也不能随便放陌生人进来（FAR 必须低）——所以"FAR=1% 时的 TAR"才是真正贴合业务的指标。

## 动手：训一个人脸 embedding，比对新身份（candle）

> ⚠️ **注意**：本章代码基于 **candle 0.11.0**，纯 CPU。完整独立工程见 `code/dl_labs/ch57_face_recog/`，`cd` 进去 `cargo run --release` 即可复现。`Cargo.toml` 依赖 `candle-core`/`candle-nn`/`image`（含空 `[workspace]` 隔离）。

### 合成"多身份"人脸

每个**身份**由一组固定的**五官参数**定义——肤色、脸型比例、双眼间距、眼睛大小、嘴宽等（这些就是"身份特征"）。同一身份的多张"照片"再叠加**类内扰动**：位置 ±1.5px、尺度 ±6%、全局亮度、像素噪声。**身份信号藏在五官几何里，扰动不改变身份**——这正对应真实人脸识别：在**已对齐**的人脸上（[第 54 章](../p11-keypoints/ch54-face-landmarks.md)），姿态位置已被摆正，剩下的差异才是"谁"。

```rust
struct Id { sk: f32, warm: f32, aspect: f32, eye_dx: f32, eye_dy: f32, eye_r: f32, mouth_w: f32 }
// 眼睛间距 eye_dx、脸型 aspect、肤色 sk…… 每个身份一套固定参数；render() 时加类内扰动
```

关键设计：**先造好所有身份，前 16 个用于训练，后 8 个留作验证——身份不重叠**。这样验证的是"网络对**从没见过的人**能不能认出同人异人"，也就是真正的**开集**能力（真实人脸识别就是要认没登记过训练的人脸）。

### embedding 网络 + ArcFace 头

骨干是熟悉的三段卷积 + 一个全连接，输出 32 维特征（**不加最后的 relu**，方向可正可负）：

```rust
struct Embed { conv1: Conv2d, conv2: Conv2d, conv3: Conv2d, fc: Linear }
// 32x32 →(conv+pool)×3→ 4x4x64 → flatten → fc → [N, 32]
```

ArcFace 的"类别中心"就是一个 `linear_no_bias` 的权重矩阵 \\( W \\)（形状 `[身份数, 32]`）。训练时把特征和 \\( W \\) 都归一化、算余弦、加间隔：

```rust
fn arcface_logits(cos: &Tensor, one_hot: &Tensor, s: f64, m: f64) -> Result<Tensor> {
    if m == 0.0 { return cos.affine(s, 0.0); }        // 无间隔：退化成归一化 softmax（对照组）
    let (cos_m, sin_m) = (m.cos(), m.sin());
    let sin = cos.sqr()?.affine(-1.0, 1.0)?.relu()?.sqrt()?; // sinθ=√max(1-cos²,0)，relu 防负数开根
    let phi = cos.affine(cos_m, 0.0)?.broadcast_sub(&sin.affine(sin_m, 0.0)?)?; // cos(θ+m)
    let diff = phi.broadcast_sub(cos)?;                // 只给真值类别换成带间隔的 phi
    let out = cos.broadcast_add(&one_hot.broadcast_mul(&diff)?)?; // out = cos + onehot·(phi-cos)
    out.affine(s, 0.0)
}
```

> 🕳️ **坑**：**算 \\( \sin\theta = \sqrt{1-\cos^2\theta} \\) 时，`1-cos²` 可能因浮点误差微微为负**，直接开根号得 NaN。这里用 `.relu()` 把负数截成 0 再开根，既稳又不用额外的 clamp API。归一化后的余弦本应在 \\( [-1,1] \\)，但别信浮点，一定兜底。

训练损失就是把 ArcFace logits 喂给 `candle_nn::loss::cross_entropy`（标签是 **U32**），`AdamW` 反向。归一化用一个小工具：

```rust
fn l2norm(t: &Tensor) -> Result<Tensor> {
    let n = t.sqr()?.sum_keepdim(1)?.affine(1.0, 1e-12)?.sqrt()?; // 每行模长(加 eps 防除零)
    t.broadcast_div(&n)
}
```

### 受控对照：只改 margin 一个变量

为了看清"角度间隔到底值多少"，我们跑**两次训练**：`margin=0`（普通归一化 softmax）和 `margin=0.5`（ArcFace），**数据、初始化、轮数、尺度全部相同**（固定种子），只差这一个变量——这是 [第 47 章](../p09-detection/ch47-train-detector.md) 那套"单变量消融"纪律的又一次实践。两者都训到训练准确率 100%：

```text
=== 训练 A：普通归一化 softmax（margin=0）===
    epoch 160  loss=0.0155  train_acc=1.000
=== 训练 B：ArcFace 角度间隔（margin=0.50）===
    epoch 160  loss=0.0568  train_acc=1.000
```

注意 ArcFace 的 loss 收敛得"慢"、终值更高（0.057 vs 0.016）——**这不是它更差，恰恰是间隔在起作用**：它给自己出了更难的题（角度要多掰开 0.5 才算对），所以训练损失显得高，但学出的 embedding 更能打。见真章的是**在新身份上的比对**：

### 真实比对结果（全在"训练没见过"的 8 个新身份上）

```text
================= 新身份（开集）比对结果对比 =================
指标                           普通softmax       ArcFace
同人对 平均余弦相似度                      0.661         0.698
异人对 平均余弦相似度                     -0.018         0.015
同异相似度间隔(差)                        0.680         0.683
类内平均距离(1-cos)                     0.339         0.302
类间平均距离(1-cos)                     1.018         0.985
最佳阈值验证准确率                        94.7%         96.3%
（对应最佳阈值）                          0.57          0.56
TAR@FAR=10%                        96.0%         98.3%
TAR@FAR=1%                         49.1%         69.3%
1:N 识别准确率                         88.6%         89.8%
```

**读懂这张表：**

- **同人相似度 0.66/0.70，异人相似度约 0（-0.02/0.02）**——两条分布拉得很开：同一个人的两张脸向量夹角很小（余弦大），不同人的几乎正交（余弦≈0）。这正是"好指纹"该有的样子，而且是在**训练从没见过的人**上做到的。
- **验证准确率 94.7% → 96.3%**：只加了角度间隔，就涨了 1.6 个百分点。
- **最亮眼的是 TAR@FAR=1%：49.1% → 69.3%**！在"严禁误放陌生人"（FAR 压到 1%）这个**最贴近门禁业务**的苛刻工作点上，ArcFace 让通过率从"一半都过不了"猛增到近七成。**这就是角度间隔对"比对"的真正价值**——它在决策边界附近留出了安全余量，越是严格的阈值，余量越值钱。
- **1:N 识别 88.6% → 89.8%**：每个新身份只"注册"1 张，其余作探针最近邻辨识，也稳稳提升。

> 💡 **提示**：TAR@FAR=10% 时两者都很高（96% vs 98%），差距不大；但把 FAR 收紧到 1%，差距立刻拉开到 20 个百分点。**评价比对系统一定要看你真实业务能容忍的那个 FAR 下的 TAR**，只报"最佳准确率"会严重高估系统在严格阈值下的表现。

## 常见坑与提示

> 🕳️ **坑**：**别用分类准确率评价识别系统。** 训练时的分类准确率两组都是 100%，可比对能力差了 20 个百分点（TAR@FAR=1%）。识别的正确指标是**在未见身份上的**验证准确率 / TAR@FAR / 类内类间分离度，绝不是训练分类精度。分类精度高只说明"训练身份记住了"，不代表 embedding 泛化得好。

> ⚠️ **注意**：**训练和比对的度量必须一致。** ArcFace 之所以强，一半功劳在**归一化**——训练用余弦、比对也用余弦。普通 softmax 训练用未归一化内积、比对却用余弦，两者对不上，先天吃亏。自己搭识别网络时，务必让"训练时怎么比"和"上线时怎么比"是同一种度量。

> 🕳️ **坑**：**阈值必须在有代表性的数据上定，不能拍脑袋。** 本章最佳阈值约 0.57，但这是合成数据上的值。真实系统的阈值要在**贴近线上分布**的验证集上，**按业务能容忍的 FAR** 来定；换了摄像头、光照、人群，阈值可能要重标。把 0.5 当万能阈值是新手常见错误。

> ⚠️ **注意**：**识别高度依赖前面的检测与对齐。** 脸没摆正、尺度不一，embedding 就会把"姿态差异"误当成"身份差异"。本章特意在**已对齐**的人脸上做识别（脸居中、尺度接近）——真实流水线里，[第 56 章](ch56-face-detection.md) 检测 + [第 54 章](../p11-keypoints/ch54-face-landmarks.md) 对齐没做好，再强的识别网络也带不动。

> 💡 **提示**：**合成数据的漂亮数字别当真。** 我们的"身份"是几张参数一变的几何脸，天然好分。真实人脸识别要面对同卵双胞胎、年龄跨度、妆容、口罩、跨种族公平性等硬骨头，还有**注册照与抓拍照的域差异**。工业级模型（ArcFace/CosFace 等）都在**百万级身份**上训练、在标准 benchmark（如 LFW、IJB）上按 TAR@FAR 评测。本章讲的是**原理与管线**，数字仅用于对比 margin 的效果。

> 📖 **术语**：**ArcFace / CosFace / SphereFace**。都是 margin-softmax 家族：SphereFace 乘性角度间隔、ArcFace 加性角度间隔（\\( \cos(\theta+m) \\)）、CosFace 加性余弦间隔（\\( \cos\theta - m \\)）。思路一致——归一化 + 间隔，逼出类内紧、类间宽的 embedding。CosFace 省掉了开根号那步、更稳，是本章"坑"里那个 NaN 风险的另一种规避法。

## 本章小结

- **人脸识别 = 把脸映射成 L2 归一化向量（embedding），用余弦相似度比对。** 注册即存向量、比对即算相似度，加新用户**无需重训**——这就是它不做"每人一类"分类的根本原因。
- **度量学习**直接优化"同人近、异人远"：三元组损失直观但难训（要难样本挖掘），**ArcFace 用归一化 + 角度间隔的 margin-softmax**，稳且强。
- ArcFace 两处关键改造：① 特征与类中心都**归一化**，让训练度量与比对度量一致；② 对真值类别**加角度间隔 \\( m \\)**，逼出类内紧、类间宽的余量。
- **实测（全在训练未见的新身份上）**：只把 margin 从 0 加到 0.5，验证准确率 **94.7%→96.3%**，而最贴合门禁业务的 **TAR@FAR=1% 从 49.1% 猛增到 69.3%**，1:N 识别 88.6%→89.8%。角度间隔的价值在严格阈值下最为显著。
- **1:1 verification**（是不是同一人，过阈值）与 **1:N identification**（在库里找是谁，取最近邻）是识别的两种落地形态；评价务必看**业务可容忍 FAR 下的 TAR**，别只报最佳准确率。

## 动手练习

1. **扫描 margin**：把 `margin` 取 0.0 / 0.2 / 0.35 / 0.5 各跑一遍，把 TAR@FAR=1% 画成曲线，找出你合成数据上的"甜点"——太大也会训不动，体会间隔的两面性。
2. **换成 CosFace**：把角度间隔 \\( \cos(\theta+m) \\) 换成余弦间隔 \\( \cos\theta - m \\)（就是 `arcface_logits` 里 `phi = cos - m` 对真值类别），省掉开根号，对比稳定性与指标。
3. **改 embedding 维度**：把 `EMB` 从 32 改成 8 和 128，看比对准确率与"指纹"存储成本怎么权衡——维度不是越高越好。
4. **画相似度直方图**：把同人对、异人对的余弦相似度各自分桶统计，用 ASCII 直方图打印出来，直观看两条分布随 margin 变化怎么被推开（呼应 [第 12 章](../p02-image-basics/ch12-histogram.md) 的直方图思想）。
5. **想一想**：一个 10 万人的刷脸门禁，1:N 每次都和 10 万个 embedding 比对太慢。你会怎么加速？（提示：向量检索 / 近似最近邻，呼应 [第 28 章](../p04-features/ch28-bovw-retrieval.md) 的检索思想。）
