# 第 58 章 活体检测与人脸属性分析

> **本章导读**
> - 学完你能：给人脸系统补上两块关键拼图——**活体检测（反欺骗）** 识破照片、屏幕翻拍这类"假脸"攻击；**人脸属性分析** 用一个骨干 + 多个头，一次前向读出眼镜/表情/帽子等多个属性。
> - 活体你会走**两条路**：手工特征（明暗 + 高频能量）阈值判别 vs 小 CNN，都报真实准确率，直观看到"学出来的特征"强在哪。
> - 属性你会亲手搭**多任务网络**（共享骨干 + 多分类头），报每个属性的真实准确率，理解"共享表示"为何省算力又互相促进。
> - 代码在本机 `cargo run --release` 实测，数字均为真实输出；并**诚实标注纯 RGB 单帧活体的局限**。

## 场景：举着你的照片，能骗过刷脸吗？

[第 57 章](ch57-face-recognition.md) 的识别网络只回答"这张脸**像不像**你"，它可管不着"这是不是一张**活人**的脸"。于是攻击者有了可乘之机：举一张你的**打印照片**、播放一段你的**手机视频**、甚至戴一个你的 **3D 面具**对着摄像头——识别网络很可能照样说"像，是本人"。这是人脸系统最要命的安全漏洞。

**活体检测（liveness detection / anti-spoofing，反欺骗）** 就是挡在识别**之前**的那道防线：先确认"这是一张真人的、活的脸"，再谈"是谁"。顺带地，很多系统还想从脸上读出些**属性**——性别、年龄段、表情、有没有戴眼镜/口罩，用于人群统计、人机交互，或给识别加辅助线索。这两件事——**安全的活体、附加的属性**——正是补全人脸流水线的最后一块。

## 原理一：活体检测——真假脸差在哪

**直觉**：真人的脸是**立体的、有生命的**；假体是**平的、印刷或显示出来的**。这些物理差异会在图像里留下痕迹：

- **打印照片攻击**：一张纸是**平的**，没有真脸那种随 3D 形状产生的**明暗渐变（shading）**；油墨动态范围有限，画面**发灰、对比低**；放大还能看到印刷网点。
- **屏幕翻拍攻击**：拿手机/屏幕播放录像。屏幕由密集像素栅格构成，它与相机传感器的栅格叠加会产生**摩尔纹（moiré）**——一种高频周期性条纹（[第 22 章](../p03-classic/ch22-frequency.md) 讲过这种"栅格拍频"），还常伴随偏色、反光、屏幕边框。
- **面具 / 3D 攻击**：有立体感，但材质、纹理、微表情与真皮肤不同——更难，常需红外或深度才能破。

> 📖 **术语**：**PAD（Presentation Attack Detection，呈现攻击检测）** 是活体检测的学术叫法；照片/屏幕/面具这些统称**呈现攻击（presentation attack）** 或 **spoof（假体）**。评价活体常看两个错误率：**APCER**（把假体误判成真人的比例，安全命门）与 **BPCER**（把真人误判成假体、误拒的比例，体验命门）。

技术上有两条路（[第 27 章](../p04-features/ch27-handcrafted-features.md) 的手工特征思路在此复用）：

1. **手工特征 + 分类器**：提取纹理（LBP）、频域高频能量（FFT / 拉普拉斯）、色彩等，喂给简单分类器。直觉强、轻量、可解释。
2. **端到端 CNN**：直接让网络从像素里学"真 / 假"的判别特征。

本章两条都做，用真实数字对比。

> ⚠️ **注意（诚实边界，务必牢记）**：**单帧 RGB 的活体检测天生有限。** 攻击者只要提高照片/屏幕质量，单帧线索就会失效。工业级活体普遍**上多模态**：**深度相机**（结构光 / ToF，直接看是不是平的）、**红外**（屏幕在红外下发黑、真皮肤有特定反射）、**多帧动作配合**（让你眨眼 / 转头 / 张嘴的 challenge-response）、甚至 **rPPG**（从面部微小颜色变化估计心率，纸和屏幕没有脉搏）。本章合成数据上的漂亮数字，**别当成真实世界的水平**。

## 原理二：属性分析——一个骨干，多个头

要同时判断"戴没戴眼镜、笑没笑、戴没戴帽子"，难道训三个网络？太浪费。**多任务学习（multi-task learning）** 的做法是：**一个骨干抽取共享特征，接多个"头"各管一个任务**。

```text
                        ┌──▶ 头1：眼镜？ → 是/否
输入人脸 ─▶ 共享骨干CNN ─┼──▶ 头2：微笑？ → 是/否
          (抽共享特征)   └──▶ 头3：帽子？ → 是/否
```

总损失是各任务损失之和（可加权）：

\\[ L = \sum_k \lambda_k L_k \\]

好处三条：① **省算力**——骨干只跑一次，多个输出白捡；② **共享表示互相促进**——"人脸长什么样"的底层特征被多个任务复用，还起到正则作用，数据少时尤其划算（呼应 [第 43 章](../p08-classification/ch43-finetune.md) 的迁移思想）；③ **部署简单**——一个模型、一次前向出全部属性。这正是 [第 56 章](ch56-face-detection.md) 检测器"框 + 关键点"多头思想在分类上的翻版。

## 动手写代码（candle）

> ⚠️ **注意**：基于 **candle 0.11.0**，纯 CPU。完整独立工程见 `code/dl_labs/ch58_liveness_attr/`，`cd` 进去 `cargo run --release` 即可复现（`Cargo.toml` 依赖 `candle-core`/`candle-nn`/`image`，含空 `[workspace]` 隔离）。

### 把物理差异写进合成数据

活体这一步的灵魂在**合成**：把真假脸的物理差异如实画出来。真人加 **3D 明暗渐变** + 皮肤纹理噪声；打印**压低对比**（扁平）；屏幕**叠加摩尔纹**：

```rust
// 真人/屏幕：椭圆脸带方向性明暗（模拟 3D 受光）；打印：ramp 关掉 → 扁平
if ramp { base += shade_k * (dx * lx + dy * ly); }
// 打印照片：全局压低对比，发灰扁平
if Print { each_channel = 128.0 + (c - 128.0) * 0.55; }
// 屏幕翻拍：叠加高频摩尔纹正弦 + 轻微偏色
if Screen { let m = 1.0 + amp * (2π*(fx*x + fy*y)/IMG + ph).sin(); c *= m; }
```

### 两把手工尺子：明暗能量 + 高频能量

- **明暗能量**：中央区分成小块，取**块均值的方差**——真人 3D 明暗渐变让方差大，打印扁平让方差小。
- **高频能量**：**脸颊皮肤区**的拉普拉斯响应平方均值——屏幕摩尔纹让它飙高，打印平滑让它低。

> 🕳️ **坑（真踩过）**：**高频特征一定要在平滑皮肤区（脸颊）上测，不能在整脸上测。** 我一开始在中央整个区域算拉普拉斯，结果**眼睛、嘴的强边缘**产生的巨大响应把摩尔纹信号彻底淹没了，屏幕和真人根本分不开。改到脸颊 patch（避开五官边缘）后，摩尔纹才凸显出来。选特征区域，和选特征本身一样重要。

实测各类型的特征均值（训练集），可分性一目了然：

```text
  手工特征各类型均值（训练集）：
    明暗能量  真人= 1312.6  打印=  372.5  屏幕= 1291.8   (真人/屏幕高、打印低)
    高频能量  真人= 9184.5  打印= 2589.3  屏幕=11936.7   (屏幕摩尔纹最高)
```

看规律：**明暗**能把"打印"（372，扁平）从真人（1313）里揪出来，但屏幕（1292）和真人差不多；**高频**能把"屏幕"（11937，摩尔纹）揪出来，但真人（9184）和它有重叠。所以**单一特征都不够**，得两把尺子一起用——真人 iff `明暗 >= t1 且 高频 <= t2`：

```text
    规则阈值：明暗>= 842.5 且 高频<= 10560.6 → 判真人
    手工特征两阈值规则  测试准确率 = 69.0%
```

### 小 CNN 二分类：让网络自己学判别特征

同样的骨干（3 段卷积 + 全连接 → 64 维特征），接一个二分类头（真 / 假），`cross_entropy` 训练：

```text
  训练小 CNN 活体分类器（AdamW lr=1e-3）...
    epoch  34  loss=0.4345  train_acc=0.780
    epoch 170  loss=0.0402  train_acc=0.997

  ==== 活体检测结果（测试集）====
    手工特征规则 准确率 = 69.0%
    小 CNN       准确率 = 99.0%
    CNN 分类型正确率：真人 134/135、打印攻击 79/79、屏幕翻拍 84/86
```

**手工两阈值规则 69.0%，小 CNN 99.0%**——CNN 大幅胜出。分类型看：打印攻击最好识破（79/79，扁平 + 低对比太明显），屏幕翻拍最难（84/86，摩尔纹强弱不一时，单帧里和皮肤纹理会撞车）。这条"手工特征捕捉直觉、CNN 学得更好"的对比，正是深度学习在感知任务上的典型优势；但请记住上面那条诚实边界——**这是干净的合成数据，真实屏幕翻拍远比这难**。

### 属性多任务：一个骨干 + 三个头

合成真人脸，随机赋 **眼镜 / 微笑 / 帽子** 三个独立二值属性；网络共享骨干、接 3 个分类头，损失是三项交叉熵之和：

```rust
let feat = bb.forward(&xtr)?;                       // 骨干只跑一次
let mut loss = cross_entropy(&heads[0].forward(&feat)?, &ytr_t[0])?;
for i in 1..3 { loss = loss.broadcast_add(&cross_entropy(&heads[i].forward(&feat)?, &ytr_t[i])?)?; }
opt.backward_step(&loss)?;                           // 一次反向更新全部头 + 骨干
```

逐属性测试准确率：

```text
  ==== 属性分析结果（测试集，逐属性准确率）====
    眼镜   准确率 = 100.0%
    微笑   准确率 = 100.0%
    帽子   准确率 = 100.0%
    三属性平均准确率 = 100.0%
```

三个属性都学得很好（合成属性视觉上清晰无歧义，故准确率高）。要点不在这个漂亮的 100%，而在**一个骨干喂三个头、一次前向出三个属性**的多任务结构——真实系统里把它换成年龄 / 性别 / 表情等更难的属性，结构分毫不动，只是每个头的准确率会实打实地掉下来。

## 常见坑与提示

> 🕳️ **坑（本章真踩、值得所有人记住）**：**确定性 RNG 造数据做离散选择时，默认一律走高位。** 我一开始用 `rng.next() % 4` 选真/打印/屏幕、用 `next() & 1` 掷布尔属性，结果**"屏幕翻拍"类一个样本都没生成**、布尔属性也几乎恒定——因为**线性同余发生器（LCG）第 \\(k\\) 低位的周期只有 \\(2^k\\)**（最低位就是严格 0/1/0/1 交替）。这里踩中的正是两个**真地雷**：**`& 1` 取最低位掷布尔**（周期 2、几乎恒定），和**对 2 的幂取模 `% 4`**（等于只取最低那两位）——它俩直接抽出一个退化序列。**改用高位**（本章统一走 `unit()`，它取 `>>11` 的高 53 位，整数用 `(unit()*n) as usize`、布尔用 `unit() < 0.5`）就正常了。⚠️ 严格说，对**非 2 的幂**的 `n` 做 `next() % n` 会好不少（取模把高位也搅进来，不会退化成 2/4 周期），本书别处的合成数据就是这么用的、结果稳定可复现；但 LCG 的格点结构仍让它质量平平。**与其每次判断 `n` 是不是 2 的幂，不如养成"离散选择一律走高位"的肌肉记忆**——它永远安全。教训：LCG 低位周期极短，`& 1` 和对 2 的幂取模是真正的坑，取整数优先用高位或专门的高质量发生器。

> 🕳️ **坑**：**手工高频特征要挑平滑皮肤区测。** 眼睛/嘴的强边缘会在拉普拉斯上产生远大于摩尔纹的响应，淹没你想要的信号。特征"在哪测"和"测什么"同等重要。

> ⚠️ **注意**：**活体是安全前置关卡，要放在识别之前，且判不准时保守拒绝。** 顺序错了（先识别后活体）等于没设防。而且活体的两类错误代价不对称——**放进一个假体（APCER 高）比误拒一个真人（BPCER 高）严重得多**，阈值要偏保守：宁可让真人多刷一次，也别放行假脸。

> ⚠️ **注意**：**多任务要平衡各任务。** 不同任务的损失尺度、难度不同，常需给 \\( \lambda_k \\) 加权；把**无关**任务硬塞进一个骨干还可能互相拖累（负迁移 negative transfer）。任务相关时共享才划算。

> ⚠️ **注意（伦理与合规）**：**人脸属性（年龄、性别等）涉及隐私与算法偏见。** 采集要合规、告知与授权到位；评测必须**分人群看公平性**（不同肤色、性别、年龄的准确率差异），别让一个漂亮的总体数字掩盖对某个群体的系统性歧视。活体与属性都是"能力越强、越要负责任"的技术。

## 本章小结

- **活体检测（反欺骗）** 是识别之前的安全关卡：靠真假脸的物理差异——真人有 **3D 明暗**与自然皮肤纹理，打印**扁平低对比**，屏幕翻拍带**摩尔纹**（高频周期）。
- 两条技术路线实测对比：**手工特征（明暗能量 + 脸颊高频能量）两阈值规则 69.0%**，**小 CNN 99.0%**；分类型看打印最易识破、**屏幕翻拍最难**（84/86）。CNN 学到的判别特征明显强于单一手工特征。
- **诚实边界**：单帧 RGB 活体天生有限，合成数据上的高分不代表真实水平；工业级活体要上**深度 / 红外 / 多帧动作配合 / rPPG** 等多模态。
- **属性分析用多任务**：一个骨干 + 多个分类头，损失求和、一次前向出全部属性；省算力、共享表示互促、部署简单。实测三属性（眼镜/微笑/帽子）准确率各 100%（合成属性清晰所致，真实属性会更难）。
- **两个真实的坑**：① LCG 低位周期极短（`& 1`、对 2 的幂取模是真地雷），离散选择一律走高位最省心；② 手工高频特征要在平滑皮肤区测，别被五官边缘淹没。

## 动手练习

1. **提高攻击质量**：把打印的对比压缩系数从 0.55 调到 0.8（更接近真脸）、把摩尔纹幅度调小，重跑，看手工规则和 CNN 的准确率各掉多少——**亲手体会"攻防升级"里防守方的被动**。
2. **补 LBP 特征**：仿 [第 27 章](../p04-features/ch27-handcrafted-features.md) 给每张脸算 LBP 直方图作为第三个手工特征，加进规则或喂给一个小分类器，看能不能把 69% 往上抬。
3. **加一类攻击**：新增"面具"类（3D 明暗保留、但叠加异常斑块纹理），把活体做成三分类（真人/打印/屏幕）或多加一类假体，观察 CNN 混淆矩阵，找出最难分的一对。
4. **多任务消融**：把三个属性拆成三个**单任务**网络分别训练，与多任务版比准确率和总参数量/训练时间——验证"共享骨干"到底省了多少、有没有损失精度。
5. **想一想**：你的刷脸门禁要求"绝不放进假体"。你会把活体阈值往哪个方向调？这会牺牲什么体验？如果预算允许加一个传感器，你选深度相机还是红外，为什么？
