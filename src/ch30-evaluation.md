# 第 30 章 · 模型评估与度量：mAP、PR 曲线与阈值决策

> **本章导读**：到第 29 章为止，你的程序已经能 7×24 稳定地吐检测框了。但一个资深工程师每天要回答的头号问题不是"能不能跑"，而是——**"它到底准不准？准到能上线吗？换了个新模型，是变好了还是偷偷变差了？"** 这些问题不能靠"我看画面里框得挺准"来拍脑袋，必须有**能算出来的数字**。这一章把机器视觉最核心的一套评估语言讲透：从 TP/FP/FN 的原点出发，到精确率/召回率/F1，再到检测领域的黄金标准 **mAP**，最后落到最实用的两件事——**怎么用业务成本反推该设多少阈值**、**新模型上线前怎么做版本回归**。这一章几乎不引入新模型，却是"会用模型"和"能对模型负责"之间的分水岭。读完你就有了一把尺子，能给任何一个模型打出可信的分数。

## 30.1 为什么必须量化评估：肉眼看"挺准"是错觉

先讲个真实会踩的坑。你训练/拿到一个人形检测模型，翻了几十张测试图，"框得挺准啊"，于是上线。结果跑了一周，运维投诉两件事：**白天误报一堆**（把假人、影子当人），**夜里又老是漏报**（黑暗里的人检不出）。你翻的那几十张图，恰好都是光照良好、人站得清清楚楚的"简单样本"——**肉眼抽查天然偏向容易的样本，看到的是幸存者偏差**。

量化评估要做的，是把"准不准"这个模糊感受，拆成一组**能复现、能比较、能对着定决策**的数字：

- **能复现**：同一个模型、同一个测试集，今天算和明天算，得出一模一样的分数。
- **能比较**：模型 A 得 0.82，模型 B 得 0.86，你能理直气壮说 B 更好，好在哪。
- **能定决策**：分数告诉你阈值该设 0.4 还是 0.6、这模型能不能上变电站这种"漏报要人命"的场景。

一句话：**没有评估数字，你对模型的一切判断都是猜的。** 这一章就是教你把猜变成算。

## 30.2 一切的原点：TP / FP / FN 与混淆矩阵

评估的最小积木只有四个词，先用**医院筛查**这个生活场景记住它们。假设一台仪器筛查某种病，"阳性"= 仪器说"有病"：

- **TP（True Positive，真阳）**：真有病，仪器也说有病 —— **报对了**。
- **FP（False Positive，假阳）**：没病，仪器却说有病 —— **误报**（虚惊一场）。
- **FN（False Negative，假阴）**：真有病，仪器却说没病 —— **漏报**（最危险）。
- **TN（True Negative，真阴）**：没病，仪器也说没病 —— **对的沉默**。

搬到检测里，"阳性"就是"模型报了一个框"：

| 术语 | 检测里的含义 | 一句话 |
| --- | --- | --- |
| **TP** | 报的框，确实框中了一个真目标 | 报对了 |
| **FP** | 报的框，没对上任何真目标 | 误报（画面里那个"框住了影子"的框） |
| **FN** | 真目标存在，却没有任何框框中它 | 漏报（那个没被检出的人） |
| **TN** | 检测里几乎不用（"没目标也没报"无从计数） | —— |

把它们排成一张 2×2 表，就是**混淆矩阵（confusion matrix）**：

```text
                  真实情况
                有目标        无目标
预测  报了框   │  TP        │  FP        │
      没报     │  FN        │  TN(不计)  │
```

> **注意检测与分类的一个关键区别**：分类问题里"一张图属于哪类"是干脆的，TN 有意义；而检测是"在图里找目标"，背景无穷多，"没目标的地方也没报"没法计数，所以**检测评估里基本只用 TP / FP / FN 三个**。记住这点，下面的公式就不会用错。

## 30.3 检测特有的一步：靠 IoU 判定"框对了没"

分类里判断"对不对"很简单——预测类别等于真值类别即可。但检测多了一层：模型报了一个框，怎么算"框中了"真目标？框的位置差一点点算不算对？

答案是用第 16 章、第 22 章反复用到的 **IoU（交并比）**：预测框与真值框的重叠程度。约定一个 **IoU 阈值**（最常用 0.5），**IoU ≥ 阈值才算这个预测"命中"了那个真值**：

```text
预测框 ┌───────┐
       │   ┌───┼───┐ 真值框      IoU = 交集面积 / 并集面积
       │   │███│   │            ≥ 0.5 → 命中(TP)
       └───┼───┘   │            < 0.5 → 没中(FP)
           └───────┘
```

一个真值只能被**一个**预测认领。于是同一张图里，判定规则是：

1. 把本类的预测框按**分数从高到低**排序（高分的优先挑真值）。
2. 每个预测去找**IoU 最大、且还没被别人占用**的同类真值框。
3. 找到且 IoU ≥ 阈值 → 这个预测是 **TP**，占用该真值；否则是 **FP**。
4. 全部预测判完后，**没被任何预测占用的真值 → FN**（漏报）。

第 3 步的"占用"很关键：它自动把**重复框**判成 FP——两个框都框住同一个人，只有分数高的那个算 TP，另一个抢不到真值，变成 FP。这正好惩罚了"对一个目标狂报好几个框"的坏模型，也解释了为什么 NMS（第 16 章）没做好会拉低 mAP。

用 Rust 把"单张图、单类别"的 TP/FP 判定写出来（复用全书统一的 `BBox`/`Detection`，`BBox::iou` 是第 16 章造好的）：

```rust,ignore
use crate::{BBox, Detection}; // 第16章统一类型：Detection{ bbox, score, class_id }

/// 单张图、单类别：把每个预测判成 TP(true) 或 FP(false)，并返回漏掉的真值数(FN)
/// 返回：(每个预测的 TP/FP 标记 + 其分数, 该图该类的 FN 个数)
fn match_one_image(
    mut preds: Vec<Detection>, // 已筛成同一类别的预测
    gts: &[BBox],              // 同一类别的真值框
    iou_thr: f32,
) -> (Vec<(f32, bool)>, usize) {
    // ① 高分优先：分数降序，用 total_cmp 避免 NaN 破坏排序（第16章的教训）
    preds.sort_by(|a, b| b.score.total_cmp(&a.score));

    let mut gt_taken = vec![false; gts.len()]; // 每个真值是否已被认领
    let mut flags = Vec::with_capacity(preds.len());

    for p in &preds {
        // ② 找 IoU 最大、且未被占用的同类真值
        let mut best_iou = 0.0f32;
        let mut best_j = None;
        for (j, g) in gts.iter().enumerate() {
            if gt_taken[j] { continue; }
            let iou = p.bbox.iou(g);
            if iou > best_iou {
                best_iou = iou;
                best_j = Some(j);
            }
        }
        // ③ IoU 够大才算命中；命中就占用那个真值（后来者抢不到 → 重复框判 FP）
        if let Some(j) = best_j.filter(|_| best_iou >= iou_thr) {
            gt_taken[j] = true;
            flags.push((p.score, true));   // TP
        } else {
            flags.push((p.score, false));  // FP
        }
    }

    // ④ 没被认领的真值 = 漏报 FN
    let fn_count = gt_taken.iter().filter(|&&taken| !taken).count();
    (flags, fn_count)
}
```

## 30.4 精确率、召回率与 F1：你更怕误报还是漏报

有了 TP/FP/FN，就能算两个最重要的指标。它们是一对"跷跷板"，理解它们的对立是理解一切评估的钥匙。

**精确率（Precision，查准率）**：你报出来的框里，有多少是对的？

$$
\text{Precision} = \frac{TP}{TP + FP} = \frac{\text{报对的}}{\text{一共报的}}
$$

**召回率（Recall，查全率）**：真实存在的目标里，你找回来了多少？

$$
\text{Recall} = \frac{TP}{TP + FN} = \frac{\text{找回的}}{\text{一共该找的}}
$$

用一句大白话记牢它俩的分母：**精确率的分母是"你报的"（怕误报就看它），召回率的分母是"该找的"（怕漏报就看它）。**

**手算一遍**。测试集里一共有 100 个真人（GT=100）。模型报了 80 个框，其中 70 个框对了（TP=70）、10 个是误报（FP=10）；剩下 30 个真人没检出（FN=30）：

$$
\text{Precision} = \frac{70}{70+10} = 0.875, \qquad \text{Recall} = \frac{70}{70+30} = 0.70
$$

意思是：**报出来的框 87.5% 靠谱，但只找回了 70% 的人**，还有 30% 漏了。

**跷跷板效应**：这两个数几乎永远对着干。你把置信度阈值调高（只信高分框），FP 变少、Precision 升，但一些低分的真目标也被砍掉、FN 变多、Recall 降；阈值调低则反过来。**同一个模型，靠调阈值就能在"高查准低查全"和"低查准高查全"之间滑动**——所以只报一个 Precision 或一个 Recall 是耍流氓，必须说清楚"在哪个阈值下"。

**F1：把两个数捏成一个。** 有时想要单一数字比较，用**调和平均**：

$$
F_1 = \frac{2 \cdot P \cdot R}{P + R}
$$

上例 $F_1 = \frac{2 \times 0.875 \times 0.70}{0.875 + 0.70} \approx 0.778$。用调和平均而非算术平均，是因为它**惩罚偏科**：P=0.99 但 R=0.01 时，算术平均还有 0.5，F1 却只有 0.02——一个只会报一个超准的框、其他全漏的模型，F1 直接判它不及格。

**F-beta：偏心哪一头。** 有的场景漏报比误报可怕得多（变电站周界：漏一个入侵者是事故，多报几次运维忍得了），这时用 $F_\beta$ 给召回率加权（$\beta>1$ 偏重召回，$\beta<1$ 偏重精确）：

$$
F_\beta = (1+\beta^2) \cdot \frac{P \cdot R}{\beta^2 \cdot P + R}
$$

安防常用 $\beta=2$（召回权重是精确的 4 倍）。**选哪个 β，本质是把"漏报和误报谁更贵"这个业务判断写进公式**——这是 30.8 阈值决策的地基。

```rust,ignore
fn precision(tp: usize, fp: usize) -> f64 {
    if tp + fp == 0 { return 0.0; }          // 一个框都没报，精确率定义为 0（也有约定为 1，按团队规范）
    tp as f64 / (tp + fp) as f64
}
fn recall(tp: usize, fn_: usize) -> f64 {
    if tp + fn_ == 0 { return 0.0; }         // 测试集里没有该类真值，召回率无意义
    tp as f64 / (tp + fn_) as f64
}
fn f_beta(p: f64, r: f64, beta: f64) -> f64 {
    let b2 = beta * beta;
    if b2 * p + r == 0.0 { return 0.0; }
    (1.0 + b2) * p * r / (b2 * p + r)
}
```

## 30.5 PR 曲线与 AP：一条曲线看尽一个模型

单个阈值下的 P/R 只是曲线上的**一个点**。既然阈值一动 P/R 就变，那把**阈值从高到低连续扫一遍**，每个阈值画一个 (Recall, Precision) 点，连起来就是**PR 曲线（Precision-Recall Curve）**。它一张图说尽这个模型在所有工作点上的表现：

```text
Precision
 1.0 ┤●●●●●●●○              好模型：曲线贴着右上角，
     │        ●○○           拉高召回时精确率跌得慢
     │           ●○○
     │              ●●○○    差模型：曲线早早往下掉
     │                  ●●●○○○○
 0.0 └──────────────────────────▶ Recall
     0                        1.0
```

怎么扫？**不需要真的试几百个阈值**——把所有预测按分数降序排好，从上往下一个个"放行"，每放行一个就重算一次累计的 TP/FP，就等价于"阈值从高慢慢降到低"。放行到第 i 个时：

- 累计 TP、FP 就是前 i 个里 TP/FP 的个数；
- $\text{Recall}_i = TP_i / (\text{该类真值总数})$，随着放行只增不减（分母固定）；
- $\text{Precision}_i = TP_i / (TP_i + FP_i)$，上下抖动（碰到 FP 就跌一下）。

**AP（Average Precision，平均精度）就是这条 PR 曲线下的面积**，范围 0~1，一个数概括整条曲线。面积越大 = 曲线越贴右上角 = 在各个召回水平上都能保持高精确率 = 模型越好。

VOC 2010 之后常用的 **all-points** 算法分两步：先把 Precision 修成包络（消掉曲线的锯齿抖动），再按召回增量求和积分。下面的 Rust 实现适合讲清原理。要注意，COCO 官方协议使用 101 个召回采样点，并另有 `maxDets`、面积范围、`crowd/ignore` 等规则；这段代码不能冒充与 COCO 榜单逐位一致的实现。

```rust,ignore
/// 给定某个类别、全测试集所有预测的 (分数, 是否TP)，和该类真值总数，算 AP
fn compute_ap(mut scored_flags: Vec<(f32, bool)>, n_gt: usize) -> f64 {
    if n_gt == 0 { return 0.0; }                 // 该类没有真值，AP 无意义
    // ① 全局按分数降序 = 阈值从高到低逐个放行
    scored_flags.sort_by(|a, b| b.0.total_cmp(&a.0));

    // ② 从上往下累计 TP/FP，得到每一步的 recall 与 precision
    let (mut tp, mut fp) = (0usize, 0usize);
    let mut recalls = Vec::with_capacity(scored_flags.len());
    let mut precisions = Vec::with_capacity(scored_flags.len());
    for (_score, is_tp) in &scored_flags {
        if *is_tp { tp += 1; } else { fp += 1; }
        recalls.push(tp as f64 / n_gt as f64);
        precisions.push(tp as f64 / (tp + fp) as f64);
    }

    // ③ 从右往左取后缀最大值，使 precision 随 recall 增大而单调不增
    for i in (0..precisions.len().saturating_sub(1)).rev() {
        precisions[i] = precisions[i].max(precisions[i + 1]);
    }

    // ④ 按 recall 增量积分 = 曲线下面积
    let mut ap = 0.0;
    let mut prev_r = 0.0;
    for i in 0..recalls.len() {
        ap += (recalls[i] - prev_r) * precisions[i];
        prev_r = recalls[i];
    }
    ap
}
```

## 30.6 mAP：检测领域的黄金标准

AP 是**单个类别**的分数。一个检测模型要认 person、car、dog……几十上百个类，把**测试集中有真值的各类别 AP 求平均**，就是 **mAP（mean Average Precision）**——检测领域论文、榜单、验收报告里那个最常被报的数字。没有任何真值的类别，其 AP 没有定义，应从平均值中排除：

$$
\text{mAP} = \frac{1}{C}\sum_{c=1}^{C} \text{AP}_c
$$

但"mAP"有两种常见口径，务必分清，否则数字对不上：

| 口径 | 含义 | 用在哪 |
| --- | --- | --- |
| **mAP@0.5**（VOC 口径） | IoU 阈值固定 0.5 算一次 mAP | 宽松，看"大致框住"的能力；工业界日常沟通多用它 |
| **mAP@0.5:0.95**（COCO 口径） | IoU 阈值从 0.5 到 0.95、每隔 0.05 各算一次 mAP 再平均（共 10 个） | 严格，额外考核**框的位置精度**；论文/榜单标配 |

mAP@0.5:0.95 更严是因为它要求框不仅"框住"还要"框准"——IoU=0.9 的阈值下，框歪一点就不算 TP。**看到别人报 mAP，第一句要问的是"哪个 IoU 口径"**。

把 30.3~30.6 串成完整流程，就是一个能对整个测试集算 mAP 的评估器：

```rust,ignore
/// 一张图的标注：预测框 + 真值框（真值只需框和类别）
struct ImageEval {
    preds: Vec<Detection>,           // 模型在这张图上的全部预测
    gts: Vec<(BBox, usize)>,         // 真值：(框, 类别)
}

/// 算整个测试集在某个 IoU 阈值下的 mAP，返回 (mAP, 每类AP)
fn mean_ap(dataset: &[ImageEval], num_classes: usize, iou_thr: f32) -> (f64, Vec<Option<f64>>) {
    let mut aps = Vec::with_capacity(num_classes);
    for c in 0..num_classes {
        // ① 收集该类：所有图的 (分数, TP/FP) 汇成一堆，并累计该类真值总数
        let mut scored_flags: Vec<(f32, bool)> = Vec::new();
        let mut n_gt = 0usize;
        for img in dataset {
            let preds_c: Vec<Detection> =
                img.preds.iter().filter(|d| d.class_id == c).cloned().collect();
            let gts_c: Vec<BBox> =
                img.gts.iter().filter(|(_, cls)| *cls == c).map(|(b, _)| *b).collect();
            n_gt += gts_c.len();
            let (flags, _fn) = match_one_image(preds_c, &gts_c, iou_thr);
            scored_flags.extend(flags);
        }
        // ② 该类没有真值时 AP 无定义，不应拿 0 拉低 mAP
        aps.push((n_gt > 0).then(|| compute_ap(scored_flags, n_gt)));
    }
    let valid: Vec<f64> = aps.iter().flatten().copied().collect();
    let map = if valid.is_empty() { 0.0 } else { valid.iter().sum::<f64>() / valid.len() as f64 };
    (map, aps)
}

/// 教学版近似：IoU 0.5→0.95 步长 0.05 各算一次再平均。
/// 精确 COCO 指标应使用官方评测工具。
fn map_50_95_approx(dataset: &[ImageEval], num_classes: usize) -> f64 {
    let mut sum = 0.0;
    let mut n = 0;
    let mut thr = 0.50;
    while thr <= 0.951 {                 // 0.5,0.55,...,0.95 共 10 档（用 0.951 兜浮点误差）
        let (m, _) = mean_ap(dataset, num_classes, thr as f32);
        sum += m;
        n += 1;
        thr += 0.05;
    }
    sum / n as f64
}
```

> 这段代码为讲清原理写得直白（每类每图重新过滤，有重复计算），得到的是 mAP@0.5 和 mAP@0.5:0.95 的教学版近似值。真做验收或榜单对比，应使用 COCO 官方 `pycocotools` 等成熟实现，保证 101 点插值、`maxDets`、忽略标注等细节逐项对齐。评估代码算错，比模型差更危险，因为它会让你对着错的数字做决策。

> **评估时不要先用业务阈值砍掉低分预测。** 第 26 章 `Detector::detect` 默认会按 0.25 过滤，这会截断 PR 曲线、低估可达到的召回率。评估应从尽可能低的置信度开始保留候选（并按既定协议做 NMS），再由评估器按分数排序扫描工作点。

## 30.7 阈值决策：0.5 不是天经地义

新手最容易忽略、资深工程师最花心思的一步：**置信度阈值到底设多少？** 很多人代码里写死 `score > 0.5`，把 0.5 当成天经地义——**这几乎总是错的**。0.5 只是个默认值，最优阈值由**业务成本**决定，而 PR 曲线正好给了你反推它的工具。

思路是：**把每种错误的代价量化，再在曲线上找总代价最小（或收益最大）的那个点。**

- **周界入侵/安防**：漏报（FN）代价极高（出事故），误报（FP）代价低（运维多看一眼）。→ **要高召回**，阈值往**低**调，甚至用 $F_2$ 选点，宁可多报不可漏报。
- **人脸门禁/自动放行**：误识（FP，放错人进门）代价极高，漏识（FN，让你再刷一次）代价低。→ **要高精确**，阈值往**高**调。
- **人流统计**：进出计数，误报漏报会互相抵消一部分，追求 F1 附近的平衡点即可。

工程上有个可直接落地的做法——**扫一遍阈值，让机器帮你挑**：

```rust,ignore
/// 在一批候选阈值里，挑出使 F_beta 最大的那个工作点
/// eval_at(thr) 应返回该阈值下整个测试集的 (precision, recall)
fn pick_threshold<F>(candidates: &[f32], beta: f64, eval_at: F) -> (f32, f64)
where
    F: Fn(f32) -> (f64, f64), // thr -> (precision, recall)
{
    let mut best = (candidates[0], f64::MIN);
    for &thr in candidates {
        let (p, r) = eval_at(thr);
        let score = f_beta(p, r, beta);   // 安防 beta=2 偏召回；门禁 beta=0.5 偏精确
        if score > best.1 {
            best = (thr, score);
        }
    }
    best // (最优阈值, 对应的 F_beta)
}
```

关键认知：**同一个模型，安防现场和门禁现场应该用不同的阈值**。把阈值写进配置（呼应第 27 章 `score_thresh`），针对每个现场用它的测试集扫一遍、按它的成本选点——这就是"部署工程师"和"调包侠"的区别。

## 30.8 其他任务的指标速览

检测之外，各类模型有各自的尺子，这里给一张速查表，够你看懂验收报告、指路对应章节：

| 任务 | 主指标 | 一句话 |
| --- | --- | --- |
| **分类**（第15章） | Top-1 / Top-5 准确率、混淆矩阵 | 预测类别对不对；类别多时看 Top-5 |
| **检测**（本章） | mAP@0.5、mAP@0.5:0.95 | 上文主角 |
| **分割**（第18章） | **mIoU**（各类 IoU 求平均）、Dice | 逐像素的交并比，衡量掩膜贴合度 |
| **关键点/姿态**（第17章） | **OKS**、PCK | 关键点位置误差，OKS 是姿态版的 IoU |
| **人脸识别**（第20章） | ROC 曲线、TAR@FAR、EER | 在"万分之一误识率下的通过率"这种口径上比 |
| **多目标跟踪**（第21章） | **MOTA**、**IDF1**、ID switches | 不仅框要准，ID 还要稳（见下） |

**跟踪指标值得单独点一句**，因为它和第 21 章直接挂钩。检测的 mAP 高，不代表跟踪好——一个目标被检出但 ID 频繁跳变（第 21、28 章反复强调的痛点），mAP 看不出来，得靠跟踪专属指标：

- **MOTA（Multi-Object Tracking Accuracy）**：综合漏报、误报、**ID 跳变**三种错误的总分，越高越好。
- **IDF1**：把"身份保持得对不对"做成 F1，专门惩罚 ID switch——它才是"这个人从头到尾是不是同一个 ID"的度量。
- **ID switches**：一条真实轨迹被换了几次 ID 的计数，越少越好。

所以第 28 章说"计数准不准七成看跟踪稳不稳"，落到数字上就是：**光看 mAP 会高估跟踪系统，必须同时看 IDF1**。

## 30.9 版本回归：新模型上线前的必答题

资深工程师最常做、也最容易出事的操作之一，是**换模型**——供应商给了 v2、你自己重训了一版、或换了个量化配置。**换上去之前必须回答：新版在我的测试集上，到底是全面变好，还是"总分涨了、但某个关键类偷偷崩了"？**

这就是**版本回归（regression testing）**：拿**同一个固定测试集**，让新旧模型各跑一遍，**逐类对比**指标，任何一类的关键指标掉超过阈值就亮红灯、拦住上线。

```text
              旧模型 v1    新模型 v2     Δ        判定
person  AP    0.842        0.861       +0.019    ✅ 变好
car     AP    0.795        0.803       +0.008    ✅ 变好
person  召回  0.910        0.874       -0.036    ❌ 召回掉了！拦住
────────────────────────────────────────────────────
整体 mAP      0.812        0.827       +0.015    （总分涨了，但被 person 召回下降否决）
```

看这张表的杀伤力：**整体 mAP 涨了 0.015，看着是"新模型更好"**，但 person 类的召回掉了 3.6 个点——在安防场景这意味着"更容易漏人"，是不可接受的回归。**只看一个总分会被骗，逐类逐指标对比才拦得住"偏科式变差"。**

把它写成一个能挂进 CI（第 31 章会讲）的守门函数：

```rust,ignore
/// 逐类回归对比：任何关注指标相对旧版下降超过 tol，就返回失败清单
struct ClassMetric { name: String, ap: f64, recall: f64 }

fn regression_gate(
    old: &[ClassMetric],
    new: &[ClassMetric],
    tol: f64,            // 容忍的最大下降幅度，如 0.01
) -> Result<(), Vec<String>> {
    let mut failures = Vec::new();
    if old.len() != new.len() {
        failures.push(format!("类别数量不一致: {} → {}", old.len(), new.len()));
    }
    for (o, n) in old.iter().zip(new.iter()) {
        if o.name != n.name {
            failures.push(format!("类别顺序/名称不一致: {} vs {}", o.name, n.name));
            continue;
        }
        if n.ap < o.ap - tol {
            failures.push(format!("{} AP 回退: {:.3} → {:.3}", o.name, o.ap, n.ap));
        }
        if n.recall < o.recall - tol {
            failures.push(format!("{} 召回回退: {:.3} → {:.3}", o.name, o.recall, n.recall));
        }
    }
    if failures.is_empty() { Ok(()) } else { Err(failures) }
}
```

上线流程因此变成：**新模型 → 跑固定测试集 → `regression_gate` 逐类比对 → 全绿才准发布**。这一步自动化后，"手滑换了个更差的模型上线"这类事故就基本绝迹了。

## 30.10 评估的坑：数字也会骗人

评估本身也有一堆陷阱，踩中了你会对着**错误的数字**信心满满地做错误决策——这比模型差更隐蔽：

- **测试集泄漏（最致命）**：训练集和测试集有重叠/同源图片，分数会虚高得离谱。**测试集必须是模型从没见过的数据**，最好来自真实部署现场。评估的第一诫：**测试集干净、且和上线场景同分布**。
- **测试集不代表现场**：拿白天晴天的图评估，上线却要跑夜间雨天。分数再高也是"考场发挥"，不代表"实战成绩"。测试集要**覆盖你会遇到的光照、天气、角度、遮挡、人群密度**。
- **类别不平衡让指标不稳定**：mAP 对各类别做宏平均，不会让 1000 个 person 直接压过 5 个 cat；但只有 5 个真值的 cat AP 方差很大，少对或少错一个就会剧烈波动。另一方面，一个关键类别的回退仍可能被几十个其他类别的平均值掩盖。必须同时报告每类样本数、每类 AP 和关键类指标。
- **单一数字迷信**：mAP=0.9 听着漂亮，但没说 IoU 口径、没说哪个阈值、没说各类分布——**任何单一数字脱离上下文都可能是话术**。资深工程师看到一个孤零零的 mAP，会追问"哪个 IoU、什么测试集、逐类多少"。
- **测试集太小**：几十张图算出来的 mAP 抖动极大，换一批图就变。**测试集要够大够多样**，分数才稳定可信。
- **忽视"位置精度"**：只看 mAP@0.5，框歪一半也算对；下游要抠图/测距（如第 28 章人脸抓拍要抠脸）时，得看 mAP@0.75 甚至更严的口径。

一句话收尾：**评估代码和测试集的可信度，决定了你所有决策的可信度。** 花在"把测试集建干净、把评估口径对齐"上的时间，回报远高于再调半天模型。

## 30.11 小结

- 肉眼抽查有幸存者偏差，**必须量化评估**：得到能复现、能比较、能定决策的数字，才谈得上对模型负责。
- 一切的原点是 **TP/FP/FN**（检测里 TN 不计）；检测比分类多一步——用 **IoU ≥ 阈值** 判定一个预测有没有"命中"真值，且一个真值只能被最高分的那个预测认领（重复框自动判 FP）。
- **精确率**（报的准不准，怕误报看它）与**召回率**（找得全不全，怕漏报看它）是一对跷跷板，靠调阈值滑动；**F1/F-beta** 把两者捏成一个数，选 β 就是把"漏报和误报谁更贵"写进公式。
- **PR 曲线**扫遍所有阈值，其**曲线下面积 = AP**；有真值类别的 AP 求平均 = **mAP**。务必分清 **mAP@0.5**（宽松）和 **mAP@0.5:0.95**（更严格）；与 COCO 官方数字对比时还要使用它的 101 点及完整评测协议。
- **阈值不是天经地义的 0.5**：按业务成本（安防偏召回、门禁偏精确）在曲线上选工作点，写进每个现场的配置。
- 换模型必做**版本回归**：固定测试集、**逐类逐指标**对比，防"总分涨了但关键类偷偷崩"；把它做成 CI 守门（第 31 章）。
- 评估的坑几乎都在数据与口径：**测试集泄漏、不代表现场、类别不平衡、单一数字迷信**——评估的可信度决定一切决策的可信度。

## 30.12 练习

1. **手算一张混淆矩阵**：测试集有 50 个真目标，模型报了 60 个框，其中 45 个是 TP。算出 FP、FN、Precision、Recall、F1、F2，并说明在"安防"和"门禁"两种场景下你分别更看重哪个数、阈值该往哪调。

2. **画一条 PR 曲线**：给定 10 个预测（自己编 `(分数, 是否TP)`）和真值总数=6，手动从高分到低分累计 TP/FP，算出每一步的 (Recall, Precision) 并画在纸上，最后用 30.5 的 `compute_ap` 逻辑手算 AP，对照直觉验证"曲线越贴右上角 AP 越大"。

3. **给第 26 章的检测器接上评估**：准备一小批标注好的测试图（或用 COCO val 的一个子集），把检测置信度阈值降到足够低后收集预测，实现 `mean_ap`，算出教学版 mAP@0.5 和 mAP@0.5:0.95；再用官方评测工具核对，看看两个口径差多少，并解释差距反映的是"框得住"还是"框得准"。

4. **写一个阈值扫描器**：对同一个测试集，把置信度阈值从 0.1 扫到 0.9（步长 0.05），画出 Precision、Recall、F1 随阈值变化的三条曲线，找出 F1 最高的阈值和 F2 最高的阈值，比较它俩差多少，并解释为什么安防要用后者。

5. **做一次版本回归实验**：把同一个模型导出 float32 和 int8 两个版本（量化见第 13 章），用 `regression_gate` 逐类对比二者的 AP 与召回。观察量化在哪些类上掉点最多，讨论"用速度换精度"这笔账在你的场景里划不划算。
