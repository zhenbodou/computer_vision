# 第 19 章 · 差分模型：帧差、背景建模与变化检测

> **本章导读**：第 15~18 章的模型（分类、检测、关键点、分割）都在回答同一个问题——"**这是什么**"。它们本事大，但代价也大：每一帧都要把一个几千万参数的神经网络从头跑一遍。可很多真实场景里，我们其实不关心画面里有什么，只关心"**和刚才比，哪里变了**"：一条空走廊、一个空仓库，99% 的时间什么也没发生，直到某一刻有个东西动了。本章讲的**差分（differencing）**与**变化检测（change detection）**就是干这个的：不做识别，只做"找不同"。它极快、零训练、零模型，天生适合当**触发器（trigger）**——先用它把不动的帧筛掉，只有真有动静时才叫醒后面的重模型。读完你能亲手写出一个能跑的运动侦测器：帧差、三帧差、滑动平均背景建模，再借第 8 章的形态学与轮廓把结果清理成一组"运动区域框"（复用全书统一的 `BBox`），并理解工业界"差分粗筛 + 深度模型确认"这套省钱的级联范式。

## 19.1 换个思路：不问"是什么"，只问"变了没"

先玩个小游戏。杂志上常有"**找不同**"：两张几乎一样的图并排，让你圈出不一样的几处。你不会去逐一辨认"这是花瓶、那是猫"，你的眼睛只盯着"**和另一张不一样的地方**"。差分算法干的就是这件事——把两张图（两帧）**逐像素相减**，结果为 0 的地方（没变）忽略，非 0 的地方（变了）就是答案。

再想想监控值班室：保安面对 16 路监控墙，他不是在"识别每个画面里有什么"，而是在等"**哪个画面动了一下**"。人动了、门开了、有车进来了——是"变化"触发了他的注意，而不是"内容"。

**为什么差分这么省算力？** 算笔账就懂了。一帧 1080p 灰度图有 `1920×1080 ≈ 200 万`个像素，帧差不过是 200 万次减法加比大小，普通 CPU **零点几毫秒**就算完。而跑一次 YOLOv8（第 16 章）动辄几十毫秒，还得要 GPU。二者差着几百倍。

于是有了工业界最常见的省钱套路——**触发器 + 重模型**的级联：

```text
每一帧 ─▶ 差分粗筛(极快) ─┬─ 没动静？ ─▶ 丢弃，看下一帧
                          └─ 有动静？ ─▶ 唤醒 YOLO 检测(慢但准) ─▶ 报警 / 录像 / 抓拍
```

一路 24 小时的摄像头，画面绝大多数时间是静止的。让 GPU 全天候空跑 YOLO 是巨大的浪费；让差分当"门卫"，只有真有东西动了才叫醒重模型——同样一块边缘盒子，功耗和成本能降一个数量级。**差分很少单独交付结果，它更多是整条流水线最前端那个便宜、高召回的开关。**

## 19.2 帧差法：和上一帧相减

最朴素的差分叫**帧差法（frame differencing）**：拿**当前帧**减去**上一帧**，逐像素取绝对值。静止的背景两帧一模一样，相减得 0；有物体移动经过的地方，两帧不同，差值就大。写成公式就是 $|frame_t - frame_{t-1}|$。

**用一行像素手算一遍**。取一行 6 个灰度像素，看一个亮物体移动到中间：

```text
帧 t-1:   50   50   50   50   50   50      ← 一段静止的墙（灰度 50）
帧 t:     50   50  200  200   50   50      ← 一个亮物体（灰度 200）挪到了中间
|差|:      0    0  150  150    0    0      ← 只有物体所在的两列亮了起来
```

差出来的还是灰度值，我们只想要"动/不动"两种答案，于是**阈值二值化（threshold）**：差值大于阈值 `T` 的判为"动"（涂 255），否则"静"（涂 0），得到一张只有黑白两色的**运动掩膜（motion mask）**。取 `T = 30`：

```text
|差|:     0    0  150  150    0    0
mask:     0    0  255  255    0    0        （> 30 → 255，否则 0）
```

帧差法快得离谱、不用任何模型，但它有三个必须知道的毛病：

| 毛病 | 为什么 | 后果 |
| --- | --- | --- |
| **内部空洞（hollow）** | 一辆纯白色的车，车身中间大片同色，前一帧白、这一帧还是白，相减为 0 | mask 只描出车的**前后边缘**，中间是空的 |
| **静止即消失** | 物体一旦停下不动，和上一帧又一模一样 | 停住的人/车瞬间从 mask 里消失 |
| **拖影 / 双影** | 物体从 A 挪到 B，A（它离开的空位）和 B（它到达处）两帧都不同 | 一个物体被点亮成两团，其中 A 处是"假运动" |

前两个毛病是帧差法的天性（它只对"正在变化"敏感），后一个可以靠三帧差改善（下一节）。

**用 Rust 实现两帧差**。输入是相邻两帧的灰度图（`GrayImage` 即第 2/3 章的 `Luma<u8>` 图，彩色帧先用 `to_luma8()` 转灰度——我们只关心亮度变化）：

```rust,ignore
use image::{GrayImage, Luma};

/// 两帧差：输入相邻两帧灰度图，输出运动掩膜（255=动，0=静）
/// prev、curr 尺寸必须相同，复用第 2/3 章的逐像素访问
fn frame_diff(prev: &GrayImage, curr: &GrayImage, thresh: u8) -> GrayImage {
    let (w, h) = curr.dimensions();
    let mut mask = GrayImage::new(w, h);
    for y in 0..h {
        for x in 0..w {
            // 关键：先转 i16 再相减，否则 u8 相减会下溢（50u8 - 200u8 会 panic 或回绕）
            let a = prev.get_pixel(x, y)[0] as i16;
            let b = curr.get_pixel(x, y)[0] as i16;
            let d = (b - a).abs() as u8;                 // |curr - prev|
            let v = if d > thresh { 255 } else { 0 };    // 阈值二值化
            mask.put_pixel(x, y, Luma([v]));
        }
    }
    mask
}
```

注意那个 `as i16`：`u8` 直接相减会下溢，这是新手写帧差最常见的第一个坑。**工程上通常会**把这层循环换成对底层 `&[u8]` 缓冲区的顺序遍历、甚至用 SIMD 一次算 16 个像素，速度还能再上一个台阶——但看得懂优先，先把逻辑理清。

## 19.3 三帧差：治一治拖影

两帧差最烦人的是**拖影**：物体从 A 移到 B，差分图会把 A（它刚离开的空位）和 B（它现在所在）**同时**点亮，于是一个物体报成一团横跨 A、B 的"糊影"，其中 A 处根本已经没东西了。

**三帧差（three-frame differencing）**的思路很巧：拿**中间帧当"当前"**，分别和它的前一帧、后一帧各做一次帧差，再把两张 mask 取**逻辑与（AND）**——只有两次都判为"动"的像素，才算真运动。

```text
用中间帧 f2 分别和前帧 f1、后帧 f3 比，再取交集（AND）：

帧 f1:        . . ■ ■ . . . .     物体在 A
帧 f2:        . . . . ■ ■ . .     物体到 B（要判断的当前帧）
帧 f3:        . . . . . . ■ ■     物体到 C

da=|f2-f1|:   . . ▓ ▓ ▓ ▓ . .     A(空了) + B(来了) 都亮  ← 这就是两帧差的"拖影"
db=|f2-f3|:   . . . . ▓ ▓ ▓ ▓     B(还在) + C(将到) 都亮
da AND db:    . . . . ▓ ▓ . .     只剩 B ← A 的拖影、C 的"未来位置"都被交集消掉了
```

直觉：A 处只在"和前帧比"时变了（后帧那里也是空的，不亮），C 处只在"和后帧比"时变了，一取交集，这两处各自落单的就被剔除，留下的正是物体在中间帧的真实位置。代价是：需要**缓存三帧**、且对纯平移的大物体内部空洞更明显。

```rust,ignore
/// 三帧差：判断中间帧 f2。两次差都为"动"才算真运动
fn three_frame_diff(f1: &GrayImage, f2: &GrayImage, f3: &GrayImage, thresh: u8) -> GrayImage {
    let da = frame_diff(f1, f2, thresh); // |f2 - f1|：当前帧相对前一帧
    let db = frame_diff(f2, f3, thresh); // |f3 - f2|：当前帧相对后一帧（绝对值，方向不影响）
    let (w, h) = f2.dimensions();
    let mut mask = GrayImage::new(w, h);
    for y in 0..h {
        for x in 0..w {
            let hit = da.get_pixel(x, y)[0] == 255 && db.get_pixel(x, y)[0] == 255;
            mask.put_pixel(x, y, Luma([if hit { 255 } else { 0 }]));
        }
    }
    mask
}
```

## 19.4 背景建模：和"干净的背景"比

帧差法有个绕不过的硬伤：**物体一停就消失**——因为它总是和"上一帧"比，而停住的物体和上一帧完全一样。要让停住的东西也能被持续发现，就得换个参照物：不和上一帧比，而和一张**干净的空场景背景**比。这类方法叫**背景减除（background subtraction）**，也叫**背景建模**。

最天真的做法是"拍一张空场景当背景，每帧减它"。但真实背景是会**缓慢变化**的：日光渐移、云影飘过、树影摇动、摄像头自动增益跳变……一张拍死的背景很快就对不上号，导致**全屏误报**。所以背景必须"活"起来，能跟着环境慢慢更新。

最常用的活背景是**滑动平均（running average）**背景：每来一帧，就用当前帧把背景**更新一点点**：

$$bg \leftarrow \alpha \cdot frame + (1-\alpha)\cdot bg$$

这里的 $\alpha$ 叫**学习率（learning rate）**，取 0~1，控制"背景追新画面的速度"：

- $\alpha$ **大**（如 0.5）：背景紧跟当前帧，光照变化立刻被吸收——但停下的物体也很快被"学"进背景，记性短。
- $\alpha$ **小**（如 0.01）：背景更新极慢，稳如老狗，能记住很久以前的空场景——但突然的光照变化要好一阵才追上。

**用小数字体会 $\alpha$**。设某像素背景 `bg = 50`，来了个物体让它变成 `frame = 200`，物体停在原地不走，取 $\alpha = 0.1$：

```text
第 1 帧后: bg = 0.1×200 + 0.9×50   = 20 + 45.0 = 65.0
第 2 帧后: bg = 0.1×200 + 0.9×65   = 20 + 58.5 = 78.5
第 3 帧后: bg = 0.1×200 + 0.9×78.5 = 20 + 70.7 = 90.7
...        背景一点点"爬"向 200
```

背景与目标值 200 的差距，每帧乘以 `(1-α)=0.9`，所以 `0.9ⁿ = 0.5` 时差距减半——解得 `n ≈ 7`：$\alpha=0.1$ 时，一个停住的物体大约 **7 帧**后就被背景"吃掉一半"，十几帧后基本溶进背景，前景差随之变小。换成 $\alpha=0.01$，半衰期约 **69 帧**（25fps 下近 3 秒），物体能"存在"久得多。**这就是调 $\alpha$ 的直接后果：想让停住的目标赖得久，就把 $\alpha$ 调小。**

有了背景，前景就是 $|frame - bg| > T$。用 Rust 实现一个滑动平均背景建模器（背景用 `f32` 存，因为 `α·frame` 会产生小数）：

```rust,ignore
use image::{GrayImage, Luma};

/// 滑动平均背景建模器：维护一张 f32 背景图，逐帧更新并输出前景掩膜
struct RunningAvgBg {
    bg: Vec<f32>,   // 背景灰度，行主序，索引 = y*w + x
    w: u32,
    h: u32,
    alpha: f32,     // 学习率 0~1
}

impl RunningAvgBg {
    /// 用第一帧初始化背景（最好是"空场景"，否则目标会被当成背景，直到被慢慢学掉）
    fn new(first: &GrayImage, alpha: f32) -> Self {
        let (w, h) = first.dimensions();
        let bg = first.pixels().map(|p| p[0] as f32).collect(); // 逐像素拷成 f32
        Self { bg, w, h, alpha }
    }

    /// 喂一帧：先算前景掩膜，再更新背景。thresh 为前景判定阈值
    fn apply(&mut self, frame: &GrayImage, thresh: f32) -> GrayImage {
        let mut mask = GrayImage::new(self.w, self.h);
        for y in 0..self.h {
            for x in 0..self.w {
                let i = (y * self.w + x) as usize;
                let cur = frame.get_pixel(x, y)[0] as f32;
                let diff = (cur - self.bg[i]).abs();
                let v = if diff > thresh { 255 } else { 0 };   // 偏离背景够多 → 前景
                mask.put_pixel(x, y, Luma([v]));
                // 背景更新：bg = α·当前 + (1-α)·旧背景
                self.bg[i] = self.alpha * cur + (1.0 - self.alpha) * self.bg[i];
            }
        }
        mask
    }
}
```

一个进阶细节：上面对**所有**像素都更新背景，包括前景像素。讲究的做法是对判为前景的像素**慢更新甚至不更新**（叫 **selective update**，选择性更新），否则停住的目标会被快速学进背景。点到为止，读者按需加。

**更高级的背景建模：MOG2 与 KNN。** 滑动平均给每个像素只记"一个背景值"，遇到**会晃动的背景**（风吹树叶、水面波光、闪烁的屏幕）就抓瞎——那个像素一会儿是叶子绿、一会儿是天空蓝，用一个平均值根本描述不了。工业界常用的 **MOG2（Mixture of Gaussians，高斯混合模型）**换了个思路：给每个像素记住"它平时会出现哪几种值"（用几个高斯分布表示），新来的值只要落在这些"常见值"里就算背景，否则算前景，因此扛得住摇摆背景，还自带阴影检测。**KNN** 思路类似，用最近邻判断新像素像不像最近见过的背景样本。二者 OpenCV 都有现成：`cv::createBackgroundSubtractorMOG2()` / `createBackgroundSubtractorKNN()`，Rust 的 `opencv` 绑定同名可用。思想懂了即可，数学不深挖。

| 方法 | 每像素记什么 | 扛摇摆背景 | 成本 |
| --- | --- | --- | --- |
| 帧差 / 三帧差 | 不建模，只比相邻帧 | 差 | 最低 |
| 滑动平均 | 一个背景值 | 差 | 低 |
| MOG2 / KNN | 一组背景值的分布 | 好 | 中 |

## 19.5 差分之后：形态学清理与运动框

到这里，本章的零件正好拼成一条完整的差分流水线——和第 8 章那条传统检测流水线是"表亲"，只是把"阈值"换成了"差分"：

```text
彩色帧 → 灰度 → 差分/背景减除 → 阈值二值化 → 开运算去噪 → 闭运算补洞 → 找轮廓 → 面积筛选 → 运动框 BBox
─────   ────   ────────────    ─────────    ─────────    ─────────    ──────   ────────   ──────────
第3/4章  转亮度   19.2~19.4        运动掩膜      第8章         第8章        第8章     去残渣      统一类型
```

不论帧差还是背景减除，出来的运动掩膜总是**脏的**：星星点点的噪点（传感器噪声、视频压缩的块效应）、物体内部的空洞、断成几截的运动块。直接拿去找轮廓会得到一堆碎渣。清理手段正是第 8 章的**形态学**——这里只用、不重讲原理：

- **开运算（open，先腐蚀后膨胀）**：干掉零星噪点白斑，主体保留。
- **闭运算（close，先膨胀后腐蚀）**：填掉物体内部空洞、把断裂的运动块连成一整块。

常见顺序是"先开去噪，再闭补洞"。清理干净后，用第 8 章的 `find_contours` 找轮廓、取外接矩形，产出全书统一的 `BBox`（左上-右下像素坐标），再按面积滤掉太小的残渣：

```rust,ignore
use image::GrayImage;
use imageproc::morphology::{open, close};
use imageproc::distance_transform::Norm;
use imageproc::contours::{find_contours, Contour, BorderType};

// BBox 与 bbox_of_contour 沿用第 8 章的定义（全书统一类型），此处不再重复

/// 把运动掩膜清理干净，转成一组"运动区域框"
fn motion_boxes(mask: &GrayImage, min_area: f32) -> Vec<BBox> {
    // ① 形态学清理：开运算去噪点，再闭运算补空洞（原理见第 8 章）
    let cleaned = close(&open(mask, Norm::LInf, 1), Norm::LInf, 2);

    // ② 找轮廓 → 外接框（第 8 章的老套路）
    let contours: Vec<Contour<i32>> = find_contours(&cleaned);
    let mut boxes = Vec::new();
    for c in &contours {
        if c.border_type != BorderType::Outer { continue; } // 只要外轮廓，内部空洞的边不算目标
        let b = bbox_of_contour(c);
        if b.area() < min_area { continue; }                // 太小 → 噪声残渣，丢弃
        boxes.push(b);
    }
    boxes
}
```

得到的这组 `BBox` 就是"画面里哪几块在动"，它能直接：画在录像上高亮、当作 ROI 裁给检测模型（下一节）、或作为多目标跟踪（第 21 章）的初始框。**注意本章的差分只告诉你"这块在动"，并不知道"动的是人还是猫"——那要靠后面的识别模型补上。**

> 小提醒：`min_area` 不是一个可以到处照搬的魔法数字。同一个人，站在镜头近处占几万像素，走到画面深处可能只剩几百像素——阈值定死了，近处正常、远处全漏。工程上要么按分辨率和目标"最远处该有多大"来估算，要么干脆分区域设不同的 `min_area`。

## 19.6 变化检测能用在哪

差分虽"笨"，却是无数真实产品的骨架。几个典型场景：

- **移动侦测录像（motion-triggered recording）**：家用摄像头、行车记录仪、云台机的看家功能——没动静不录，运动掩膜的白像素面积超过阈值才存这一段。轻松省下 90% 的存储和回放翻找时间。工程上还会留一个几秒的**预录缓冲（pre-roll）**：把最近几秒的帧一直存在内存环形队列里，触发时连同"事发前那几秒"一起落盘，否则录下来的永远缺了动作发生的开头。
- **遗留物检测（abandoned object detection）**：反着用背景建模。同时维护一快一慢两个背景：快背景很快把新物体学进去，慢背景还记得"没它的时候"。若两者在某处**长时间**不一致，说明"有人放下东西走了"——车站的无主行李、路上的路障、货架空位补货提醒。
- **周界预警前置粗筛**：在画面里划一块警戒区，差分一旦发现区内有运动就触发，再叫醒人形检测确认"是不是人"（排除猫狗、树影、飘动的塑料袋），是人才报警。这套完整系统是第 27 章的主题，本章只负责提供最前端那个"动静触发器"。
- **工业与产线**：传送带上"有没有来料"、料位/液面变化、设备指示灯闪动——这些固定视角、固定光照的场景，差分比训练一个模型划算太多。

## 19.7 差分做触发，模型做确认

把前面几节收束成一句工程箴言：**差分做触发，检测/分类模型做确认**。这是视频分析里最普遍的**级联（cascade）**范式，因为二者优劣正好互补：

| | 差分 | 深度检测/分类 |
| --- | --- | --- |
| 速度 | 极快（CPU 亚毫秒） | 慢（几十 ms，常需 GPU） |
| 召回（漏不漏） | 高，任何动静都不放过 | 取决于模型 |
| 精度（准不准） | 低，风吹草动都报 | 高，能说出"是什么" |
| 成本 | 几乎为 0 | 高 |

于是让差分负责**缩小范围**——时间上只在"有动静的帧"、空间上只在"运动框那块 ROI"——把昂贵的检测模型的调用次数压到最低；检测模型负责**下最终判断**。一台没有 GPU 的边缘盒子，靠这套配合也能 24 小时稳稳跑一路摄像头。这正是第 26、27 章实战程序的底层骨架。

顺带一提，差分本身也能"深度学习化"：**孪生网络（Siamese network）**、**变化检测网络（change detection network）**直接吃两个时刻的图像、输出一张"变化图"，常见于遥感（比对同一地块不同年份，自动找出新盖的房子）和缺陷检测。不过那些是训练侧话题，成本高；本章的传统差分零训练、可解释、够用就好，一句带过即可。

## 19.8 工程坑与调参

差分简单，但上线后的误报几乎全来自下面这几个坑。逐个认清，比背公式重要：

- **光照突变 → 全屏误报**：云突然遮住太阳、灯被打开关闭、摄像头自动增益（AGC）跳变——整帧亮度齐刷刷变，差分瞬间"满屏都在动"。**缓解**：统计"运动像素占比"，一旦超过某个大比例（如 50%）就判定为全局光照突变、丢弃这一帧不报警；或改用 MOG2 这类能较快吸收全局亮度变化的背景。
- **摄像头抖动 → 边缘全是假运动**：风吹杆晃、车载震动使整帧平移几像素，所有高对比边缘（栏杆、树枝、屋檐）都错位，勾出一圈假运动。**缓解**：先做帧对齐/电子防抖（第 9 章几何变换里的配准），或把阈值和最小面积调大，忽略细碎的边缘运动。
- **阴影 → 物体被放大、粘连**：人的影子亮度也和背景不同，会被算成运动的一部分，框比人大；两个人的影子还会把他俩连成一坨。**缓解**：阴影通常"颜色不变、只是变暗"，可在 HSV 空间里判断（色调 H 基本不变、明度 V 下降）来剔除；MOG2 自带阴影检测开关。
- **缓慢变化被背景"学掉"**：$\alpha$ 偏大时，站着不动的人、缓慢移动的物体会被背景一点点吸收，几秒后凭空"消失"。**缓解**：调小 $\alpha$、对前景像素用选择性更新（selective update）、或配合跟踪（第 21 章）在目标停下后仍保住它的身份。

调参其实就拧三个旋钮，记住方向即可：

| 现象 | 拧哪个旋钮 | 方向 |
| --- | --- | --- |
| 噪点多、误报频繁 | 阈值 `T` / 最小面积 `min_area` | 调大 |
| 漏检、动了没反应 | 阈值 `T` | 调小 |
| 光照/背景变化后误报持续不停 | 学习率 $\alpha$ | 调大（让背景快点适应） |
| 停下的目标很快消失 | 学习率 $\alpha$ | 调小（让背景记性久一点） |

最后一句忠告：差分**没有万能参数**。一定要拿目标现场的**真实回放视频**来调，而且白天、夜晚、雨天可能各要一套参数——这也是为什么它虽简单，却是需要长期在现场打磨的工程活。

## 19.9 小结

- 差分/变化检测换了个问题：不问"是什么"，只问"和之前比变了没"——逐像素相减 + 阈值二值化，极快、零训练、零模型，天生适合当"门卫"式**触发器**。
- **帧差法**（两帧差）= $|frame_t - frame_{t-1}|$ → 阈值 → 运动掩膜；快，但有"内部空洞""静止即消失""拖影"三大毛病。**三帧差**用中间帧和前后帧各做一次差再取交集，压掉拖影、定位更准。
- **背景建模**和"干净背景"比，能持续发现停住的目标：滑动平均 $bg=\alpha\cdot frame+(1-\alpha)\cdot bg$，$\alpha$ 是学习率——大则跟得快但记性短、小则稳但反应慢；会晃动的背景要上 **MOG2/KNN**（每像素记一组分布，OpenCV 现成）。
- 差分结果脏，用**开运算去噪、闭运算补洞**（第 8 章），再找轮廓取外接框，产出全书统一的 `BBox` 运动区域框，可交给 ROI 裁剪或跟踪（第 21 章）。
- 工程主线是**级联**：差分粗筛（便宜、高召回）触发，检测/分类（贵、高精度）确认——边缘盒子也能全天候跑；应用有移动侦测录像、遗留物检测、周界预警前置（第 27 章）。
- 头号坑：光照突变全屏误报、摄像头抖动、阴影、慢速目标被背景学掉；靠"阈值 / 最小面积 / 学习率"三个旋钮 + 现场真实视频反复调参。

## 19.10 练习

1. **手算三帧差**：给下面三帧同一行像素（背景 50，物体 200），先各算 `da=|f2-f1|`、`db=|f2-f3|` 并以 `T=30` 二值化，再取 `da AND db`，说明结果为什么恰好落在物体在 f2 的位置：
   ```text
   f1:  200 200  50  50  50  50
   f2:   50 200 200  50  50  50
   f3:   50  50 200 200  50  50
   ```
2. **帧差 vs 背景减除**：录一段"人走进来、站定约 10 秒、再走出去"的视频，抽帧（第 6 章）后分别跑 `frame_diff` 和 `RunningAvgBg`（用小 $\alpha$，如 0.01）。观察：帧差里人一站定就很快消失；背景减除会多保留一段时间，但由于本节实现会更新前景像素，最终也会把静止的人逐渐吸收到背景中。记录两种方法分别多久低于阈值，并解释差异。
3. **$\alpha$ 半衰期实验**：用 `RunningAvgBg` 对同一段视频分别取 $\alpha=0.5, 0.05, 0.005$，数"一个停下的物体大约多少帧后从前景里消失"，和 19.4 用 `0.9ⁿ=0.5` 推出的半衰期公式对一对，验证 $\alpha$ 越小目标赖得越久。
4. **搭一个触发器**：以 `motion_boxes` 返回的所有框总面积 `> 画面面积的 1%` 作为"有动静"信号，打印出视频里哪些帧被触发；再想想（不必真跑模型）如何把它接成"只在触发帧才调用 YOLO（第 16 章）"的级联管线，估算相比每帧都跑 YOLO 能省下多少次推理。
