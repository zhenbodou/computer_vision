# 第 82 章 光源、镜头与成像方案（硬件与打光常识）

> **本章导读**
> - 记住一句行话：**工业视觉一半的功夫在"打光"**。学完你会明白为什么打光常常比算法更决定成败。
> - 掌握常见打光方式（明场/暗场/背光/同轴/穹顶/结构光/多光谱）各自"看什么、怎么看"。
> - 看懂镜头三兄弟——**焦距、视场(FOV)、工作距离(WD)**——的关系，以及景深、远心镜头为什么对测量至关重要。
> - 分清面阵/线阵、全局/卷帘快门怎么选，动手算"每像素多少毫米"，并了解触发与工业接口这些"工程细节"。

## 场景引入：同一个划痕，打光对了才看得见

假设产线要挑出金属外壳上的细微划痕。工程师小张把相机架好、用最普通的顶灯一照——画面里表面白花花一片，划痕几乎看不见，他调了三天算法也检不出。老师傅走过来，把灯挪到侧面、几乎贴着外壳斜射，划痕**唰**地一下投出清晰的阴影，肉眼都看得一清二楚，简单一个阈值就检出来了。

这就是工业视觉最反直觉、也最值钱的一课：**很多问题不是"算法不够强"，而是"光没打对"**。上一章 [第 6 章相机模型](../p01-start/ch06-camera-model.md) 讲了光如何经镜头、传感器变成像素；这一章我们退一步，讲**在按下快门之前**——怎么打光、选什么镜头和相机——才能让后面所有算法（读码、测量、缺陷检测）事半功倍。这些是没法用代码替代的**硬件与方案常识**。

## 打光：让你想看的东西"跳出来"

打光的核心目标就一句话：**最大化"目标特征"与"背景"的对比，同时压掉干扰**。不同缺陷、不同材质，要用不同的打法。

### 常见打光方式一览

| 打光方式 | 怎么打 | 适用场景 | 效果 |
|---|---|---|---|
| **明场/正面光** | 光源与相机同侧，正对物体 | 通用表面、读码、颜色检查 | 均匀照亮，最百搭 |
| **暗场/低角度掠射** | 光几乎**贴着表面**斜射 | 表面划痕、刻字、凹凸、压痕 | 凸起与划痕投出阴影，极其突出 |
| **背光 backlight** | 光源在物体**背后**，相机对着光 | 测外形轮廓/尺寸、通孔、透明件找气泡 | 物体成**黑剪影**，边缘极锐利 |
| **同轴光 coaxial** | 光经半透镜与镜头**同轴**垂直打下 | 镜面/高反光平面（晶圆、金属抛光面） | 消除眩光，平面照得均匀 |
| **穹顶光 dome** | 半球罩内壁漫反射，从各方向包住物体 | **曲面/球面**高反光件（如焊点、金属扣） | 无方向性均匀光，压掉曲面高光斑 |
| **结构光** | 投射条纹/网格图案 | 三维形貌、高度测量 | 由条纹变形反推 3D（见 [第 65 章](../p14-3d/ch65-stereo-depth.md)） |
| **多光谱/特定波长** | 红外、紫外或特定颜色光 | 荧光检测、透过特定材料、抑制干扰 | 看见可见光下看不见的对比 |

两个最能体现"打光智慧"的对比，用 ASCII 感受一下。

**背光**——只关心"外形对不对、尺寸准不准"时的王牌，把物体变成纯黑剪影，边缘干净到没有任何纹理干扰：

```text
   面光源 ▒▒▒▒▒▒▒▒▒▒▒▒
            │ │ │ │          光从背后穿过/绕过物体
          ┌──███──┐          物体挡光 → 相机只看到黑色轮廓
    ──────┘       └──────
              ▲
           [ 相机 ]           边缘锐利，最适合量外形、找缺口
```

**暗场（低角度掠射）**——专治"平面上的凹凸和划痕"，靠影子放大微小起伏：

```text
                [ 相机 ]（垂直俯视）
                   ▲
                   │
     光源 ＼        │        ／ 光源   （几乎贴着表面斜射）
          ＼       │       ／
   ────────＼──────┴───△──／────────  被检表面
                     划痕/凸起 → 迎光面亮、背光面留阴影 → 缺陷高亮
```

### 颜色光与滤镜：用颜色"挑"出目标

光是有颜色的，聪明地利用颜色能极大提升对比：

- **同色增亮、异色压暗**：用**和目标同色**的光照它，目标会更亮（趋近白）；用**互补色**光照，目标会更暗（趋近黑）。例如想让红色标签更突出，用红光；想把红色背景压下去、突出上面的黑字，也可以用红光把红背景"洗白"。
- **滤镜**：镜头前加**带通滤镜**只放行某个波长（配合同波长光源，滤掉环境杂光）；加**偏振片**可以压掉金属/玻璃的镜面反光。

> 💡 **提示**：打光方案没有"标准答案"，但有"标准套路"。拿到新工件先问自己三句话：**我要看的特征是什么？它和背景在哪个维度上有差异（亮度/颜色/高度/透光）？哪种光能把这个差异放到最大？** 想清楚再架灯，往往比调算法快十倍。

## 镜头：焦距、视场与工作距离的三角关系

选镜头，本质是在**看多大范围（视场 FOV）**、**离多远拍（工作距离 WD）**、**用多长焦距 \\( f \\)** 三者间做平衡。它们由一个近似公式串起来：

\\[ \text{FOV} \approx \dfrac{\text{传感器尺寸} \times \text{WD}}{f} \\]

（严格说放大率 \\( m = f/(\text{WD}-f) \\)，当 \\( \text{WD} \gg f \\) 时约等于 \\( f/\text{WD} \\)，于是有上式。）读懂这个式子，选型就有了主心骨：

- **焦距 \\( f \\) 越长**：视场越小、放大越大——看得细但看得窄（长焦/远摄）。
- **工作距离 WD 越大**：视场越大——离得远看得宽，但同样的细节占的像素变少。
- **传感器越大**：同等条件下视场越大。

还有几个绕不开的概念：

- **景深（Depth of Field, DOF）**：能保持清晰的**前后深度范围**。光圈越小（F 数越大）景深越大——但进光变少，就**更依赖强打光**。工件有高低起伏时，景深不够会导致一部分清晰、一部分糊。
- **畸变（distortion）**：广角镜头会把直线拍弯（见 [第 6 章](../p01-start/ch06-camera-model.md)）。**做测量一定要选低畸变镜头**，否则边缘处量出来的尺寸是错的。

> ⚠️ **注意**：**分辨率够 ≠ 清晰度够。** 相机像素再多，如果镜头分辨力（用 **MTF** 调制传递函数衡量）跟不上、光圈过小引起衍射、或对焦/景深不到位，画面照样"糊"。系统的实际清晰度由镜头、光圈、工作距离、景深、衍射和传感器**共同决定**——买高像素相机配劣质镜头是常见的浪费。

### 远心镜头：精密测量的"作弊器"

普通镜头有"近大远小"的透视效应——同一个零件，离镜头近一点成像就大一点。**这对测量是灾难**：工件在传送带上前后晃动几毫米，量出的尺寸就变了。

**远心镜头（telecentric lens）** 专治这个：它的主光线平行于光轴，在设计的景深范围内**放大率恒定**，"近大远小"消失了。

```text
   普通镜头：              远心镜头：
   物体前移→成像变大         物体前移→成像大小不变
     ◄ 大  小 ►              ▉  ▉  ▉ （放大率恒定）
   有透视误差，测量会飘        无透视误差，测量稳准
```

代价是：远心镜头的**镜头口径必须 ≥ 被测物**，所以又大又重又贵。因此它只用在**对尺寸精度要求高**的场合（[第 78 章 精密测量](ch78-metrology.md) 那类任务），一般定位、读码用普通镜头即可。

## 相机与传感器：拍全景还是拍高速？

### 面阵 vs 线阵

- **面阵相机（area scan）**：一次拍一整幅二维图像，最常用，绝大多数场景都用它。
- **线阵相机（line scan）**：一次只拍**一行**像素，靠物体与相机的**相对运动**把一行行"扫"成完整图像。适合**高速连续卷材**（布匹、纸张、钢卷、印刷）、超大幅面、以及圆柱体表面"展开"检测。代价是必须有稳定匀速的运动配合（常用**编码器**触发每一行），系统更复杂。

### 全局快门 vs 卷帘快门

| | 全局快门 global | 卷帘快门 rolling |
|---|---|---|
| 曝光方式 | 所有像素**同时**曝光 | **逐行**先后曝光 |
| 拍高速运动 | 不变形，清晰 | "果冻效应"、倾斜/扭曲 |
| 成本 | 较高 | 较低（手机、普通工业相机常见） |
| 选用 | **动目标、高速产线选它** | 静态或慢速场景够用 |

拍运动物体还有一条铁律：**曝光时间要短到让运动模糊小于允许的像素数**。物体飞快经过时，曝光越长拖影越明显；所以高速场景常用"**短曝光 + 频闪强光 + 硬触发**"三件套——用极短的强光脉冲"冻住"运动。

> 🕳️ **坑**：用卷帘快门拍飞速经过的工件，拍出来的方孔会变成平行四边形、圆会变歪——不是算法的错，是快门类型选错了。**动态场景一律优先全局快门。**

### 分辨率与测量精度

这是最容易被忽视、却直接决定"测得准不准"的一环。关键指标是**每像素对应的物理尺寸**（也叫 GSD）：

\\[ \text{每像素尺寸} = \dfrac{\text{FOV}}{\text{该方向像素数}} \\]

它是测量精度的**物理下限**——一个像素对应 0.1mm，你就别指望裸测出 0.05mm 的差异（除非上**亚像素**技术，见 [第 78 章](ch78-metrology.md)）。想提高精度，只有三条路：**提高相机分辨率、缩小视场（换长焦或拉近）、或用亚像素算法**。

## 触发与工业接口（进阶）

实验室里手动拍一张就够了，但产线要**在工件恰好到位的一瞬间**拍、还要多相机协同，这就绕不开触发与接口：

- **硬触发（hardware trigger）**：用**光电传感器/PLC 信号**在工件到位时精准触发相机曝光，而不是软件轮询——延迟低、抖动小。配合**频闪灯同步**，让强光脉冲和曝光对齐。
- **编码器触发**：线阵相机按传送带**编码器**脉冲逐行采集，保证不同速度下图像不被拉伸/压扁。
- **工业接口与协议**：常见 **GigE Vision（千兆网）/ USB3 Vision / Camera Link**，多数遵循 **GenICam** 标准统一配置参数；多相机高精度同步用 **PTP 时间同步**。这些和网络带宽、丢包重传、多相机拓扑一起，构成"能不能稳定不丢帧"的工程底座。
- **留痕便于排障**：记录每帧的**曝光、增益、温度、触发计数和帧号（frame id）**，一旦漏帧或图像异常，靠这些日志能快速定位是触发丢了、带宽爆了还是温漂了。

> 💡 **提示**：**方案要用数据验证，别靠"看起来清楚"。** 老手定方案会量化**对比度、信噪比(SNR)、边缘宽度/MTF** 等指标，甚至做**实验设计(DoE)** 对比不同打光/镜头组合，并在速度上限、多相机带宽、温漂条件下做长稳测试——而不是凭肉眼"感觉这样打挺亮"。

## 动手写代码：算视场与每像素物理尺寸

把上面的公式写成一个小工具，输入传感器尺寸、焦距、工作距离和像素数，直接算出**视场**和**每像素对应多少毫米**——选型时拿它先估一把。纯计算，不需要任何图像库。

新建 `code/examples/ch82_optics.rs`：

```rust
/// 相机在某一方向（水平或竖直）的光学参数
struct Optics {
    sensor_mm: f64, // 传感器该方向的物理尺寸(mm)
    focal_mm: f64,  // 镜头焦距(mm)
    wd_mm: f64,     // 工作距离：镜头到被测物(mm)
    pixels: u32,    // 该方向的像素数
}

impl Optics {
    // FOV ≈ 传感器尺寸 × 工作距离 / 焦距
    fn fov_mm(&self) -> f64 {
        self.sensor_mm * self.wd_mm / self.focal_mm
    }
    // 每像素对应的物理尺寸(mm/像素)——测量精度的物理下限
    fn mm_per_pixel(&self) -> f64 {
        self.fov_mm() / self.pixels as f64
    }
}

fn main() {
    // 场景 A：16mm 镜头
    let a = Optics { sensor_mm: 8.0, focal_mm: 16.0, wd_mm: 400.0, pixels: 2000 };
    println!("[A] FOV ≈ {:.1} mm，每像素 ≈ {:.1} µm",
             a.fov_mm(), a.mm_per_pixel() * 1000.0);

    // 场景 B：只把镜头换成长焦(35mm)，看视场变窄、精度变高
    let b = Optics { sensor_mm: 8.0, focal_mm: 35.0, wd_mm: 400.0, pixels: 2000 };
    println!("[B] FOV ≈ {:.1} mm，每像素 ≈ {:.1} µm",
             b.fov_mm(), b.mm_per_pixel() * 1000.0);
}
```

运行：

```bash
cargo run --example ch82_optics
```

实测输出：

```text
[A] FOV ≈ 200.0 mm，每像素 ≈ 100.0 µm
[B] FOV ≈ 91.4 mm，每像素 ≈ 45.7 µm
```

一目了然：同一台相机、同样的工作距离，只把 16mm 换成 35mm 长焦，视场从 200mm 缩到 91mm，每像素的物理尺寸从 100µm 降到 46µm——**精度翻倍，但能看的范围也砍掉一半多**。选型的本质，就是在这张"精度 vs 范围"的跷跷板上找平衡点。

## 常见坑与提示

> 🕳️ **坑**：**只顾算法、不管打光，是新手最大的误区。** 花一周调算法检不出的缺陷，可能换个打光方式当天就解决。遇到"怎么调都检不好"，先回头审视打光，别死磕代码。

> ⚠️ **注意**：**反光和阴影是隐形杀手。** 金属、玻璃、抛光面的镜面反光会形成大片过曝白斑，盖住真实特征；杂乱阴影会被误当成缺陷。对策是选对光型（同轴/穹顶光治镜面、暗场光治纹理）并加偏振片，而不是回头怪算法。

> 🕳️ **坑**：**景深不足 = 一部分清楚一部分糊。** 工件有高低起伏时，光圈开太大（F 数小）会让景深太浅。适当收小光圈换景深，但记得同步加强打光补回损失的光量（也留意光圈过小引起的衍射）。

> ⚠️ **注意**：**分辨率不够，精度就是上不去。** 测量精度受"每像素物理尺寸"硬约束。上项目前务必用本章的小工具估一把 GSD，确认它满足公差要求，再去写测量算法——否则算法再精细也白搭。

## 本章小结

- **打光决定成败**：目标是放大"目标特征与背景的对比"。背光测轮廓、同轴/穹顶光治镜面、暗场（低角度）查划痕，是几大经典套路；颜色光与滤镜可"挑出"特定颜色、压掉反光。
- **镜头三角关系**：\\( \text{FOV} \approx \text{传感器尺寸} \times \text{WD} / f \\)。焦距长→视场窄精度高；还要关注景深、畸变，且**分辨率够不等于清晰度够**（受 MTF/衍射制约）。**远心镜头**放大率恒定、无透视误差，是精密测量首选，代价是又大又贵。
- **相机选型**：面阵通用、线阵专攻高速卷材；动目标必用**全局快门** + 短曝光 + 频闪，卷帘快门拍高速会变形。
- **工程底座**：硬触发/编码器触发保证"拍得准"，GigE/USB3 Vision + GenICam + PTP 保证"传得稳、同步齐"，记录帧号/曝光/温度便于排障。
- **精度看 GSD**：每像素物理尺寸 = FOV / 像素数，是测量精度的物理下限；要更准就提分辨率、缩视场或上亚像素（见 [第 78 章](ch78-metrology.md)）。

## 动手练习

1. **反推工作距离**：已知传感器 8mm、要求视场覆盖 150mm、镜头 12mm，用本章公式反解需要的工作距离 WD，再改代码验证。
2. **精度够不够**：某任务要测 ±0.02mm 的尺寸，相机 2500 像素、视场 100mm。算出每像素尺寸，判断裸分辨率够不够；不够的话，要把视场缩到多少（或分辨率提到多少）才行？
3. **给场景配打光**：为下面三个任务各选一种打光方式并说明理由——(a) 检查透明塑料瓶身有无气泡；(b) 读金属件上的激光打标 DataMatrix（[第 81 章](ch81-code-reading.md)）；(c) 检查手机中框边缘的细微划痕。
4. **想一想（进阶）**：为什么高速运动的产品要用"全局快门 + 短曝光 + 频闪强光 + 硬触发"这一整套？（提示：短曝光防运动模糊，但曝光短进光少要强光补偿，硬触发保证在工件到位的精确时刻曝光，卷帘快门则会让运动物体变形。）

## 第十七部分阶段验收：工业方案验收包

针对一个真实零件提交：视野/最小缺陷/像元覆盖/景深/运动模糊/带宽计算，光源与镜头 DoE，
标定误差地图，测量 GR&R，按批次冻结的漏检与过杀置信区间，以及节拍和最坏热态性能。
接入硬触发与帧 id，注入漏触发、丢包、温漂、焦点漂移和脏污。最终交付接受标准、维护与
重标定条件、备件清单和回退方案；一次实验室演示不能算工业验收。
