# 第 43 章 微调自己的分类器：数据、策略与消融

> **本章导读**
> - 学完你能：把 [第 42 章](ch42-candle-classify.md) 那个"通才"小 CNN，用**少量新数据微调（fine-tune）**成一个全新任务的"专才"分类器——这就是**迁移学习**（[第 41 章](../p07-dl-basics/ch41-training-tricks.md) 讲过直觉）的实战。
> - 你会亲手做到三件关键事：**加载并冻结骨干（backbone）**、**换上新类别数的新分类头（head）**、**只训练新头**——并**实测微调前后在新任务上的准确率跳变**。
> - 你会看清 candle 里"**哪些参数参与优化、哪些被冻结**"到底怎么写，还会用一个小实验**证明骨干真的纹丝没动**。
> - 代码在本机 `cargo run --release` 实测，正文数字均为真实输出。

## 场景：只有 300 张图，还想训出好模型

假设你要做一个新的分类任务——比如区分产线上四种零件形态——但手里只有几百张图。从零训练一个 CNN？数据太少，[第 41 章](../p07-dl-basics/ch41-training-tricks.md) 说过，这种情况下网络会疯狂**过拟合**，怎么增强都不够。

正确姿势是**迁移学习**：[第 42 章](ch42-candle-classify.md) 那个模型的骨干，在"竖条 / 横条 / 方块"上已经学会了通用的视觉基本功——**认边缘、认朝向、认团块**。这套"眼力"换个任务照样管用。我们不必从零学，只要**保留这套现成的眼力，换掉最后做决策的那一层**，用少量新数据把它调过来即可。

> 📖 **术语**：**微调（fine-tuning）**。拿一个预训练模型，在你自己的（通常较小的）数据集上继续训练，让它适配新任务。最常见的做法是**冻结骨干、只训练新分类头**——因为骨干学到的底层特征是通用的，可以直接复用，真正需要"重新学"的只是"怎么根据这些特征做新的分类决策"。这也是为什么**少量数据也能 work**：你要学的参数极少（本章实测只有 260 个）。

## 原理：冻结骨干、换头、只训新头

**直觉**：一个见多识广的老师傅（骨干），已经会"看料、辨纹理、识形状"。现在换了个新活儿，你不用把他重新培训一遍，只要教他"这个新活儿里，什么样的特征算 A 类、什么样算 B 类"——也就是**只训练最后那个做判断的"头"**。

```text
        预训练骨干（在任务 A 上学好：认竖条/横条/方块 → 会抽"边缘/朝向/团块"特征）
   ┌──────────────── backbone ────────────────┐   ┌── head ──┐
   │  conv1  →  conv2  →  fc1（输出 64 维特征） │ → │  Linear  │ → logits
   └───────────────────────────────────────────┘   └──────────┘

   策略一：冻结骨干，只训新头（本章动手做的）
     ├─ 骨干权重原样不动（不交给优化器）
     └─ 只训练一个新的 Linear(64 → 新类别数)，参数极少、又快又稳

   策略二：全网微调
     ├─ 骨干也一起训，但用很小的学习率
     └─ 更贴合新数据，但数据少时易过拟合、还可能"灾难性遗忘"
```

**为什么要换头？** 骨干输出的是 64 维特征，和任务无关；但**分类头的输出维度 = 类别数**。任务 A 是 3 类，新任务 B 是 4 类，输出维度对不上，所以必须**丢掉旧头、新建一个 `Linear(64 → 4)`**，从随机初始化开始训。

**两种策略怎么选？**

- **冻结骨干、只训新头**（本章）：新任务和预训练任务比较像、或数据很少时首选。参数少、训练快、不容易过拟合。
- **全网小学习率微调**：新任务和预训练差别大时更有必要。它连骨干一起微调，但学习率必须**很小**，否则会把宝贵的预训练特征"冲坏"。

> 📖 **术语**：**灾难性遗忘（catastrophic forgetting）**。用大学习率去微调整个网络时，骨干里那些通用特征会被新任务的梯度迅速覆盖、"忘掉"原来学到的东西，结果两头不讨好。这正是"全网微调必须用小学习率"的原因。进阶做法是**分层学习率**：越靠近输出的层学得越快、越靠近输入的层学得越慢，第 \\( l \\) 层用 \\( \eta_l = \eta_{\text{head}}\, \gamma^{L-l} \\)（其中 \\( 0 < \gamma < 1 \\)），让底层特征只被轻轻带动。

## 动手：冻结骨干 + 新头 + 只训新头

> ⚠️ **注意**：本章基于 **candle 0.11.0**，纯 CPU，接着 [第 42 章](ch42-candle-classify.md) 的模型来做。完整独立工程见 `code/dl_labs/ch43_finetune/`，**`cd` 进去 `cargo run --release`**。为了让本章能**独立跑通**，工程开头会先按第 42 章的方式把骨干在任务 A 上训练好并存成 `cnn.safetensors`（这段代码与第 42 章一致，不再赘述），然后进入微调正题。

`Cargo.toml`（比第 42 章还少一个依赖——微调不碰图片文件，纯张量计算）：

```toml
[package]
name = "ch43_finetune"
version = "0.1.0"
edition = "2021"

[workspace] # 让本工程独立，不被上层 code/Cargo.toml 收编（别处 cargo new 不需要这行）

[dependencies]
candle-core = "0.11.0"
candle-nn = "0.11.0"
```

骨干结构和第 42 章的 `SmallCnn` 一模一样，只是**单独拎出来**（不含 head）：

```rust
struct Backbone { conv1: Conv2d, conv2: Conv2d, fc1: Linear }
impl Backbone {
    fn load(vb: VarBuilder) -> Result<Self> {
        let cfg = Conv2dConfig { padding: 1, ..Default::default() };
        Ok(Self {
            conv1: conv2d(3, 8, 3, cfg, vb.pp("conv1"))?,
            conv2: conv2d(8, 16, 3, cfg, vb.pp("conv2"))?,
            fc1:   linear(16 * 7 * 7, 64, vb.pp("fc1"))?,
        })
    }
    fn features(&self, x: &Tensor) -> Result<Tensor> {
        let x = self.conv1.forward(x)?.relu()?;
        let x = x.max_pool2d(2)?;
        let x = self.conv2.forward(&x)?.relu()?;
        let x = x.max_pool2d(2)?;
        let x = x.flatten_from(1)?;
        self.fc1.forward(&x)?.relu()
    }
}
```

### 第一步：加载骨干，并"冻结"它

这是全章最妙的一处——**冻结几乎不需要额外代码**：

```rust
// from_mmaped_safetensors 读进来的是普通常量张量（不是 Var），天然不参与梯度更新 → 这就是"冻结"
let vb = unsafe { VarBuilder::from_mmaped_safetensors(&["cnn.safetensors"], DType::F32, &dev)? };
let backbone = Backbone::load(vb)?; // 只取 conv1/conv2/fc1；文件里旧的 3 类 head 直接忽略
```

> 📖 **术语**：**冻结（freeze）**。让某些参数在训练中**保持不变、不被优化器更新**。candle 里，`from_mmaped_safetensors` 加载出来的是**常量 `Tensor`**（不是可训练的 `Var`），所以它们**根本不会拿到梯度、也不会被更新**——这就天然实现了冻结。文件里那个旧的 3 类 head？我们 `load` 时压根没请求它，多出来的键会被自动忽略。

### 第二步：换上新任务的新头（4 类），这才是"可训练"的部分

新头放在**单独的 `VarMap`** 里——这是"哪些参数参与优化"的关键：

```rust
let head_vm = VarMap::new();                                   // 只装 head 的参数
let head_vb = VarBuilder::from_varmap(&head_vm, DType::F32, &dev);
let head = linear(64, TASK_B.len(), head_vb.pp("head"))?;      // 新头：64 → 4 类
det_init(&head_vm, 7)?;                                        // 随机初始化新头
```

于是"可训练的"和"冻结的"泾渭分明。打印一下参数量对比：

```text
冻结骨干参数 = 51632 个；新分类头可训练参数 = 260 个（2 个张量）
```

**5 万多个参数被冻结，真正要训练的只有新头的 260 个**（一个 `[4,64]` 的 weight 加一个 `[4]` 的 bias）——这就是"少量数据也能 work"的底气。

### 第三步：微调前先测一发（基线）

新头是随机初始化的，此刻在新任务上应该约等于**瞎猜**：

```rust
// 用"骨干 + 头"算准确率；acc(...) 内部就是 head.forward(&backbone.features(x)) 再 argmax
println!("微调前：训练 acc = {:.1}%   测试 acc = {:.1}%",
    acc(&backbone, &head, &xb, &bo)? * 100.0, acc(&backbone, &head, &xbe, &beo)? * 100.0);
```

```text
微调前（随机初始化的新头）：训练 acc = 25.0%   测试 acc = 25.0%
```

**25% 正是 4 类瞎猜的理论基线**（1/4）。这就是我们要超越的起点。

### 第四步：只训练新头（骨干冻结）

优化器**只拿到 `head_vm.all_vars()`**——也就是只有新头的那 2 个张量会被更新，骨干碰都不碰：

```rust
// 关键：优化器只收到 head 的 Var → 只有新头被更新，骨干纹丝不动
let mut opt = AdamW::new(head_vm.all_vars(), ParamsAdamW { lr: 1e-2, ..Default::default() })?;
for epoch in 1..=60 {
    let feat = backbone.features(&xb)?;                      // 前向经过冻结骨干
    let loss = cross_entropy(&head.forward(&feat)?, &yb)?;   // 交叉熵（内部含 softmax）
    opt.backward_step(&loss)?;                              // 反向 + 更新，只动 head
    if epoch % 15 == 0 { println!("  epoch {epoch:>2}  loss = {:.4}", loss.to_scalar::<f32>()?); }
}
```

新任务 B 是 4 个全新形状：**左斜线 `\`、右斜线 `/`、十字 `+`、圆盘**。它们骨干从没见过，但都由"边缘 / 朝向 / 团块"这些基本特征组合而成——正好能复用骨干的眼力。训练输出：

```text
开始微调（冻结骨干，只训新头，AdamW，lr=1e-2）...
  epoch 15  loss = 0.2671
  epoch 30  loss = 0.0841
  epoch 45  loss = 0.0430
  epoch 60  loss = 0.0294
```

### 第五步：微调后再测，并证明骨干没被动过

```text
微调后（训好的新头）：    训练 acc = 100.0%   测试 acc = 100.0%

[冻结验证] 骨干 conv1.weight 和值 微调前=1.417208 微调后=1.417208（完全一致，骨干未被更新）
```

**准确率从 25% 跳到 100%**——只训练了 260 个参数、几十轮，就把一个"只会认竖横方块"的骨干，变成了"会认斜线、十字、圆盘"的新分类器。这就是迁移学习的威力。

而那行**冻结验证**是本章的点睛之笔：我们在训练前后各算了一次骨干 `conv1.weight` 的**和值**，两次**完全相同**（`1.417208`）。它用实测证明：优化器确实只动了新头，**骨干的每一个权重都原封未动**。实现它只要在训练前后各取一次骨干权重的指纹：

```rust
let bb_w0 = backbone.conv1.weight().sum_all()?.to_scalar::<f32>()?; // 训练前
// ……微调……
let bb_w1 = backbone.conv1.weight().sum_all()?.to_scalar::<f32>()?; // 训练后：与 bb_w0 相同
```

> 💡 **提示**：**这个"权重指纹"技巧值得随手备着。** 想确认某部分参数到底有没有被训到？训练前后各取一次它的和值（或范数）比一比即可——变了就是在训、没变就是冻住了。比对着日志猜半天，不如让数字说话。

## 常见坑与提示

> 🕳️ **坑**：**类别数变了，就必须换头，不能直接加载旧头。** 任务 A 是 3 类、任务 B 是 4 类，旧头输出维度是 3，形状对不上。硬把旧头 `Linear(64,3)` 的权重加载进 `Linear(64,4)` 会直接报形状错。正确做法就是本章这样：**只加载骨干，新头从随机初始化重新训**。

> ⚠️ **注意**：**微调的学习率要拿捏。** 只训新头时可以用相对大一点的学习率（本章用 `1e-2`）——反正骨干冻着，冲不坏。但一旦改成**全网微调**（连骨干一起训），学习率就必须调**很小**（比如 `1e-4`），否则会把预训练特征冲坏、发生**灾难性遗忘**。一句话：**冻着的部分不怕大步子，要动的预训练部分必须小步走。**

> 🕳️ **坑**：**数据少，最容易过拟合。** 微调的典型场景就是数据少，这时"训练集 100%、测试集却很差"是常态。对策：**冻结更多层**（可训练参数越少越不容易过拟合）、**加数据增强**（[第 41 章](../p07-dl-basics/ch41-training-tricks.md)）、**早停**。本章训练/测试都 100%，是因为合成形状**区分度太大**——[第 40 章](../p07-dl-basics/ch40-burn-train.md) 早就提醒过：**别被合成数据的满分冲昏头**，真实业务数据绝不会这么听话（[第 16 章](../p03-classic/ch16-threshold.md) 讲指标时也强调过这一点）。

> ⚠️ **注意**：**冻结哪些层，是个需要权衡的选择。** 新任务越接近预训练任务，就可以冻得越多（甚至只训头）；差别越大，越需要放开更靠后的层一起微调。经验法则：**先只训头**跑个基线，不够好再逐段解冻，别一上来就全网微调。

> 🕳️ **坑**：**训练和评估的"模式"要分清。** 如果网络里有 **Dropout** 或 **BatchNorm**（[第 41 章](../p07-dl-basics/ch41-training-tricks.md)），它们在训练和推理时行为不同（Dropout 推理时要关掉、BatchNorm 用的是训练期统计量）。本章的小 CNN 没用这两者所以无需切换，但用到时**务必在评估前切到 eval 模式**，否则准确率会莫名其妙地抖。

## 本章小结

- **微调 = 迁移学习的实战**：加载预训练**骨干**、冻结它、换上**新类别数的新头**、只训练新头。少量数据也能 work，因为要学的参数极少（本章实测仅 **260** 个 vs 冻结的 **51632** 个）。
- candle 里**冻结几乎零成本**：`from_mmaped_safetensors` 加载出来是**常量张量**（非 `Var`），天然不被更新；新头放**单独的 `VarMap`**，优化器只收 `head_vm.all_vars()`——**这就精确控制了"谁参与优化"**。
- 我们实测：新任务 4 类，**微调前 25%（=瞎猜）→ 微调后 100%**；并用"权重指纹"证明骨干 `conv1.weight` 和值**前后一致**、纹丝没动。
- 两种策略：**冻结骨干只训头**（快、稳、抗过拟合，任务相近时首选）vs **全网小学习率微调**（更贴合新数据，但要防**灾难性遗忘**与过拟合）。

## 动手练习

1. **改学习率**：把新头的 `lr` 从 `1e-2` 调成 `1e-4` 和 `1e-1`，各跑一遍，观察 loss 下降速度和最终准确率——体会"步子太小磨蹭、太大发飘"。
2. **做全网微调**：把骨干也改成可训练的（用 `VarBuilder::from_varmap` 载入骨干权重、和新头放进同一个 `VarMap`、一起交给优化器），用**很小**的学习率跑，比较它和"只训头"的收敛与最终准确率，并再用"权重指纹"确认这次骨干**确实被更新了**。
3. **减数据看过拟合**：把新任务每类的训练样本从 60 张减到 5 张，看训练集和测试集准确率是否拉开差距，亲手制造一次"过拟合"。
4. **想一想（呼应 [第 41 章](../p07-dl-basics/ch41-training-tricks.md)）**：你要区分 3 种螺丝的合格/次品，只有 300 张图。你会冻结骨干只训头，还是全网微调？新头输出几类？为什么骨干的学习率（如果要训）一定要设得很小？

## 专家补强：让"准确率提升"经得起追问

25%→100% 很好看，但专家级的微调，问的是更硬的问题：**预训练表示和目标域到底有多接近、哪些参数该改、数据划分能否代表部署分布、收益能不能靠受控实验解释。** 进阶时请建立这套纪律：

- **先建不可作弊的基线**：按**主体 / 批次 / 相机 / 时间**分组划分数据（别把同一物体的近重复图既放训练又放测试，那会严重泄漏），冻结测试集后，依次跑"多数类基线 → 只训线性头 → 解冻最后一段 → 全量微调"，用**同一份数据、同一套评估脚本**横向比。
- **消融要单因素**：把"冻结权重"和"是否更新 BatchNorm 运行统计"当成**两个独立**的实验因素；每次只改一个，才能说清收益来自哪。
- **指标别只看 accuracy**：报告**混淆矩阵、macro-F1、每类召回、概率校准（ECE）**；数据不平衡时，类别权重 / 重采样 / focal loss 解决的是不同问题，别无脑叠加。
- **多种子 + 存档**：至少三个随机种子，报均值和标准差；存下配置、数据划分、权重校验和与失败样本，并和"从零训练"基线对比，**证明预训练确实带来了收益**。
