# 第 17 章 · 关键点与姿态模型：骨架与人脸关键点

> **本章导读**：第 16 章我们让 YOLO 吐出一个个"框"，回答了"这里有一个人"。可很多业务还想再往里追一层——这个人是站着、坐着，还是摔倒了？手举起来没有？两个人是不是在拉扯？要回答这些，光有框不够，得知道**关节在哪**。本章讲**关键点（keypoint，目标上带语义的"点"）模型**：它的输出不再是框，而是一组坐标——人体的鼻、肩、肘、腕，或人脸的眼角、嘴角。读完你会搞懂关键点的两大流派（热力图 vs 直接回归）、看清 YOLOv8-pose 如何把"检测 + 关键点"合成一个 `[1,56,8400]` 输出、学会把点从 640 画布还原回原图、并按"骨架"把点连成一个火柴人。最后的人脸关键点一节，还会为第 20 章的人脸对齐埋下伏笔。

## 17.1 从"框"到"点"：关键点在解决什么问题

先回忆一下前一章。检测模型（第 16 章）给你的是一个**框**：`(x1, y1, x2, y2)` + 类别 + 置信度，它只告诉你"这一块区域里有个人"。可框是个笨拙的矩形，它不知道人的**姿势**——一个站着的人和一个躺着摔倒的人，框可能长得差不多。

**关键点模型**要做的，是在目标身上**精确定位一组有语义的点**。"有语义"是关键：不是随便找点，而是"这一点是鼻子、那一点是左手腕"。有了这些点的坐标，姿态、动作、朝向就都能算出来了。

打两个生活比方：

- **连连看的点**：关键点就像连连看棋盘上一个个固定位置的图案，位置本身有含义。你把这些点按规则连起来，就还原出一个人的轮廓骨架。
- **提线木偶的关节**：木偶身上有十几个固定的"关节孔"（脖子、肩、肘、膝……），提线师傅拉动这些点，木偶就摆出各种姿势。关键点模型干的，正是"反过来"——看一张照片，把这些关节孔的位置一个个标出来。

关键点能做的事非常多，都建立在"点的坐标"之上：

| 业务 | 用到的点 | 怎么用 |
| --- | --- | --- |
| 摔倒检测 | 人体关节 | 看躯干是不是接近水平、重心是否贴地 |
| 健身计数 | 肩、肘、腕 | 算胳膊夹角，判断一次"举起-放下" |
| 举手/招手识别 | 腕、肩 | 看手腕是否高过肩膀 |
| 人脸对齐（第 20 章） | 眼、鼻、嘴 | 把歪脸摆正，再送去识别 |
| AR 贴纸 / 美妆 | 人脸密集点 | 沿着眼、唇轮廓贴特效 |

一句话：**检测回答"在哪"，关键点回答"什么姿势/什么结构"**。

## 17.2 两类关键点任务：人体 17 点与人脸 5/68/106 点

工程里最常见的关键点任务就两大类：人体姿态、人脸关键点。它们最大的共同点是——**点的个数、顺序、含义都是"约定死"的**。模型输出第 5 个点，它就固定是"左肩"，你不能自己改。这个"索引 → 部位"的对应表，是用好关键点的第一张必背表。

### 人体姿态：COCO 17 点

业界事实标准是 **COCO 数据集的 17 个人体关键点**（COCO 是一个百万级标注图像数据集，姿态任务用它的 17 点定义）。索引 0~16 固定如下：

| 索引 | 英文名 | 部位 | 索引 | 英文名 | 部位 |
| --- | --- | --- | --- | --- | --- |
| 0 | nose | 鼻子 | 9 | left_wrist | 左手腕 |
| 1 | left_eye | 左眼 | 10 | right_wrist | 右手腕 |
| 2 | right_eye | 右眼 | 11 | left_hip | 左髋 |
| 3 | left_ear | 左耳 | 12 | right_hip | 右髋 |
| 4 | right_ear | 右耳 | 13 | left_knee | 左膝 |
| 5 | left_shoulder | 左肩 | 14 | right_knee | 右膝 |
| 6 | right_shoulder | 右肩 | 15 | left_ankle | 左脚踝 |
| 7 | left_elbow | 左肘 | 16 | right_ankle | 右脚踝 |
| 8 | right_elbow | 右肘 | | | |

> 一个必须先说清的坑：这里的 **left/right 是"被拍的人"自己的左右**，不是你看画面的左右。一个人正对镜头站着，他的"左肩"（索引 5）出现在**你视野的右边**。搞反了，后面画骨架、算动作全乱。17.10 节还会再强调这件事。

### 人脸关键点：5 点 / 68 点 / 106 点

人脸关键点（业界也叫 **facial landmark，人脸地标点**）按"点的密度"分几档，用途各不相同：

| 点数 | 覆盖 | 典型用途 |
| --- | --- | --- |
| **5 点** | 左眼、右眼、鼻尖、左嘴角、右嘴角 | **人脸对齐**——把歪脸摆正再做识别（第 20 章） |
| **68 点** | 脸颊轮廓、眉、眼、鼻、唇的密集描边 | 表情分析、换脸、AR 美妆 |
| **106 点 / 更多** | 更密，含眼睑、唇内外缘等细节 | 精细美颜、虚拟试妆（国内商业 SDK 常见） |

其中 **5 点最常用、最实用**：点少、算得快，且足够撑起"把人脸对齐到标准姿态"这件核心事（17.9 节展开，细节留给第 20 章）。

## 17.3 两大流派：热力图法 vs 直接回归法

模型怎么把一个点的坐标"说"出来？有两条技术路线，理解它们的差别，你才看得懂不同模型的输出长什么样。

### 热力图法（heatmap）：输出概率图，取峰值

**热力图法**不直接给坐标，而是为**每个关键点输出一整张概率图**（heatmap，热力图）。这张图和输入差不多大，每个格子上的数值表示"这个关键点落在这里的概率"。真正的关键点位置，就在这张图**数值最高的那个格子**——用 **argmax（取最大值所在的位置）** 找出来。

打个比方：这就像用一张"温度分布图"找热源——不直接报坐标，而是画一张热成像图，最红最烫的那一点就是答案。17 个关键点，就输出 17 张这样的热力图。

它的好处是**精度高**：概率图保留了完整的空间信息，峰值能定位得很准，还能通过看峰值附近的数值做亚像素级微调。代价是**慢、吃显存**：要生成并处理 K 张较大的图。追求精度的人体姿态模型（HRNet、SimpleBaseline 等）都走这条路。

### 直接回归法（regression）：网络直接吐坐标

**直接回归法**简单粗暴：网络最后一层直接输出一串数字，就是各个点的 `(x, y)` 坐标，不绕概率图。

好处是**快、省**：没有大热力图，一步到位。代价是精度通常略逊于热力图法（把"定位"硬压成几个回归数值，空间信息丢得多）。但对人脸这种"区域小、结构规整"的任务，回归法精度完全够用，所以**人脸关键点几乎都用回归**；实时人体姿态（如 YOLOv8-pose）为了速度也用回归。

### 一表看清两派

| 对比项 | 热力图法（heatmap） | 直接回归法（regression） |
| --- | --- | --- |
| 输出形式 | 每个点一张概率图（K 张） | 直接一串 `(x, y)` 数值 |
| 求坐标 | 在概率图上 **argmax** 取峰值 | 网络直接给，无需解码峰值 |
| 精度 | 高（空间信息保留好） | 稍逊，但多数场景够用 |
| 速度 / 显存 | 慢、吃显存 | 快、省 |
| 典型模型 | HRNet、SimpleBaseline | YOLOv8-pose、人脸 landmark 网络 |
| 常见场景 | 高精度人体姿态 | 实时姿态、人脸对齐 |

下面 17.4 讲热力图怎么解码（因为它多一道"从图到坐标"的手续），17.5 讲我们主线用的 YOLOv8-pose（回归派）输出结构。

## 17.4 热力图怎么变成坐标：argmax 求峰值 + 缩放回原图

热力图法的核心手续，就是把一张概率图"翻译"成一个坐标。分两步：**① 找峰值（argmax）→ ② 把峰值坐标缩放回原图**。

### 手算一遍 argmax

假设某个关键点（比如鼻子）的热力图是下面这张 4×4 的小图（真实模型是几十×几十，原理一样）。每个格子是概率：

```text
        列 x →   0      1      2      3
  行 y ↓
   0           0.01   0.02   0.00   0.00
   1           0.03   0.20   0.65   0.05
   2           0.02   0.30   0.92   0.10   ← 这一格最大
   3           0.00   0.08   0.15   0.01
```

扫一遍所有格子，最大值 **0.92** 落在**第 2 行、第 2 列**。所以：

- 关键点在热力图里的坐标是 **(x=2, y=2)**；
- 这个点的**置信度**就取峰值本身 **0.92**（后面用来判断可见性）。

这就是 argmax：不是取"最大的值"，而是取"最大值**所在的位置**"。

### 把热力图坐标缩放回去

热力图通常比模型输入**小一圈**。举个真实数字：一个自顶向下（top-down）的姿态模型，把人裁出来缩放成 `192×256`（宽×高）送进网络，输出的热力图是 `48×64`。两者宽高都差 4 倍，这个倍数叫**步长（stride）**：

$$
\text{stride}_x = \frac{192}{48} = 4, \qquad \text{stride}_y = \frac{256}{64} = 4
$$

所以热力图上的一格，对应输入图上的 4 个像素。把峰值格子换算成输入坐标时，习惯上取格子**中心**（`+0.5`）：

$$
x_{\text{输入}} = (x_{\text{热图}} + 0.5)\times \text{stride}_x, \qquad y_{\text{输入}} = (y_{\text{热图}} + 0.5)\times \text{stride}_y
$$

比如峰值在热力图 `(24, 30)`，换算到输入就是 `((24+0.5)×4, (30+0.5)×4) = (98, 122)`。

**最后一步和检测框一模一样**：从"模型输入坐标系"还原回**原图**，要逆着预处理时做的几何变换来一遍——letterbox 就减 pad、除 scale（第 10 章、第 16 章反复讲的那套），裁剪-缩放就套裁剪的逆变换。这条"预处理做了啥、后处理就逆着做啥"的镜像原则（第 10 章 10.9 节），在关键点这里同样成立。

### 代码：argmax + 缩放到输入坐标

先写一个"在一张热力图上找峰值"的函数，再写"把 K 张热力图批量解码"的函数：

```rust
use ndarray::{ArrayView2, ArrayView3, Axis};

// 复用本章 17.6 会定义的 Keypoint（这里先假设它已存在）

/// 在一张热力图上找峰值，返回 (峰值列 x, 峰值行 y, 峰值分数)
fn heatmap_argmax(hm: ArrayView2<f32>) -> (usize, usize, f32) {
    let (rows, cols) = hm.dim();               // ndarray 里 Ix2 的 dim() 给 (行, 列)
    let (mut best_x, mut best_y, mut best_v) = (0usize, 0usize, f32::MIN);
    for y in 0..rows {
        for x in 0..cols {
            let v = hm[[y, x]];                 // 注意索引是 [行, 列] = [y, x]
            if v > best_v {
                best_v = v;                     // 记住最大值……
                best_x = x;                     // ……以及它所在的位置（这才是 argmax）
                best_y = y;
            }
        }
    }
    (best_x, best_y, best_v)
}

/// 把一组热力图 [K, Hh, Wh] 解码成 K 个关键点（坐标先落在"模型输入"坐标系）。
/// input_w / input_h 是模型输入尺寸（如 192 / 256）；热力图通常小一圈（如 48 / 64）。
fn decode_heatmaps(heatmaps: ArrayView3<f32>, input_w: f32, input_h: f32) -> Vec<Keypoint> {
    let (k, hh, wh) = heatmaps.dim();
    let stride_x = input_w / wh as f32;         // 一个热图格子 = 输入里多少像素
    let stride_y = input_h / hh as f32;

    let mut kps = Vec::with_capacity(k);
    for j in 0..k {
        let hm = heatmaps.index_axis(Axis(0), j);       // 取第 j 张热力图 [Hh, Wh]
        let (px, py, score) = heatmap_argmax(hm);
        // 峰值格子中心（+0.5）→ 输入像素坐标
        let x = (px as f32 + 0.5) * stride_x;
        let y = (py as f32 + 0.5) * stride_y;
        // 注意：这还只是"输入坐标系"，最后还得逆变换回原图（同第 10 章 letterbox 逆）
        kps.push(Keypoint { x, y, score });
    }
    kps
}
```

> **工程上通常会**在 argmax 之后再做一次**亚像素微调**：看峰值格子上下左右邻居的数值，往数值更大的方向偏移零点几个格子（经典做法叫 DARK / 泰勒展开修正）。这能显著提升精度，但原理不变——本书先掌握"argmax + 缩放"这条主干。

## 17.5 YOLOv8-pose 的输出：检测 + 关键点合一

本书主线用的是 **YOLOv8-pose**——它属于直接回归派，而且巧妙地把"检测"和"关键点"**塞进同一个模型、同一次推理**：既给你人的框，又给你这个人的 17 个关节点。

回忆第 16 章：普通 YOLOv8 检测器输出 `[1, 84, 8400]`，其中 `84 = 4（框）+ 80（COCO 类别分数）`，`8400` 是候选个数。YOLOv8-pose 的输出是 **`[1, 56, 8400]`**，区别只在中间那个数从 84 变成 **56**：

```text
       [ 1 ,  56 ,  8400 ]
         │     │      └── 8400 个候选（和检测一样，多尺度网格铺出来的）
         │     └───────── 每个候选 56 个数：见下面拆解
         └─────────────── batch = 1（一次一张图 / 一帧）

  56 = 4  +  1  +  17×3
       │     │      └── 17 个关键点，每个点 3 个数：(x, y, 该点可见性/置信度)
       │     └───────── 1 个"人"的置信度（pose 只有 person 这一个类，所以不是 80）
       └─────────────── 4 个框坐标：中心点 cx, cy + 宽 w + 高 h
```

三段拆得很清楚：**前 4 个**是框（中心-宽高格式，和第 16 章一致）、**第 5 个**是这个人的置信度（姿态只关心"人"，所以只有 1 个类别分，不像检测有 80 个）、**后 51 个**是 17 个关键点，每点 3 个数——`(x, y, 可见性)`。

要特别记住两件和第 16 章完全同款的事：

1. **张量是"属性在前、候选在后"**：读第 `i` 个候选的第 `c` 个属性，要取 `output[[0, c, i]]`（在 8400 这一维上跨步走），不是一行行读。这个"转置"的访问方式第 16 章讲过。
2. **框和关键点的 x/y，都在 640 letterbox 坐标系里**：也就是第 10 章那张 640×640 灰边画布上的像素坐标。要还原回原图，用的是**同一套** `减 pad、除 scale` 公式（17.7 节）。可见性那一维是 0~1 的分数，不用做坐标还原。

候选还没去重——多个候选可能框住同一个人。**去重靠 NMS**（非极大值抑制），做法和第 16 章检测的 NMS 一模一样（按框 IoU 抑制，抑制时把整条 56 个数一起丢弃或保留）。本章不重复 NMS，只聚焦"关键点这部分怎么解出来、怎么还原、怎么画"。

## 17.6 统一数据类型：Keypoint 与 Pose

按全书惯例（写作规范第 6 节），一个新概念先定好统一的数据结构，全书复用。关键点这里新增两个类型，并**直接复用第 3 / 16 章的 `BBox`**，不另起炉灶：

```rust
/// 边界框：左上-右下像素坐标（全书统一类型，见第 3、16 章，此处直接复用）
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct BBox {
    pub x1: f32,
    pub y1: f32,
    pub x2: f32,
    pub y2: f32,
}

/// 单个关键点：原图像素坐标 + 该点的可见性/置信度
#[derive(Clone, Copy, Debug)]
pub struct Keypoint {
    pub x: f32,      // 原图像素 x（已还原，不是 640 画布坐标）
    pub y: f32,      // 原图像素 y
    pub score: f32,  // 该点的可见性/置信度 0~1，低于阈值视为被遮挡/不可信
}

/// 一个姿态目标：一组关键点 + 这个人的检测框
#[derive(Clone, Debug)]
pub struct Pose {
    pub keypoints: Vec<Keypoint>, // 顺序固定！索引含义见 17.2 的 COCO 17 点表
    pub bbox: BBox,               // 这个人的框（复用统一 BBox）
    pub score: f32,               // 整个人的置信度（YOLOv8-pose 输出的第 5 个数）
}
```

设计要点：

- `Keypoint.score` 是**每个点各自**的置信度，`Pose.score` 是**整个人**的置信度，两者不是一回事。画图时用前者决定"这个点画不画"，用后者决定"这个人要不要"。
- `keypoints` 是 `Vec`，长度对 COCO 姿态就是 17，**顺序必须严格按 17.2 的索引表**——`keypoints[5]` 永远是左肩。顺序错了，后面画骨架会连成鬼画符（17.10 节）。
- `bbox` 直接是统一的 `BBox`，这样第 21 章跟踪、第 26 章实战里，姿态目标能和普通检测目标共用一套下游逻辑。

## 17.7 坐标还原到原图 + 可见性过滤

模型吐出来的坐标，都在 640×640 那张 letterbox 画布里。要画到原图上、要算真实世界的动作，必须先**还原回原图像素坐标**。这一步和第 16 章还原检测框**用的是同一把钥匙**——第 10 章预处理时存下来的 `LetterboxInfo`：

```rust
/// 第 10 章预处理留下的"回执"：怎么缩放、怎么填边，还原坐标全靠它
#[derive(Clone, Copy, Debug)]
pub struct LetterboxInfo {
    pub scale: f32,   // 原图 → 640 画布的等比缩放系数
    pub pad_x: f32,   // 左侧灰边宽度（640 坐标系）
    pub pad_y: f32,   // 顶部灰边高度
    pub orig_w: u32,  // 原图宽（还原后夹取边界用）
    pub orig_h: u32,  // 原图高
}
```

还原公式就是第 10 章那条镜像逆运算（先减 pad、再除 scale）：

$$
x_{\text{原图}} = \frac{x_{\text{模型}} - \text{pad\_x}}{\text{scale}}, \qquad y_{\text{原图}} = \frac{y_{\text{模型}} - \text{pad\_y}}{\text{scale}}
$$

关键点和框坐标都套这条公式。把 17.5 拆好的 `[1,56,8400]` 结构、加上还原，写成一个"解码一个候选"的函数——它几乎就是第 16 章检测解码的"加长版"，只是多解了后面 51 个关键点数：

```rust
use ndarray::ArrayView3;

/// 把一个关键点从 640 letterbox 坐标还原回原图（和框还原同一套公式）
fn restore_keypoint(kx: f32, ky: f32, score: f32, lb: &LetterboxInfo) -> Keypoint {
    Keypoint {
        x: (kx - lb.pad_x) / lb.scale,
        y: (ky - lb.pad_y) / lb.scale,
        score, // 可见性分数不做坐标变换，原样带走
    }
}

/// 解码 [1,56,8400] 里的第 i 个候选：分低于阈值就丢弃，否则解成一个 Pose。
/// （8400 个候选之间的去重 = NMS，做法同第 16 章，此处不展开）
fn decode_one_pose(
    out: ArrayView3<f32>, // 形状 [1, 56, 8400]
    i: usize,
    lb: &LetterboxInfo,
    conf_thresh: f32,
) -> Option<Pose> {
    let person_score = out[[0, 4, i]];        // 第 5 个数（索引 4）= 人的置信度
    if person_score < conf_thresh {
        return None;                           // 太低，直接丢
    }

    // 前 4 个：中心点 + 宽高（640 坐标系）→ 左上右下，再减 pad、除 scale 还原（同第 16 章）
    let (cx, cy) = (out[[0, 0, i]], out[[0, 1, i]]);
    let (w, h) = (out[[0, 2, i]], out[[0, 3, i]]);
    let bbox = BBox {
        x1: (cx - w / 2.0 - lb.pad_x) / lb.scale,
        y1: (cy - h / 2.0 - lb.pad_y) / lb.scale,
        x2: (cx + w / 2.0 - lb.pad_x) / lb.scale,
        y2: (cy + h / 2.0 - lb.pad_y) / lb.scale,
    };

    // 后 51 个：17 个关键点，每点 3 个数 (x, y, 可见性)
    let mut keypoints = Vec::with_capacity(17);
    for k in 0..17 {
        let base = 5 + k * 3;                  // 前 5 个是 box(4)+conf(1)，之后每点占 3 个槽
        let kx = out[[0, base, i]];
        let ky = out[[0, base + 1, i]];
        let ks = out[[0, base + 2, i]];        // 该点可见性/置信度
        keypoints.push(restore_keypoint(kx, ky, ks, lb));
    }

    Some(Pose { keypoints, bbox, score: person_score })
}
```

注意 `base = 5 + k * 3` 这个下标：前 5 个槽被"框 4 + 人置信度 1"占掉，从第 5 个（索引 5）起，每个关键点连续占 3 个槽。这类"按固定步长拆一长条数字"的活儿，写错一格就全偏，务必和输出定义（17.5）对齐着写。

### 可见性过滤：遮挡的点不要画

关键点有个和框很不一样的特性：**一个人身上，总有些点是看不见的**——背对镜头时脸上的点、被桌子挡住的腿。模型对这些点会给一个**很低的可见性分数**。工程上的规矩是：

> **每个关键点单独判断**：`keypoint.score` 低于阈值（常用 0.3~0.5）的点，视为被遮挡/不可信，**不画、也不参与下游计算**（比如别拿一个瞎猜的手腕去算胳膊角度）。

这就是为什么 `Keypoint` 要带 `score`：它不只是"有多准"，更是"这点到底可不可见"的开关。下一节画火柴人时，我们就靠它决定每个点、每条骨头画不画。

## 17.8 骨架连线：把点连成火柴人

17 个孤零零的点，人眼看着费劲。把它们按人体结构**连成线**，就成了一目了然的"火柴人"。连哪两个点，由一张预定义的**骨架（skeleton）**表决定——它就是一组"该连线的点对"。

用点的索引（0~16，见 17.2）把骨架边列出来。下面是一套常用的 COCO 骨架连线（0 基索引的点对）：

```rust
/// COCO 17 点的骨架边：每个元组是"该连线的两个关键点索引"（0 基）
const SKELETON: &[(usize, usize)] = &[
    // 两条腿 + 髋部横杆
    (15, 13), (13, 11), (16, 14), (14, 12), (11, 12),
    // 躯干：肩到髋、两肩相连
    (5, 11), (6, 12), (5, 6),
    // 两条胳膊：肩-肘-腕
    (5, 7), (7, 9), (6, 8), (8, 10),
    // 头部：鼻-眼、眼-耳
    (0, 1), (0, 2), (1, 3), (2, 4),
];
```

举个例子，`(5, 7)` 表示"把左肩（5）和左肘（7）连起来"，`(7, 9)` 再把左肘（7）连到左手腕（9）——一整条左臂就画出来了。

画图用第 3 章介绍过的 `imageproc`：画点用 `draw_filled_circle_mut`，画线用 `draw_line_segment_mut`。先加依赖：

```bash
cargo add image imageproc ndarray
```

然后写一个"在原图上画一个人"的函数——**先连线、后画点**（点盖在线头上更好看），每条边、每个点都过一遍可见性阈值：

```rust
use image::{Rgb, RgbImage};
use imageproc::drawing::{draw_filled_circle_mut, draw_line_segment_mut};

/// 在原图上画出一个人的骨架和关键点（火柴人）。
/// kpt_thresh：关键点可见性阈值，低于它的点/边不画（见 17.7）。
fn draw_pose(img: &mut RgbImage, pose: &Pose, kpt_thresh: f32) {
    let bone_color = Rgb([0u8, 255, 0]);   // 骨架线：绿
    let point_color = Rgb([255u8, 0, 0]);  // 关键点：红

    // ① 先画骨架线：一条边的两个端点都够可信，才连线
    for &(a, b) in SKELETON {
        let pa = pose.keypoints[a];        // 端点 a、b 的坐标（已是原图像素）
        let pb = pose.keypoints[b];
        if pa.score < kpt_thresh || pb.score < kpt_thresh {
            continue;                       // 有一端被遮挡/不可信，这根"骨头"就不画
        }
        draw_line_segment_mut(img, (pa.x, pa.y), (pb.x, pb.y), bone_color);
    }

    // ② 再画关键点：低于阈值的点视为不可见，不画
    for kp in &pose.keypoints {
        if kp.score < kpt_thresh {
            continue;
        }
        // draw_filled_circle_mut 要 i32 圆心；半径 3px 的实心小圆当"关节"
        draw_filled_circle_mut(img, (kp.x.round() as i32, kp.y.round() as i32), 3, point_color);
    }
}
```

用起来就是把整条流水线串起来——预处理（第 10 章）→ 推理（第 14 章）→ 解码 + NMS（本章 `decode_one_pose` + 第 16 章）→ 画：

```rust
let mut img = image::open("gym.jpg")?.to_rgb8();
// let (input, lb) = preprocess(&img, 640);   // 第 10 章，拿到张量 + LetterboxInfo
// let out = model.run(input)?;                // 第 14 章，得到 [1,56,8400]
// let poses: Vec<Pose> = decode_and_nms(out.view(), &lb, 0.5); // 本章解码 + 第 16 章 NMS
for pose in &poses {
    draw_pose(&mut img, pose, 0.5);            // 关键点可见性阈值 0.5
}
img.save("pose_out.png")?;
```

> 如果还想把每个人的**框**也画出来，直接用第 3 / 16 章画 `BBox` 的老办法（`imageproc::draw_hollow_rect_mut`）画 `pose.bbox` 即可——姿态目标的框就是统一的 `BBox`，工具链完全通用。给不同的人配不同颜色，视频里就能一眼分清谁是谁（真正的"谁是谁"跨帧稳定 ID，要靠第 21 章的跟踪）。

## 17.9 人脸关键点：为第 20 章的对齐铺垫

人脸关键点的**头号用途是对齐（alignment）**。这里先讲清"为什么要对齐、5 个点怎么帮上忙"，具体怎么做留给第 20 章。

问题背景：人脸识别模型（第 20 章）想比对两张脸是不是同一个人，可现实里的脸**东倒西歪**——有的仰头、有的侧脸、有的歪着。同一个人歪着拍和正着拍，像素差异很大，直接比会误判。

**对齐**就是：先用人脸关键点当"锚点"，把这张歪脸通过一次**几何变换（仿射/相似变换，第 9 章）**摆正、缩放到一个**标准脸模板**上（比如固定的 112×112，两只眼睛落在约定好的位置）。摆正之后，所有脸的姿态、大小都统一了，识别模型才好比对。

而 **5 个点（双眼、鼻尖、双嘴角）就是干这个的最小够用集**：

```text
     歪着的原始人脸                 对齐到标准模板（112×112）
   ┌──────────────┐                ┌──────────────┐
   │   ●左眼        │   5 点做锚点    │   ●      ●   │  两眼固定落在
   │       ●右眼    │  ─────────►    │  左眼    右眼  │  约定的标准位置
   │     ● 鼻        │   仿射变换      │      ●        │
   │   ●   ● 嘴角    │                │   ●      ●    │
   └──────────────┘                └──────────────┘
```

流程串起来就是：**人脸检测（框）→ 5 点关键点 → 用 5 点估计仿射变换 → warp 到标准脸 → 送识别模型提特征**。这里你只需记住一件事：**人脸 5 点关键点，是"检测"和"识别"之间的对齐桥梁**。它多半用直接回归法（17.3）产出——脸区域小、结构规整，回归又快又够准。至于仿射矩阵怎么解、标准脸模板长什么样、特征怎么比对，全在第 20 章。

## 17.10 工程坑：顺序、左右、翻转、遮挡

关键点的坑，几乎都不在"算法"，而在"约定对没对上"。逐条列清：

- **关键点顺序/索引含义绝不能错。** 模型输出第 `k` 个点是什么部位，是**数据集约定死的**（COCO 是 17.2 那张表）。不同数据集顺序不同（COCO 和 MPII 就不一样），换一个模型务必**重新核对它的索引表**。顺序错了，火柴人会把"手腕连到脖子"，连成鬼画符——而且**不报错**，只出乱图。

- **left/right 是"被拍者"的左右，不是画面的左右。** COCO 里 `left_shoulder`（索引 5）是那个人自己的左肩；他正对镜头时，出现在**你视野的右侧**。算"举的是左手还是右手"这类业务时，先想清楚参照系，别镜像搞反。

- **翻转增强会把左右点对互换。** 训练或测试时常做水平翻转来增强/提分（TTA，测试时增强）。图一翻，左肩就跑到了右边——所以**翻转后必须把成对的关键点索引也交换**：left_shoulder↔right_shoulder、left_eye↔right_eye…… 忘了交换，骨架会诡异地交叉扭曲。这是关键点特有、检测框不会遇到的经典坑（框翻转只改 x 坐标，没有"左右语义"要换）。

- **遮挡点要老实处理。** 看不见的点，模型给的是**低分 + 瞎猜的坐标**。规矩（17.7）：低于阈值的点不画、不连线、不参与算角度/距离。真实标注里可见性还分三态（没标注 / 标注了但不可见 / 可见），但推理侧统一看 `score` 阈值判断即可。

- **还原后记得夹取边界。** 关键点还原回原图后，可能**落在图像外**（人被画面裁掉一半时尤其常见，模型仍会外推一个坐标）。画之前把坐标 clamp 进 `[0, w-1] × [0, h-1]`，否则 `put_pixel` 越界 panic——和第 3 章 `draw_bbox` 里的夹取是同一个道理。

- **别忘了坐标系一致性。** 框和关键点必须用**同一份 `LetterboxInfo`** 还原（17.7）。一旦框用了原图坐标、关键点忘了还原（还停在 640 画布），画出来就是"人在左边、骨架飘到右上角"的错位——查起来很费神，源头往往就是漏了一次 `restore`。

## 17.11 小结

- **关键点模型输出"点"不是"框"**：在目标上精确定位一组有语义的坐标（人体 17 关节、人脸 5/68/106 点）。检测回答"在哪"，关键点回答"什么姿势/什么结构"。
- **点的顺序和索引含义是约定死的**：COCO 人体 17 点（0=鼻、5=左肩、9=左腕……）要背熟；left/right 指被拍者自己的左右。
- **两大流派**：热力图法为每个点输出一张概率图、用 **argmax 取峰值**再缩放回原图，精度高但慢；直接回归法直接吐 `(x,y)`，快，人脸对齐和 YOLOv8-pose 都用它。
- **YOLOv8-pose 把检测 + 关键点合一**，输出 `[1,56,8400]`，`56 = 4(框) + 1(人置信度) + 17×3(x,y,可见性)`；张量"属性在前、候选在后"，去重靠 NMS（同第 16 章）。
- **坐标还原和框同一套**：减 `pad`、除 `scale`（复用第 10 章 `LetterboxInfo`）；**每个点单独按 `score` 阈值过滤**，遮挡点不画、不算。
- **骨架（skeleton）是一组预定义点对**，按它连线画火柴人（`imageproc` 的 `draw_line_segment_mut` + `draw_filled_circle_mut`）。
- **人脸 5 点主要用于对齐**：把歪脸仿射变换到标准脸，为第 20 章的人脸识别铺路。
- **头号坑**：索引顺序错、左右搞反、翻转增强忘了交换左右点、遮挡点乱用、忘了还原坐标——大多不报错，只出乱图。
