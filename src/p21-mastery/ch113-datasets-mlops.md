# 第 113 章 数据与 MLOps：从血缘到线上质量闭环

> **本章导读**
> - 学完你能：把"数据集"当成一份**不可变的清单（manifest）**来管理，用**纯 Rust（serde）**解析 COCO 风格标注、统计类别分布、检测不平衡，并做一次**杜绝泄漏**的 train/val 划分。

> - 诚实盘点纯 Rust 在 MLOps 里的**能力边界**：能做什么（高性能数据流水线、预处理、serving），不能取代什么（MLflow/DVC 那套 Python 工具链）。
> - 本章动手部分**在本机 `cargo run` 实测通过**，所有统计与划分数字都是真实输出。

## 场景：验证集 99%，上线就翻车

想象你训练了一个检测模型，验证集准确率漂亮得不行——99%。信心满满推上线，结果第二天现场反馈：一堆漏检、误报。你百思不得其解：模型明明"很准"啊？

这种"离线很香、上线拉胯"的故事，在真实项目里天天上演。而**十有八九，锅不在模型，在数据和流程**：

- 验证集里混进了训练集的**近重复样本**（同一段视频的相邻帧被随机拆到了两边），于是验证分数是**虚高**的；
- 数据**类别严重不平衡**，模型只要无脑猜多数类就能拿高 accuracy，一到现场遇到少数类就抓瞎；
- 标注的**坐标约定**和推理端对不上（一边 `xywh`、一边 `xyxy`），框全偏了；
- 上线后现场光照、设备变了（**分布漂移**），而你根本没在监控。

[第 1 章](../p01-start/ch01-what-is-cv.md) 那张流水线图里，"模型"只是中间一格。这一章讲的，正是模型之外那些**决定项目生死**的工程素养——它是全书收官的一课。

## 原理：把数据当"一等公民"

### 数据集不是一个文件夹，是一份不可变清单

新手眼里，数据集就是 `images/` 加 `labels/` 两个文件夹。专家眼里，数据集是一份**不可变的清单（manifest）**：每个样本都登记它的 **id、内容哈希、来源、采集时间、许可、主体/设备、标签版本、所属划分、质量状态**。大文件（图片本身）存进对象存储，Git 里只放 schema、清单和代码。

为什么要这么较真？因为 [附录 G](../appendix/g-expert-standard.md) 的铁律是**可复现**：半年后有人质疑某个结论，你得能精确重建出"当时那一版数据"。文件名叫 `dataset_final_v2_really_final/` 是管不住版本的。

### 主流标注格式：三种组织方式，一个大坑

同一批框，不同框架有不同的存法。你迟早都会遇到，先混个脸熟：

| 格式 | 载体 | 框坐标约定 | 特点 |
|------|------|-----------|------|
| **COCO** | 一个大 `.json` | `bbox = [x, y, w, h]`（左上角 + 宽高，绝对像素） | 检测/分割主流；`images`/`annotations`/`categories` 三张表用 id 关联 |
| **YOLO** | 每图一个 `.txt` | `class cx cy w h`（中心点 + 宽高，**归一化到 0~1**） | 简单直接，训练器友好；类别只有序号，名字另存 |
| **VOC** | 每图一个 `.xml` | `xmin ymin xmax ymax`（**xyxy**，绝对像素） | 老牌，人可读，冗长 |

> 🕳️ **坑**：**坐标约定不一致，是数据流水线第一大坑。** COCO 是 `xywh`、VOC 是 `xyxy`、YOLO 是归一化的中心点格式。转换时错一步，框就全偏了。[第十八部分的事件模型](../p18-events/ch83-filtering-basics.md) 里统一用左上角 `xywh`，喂给 IoU 计算（[第 45 章](../p09-detection/ch45-detection-principles.md)）前**务必先对齐约定**。本章代码会显式演示一次 `xywh → xyxy`。

### 数据质量的三害

- **类别不平衡（class imbalance）**：某些类的样本数远多于其他类。模型会偏向多数类，此时**只看 accuracy 会被多数类主导**——必须报混淆矩阵、macro-F1、每类召回（这正是 [第 40 章](../p07-dl-basics/ch40-burn-train.md) 专家节反复强调的）。
- **标注噪声（label noise）**：漏标、错标、框歪了。少量噪声可容忍，系统性错误（比如某个标注员总把"卡车"标成"汽车"）会毒害模型。
- **近重复泄漏（near-duplicate leakage）**：几乎相同的样本（同一视频的相邻帧、同一物体的连拍）如果被随机拆到 train 和 val，验证分数就是自欺欺人。

### 划分纪律：按"组"划分，而不是按"样本"

这是最反直觉、也最关键的一条：**train/val/test 要按主体、视频、设备或时间分组来划分，而不是把样本打乱了随机分**。

一个视频里连续 100 帧几乎一模一样。如果你按帧随机划分，第 50 帧进了训练、第 51 帧进了验证——模型在训练里"背下"了第 50 帧，验证时看到几乎相同的第 51 帧当然答得出来。这不是泛化，是**泄漏**。正确做法：**整段视频（或整个主体、整台设备）要么全进训练、要么全进验证**，绝不跨集。

### MLOps 全环节与纯 Rust 的诚实定位

一套成熟的 MLOps 闭环包括：**数据版本化 → 实验跟踪 → 模型注册（带校验和）→ 上线 → 漂移监控 → 回滚/再训练**。每次训练都要记录代码提交、环境、数据版本、配置、种子、指标、模型哈希和父模型（[附录 G](../appendix/g-expert-standard.md) 的"统一实验记录"）。

> ⚠️ **注意（诚实盘点）**：**成熟的 MLOps 工具链，主力在 Python 生态**——实验跟踪有 MLflow/W&B，数据版本化有 DVC，编排有 Airflow/Prefect。**纯 Rust 目前没有对标它们的成熟替代品，别硬造。** Rust 在 MLOps 里的真实定位是**高性能的数据流水线、预处理和 serving**：用 Rust 写吞吐高、内存稳、可静态部署的**数据清洗/特征提取/推理服务**（呼应 [第 96 章](../p19-deploy/ch96-web-service.md) 的 axum 服务化、[第 107 章](../p20-projects/ch107-deploy-service.md) 的端到端部署），把它接进以 Python 为中枢的 MLOps 体系里，各司其职。这才是务实、诚实的用法。

## 动手：解析 COCO 标注，统计并防泄漏划分

理论说够了，上代码。我们用 `serde` + `serde_json`（都是**纯 Rust**）解析一段合成的 COCO 风格标注，完成四件事：**① 统计类别分布、检测不平衡；② 演示 `xywh → xyxy`；③ 按 `image_id` 分组做 train/val 划分；④ 反面对照"按标注随机划分"如何泄漏。**

> 💡 **提示**：`serde` 是 Rust 生态的序列化基石，`serde_json` 是它的 JSON 实现，二者均为纯 Rust。已加入主工程 `code/Cargo.toml`：`serde = { version = "1.0.229", features = ["derive"] }`、`serde_json = "1.0.151"`。运行：`cargo run --example ch113_datasets_mlops`。

### 第一步：用 serde 把 JSON 映射成结构体

`serde` 的精髓是**声明式**：你把 JSON 的结构写成 Rust struct、标上 `#[derive(Deserialize)]`，解析就自动完成，字段对不上会报错。

```rust
use serde::Deserialize;

#[derive(Debug, Deserialize)]
struct Coco {
    images: Vec<CocoImage>,
    annotations: Vec<CocoAnn>,
    categories: Vec<CocoCat>,
}
#[derive(Debug, Deserialize)]
struct CocoAnn {
    image_id: u64,        // 这条标注属于哪张图 —— 分组划分的关键
    category_id: u64,
    bbox: [f64; 4],       // COCO 约定：[x, y, w, h]
    // ……id 等字段略
}
// CocoImage { id, file_name, width, height }、CocoCat { id, name } 同理

let ds: Coco = serde_json::from_str(coco_json)?;   // 一行解析
```

### 第二步到第四步：统计、划分、对照

核心逻辑（完整版见 `code/examples/ch113_datasets_mlops.rs`）：

```rust
// ② 类别分布：遍历标注，按 category 计数
let mut per_cat: BTreeMap<&str, usize> = BTreeMap::new();
for a in &ds.annotations { *per_cat.entry(id2name[&a.category_id]).or_insert(0) += 1; }
let (max, min) = (/* 最多类计数 */, /* 最少类计数 */);
// max/min >= 10 就告警：严重不平衡，别只看 accuracy

// ③ 按 image_id 分组划分：划分单位是"图片"，不是"标注框"
let mut img_ids: Vec<u64> = ds.images.iter().map(|i| i.id).collect();
Lcg::new(42).shuffle(&mut img_ids);                    // 固定种子 → 可复现
let n_val = (img_ids.len() as f64 * 0.35).round() as usize;
let val_set: HashSet<u64> = img_ids[..n_val].iter().copied().collect();
// 一张图的所有标注，跟着这张图整体进 train 或 val —— 天然无泄漏

// ④ 反面对照：把"单个标注"随机分到两边，统计有多少图被拆到了两集（泄漏）
```

这里的 `Lcg` 是本书一贯用的固定种子极简随机数发生器（[第 40 章](../p07-dl-basics/ch40-burn-train.md) 同款），保证**划分完全可复现**——这本身就是 [附录 G](../appendix/g-expert-standard.md) 的要求。

### 跑起来：真实输出

```text
解析成功：8 张图，23 条标注，4 个类别

== 类别分布（按标注框计）==
  bicycle    3 ( 13.0%) ###
  car        7 ( 30.4%) #######
  dog        1 (  4.3%) #
  person    12 ( 52.2%) ############
  不平衡比 max/min = 12/1 = 12.0x
  ⚠️ 类别严重不平衡（≥10x）：只看 accuracy 会被多数类主导，须报 macro-F1/每类召回

== bbox 约定演示（COCO 用 xywh）==
  第一条标注 xywh = [34, 50, 40, 120]
  转成 xyxy       = [34, 50, 74, 170]（喂检测框/IoU 前务必对齐约定）

== 按 image_id 分组划分（val_ratio=0.35, seed=42）==
  train: 5 张图 / 15 标注   {"bicycle": 2, "car": 6, "dog": 1, "person": 6}
  val  : 3 张图 / 8 标注   {"bicycle": 1, "car": 1, "person": 6}
  val 图片清单：["street_01.jpg", "park_02.jpg", "alley_01.jpg"]
  ⚠️ 稀有类 dog 全落在 train、val 里一个都没有——随机分组对长尾类不友好，
     真实项目要做分组+分层（group-stratified）划分，保证每类在各集都有样本。
  同图跨集检查：0 张图跨集（应为 0 → 无泄漏）

== 反面对照：按单个标注随机划分 ==
  有标注同时落入 train 和 val 的图片：5 张 → [100, 102, 104, 105, 106]
  这些图既在训练里"见过"、又在验证里被考——验证分数虚高，就是数据泄漏。
```

这份输出，把本章的道理全落到了实处：

- **类别不平衡是真的**：`person` 有 12 个框、`dog` 只有 1 个，不平衡比 `12x`，程序自动告警。这时候若只看 accuracy，模型无脑多报 `person` 都能骗到高分——[第 40 章](../p07-dl-basics/ch40-burn-train.md) 说的"必须报 macro-F1、每类召回"就是为了戳穿这种假象。
- **分组划分真的无泄漏**：按 `image_id` 分组后，"同图跨集检查"是 `0`——没有任何一张图的框被拆到两边。
- **反面教材触目惊心**：同样的数据，改成"按单个标注随机划分"，立刻有 **5 张图**的框同时落进了 train 和 val。这 5 张图模型在训练时"见过"、验证时又拿来考，分数当然虚高。**这就是泄漏，而且它悄无声息。**
- **长尾类是另一个坑**：随机分组还把唯一的 `dog` 全甩给了训练集，验证集一个都没有——真实项目要用**分组 + 分层（group-stratified）**划分，兼顾"同组不拆"和"每类都在"。

## 常见坑与提示

> 🕳️ **坑**：**按样本随机划分 = 数据泄漏。** 同视频/同主体/同连拍的近重复样本被拆到 train 和 val，验证分数虚高、上线打回原形。**按组划分**（视频/主体/设备/时间），本章代码已实测演示。

> 🕳️ **坑**：**坐标约定不对齐，框全偏。** `xywh`（COCO）、`xyxy`（VOC）、归一化中心点（YOLO）混用是重灾区。转换后**挑几个框可视化核对**，别闷头训练。

> ⚠️ **注意**：**类别不平衡别装看不见。** 重采样、加权损失、或至少在评估时报**混淆矩阵 + macro-F1+ 每类召回**（[第 40 章](../p07-dl-basics/ch40-burn-train.md)、[附录 G](../appendix/g-expert-standard.md)）。一个平均分能掩盖少数类的系统性失败——安全关键场景尤其致命。

> 🕳️ **坑**：**数据和模型不版本化 = 不可复现。** 只靠 `best_final_v2.pt` 这种文件名管版本，三个月后没人说得清它是用哪版数据、什么配置训出来的。给数据集做**清单 + 内容哈希**，给模型存**校验和 + 训练配置 + 数据划分**。

> ⚠️ **注意**：**离线指标好 ≠ 线上没事。** 现场光照、设备、季节会让输入**分布漂移**。标签往往延迟到达，此时可监控 embedding、亮度、目标尺寸、置信度分布和人工抽检队列。**漂移是调查信号，不等于性能一定下降**；再训练必须过离线门、影子、灰度，再决定是否替换——别一报警就自动覆盖生产模型。

## 专家补强：从血缘到线上质量闭环

> 本节呼应 [附录 G](../appendix/g-expert-standard.md)：数据能解析只是第一关，**血缘可追溯、退化可定位、发布有闸门**才算掌握。

一套可信的数据/模型闭环，至少要能做到：

- **血缘（lineage）可追溯**：从任意一条生产预测，能反查到它用的是哪个模型、哪份配置、哪次代码提交、哪批训练数据。断了任何一环，出了问题就无从复盘。
- **模型注册表**：记录每个模型的状态流转（开发→影子→灰度→生产）与审批记录，而不是拿文件名管版本。
- **数据卡 / 模型卡**：数据卡说明采集方式、代表性、许可、敏感属性和**已知空白**；模型卡说明用途、**禁用场景**、分切片指标、阈值和资源要求。
- **发布闸门**：新模型要过离线门、影子（shadow，只看不生效）、灰度（canary，小流量），并保留一键**回滚**。**总体指标提升、但关键切片（某人群/某工况）退化超过阈值，必须阻止发布**——这是 [附录 G](../appendix/g-expert-standard.md) 明确的红线。

一个值得动手的开放式考核：模拟"新设备接入导致漂移"，走完**采样 → 标注 → 候选训练 → 离线对比 → 影子 → 灰度 → 回滚**全流程，提交配对指标、切片退化表、监控图和复盘。这比"又刷高了 0.5% mAP"有价值得多。

## 本章小结

- **数据集是一份不可变清单**（id、哈希、来源、标签版本、划分、质量），不是一个文件夹；可复现是底线（[附录 G](../appendix/g-expert-standard.md)）。
- 标注三大格式 **COCO(`xywh`) / YOLO(归一化中心点) / VOC(`xyxy`)**，坐标约定不一是头号坑；数据三害是**不平衡、标注噪声、近重复泄漏**。
- **划分要按组（视频/主体/设备/时间），不能按样本随机分**——本章用 serde 解析 COCO、按 `image_id` 分组划分（同图跨集 = 0），并实测演示了按标注随机划分会让 **5 张图泄漏**。
- **纯 Rust 在 MLOps 的诚实定位**：做高性能数据流水线、预处理与 serving（[第 96 章](../p19-deploy/ch96-web-service.md)/[第 107 章](../p20-projects/ch107-deploy-service.md)），**不取代** MLflow/DVC 那套 Python 工具链。
- 上线不是终点：**监控漂移、有闸门、能回滚、可追溯血缘**，才是闭环。

## 动手练习

1. **跑通并改数据**：运行 `cargo run --example ch113_datasets_mlops`，然后往 JSON 里多加几张图和标注，观察类别分布、不平衡比和划分结果怎么变。
2. **改进划分**：当前随机分组把稀有类 `dog` 全甩给了训练集。实现一个**分组 + 分层**划分：在"同图不跨集"的前提下，尽量让每个类别在 train/val 都出现。
3. **换格式**：把示例改成解析 **YOLO** 格式（每图一个 `.txt`，`class cx cy w h` 归一化）。注意坐标要从归一化中心点转回绝对 `xyxy`，并和 COCO 版本对拍同一批框。
4. **进阶——做张数据卡**：为这份合成数据集写一份数据卡（Markdown 即可）：类别、样本数、划分策略、已知不平衡与空白（如 val 无 `dog`）、许可与适用范围。这正是 [附录 G](../appendix/g-expert-standard.md) 毕业项目要求的提交物之一。
