# 第 101 章 项目：人脸考勤 / 门禁 Demo

> **本章导读**
> - 这是一个**集成落地项目**：把 [第 56 章](../p12-face/ch56-face-detection.md) 的人脸检测、[第 54 章](../p11-keypoints/ch54-face-landmarks.md) 的五点对齐、[第 57 章](../p12-face/ch57-face-recognition.md) 的 ArcFace 识别、[第 58 章](../p12-face/ch58-liveness-attributes.md) 的活体检测，**串成一条端到端的考勤/门禁流水线**。
> - 重点不是重推理论（理论在前四章），而是**工程决策**：流水线顺序、注册库(gallery)管理、识别阈值怎么定、**误放行 vs 误拒的代价不对称**、以及集成时最容易踩的**级联域偏移**坑。
> - 全流程自包含、纯 CPU、`cargo run --release` 真跑真数字：注册数、检测质量、员工放行率、陌生人拒绝率、假体拦截率、逐帧决策示例。
> - 诚实边界：真门禁需要更鲁棒的活体（深度/红外）、大规模注册库、姿态/质量处理与现场阈值标定，以及严格的隐私合规。

## 场景：一道会"看脸"的门

公司大门口装了个摄像头。员工走近，门自动开；快递小哥（陌生人）走近，门不开、提示"请登记"；有人举着员工的照片或用手机播放员工的视频想蒙混进来，门也得识破、拒绝。

这道门要同时回答三个问题：**这是不是一张活人的脸？（活体）** **脸在哪、朝向如何？（检测+对齐）** **是不是登记过的员工、是哪位？（识别）** 单独看，这四件事我们前面都做过了；难的是**把它们拼成一条可靠的流水线**，并在每一帧上做出**一个明确的门禁决策**。这一章就干这件事。

## 系统设计：五级流水线

```text
摄像头帧
  │ ① 人脸检测 (ch56)：找到脸的框 + 5 个关键点
  ▼
  │ ② 五点对齐 (ch54)：用关键点把脸摆正、缩放到 32×32 标准脸
  ▼
  │ ③ 活体闸门 (ch58)：真人？假体(打印/翻拍)？——假体在此直接拒，不再往下走
  ▼
  │ ④ 识别比对 (ch57)：ArcFace embedding 与注册库逐一算余弦相似度，取最相似者
  ▼
  │ ⑤ 决策：最相似度 ≥ 阈值 → 放行·记考勤；否则 → 陌生人拒绝
  ▼
门开 / 门不开
```

**为什么活体在识别之前？** 两个理由：一是**安全**——假体（照片/屏幕）即使"长得像"员工，也绝不能放行，先拦住假的再谈是谁；二是**省算力**——假体在闸门就被丢弃，不必再跑识别。这呼应 [第 58 章](../p12-face/ch58-liveness-attributes.md)：活体是安全前置关卡。

**注册-比对（1:N 辨识）。** 门禁不知道你要"声称"是谁，必须在 \\( N \\) 名员工的**注册库（gallery）** 里找出最像的那个——这是 **1:N identification**。注册时给每位员工拍几张登记照，取其 embedding 的**平均**作为模板（比单张稳）；比对时算查询脸与每个模板的**余弦相似度**，最高的那个若**超过阈值**就判为该员工，否则判"陌生人"。加新员工只需往 gallery 里加一条模板，**无需重训任何模型**——这正是 [第 57 章](../p12-face/ch57-face-recognition.md) 用 embedding 而非"每人一类"分类的根本好处。

## 动手：把四章拼成一条流水线（candle）

> ⚠️ **注意**：本章基于 **candle 0.11.0**，纯 CPU。独立工程见 `code/projects/ch101_face_attendance/`（自带含空 `[workspace]` 的 Cargo.toml），`cargo run --release` 即可复现。工程里内联训练了三个紧凑模型（检测器、ArcFace embedding、活体分类器），全部用合成人脸——把"检测→对齐→活体→识别→决策"完整跑通。

一帧的决策逻辑就是把五级串起来（核心片段）：

```rust
// ① 检测：没检出人脸 → 直接不放行（对陌生人/假体是安全的，对员工是漏检）
let det = match detect_best(&detector, &frame, &dev, 0.5)? { Some(d) => d, None => { /* 拒绝 */ } };
let crop = align_crop(&frame, &det.lmk);        // ② 五点对齐 → 32×32 标准脸
if !is_live(&livenet, &crop, &dev)? { /* ③ 活体拦截：拒绝 */ }
let emb = &embed(&embnet, &[crop], &dev)?[0];   // ④ ArcFace embedding
let (best_k, best_s) = nearest_in_gallery(emb, &gallery); // 1:N 最近邻
if best_s >= thr { pass_as(best_k) } else { reject_as_stranger() } // ⑤ 决策
```

**五点对齐**用全部 5 个关键点做一次**相似变换**（scale+旋转+平移），把检测到的关键点最小二乘对齐到一组标准位置——比只用双眼瞳距稳得多（原因见下方的"坑"）：

```rust
// 求相似变换 dst = M(src-ms)+md：a=Σ点积, bb=Σ叉积, ss=Σ|src'|² → p=a/ss(=scale·cosθ), q=bb/ss
// 逆映射(输出像素→原图)采样即得对齐后的标准脸。用 5 个点平均掉单点噪声。
```

### 真实运行结果

三个模型训完后，先给检测阶段体检，再注册 8 名员工、在验证集上定阈值，最后处理 60 帧"摄像头流"。真实输出（节选）：

```text
[检测体检] 37/40 帧成功定位人脸，命中框平均 IoU=0.824，关键点平均误差=1.33px
[注册] 已登记 8 名员工（每人 5 张登记照取平均模板）；另有 4 个陌生人身份未登记
[定阈值] 验证集 genuine 均值=0.807、impostor(1:N最大) 均值=0.474
         选识别阈值 0.64：验证集员工通过率 91%、陌生人拒绝率 94%

[实时决策] 处理 60 帧：30 员工真人、15 陌生人、15 假体(打印/翻拍)
  ✓ 真况=员工#2真人      活体=真 → 决策：放行·员工#2(sim=0.88)
  ✗ 真况=员工#1真人      活体=真 → 决策：陌生人(拒绝, best_sim=0.49)   ← 误拒(本人相似度偏低)
  ✓ 真况=员工#0真人      活体=真 → 决策：放行·员工#0(sim=0.74)

===== 汇总（真实数字，共 60 帧每帧一个门禁决策）=====
员工真人  正确放行且认对本人：25/30（83.3%）
陌生人    正确拒止(判陌生人/未检出)：15/15（100.0%）
假体攻击  正确拒止：15/15（100.0%）— 其中活体拦截 11、检测阶段挡掉 4
安全事故（假体骗过活体又被认成员工而放行）：0 起
```

**读懂这组数字**：安全相关的指标全部满分——**陌生人 100% 拒止、假体 100% 拒止、0 起安全事故**（没有任何假体被放行）；便利性指标**员工放行 83.3%**，即约六分之一的员工被误拒、需要再刷一次。这个"安全满分、便利打折"的取舍**不是 bug，而是我们主动选的**（下面细说）。注意 embedding 是在**另外 16 个身份**上训练的，门禁里这 12 个人（8 员工 + 4 陌生人）**它从没见过**——这正是人脸识别"开集"的真实用法。

### 集成项目最大的坑：级联域偏移

这条流水线我第一次跑通时，**员工放行率是 0/29**——一个都认不出！排查发现：我用**真值关键点**裁剪人脸来训练识别模型，推理时却用**检测器预测的关键点**裁剪。两者差一点点，裁出来的脸就有系统性偏移，embedding 全对不上，本人相似度从验证时的 0.84 崩到 0.3。

> 🕳️ **坑（集成项目头号杀手：级联域偏移）**：**每一级模型，必须在它上游那一级的\*真实输出\*上训练，而不是在"理想输入"上训练。** 检测→对齐→识别是一条级联，识别模型吃的是"检测器给的关键点对齐出来的脸"，就必须拿这种脸去训练它。修法：把训练、注册、验证、推理的裁剪**全部走同一条 `检测→对齐` 链**。只此一改，员工放行率从 **0% 升到 40.7%**。

第二个坑是**对齐对关键点噪声太敏感**：最初我按"双眼瞳距"定裁剪尺度，可瞳距才 ~7px，检测器 1.3px 的关键点误差就被放大成 ~25% 的尺度抖动，脸忽大忽小，识别自然差。换成 [第 54 章](../p11-keypoints/ch54-face-landmarks.md) 的**五点相似变换对齐**（用全部 5 个点最小二乘，平均掉单点噪声）后，员工放行率再从 **40.7% 升到 83.3%**。两个坑串起来的教训是：**集成系统里，上游的小误差会被下游放大，必须端到端地对齐训练分布、并选鲁棒的中间表示。**

## 常见坑与提示

> ⚠️ **注意（阈值：误放行 vs 误拒，代价不对称）**：门禁的两类错误代价天差地别——**把陌生人/假体误放行（安全事故）远比把员工误拒（多刷一次）严重**。所以阈值要往**安全侧**定：本章在验证集上选了让陌生人拒绝率 ≥94% 的阈值 0.64，代价是员工放行率降到 83%。这正是 [第 58 章](../p12-face/ch58-liveness-attributes.md) APCER/BPCER 取舍的落地——**先定"能容忍的误放行率"，再看误拒**，而不是反过来。

> 💡 **提示（gallery 管理）**：注册库是门禁的"人事表"，工程上要当一等公民管理：每人存**多张登记照的平均模板**（更抗光照/表情）；员工入职/离职只增删 gallery 条目、**不重训模型**；模板要版本化、可追溯、可吊销。1:N 里"取与最相似模板的相似度"这一步，人少时线性扫即可，人多（上万）就得上**向量检索/近似最近邻**（呼应 [第 28 章](../p04-features/ch28-bovw-retrieval.md) 的检索思想）。

> 🕳️ **坑（合成数据的确定性 RNG）**：本章造脸用自写的 LCG，**取离散随机（选身份/真假/属性）务必用高位**（`unit()` 的 `>>11` 派生 `boolean()`/`below(n)`），别用 `next()%k` 或 `next()&1`——LCG 低位周期极短会退化（这是第 58 章记下、全书通用的坑）。

> ⚠️ **注意（端到端评估，别只看单级）**：检测 IoU 0.82、识别验证准确率 91% 单看都不错，可**串起来的员工放行率只有 83%**——因为误差在级联里累积。上线前一定要**按最终业务决策**（放行/拒绝/拦截）端到端评估，而不是只体检各级指标。

> ⚠️ **注意（诚实边界）**：本章是**教学级 Demo**，合成脸干净、规模小。真实门禁还要啃这些硬骨头：**鲁棒活体**（单帧 RGB 不够，得上深度/红外/多帧动作，见 [第 58 章](../p12-face/ch58-liveness-attributes.md)）、**大规模 gallery**（向量检索 + 阈值随规模标定）、**姿态/遮挡/低质量**人脸的检测与拒识、**现场阈值标定**（换摄像头/光照就要重标）。更要紧的是**隐私与合规**：人脸是敏感生物特征，模板要加密存储、明确授权、可删除，遵守当地法规——技术能力越强，越要守住合规红线。

## 本章小结

- 人脸考勤/门禁是一条**五级集成流水线**：检测（[第 56 章](../p12-face/ch56-face-detection.md)）→ 五点对齐（[第 54 章](../p11-keypoints/ch54-face-landmarks.md)）→ 活体闸门（[第 58 章](../p12-face/ch58-liveness-attributes.md)）→ ArcFace 识别比对（[第 57 章](../p12-face/ch57-face-recognition.md)）→ 门禁决策。活体放在识别之前，既堵安全漏洞又省算力。
- **注册-比对是 1:N 辨识**：gallery 存每位员工的平均模板；比对取最相似模板的余弦相似度，过阈值放行、否则判陌生人；加人只改 gallery、不重训。
- 实测（embedding 在另外 16 个身份上训练、门禁世界的 12 人全未见过）：**员工正确放行 25/30（83.3%）、陌生人拒止 15/15、假体拒止 15/15、0 起安全事故**；阈值 0.64 是主动往安全侧定的结果。
- **集成头号坑是级联域偏移**：识别必须用"检测器真实输出对齐出来的脸"训练；再配 [第 54 章](../p11-keypoints/ch54-face-landmarks.md) 的五点相似变换对齐（抗关键点噪声）。这两步把员工放行率从 **0% → 40.7% → 83.3%**。
- **工程心法**：误放行 vs 误拒代价不对称，阈值按业务风险定；端到端按最终决策评估，别只看单级指标；人脸涉隐私，合规是红线。

## 动手练习

1. **调阈值看取舍**：把识别阈值从 0.64 调到 0.55 和 0.75，各跑一遍，观察"员工放行率"和"陌生人拒绝率"如何此消彼长——亲手体会 APCER/BPCER 曲线。
2. **复现级联域偏移**：把识别训练改回用真值关键点对齐（推理仍用检测关键点），看员工放行率怎么崩，再改回来——记住这个"不报错但全崩"的集成故障。
3. **加考勤逻辑**：给放行事件加上"同一员工 5 秒内只记一次"的去重（呼应第十八部分的 cooldown 去抖），把它变成真正的考勤打卡而非单帧判定。
4. **换对齐方式**：把五点相似变换换回"双眼瞳距裁剪"，对比员工放行率，验证鲁棒对齐的价值。
5. **想一想**：员工库扩到 5 万人，1:N 每帧比 5 万次太慢，你会怎么加速？（提示：向量检索/近似最近邻；以及先用其他线索缩小候选范围。）
