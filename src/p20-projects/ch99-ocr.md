# 第 99 章 项目：OCR 文字检测与识别

> **本章导读**
> - 这是一个**集成项目**：把**连通域分析**（[第 18 章](../p03-classic/ch18-contours.md)）和 **candle 小 CNN 分类**（[第 42 章](../p08-classification/ch42-candle-classify.md)）串成一条能跑的 **OCR 流水线**：图 → **连通域定位每个字符（检测）** → **逐字 CNN 分类（识别）** → 左到右拼成字符串。
> - **诚实边界（本章的核心卖点）**：纯 Rust 生态**没有**成熟的**通用 OCR 引擎**（Tesseract 是 C++/leptonica、PaddleOCR 是 Python/C++，都违反纯 Rust 约束）。真正能用纯 Rust 稳稳拿下的，是**受限字符集 OCR**——读**序列号 / 仪表读数 / 编码 / 车牌**这类**固定字形、干净背景**的短串。通用/手写/弯曲文字要 CTC、注意力序列模型 + 大模型，纯 Rust 生态很薄，务实路线是 ONNX + `tract`（下面会讲清）。
> - **头号教训（第 20 部分反复强调的『级联域偏移』）**：字符分类器**必须**在『和推理同一条分割管线产出的字形』上训练。本章同时训两个分类器对拍，真实数字：**NAIVE**（用干净居中字形训练）逐字 **69.6%** / 整串 **20.5%**，**PIPELINE**（用分割真实产出训练）逐字 **93.6%** / 整串 **85.0%**——一次把域偏移的杀伤力看清。
> - **混淆与失败观察**：混淆几乎全压在 **0/O**（21 次），而 **1/I、5/S 一次都不混**——背后是『内部特征 vs 边界特征』的可辨识度差异；**粘连字符**则直接击穿连通域分割（99% 的串被粘连成块、整串精确率跌到 1%）。
> - 代码基于 **candle 0.11.0**，纯 CPU，本机 `cargo run --release` 实测，数字均为真实输出、可复现。

## 场景：读出设备上那一串序列号

你要给一条产线做质量追溯：每个零件上都激光打了一串**序列号**（像 `60704`、`3A2F1`），相机拍下来，程序得**自动读成文本**存进数据库。人工抄又慢又错。这就是最典型、也最适合纯 Rust 落地的 OCR 场景——**字符集固定、背景干净、字形规整**。

但在动手前，必须先把一件事说透，否则会走进死胡同：

> ⚠️ **注意（先认清纯 Rust 的 OCR 边界）**：**纯 Rust 目前没有成熟的通用 OCR 引擎。** 业界主力 Tesseract（C++/leptonica）、PaddleOCR（Python + C++）都不是纯 Rust，用它们就违反了本书的硬约束。硬要在纯 Rust 里做**通用**文字识别（任意字体、手写、弯曲排版、成千上万汉字），需要 CTC / 注意力的**序列识别模型**加上不小的训练数据与算力，纯 Rust 生态还很单薄。**所以本章不假装纯 Rust 能做通用 OCR**，而是老老实实走**能做好、也够用**的一条路：受限字符集。

| 需求 | 可行方案 | 是否纯 Rust |
| --- | --- | --- |
| **固定字形、干净背景的短串**（序列号/仪表/编码/车牌） | **本章方案**：连通域分割 + 小 CNN 逐字分类 | ✅ 纯 Rust |
| 通用印刷体 / 多语言 / 弯曲排版 | 下载导出的 **CRNN / PaddleOCR ONNX**，用 `tract` 加载推理（[第 94 章](../p19-deploy/ch94-onnx.md)） | ⚠️ 代码纯 Rust，但**依赖外部模型文件**，非自包含 |
| 手写体 / 复杂版面理解 | 调 Tesseract 绑定或云 OCR API | ❌ 非纯 Rust |

本章聚焦第一行——它自包含、可复现、且是工业读码（[第 81 章](../p17-industrial/ch81-code-reading.md)）里字符识别的真实做法。

## 原理：检测 + 识别，两步走

书名里的『检测与识别』，在受限 OCR 里可以拆得非常清楚：

```text
字符串图 ──连通域(第18章)──▶ 每个字符的外接框(检测/定位) ──抠图+缩放──▶ 小CNN逐字分类(识别) ──按x排序──▶ 拼成字符串
```

### 第一步：连通域分割 = 检测每个字符在哪

我们的字（亮字暗底）互不相连，那么**一个字符就是一个连通的亮像素块**。用 [第 18 章](../p03-classic/ch18-contours.md) 的 **8 邻域 BFS 连通域**：把满足 \\( I(x,y) > \tau \\) 的像素当前景（本例阈值 \\( \tau = 0.35 \\)），泛洪出每一块的外接框，再按最小面积滤掉噪点，最后**按外接框左边界 \\( x_0 \\) 排序**，就得到从左到右的一个个字符框。

### 第二步：小 CNN 逐字识别

把每个字符框抠出来、缩放到统一的 \\( 24 \times 24 \\) 灰度，喂进一个**小 CNN**（结构复用 [第 42 章](../p08-classification/ch42-candle-classify.md)：两层卷积 + 池化 + 两层全连接，输出 13 类）。字符集取 `"0123456789OIS"`——10 个数字加 3 个易混字母 O/I/S，**故意**构造 0/O、1/I、5/S 三对形近字，好观察谁真的会混。

### 评测指标：两个都要看

```text
逐字准确率  = 预测对的字符数 / 总字符数
整串精确匹配率 = 整串一字不差的样本数 / 样本总数
```

\\[ \text{逐字准确率}=\frac{\text{正确字符数}}{\text{总字符数}},\qquad \text{整串精确匹配率}=\frac{\text{整串完全正确的样本数}}{\text{样本总数}} \\]

为什么要分开看？因为一串序列号**错一个字符，整串就作废**。逐字 93% 听着不错，但一串 5 个字，整串正确率可能只有 \\( 0.93^5 \approx 70\% \\)。产线真正关心的是**整串对不对**，所以整串精确匹配率是更狠、更贴近现实的指标。

## 头号教训：分类器要在『分割产出』上训练

这是本章最想让你记住的一点，也是第 20 部分实战项目（如姊妹篇 [第 102 章](ch102-defect-system.md)）反复出现的**级联域偏移（domain gap）**：当系统由多个阶段串起来（这里是 **分割 → 分类**），**下游必须在上游真实产出的数据分布上训练**，而不是在你想当然的『干净理想输入』上训练。

具体到 OCR：分割器抠出来的字符框是**紧贴笔画的外接框**，再被**拉伸**成正方形——长宽比全乱了（窄窄的 `1` 被横向拉胖，宽宽的 `0` 被压扁）。如果你图省事，用『**保持长宽比、居中摆好**』的漂亮字形去训练分类器，它在训练集上表现完美，一接上真实分割器就**精度崩塌，而且不报错**——这是最阴险的一类 bug。

本章的做法是**同时训两个分类器**，端到端对拍：

- **NAIVE**：每类用『干净居中、保持长宽比』的字形训练（初学者的想当然做法）。
- **PIPELINE**：真的跑一遍分割，把**分割器实际抠出、拉伸后的字形**收集起来训练。

两者除了训练数据的『几何分布』不同，网络、超参、样本量全都对齐，公平对比。

## 动手写代码

> ⚠️ **注意**：完整工程见 `code/projects/ch99_ocr/`，`cargo run --release` 即可复现（纯 CPU，约十几秒）。`Cargo.toml` 只依赖三个**纯 Rust** crate（含空 `[workspace]` 独立成工程，不牵动主工程）：

```toml

[workspace]

[dependencies]
candle-core = "0.11.0"   # 纯 Rust 张量/自动微分
candle-nn = "0.11.0"     # 卷积/全连接/优化器
image = "0.25"           # 抠图、缩放、存 PNG
```

**自包含合成数据**：不用任何字体文件，直接手写一套 **5×7 位图字体**。关键是把形近字设计成『只差一点点』——0 和 O 只差**正中心那一个像素**：

```rust
// 每个字形 7 行、每行低 5 位；1=亮像素。0 比 O 在正中心多一个点：
'0' => [0b01110, 0b10001, 0b10001, 0b10101, 0b10001, 0b10001, 0b01110],
'O' => [0b01110, 0b10001, 0b10001, 0b10001, 0b10001, 0b10001, 0b01110],
// 1 与 I 只差顶部一横（边界、多像素）；5 与 S 只差拐角走向（边界、多像素）
```

合成一张短串图时，亮字（0.9）画在暗底（0.10）上，再叠**一次 \\([1,2,1]/4\\) 分离式模糊**（模拟成像退化）、**高斯噪声**、**位置抖动**和**字间距变化**。随机数用固定种子的 LCG，且**只取高位** `self.next() >> 11`（低位规律差，会污染合成、破坏可复现——[第 42 章](../p08-classification/ch42-candle-classify.md) 里踩过）。

**8 邻域 BFS 连通域分割**（返回按 \\( x_0 \\) 排序的外接框）：

```rust
fn segment(gray: &[f32], w: usize, h: usize, thr: f32, min_area: usize) -> Vec<[usize; 4]> {
    let fg: Vec<bool> = gray.iter().map(|&v| v > thr).collect(); // 亮字为前景
    // ... 对每个未访问前景像素做 BFS 泛洪，8 邻域，累计外接框 (x0,y0,x1,y1) 与面积 ...
    // 面积 >= min_area 的块才保留（滤噪点）
    boxes.sort_by_key(|b| b[0]); // 按左边界 x0 排序 → 左到右
    boxes
}
```

**两个训练集的构造**（§20 的关键就在这几行——一个走真实分割，一个想当然居中）：

```rust
// PIPELINE：真的跑分割，只保留『分割块数 == 真值长度』的串，用分割产出的字形训练
let boxes = segment(&g, w, h, THR, MIN_AREA);
if boxes.len() != gt.len() { continue; }          // 分割数对不上就丢弃（没法可靠打标签）
for (b, c) in boxes.iter().zip(gt.chars()) {
    px.push(crop_resize(&g, w, h, *b));           // ← 紧贴框 + 拉伸，正是推理时的真实分布
    py.push(idx_of(c) as u32);
}

// NAIVE：每类画『保持长宽比、居中』的干净字形（分布与分割产出不一致）
nx.push(render_centered(char_at(ci), &mut rng));  // ← 居中、不拉伸，漂亮但不真实
```

**完整 OCR** 就是把三步接起来：

```rust
fn ocr(net: &CharCnn, gray: &[f32], w: usize, h: usize, dev: &Device) -> Result<(String, Vec<[usize;4]>)> {
    let boxes = segment(gray, w, h, THR, MIN_AREA);   // ① 检测：连通域定位
    let mut s = String::new();
    for &b in &boxes {
        let crop = crop_resize(gray, w, h, b);        // ② 抠图 + 拉伸到 24×24
        let x = Tensor::from_vec(crop, (1,1,CLS_SZ,CLS_SZ), dev)?;
        let pred = net.forward(&x)?.argmax(D::Minus1)?.to_vec1::<u32>()?[0] as usize;
        s.push(char_at(pred));                        // ③ 识别：逐字分类
    }
    Ok((s, boxes))                                    // 按 x 排序过 → 天然左到右拼串
}
```

运行 `cargo run --release`，真实输出（节选）：

```text
受限字符集 OCR：字符集 = "0123456789OIS"（13 类），亮字暗底短串，纯 Rust 纯 CPU。

PIPELINE 训练：扫过 269 串、保留分割正确的 260 串 → 共 1311 个字符样本（走真实分割分布）。
NAIVE  训练：每类 100 个"干净居中"字形 → 共 1300 个字符样本（分布与分割产出不一致，§20 对照）。

========== 评测（干净测试集，字间距清晰）==========
分割成功率（连通域数=真值长度）：95.5%（191/200）

NAIVE ：逐字准确率 = 69.6%（699/1005），整串精确匹配率 = 20.5%（41/200）
PIPELINE：逐字准确率 = 93.6%（941/1005），整串精确匹配率 = 85.0%（170/200）
```

**这就是级联域偏移的真身。** 两个分类器网络结构、样本量（约 1300）、训练轮数完全一样，唯一的差别是**训练字形的几何分布**：NAIVE 居中保长宽比，PIPELINE 用分割真实抠出的拉伸字形。结果 NAIVE 一接上真实分割器，逐字准确率就从『训练集近乎满分』掉到 **69.6%**，整串精确匹配率只剩 **20.5%**——五串里四串是错的；而 PIPELINE 达到 **93.6% / 85.0%**。**同一个分割器、同一批测试图，只因分类器训练数据的分布对没对上，整串正确率差了 4 倍。**

### 混淆观察：为什么只有 0/O 混，1/I、5/S 不混？

```text
========== 混淆观察（PIPELINE 分类器）==========
最主要的错分对（真值→预测：次数）：
  0 → O ：21
  0 → 8 ：1
重点易混对：
  0/O: 0→O 21 次，O→0 0 次
  1/I: 1→I 0 次，I→1 0 次
  5/S: 5→S 0 次，S→5 0 次
```

混淆几乎全压在 **0/O**（21 次，且清一色 0→O）。为什么偏偏是它？因为 0 与 O 的唯一区别，是 0 正中心那**一个像素点**——它被字形**内部**的暗背景团团围住，成像时轻轻一模糊就和周围暗背景搅在一起、被抹平了，分类器只能按更『干净』的 O 去猜。反观 **1/I**（差在顶部有没有一横）、**5/S**（差在拐角的走向），它们的判别特征都长在字形的**边界**上、而且跨好几个像素，模糊糊不掉——所以这两对**一次都没混**（0/0）。

> 💡 **提示（一条反直觉但极实用的经验）**：受限 OCR 里最该防的，往往**不是『长得最像』的字，而是『唯一区别恰好落在会被成像退化吃掉的地方』的字**。0/O 的区别是被暗背景包围的一个内部像素，最脆；1/I、5/S 的区别在高对比的字形边界上，反而稳。设计字符集或字体时，尽量让易混字的差异落在**边界、且跨多像素**。

### 粘连字符：连通域分割的『阿喀琉斯之踵』

把字间距调成负数（字符相互挨上），再看：

```text
========== 粘连测试集（字间距为负，字符相互粘连）==========
  例：真值"60704"（5 字）→ 分割出 1 块 → 识别"8"
粘连集：99.0% 的串出现"分割块数<真值长度"（99/100），整串精确匹配率骤降到 1.0%（1/100）
```

一旦字符粘连，『一个字 = 一个连通块』的前提就崩了：`60704` 五个字连成**一整块**，分割只给出 **1 个框**，CNN 把这一大坨认成 `8`。**99%** 的粘连串都出现了『分割块数 < 真值长度』，整串精确匹配率从干净集的 85% **暴跌到 1%**。这就是纯连通域方案的硬边界——它吃『字符分得开』这口饭。程序会存 `ocr_clean.png`（红框整整齐齐框住每个字）和 `ocr_touch.png`（一个红框跨了好几个字）让你肉眼看清。

## 常见坑与提示

> 🕳️ **坑（本章最大的坑）**：**下游分类器一定要用上游的真实产出训练。** 用漂亮的居中字形训练，接上真实分割器后精度会崩且不报错（本章 NAIVE 整串 20.5% vs PIPELINE 85.0%）。任何『分割→分类』『检测→识别』的级联系统都适用：**让训练输入 = 上游真实输出的分布**。

> 🕳️ **坑**：**连通域分割怕粘连、也怕碎裂。** 字符一挨上就被并成一块（本章粘连集 99% 中招）；反过来，如果模糊 + 阈值配得太狠，一个字的细笔画会被切成好几块（碎裂）。阈值 \\( \tau \\) 和最小面积要在『能连住笔画』和『能分开相邻字』之间平衡。真要处理粘连，得上投影切分、过分割再合并，或直接换 CTC 序列模型。

> ⚠️ **注意**：**抠图后的缩放会破坏长宽比，这既是坑也是必须如实建模的现实。** 紧贴外接框再拉成正方形，会把 `1` 拉胖、把 `0` 压扁。别试图在训练端『修正』成漂亮长宽比——那只会重新制造域偏移。正确姿势是**让训练和推理用完全相同的抠图+缩放**。

> 📖 **术语**：**受限字符集 OCR（constrained/fixed-charset OCR）**——已知字符种类有限、字形规整、背景干净的识别任务（序列号、仪表、车牌、编码）。与之相对的**通用 OCR**要应对任意字体、语言、版面与手写，难度和模型量级完全不同。

> 💡 **提示（想要更强就走 ONNX）**：要识别通用印刷体、多语言或弯曲文字，务实路线是拿一个训练好的 **CRNN / PaddleOCR** 模型**导出成 ONNX**，用纯 Rust 的 `tract` 加载推理（[第 94 章](../p19-deploy/ch94-onnx.md)）——代码仍是纯 Rust，代价是**依赖外部模型文件、不再自包含**。这和用纯 Rust 跑真实 YOLO/SAM 是同一条思路：**结构与预处理讲透，权重靠下载**。

## 本章小结

- **受限字符集 OCR = 检测 + 识别**：连通域定位每个字符（[第 18 章](../p03-classic/ch18-contours.md)）→ 小 CNN 逐字分类（[第 42 章](../p08-classification/ch42-candle-classify.md)）→ 按 \\( x \\) 排序拼串。这是纯 Rust 能稳稳拿下的 OCR，也是工业读码（[第 81 章](../p17-industrial/ch81-code-reading.md)）里字符识别的真实做法。
- **诚实边界**：纯 Rust **没有**成熟通用 OCR 引擎；通用/手写/弯曲文字要序列模型 + 大模型，务实路线是 ONNX + `tract`（[第 94 章](../p19-deploy/ch94-onnx.md)），非自包含。
- **头号教训（级联域偏移）**：下游分类器必须在上游真实产出的分布上训练。本章 NAIVE（居中干净字形）逐字 **69.6%** / 整串 **20.5%**，PIPELINE（分割真实产出）**93.6%** / **85.0%**——同一分割器，整串正确率差 4 倍。
- **两个必看指标**：逐字准确率与**整串精确匹配率**；序列号错一字即废，整串指标才贴近现实。
- **两个失败观察**：混淆集中在 0/O（21 次，内部单像素特征被模糊吃掉），而 1/I、5/S 因判别特征在边界、跨多像素而不混；**粘连字符**直接击穿连通域分割（99% 合并、整串 1%）。

## 动手练习

1. **亲手复现域偏移**：把 NAIVE 的 `render_centered` 改成也走一遍分割再抠图（即变成 PIPELINE 的做法），重跑，看它的整串精确匹配率是不是从 20.5% 追上 PIPELINE。这是理解 §20 最直接的一步。
2. **调分割阈值**：把 \\( \tau \\)（`THR`）从 0.35 改成 0.25、0.45、0.6，记录分割成功率、碎裂/合并各自怎么变，找出这批合成图的『甜点』阈值。
3. **制造更多混淆**：给字符集加入 2/Z、8/B 等形近对，或把 0 的中心点改成更小/更大，观察混淆矩阵怎么变——验证『内部特征脆、边界特征稳』的规律。
4. **对付粘连（进阶）**：对分割出的**过宽**连通块，按宽度估计它含几个字，做等分或垂直投影谷底切分，看粘连集的整串精确率能从 1% 救回多少。
5. **接真实模型（进阶）**：找一个导出的 CRNN ONNX，用 `tract`（[第 94 章](../p19-deploy/ch94-onnx.md)）加载，对同一批测试串跑推理，和本章的连通域 + CNN 方案对比准确率与依赖成本。

## 结语

这一章把连通域分析和小 CNN 拼成了一个**能落地的受限字符集 OCR**，更重要的是让你亲手摸到了两个专家级直觉：**级联系统里下游要吃上游的真实分布**（NAIVE 与 PIPELINE 差了 4 倍整串正确率），以及**易混字的可辨识度取决于判别特征扛不扛得住成像退化**（0/O 混而 1/I、5/S 不混）。纯 Rust 做不了通用 OCR，但把边界认清、把这条受限路线走扎实，序列号、仪表、编码这些**最常见的工业读字需求，它完全够用**。👉 要上更强模型，见 [第 94 章 ONNX 部署](../p19-deploy/ch94-onnx.md)。
