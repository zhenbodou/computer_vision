# 第 103 章 项目：周界入侵报警（ROI + 绊线 + cooldown）

> **本章导读**
> - 这是一个**集成项目**：把第十八部分的三块“积木”——**ROI 多边形**（[第 84 章](../p18-events/ch84-roi-filter.md)）、**绊线方向**（[第 87 章](../p18-events/ch87-tripwire.md)）、**cooldown 冷却去重**（[第 86 章](../p18-events/ch86-cooldown-dedup.md)）——组装成一个**周界入侵报警**系统。
> - 核心是一个工程直觉：**单靠“进没进区域”会误报**（把正要离场的保安也报了）。真正的入侵要满足**两个因子**——既**越过警戒线朝“进入”方向**、又**落在布防区内**。本章用真实数字对比“只看区域”和“两因子”的报警差别。
> - 全程纯 Rust、只用 `std`、不碰 OpenCV；数据模型复用 [第 83 章](../p18-events/ch83-filtering-basics.md) 的 `BBox/Track/Event`，输入是跟踪器（[第 62](../p13-tracking/ch62-mot.md)、[97 章](ch97-realtime-pipeline.md)）给的带稳定 `track_id` 的轨迹。射线法、叉积定侧的**原理前面已讲透**，这里只讲**怎么把它们拼成一个不误报、不刷屏的报警器**，正文每个数字都来自本机 `cargo run --release`。

## 场景：院子的周界，翻墙的贼与离场的保安

给一个院子布防：拉一圈**布防多边形**（脚点落进去才可能报警），沿墙头拉一条**警戒绊线**。我们希望：

- **翻墙进来的人** → 报警（入侵）。
- **本来在院里、正走出去的保安** → 不报警（他在离场，不是威胁）。
- **街面上路过、根本没进院的人** → 不报警。
- 同一个入侵者**在院里赖着不走** → 只报一次，别每帧都刷屏。

这四条诉求，恰好把三块积木都用上了。

## 设计一：三块积木各管一件事

```text
① ROI 多边形(第84章)：脚点在不在布防区内？   —— 射线法(奇偶穿越)
② 绊线方向(第87章)：越线是"进院"还是"出院"？ —— 叉积定侧(符号=哪一侧)
③ cooldown(第86章)：同一目标持续停留只报一次 —— 按 track_id 冷却
```

**判进没进区域**用射线法（[第 84 章](../p18-events/ch84-roi-filter.md)）：从脚点向右引射线，数它穿过多边形边的次数，奇数=在内。**判越线方向**用叉积（[第 87 章](../p18-events/ch87-tripwire.md)）：对有向线 \\(A\to B\\) 和点 \\(P\\)，

\\( \text{cross}(A,B,P)=(B_x-A_x)(P_y-A_y)-(B_y-A_y)(P_x-A_x) \\)

的**符号**就是 \\(P\\) 在线的哪一侧。约定警戒线上方（院外）为负、下方（院内）为正，那么“出发点在院外、这一帧到了院内”就是**入侵方向**。**判去重**用 cooldown（[第 86 章](../p18-events/ch86-cooldown-dedup.md)）：一张 `last_fire: HashMap<track_id, ts>`，冷却期内的重复命中一律吞掉。

## 设计二：两因子——为什么只看区域会误报

先看一个反例：**方案 A，只用“脚点在布防区内 + cooldown”**，不看方向。跑我们这 4 条轨迹：

```text
—— 方案 A：仅 ROI + cooldown（不看方向）——
  [intrusion] t= 280ms track#1 person 出现在布防区内
  [intrusion] t=1080ms track#2 person 出现在布防区内
  [intrusion] t=   0ms track#3 person 出现在布防区内
  方案 A 报警数 = 3（把离场保安 track#3 也报了）
```

**3 条报警里有一条是冤枉的**：`track#3` 是本来就在院里、正往外走的保安，他从没“闯入”，只是碰巧还站在区内，方案 A 却报了他。

**方案 B，两因子**：一个目标必须**先越警戒线朝“进入”方向**（叉积判定），**之后又落在布防区内**，才算真入侵。先看方向判定这一关：

```text
—— 绊线方向判定（叉积定侧，进院 / 出院）——
  track#1 person：进院 1 次 / 出院 0 次  —— 翻墙进院（入侵方向）
  track#2 person：进院 1 次 / 出院 0 次  —— 翻墙进院（入侵方向）
  track#3 person：进院 0 次 / 出院 1 次  —— 走出院子（离开方向，非报警）
  track#4 person：进院 0 次 / 出院 0 次  —— 未越警戒线（街面路过）
```

方向这一关就把 `track#3`（叉积符号显示是“出院”）和 `track#4`（压根没越线）滤掉了。加上 cooldown 去重后：

```text
—— 方案 B：两因子（越警戒线【进入方向】且在布防区内）+ cooldown ——
  不做 cooldown：每个“入侵后仍在区内”的帧都报 → 218 条
  实际报警（按 track_id 冷却 10s 去重）：
  [intrusion] t= 280ms track#1 person 翻越警戒线闯入布防区
  [intrusion] t=1080ms track#2 person 翻越警戒线闯入布防区
  入侵事件数 = 2
```

**方案 B 精确报出 2 起真入侵**（两个翻墙者），不含离场保安。注意 `track#1` 和 `track#2` 都报了——**cooldown 是按 `track_id` 各算各的**，不会因为 `#1` 先报了就把 `#2` 一起冷却掉。

## 动手：从命中帧到告警的收敛链

> ⚠️ **注意**：完整独立工程见 `code/projects/ch103_perimeter/`，**`cd` 进去 `cargo run --release`**，纯 `std` 无依赖。输入是**合成的带 `track_id` 轨迹**（4 条：两个翻墙者、一个离场保安、一个街面路人），确定性可复现。

把整条“过滤—去重”链的数字摊开看，最能体会各环节的作用：

```text
—— 去重 / 过滤前后对比 ——
原始命中帧 245 → 两因子过滤(进入方向且在区内) 218 → cooldown 后报警 2 条
方案 A（仅 ROI）3 条  vs  方案 B（两因子）2 条
差异来自：track#3 保安在区内但方向是“离开”，两因子直接排除；track#4 从未进区，ROI 直接排除。
```

**245 → 218 → 2** 这条收敛链讲清了三件事：ROI 层把“脚点在区内”的原始命中收成 **245 帧**（含保安在区内的 27 帧）；两因子层要求“先入侵方向越线”，把保安整条轨迹排除、剩 **218 帧**；cooldown 层把同一目标的连续命中收成**每人一条**、最终 **2 条**。**层层收敛，把成千帧的原始信号收成两条能直接推给保安的告警。**

## 常见坑与提示

> 🕳️ **坑（脚点恰好落在线上——浮点退化，本章真实踩到）**：判越线用的是“线段真相交”——两组叉积**严格异号**（`d1*d2 < 0.0 && d3*d4 < 0.0`）。但如果某一帧脚点**恰好落在警戒线上**，该点叉积 `=0`，乘积就**不小于 0**，这一步跨越会被漏判，导致“翻墙者却报了 0 次进院”。本章造数据时 `track#1` 起点走位恰好在某帧压中 `y=180`，就中招过。工程对策：**别让轨迹端点卡在线上**（给坐标留零点几像素余量），或把判据放宽成含等号、或引入**迟滞**（离线一段距离才算真正越过）——总之要正视“恰好在边界上”这个浮点世界的常客。

> ⚠️ **注意（cooldown 按 track_id，不是全局）**：冷却闸门的键必须是 `track_id`。若图省事用一个全局“上次报警时间”，`track#1` 报警后 10s 内 `track#2` 翻墙就会被一起冷却掉、漏报。**每个目标一把独立的冷却锁**，才能既去重同一人、又不漏报不同人（本章 `#1`、`#2` 都正确报出）。

> 💡 **提示（两因子＝“方向”＋“区域”的与门）**：入侵 = **越警戒线朝进入方向** AND **落在布防区内**，两个条件是**逻辑与**。只用其一都不够：只看区域会报离场者（方案 A 的教训），只看越线会报“隔着栏杆蹭一下又退回去、根本没进院”的。两个正交的几何证据叠加，才是稳的报警判据。

> 📖 **诚实边界**：这是**教学级报警器**。真周界系统还要：（1）用**真检测器+跟踪器**，且 `track_id` 断裂会让“入侵方向”的历史丢失（需 ReID 续上）；（2）**布防多边形/警戒线要在真实相机视角下标定**，还常随镜头畸变、透视变形；（3）处理**夜间/雨雾/小动物/树影晃动**等误报源；（4）用**采集真实时间戳**做 cooldown，而非帧序号。但“ROI × 方向 × cooldown”这套两因子骨架，是工业周界报警的通用配方。

## 本章小结

- **周界入侵报警 = ROI 多边形 × 绊线方向 × cooldown** 三块积木的组装（分别来自 [第 84](../p18-events/ch84-roi-filter.md)、[87](../p18-events/ch87-tripwire.md)、[86 章](../p18-events/ch86-cooldown-dedup.md)），输入是跟踪器给的带 `track_id` 轨迹。
- **核心是“两因子”**：真入侵要**同时**满足“越警戒线朝进入方向”和“落在布防区内”。只看区域会误报离场者——实测**方案 A 报 3 条**（含冤枉的保安 `track#3`），**方案 B 精确报 2 条**真入侵。
- **过滤—去重是一条收敛链**：原始命中 **245 帧** → 两因子过滤 **218 帧** → cooldown 后 **2 条**告警。层层收敛，把海量原始信号收成可直接派发的告警。
- **cooldown 必须按 `track_id`**，每个目标独立冷却，才能既去重同一人、又不漏报不同人。
- **新踩的坑**：脚点**恰好落在警戒线上**时，严格叉积异号判据会漏判越线（浮点退化）——对策是避开边界、放宽等号或加迟滞。
- **诚实边界**：真系统还需处理检测/跟踪误差、相机标定、环境误报源与真实时钟。

## 动手练习

1. **改布防形状**：把矩形/梯形布防区改成一个**凹多边形**（比如 L 形院子），重跑看射线法是否照样正确——体会 [第 84 章](../p18-events/ch84-roi-filter.md) 射线法对凹多边形也成立。
2. **反转警戒线方向**：把 `wire_a` 和 `wire_b` 对调，观察“进院/出院”判定是否整个翻转——理解叉积符号与线段定向的关系。
3. **调 cooldown**：把冷却时长从 10s 改成 1s，看 `track#1`、`track#2` 是否被报了多次；再改成 60s，体会“去重强度”与“漏掉二次入侵”的权衡。
4. **复现那个坑**：把 `track#1` 的起点脚点改回恰好压线的坐标，观察它的“进院次数”变成 0、入侵漏报；再把判据改成含等号或加半像素余量，看是否修复。
