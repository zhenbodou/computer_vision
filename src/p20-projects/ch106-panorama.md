# 第 106 章 项目：全景图拼接工具

> **本章导读**
> - 学完你能：用**纯 Rust** 把两张有重叠的照片**拼成一张全景图**，跑通经典 CV 的完整流水线——**特征检测（FAST）→ 描述与匹配（BRIEF）→ RANSAC 估单应矩阵 → 透视变换 + 羽化融合**。这是[第 23](../p04-features/ch23-corners.md)~[26 章](../p04-features/ch26-homography-stitching.md)特征与几何知识的**集大成落地**。
> - 你会得到一组**最有说服力的真数字**（本机 `cargo run --release` 实测、确定性可复现）：140 对 BRIEF 匹配里，RANSAC 筛出 **111 个内点（内点率 79.3%）**，内点平均**重投影误差仅 0.471px**；把估出的单应矩阵和**真值单应**一比，右图四角平均落点误差只有 **1.965px**——纯手写的 DLT + RANSAC，把单应矩阵估得相当准。
> - 你还会看到一个**真实踩过的深坑**：用 `nalgebra` 的 SVD 解 \\(A\mathbf{h}=\mathbf{0}\\) 时，「取 V 的最后一行」这个教科书写法**在 4 点最小解那里翻了车**——因为瘦 SVD 的 V 根本不够 9 行。这个 bug 让真值单应算成一堆乱码，我们会讲清它、修好它。
> - 一条**诚实边界**：本章是「平面/纯旋转」假设下的两图拼接；真正的全景软件还需**光束法平差、曝光补偿、柱面/球面投影**，且 BRIEF **不具旋转/尺度不变性**——我们会说清差距在哪。

## 场景：手机「全景模式」背后到底做了什么

你举起手机横扫一圈，它把连拍的十几张照片无缝拼成一张超宽的全景图。这背后是一条经典得不能再经典的 CV 流水线。它的核心问题是：**两张有重叠的图，怎么知道它们该怎么对齐、然后严丝合缝地拼起来？**

拆开看就三件事：**① 在两张图里各自找一批「地标」**（特征点）；**② 把同一个地标在两张图里配上对**（匹配）；**③ 求出一个几何变换，把右图掰到左图的坐标系里**，再叠上去融合。难点集中在第③步——匹配里混着大量错配，得有办法**从一堆真真假假的对应里，稳稳地估出那个正确的变换**。这正是 RANSAC 大显身手的地方。

## 原理：五步流水线

```text
  左图 ┐                                                      ┌─▶ 融合(羽化)
       ├─▶ ① FAST 找角点 ─▶ ② BRIEF 描述+匹配 ─▶ ③ RANSAC ─┤
  右图 ┘                                            估单应 H  └─▶ ④ 把右图 warp 到左图坐标系
                                                                        │
                                                                        ▼
                                                                  ⑤ 全景图
```

### ① 找地标：FAST 角点

要对齐两张图，先得在各自图里找到一批**稳定、可重复检测**的关键点。角点（两条边的交汇处）是最好的地标——它在哪个方向上都有明显变化，换个视角还认得出。我们用 [第 23 章](../p04-features/ch23-corners.md)的 **FAST**：看一个像素周围一圈 16 个点，若有连续一长串都比中心显著亮（或暗），中心就是角点。快、够用。

### ② 配对：BRIEF 描述子 + 匹配

光有角点位置还不够，得给每个角点一个「指纹」，才能判断左图的某个角点和右图的哪个是同一个。我们用 [第 24 章](../p04-features/ch24-descriptors.md)的 **BRIEF**：在角点周围的小块（本章 31×31）里，取 256 组固定的点对，每组比一下谁亮谁暗，得到一个 **256 位的二进制串**。两个 BRIEF 指纹的距离就是**汉明距离**（有多少位不同）。匹配就是：给左图每个指纹，在右图找汉明距离最近、且小于阈值的那个。

> ⚠️ **注意**：BRIEF 的 256 组测试点对**必须两张图共用同一套**，否则指纹的每一位含义都对不上，根本没法比。`imageproc` 默认用系统随机数生成这套点对——**那样每次运行都不同、不可复现**！本章用固定种子的 LCG 自己生成点对传进去（`override_test_pairs`），这是让整个流程确定性可复现的关键一步。

### ③ 去伪存真：RANSAC 估单应矩阵

即便有阈值，匹配里仍混着大量**错配**（不同地标指纹撞脸）。此时若拿所有匹配去拟合变换，会被错配带跑偏。**单应矩阵（homography）** \\(H\\) 是描述「两个平面视图之间投影关系」的 3×3 矩阵（[第 26 章](../p04-features/ch26-homography-stitching.md)），它把右图的点 \\((x,y)\\) 映到左图的 \\((u,v)\\)：

\\[ \begin{bmatrix} u \\\\ v \\\\ 1 \end{bmatrix} \sim H \begin{bmatrix} x \\\\ y \\\\ 1 \end{bmatrix}, \qquad H = \begin{bmatrix} h_{11} & h_{12} & h_{13} \\\\ h_{21} & h_{22} & h_{23} \\\\ h_{31} & h_{32} & h_{33} \end{bmatrix} \\]

\\(H\\) 有 8 个自由度（尺度无关），**一对点给两个方程，4 对点即可解**。每对对应点 \\((x,y)\to(u,v)\\) 贡献两行约束（这套「直接线性变换 DLT」的推导见 [第 26 章](../p04-features/ch26-homography-stitching.md)）：

\\[ \begin{bmatrix} -x & -y & -1 & 0 & 0 & 0 & ux & uy & u \\\\ 0 & 0 & 0 & -x & -y & -1 & vx & vy & v \end{bmatrix} \mathbf{h} = \mathbf{0} \\]

把 \\(N\\) 对点的行堆成矩阵 \\(A\\)（\\(2N\times 9\\)），要解的就是 \\(A\mathbf{h}=\mathbf{0}\\)——其中 \\(\mathbf{h}\\) 是 \\(H\\) 拉平成的 9 维向量。这是个齐次最小二乘：**解就是 \\(A\\) 最小奇异值对应的右奇异向量**（用 `nalgebra` 的 SVD 求，呼应第十四部分标定里同样的线性代数套路）。

**RANSAC** 则负责在错配中捞出真值：反复随机取 4 对点算一个 \\(H\\)、数有多少对匹配满足它（内点），留下**内点最多**的那个，最后用全部内点重新精拟合。

### ④⑤ 变换 + 融合

有了 \\(H\\)，把右图每个像素通过 \\(H\\) **透视变换**到左图坐标系（`imageproc::warp_into`），落到一张更宽的画布上；重叠区用**线性羽化（feathering）**——沿水平方向让左图权重渐弱、右图权重渐强地加权平均——把接缝抹平。

**合成输入**（自包含、无需外部图）：先造一张 1000×420 的场景，**关键在纹理要「局部处处可区分」**——中性底 + 少量大色块（全局结构）+ **2600 个随机彩色斑点**。左图取场景左 600px；右图用一个带**轻微透视**的四边形把场景右侧 `warp` 成 600×420，两图重叠约 240px。真值单应由这组控制点直接算出，留作最后核验精度。

**检测 + 描述**：FAST 找角点 → 滤掉离边 16px 内的（BRIEF 的 31×31 块会越界）→ 按响应强度取前 500 → BRIEF 描述：

```rust
fn detect_and_describe(gray: &GrayImage, pairs: &[TestPair], max_kp: usize)
    -> Vec<BriefDescriptor>
{
    let (w, h) = (gray.width(), gray.height());
    let mut corners = corners_fast9(gray, 25);
    corners.retain(|c| c.x > 16 && c.x + 16 < w && c.y > 16 && c.y + 16 < h);
    corners.sort_by(|a, b| b.score.partial_cmp(&a.score).unwrap()); // 响应降序
    corners.truncate(max_kp);
    let kps: Vec<Point<u32>> = corners.iter().map(|c| Point::new(c.x, c.y)).collect();
    // pairs：两图共用的确定性 BRIEF 测试点对，必须传进去，别用默认的系统随机
    brief(gray, &kps, 256, Some(&pairs.to_vec())).expect("BRIEF 失败").0
}
```

**DLT 估单应**（本章的核心，含 Hartley 归一化提升数值稳定性）：

```rust
/// 由 ≥4 对点 (src→dst) 用 DLT 估单应 H（H 把 src 映到 dst）。
fn estimate_homography(pairs: &[([f64; 2], [f64; 2])]) -> Option<Matrix3<f64>> {
    if pairs.len() < 4 { return None; }
    // …先对 src、dst 各做归一化（平移到质心、缩放到平均距离 √2），拿到 Ts、Td…
    let mut a = DMatrix::<f64>::zeros(2 * pairs.len(), 9);
    for i in 0..pairs.len() {
        let [x, y] = sn[i];  let [u, v] = dn[i];      // 归一化后的坐标
        a[(2*i,0)]=-x; a[(2*i,1)]=-y; a[(2*i,2)]=-1.0;
        a[(2*i,6)]=u*x; a[(2*i,7)]=u*y; a[(2*i,8)]=u;
        a[(2*i+1,3)]=-x; a[(2*i+1,4)]=-y; a[(2*i+1,5)]=-1.0;
        a[(2*i+1,6)]=v*x; a[(2*i+1,7)]=v*y; a[(2*i+1,8)]=v;
    }
    // 解 A h = 0：取最小奇异向量。用 9×9 的 AᵀA 做对称特征分解最稳 ——
    // 无论点对数是 4 还是几百，都得到 9×9 系统，避开「瘦 SVD 的 V 不足 9 行」的坑！
    let ata = &a.transpose() * &a;
    let se = ata.symmetric_eigen();
    let mut min_i = 0;
    for i in 1..se.eigenvalues.len() {
        if se.eigenvalues[i] < se.eigenvalues[min_i] { min_i = i; }
    }
    let hv = se.eigenvectors.column(min_i);           // 最小特征值 → Ah=0 的解
    let hn = Matrix3::new(hv[0],hv[1],hv[2], hv[3],hv[4],hv[5], hv[6],hv[7],hv[8]);
    Some(td.try_inverse()? * hn * ts)                 // 反归一化，固定 h33=1
}
```

**RANSAC** 反复取 4 对点估 \\(H\\)、统计重投影误差 <3px 的内点，留内点最多者，末了用全部内点精拟合。**变换 + 羽化融合**用 `warp_into` 把右图和一张全白 mask 一起 `warp` 到画布（mask 给出右图的真实覆盖范围），重叠区按水平位置线性加权。完整可运行代码（约 290 行）在仓库 `code/projects/ch106_panorama/src/main.rs`。

## 常见坑与提示

> 🕳️ **坑（本章最贵的教训）**：**解 \\(A\mathbf{h}=\mathbf{0}\\) 时，「取 SVD 里 V 的最后一行」这个教科书写法会在最小解翻车。** 教科书说：解是 \\(A\\) 最小奇异值对应的右奇异向量，即 \\(V\\) 的最后一列 / \\(V^\top\\) 的最后一行。但 `nalgebra` 的 `svd` 默认算**瘦 SVD**：对 \\(2N\times 9\\) 的 \\(A\\)，当点对数多（\\(2N>9\\)）时 \\(V^\top\\) 是 9×9、取最后一行没问题；可**当只有 4 对点时** \\(A\\) 是 8×9（行比列少），瘦 SVD 的 \\(V^\top\\) 只有 **8 行**——第 9 个（也就是真正的零空间向量）**根本没算出来**！于是「最后一行」取到的是错的向量。症状极其迷惑：RANSAC 里几百个内点精拟合出的 \\(H\\) 是对的（那时 \\(A\\) 很高、V 够 9 行），可用 4 个控制点算真值 \\(H\\) 却成了一堆乱码，四角误差飙到几百像素。**正解**：改用 9×9 的 \\(A^\top A\\) 做对称特征分解，取最小特征值的特征向量——它**恒为 9 维**，点对数是 4 还是 400 都不塌，数值上还更稳。

> 🕳️ **坑**：**BRIEF 靠局部像素对比来区分，纹理太「自相似」就会误匹配爆炸。** 我第一版场景画的是大矩形和大圆——结果「所有直角 corner 在 31×31 块里长得一模一样」，BRIEF 指纹毫无区分度，匹配里全是错配，RANSAC 甚至锁定到一个自洽但完全错误的模型。**对策**：撒一层**随机彩色斑点**，让每个局部邻域都独一无二，匹配立刻变干净。但斑点也不能太细——太细的高频纹理经 `warp` 的双线性重采样会被糊掉，真匹配反而消失；**中等尺度、局部各异**才是甜点。

> ⚠️ **注意**：**搞清 `warp_into` 的方向，别把 \\(H\\) 用反。** `imageproc` 的 `warp_into(src, proj, ..., dst)` 内部会对 `proj` **求逆**再做反向采样，所以**传进去的 `proj` 应是「源→目标」方向**。本章 \\(H\\) 把右图映到左图坐标系，正是「源(右图)→目标(画布)」，直接 `Projection::from_matrix` 传入即可。方向反了，右图会被投到画面外、或严重变形。

> 💡 **提示**：**估单应前先做坐标归一化（Hartley normalization）。** 直接拿原始像素坐标（几百上千）塞进 DLT，\\(A\\) 各列量级悬殊、条件数极差，SVD 解不稳。标准做法：把每张图的点**平移到质心、缩放到平均距离 \\(\sqrt{2}\\)**，用归一化坐标解出 \\(H_n\\)，再 \\(H = T_d^{-1} H_n T_s\\) 变回去。本章 0.471px 的低误差有它一份功劳。

> ⚠️ **注意（诚实边界）**：**这是教学级两图拼接，和 Hugin/AutoStitch 那类全景软件仍有明显差距。**（1）真全景是**多图**拼接，要用**光束法平差（bundle adjustment）** 全局联合优化所有相机位姿，否则误差会沿链累积、越拼越歪；（2）不同照片曝光不同，需**曝光补偿 + 多频段融合**，单纯羽化会留下亮度带；（3）相机纯旋转扫一大圈时，平面单应会把边缘拉伸变形，需**柱面/球面投影**；（4）**BRIEF 不具旋转/尺度不变性**——本章两图视角接近才好用，视角差大就得换 **ORB**（带方向的 BRIEF）或 **SIFT**（尺度+旋转不变，纯 Rust 有 `sift-features` 等实现）。这条流水线是骨架，工业级全景是在每一环上把它做深。

## 本章小结

- **全景拼接 = 五步流水线**：FAST 找角点（[第 23 章](../p04-features/ch23-corners.md)）→ BRIEF 描述+匹配（[第 24 章](../p04-features/ch24-descriptors.md)）→ RANSAC 估单应（[第 25](../p04-features/ch25-matching-ransac.md)、[26 章](../p04-features/ch26-homography-stitching.md)）→ 透视 warp → 羽化融合。纯 Rust（`image`/`imageproc`/`nalgebra`）全程无 C/C++ 依赖。
- **单应矩阵与 DLT**：\\(H\\) 是 3×3、8 自由度的平面投影，一对点两个方程、4 对可解；把约束堆成 \\(A\\)，解 \\(A\mathbf{h}=\mathbf{0}\\) 取最小奇异向量。**RANSAC** 从错配里捞真值：随机 4 点估、数内点、留最优、再精拟合。
- **实测结果过硬**：140 对匹配 → 111 内点（**79.3%**），内点重投影误差 **0.471px**；估计单应 vs **真值单应**四角误差仅 **1.965px**，拼接肉眼无缝。
- **最贵的坑**：`nalgebra` 瘦 SVD 在 4 点最小解处 \\(V^\top\\) 不足 9 行，「取最后一行」拿到错向量——改用 **\\(A^\top A\\) 的对称特征分解**（恒 9 维）根治。另有两坑：纹理要**局部可区分**（否则 BRIEF 误匹配爆炸）、`warp` 方向别用反、DLT 前务必**坐标归一化**。
- **诚实边界**：真全景还需**光束法平差、曝光补偿、柱面/球面投影**；BRIEF 无旋转/尺度不变性，视角差大要换 ORB/SIFT。

## 动手练习

1. **加大视角差，逼出 BRIEF 的短板**：把合成右图的透视四边形改得更「斜」（更大的梯形形变），重跑，观察内点率和四角误差怎样恶化——体会 BRIEF「不具旋转/尺度不变性」的边界在哪。
2. **调 RANSAC 参数**：把内点阈值从 3px 收紧到 1px、放宽到 8px，或把迭代次数从 3000 改成 300/30000，看内点数、重投影误差、四角误差如何变化，找准确率与耗时的平衡点。
3. **换更强的融合**：把线性羽化换成**多频段融合（拉普拉斯金字塔）**，对比曝光/亮度有差异时接缝的平滑程度；或给左右图人为加一点亮度差，看羽化会不会留下亮度带。
4. **（挑战）拼三张图**：再合成一张与右图重叠的第三图，依次估 \\(H_{2\to1}\\)、\\(H_{3\to2}\\)，用 \\(H_{3\to1}=H_{2\to1}H_{3\to2}\\) 串联拼三图。你会亲眼看到误差**沿链累积**——从而理解真全景为何非要**光束法平差**做全局优化不可。
