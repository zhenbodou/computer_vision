# 第 55 章 手部关键点与手势识别

> **本章导读**
> - 学完你能：用 **candle**（0.11.0）搭一个热图回归网络，在合成手上预测 **11 个手部关键点**（手腕 + 5 指的指根/指尖），再**只靠关节的几何关系**识别 5 种手势（握拳、张开、数字一、数字二、点赞）。
> - 你会走通一条完整的**自底向上链路**：**关键点 → 几何特征（每指伸/屈）→ 语义手势**——这也是手势控制、手语识别的通用套路。
> - 你会亲眼看到一个重要事实：**几何规则本身可以 100% 正确，端到端却做不到——瓶颈在"看得准不准"（关键点定位），不在规则**。
> - 纯 CPU、不下载模型就跑通；正文每个数字都来自本机 `cargo run --release`。

## 场景：隔空比划就能操控

在 VR/AR 里，你不用手柄，抬手一比就能点击、缩放；手语翻译 App 看你的手型就能识别字母；智能电视看你比"手掌"就暂停。这些背后都是**手部关键点检测 + 手势识别**：先定位手上的一串关节点，再根据这些点的**几何关系**（哪根手指伸直、哪根弯曲、指尖朝哪）判断你在比什么。

这一章我们把 [第 52 章](ch52-keypoint-basics.md)、[第 53 章](ch53-human-pose.md) 的热图回归**原样搬到手上**（手就是"另一种带骨架的关节体"），再加一层**几何规则**把关键点翻译成手势——一条从"点"到"语义"的完整链路。

> 📖 **术语**：**手部关键点（hand keypoint）**。手上有语义的关节点。业界标准（如 MediaPipe Hands）用 **21 点**：1 个手腕 + 每根手指 4 个关节。本章为讲清原理**简化成 11 点**：手腕 + 5 指各取"指根 + 指尖"两点，足够判断每根手指的伸屈。

## 原理一：手部关键点检测 = 热图回归（原样复用）

手是一个"带骨架的关节体"，和人体姿态（[第 53 章](ch53-human-pose.md)）**同构**：关节 = 关键点，骨头 = 连接。所以检测手部关键点，**完全复用 [第 52 章](ch52-keypoint-basics.md) 的热图回归**——每个关节一张高斯热图，MSE 训练，argmax + 亚像素解码。我们的骨架这样连：

```text
   指尖  指尖 指尖 指尖  指尖        BONES：
    │    │   │   │    │           手腕 → 各指根（掌部 5 条）
   指根  指根 指根 指根 指根          各指根 → 对应指尖（手指 5 条）
     ╲   ╲   │   ╱   ╱
      ╲   ╲  │  ╱   ╱
       ╲___╲_│_╱___╱
           手腕(0)
```

关键点索引：`0=手腕`，第 `f` 根手指（拇/食/中/无名/小）的 `指根=1+2f`、`指尖=2+2f`。热图网络结构、`det_init`、解码都与 [第 53 章](ch53-human-pose.md) 一致，头输出 `J=11` 张热图。

## 原理二：关键点 → 几何特征 → 语义手势

有了 11 个关节坐标，怎么知道比的是"握拳"还是"数字二"？靠**几何**：一个手势，本质就是**哪几根手指伸直、哪几根弯曲**的组合。

怎么判断一根手指是伸直还是弯曲？看它的**指尖离手腕的距离**：手指伸直时，指尖伸向远方，**离手腕比指根更远**；手指弯曲时，指尖折回掌心，**反而离手腕更近**。于是一条简单又稳的规则：

\\[ \text{第 } f \text{ 指伸直} \iff \lVert \text{tip}_f - \text{wrist} \rVert > \tau \cdot \lVert \text{base}_f - \text{wrist} \rVert \\]

\\( \tau \\) 取 1.15（留点余量抗噪）。算出 5 根手指的伸/屈组合，再查一张手势表就得到语义：

| 手势 | 拇 | 食 | 中 | 无名 | 小 |
|------|----|----|----|------|----|
| 握拳 | 屈 | 屈 | 屈 | 屈 | 屈 |
| 张开 | 伸 | 伸 | 伸 | 伸 | 伸 |
| 数字一 | 屈 | 伸 | 屈 | 屈 | 屈 |
| 数字二 | 屈 | 伸 | 伸 | 屈 | 屈 |
| 点赞 | 伸 | 屈 | 屈 | 屈 | 屈 |

```rust
fn extended_pattern(js: &Joints) -> [bool; 5] {
    let wrist = js[0];
    let mut ext = [false; 5];
    for f in 0..5 {
        let base = js[1 + 2 * f];
        let tip = js[2 + 2 * f];
        ext[f] = dist(tip, wrist) > 1.15 * dist(base, wrist); // 指尖比指根更远离手腕 → 伸直
    }
    ext
}
// 把伸屈模式匹配到 5 种手势之一
fn classify(js: &Joints) -> i32 { /* 精确匹配手势表，见配套工程 */ }
```

> 📖 **术语**：**自底向上（bottom-up）的语义理解**。先从像素里抽出**低层几何实体**（关键点），再由它们的**空间关系**组合出**高层语义**（手势）。这套"感知 → 几何 → 语义"的分层，比"一张图直接分类手势"更**可解释、可调试**——识别错了，你能立刻定位是关键点没测准，还是规则没写对。

## 动手：合成手 + 热图回归 + 手势识别（candle）

> ⚠️ **注意**：本章代码基于 **candle 0.11.0**，纯 CPU。完整独立工程见 `code/dl_labs/ch55_hand/`，**`cd` 进去 `cargo run --release`**（约几分钟）。热图网络、解码复用 [第 53 章](ch53-human-pose.md)。

合成手是一副**骨架**：手腕 + 5 指的指根/指尖，随机旋转/缩放/位置。**手势决定每指伸屈**——伸直则指尖沿手指外向伸长，弯曲则指尖折回半根手指（落在指根靠掌一侧）。5 种手势各均衡合成，train 300 张、test 100 张。

热图回归训练 250 轮（MSE + lr 衰减），在 100 张全新测试手上评估定位精度：

```text
===== 关键点定位（100 张测试手，共 1100 个关节）=====
  平均定位误差 = 1.263 像素，PCK@0.2 = 95.9%
  指根平均误差 = 1.097 像素，指尖平均误差 = 1.618 像素（指尖更难）
```

**平均定位误差 1.26 像素、PCK@0.2 达 95.9%**。注意**指尖（1.62px）明显比指根（1.10px）更难定**——指尖在手指末端、活动范围大、弯曲时还会折向掌心与别的关节挤在一起，这正是真实手部姿态估计里最头疼的地方（手指自遮挡）。配套工程会存 5 张骨架 PNG（每种手势一张），**绿色真值骨架与黄色预测骨架紧密重合**，张开手的手指清晰伸展、握拳的指尖折回掌侧。

### 关键发现：规则没错，错的是"看得准不准"

把预测出的关键点喂进几何规则识别手势，并和"直接用真值关键点"对比：

```text
===== 手势识别（关键点→几何规则→手势）=====
  用“真值关键点”识别准确率 = 100.0%（几何规则上限）
  用“预测关键点”识别准确率 = 89.0%（端到端）
  分手势（预测点）：握拳=19/20  张开=16/20  数字一=17/20  数字二=19/20  点赞=18/20
```

**这两行数字信息量极大：**

- **用真值关键点，识别 100% 正确**——说明我们的几何规则**本身完全靠谱**，5 种手势的伸屈模式定义得清清楚楚。
- **用预测关键点，掉到 89%**——这 11 个百分点的损失，**全部来自关键点定位的那 1.26 像素误差**（尤其指尖）。某根手指的指尖偶尔测偏，伸/屈判断就翻车，进而整个手势判错。

**结论：这条链路的瓶颈在"感知"（关键点测得准不准），而不在"规则"。** 这是一个特别值得记住的工程直觉：当端到端效果不好时，先分段定位——是**关键点没测准**，还是**规则没写对**？本章用"真值 vs 预测"两个数字，一秒钟就把锅甩给了感知端。相应地，**想把手势识别做得更好，最划算的是提升关键点精度**（更大的热图、更多数据、更强骨干），而不是把规则越写越复杂。

## 常见坑与提示

> 🕳️ **坑**：**混合手势比"全伸/全屈"脆弱得多。** 握拳（全屈）、张开（全伸）容错性高——个别手指测偏也不影响整体判断；而"数字一/二"这种**要求某几根伸、其余屈**的混合模式，**任何一根手指判错，整个手势就错**。所以你会看到极端手势稳、精细手势飘。真实系统对精细手势要么用更准的关键点，要么加时间平滑（连续几帧投票，[第 85 章](../p18-events/ch85-temporal-window.md)）。

> 💡 **提示**：**规则判定 vs 学一个小分类器。** 本章用**几何规则**（可解释、零训练、易调试）。当手势多、边界模糊时，也可以把关键点的几何特征（各指伸屈、指间夹角、指尖间距）拼成一个特征向量，喂给一个小分类器（[第 33 章](../p06-ml/ch33-linfa.md) 的 SVM/决策树，或一个小 MLP）。**关键点 → 几何特征**这一步不变，变的只是最后"特征 → 手势"用规则还是用模型。

> ⚠️ **注意**：**真实手是 21 点，且有严重自遮挡。** 本章简化成 11 点、且手指不交叉。真实手部姿态估计要处理**手指互相遮挡、握拳时指尖藏进掌心、正反手**等难题——这也是为什么专业方案（MediaPipe Hands）用 21 点、且常配深度信息或多视角。上真实数据前，务必把这些难样本纳入评估。

> 🕳️ **坑**：**划分泄漏对手部同样致命。** 和 [第 53 章](ch53-human-pose.md) 一样，若同一段手势视频的近似重复帧被随机切进 train/val，指标会虚高。手势数据要**按录制片段/被试者**分组划分，别随机切帧。

> 💡 **提示（上真实模型）**：想跑真正的手部关键点模型，纯 Rust 路线和 [第 53 章](ch53-human-pose.md) 一致——用 `tract` 加载导出的 `.onnx`（如 MediaPipe Hands 系列），**务必先看输出形状**（是热图还是直接坐标）再解码，需自备权重、不入一键 demo。

## 本章小结

- **手部关键点检测 = 热图回归**，与人体姿态（[第 53 章](ch53-human-pose.md)）同构：手就是"另一种带骨架的关节体"，网络、损失、解码原样复用。
- **手势识别走"关键点 → 几何特征 → 语义"的自底向上链路**：由每根手指"指尖是否比指根更远离手腕"判断伸/屈，再把伸屈组合查表得到手势——可解释、可调试。
- 实测：11 点手部关键点平均定位误差 **1.26 像素**、PCK@0.2 **95.9%**，其中**指尖（1.62px）比指根（1.10px）更难**（手指自遮挡的缩影）。
- **最重要的发现**：几何规则用**真值关键点**识别 **100%**，用**预测关键点**只有 **89%**——**瓶颈在感知（关键点准不准），不在规则**。端到端不好时，先分段甩锅，再对症下药（多半是去提升关键点精度）。
- 极端手势（握拳/张开）稳、混合手势（数字一/二）脆——因为混合模式对每根手指的判断都零容忍。

## 动手练习

1. **加手势**：给手势表加"数字三"（食+中+无名伸）或"OK"（拇尖与食尖相碰），重训重测，看新手势的识别率——精细手势通常更难。
2. **换分类器**：把 `classify` 的精确匹配换成"到 5 种模式的最近汉明距离"，看它能不能挽救一部分"个别手指判错"的样本；再想想为什么相邻手势（拳/一/二）只差一根手指，最近匹配也难完全救回。
3. **提升关键点精度**：把热图分辨率/数据量/训练轮数加大，看关键点误差降到多少、端到端手势识别能不能逼近那个 100% 的上限——亲手验证"瓶颈在感知"。
4. **想一想**：为什么"用真值关键点 100%、用预测关键点 89%"这两个数字，比单看一个 89% 有用得多？在你自己的项目里，怎么用"理想输入 vs 真实输入"这招快速定位瓶颈？
