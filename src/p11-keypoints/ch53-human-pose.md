# 第 53 章 人体姿态估计（OpenPose/HRNet/MoveNet）

> **本章导读**
> - 学完你能：把 [第 52 章](ch52-keypoint-basics.md) 的热图回归用到**人体姿态**上——在合成"火柴人"上预测 **J 个身体关节**，再**把关节按骨架连成姿态**画出来，并用 **PCK** 量化准不准。
> - 你会想通人体姿态的两条技术路线（**自顶向下 vs 自底向上**），并认识三个真实模型的定位：**OpenPose、HRNet、MoveNet**。
> - 姿态估计**本质是关键点检测**，所以我们直接**套用检测的经验**：数值稳定的损失、学习率衰减，以及那条价值千金的**划分泄漏**教训——这次在关键点任务上**再实测一遍**。
> - 我们用**小网络 + 合成火柴人**，纯 CPU、不下载模型就跑通；正文每个数字都来自本机 `cargo run --release`。最后给出**诚实的"上真实模型"路线**（`tract` 加载 `.onnx`，需自备权重）。

## 场景：从"一串点"到"一个姿态"

[第 52 章](ch52-keypoint-basics.md) 我们学会了在图上定位若干关键点。但把 17 个身体关键点单独拎出来看，只是一地散落的点——**人真正关心的是"姿态"：这个人是站着、蹲着，还是举着手？** 要回答这个，光有点不够，还得知道**点之间怎么连**：头连颈、颈连肩、肩连肘、肘连腕……这套固定的"连线规则"叫**骨架（skeleton）**。关键点 + 骨架，才拼出一个能看懂的**人体姿态（human pose）**。

有了姿态就能做很多事：健身 App 数深蹲（看髋、膝的高度变化，[第 105 章](../p20-projects/ch105-pose-counter.md) 会做）、跌倒检测（看躯干角度）、动作捕捉、手语识别……这一章我们就亲手把"检测关节 → 连成骨架 → 量化准不准"这条链路跑通。

## 原理一：姿态估计 = 关键点检测 + 骨架拓扑

好消息是——**检测关节本身，就是 [第 52 章](ch52-keypoint-basics.md) 的热图回归**：每个关节一张高斯热图，MSE 训练，argmax + 亚像素解码出坐标。姿态估计新增的，只有两件事：

1. **关节更多、有语义分组**：一个人通常定义 **17 个关键点**（COCO 标准：鼻、双眼、双耳、双肩、双肘、双腕、双髋、双膝、双踝）。本章为讲清原理用简化的 **7 关节火柴人**（头、颈、双手、髋、双脚）。
2. **骨架拓扑**：一张**固定的连接表**说明"哪些关节该连成肢体"。解码出关节后，按这张表连线，就画出了姿态。

```text
   0 头                 骨架连接表 BONES：
   │                    (0,1) 头-颈
   1 颈                 (1,2) 颈-左手 [左臂]
  ╱│╲                   (1,3) 颈-右手 [右臂]
 2 │ 3  (手)            (1,4) 颈-髋   [躯干]
   4 髋                 (4,5) 髋-左脚 [左腿]
  ╱ ╲                   (4,6) 髋-右脚 [右腿]
 5   6  (脚)
```

## 原理二：两条路线——自顶向下 vs 自底向上

一张图里有多个人时，怎么办？业界有两条经典路线：

- **自顶向下（top-down）**：先用**目标检测**（[第 46 章](../p09-detection/ch46-yolo-inference.md)）把每个人框出来，把每个人的框**裁剪**出来，再对**单人**跑姿态估计。优点是**每次只面对一个人，定位精准**；缺点是**开销随人数线性增长**（100 个人就要跑 100 次），且依赖检测器别漏人。**HRNet** 常这么用。
- **自底向上（bottom-up）**：一次性**检出图里所有人的所有关键点**（比如所有的肘、所有的腕），再想办法**把它们分组**——哪几个点属于同一个人。优点是**开销几乎与人数无关**（一次前向搞定）；缺点是**分组难**。**OpenPose** 就是自底向上的代表，它用 [第 52 章](ch52-keypoint-basics.md) 讲的 **PAF（部件亲和场）**沿肢体方向积分来判断"这只肘和这只腕是不是同一条胳膊"，从而分组。

> 📖 **术语**：**三个绕不开的真实模型**。
> - **OpenPose**：自底向上鼻祖，热图 + PAF，能实时多人，但模型不小。
> - **HRNet（High-Resolution Net）**：核心思想是**全程保持高分辨率特征**——不像普通网络先猛降采样再恢复，它用多条不同分辨率的分支**并行**且不断交换信息，因此**定位极准**，是精度标杆（常配自顶向下）。
> - **MoveNet**：Google 出品的**轻量级**模型（MobileNet 骨干 + 特征金字塔），为**手机/边缘设备实时**而生，可导出 ONNX / TFLite。**注意它直接输出坐标，不是热图**——这点后面接真实模型时是个大坑。

我们的小 demo 走**单人、热图回归**路线（相当于自顶向下里"裁出单人后"的那一步），把最核心的机制讲透。

## 原理三：PCK——姿态估计怎么算"对"

关键点定位准不准，最常用的指标是 **PCK（Percentage of Correct Keypoints，正确关键点百分比）**：一个预测关节，只要它离真值**足够近**（在阈值内），就算"对"；PCK 就是"算对的关节"占全部关节的百分比。

阈值不用绝对像素（大图小图不公平），而是用一个**与人体尺度成比例**的参考长度 \\( d_{ref} \\)（常用躯干长或头部长），乘一个系数 \\( \alpha \\)：

\\[ \mathrm{PCK@}\alpha = \frac{1}{N_J}\sum_{i} \mathbb{1}\left[\lVert \hat{p}_i - p_i \rVert_2 \le \alpha \cdot d_{ref}\right] \\]

\\( \alpha \\) 越小越严格。本章用**躯干长（颈到髋的距离）**作参考，同时报 **PCK@0.2（严）**和 **PCK@0.5（松）**，外加**平均关节误差（像素）**——三个数一起看，才不会被单一指标骗到（这条纪律和 [第 47 章](../p09-detection/ch47-train-detector.md) 一模一样）。

## 动手：合成火柴人上的姿态估计（candle）

> ⚠️ **注意**：本章代码基于 **candle 0.11.0**，纯 CPU。完整独立工程见 `code/dl_labs/ch53_pose/`，**`cd` 进去 `cargo run --release`**（含两次训练，约几分钟）。网络结构、热图目标、解码、`det_init` 都**复用 [第 52 章](ch52-keypoint-basics.md)**——姿态估计就是"关节更多的关键点检测"。

`Cargo.toml` 依赖同 [第 52 章](ch52-keypoint-basics.md)（candle-core / candle-nn / image / imageproc）。

### 合成火柴人：一个"场景"就是一副姿态

我们造 48×48 的火柴人：一副**姿态（场景）**由 7 个关节的规范布局决定（左肢体偏左、右肢体偏右，保证关节**身份可学**，但四肢角度随机 → 姿态多样：抬手/垂手、叉腿/并腿）。渲染时用**盖小圆的方式画出有粗细的肢体**：

```rust
const J: usize = 7;
const BONES: [(usize, usize); 6] = [(0,1),(1,2),(1,3),(1,4),(4,5),(4,6)];

fn draw_thick_line(img: &mut RgbImage, a: [f32;2], b: [f32;2], r: i32, color: Rgb<u8>) {
    let steps = ((a[0]-b[0]).abs().max((a[1]-b[1]).abs()) as i32 * 2).max(1);
    for s in 0..=steps {                       // 沿线段插值，每步盖一个实心小圆 → 有粗细的肢体
        let t = s as f32 / steps as f32;
        stamp_disk(img, a[0]+(b[0]-a[0])*t, a[1]+(b[1]-a[1])*t, r, color);
    }
}
```

**关键设计（为随后的泄漏实验埋线）**：每副姿态渲染**多帧近似重复图**——整体小平移 + 每关节小抖动 + 随机亮度 + 像素噪声。这样一个"场景"就有一组"长得很像但不完全一样"的帧，正如监控视频里相邻的帧（呼应 [第 47 章](../p09-detection/ch47-train-detector.md)）。

### 网络、训练：直接套用检测/关键点的经验

网络就是 [第 52 章](ch52-keypoint-basics.md) 的编码器-解码器，头输出 `J` 张热图。训练**套用检测经验**（[第 47 章](../p09-detection/ch47-train-detector.md)）：**MSE 热图损失**（数值稳定，不碰 `cross_entropy` / 不稳的 BCE）、**AdamW + 学习率后段衰减**、candle CPU 不能 `set_seed` 故用**确定性初始化**：

```rust
let mut opt = AdamW::new(vm.all_vars(), ParamsAdamW { lr: 3e-3, ..Default::default() })?;
for epoch in 1..=epochs {
    if epoch == epochs * 2 / 3 { opt.set_learning_rate(5e-4); }  // lr 衰减，把峰值磨准
    let pred = net.forward(&x)?;
    let loss = pred.broadcast_sub(&target)?.sqr()?.mean_all()?;  // MSE 热图回归
    opt.backward_step(&loss)?;
}
```

在**诚实的分组划分**（详见下节）上训练 150 轮，真实 MSE 曲线：

```text
===== 训练姿态网络（分组划分，AdamW lr=3e-3→5e-4，MSE 热图回归）=====
  epoch         MSE
      1    0.005464
     40    0.002827
     80    0.001751
    120    0.001079
    140    0.000958
```

### 解码 + 连骨架 + 报 PCK

解码沿用 [第 52 章](ch52-keypoint-basics.md) 的"argmax + 抛物线亚像素"逐关节取峰值坐标，然后按 `BONES` 把关节连成骨架画出来。在 **48 张全新姿态**（分组 val）上评估，真实输出：

```text
【分组 val（全新姿态）】平均关节误差 = 1.258 像素，PCK@0.2 = 84.2%，PCK@0.5 = 99.4%
分关节平均误差(像素)：头=1.27  颈=2.07  左手=0.66  右手=1.77  髋=1.97  左脚=0.61  右脚=0.45
```

**在从没见过的姿态上，PCK@0.2 达 84.2%、平均关节误差仅 1.26 像素**，骨架画出来和真人姿态贴合。有意思的是**分关节误差**：颈（2.07）、髋（1.97）这两个**躯干内部的分叉点**明显比手、脚这些**肢体末端**（0.45~0.66）更难定准——因为末端有明确的"线头"可抓，而内部分叉点周围都是肢体、上下文更模糊。这种**逐关节的误差分析**，正是找改进方向的抓手。

配套工程会存 3 张骨架 PNG（`pose_0.png` 等，文字示意）：深色底上是白色火柴人，**绿色骨架（真值）**和**黄色骨架（预测）**几乎重合，关节处绿圈套着黄叉——一眼能看出姿态估对了。

## 实验：划分泄漏——关键点检测里同样致命

[第 47 章](../p09-detection/ch47-train-detector.md) 在检测上证明过：**同场景/同视频的近似重复帧跨 train/val 乱分，会把指标虚高得离谱**。姿态估计是关键点检测，这条铁律照样成立。我们用完全相同的数据（**16 个场景 × 12 帧 = 192 帧**），只改划分方式，各训一个网络：

- **分组划分（诚实）**：前 12 个场景（144 帧）train，后 4 个**全新姿态**（48 帧）val。
- **随机划分（泄漏）**：192 帧打乱随机切。诊断证实泄漏满格：

```text
随机划分：train 144 帧，val 48 帧；其中 48/48 个 val 帧的场景也出现在 train 中（近似重复→泄漏）
```

同网络、同训练，只改划分，结果：

```text
  划分方式        平均误差(px)   PCK@0.2    PCK@0.5
  随机(泄漏)         0.900       95.8%     99.7%
  分组(诚实)         1.258       84.2%     99.4%
  → 随机划分把 PCK@0.2 虚高了 11.6 个百分点（关键点检测里的泄漏代价）
```

**随机划分报出 PCK@0.2 = 95.8%，诚实的分组划分只有 84.2%——虚高了 11.6 个百分点**，平均误差也从 1.26px 被"优化"到 0.90px。原因和检测一模一样：随机划分下，模型训练时已见过每个 val 帧的"孪生兄弟"，val 成绩衡量的是**"记住了没有"**而非**"能不能泛化到新姿态"**。

> 💡 **提示**：**注意 PCK@0.5 几乎没差（99.7% vs 99.4%）——阈值太松，把泄漏藏起来了。** 只有严格的 PCK@0.2 才把 11.6 个点的水分挤出来。这提醒你：**指标的阈值选得太松，会掩盖真实差距**；评估姿态时务必报几个不同严格度的 PCK，别只报一个漂亮的松阈值。

> 🕳️ **坑**：**卷积平移等变，"只改位置"的近似重复帧几乎不虚高指标。** 想让泄漏在关键点任务上**显形**，数据必须**场景少 + 每场景多个近似重复帧 + 有亮度/噪声/姿态抖动等非平移差异**（本章正是这么造的）。真实视频每秒几十帧、帧帧近似，泄漏能把指标吹到离谱。**同视频/同主体/同场次的帧，必须按组划分**——先划分、后一切。

## 诚实的"上真实模型"路线（tract 加载 ONNX）

上面是我们自己训的小火柴人网络。想在纯 Rust 里跑真正的 HRNet / MoveNet？能，但要说清边界：

> ⚠️ **注意（诚实边界）**：**纯 Rust 生态里没有"内置权重、开箱即跑"的姿态模型。** 你需要自备 `.onnx`（HRNet 用 PyTorch 导出，或下载现成的 MoveNet ONNX），再用纯 Rust 的 `tract-onnx`（[第 94 章](../p19-deploy/ch94-onnx.md)，零 C/C++ 依赖）加载。因为要下载模型，这条路**不纳入本章一键 demo**，但下面的骨架**真实、可编译**（已用 `tract-onnx 0.23.5` `cargo build` 验证通过）。

对**热图式**模型（如 HRNet），解码和我们的小 demo 一模一样——argmax 取每张热图峰值：

```rust
use tract_onnx::prelude::*;
const INPUT: usize = 256;

let model = tract_onnx::onnx()
    .model_for_path("pose_hrnet.onnx")?
    .with_input_fact(0, f32::fact([1, 3, INPUT, INPUT]).into())?
    .into_optimized()?.into_runnable()?;
let input = Tensor::from_shape(&[1, 3, INPUT, INPUT], &data)?;  // data: letterbox/resize+/255+CHW
let result = model.run(tvec!(input.into()))?;

// ⚠️ 先看形状再解码：不同模型布局天差地别，绝不能照抄下标！
let out = result[0].to_plain_array_view::<f32>()?;   // 期望 [1,K,Hh,Ww]（热图）
println!("原始输出形状 = {:?}", out.shape());
let (kk, hh, ww) = (out.shape()[1], out.shape()[2], out.shape()[3]);
for k in 0..kk {                                     // 逐关节 argmax 峰值 → 映射回原图
    let (mut br, mut bc, mut bv) = (0usize, 0usize, f32::MIN);
    for r in 0..hh { for c in 0..ww {
        let v = out[[0, k, r, c]];
        if v > bv { bv = v; br = r; bc = c; }
    }}
    let (x, y) = (bc as f32 / ww as f32 * w0, br as f32 / hh as f32 * h0);
    println!("关节 {k}: ({x:.1}, {y:.1})  峰值={bv:.3}");
}
```

> 🕳️ **坑（本节最想让你记住的）**：**别把某个模型的输出布局当"通用姿态"写死。** 这里 HRNet 输出**热图** `[1,K,Hh,Ww]`，你 argmax 解码；但 **MoveNet 直接输出坐标** `[1,1,17,3]`（每关节的 `y,x,score`，而且是**归一化坐标**、`y` 在前！），根本不用 argmax，拿到就是坐标。还有输入布局差异（NCHW vs NHWC）、是否要特定归一化、单人还是多人……**正确姿势和 [第 46 章](../p09-detection/ch46-yolo-inference.md) 一样：先用模型检查器（Netron）看清输入输出的名字/形状/语义，用几个黄金样本和原框架对齐结果，再固化预处理与解码。** 上面那句打印形状就是在提醒你：**先看形状，再谈解码**。

> 💡 **提示（验证到什么程度）**：本骨架已 `cargo build` 编译通过，但**没跑真实权重**（那需要你自备 `.onnx`）。所以这里**不给"PCK 多少"的数字**——**没跑过的模型，本书绝不编数字**（和 [第 46 章](../p09-detection/ch46-yolo-inference.md) 同一条底线）。跑不通时，十有八九是预处理或解码没对齐。

## 常见坑与提示

> 🕳️ **坑**：**左右关节的身份最难学。** "左手"和"右手"长得一样，只能靠**身体上下文**区分（哪个在躯干左边）。姿态一大、肢体交叉（比如手举过头、双腿交叉），模型极易**左右互换**。本章特意把左肢体约束在偏左、右肢体偏右来降低歧义；真实数据里这是常见错误源，评估时要专门看**左右混淆**。

> ⚠️ **注意**：**遮挡与截断是家常便饭。** 真实图里关节常被挡住或出画。通用做法是给每个关节配**可见性标志**，不可见的**不计损失**、评估时单独统计（[第 52 章](ch52-keypoint-basics.md) 提过）。本章火柴人无遮挡，故从简——但上真实数据前必须把这套加上。

> 💡 **提示**：**自顶向下 vs 自底向上，按人数和精度需求选。** 人少、要精度 → 自顶向下（检测 + 单人 HRNet）；人多、要恒定开销 → 自底向上（OpenPose + PAF）。别无脑照搬某一种。

> 🕳️ **坑**：**热图分辨率决定精度上限。** 和 [第 52 章](ch52-keypoint-basics.md) 一样，热图越大定位越准但越费算力。本章热图与输入同分辨率、再加亚像素，才拿到 1.26px 的误差；真实系统常用 1/4 分辨率热图 + 亚像素折中。

## 本章小结

- **人体姿态 = 关键点检测 + 骨架拓扑**。检测关节就是 [第 52 章](ch52-keypoint-basics.md) 的热图回归；姿态多做的只是**按固定连接表把关节连成骨架**。
- 多人有两条路线：**自顶向下**（先检测人、再单人姿态，准但开销随人数增长，HRNet 常用）和**自底向上**（一次检出所有关键点再分组，开销恒定但分组难，OpenPose 用 PAF 分组）；**MoveNet** 是为端侧实时而生的轻量模型（且**直接输出坐标**）。
- 姿态是关键点检测，**直接套用检测经验**：MSE 稳定损失、lr 衰减、逐关节误差分析、以及**划分泄漏**纪律。
- 我们实测：7 关节火柴人姿态网络，在**全新姿态**上平均关节误差 **1.26 像素**、**PCK@0.2 = 84.2%**；躯干内部分叉点（颈、髋）比肢体末端更难定准。
- **划分泄漏实测**：同一批"场景 + 近似重复帧"，随机划分把 PCK@0.2 从诚实的 84.2% 虚高到 **95.8%（+11.6 点）**，而松阈值 PCK@0.5 几乎看不出差别——**泄漏要靠严格指标 + 分组划分才抓得住**。
- **诚实边界**：纯 Rust 没有开箱即跑的姿态模型；上真实 HRNet/MoveNet 走 `tract` 加载自备 `.onnx`，**务必先看输出形状**——HRNet 出热图（argmax 解码）、MoveNet 直接出归一化坐标，**绝不能照抄某个布局**。

## 动手练习

1. **复现泄漏放大**：把配套工程 `frames_per_scene` 从 12 改到 4、再改到 20（同时可减少 `n_scenes`），重跑对照，找出让 PCK@0.2 虚高差距**最大**的配置——亲手体会"场景越少、近似重复越多，泄漏越狠"。
2. **换指标严格度**：把 PCK 的阈值系数从 0.2 / 0.5 改成 0.1 和 0.3，看泄漏差距怎么随阈值变化——理解"为什么松阈值会掩盖问题"。
3. **加难样本**：给火柴人加入**手举过头**或**双腿交叉**的极端姿态，重训，看哪些关节误差飙升、左右是否互换——定位模型的真实短板。
4. **接真实模型（进阶）**：`cargo add tract-onnx image`，下载一个 MoveNet 或 HRNet 的 `.onnx`，用本章骨架跑一张真人照片；**先 `println!` 出输出形状**，判断它是"热图"还是"直接坐标"，再写对应解码。跑通后对照官方结果验证。
