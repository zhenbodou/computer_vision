> - 最后讲清 **PAF（部件亲和场）**——多人场景里"这只胳膊到底是谁的"怎么解，为下一章的人体姿态打底。

## 场景：健身 App 怎么数你做了几个深蹲

[第 1 章](../p01-start/ch01-what-is-cv.md) 的任务地图里有一项叫**关键点 / 姿态**。最接地气的例子是健身 App：你对着手机做深蹲，它能实时数出"第 3 个""第 4 个"。它靠的不是识别"这是一个人"（那是分类），也不是框出"人在这儿"（那是检测），而是**精确定位身上一串关键位置**——鼻子、肩、肘、腕、髋、膝、踝……然后看膝盖和髋的相对高度变化来判断"蹲下去又起来了"。

**关键点检测（keypoint detection）**要回答的就是："图里那个物体上，我关心的那几个点，各自在哪个像素？"人脸的眼角嘴角、手的指尖关节、工业零件的定位孔中心、动物的鼻尖——本质都是同一个任务。这一章我们把它的**原理和最经典的解法（热图回归）**一次讲透，并亲手实现一个能跑出真实定位误差的小 demo。

> 📖 **术语**：**关键点（keypoint）/ 地标（landmark）**。物体上预先定义好、有语义的一些点，每个点有固定的"身份"（比如"左眼""右膝"）。关键点检测既要**找到**这些点，又要保证**身份不错位**（左膝不能标成右膝）。

## 原理一：为什么不直接回归坐标？

最朴素的想法是：让网络最后接一个全连接层，直接吐出 \\( 2K \\) 个数——\\( (x_1, y_1, x_2, y_2, \dots) \\)，就是每个关键点的像素坐标。这叫**直接坐标回归（coordinate regression）**。听起来最省事，但实践中它往往**又难训又不准**，原因有三：

- **它把空间信息硬压成几个数。** 卷积网络辛辛苦苦保留下来的"哪里像个膝盖"的**空间结构**，被最后的全连接层一把拍扁成一串数字，位置信息在这一步大量流失。
- **全连接层破坏了平移等变性。** 卷积天生"平移等变"——目标往右移 10 像素，特征图也跟着往右移。但全连接层要为"输出坐标 = 37.5"这种**具体数值**负责，它得为每个可能的位置死记硬背一套权重，泛化很吃力。
- **没有"置信"和"多峰"的概念。** 直接回归只能给一个点，说不出"我有多确定"，更无法表达"这里可能有两个候选"。遮挡、模糊时它只能硬猜一个坐标。

> 📖 **术语**：**平移等变性（translation equivariance）**。输入平移，输出跟着做同样的平移。卷积滤波器在整张图上**共享同一套权重**、滑窗扫描，所以天然平移等变——这正是它擅长"在哪里"这类定位任务的根本原因（[第 37 章](../p07-dl-basics/ch37-cnn.md)）。

## 原理二：热图回归——把"坐标"变成"一张概率图"

热图回归换了个思路：**不让网络说"坐标是 (37, 12)"，而让它为每个关键点画一张和图差不多大的"热力图"，图上哪儿最亮，关键点就在哪儿。**

```text
输入图 48×48        每个关键点一张热图 48×48         解码
┌──────────┐      顶点热图   左下热图   右下热图      argmax→(x,y)
│   /\     │      ┌──────┐  ┌──────┐  ┌──────┐    亚像素精化
│  /  \    │ ───▶ │  ·   │  │      │  │      │ ───▶ 顶点=(24, 8)
│ /____\   │      │      │  │·     │  │     ·│      左下=(13,32)
└──────────┘      └──────┘  └──────┘  └──────┘      右下=(35,32)
  一个三角形       亮点在顶点  亮点在左下 亮点在右下
```

这么做好在哪？**它把"回归一个坐标"变成了"在每个像素上判断：关键点在不在我这儿"**——一个**逐像素**的稠密预测任务。而逐像素预测正是卷积网络的主场（和 [第 49 章](../p10-segmentation/ch49-semantic-seg.md) 的语义分割是近亲）：全程保留空间结构、天然平移等变、还能用"亮度"表达置信度，甚至同时容纳多个峰值。代价是要多花一点显存去输出整张热图，以及最后需要一步**解码**把热图变回坐标——这点代价换来的稳定性，绝对值。

**高斯目标：别用"一个孤零零的亮点"。** 训练时，热图的"标准答案"该长什么样？最直接的是把关键点那一个像素设成 1、其余全 0（one-hot）。但这样**正样本只有 1 个像素、其余 2303 个都是 0**，梯度信号极稀疏，网络很难学，还对 1 像素的标注抖动零容忍。经典做法是把这个点**摊成一个高斯核**——以关键点 \\( (k_x, k_y) \\) 为中心、峰值为 1 的小山包：

\\[ H_k(x, y) = \exp\left(-\frac{(x - k_x)^2 + (y - k_y)^2}{2\sigma^2}\right) \\]

\\( \sigma \\)（本章取 2 像素）控制山包胖瘦。它给了网络一片**平滑、有梯度**的目标：离得越近该越亮，离得远就该暗——学起来顺，也天然容忍标注差个一两像素。

**损失就用 MSE。** 预测热图 \\( \hat{H} \\) 和目标高斯热图 \\( H \\) 逐像素求**均方误差（mean squared error）**：

\\[ L = \frac{1}{N K H W} \sum_{n,k,y,x} \left(\hat{H}_{n,k,y,x} - H_{n,k,y,x}\right)^2 \\]

> ⚠️ **注意**：**关键点热图回归请用 MSE，别用交叉熵。** 交叉熵是给"选一个类别"的分类任务用的（[第 42 章](../p08-classification/ch42-candle-classify.md)）；这里每张热图是一片连续的高斯"亮度场"，要的是"逐像素数值贴近"，MSE 才对味。也别硬套 `binary_cross_entropy_with_logit`——[第 44 章](../p08-classification/ch44-finegrained.md) 已经踩过它数值不稳（logit 一大就 `log(0)→NaN`）的坑。

## 原理三：从热图解码出坐标（argmax + 亚像素）

网络吐出热图后，怎么变回一个坐标？

- **第一步 argmax**：找热图里**最亮的那个像素** \\( (r, c) \\)，它的行列就是关键点的整数坐标。简单可靠，但精度被"像素格子"锁死——最好也就到 ±0.5 像素。
- **第二步亚像素精化（sub-pixel refinement）**：峰值附近的几个像素其实携带了"真正的峰偏哪边"的信息。用一条**抛物线**去拟合峰值和它左右邻居的亮度，抛物线顶点就是亚像素级的峰位。以 x 方向为例，设峰值列 \\( c \\) 处亮度为 \\( m \\)、左右邻居为 \\( l, r \\)，偏移量：

\\[ \delta_x = \frac{l - r}{2(l + r - 2m)} \\]

把 \\( \delta_x \\) 加到 \\( c \\) 上（y 方向同理），就得到亚像素坐标。别小看这一步——本章实测它把平均误差从 **0.488 像素压到 0.370 像素**。

### 合成数据：三角形的三个角就是三个关键点

我们合成 48×48 的图，每张画一个**白色实心三角形**（顶点朝上、随机位置/大小、顶点带小抖动），把它的 **3 个角**当作 3 个关键点：`0=顶点、1=左下角、2=右下角`。这个设计有个妙处——**整个三角形都是亮的，但关键点只在三个角**，逼着网络去学"角"这个**语义位置**，而不是偷懒地"哪儿白就报哪儿"。合成与填充（重心符号法判断像素是否在三角形内）的代码比较朴素，完整版见配套工程。

### 目标高斯热图

按上面的公式，为每张图的每个关键点铺一张以它为中心的高斯核（只在 3σ 邻域内填，省事够用）：

```rust
const IMG: usize = 48;   const K: usize = 3;   const SIGMA: f32 = 2.0;

// 由关键点真值构造目标热图 [N,K,IMG,IMG]：每个关键点一张峰值为 1 的高斯核
fn build_heatmaps(all: &[Kps], dev: &Device) -> Result<Tensor> {
    let n = all.len();
    let mut hm = vec![0f32; n * K * IMG * IMG];
    let two_s2 = 2.0 * SIGMA * SIGMA;
    let rad = (3.0 * SIGMA).ceil() as i32;
    for (ni, kps) in all.iter().enumerate() {
        for (k, kp) in kps.iter().enumerate() {
            let (kx, ky) = (kp[0], kp[1]);
            let (cxi, cyi) = (kx.round() as i32, ky.round() as i32);
            for dy in -rad..=rad { for dx in -rad..=rad {
                let (x, y) = (cxi + dx, cyi + dy);
                if x < 0 || x >= IMG as i32 || y < 0 || y >= IMG as i32 { continue; }
                let r2 = (x as f32 - kx).powi(2) + (y as f32 - ky).powi(2);
                let idx = ((ni * K + k) * IMG + y as usize) * IMG + x as usize;
                hm[idx] = hm[idx].max((-r2 / two_s2).exp());   // 峰值 1 的高斯
            }}
        }
    }
    Tensor::from_vec(hm, (n, K, IMG, IMG), dev)
}
```

### 网络：编码器-解码器，输出 K 张热图

要输出和输入同分辨率的热图，网络得先**降采样**抽语义特征、再**上采样**回原尺寸——这就是 U-Net / 沙漏（hourglass）式的**编码器-解码器**结构（真实的 HRNet、OpenPose 骨干都是这个思路的放大版）。上采样用**最近邻 + 卷积**，最后一个 **1×1 卷积头**把特征映射成 `K` 张热图——**每个关键点一张通道**，这和 [第 46 章](../p09-detection/ch46-yolo-inference.md) 检测头"每格 A 个输出"是同一套 1×1 卷积套路，只是这里输出的是"每个关键点一张空间热图"。

```rust
struct HeatmapNet { enc1: Conv2d, enc2: Conv2d, bott: Conv2d,
                    dec1: Conv2d, dec2: Conv2d, head: Conv2d }
impl HeatmapNet {
    fn load(vb: VarBuilder) -> Result<Self> {
        let c  = Conv2dConfig { padding: 1, ..Default::default() }; // 3x3 保持边长
        let c0 = Conv2dConfig { padding: 0, ..Default::default() }; // 1x1 头
        Ok(Self {
            enc1: conv2d(3, 12, 3, c, vb.pp("enc1"))?,
            enc2: conv2d(12, 24, 3, c, vb.pp("enc2"))?,
            bott: conv2d(24, 24, 3, c, vb.pp("bott"))?,
            dec1: conv2d(24, 12, 3, c, vb.pp("dec1"))?,
            dec2: conv2d(12, 8,  3, c, vb.pp("dec2"))?,
            head: conv2d(8, K, 1, c0, vb.pp("head"))?,   // → [N,K,IMG,IMG]
        })
    }
    fn forward(&self, x: &Tensor) -> Result<Tensor> {
        let x = self.enc1.forward(x)?.relu()?.max_pool2d(2)?;      // 48 → 24
        let x = self.enc2.forward(&x)?.relu()?.max_pool2d(2)?;     // 24 → 12
        let x = self.bott.forward(&x)?.relu()?;                    // 12（瓶颈）
        let x = x.upsample_nearest2d(IMG / 2, IMG / 2)?;           // 12 → 24 上采样
        let x = self.dec1.forward(&x)?.relu()?;                    // 24
        let x = x.upsample_nearest2d(IMG, IMG)?;                   // 24 → 48
        let x = self.dec2.forward(&x)?.relu()?;                    // 48
        self.head.forward(&x)   // [N,K,48,48]，每个关键点一张热图
    }
}
```

### 训练：MSE 逼近高斯热图

训练循环干净利落——前向出预测热图，和目标高斯热图求 MSE，反向一步更新（`AdamW`、确定性初始化 `det_init` 等沿用 [第 46 章](../p09-detection/ch46-yolo-inference.md)，因为 candle 0.11 的 CPU 后端不能 `set_seed`）：

```rust
let mut opt = AdamW::new(vm.all_vars(), ParamsAdamW { lr: 3e-3, ..Default::default() })?;
for epoch in 1..=250 {
    if epoch == 160 { opt.set_learning_rate(5e-4); }               // 后段降 lr，把峰值磨准
    let pred = net.forward(&xtr)?;                                 // [N,K,48,48]

}
```

### 解码 + 评估定位误差

解码就是前面讲的"argmax + 抛物线亚像素"：

```rust
fn decode_peak(hm: &[Vec<f32>], subpixel: bool) -> (f32, f32) {
    // 1) argmax：找最亮像素 (br, bc)
    let (mut br, mut bc, mut bv) = (0usize, 0usize, f32::MIN);
    for r in 0..IMG { for c in 0..IMG {
        if hm[r][c] > bv { bv = hm[r][c]; br = r; bc = c; }
    }}
    let (mut px, mut py) = (bc as f32, br as f32);
    // 2) 抛物线亚像素精化：用左右/上下邻居拟合峰位
    if subpixel {
        if bc >= 1 && bc + 1 < IMG {
            let (l, m, r) = (hm[br][bc - 1], hm[br][bc], hm[br][bc + 1]);
            let d = l + r - 2.0 * m;
            if d.abs() > 1e-6 { px += ((l - r) / (2.0 * d)).clamp(-0.5, 0.5); }
        }
        if br >= 1 && br + 1 < IMG {
            let (u, m, dn) = (hm[br - 1][bc], hm[br][bc], hm[br + 1][bc]);
            let d = u + dn - 2.0 * m;
            if d.abs() > 1e-6 { py += ((u - dn) / (2.0 * d)).clamp(-0.5, 0.5); }
        }
    }
    (px, py)
}
```

在 **64 张全新测试图**（共 192 个关键点）上评估，比较 argmax 和亚像素两种解码的**平均定位误差（预测点到真值点的欧氏像素距离）**，真实输出：

```text
===== 定位误差（64 张全新测试图，共 192 个关键点）=====
  argmax 解码平均误差    = 0.488 像素
  亚像素精化平均误差     = 0.370 像素
  分关键点（亚像素）：顶点 = 0.369,  左下角 = 0.342,  右下角 = 0.398 像素
```

**平均定位误差 0.37 像素**——不到半个像素，三个关键点都定得很准。而且亚像素精化确实把误差从 0.488 进一步压到 0.370（降了约 24%），印证了"多解一步、精度更高"。

配套工程还会存 3 张"预测热图叠加原图"的 PNG（`kp_0.png` 等），长这样（文字示意）：白色三角形上，**三个角各有一团红色热斑**（网络预测的热图），红斑中心叠着**绿色圆圈（真值）**和**黄色十字（亚像素预测）**——三者几乎重合。最直观的一点：**整个三角形都是白的，热斑却只出现在三个角**，说明网络学到的是"角"这个语义，不是"哪儿亮报哪儿"。

## 原理四：PAF——多人场景里，"这只胳膊是谁的"？

上面是"图里只有一个物体"的关键点检测。可现实中一张合影里有 5 个人，热图会告诉你"这儿有 5 个鼻子、10 个肩膀、10 个手肘"——**但哪个肘连哪个肩、又属于哪个人？** 光靠热图答不了。这就是**多人姿态估计**的核心难题：**分组（grouping）**。

OpenPose 给出的经典解法叫 **PAF（部件亲和场，Part Affinity Fields）**：除了给每个关键点出一张热图，**再给每条"肢体"（比如肘→腕）出一个 2D 向量场**——在这条肢体覆盖的像素上，向量都指向肢体的方向。要判断"某个肘"和"某个腕"是不是同一条前臂，就把这两点连成一条线，**沿线把 PAF 向量积分**：如果线上的向量都和"肘→腕"方向一致（积分值高），就判定它俩相连；否则不连。这样自底向上地把散落的关键点**拼装成一个个骨架**，天然支持任意人数。

```text
热图：告诉你所有关键点在哪（但不知谁是谁的）
  鼻○  肩○ ○肩        PAF：每条肢体一个方向向量场
  肘○      ○肘   +    肩→肘 的场里，向量沿上臂方向 →→→
  腕○      ○腕        沿"某肩—某肘"连线积分，高=相连
        │
        ▼  按 PAF 把关键点连成骨架
   拼出第 1 个人、第 2 个人…的完整姿态
```

> ⚠️ **注意（诚实边界）**：**完整的 OpenPose 很大**（多阶段、几十 MB 权重、热图 + PAF 双分支），不是本章一个小 demo 能端到端复现的。这里我们把**热图这一半**用真实代码跑通了，PAF 只讲清思想。下一章 [第 53 章](ch53-human-pose.md) 会亲手把预测出的关键点**连成骨架**画出来，让你看到从"点"到"姿态"的最后一步；至于跑真实的 OpenPose / HRNet / MoveNet，会走 `tract` 加载 ONNX 的务实路线（需自备权重）。

## 常见坑与提示

> 🕳️ **坑**：**热图目标别用 one-hot 单点，要摊成高斯。** 只把一个像素设 1、其余全 0，正样本极稀、梯度几乎全零，网络要么学不动、要么对 1 像素的标注抖动过敏。高斯目标（本章 σ=2）给出平滑可导的"引力场"，训练顺、抗噪强。σ 太小退化回单点，太大则峰不尖、定位变糊——是个要调的超参。

> 🕳️ **坑**：**损失函数选错，白训。** 关键点热图是"连续亮度场"，用 **MSE**；这**不是分类**，别套 `cross_entropy`；也别用数值不稳的 `binary_cross_entropy_with_logit`（[第 44 章](../p08-classification/ch44-finegrained.md) 的教训）。记住：`(pred - target).sqr()?.mean_all()?` 就是你要的那一行。

> 💡 **提示**：**热图分辨率是"精度 vs 开销"的权衡。** 热图越大，argmax 的量化误差越小、定位越准，但显存和算力涨得快。真实系统常让热图是输入的 1/4（如输入 256、热图 64），再靠亚像素精化把量化误差补回来。本章为讲清原理用了和输入同分辨率的热图；工程里请按精度需求选。

> ⚠️ **注意**：**关键点的"身份"必须始终对齐。** 热图第 0 张永远是"顶点"、第 1 张永远是"左下角"……训练目标的通道顺序、解码后的下标、可视化的颜色，全链路的关键点编号必须一致，错一位就"左膝标成右膝"。这和 [第 42 章](../p08-classification/ch42-candle-classify.md) 里"类别索引和标签表要对齐"是同一条纪律。

> 💡 **提示**：**遮挡的关键点怎么办？** 真实数据里关键点常被挡住。通用做法是给每个关键点再配一个**可见性标志**，训练时对不可见的关键点**不计损失**（或单独学一个"可见性"分支）；评估时也要区分"没看见"和"定错了"。本章合成图无遮挡，故从简。

## 本章小结

- **关键点检测**要定位物体上一串有语义、有固定身份的点（膝、肘、眼角、定位孔……），是健身计数、人脸对齐、手势识别等应用的地基。
- **直接回归坐标**会把空间结构拍扁、破坏平移等变、也给不出置信度，又难训又不准；**热图回归**把它变成卷积擅长的**逐像素稠密预测**——每个关键点输出一张热图，稳、准、还能表达置信与多峰。
- 训练目标是**以关键点为中心的高斯核**（别用单点），损失用 **MSE**（别用交叉熵）；解码用 **argmax 找峰 + 抛物线亚像素精化**。
- 我们实测：一个编码器-解码器小网络，MSE 从 0.0055 降到 0.0001，在全新测试图上**平均定位误差 0.37 像素**，亚像素精化比纯 argmax 再降约 24%。
- 多人场景靠 **PAF（部件亲和场）**把散落的关键点按"肢体方向一致性"连成一个个骨架——热图管"在哪"，PAF 管"是谁的"。完整 OpenPose 很大，本章只跑通热图这一半、讲清 PAF 思想。

## 动手练习

1. **调 σ 看变化**：把 `SIGMA` 从 2 改成 1 和 4，重跑训练，观察 MSE 曲线和最终定位误差怎么变——体会高斯太尖（回退单点）和太胖（峰不清）各自的毛病。
2. **关掉亚像素**：把评估里 `decode_peak(..., true)` 改成 `false`，只用 argmax，看误差涨多少——亲手量出"亚像素精化"值多少钱。
3. **加噪声考验**：给测试图叠加高斯噪声（[第 41 章](../p07-dl-basics/ch41-training-tricks.md) 的 `gaussian_noise`），看定位误差上升多少、热斑会不会散开——真实图可没这么干净。
4. **想一想**：如果把三角形换成**正方形**（4 个角、且 4 个角长得几乎一样），热图回归还分得清"左上角"和"右上角"吗？缺了什么线索会导致身份错位？（提示：对称、缺乏方向参照——这正是为什么真实关键点要靠"身体上下文"来区分。）
