# 第 69 章 自编码器与表示学习

> **本章导读**
> - 学完你能：用 **candle**（0.11.0）亲手搭一个**自编码器（autoencoder）**——编码器把图片压进一个几维的"瓶颈"，解码器再从瓶颈把图片还原出来，全程只用 **MSE 重建损失**、不需要任何标签。
> - 你会看到三件真事：① 把 256 个像素压进 **8 个数**再还原，测试集重建 **PSNR = 23.21 dB**；② 把训练好的编码器**冻结**当特征提取器，只用它输出的 8 维向量训一个线性分类器，少样本下 **acc = 85.0%**，反超直接用 256 原始像素的 **75.8%**；③ **去噪自编码器（DAE）**把 PSNR 从 **15.70 dB** 拉到 **22.55 dB**。
> - 搞懂几个贯穿现代视觉的核心概念：**欠完备、瓶颈、重建损失、latent 空间**，以及自编码器和 **PCA、自监督学习**的血缘关系。
> - 代码在本机 `cargo run --release` 实测通过，正文所有数字都是真实运行结果、可复现。

## 场景：一张图，能不能用几个数字"记住"？

想象你要把一大批监控截图存进一个**很小**的数据库，每张图只准存**8 个浮点数**。这可能吗？

听起来像天方夜谭——一张 16×16 的灰度图有 256 个像素，你却只给 8 个数的额度，压缩比 32 倍。但如果这批图片都长得**很有规律**（比如都是"某处有一根竖条 / 横条 / 一个方块"），那么"图里是什么、在哪儿"其实用不了几个数就能说清。**能不能让神经网络自己去发现这套"精简记法"？**

这正是**自编码器**要干的事，而且它有一个诱人的特点：**全程不需要标注**。你不用告诉它"这是竖条""那是方块"，只要求它——**把图压小，再尽量原样还原回来**。为了在这么苛刻的瓶颈下还原得像，网络被逼着去抓住数据里最本质的结构。这种"逼出来的理解"，就是本章的另一个主角：**表示学习（representation learning）**。

> 📖 **术语**：**自编码器（autoencoder，AE）**。一种"自己监督自己"的神经网络：**输入是 \\( x \\)，要求的输出也是 \\( x \\)**（重建自己）。它由两半组成——**编码器（encoder）** 把输入压成一个低维向量，**解码器（decoder）** 再把这个低维向量还原回原图。中间那个低维向量叫 **latent（潜在表示）**。

## 原理：编码器 — 瓶颈 — 解码器

### 一条"先压再还原"的流水线

把自编码器画出来，就是一个中间细、两头粗的"沙漏"：

```text
   输入 x                 latent z              重建 x̂
 [1,16,16]   编码器 f    (8 维瓶颈)   解码器 g   [1,16,16]
   ┌────┐   ────────▶   ┌──┐   ────────▶   ┌────┐
   │图片│  卷积↓池化↓fc  │瓶│   fc↑上采样↑卷积 │重建│
   └────┘               └──┘               └────┘
    256 个数         压到 8 个数            还原成 256 个数
             \_____ 越窄，越逼它学本质 _____/
```

用数学写，编码器是一个函数 \\( z = f_{\theta}(x) \\)，解码器是另一个函数 \\( \hat{x} = g_{\phi}(z) \\)，串起来就是 \\( \hat{x} = g_{\phi}(f_{\theta}(x)) \\)。训练的目标只有一个：**让重建 \\( \hat{x} \\) 尽量接近原图 \\( x \\)**。

### 欠完备与瓶颈：为什么"变窄"才有意义

如果中间那层和输入一样宽（甚至更宽），网络可以偷懒——直接把输入"抄"到输出，什么也没学到。所以关键在于**让瓶颈比输入窄**：

> 📖 **术语**：**欠完备自编码器（undercomplete autoencoder）**。latent 维度**小于**输入维度的自编码器。我们的例子里输入是 256 维（16×16），latent 只有 8 维——**8 < 256，这就是"欠完备"**。因为通道太窄、抄不过去，网络被迫**丢掉噪声与冗余、只保留最能帮助还原的信息**。这个被强行收窄的通道，就叫**瓶颈（bottleneck）**。

一句话：**瓶颈是自编码器的灵魂**。它像一道窄门，逼着数据"卸下所有不必要的行李"才能通过——留下的，正是数据的本质结构。

### 重建损失：为什么用 MSE

"接近"要用一个数来衡量，这个数就是**重建损失（reconstruction loss）**。最常用的是**均方误差（MSE）**——逐像素算差的平方再求平均：

\\[ L_{\text{rec}} = \frac{1}{N}\sum_{i=1}^{N} \| x_i - \hat{x}_i \|^2 \\]

其中 \\( N \\) 是样本数，\\( \| x_i - \hat{x}_i \|^2 \\) 是第 \\( i \\) 张图所有像素误差的平方和。MSE 越小，重建越像。[第 36 章](../p07-dl-basics/ch36-neural-nets.md) 讲 XOR 时我们就用过 MSE，它天生适合这种"输出是连续数值"的回归任务。

> 💡 **提示**：本章**刻意避开** `binary_cross_entropy`。虽然像素值在 \\( [0,1] \\)、理论上也能用交叉熵，但 candle 0.11 里那个实现数值不稳定（见 [第 44 章](../p08-classification/ch44-finegrained.md) 踩过的坑）。**MSE 简单、稳、够用**，是重建类任务的稳妥默认。

### latent 空间，以及它的两个近亲

训练好之后，那 8 维的 latent 不是一堆乱码——**相似的图片会被编码到相近的位置**，整个 8 维空间被组织成了一张"图片的地图"。这张图叫 **latent 空间（潜在空间）**。本章第二步就会验证：在这张地图上，同类形状确实扎堆，以至于**一条直线就能把它们分开**。

自编码器不是凭空冒出来的，它有两个你可能已经听过的近亲：

- **PCA（主成分分析）**：如果把编码器、解码器都退化成**没有非线性激活的单层线性变换**，那么 MSE 训练出来的自编码器**张成的子空间和 PCA 完全一致**——PCA 就是"线性版自编码器"。我们的网络加了卷积和 ReLU 非线性，所以能学到 PCA 学不到的**弯曲**结构，这也是它更强的地方。
- **自监督学习（self-supervised learning）**：自编码器"用数据自己当标签"的思路，正是当今**自监督**大潮的鼻祖之一。今天的 MAE（掩码自编码器）、对比学习等，本质都在做同一件事：**不靠人工标注，从海量数据里先学一个好用的表示，再拿去做下游任务**。这正是我们第二步要演示的。

## 动手：训练自编码器 + 表示学习 + 去噪

> ⚠️ **注意**：本章代码基于 **candle 0.11.0**，纯 CPU。完整独立工程见 `code/dl_labs/ch69_autoencoder/`，**`cd` 进去 `cargo run --release`** 一键复现（首次编译 candle 较久）。`Cargo.toml` 依赖 `candle-core`、`candle-nn`、`image`，并加一行空的 `[workspace]` 让它独立于本书主工程。

数据仍是本书的老朋友——合成的**竖条 / 横条 / 方块**，这次是 16×16 灰度、像素值在 \\( [0,1] \\)、位置随机。随机数发生器 `Lcg` 与确定性初始化 `det_init` 沿用 [第 42 章](../p08-classification/ch42-candle-classify.md) 的写法（candle 0.11 的 CPU 后端不能 `set_seed`，随机性得自己掌控），此处不再重复。

### 第一步：搭编码器与解码器

编码器就是一个"缩小版 CNN"：两层卷积 + 池化把图越缩越小，最后用一个全连接压到 8 维。

```rust
const SZ: usize = 16;      // 图像边长
const LATENT: usize = 8;   // 瓶颈维度：远小于 256 像素 → 强迫压缩

struct Encoder { conv1: Conv2d, conv2: Conv2d, fc: Linear }
impl Encoder {
    fn load(vb: VarBuilder) -> Result<Self> {
        let cfg = Conv2dConfig { padding: 1, ..Default::default() }; // padding=1 → 卷积不改变边长
        Ok(Self {
            conv1: conv2d(1, 8, 3, cfg, vb.pp("conv1"))?,   // 1→8 通道
            conv2: conv2d(8, 16, 3, cfg, vb.pp("conv2"))?,  // 8→16 通道
            fc: linear(16 * 4 * 4, LATENT, vb.pp("fc"))?,   // 256 → 8（瓶颈）
        })
    }
    fn forward(&self, x: &Tensor) -> Result<Tensor> {
        let x = self.conv1.forward(x)?.relu()?; // [N,1,16,16]→[N,8,16,16]
        let x = x.max_pool2d(2)?;               // →[N,8,8,8]
        let x = self.conv2.forward(&x)?.relu()?;// →[N,16,8,8]
        let x = x.max_pool2d(2)?;               // →[N,16,4,4]
        let x = x.flatten_from(1)?;             // →[N,256]
        self.fc.forward(&x)                     // →[N,8]（latent，不加激活）
    }
}
```

解码器要干**相反**的事：从 8 维还原回 16×16。这里有个绕不开的问题——编码器用池化"缩小"，解码器怎么"放大"？

> 🕳️ **坑**：**candle 0.11 没有现成的转置卷积（`ConvTranspose2d`）算子**做上采样。务实的替代是**"最近邻上采样 + 普通卷积"**：先用 `upsample_nearest2d` 把特征图"生硬地放大"（每个像素复制成 2×2），再用一层卷积把放大后的马赛克"抹平、修饰"。效果和转置卷积相近，实现却简单得多。

```rust
struct Decoder { fc: Linear, conv1: Conv2d, conv2: Conv2d }
impl Decoder {
    fn forward(&self, z: &Tensor) -> Result<Tensor> {
        let n = z.dim(0)?;
        let x = self.fc.forward(z)?.relu()?;    // [N,8]→[N,256]
        let x = x.reshape((n, 16, 4, 4))?;      // →[N,16,4,4]
        let x = x.upsample_nearest2d(8, 8)?;    // 最近邻上采样 →[N,16,8,8]
        let x = self.conv1.forward(&x)?.relu()?;// 卷积修饰 →[N,8,8,8]
        let x = x.upsample_nearest2d(SZ, SZ)?;  // 再上采样 →[N,8,16,16]
        let x = self.conv2.forward(&x)?;        // →[N,1,16,16]
        sigmoid(&x)                             // 压到 [0,1]，与目标图同域
    }
}
```

末尾的 `sigmoid` 把输出压进 \\( [0,1] \\)，正好和输入图片的值域对齐——这样 MSE 才算得干净。把两半拼起来就是完整的自编码器，`forward` 就是"编码再解码"：

```rust
struct AutoEncoder { enc: Encoder, dec: Decoder }
impl AutoEncoder {
    fn load(vb: VarBuilder) -> Result<Self> {
        Ok(Self { enc: Encoder::load(vb.pp("enc"))?, dec: Decoder::load(vb.pp("dec"))? })
    }
    fn forward(&self, x: &Tensor) -> Result<Tensor> { self.dec.forward(&self.enc.forward(x)?) }
}
```

注意 `vb.pp("enc")` / `vb.pp("dec")` 这两个前缀——它让权重在 safetensors 文件里的键名变成 `enc.conv1.weight`、`dec.fc.weight` 这样清清楚楚的层级结构。**这一步是第二步"只加载编码器、丢掉解码器"的关键伏笔**（回想 [第 43 章](../p08-classification/ch43-finetune.md) 冻结骨干的套路）。

### 第二步：训练——目标就是输入自己

训练循环和普通 CNN 几乎一样，唯一的不同是**损失里的"标签"就是输入图片本身**：

```rust
let ae = AutoEncoder::load(vb)?;
det_init(&vm, 42)?;
let mut opt = AdamW::new(vm.all_vars(), ParamsAdamW { lr: 1e-3, ..Default::default() })?;
for epoch in 1..=400 {
    let recon = ae.forward(&xtr)?;                  // 前向：编码→瓶颈→解码
    let loss = (&recon - &xtr)?.sqr()?.mean_all()?; // MSE 重建损失：目标就是输入 xtr 自己！
    opt.backward_step(&loss)?;                       // 反向 + 更新，一行搞定
    if epoch % 50 == 0 { println!("  epoch {epoch:>3}  重建 MSE = {:.5}", loss.to_scalar::<f32>()?); }
}
```

`(&recon - &xtr)?.sqr()?.mean_all()?` 就是上面那条 MSE 公式的直译：预测减目标、平方、求平均。跑起来，loss 一路下降：

```text
==== 1) 欠完备自编码器：16x16 灰度 → 瓶颈 8 维 → 重建（MSE 损失） ====
  epoch  50  重建 MSE = 0.13499
  epoch 100  重建 MSE = 0.04677
  epoch 150  重建 MSE = 0.00771
  epoch 200  重建 MSE = 0.00498
  epoch 300  重建 MSE = 0.00340
  epoch 400  重建 MSE = 0.00294
  测试集重建：MSE = 0.00477，PSNR = 23.21 dB（把 256 个像素压进 8 个数再还原）
```

**测试集 PSNR = 23.21 dB**——把 256 个像素狠狠压进 8 个数、再还原，居然还能有这个质量。存下来的对照图 `out_ch69_ae_recon.png`（每行左=原图、右=重建）里，竖条、横条、方块都清晰可辨，只是边缘**略带模糊**。

> 💡 **提示**：**为什么重建总是有点糊？** 这是 MSE 的"性格"。当网络吃不准边缘到底在哪一列时，MSE 让它选择"取平均、抹一层灰"最省损失——于是锐利的边被磨圆。这也是后面 [第 70 章](ch70-gan.md) GAN 出场的动机之一：用对抗损失代替 MSE，能逼出更锐利、更真实的细节。

### 第三步：表示学习——冻结编码器，只训一个线性分类器

重建只是"表面功夫"。自编码器真正值钱的地方在于：**训练过程中，编码器被逼着学会了怎么"看懂"这些图**。我们来验证这一点——把编码器**冻结**，只拿它吐出的 8 维 latent 当特征，训一个**最简单的线性分类器**，看能不能分对类。

冻结的手法和 [第 43 章](../p08-classification/ch43-finetune.md) 一模一样：用 `from_mmaped_safetensors` 加载进来的是**常量张量（不是 `Var`）**，天生不参与梯度更新；文件里多余的 `dec.*` 键会被**静默忽略**——正好"只要编码器、丢掉解码器"。

```rust
// 读进来是常量张量 → 天然冻结；文件里 dec.* 键被静默忽略
let vb = unsafe { VarBuilder::from_mmaped_safetensors(&["ae.safetensors"], DType::F32, dev)? };
let enc = Encoder::load(vb.pp("enc"))?;
// 用冻结编码器把图片压成 8 维特征（只算一次；编码器是常量，不产生梯度）
let ztr = enc.forward(&xtr)?; // [24,8]  ← 24 张有标签图（少样本！）
let zte = enc.forward(&xte)?; // [120,8]
// 在这 8 维特征上训一个线性分类器（只有它是可训练的 Var）
let acc_lat = train_linear_probe(&ztr, &ytr, &zte, &teo, LATENT, dev, "latent 8 维")?;
```

为了让对比更有说服力，我们**故意只给很少的标注**（每类 8 张，共 24 张），再拿两组特征各训一个同样的线性分类器：一组是 8 维 latent，一组是直接摊平的 256 个原始像素。结果：

```text
==== 2) 表示学习：冻结编码器，用 8 维 latent 训练线性分类器（少样本，每类 8 张） ====
  [latent 8 维  ] 线性分类器测试 acc = 85.0%
  [raw 256 像素  ] 线性分类器测试 acc = 75.8%
  → 无监督学到的 8 维表示 acc=85.0%  vs  256 原始像素 acc=75.8%（少样本下低维表示更抗过拟合）
```

**8 维 latent 反超 256 原始像素（85.0% vs 75.8%）**。这背后是两件事叠加：① 编码器**没看过一个标签**，纯靠重建就把图组织成了"同类扎堆"的 latent 空间，所以一条直线就能分得不错；② 少样本下，256 维原始像素的分类器**参数太多、容易过拟合**那 24 张训练图，而 8 维特征清爽、反而更稳。**这就是表示学习的价值：先无监督学一个好表示，下游任务用很少的标注就能做好。**

### 第四步：去噪自编码器（DAE）

最后一个变体，能戳破一个常见误解——"自编码器会不会只是把图**背下来**了？" 答案是否定的，**去噪自编码器（denoising autoencoder，DAE）** 就是证据。

DAE 只改一处：**输入是加了噪声的脏图，但要求还原的目标是干净图**。

```rust
let recon = ae.forward(&xin)?;                   // xin = 加噪输入
let loss = (&recon - &xtar)?.sqr()?.mean_all()?; // 关键：目标 xtar 是干净图，不是带噪输入！
```

如果网络只会死记输入，那面对满是噪声的脏图它就该输出脏图。可实测它输出的是**干净**的形状：

```text
==== 3) 去噪自编码器（DAE）：输入=加噪图，目标=干净图 ====
  去噪前 PSNR(噪声图 vs 干净) = 15.70 dB
  去噪后 PSNR(DAE输出 vs 干净) = 22.55 dB   （提升 6.84 dB）
```

对照图 `out_ch69_dae.png`（左=噪声输入，中=DAE 输出，右=干净目标）里，左列几乎被雪花淹没的形状，到中列又变回了清爽的竖条/横条/方块。**PSNR 提升 6.84 dB**，证明 DAE 学到的是"竖条长什么样"这种**结构**，而不是某张图的像素。这也顺带做了一件有用的活儿——**去噪**，这正是下一章 [第 72 章](ch72-superres-style.md) 的主题之一。

> 📖 **术语**：**PSNR（峰值信噪比，Peak Signal-to-Noise Ratio）**。衡量两张图有多像的常用指标，单位分贝（dB），**越大越像**。像素值域为 \\( [0,1] \\) 时 \\( \text{PSNR} = -10\log_{10}(\text{MSE}) \\)。本章的 PSNR 是我们纯手写算的（见配套代码），[第 72 章](ch72-superres-style.md) 会把它用足。

## 常见坑与提示

> 🕳️ **坑**：**瓶颈开太大，等于没训。** 如果把 `LATENT` 从 8 调到 256（和输入一样宽），网络会轻松把输入"抄"到输出，重建 MSE 逼近 0——**看着完美，其实什么表示都没学到**，第二步的线性探针会原形毕露。瓶颈**必须比输入窄**，"欠完备"这三个字是自编码器的命根子。

> ⚠️ **注意**：**输入值域要和输出激活对齐。** 解码器末尾用了 `sigmoid`，输出被压在 \\( [0,1] \\)；所以喂进去的图片、以及算 MSE 的目标，也都得在 \\( [0,1] \\)。本章直接用 \\( [0,1] \\) 的原始像素，**没做** [第 42 章](../p08-classification/ch42-candle-classify.md) 那种映射到 \\( [-1,1] \\) 的标准化——否则目标在 \\( [-1,1] \\)、输出却卡在 \\( [0,1] \\)，MSE 永远降不下去。

> 🕳️ **坑**：**上采样别忘了后面那层卷积。** `upsample_nearest2d` 单独用会产生明显的"马赛克块"（每 2×2 一模一样）。**上采样负责放大、卷积负责抹平**，两者要配对出现。只上采样不卷积，重建会是一格一格的色块。

> 💡 **提示**：**重建糊 ≠ 训练失败。** 前面说过，MSE 天生偏爱"平均、模糊"的解。想要更锐利的重建，方向有二：换**对抗损失**（[第 70 章](ch70-gan.md) 的 GAN）或**感知损失**，或者干脆接受"AE 主打的是压缩与表示、不是出片质量"这个定位。

## 本章小结

- **自编码器 = 编码器（压）+ 瓶颈（latent）+ 解码器（还原）**，用**输入自己当标签**、靠 **MSE 重建损失**训练，**不需要任何标注**。
- **欠完备**（latent 维度 < 输入维度）是灵魂：窄瓶颈逼网络丢冗余、留本质。我们把 256 像素压进 8 维再还原，测试 **PSNR = 23.21 dB**。
- **表示学习**：冻结训练好的编码器当特征提取器，8 维 latent + 线性分类器在少样本下 **85.0%**，反超 256 原始像素的 **75.8%**——无监督学到的表示，下游任务用极少标注就能做好。
- **去噪自编码器（DAE）**：输入加噪、目标干净，PSNR **15.70 → 22.55 dB**，证明 AE 学的是**结构**而非死记像素。
- 血缘：**线性 AE ≈ PCA**；"自己监督自己"的思路是当今**自监督学习**的先声。

## 动手练习

1. **调瓶颈看权衡**：把 `LATENT` 依次设成 2、4、8、16、32，各跑一遍，记录测试重建 PSNR 与第二步的线性探针准确率。你会看到一条"压得越狠、重建越差，但太宽表示反而没学好"的权衡曲线——找出这批数据的"甜点"维度。
2. **画出 latent 地图**：把测试图的 8 维 latent 取出来，用降维（如取前两维或做一次 PCA）按真实类别涂色画散点图，亲眼看看"同类是否扎堆"。（提示：`enc.forward(&xte)?.to_vec2::<f32>()?` 拿到 `[N,8]`。）
3. **DAE 抗噪极限**：把 DAE 的噪声强度 `SIGMA` 从 0.4 一路加到 0.8，看 PSNR 提升在什么噪声水平下开始崩——体会"结构先验"能扛多少噪声。
4. **想一想**：第二步里，如果编码器**不是**用重建预训练、而是随机初始化后直接冻结，线性探针的准确率会怎样？（先猜，再把 `from_mmaped_safetensors` 换成随机初始化跑一次验证。）这能帮你理解"表示到底是训练带来的，还是网络结构自带的"。
