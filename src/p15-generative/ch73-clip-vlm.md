## 场景：能不能"用一句话，搜出对应的图"？

你手机相册里几千张照片，想找"**海边的日落**"，可你从没给照片标过"日落"这个词，怎么办？再想一个更狠的：给一个**训练时从没见过的新类别**（比如"羊驼"），模型能不能只凭"a photo of an alpaca"这句话，就在一堆图里把羊驼挑出来？传统分类器做不到——它的输出层只有训练时定死的那几个类别，加一个新类就得重训。

**CLIP（Contrastive Language-Image Pre-training，对比式语言-图像预训练）** 正是为这两件事而生。它的核心能力叫**零样本分类（zero-shot classification）**：不为具体任务训练分类头，而是**用文本提示当分类器**。它怎么做到的？往下看。

> 📖 **术语**：**多模态（multimodal）** 指模型同时处理**不止一种信息形态**——这里是**图像 + 文本**。**嵌入空间（embedding space）** 是把不同东西都映射成的那个统一的向量空间；只要图和文落进**同一个**空间，就能直接算它们"像不像"。

## 原理：两个"翻译官"，把图和文翻译成同一种向量语言

### 直觉：图像塔 + 文本塔 + 一把尺子

想象两个翻译官：一个只懂**图像**，一个只懂**文本**。CLIP 让他们把各自的输入都翻译成**同一种"向量语言"**（比如 32 维向量）。训练目标只有一句话：

> **配对的（图, 文）要翻译到相近的地方；不配对的要离得远。**

- **图像编码器（image encoder）**：一个小 **CNN**，吃图像、吐一个 \\( D \\) 维向量 \\( \mathbf{v} \\)。
- **文本编码器（text encoder）**：一张**词向量表** + **均值池化** + 一个线性投影，吃一串词的编号、吐一个 \\( D \\) 维向量 \\( \mathbf{t} \\)。
- 两个向量都做 **L2 归一化**（除以自己的长度），这样两者点积就正好是**余弦相似度**——只看方向、不看长短。这套"归一化 + 余弦"你在 [第 57 章](../p12-face/ch57-face-recognition.md) 的 ArcFace 度量学习里已经见过，是一脉相承的思路。

```text
   图像 ──▶ 图像编码器(小CNN) ──▶ v ──L2──▶ v̂ ┐
                                              ├─▶ 余弦相似度矩阵 S (N×N) ─▶ InfoNCE 对比损失
   文本 ──▶ 文本编码器(词表+池化) ─▶ t ──L2──▶ t̂ ┘
```

### 对比损失 InfoNCE：把配对拉近、不配对推开

一个 batch 里有 \\( N \\) 对 \\( (\text{图}_i, \text{文}_i) \\)。把所有图向量和所有文向量两两算余弦相似度，得到一个 \\( N \times N \\) 的矩阵 \\( S \\)，其中 \\( s_{ij} = \hat{\mathbf{v}}_i \cdot \hat{\mathbf{t}}_j \\)：

```text
        文0   文1   文2  ...
  图0 [  ✓                 ]   对角线 s_ii = 配对(正样本) → 要最大
  图1 [        ✓           ]   其余   s_ij = 不配对(负样本) → 要小
  图2 [              ✓      ]
```

我们希望**每一行的最大值都落在对角线上**（图 \\( i \\) 最像文 \\( i \\)）。这不就是个**分类问题**吗——第 \\( i \\) 行是一条"logits"，正确答案是第 \\( i \\) 列。于是用**交叉熵**：先按温度 \\( \tau \\) 缩放，再对每一行做 softmax + 交叉熵。这就是大名鼎鼎的 **InfoNCE** 损失（图→文方向）：

\\[ L_{\text{i2t}} = -\frac{1}{N}\sum_{i=1}^{N}\log\frac{\exp(s_{ii}/\tau)}{\sum_{j=1}^{N}\exp(s_{ij}/\tau)} \\]

图和文是对称的，所以再算一遍**文→图**方向（对 \\( S \\) 的转置做同样的事），两者平均即最终损失：

\\[ L = \tfrac{1}{2}\left(L_{\text{i2t}} + L_{\text{t2i}}\right) \\]

温度 \\( \tau \\) 控制 softmax 的"尖锐度"：\\( \tau \\) 越小、\\( 1/\tau \\) 越大，softmax 越尖，越逼模型把配对项拉得远高于其他项。

> 📖 **术语**：**对比学习（contrastive learning）**。不直接预测标签，而是学一个"什么和什么该像、什么和什么该不像"的空间。**InfoNCE** 是它最常用的损失：把"正样本 vs 一堆负样本"变成一个 softmax 分类。CLIP 的妙处在于——**负样本就是同 batch 里的其他图文对**，白捡的、不用额外标注。

### 零样本分类：让文本当分类器

训练完，图和文在同一空间里对齐好了。要给一张图分类到 \\( C \\) 个类别之一，只需：为每个类别写一句**文本提示（prompt）**（如 "a photo of a {类别}"），把 \\( C \\) 句话都编码成文本向量，再看图向量**离哪句话最近**：

\\[ \hat{y} = \arg\max_{c}\ \hat{\mathbf{v}} \cdot \hat{\mathbf{t}}_c \\]

**没有训练任何分类头**——分类器是"临时用文本拼出来的"。想加新类别？再写一句话就行。这就是零样本的魔法。

### 数据：9 类"带颜色的形状" + 手建词表

词表只有 10 个词，描述是"a photo of <颜色> <形状>"这 5 个 token。运行会先存一张数据集缩略图 `out_ch73_dataset.png`（行=红/绿/蓝，列=竖条/横条/方块），一眼看清 9 类 (图, 文) 配对长什么样：

```rust
// 词表：0<pad> 1 a 2 photo 3 of 4 red 5 green 6 blue 7 vertical 8 horizontal 9 square
const COLOR_TOK: [u32; 3] = [4, 5, 6];   // red / green / blue
const SHAPE_TOK: [u32; 3] = [7, 8, 9];   // vertical / horizontal / square

// class = color*3 + shape，共 9 类；黑底上画一个带颜色的形状（CHW，值域[0,1]）
fn draw(class: usize, rng: &mut Lcg) -> Vec<f32> {
    let (color, shape) = (class / 3, class % 3);
    let mut g = vec![0f32; 3 * IMG * IMG];
    let ch = color * IMG * IMG;            // 颜色 → 对应的 R/G/B 通道
    let val = 0.85 + rng.unit() * 0.15;    // 轻微亮度抖动
    let mut set = |x: usize, y: usize| { g[ch + y * IMG + x] = val; };
    match shape {                          // 0 竖条 / 1 横条 / 2 方块，位置随机
        0 => { let x0 = rng.range(IMG - 4); for y in 0..IMG { for x in x0..x0+4 { set(x,y); } } }
        1 => { let y0 = rng.range(IMG - 4); for x in 0..IMG { for y in y0..y0+4 { set(x,y); } } }
        _ => { let (x0,y0)=(rng.range(IMG-8),rng.range(IMG-8)); for y in y0..y0+8 { for x in x0..x0+8 { set(x,y); } } }
    }
    g
}
// class → 文本提示 "a photo of <color> <shape>"
fn prompt(class: usize) -> [u32; L] { [1, 2, 3, COLOR_TOK[class/3], SHAPE_TOK[class%3]] }
```

### 两个编码器：小 CNN + 词表池化

```rust
// 图像编码器：小 CNN → D 维
struct ImageEncoder { c1: Conv2d, c2: Conv2d, fc: Linear }
impl ImageEncoder {
    fn forward(&self, x: &Tensor) -> Result<Tensor> {
        let h = self.c1.forward(x)?.relu()?.avg_pool2d(2)?;   // 16x16 → 8x8
        let h = self.c2.forward(&h)?.relu()?.avg_pool2d(2)?;  // 8x8 → 4x4
        self.fc.forward(&h.flatten_from(1)?)                  // [N, D]
    }
}

// 文本编码器：词向量表 + 均值池化 + 线性投影 → D 维
struct TextEncoder { emb: Tensor, fc: Linear }   // emb: 可训练词表 [VOCAB, E]
impl TextEncoder {
    fn forward(&self, tokens: &Tensor) -> Result<Tensor> {
        let (n, l) = tokens.dims2()?;
        let flat = tokens.reshape((n * l,))?;               // [N*L]
        let looked = self.emb.index_select(&flat, 0)?;      // 查表：[N*L, E]（可微！）
        let pooled = looked.reshape((n, l, E))?.mean(1)?;   // 均值池化 → [N, E]
        self.fc.forward(&pooled)                            // [N, D]
    }
}
```

文本编码器里没有用现成的 `Embedding` 层，而是把词表建成一个可训练张量，用 **`index_select` 手动查表**——它对词表**可微**，梯度会正常回流（本章训练能收敛就是证明）。这是纯 candle 实现词嵌入的最透明写法。

### L2 归一化 + 对称 InfoNCE

```rust
// L2 归一化（加小 eps 防除零）：归一化后点积 = 余弦相似度
fn l2n(x: &Tensor) -> Result<Tensor> {
    let denom = x.sqr()?.sum_keepdim(D::Minus1)?.affine(1.0, 1e-12)?.sqrt()?;
    x.broadcast_div(&denom)
}

// 对称 InfoNCE：相似度矩阵按 1/τ 缩放，对角线下标作 target 做交叉熵
fn clip_loss(img_emb: &Tensor, txt_emb: &Tensor, dev: &Device) -> Result<Tensor> {
    let n = img_emb.dim(0)?;
    let logits = img_emb.matmul(&txt_emb.t()?)?.affine(INV_TEMP, 0.0)?;  // [N,N] 相似度/τ
    let target = Tensor::arange(0u32, n as u32, dev)?;                   // 对角线下标（U32！）
    let li = cross_entropy(&logits, &target)?;                          // 图→文
    let lt = cross_entropy(&logits.t()?.contiguous()?, &target)?;       // 文→图（转置后要 contiguous）
    (&li + &lt)?.affine(0.5, 0.0)                                        // 对称平均
}
```

### 训练循环：一个关键的 batch 构造技巧

InfoNCE 把"同 batch 里的其他文本"当负样本，这就要求 **batch 内的文本互不相同**——否则两张同类图配的是**同一句文本**，对角线之外还藏着"正确答案"，损失信号就自相矛盾了。我们的词表只有 9 种描述，怎么办？**每步各类只取一张图**，凑成一个大小为 9（或留出后为 6）的 batch，天然保证 9 句文本各不相同：

```rust
let mut opt = AdamW::new(vm.all_vars(), ParamsAdamW { lr: 3e-3, ..Default::default() })?;
for step in 1..=steps {
    let (x, t) = make_batch(classes, &mut rng, dev)?;   // 每类一张图 + 它的文本
    let ie = l2n(&img_enc.forward(&x)?)?;               // [B, D] 归一化图向量
    let te = l2n(&txt_enc.forward(&t)?)?;               // [B, D] 归一化文向量
    let loss = clip_loss(&ie, &te, dev)?;
    opt.backward_step(&loss)?;
}
```

训练后，对测试图编码，对 9 类文本提示编码，取最近者作预测：

## 进阶实验：组合零样本泛化——它能认出"没见过的搭配"吗？

CLIP 最惊艳的地方，是能推广到**训练时从没出现过的图文配对**。我们做个消融：把 3 个组合（红竖条、绿横条、蓝方块）**整个抽走**，只用剩下 6 个组合训练，再看模型能否零样本认出这 3 个"新搭配"。注意——这 3 个组合的**颜色和形状都在别的训练组合里单独出现过**（比如"红"在红横条/红方块里见过，"竖条"在绿竖条/蓝竖条里见过），只是它俩的**这个组合**从未配对训练。

```text
==== 实验 B：组合零样本泛化（留出 3 个组合不参与对比训练）====
  训练组合：红横条 红方块 绿竖条 绿方块 蓝竖条 蓝横条
  留出组合：红竖条 绿横条 蓝方块
  已见组合零样本准确率 = 120/120 = 100.0%
  留出组合零样本准确率 = 33/60 = 55.0%（模型从未见过这些图文配对！）
    └─ 拆开看：颜色认对 60/60 = 100.0%，形状认对 33/60 = 55.0%
    [红竖条] 预测→ 红竖条×10 红横条×5 红方块×5
    [绿横条] 预测→ 绿横条×10 绿方块×10
    [蓝方块] 预测→ 蓝横条×7 蓝方块×13
```

这个结果**特别有教育意义**，值得逐条读：

- **留出组合能猜对 55%，远高于随机的 11.1%**——组合泛化**确实涌现了**。模型没死记硬背"图=类别"，而是学到了"颜色"和"形状"这些**可复用的概念**。
- **拆开看更清楚：颜色 100% 认对，形状只有 55% 认对。** 看混淆分布——"红竖条"永远被认成**红**色的某个形状，"蓝方块"永远是**蓝**色的某个形状，**颜色从不出错**。因为每种颜色都和多个形状配对过，"颜色"这个概念被充分学透、完美迁移；而"形状"在遇到没见过的颜色搭配时会打折。
- **它离 100% 还差得远，这恰恰是诚实的一课**：组合泛化会涌现，但不完美——这正是真实 CLIP 研究里的活跃难题（模型认得"红"、认得"竖条"，未必就稳稳认得"红竖条"）。

## 诚实边界：教学版 vs 真正的 CLIP

我们这个 demo 抓住了 CLIP 的**灵魂**（跨模态对比对齐 + 零样本迁移），但和真家伙差着数量级，必须讲清：

> ⚠️ **注意（本章最重要的诚实边界）**：真正的 CLIP（OpenAI, 2021）是：图像塔 = **ViT-B/L**（Vision Transformer）或大 ResNet；文本塔 = **BPE 分词 + 完整 Transformer**；在约 **4 亿**网络图文对上训练。**纯 Rust 从零训练全量 CLIP，CPU 上绝无可能**（光数据和算力就是天文数字）。我们把图像塔换成小 CNN、文本塔换成"词表 + 均值池化"、9 个合成类别代替 4 亿真实图文对——**只为把内核讲通、让每个数字都真跑得出来**。

那要在本书框架里用上**真** CLIP 怎么办？两条务实路线（都不违背"纯 Rust 推理"）：

- **candle 官方 CLIP example**：下载预训练权重（safetensors），用 [第 42 章](../p08-classification/ch42-candle-classify.md) 的 `from_mmaped_safetensors` 套路加载，直接跑真正的零样本分类/图文检索。**纯 Rust，只是权重要联网下载**。
- **tract 加载 ONNX**：把 CLIP 导出成 ONNX，用 tract（纯 Rust、零 C++ 依赖）推理，交叉编译友好。

顺带把**多模态的广度**点一下：图文对齐这一个能力就能撑起一片应用——**图文检索**（本章 recall@1 即其雏形）、**零样本分类**（本章主角）、**开放词表检测/分割**（把文本能力接到 [第 46 章](../p09-detection/ch46-yolo-inference.md) 检测、[第 49 章](../p10-segmentation/ch49-semantic-seg.md) 分割，去找"任意一句话描述的东西"）。再进一步是**看图说话（image captioning）**——让模型**生成**描述句子，这需要一个文本**解码器**（Transformer），是 CLIP 之后 BLIP、LLaVA 等多模态大模型的方向。

## 常见坑与提示

> 🕳️ **坑**：**InfoNCE 的 batch 里不能有重复文本。** 如果同 batch 塞两张同类图，它们配的是同一句话，那么对角线之外就藏着"其实也对"的正样本，损失信号自相矛盾、训练变虚。词表小的时候要么**每类每步只取一张**（本章做法，batch 内文本天然互异），要么给同类样本造出不同描述。真实 CLIP 里每张图配一句独特的网络描述，天然没这问题。

> 🕳️ **坑**：**`cross_entropy` 的 target 必须是 U32，且转置后的 logits 要 `.contiguous()`。** 对角线目标用 `Tensor::arange(0u32, n as u32, dev)?`（写成 `0u32` 才是 U32）。算文→图方向时 `logits.t()?` 得到的是**非连续**张量，`cross_entropy` 内部做 `log_softmax` 需要连续内存，务必接一个 `.contiguous()?`，否则报错或结果错乱。

> ⚠️ **注意**：**温度 \\( \tau \\) 要拿捏。** \\( \tau \\) 太大（\\( 1/\tau \\) 太小），softmax 太平，配对项和负样本拉不开、学不动；\\( \tau \\) 太小，logits 被放得极大，数值容易爆、梯度不稳。本章用固定 \\( 1/\tau = 10 \\)。真 CLIP 把它设成**可学习的 log 温度** `Var` 并 **clamp 上限**（防止爆到无穷），初值约对应 \\( 1/\tau \approx 14 \\)，训练中自动调节到合适锐度。

> 💡 **提示**：**L2 归一化 + 余弦相似度，是跨模态对齐的通用套路。** 你在 [第 57 章](../p12-face/ch57-face-recognition.md) 人脸识别的 ArcFace 里见过同一招——把嵌入归一化到单位球面，用余弦度量远近。CLIP 只是把"人脸 vs 人脸"换成了"图 vs 文"。度量学习的直觉在多模态里完全通用。归一化时记得加个小 eps（本章 `affine(1.0, 1e-12)`）防止零向量除零出 NaN。

> 📖 **术语**：**recall@1（前 1 命中率）**。检索里最常用的指标之一：对每个查询，看**排在第 1 位**的检索结果是否正确，统计正确的比例。本章 9 个查询全部命中即 9/9。还有 recall@5、recall@10 等，放宽到"前 5/前 10 里有没有对的"。

## 本章小结

- **CLIP = 图文对比预训练**：一个**图像编码器** + 一个**文本编码器**，把图和文映射进**同一嵌入空间**；两者都 **L2 归一化**，点积即**余弦相似度**。
- **对比损失 InfoNCE**：把配对的 \\( (\text{图}, \text{文}) \\) 拉近、不配对推开——本质是拿 \\( N \times N \\) 相似度矩阵、**以对角线为正确答案做（对称的）交叉熵**。温度 \\( \tau \\) 控制锐度。
- **零样本分类**是最大回报：**不训分类头**，为每类写句"a photo of a {类别}"当分类器，图向量离哪句近就判哪类。想加新类别，写句话就行。
- 实测数字：对比损失 **2.59 → 0.0027**；零样本分类 **180/180 = 100%**；图↔文检索 **recall@1 = 9/9**；**组合零样本**对没见过的搭配也有 **55%**（颜色 100%、形状 55%），远超随机——组合泛化会涌现，但不完美。
- **诚实边界**：真 CLIP = ViT + BPE + Transformer 文本塔 + 4 亿图文对，纯 Rust 从零全量 CPU 不可能；务实路线 = **candle 官方 CLIP example（下载权重）** 或 **tract 加载 ONNX**。多模态广度：图文检索、零样本分类、开放词表检测/分割、看图说话。

## 动手练习

1. **改温度、看曲线**：把 `INV_TEMP` 从 10 改成 1、5、30，观察对比损失下降速度和最终零样本准确率的变化，体会"太平学不动、太尖不稳定"。
2. **扩词表、加类别**：给形状再加一种（比如"圆点"/"边框"），或给颜色再加"黄"（需要同时点亮两个通道），把类别从 9 扩到 12/16，重训并报新的零样本准确率——batch 也随之变大，负样本更多，通常更好训。
3. **提升组合泛化**：实验 B 里形状只迁移了 55%。试试**每种形状在更多颜色下出现**（比如只留出 1 个组合而不是 3 个），或**加大图像编码器**，看留出组合的"形状认对率"能不能提上去；想想为什么"颜色"那么容易迁移而"形状"难。
4. **可学习温度**：把固定 `INV_TEMP` 换成一个可训练的 log 温度 `Var`（前向时 `exp` 还原、并 `clamp` 上限防爆），加进优化器一起训，打印它训练后收敛到多少——对比固定温度的效果。
5. **（挑战）上真 CLIP**：参考 candle 官方 `examples/clip`，下载预训练权重，对你自己的几张照片跑一次真正的零样本分类（如 "a photo of a cat/dog/car"），感受 4 亿图文对训出来的模型和我们这个 9 类玩具的差距。
