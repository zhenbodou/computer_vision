# 附录 F：从这里到真正的专家（学习路线图）

> **本附录导读**
> - 回头看看：读完这 21 个部分，你到底已经掌握了什么。
> - 给你一条**分五个阶段、可执行、可自测**的成长路线：从巩固基础到给开源生态做贡献。
> - 聊聊技术之外的**软实力**——为什么"会读论文、会复现、会参与社区"才是专家的护城河。
> - 给纯 Rust 视觉方向的**务实建议**：机会在哪、坑在哪，别白走弯路。

还记得前言里那句话吗？我说要像个耐心的师兄，带你把机器视觉这座大山拆成一级一级好走的台阶。现在，你已经从"图像其实就是一堆数字"一路爬到了山腰——回头看看来时的路，是不是有点不敢相信？

但师兄要跟你说句实话：**这本书是地图和登山杖，不是山顶。** 真正的专家不是"读完一本书"就能封神的，而是在读完之后，还能自己找路、自己攀岩、甚至给后来人修路。这一节，就是给你的下山（其实是继续登顶）指南。

## 一、回顾：你已经站在半山腰了

先别急着往前冲，花一分钟盘点一下家底。你学完的这 21 个部分，其实是一条完整的能力链：

- **看懂本质**（第一~五部分）：你知道了图像就是像素矩阵、相机怎么成像，玩转了 `image`/`imageproc` 的读写、颜色、几何、滤波、边缘、形态学、轮廓、霍夫、模板匹配，还掌握了角点、SIFT/ORB 描述子与特征匹配，并用 `ndarray`/`nalgebra` 打好了数值与线代地基。
- **学会"学"**（第六~七部分）：从 `linfa` 的传统机器学习，过渡到神经网络、CNN、经典架构演进，还用 `burn` 从零训了一个 MNIST 网络，摸清了 Rust 的深度学习生态。
- **攻下主峰**（第八~十六部分）：分类、检测、分割、关键点、人脸、跟踪、三维、生成式、视频——机器视觉的主流任务，你都亲手实现过至少一遍。
- **接上地气**（第十七~十八部分）：这是很多教程**根本不讲**、却最值钱的部分——工业测量/缺陷/读码，以及 ROI、绊线、时间窗口、冷却去抖这套把"检测框"变成"业务告警"的事件后处理功夫。
- **搞定交付**（第十九~二十一部分）：ONNX 跨框架推理、模型量化、Web 服务化，一大批实战项目，以及性能优化、GPU、WASM、嵌入式、工程化与 MLOps。

> 💡 **提示**：如果上面有哪一块你读的时候是"跳过去"或"看懂了但没敲代码"的，**别骗自己**。回去把那一章的代码补跑一遍。地基上的一个空洞，往往就是你未来某个项目卡壳的地方。

一句话：**你已经具备了独立完成一个真实机器视觉项目的全部基础能力。** 接下来的问题不是"我还差哪个知识点"，而是"我怎么把这些能力练成肌肉记忆，并长出自己的专精"。

## 二、五个阶段的成长路线

专家不是一天炼成的。下面这五个阶段，建议**顺序推进、不要跳级**。每个阶段我都给了"具体怎么做"和"怎么验证自己到了这一级"。

### 阶段一：把地基夯到"不用查也能写"

**目标**：常用操作形成肌肉记忆，不必每次都翻书。

**怎么做**：把本书第一~五部分的核心操作（读写图像、颜色转换、卷积滤波、边缘检测、阈值、形态学、轮廓、特征匹配）默写一遍——**盖住书，从空白 `main` 开始写到能跑**。写不出来的地方，就是你要重练的。

> ✅ **如何验证**：随手给你一张图，你能在 20 分钟内不查资料地写出"灰度化 → Canny 边缘 → 找轮廓 → 画框"的完整管线并跑通。做到了，恭喜，地基过关。

### 阶段二：独立做出一个完整项目

**目标**：从"跟着敲"升级到"自己攒"，打通"采集 → 处理 → 模型 → 后处理 → 输出"全链路。

**怎么做**：从本书第二十部分的项目里挑一个**改造**它，而不是照抄。比如把"周界入侵报警"（[第 103 章](../p20-projects/ch103-perimeter-intrusion.md)）接上你自己的摄像头，加一个你想要的规则（夜间才布防？特定区域才报警？）。关键是**端到端跑通并交付给一个真实用户**（哪怕用户是你家人）。

> ✅ **如何验证**：你的项目能连续稳定运行几个小时不崩、不误报满屏、能把结果落库或推送。你开始关心"帧率""内存""误报率"这些**工程指标**，而不只是"模型准不准"。

### 阶段三：选一个方向往深里扎

**目标**：从"什么都会一点"变成"某个方向别人会来问你"。

**怎么做**：机器视觉太大，**没人能全精通**。从**检测 / 分割 / 三维 / 生成**里挑一个你最有热情的方向，集中火力半年：把这个方向的经典论文（见 [附录 E](e-resources.md)）按时间线读一遍，把代表模型的推理和微调都跑通，整理成自己的笔记或博客。

> ✅ **如何验证**：你能对着这个方向的一篇新论文，快速说出"它相比前作解决了什么问题、大概怎么做的、有什么局限"。你在这个细分方向的判断，开始值得别人参考。

### 阶段四：读源码、读论文、能复现

**目标**：从"用别人的轮子"到"看懂轮子怎么造、造得好不好"。

**怎么做**：挑一个你天天用的 crate（比如 `imageproc` 的 Canny，或 `tract` 的图优化），**把它的源码读进去**——你会惊讶于"原来书里讲的原理，代码是这么落地的"。再挑一篇你专精方向的论文，**用纯 Rust 复现它的核心算法**（不追求 SOTA 精度，追求"我真的搞懂了每一步"）。

> ✅ **如何验证**：你能给别人讲清一个开源实现里某个"魔法数字/技巧"为什么这么设；你复现的算法，输入输出与论文描述定性一致。到这一步，你已经不是"调包侠"了。

### 阶段五：给开源生态做贡献

**目标**：从"消费者"变成"建设者"——这是专家身份最硬的证明。

**怎么做**：从最小的贡献开始。给 `image-rs`、`rust-cv`、`candle`、`burn`、`tract` 这些项目**提 issue、补文档、写测试、修小 bug**，慢慢到实现一个缺失的算法或 crate。纯 Rust 视觉生态还年轻，**缺口很多，正是你留下名字的好时候**。

> ✅ **如何验证**：你的 PR 被合并了；有人在 issue 里 `@` 你请教；你维护的小 crate 有了第一个陌生人 star。那一刻，社区认你是"自己人"了。

## 三、专家的软实力：技术之外的护城河

同样的算法，为什么有人做出来是"能演示的 demo"，有人做出来是"能卖钱的产品"？差距往往在这些"不写在论文里"的地方：

- **工程化能力**：会写测试（视觉算法尤其要有回归测试图）、会做基准测试（[第 108 章](../p21-mastery/ch108-performance.md)）、会用 `rayon` 并行、懂错误处理与 CI/CD（[第 112 章](../p21-mastery/ch112-engineering.md)）。一个跑得快、崩不了、好维护的系统，比一个"paper 里指标 0.5% 更高"的模型值钱得多。
- **读论文并复现的习惯**：领域每月都在变，教材永远追不上。**把读论文当成日常**，而不是临时抱佛脚。能复现，才说明你真读懂了。
- **参与社区**：逛 `docs.rs`、GitHub issue、Rust 与视觉相关的论坛/Discord。**提问和回答都在让你成长**。你帮别人解一个 bug，常常也补上了自己的盲点。
- **持续跟进**：纯 Rust 视觉/ML 生态**正在快速发展**（本书成书时 `candle`、`burn`、`kornia-rs` 都还在高速迭代）。定期看这些项目的 CHANGELOG 和 release，别让自己的知识停在某个旧版本。

> ⚠️ **注意**：别陷入"教程仓鼠症"——收藏了 100 门课却一门没做完。**做项目 > 看教程**。软实力全是练出来的，不是看出来的。

## 四、给纯 Rust 视觉方向的务实建议

最后，师兄掏心窝子跟你聊聊纯 Rust 做视觉的**真实现状**——既不泼冷水，也不吹泡泡。

**Rust 的强项（放心押注的地方）：**

- **推理与部署是 Rust 的主场**。用 `tract` 能纯 Rust 加载 ONNX 跑推理，零 C/C++ 依赖、交叉编译友好；要极致性能可上 `ort`（接受其 C++ 依赖）。这块生态已经**足够生产可用**（见 [第 94 章](../p19-deploy/ch94-onnx.md)）。
- **边缘、嵌入式、WASM 是 Rust 碾压 Python 的地方**。无 GC、单文件、内存安全、可跑在浏览器（[第 110 章](../p21-mastery/ch110-wasm.md)）和资源受限设备（[第 111 章](../p21-mastery/ch111-embedded.md)）上——这些恰恰是 Python 的软肋，也正是本书第二十一部分反复强调的机会。
- **高性能服务与并发**。`axum` 做视觉 Web 服务、`rayon` 做数据并行，Rust 又快又稳，天生适合把视觉能力做成可靠的后端。

**要清醒避开的坑：**

- 🕳️ **别指望纯 Rust 训练追平 PyTorch 生态。** `burn`/`candle` 能训练、也在快速进步，但预训练模型、教程、社区体量目前仍远不及 PyTorch。**务实的混合工作流**：重活用 PyTorch 训练 → 导出 ONNX / safetensors → **Rust 端负责推理与部署**。扬长避短，别硬刚。
- 🕳️ **别造轮子上瘾。** 遇到需求先在 crates.io 搜有没有现成 crate；成熟的（`image`/`imageproc`/`nalgebra`）就别自己写。真遇到生态缺失（某些三维/SLAM 算法暂无纯 Rust 实现），**诚实评估**：要么自己实现（顺便贡献开源），要么用 ONNX 推理绕过，别假装它不存在。
- 🕳️ **版本漂移会咬人。** DL 相关 crate 迭代快、API 常变（本书 [附录 A](a-crates.md) 和各章都在钉版本、标坑）。**钉住版本号、读 CHANGELOG、以 `docs.rs` 对应版本为准**，能省下你大把 debug 时间。
- 🕳️ **`ort` 不是纯 Rust。** 它底层链接 C++ onnxruntime，交叉编译/静态链接时要额外处理运行库。追求"纯 Rust 单文件交付"时，优先 `tract`。

## 结语：山就在那里，而你已经会爬了

写到这里，这本书就要合上了。

回想前言里那个"对机器视觉四个字还有点发怵"的你，再看看现在——能拆解流水线、能训练模型、能做工业落地、能把它部署到浏览器和边缘设备上的你。这中间隔着的，不是什么天赋，而是你一章一章敲下来的代码、跑过的每一个 example、踩过又爬出来的每一个坑。

师兄能带你的路，到这里就是尽头了。但真正激动人心的部分，恰恰从这里开始：**从今往后，没有标准答案，没有既定台阶，你要面对的是真实世界里那些还没人解决好的问题。** 而纯 Rust 视觉这片天地，正年轻、正缺人、正等着有人来开疆拓土。

那个人，为什么不能是你呢？

去做项目，去读论文，去提你的第一个 PR。等哪天，轮到你在某个 issue 下，耐心地给一个"还有点发怵"的新人写下解答时——**你就已经是当初你仰望的那种大佬了。**

山就在那里。去爬吧。🚀
