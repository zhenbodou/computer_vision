# 附录 J：高级视觉工程师毕业项目与评审

> **本附录导读**
> - 第 97–107 章的小项目用于理解模块；本附录要求把其中一个发展为有真实数据与交付证据的系统。
> - 必须完成下列公共关卡，并在一个方向深入。其他方向完成概念与基础练习，不要求同时达到专业深度。
> - 没有相机时可先用获得使用许可的真实图片、视频离线回放；必须标记“未验证现场采集”，不能据此声称完成现场交付。

## 一、先冻结需求，再选择算法

选题之前写一页需求：谁使用、输入是什么、输出触发什么动作、误报与漏检如何计费、延迟从哪里开始计时、设备资源是多少、哪些情况不支持。以下为教学项目示例，不能当作通用产线标准。

| 路线 | 最低实现范围 | 教学验收线示例 | 必须施加的变化 |
|---|---|---|---|
| 工业质检（78、80、82、102） | 真实表面图→缺陷判定→区域→复检记录；比较传统基线与学习模型 | 缺陷件召回≥95%，正常件误报率≤2%，报告独立件数与区间 | 保留采集批次；另测光照与材质变化 |
| 视频事件（62、75、83–93、103–104） | 真实视频→检测→关联→事件→持久化回放 | 事件 precision、recall 均≥90%；恢复后无旧帧触发的重复事件 | 遮挡、双向穿越、5 秒断流、推送失败 |
| 几何测量（25–26、64–68、78–79、106） | 真实图像→标定/配准→测量→误差报告 | 固定物距与目标范围内，95% 绝对误差≤事先定义的公差预算 | 新姿态、新位置、轻微离焦和标定漂移 |

资源预算必须具体，例如“指定 CPU、640×480、单路、P95 采集至结果≤200 ms、峰值 RSS≤1 GiB”。必须同时满足质量与资源约束，不能换成更快设备后仍和旧方案直接比性能。达不到示例线时保留失败结论，下一轮改进重新评审，不事后降低标准使自己通过。

## 二、关卡 A：把真实数据做成可审计实验

建立 `manifest.csv`，至少包含 `sample_id,path,sha256,group_id,split,label_version,condition`。每个样本只能属于一个集合。`group_id` 对应同一工件、人物、视频或采集批次中可能共享的信息；究竟按什么分组，必须能解释。

1. 先按组划分开发数据与最终保留数据，再在开发组中分 train/val。比例由数据规模决定，不机械套 8:1:1；稀少类必须检查是否有独立组可评估。
2. 图片与其增强版本属于同组；同一视频抽帧也属于同组。归一化统计量、模板、近邻库只从训练部分拟合。
3. 写标注规范，双人独立抽检或隔一段时间复标；记录分歧及修订版本。空图与漏标不是一回事。
4. 每个关键切片报告样本数和漏检数。没有足够样本就写“证据不足”，不得用整体平均补齐。
5. 保存数据来源、使用范围与许可。原始数据不便交付时，提供可运行的脱敏子集和获取完整数据的条件，不伪造可复现性。

**放行证据**：清单检查输出、集合间组交集为空、标注审计记录、切片覆盖表、最终保留数据由评审者保管或封存校验和。

## 三、关卡 B：把教学模型换成能核对的真实模型

加载成功只证明格式能读。外部模型至少需要下面这份契约；不要写“按模型默认值”。

```text
模型：来源地址、不可变版本、文件 SHA-256、许可
结构：模型配置、权重键名、算子或 ONNX opset、后端版本
输入：名称、dtype、NCHW/NHWC、动态维约束、RGB/BGR
预处理：方向处理、resize 算法、实际填充、除数、mean/std
输出：名称、形状、类别表、logits/概率、坐标格式与单位
后处理：置信阈值、NMS 类别策略、IoU 阈值、坐标还原
参考样本：原始输入、预处理张量、原始输出、最终结果
数值要求：绝对/相对误差容限、允许差异的原因
```

先取至少 3 个固定输入：正常目标、纯背景、一个边界场景。在来源实现与 Rust 实现中保存中间结果，依次比较**解码图 → 张量 → 模型原始输出 → 后处理结果**。数值对比条件为 `|a-b|≤atol+rtol×|b|`，容限需根据精度与后端预先设定；不能用扩大容限掩盖 RGB/BGR 颠倒。

如果来源没有参考输出或无法运行原实现，应明确降低验证结论，先建立其他独立参考。遇到不支持的算子，列出失败节点与替代策略，再做一致性验证；不能把“导出成 ONNX”当成兼容所有后端的保证。纯 Rust 主线参见 [第 94 章](../p19-deploy/ch94-onnx.md)，对比来源实现是验证步骤，不要求产品依赖 OpenCV。

**放行证据**：完整契约、3 组逐层对比、错误类别/输入尺寸的可解释报错、与真实数据对应的可视化。仅提供合成形状识别率不通过这一关。

## 四、关卡 C：算法选型与误差归因

至少比较一个低成本基线与一个候选方案，固定数据、硬件、预算和评估协议。先在验证集选择参数，再冻结模型与规则。

| 需要回答 | 必交实验 |
|---|---|
| 为什么不用更简单的方法？ | 传统阈值/模板或已有轻量方案的质量、延迟和维护成本 |
| 改进来自哪里？ | 单因素消融；随机训练使用至少 3 个预先指定种子 |
| 哪些工况最差？ | 每类、目标大小、遮挡、批次/设备切片及失败样本 |
| 是模型错还是链路错？ | 固定张量对拍、真实坐标可视化、用真值替代某一模块的上限实验 |
| 一次高分可信么？ | 按独立组重采样的区间；小样本列明不确定性 |

视频事件评价要先定义同类事件在同一路摄像头、什么时间容差内一对一匹配；重复告警计 FP，未匹配的真实事件计 FN。帧级检测 AP 不能替代事件级评价。几何项目必须报告物理单位、参考量具/真值来源和不确定度，不能以训练图的重投影误差替代测量精度。

## 五、关卡 D：把系统放到压力下

将采集、算法、规则、输出拆成可以单独回放的模块。为每个结果记录输入 ID、时间戳、模型版本、规则版本和错误类型。

必须执行四种故障：输入损坏/尺寸超限、数据源中断、消费者慢于输入、输出端失败。记录故障起止、排队长度、丢弃数、重试次数、恢复时间和内存峰值。失败应进入有边界的处理路径，而不是无限排队或无限重试。

运行至少一次 2 小时教学长稳试验，按分钟记录 RSS、队列长度、吞吐和端到端 P95；这只覆盖该负载与时长，真实现场需要按实际班次与工况延长。预先冻结允许的内存增长与恢复时间，例如暖机后 RSS 增长≤10%、输入恢复后 10 秒内恢复处理。对全部请求计入错误和超时，不能只统计成功请求。

完成一次候选模型上线演练：旧版→影子运行（只记录）→少量输入试运行→人为触发退化→恢复旧版。核对权重、类别表、预处理、阈值和规则一起回滚；只换权重文件不算完整回滚。

## 六、交付目录与评分

```text
submission/
  README.md             # 从干净环境构建、运行、评估的准确命令
  requirements.md       # 输入输出、业务代价、预算、验收线
  data/manifest.csv     # 组划分、版本、校验和；大文件可另存
  model/contract.md     # 模型契约与获取方式
  configs/              # 冻结的实验、模型和规则配置
  reports/              # 基线、消融、切片、失败、压测与故障记录
  predictions/          # 每样本结果，便于独立重算指标
  runbook.md            # 启停、告警解释、排错、恢复与回滚
```

按数据与评估 25 分、算法原理与选型 25 分、实现及性能 25 分、故障恢复与交付 25 分评分。每项按证据完整程度给分，总分至少 80 且每项至少 15 才进入最终评审。以下情况直接退回：测试数据用于调参、无法重算指标、关键切片未达冻结标准却被平均掩盖、合成数据冒充真实数据、无法完成恢复或回滚。

最终由另一人按 README 从干净目录运行，并更换一批未见数据验证；独学者可使用预留批次做初评，但应明确尚未经过独立评审。答辩需回答：最大失败来自哪里？预算减半如何取舍？新相机接入先查什么？哪条证据会让你放弃当前方案？

这些关卡用于证明高级工程能力的关键部分。它们不等同于自动获得职位，也不能替代长期项目责任与团队协作经验；评审结论应指向实际完成的方向、数据与部署范围。
