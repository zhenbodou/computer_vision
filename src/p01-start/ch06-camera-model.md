## 为什么照片里会"近大远小"

拍一条笔直的马路，路两旁的树明明一样高，照片里却越远越小，最后汇聚到地平线上一点。再看：同一个人，凑近镜头脸就变大变形，退远就正常。这些我们习以为常的现象背后，藏着一套精确的几何规律——**相机是如何把三维世界"拍扁"成二维图像的**。

这一章我们就来拆解这套规律。它不仅满足好奇心，更是**三维视觉的地基**：想从照片反推出物体的真实尺寸、距离、三维形状（第十四部分要做的事），就必须先搞懂"正着拍"是怎么回事。

## 从光到数字：一次完整的旅程

一张数字照片的诞生，是这样一条流水线：

```text
真实世界   →   镜头    →    传感器      →   ADC      →  数字图像
 (光线)      (会聚光线)   (感光成电信号)   (模数转换)    (像素矩阵)
              折射          采样            量化
```

- **镜头**把物体反射的光线**会聚**到传感器上（现代镜头由多片透镜组成，作用近似一个"小孔"，下面会讲）。
- **传感器**（CMOS/CCD）表面排布着密密麻麻的感光单元，每个单元把落在自己身上的光转成电信号。这一步在**空间上**把连续的画面切成了一个个格子——这叫**采样（sampling）**，它决定了图像的**分辨率**。
- **ADC（模数转换器）**把每个格子测到的连续电压，四舍五入成一个整数（通常 0–255）。这一步在**强度上**离散化——这叫**量化（quantization）**，它决定了图像的**位深**。

看，[上一章](ch05-what-is-an-image.md)的"分辨率"和"位深"，正好对应这里的"采样"和"量化"两个动作。**采样管空间、量化管强度**，两者合力，把连续的光变成了离散的像素数字。

> 📖 **术语**：彩色是怎么来的？传感器本身只测光的强弱、不分颜色。工程师在感光单元上盖了一层**拜耳滤镜（Bayer filter）**，让每个单元只透过红、绿、蓝之一，再由算法**插值（demosaic）**补全每个像素缺失的另两个通道。所以一张 1200 万像素的彩照，其实是"猜"出了大量颜色信息——这也是为什么有时会出现彩色伪影。

## 针孔相机模型：小孔成像的智慧

镜头很复杂，但幸运的是，**绝大多数几何问题都可以用最简单的"针孔相机模型（pinhole camera model）"来近似**。它的原型就是物理课上的小孔成像：在暗盒上戳个小孔，外面的景物会在盒子后壁上形成一个**倒立、缩小**的像。

```text
        ┊＼                                    ／┊
   物体 ┊  ＼                              ／  ┊ 像（倒立、缩小）
    P   ┊    ＼          针孔 O          ／    ┊  p′
  (X,Y) ┊      ＼          ·           ／      ┊
  ──────┼────────＼────────┼────────／─────────┼────── 光轴 (Z 方向)
        ┊          ＼      │      ／           ┊
        ┊            ＼    │    ／             ┊
        ┊←──── 物距 Z ────→ · ←── 焦距 f ──→   ┊
                        (光心)
```

几个关键词就此登场：

- **光心 / 相机中心（optical center）**：那个"小孔"，记作 \\( O \\)，是所有光线汇聚的点。
- **光轴（optical axis）**：过光心、垂直于成像面的那条中线。
- **焦距（focal length）** \\( f \\)：光心到成像面的距离。
- **主点（principal point）**：光轴与成像面的交点，理想情况下就是图像中心。

> 💡 **提示**：真实成像是倒立的，处理起来别扭。数学上有个惯用技巧：把成像面**翻到光心前方**、同样距离 \\( f \\) 处，得到一个"虚拟像平面"。这样像就是**正立**的，投影公式里也少了个负号。本书后面的公式都基于这个"正立"约定，你不必纠结倒像。

## 相似三角形：投影公式的由来

针孔模型最妙的地方在于，投影关系可以用**初中的相似三角形**推出来。设相机坐标系以光心为原点、Z 轴沿光轴指向前方，空间点 \\( P = (X, Y, Z) \\)（Z 就是它到相机的距离，即**深度**）。由相似三角形，它在像平面上的位置 \\( (x, y) \\)（物理长度单位）为：

\\[
x = f \frac{X}{Z}, \qquad y = f \frac{Y}{Z}
\\]

一句话概括：**投影就是"除以深度 Z"**。同样大小的物体，Z 越大（越远），\\( X/Z \\) 越小，成像越小——**"近大远小"就是这个除法带来的**。

## 内参矩阵 K：把相机参数装进一个矩阵

上面的 \\( (x, y) \\) 还是物理长度（比如毫米），我们要的是**像素坐标** \\( (u, v) \\)。这需要两步换算：一是按像素密度缩放（每毫米多少像素），二是把原点从图像中心挪到左上角（回忆上一章：像素坐标原点在左上角）。把这些参数收拢，就得到**内参矩阵（intrinsic matrix）** \\( K \\)：

\\[
K = \begin{bmatrix} f_x & 0 & c_x \\\\ 0 & f_y & c_y \\\\ 0 & 0 & 1 \end{bmatrix}
\\]

- \\( f_x, f_y \\)：以**像素**为单位的焦距（把物理焦距和像素密度合并了；两者一般接近，因像素不完全是正方形而略有差异）。
- \\( c_x, c_y \\)：主点的像素坐标，通常约等于 `图像宽/2, 图像高/2`。

有了 \\( K \\)，投影写成一个漂亮的矩阵乘法（用齐次坐标）：

\\[
Z \begin{bmatrix} u \\\\ v \\\\ 1 \end{bmatrix} = K \begin{bmatrix} X \\\\ Y \\\\ Z \end{bmatrix}
\\]

展开就是 \\( u = f_x \dfrac{X}{Z} + c_x \\)，\\( v = f_y \dfrac{Y}{Z} + c_y \\)。**内参只和相机自身有关**（镜头 + 传感器），换个场景不变，所以叫"内"参。

## 外参 (R, t)：相机站在哪、朝哪看

上面假设点的坐标是在**相机坐标系**里给出的。但现实中物体坐标通常以**世界坐标系**描述（比如以房间某个角为原点）。**外参（extrinsic parameters）** 就负责把世界坐标变换到相机坐标：一个旋转 \\( R \\)（相机朝哪转）加一个平移 \\( t \\)（相机站在哪）。完整的投影链条是：

\\[
Z \begin{bmatrix} u \\\\ v \\\\ 1 \end{bmatrix} = K \, [\,R \mid t\,] \begin{bmatrix} X_w \\\\ Y_w \\\\ Z_w \\\\ 1 \end{bmatrix}
\\]

一句话记住区别：**内参是相机"天生"的属性，外参是相机此刻"站位"的描述**。相机搬个位置、转个角度，外参就变，内参不变。

## 镜头畸变：现实没那么理想

针孔模型很美，但真实镜头（尤其广角、鱼眼）会让直线拍弯，这叫**畸变（distortion）**，主要两类：

- **径向畸变（radial）**：越靠画面边缘弯得越厉害，表现为"桶形"（边缘外凸）或"枕形"（边缘内凹）。用几个系数 \\( k_1, k_2, \dots \\) 建模：

\\[
x_{\text{corrected}} = x\,(1 + k_1 r^2 + k_2 r^4 + \cdots)
\\]

其中 \\( r \\) 是该点到主点的距离。

- **切向畸变（tangential）**：镜头和传感器没装平行导致，用系数 \\( p_1, p_2 \\) 建模，一般较小。

标定（calibration）的任务，就是把 \\( K \\) 和这些畸变系数**测量出来**，之后就能把畸变"掰正"。这正是[第 64 章 相机标定](../p14-3d/ch64-calibration.md)要做的事。

## 动手写代码：把一个 3D 点投影成像素

概念讲够了，来点实在的。我们用 `nalgebra` 定义内参矩阵 \\( K \\)，把相机坐标系下的一个三维点投影成像素坐标。确保依赖：

```toml
[dependencies]
nalgebra = "0.35"
```

新建 `code/examples/ch06_camera_model.rs`：

```rust
use nalgebra::{Matrix3, Vector3};

fn main() {
    // 内参：焦距（像素单位）与光心（主点）
    let (fx, fy) = (800.0f32, 800.0f32);
    let (cx, cy) = (320.0f32, 240.0f32); // 假设图像 640×480，主点在中心

    // 内参矩阵 K（Matrix3::new 按「行优先」填 9 个数）
    let k = Matrix3::new(
        fx, 0.0, cx, //
        0.0, fy, cy, //
        0.0, 0.0, 1.0,
    );

    // 相机坐标系下的 3D 点 (X, Y, Z)，单位米；Z 是深度
    let point_cam = Vector3::new(0.1f32, 0.05, 2.0);

    // 投影：先算 K * P，再除以第三分量做「透视除法」
    let homogeneous = k * point_cam;
    let u = homogeneous.x / homogeneous.z;
    let v = homogeneous.y / homogeneous.z;

    println!("3D 点 (X,Y,Z) = ({}, {}, {})", point_cam.x, point_cam.y, point_cam.z);
    println!("投影到像素 (u, v) = ({:.1}, {:.1})", u, v);

    // 手算核对：u = fx*X/Z + cx = 800*0.1/2 + 320 = 360
    //          v = fy*Y/Z + cy = 800*0.05/2 + 240 = 260
    assert!((u - 360.0).abs() < 1e-3 && (v - 260.0).abs() < 1e-3);
}
```

运行：

```bash
cargo run --example ch06_camera_model
```

输出：

```text
3D 点 (X,Y,Z) = (0.1, 0.05, 2)
投影到像素 (u, v) = (360.0, 260.0)
```

和公式手算的 `(360, 260)` 完全一致。你刚刚亲手完成了相机成像最核心的一步运算——**把三维世界的一个点，映射到了照片上的一个像素**。整个三维视觉，都建立在这个投影关系（以及它的"逆向求解"）之上。

> ⚠️ **注意**：`k * point_cam` 得到的是"齐次坐标"，**必须再除以第三个分量**（透视除法）才是真正的像素坐标，这一步千万别漏。另外深度 \\( Z \\) 必须为正（点在相机前方）；\\( Z \le 0 \\) 表示点在相机背后或在光心上，投影无意义。

## 为什么三维视觉离不开相机模型

正向投影是"3D → 2D"，会丢掉深度信息（无数个 Z 不同的点会投到同一个像素）。三维视觉做的正是**反过来**——从 2D 图像恢复 3D 信息，而这一切都以相机模型为前提：

- **相机标定**（[第 64 章](../p14-3d/ch64-calibration.md)）：先求出 \\( K \\) 和畸变系数。
- **双目立体视觉**（[第 65 章](../p14-3d/ch65-stereo-depth.md)）：两个已知内外参的相机，靠视差三角化算深度。
- **位姿估计 PnP**（[第 66 章](../p14-3d/ch66-epipolar-pnp.md)）：已知 3D 点和它们的像素，反求相机外参 \\( (R, t) \\)。

没有相机模型，这些都无从谈起。所以本章虽浅，却是通往三维视觉大门的钥匙。

## 本章小结

- 数字图像的诞生：光 → 镜头会聚 → 传感器**采样**（定分辨率）→ ADC **量化**（定位深）→ 像素矩阵。
- **针孔相机模型**用"小孔成像"近似真实镜头；核心是光心、焦距 \\( f \\)、主点。
- 投影的本质是**除以深度 Z**（\\( x = fX/Z \\)），这正是"近大远小"的来源。
- **内参 \\( K \\)（\\( f_x, f_y, c_x, c_y \\)）**是相机自身属性；**外参 \\( (R, t) \\)** 描述相机在世界中的位置与朝向。
- 完整投影链：世界坐标先由外参 \\( (R, t) \\) 变到相机坐标，再经内参 \\( K \\) 投影、除以深度 \\( Z \\)，得到像素 \\( (u, v) \\)。
- 真实镜头有**径向/切向畸变**，需靠**标定**测量并校正。

## 动手练习

1. **换个点试试**：把示例里的 3D 点改成 \\( (0, 0, 5) \\)（正前方 5 米处），投影结果应该正好落在主点 \\( (320, 240) \\)。跑一下验证你的理解。
2. **模拟"近大远小"**：固定一个点的 X、Y，让 Z 从 1 米变到 10 米，打印每次的 \\( (u, v) \\)，观察像素点如何向主点收拢。
3. **改内参看变化**：把 \\( f_x, f_y \\) 增大一倍（相当于"长焦/放大"），同一个 3D 点的投影会离主点更远还是更近？先猜，再用代码验证。
4. **想一想（进阶）**：为什么单张普通照片无法直接测出物体的真实大小？（提示：投影公式里，同一个像素 \\( (u,v) \\) 对应的 \\( X \\) 和 \\( Z \\) 是绑在一起的，缺一个已知量。）想清楚这点，你就明白第十四部分为何需要双目、深度相机或多视角了。
