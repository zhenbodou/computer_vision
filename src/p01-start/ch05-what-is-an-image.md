# 第 5 章 图像到底是什么

> **本章导读**
> - 彻底想通一件事：一张图在计算机里，**本质就是一大堆数字**。
> - 搞清楚几个天天要用的概念：像素、分辨率、坐标系、通道、位深。
> - 建立"图像 = 三维数组（高 × 宽 × 通道）"的心智模型，并了解它在内存里怎么摆放。
> - 亲手用 `image` 造一张灰度图和一张彩色图，把像素的数值打印出来，眼见为实。

## 把一张照片放大到极限

拿出手机里任意一张照片，用两根手指使劲放大、再放大……到某个程度，清晰的画面会碎成一个个**彩色小方块**，糊成马赛克。恭喜你，你已经看到了图像最底层的样子——**这些小方块，就是像素**。

第 1 章说过，计算机看到的图像"只是一大堆数字"。这一章我们就把这句话彻底坐实：每一个小方块（像素），在计算机里都对应着几个具体的整数。看懂了这堆数字怎么组织，你就拿到了机器视觉的"入场券"——因为后面所有算法，本质上都是在对这堆数字做加减乘除。

## 像素、分辨率与坐标系

**像素（pixel，即 picture element，图像元素）** 是图像的最小单位，就是刚才那个小方块。一张图由横平竖直排成网格的像素组成。

**分辨率（resolution）** 就是这个网格有多大，通常写成 `宽 × 高`，单位是像素。比如 `1920 × 1080`，表示横向 1920 个像素、纵向 1080 个像素，一共 \\( 1920 \times 1080 = 2{,}073{,}600 \\) 个像素——两百多万个小方块，这就是"1080p"的由来。

要定位某个像素，得有个坐标系。这里有个**新手必记的关键点**：图像坐标系的原点在**左上角**，x 轴向**右**增大，y 轴向**下**增大。

```text
 (0,0) ─────────────▶ x 增大
   │  ┌────┬────┬────┬────┐
   │  │(0,0)│(1,0)│(2,0)│(3,0)│  ← 第 0 行（y=0）
   │  ├────┼────┼────┼────┤
   ▼  │(0,1)│(1,1)│(2,1)│(3,1)│  ← 第 1 行（y=1）
  y   └────┴────┴────┴────┘
 增大
```

> ⚠️ **注意**：图像的 y 轴是**朝下**的，和你数学课本里"y 轴朝上"正好相反！所以 `(0,0)` 是左上角而不是左下角。刚上手时，很多人算坐标时把上下搞反、把图画倒，记住"**左上角原点、y 向下**"能省掉无数 debug 时间。另外注意惯例：坐标常写 `(x, y)`（先列后行），但存进数组时却是"先行后列"，下面会看到这个"错位"。

## 灰度还是彩色：一个数字，还是三个

像素里装的数字，取决于图像是**灰度**还是**彩色**。

**灰度图（grayscale）**：每个像素只用**一个数字**表示明暗，0 是纯黑，255 是纯白，中间是各级灰。老照片、医学 X 光片、很多工业检测图都是灰度的——因为很多任务不需要颜色，灰度还能省 2/3 的存储和计算。

**彩色图（RGB）**：每个像素用**三个数字**表示，分别是红（Red）、绿（Green）、蓝（Blue）三种光的强度。三原色按不同比例混合，就能调出任何颜色：

| 像素值 `[R, G, B]` | 颜色 |
|--------------------|------|
| `[255, 0, 0]` | 纯红 |
| `[0, 255, 0]` | 纯绿 |
| `[0, 0, 255]` | 纯蓝 |
| `[255, 255, 255]` | 白 |
| `[0, 0, 0]` | 黑 |
| `[128, 128, 128]` | 中灰 |

这里的红、绿、蓝就是三个**通道（channel）**。有些图还有第四个通道 **Alpha**，表示**不透明度**（255 完全不透明，0 完全透明），常见于 PNG 图标、需要抠图叠加的场景，这时像素是 `[R, G, B, A]` 四个数。

> 📖 **术语**：**通道（channel）** 指图像在某一"颜色维度"上的数值层。灰度图有 1 个通道，RGB 有 3 个，RGBA 有 4 个。你可以把彩色图想象成三张灰度图叠在一起：一张只记录红的强度、一张绿、一张蓝。第 9 章 [颜色空间](../p02-image-basics/ch09-color-spaces.md) 会讲除 RGB 外的其他玩法（HSV、YUV、Lab）。

## 位深：为什么数字范围是 0–255

上面这些数字为什么总在 0–255 之间？因为它们通常用一个 `u8`（8 位无符号整数）存储。8 位能表示 \\( 2^8 = 256 \\) 个值，即 0 到 255。这个"每个通道用多少位"叫**位深（bit depth）**。

8 位是绝对主流——256 级明暗足够骗过人眼，且正好一字节，存取高效。这也解释了[第 4 章](ch04-rust-crash-course.md)为什么反复强调 `u8`：**它就是像素的天然容器**。当然也有更高位深（如医学、遥感用 16 位，`u16`，0–65535）或浮点图（`f32`，把像素归一化到 0.0–1.0，深度学习里常见），但入门阶段，认准 **8 位、0–255** 就够了。

## 图像就是一个三维数组：高 × 宽 × 通道

现在可以给出那个最重要的心智模型了。**一张图像，就是一个三维数组，形状是「高 H × 宽 W × 通道 C」**：

```text
彩色图 (H=2, W=3, C=3)，每格是一个 u8：

        列 x=0        列 x=1        列 x=2
行 y=0 [R,G,B]      [R,G,B]      [R,G,B]
行 y=1 [R,G,B]      [R,G,B]      [R,G,B]
```

- 灰度图 C=1，退化成一个二维矩阵（H × W）；
- 一张 1080p 彩图就是形状 `1080 × 1920 × 3` 的数组，共约 600 万个 `u8`。

**但内存其实是"一根直线"**：计算机内存是一维的，存不下三维方块，于是要把它"压扁"。绝大多数库（包括 `image`）采用**行优先（row-major）**布局——先把第 0 行所有像素排完，接着第 1 行，每个像素内部按 R、G、B 顺序排：

```text
内存里一长条 Vec<u8>：
[R00 G00 B00 | R10 G10 B10 | R20 G20 B20 || R01 G01 B01 | ...]
└──────── 第 0 行三个像素 ──────────┘   └─ 第 1 行 ─
```

给定坐标 \\( (x, y) \\) 和通道 \\( c \\)，它在这根长条里的下标（偏移量）是：

\\[
\text{offset} = (y \cdot W + x) \cdot C + c
\\]

灰度图 C=1 时就简化成你在第 4 章练习里见过的 `y * W + x`。**每一行占用的字节数 \\( W \cdot C \\) 叫步幅（stride）**，是"跳到下一行"要迈过的距离。（有些库为对齐会把 stride 设得比 \\( W\cdot C \\) 略大，`image` 一般不会，了解概念即可。）

> 💡 **提示**：记住"**先行后列、行优先铺开**"，你就掌握了图像存储的精髓。第 29 章 [ndarray](../p05-numeric/ch29-ndarray.md) 会用专门的多维数组库，让你直接用 `array[[y, x, c]]` 这种三维下标访问像素，不必手算 offset；第 31 章还会讲图像与张量（tensor）的互相转换，那是喂给神经网络的必经一步。

## 动手写代码：把图看成一堆数字

光说不练假把式。我们用 `image` 库亲手造两张小图，再把像素值打印出来。确保 `code/Cargo.toml` 里有依赖：

```toml
[dependencies]
image = "0.25"
```

新建 `code/examples/ch05_image_basics.rs`：

```rust
use image::{GenericImageView, GrayImage, ImageBuffer, Luma, Rgb, RgbImage};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    // 1. 一张 4×3 灰度图，从左到右由暗变亮
    let (w, h) = (4u32, 3u32);
    let gray: GrayImage = ImageBuffer::from_fn(w, h, |x, _y| {
        Luma([(x * 80) as u8]) // x=0..3 -> 0,80,160,240
    });
    println!("== 灰度图 {w}×{h} ==");
    // get_pixel 返回 &Luma<u8>，.0 取出内部的 [u8; 1]
    println!("像素 (0,0) = {:?}", gray.get_pixel(0, 0).0); // [0]
    println!("像素 (3,0) = {:?}", gray.get_pixel(3, 0).0); // [240]

    // 2. 一张 2×2 彩色图（RGB）
    let mut rgb: RgbImage = ImageBuffer::new(2, 2);
    rgb.put_pixel(0, 0, Rgb([255, 0, 0])); // 红
    rgb.put_pixel(1, 0, Rgb([0, 255, 0])); // 绿
    rgb.put_pixel(0, 1, Rgb([0, 0, 255])); // 蓝
    rgb.put_pixel(1, 1, Rgb([255, 255, 255])); // 白
    println!("\n== 彩色图 2×2 ==");
    println!("像素 (0,0) = {:?}", rgb.get_pixel(0, 0).0); // [255, 0, 0]

    let (width, height) = rgb.dimensions();
    println!("尺寸 = {width}×{height}，通道数 = 3");

    // 3. 把图像看成一维字节数组（行优先）
    let raw: &[u8] = rgb.as_raw();
    println!("底层字节数 = {} (= 2×2×3)", raw.len());
    println!("前 6 个字节 = {:?}", &raw[0..6]); // 红像素 + 绿像素

    // 4. 存盘（PNG 无损）
    gray.save("gray.png")?;
    rgb.save("color.png")?;
    Ok(())
}
```

运行：

```bash
cargo run --example ch05_image_basics
```

输出（去掉存盘那行）：

```text
== 灰度图 4×3 ==
像素 (0,0) = [0]
像素 (3,0) = [240]

== 彩色图 2×2 ==
像素 (0,0) = [255, 0, 0]
尺寸 = 2×2，通道数 = 3
底层字节数 = 12 (= 2×2×3)
前 6 个字节 = [255, 0, 0, 0, 255, 0]
```

盯着最后两行看：`2 × 2 × 3 = 12` 个字节，`前 6 个字节 = [255,0,0, 0,255,0]`，正是第 0 行的红像素 `[255,0,0]` 紧接着绿像素 `[0,255,0]`——**行优先布局肉眼可见**。这就是"把图看成一堆数字"最直观的一次体验。

> ⚠️ **注意**：`get_pixel(x, y)` 的参数顺序是**先 x 后 y**（先列后行），返回的是像素的**引用**（如 `&Luma<u8>`），要用 `.0` 取出里面的数组、或用 `*` 解引用。别和内存里"先行后列"的存储顺序搞混——**访问用 (x,y)，存储按 (行,列)**，这个错位是新手常见的困惑点。

## 常见图像格式：有损还是无损

同样一堆像素数字，存成文件时有多种"打包"方式，各有取舍：

| 格式 | 压缩 | 特点 | 适用 |
|------|------|------|------|
| **PNG** | 无损 | 像素一个不差，支持 Alpha 透明 | 截图、图标、需要精确像素的检测任务 |
| **JPEG** | **有损** | 体积小，但会丢细节、留"块效应" | 照片、网络传输、对精度不敏感的场景 |
| **BMP** | 几乎不压缩 | 结构最简单，文件巨大 | 教学、少数工业相机原始输出 |

> 🕳️ **坑**：**JPEG 是有损压缩**——它为了缩小体积会悄悄改动像素值，还会反复压缩导致画质越来越差。做精密测量、缺陷检测、或需要逐像素比对时，**务必用 PNG 等无损格式**保存中间结果，否则你分析的可能是"压缩瑕疵"而非真实信号。好在 `image` 库靠**文件扩展名自动选格式**（`.png` / `.jpg` / `.bmp`），保存时改后缀就行，非常省心。

## 本章小结

- 图像的本质是**一大堆 0–255 的数字**；放大到极限就是一个个像素小方块。
- **像素**是最小单位，**分辨率**是 `宽 × 高`；坐标系**原点在左上角，x 向右、y 向下**（和数学相反）。
- 灰度图每像素 1 个数（0 黑 255 白）；彩色图每像素 3 个数（R/G/B），可选第 4 个 Alpha 透明通道。每个"颜色层"叫一个**通道**。
- 像素通常用 8 位（`u8`，0–255）存储，这叫**位深**。
- 图像 = **三维数组「高 H × 宽 W × 通道 C」**，在内存里按**行优先**压扁成一维；下标公式 \\( (y \cdot W + x)\cdot C + c \\)，每行字节数叫 **stride**。
- 常见格式：**PNG 无损**、**JPEG 有损**、BMP 基本不压缩；做精密任务优先用无损格式。

## 动手练习

1. **改渐变方向**：把示例里灰度图的 `Luma([(x * 80) as u8])` 改成按 `y` 渐变（上暗下亮），保存后用系统看图器打开，验证方向对不对。
2. **画一面国旗**：用 `ImageBuffer::new` 造一张 30×20 的 RGB 图，把上半部分填成红色、下半部分填成白色，保存成 PNG。（提示：用双重 `for` 遍历 x、y，按 `y` 判断填哪种颜色。）
3. **验证行优先**：造一张 3×2 的 RGB 图，给 9 个像素填上你能记住的值，然后打印 `as_raw()` 的全部 18 个字节，对照下标公式 \\( (y\cdot W + x)\cdot 3 + c \\) 手算几个位置，确认对得上。
4. **想一想**：一张 4K（`3840 × 2160`）彩色 8 位图，不压缩要占多少字节？换算成 MB 是多少？（这解释了为什么视频必须压缩。）
