## 场景：训练集 99%，测试集只有 80%

假设你按 [第 40 章](ch40-burn-train.md) 训完了一个手写数字 CNN，兴冲冲一看指标：**训练集准确率 99%，测试集却只有 80%**。模型没坏，它得的是一种很常见的"病"——**过拟合（overfitting）**：训练数据太少、模型太"聪明"，于是它没在"学规律"，而是在"死记硬背"训练集里的每一张图。一换成没见过的图，就露馅。

这一章讲的，就是治这种病、并让模型整体练得更好的四类通用技巧：**数据增强、优化器与学习率、正则化、迁移学习**。它们是每一个视觉模型训练者都要反复用到的"基本功"。

## 数据增强：把一张图变成一打

**直觉先行**：一张猫的照片，你把它**左右翻转**，它还是猫；**调亮一点、旋转几度、裁掉边角**，它仍然是猫。但对模型来说，这些"看起来不一样、语义却没变"的图，就是**一批全新的训练样本**。这就是**数据增强（data augmentation）**——在不改变标签含义的前提下，对原图随机做各种变换，等于**免费把数据集扩大好几倍**，逼着模型去学"猫之所以是猫"的本质特征，而不是死记某一张图的像素。

常见的增强手段就是我们前几章早已学过的图像操作：**翻转、旋转、裁剪、亮度/对比度抖动、加噪、缩放**。下面用纯 `image` + `imageproc` 对一张合成图做一整套增强，并把每种增强前后的图像统计打印出来。

`Cargo.toml`：

```toml
[dependencies]
image = "0.25"
imageproc = "0.27"
```

完整代码（`examples/ch41_augment.rs`）：

```rust
use image::{ImageBuffer, Rgb, RgbImage};
use image::imageops::{self, FilterType};
use imageproc::geometric_transformations::{rotate_about_center, Border, Interpolation};
use imageproc::noise::gaussian_noise;

/// 合成一张"有明显朝向"的彩色场景：灰度渐变背景 + 左上红矩形 + 右下绿圆 + 中间偏上蓝方块。
/// 故意做得左右/上下都不对称，这样翻转、旋转的效果一眼就能看出来。
fn make_scene(w: u32, h: u32) -> RgbImage {
    ImageBuffer::from_fn(w, h, |x, y| {
        let (xi, yi) = (x as i32, y as i32);
        if (15..55).contains(&xi) && (15..45).contains(&yi) {
            return Rgb([210, 40, 40]); // 左上角红矩形
        }
        if (60..74).contains(&xi) && (18..32).contains(&yi) {
            return Rgb([50, 80, 220]); // 中间偏上的蓝方块
        }
        let (cx, cy, r) = (96, 70, 18); // 右下角绿圆
        if (xi - cx).pow(2) + (yi - cy).pow(2) < r * r {
            return Rgb([40, 190, 70]);
        }
        let g = (40 + x * 120 / (w - 1)) as u8; // 背景：从左到右由暗到亮
        Rgb([g, g, g])
    })
}

/// 用 Rec.601 权重把 RGB 折算成亮度，统计整幅图的亮度均值与标准差。
/// 均值反映"整体明暗"，标准差反映"对比度/噪声量"——增强前后一比就有直觉。
fn luma_stats(img: &RgbImage) -> (f32, f32) {
    let n = (img.width() * img.height()) as f32;
    let lumas: Vec<f32> = img
        .pixels()
        .map(|p| 0.299 * p[0] as f32 + 0.587 * p[1] as f32 + 0.114 * p[2] as f32)
        .collect();
    let mean = lumas.iter().sum::<f32>() / n;
    let var = lumas.iter().map(|v| (v - mean).powi(2)).sum::<f32>() / n;
    (mean, var.sqrt())
}

/// 亮度抖动：每个通道整体加上 delta（可正可负），越界钳到 [0,255]。
fn brightness_jitter(img: &RgbImage, delta: i32) -> RgbImage {
    let clamp = |c: u8| (c as i32 + delta).clamp(0, 255) as u8;
    ImageBuffer::from_fn(img.width(), img.height(), |x, y| {
        let p = img.get_pixel(x, y).0;
        Rgb([clamp(p[0]), clamp(p[1]), clamp(p[2])])
    })
}

/// 对比度抖动：以 128 为中心把每个像素值"拉开"(factor>1)或"压扁"(factor<1)。
fn contrast_jitter(img: &RgbImage, factor: f32) -> RgbImage {
    let adj = |c: u8| (((c as f32 - 128.0) * factor) + 128.0).clamp(0.0, 255.0) as u8;
    ImageBuffer::from_fn(img.width(), img.height(), |x, y| {
        let p = img.get_pixel(x, y).0;
        Rgb([adj(p[0]), adj(p[1]), adj(p[2])])
    })
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let (w, h) = (128u32, 96u32);
    let src = make_scene(w, h);
    let (m0, s0) = luma_stats(&src);
    println!("原图: {}x{}  亮度均值={:.1}  标准差={:.1}", w, h, m0, s0);
    src.save("out_ch41_00_src.png")?;
    println!();

    let mut generated = 0u32;
    let mut report = |name: &str, img: &RgbImage, note: &str| -> Result<(), Box<dyn std::error::Error>> {
        let (m, s) = luma_stats(img);
        println!(
            "{name:<10} {:>3}x{:<3}  亮度均值={:>5.1}  标准差={:>5.1}   {note}",
            img.width(), img.height(), m, s
        );
        img.save(format!("out_ch41_{name}.png"))?;
        generated += 1;
        Ok(())
    };

    // ① 水平翻转：像素只换位置、不换数值 → 亮度均值/标准差与原图完全一致
    let flipped = imageops::flip_horizontal(&src);
    report("01_flip", &flipped, "左右镜像；统计量与原图相同（只是位置变了）")?;

    // ② 旋转 15°：绕中心顺时针旋转，转出画面的角落用黑色填充
    let rotated = rotate_about_center(
        &src, 15f32.to_radians(), Interpolation::Bilinear, Border::Constant(Rgb([0, 0, 0])),
    );
    report("02_rotate", &rotated, "转 15°，角落黑边拉低了亮度均值")?;

    // ③ 随机裁剪 + 缩放回原尺寸：截取内部 80% 的窗口再放大，等价于"镜头拉近"
    let (cw, ch) = (w * 4 / 5, h * 4 / 5);
    let cropped = imageops::crop_imm(&src, 12, 8, cw, ch).to_image(); // 固定偏移，保证可复现
    let crop_resized = imageops::resize(&cropped, w, h, FilterType::Triangle);
    report("03_crop", &crop_resized, "裁掉边缘再放大回原尺寸（zoom-in）")?;

    // ④ 亮度抖动：整体调亮 50 个灰阶 → 亮度均值明显上升
    let brighter = brightness_jitter(&src, 50);
    report("04_bright", &brighter, "整体调亮 +50，均值上升")?;

    // ⑤ 对比度抖动：以 128 为中心拉开 1.4 倍 → 标准差变大
    let contrasted = contrast_jitter(&src, 1.4);
    report("05_contrast", &contrasted, "对比度 ×1.4，标准差变大")?;

    // ⑥ 加高斯噪声：模拟传感器/低光噪点 → 均值几乎不变、标准差上升
    let noisy = gaussian_noise(&src, 0.0, 25.0, 42);
    report("06_noise", &noisy, "高斯噪声 σ=25，均值不变、标准差上升")?;

    // ⑦ 缩放：直接缩到 0.75 倍尺寸（内容不变，尺寸变小）
    let scaled = imageops::resize(&src, w * 3 / 4, h * 3 / 4, FilterType::Lanczos3);
    report("07_scale", &scaled, "缩放到 0.75x，尺寸变小")?;

    println!();
    println!(
        "一张原图 → 额外生成了 {generated} 张增强样本（数据集直接放大到 {} 倍，全部免费）",
        generated + 1
    );
    Ok(())
}
```

运行 `cargo run --example ch41_augment`，终端输出（真实可复现）：

```text
原图: 128x96  亮度均值=101.2  标准差=33.8

01_flip    128x96   亮度均值=101.2  标准差= 33.8   左右镜像；统计量与原图相同（只是位置变了）
02_rotate  128x96   亮度均值= 90.2  标准差= 42.8   转 15°，角落黑边拉低了亮度均值
03_crop    128x96   亮度均值=101.2  标准差= 25.5   裁掉边缘再放大回原尺寸（zoom-in）
04_bright  128x96   亮度均值=151.0  标准差= 33.9   整体调亮 +50，均值上升
05_contrast 128x96   亮度均值= 90.0  标准差= 47.3   对比度 ×1.4，标准差变大
06_noise   128x96   亮度均值=100.8  标准差= 37.5   高斯噪声 σ=25，均值不变、标准差上升

```

几个数字很能说明问题：

- **翻转（01）** 的亮度均值、标准差和原图**分毫不差**——因为它只是把像素挪了位置，一个都没改。可它对模型却是全新样本。这就是数据增强"性价比最高"的一类操作。
- **调亮 +50（04）** 让均值从 `101.2` 涨到 `151.0`；**对比度 ×1.4（05）** 把标准差从 `33.8` 拉到 `47.3`（对比度"拉大了明暗差距"）；**加噪（06）** 均值几乎不动、标准差却升高（噪声给每个像素叠了随机扰动）。数字精准地对应了每种增强"改了什么"。
- 一张原图，转眼变成 `8` 张。真实训练里，这些变换是**每个 epoch 随机组合、在线生成**的，等于给了模型近乎无穷的"变体"去见世面。

> 💡 **提示**：增强要打开 `out_ch41_*.png` 亲眼看一看。数字能告诉你统计量变了，但"翻转后红矩形跑到了右边""旋转后出现黑边"这种**空间**变化，还是看图最直观。

## 优化器：模型是怎么"下山"的

训练模型，本质是在一个高低起伏的"损失地形"上找最低点（见 [第 36 章](ch36-neural-nets.md) 的反向传播）。**优化器（optimizer）** 就是决定"每一步往哪走、走多远"的策略。

- **SGD（随机梯度下降）**：最朴素的"下山"——看当前脚下哪个方向最陡（梯度），就朝反方向迈一步。简单可靠，但容易在狭长的山谷里来回横跳，走得慢。
- **加动量（Momentum）**：给下山的你加上**惯性**。它会累积之前的方向，像滚下坡的球一样越滚越顺——能冲过小坑洼（局部小震荡）、在山谷里少走冤枉路。
- **Adam**：在动量之上再加**自适应步长**——它给每个参数单独调整步子大小：坡陡的地方步子迈小点别冲过头，坡平的地方步子迈大点别磨蹭。因为"省心、通常收敛快"，Adam（及其带权重衰减的变体 **AdamW**）是今天最常用的默认优化器。

用 candle 表达出来非常简洁（下面是**用法示意**，完整训练循环见 [第 40 章](ch40-burn-train.md)）：

```rust
// candle 0.11.0（candle-nn）—— 优化器用法示意
use candle_nn::{Optimizer, SGD, AdamW, ParamsAdamW};

// 最朴素的 SGD：只要"待优化的参数 + 一个学习率"
let mut sgd = SGD::new(varmap.all_vars(), 0.01)?;

// AdamW：自适应步长 + 内置 weight decay（权重衰减），更省心
let mut opt = AdamW::new(
    varmap.all_vars(),
    ParamsAdamW { lr: 1e-3, weight_decay: 0.01, ..Default::default() },
)?;

// 每个训练步：拿到 loss，一行搞定"反向求梯度 + 更新参数"
opt.backward_step(&loss)?;
```

### 学习率：最重要的那个旋钮

上面的 `lr`（learning rate，学习率）是**整个训练里最该先调好的超参数**。它就是"每一步迈多大"：

- **太大**：一步跨过山谷，在两壁间来回弹甚至越跑越高（损失变 `NaN`）。
- **太小**：磨磨蹭蹭下不到底，训练慢得让人抓狂。

实践中还会用 **学习率调度（lr schedule）** 让它随训练动态变化，最经典的组合是 **warmup（预热）+ 衰减（decay）**：

```text
学习率
  │        ___
  │      /     \___
  │    /            \____
  │  / warmup:           \______  衰减:
  │ /  从小慢慢升,             \___ 后期调小,
  │/   别一上来就冲飞             稳稳收敛到谷底
  └──────────────────────────────▶ 训练步数
```

warmup 让模型开头别因为步子太大而"起飞"，后期衰减则让它在接近谷底时小步微调、稳稳落底。在 candle 里，调度就是训练途中随时改学习率：

```rust
opt.set_learning_rate(new_lr); // 配合 warmup / 衰减策略，按步数算出 new_lr
```

## 正则化：给模型"立规矩"防止死记硬背

**正则化（regularization）** 是一类专门对付过拟合的手段，核心思想都是"别让模型太任性、逼它学得更通用"。一句话记住每个：

- **权重衰减（weight decay，即 L2 正则）**：训练时轻微惩罚"过大的权重"，让模型倾向于更平滑、更简单的解——上面 `ParamsAdamW` 里的 `weight_decay` 就是它。
- **Dropout**：训练时**随机"关掉"一部分神经元**，逼网络别过度依赖某几个神经元，学出更鲁棒的冗余表示。candle 里是 `candle_nn::ops::dropout(&x, 0.5)`（`0.5` 是丢弃概率）。
- **早停（early stopping）**：盯着**验证集**指标，一旦它不再变好（甚至开始变差）就及时收手，别继续把训练集背得更死。
- **批归一化（BatchNorm）**：把每层的输入拉回到稳定的分布，训练更快更稳，顺带有轻微正则效果。candle 里是 `candle_nn::batch_norm(...)`。

## 迁移学习：站在巨人的肩膀上

如果你只有几百张图，还想训出好模型，硬train一个从零开始的网络基本没戏——数据太少，怎么增强都不够。这时的正确姿势是 **迁移学习（transfer learning）**。

**直觉**：一个在 ImageNet（上百万张图、一千个类别）上训练过的网络，它前面那些层早已学会了通用的视觉"基本功"——认边缘、认纹理、认形状、认颜色块。这些能力**换个任务照样管用**：不管你要分猫狗还是分零件合格与否，"怎么看图"这件事是相通的。既然如此，何必从零学起？直接把这套现成的"眼力"拿过来，只改造最后决策的那几层就行。

具体做法通常是：

```text
       预训练模型（在 ImageNet 上学好）
   ┌───────────────┬───────────────┬──────────┐
   │  前面很多层     │   中间层        │ 最后分类层 │
   │ (通用特征:      │ (较通用)        │(1000 类)  │
   │  边缘/纹理…)    │                │          │
   └───────────────┴───────────────┴──────────┘
        ↓ 冻结(freeze)        ↓ 冻结/微调     ↓ 换掉!
   ┌───────────────┬───────────────┬──────────┐
   │  原样保留        │  原样/小步微调  │ 换成你的  │
   │  不再训练        │                │ 类别数    │
   └───────────────┴───────────────┴──────────┘
              你的小数据集 + 小学习率，只训后面
```

- **冻结（freeze）前面的层**：让它们保持预训练学到的通用特征，不再更新。
- **换掉最后的分类层**：ImageNet 是 1000 类，你的任务可能只有 2 类（合格/不合格），所以把最后一层换成你自己的类别数，从头训这一层。
- **可选：微调（fine-tuning）**：用**很小的学习率**把中间层也轻轻带着一起训，让它更贴合你的数据。学习率一定要小，否则会把宝贵的预训练特征"冲坏"。

这样即使只有几百张图，也能借到"百万张图"练出的底子，又快又好。本书 [第 43 章](../p08-classification/ch43-finetune.md) 会带你真正动手微调一个分类器，第八~九部分的分类、检测也大量建立在这个思路上。

> ⚠️ **注意**：**用预训练模型，必须匹配它当年的预处理方式。** 模型在 ImageNet 上训练时，输入图是按特定尺寸缩放、并用特定的均值/方差做标准化的（还记得 [第 31 章](../p05-numeric/ch31-image-as-tensor.md) 里那组 `mean=[0.485,0.456,0.406]`、`std=[0.229,0.224,0.225]` 吗？就是它）。你推理/微调时若不用同一套预处理，喂进去的数据分布就对不上，效果会莫名其妙地差。

## 常见坑与提示

> 🕳️ **坑**：**增强不能改变标签的语义！** 手写数字 `6` 旋转 180° 会变成 `9`，水平翻转 `2` 也不再是 `2`——这类增强会把标签变错，等于给模型喂错误答案。所以增强手段必须**结合任务**来选：认猫狗，随便翻转旋转都行；认数字/文字/有方向的箭头，就得禁用翻转、限制旋转角度。

> ⚠️ **注意**：**过度增强有害。** 把图转 90°、噪声加到面目全非、亮度拉到纯白——增强过头，样本就"失真"到不再代表真实数据了，反而拖累模型。增强的幅度要贴合"现实中真会遇到的变化范围"。

> 🕳️ **坑**：**验证集/测试集绝不做（随机）增强！** 增强只用在训练集，目的是让模型见多识广。验证集是用来**如实衡量**模型表现的考场，若也随机增强，每次评测结果都在抖动，你根本没法判断模型到底行不行。（推理时的确定性预处理——如固定缩放、标准化——不算增强，那是必须做的。）

> 💡 **提示**：**学习率是你最该第一个调的超参。** 拿不准时，先固定别的、只扫学习率（比如 `1e-2 / 1e-3 / 1e-4` 各试一下看损失曲线），往往比纠结换哪个优化器收益大得多。默认用 **AdamW + 一个不大的学习率**，是当下最省心的起手式。

## 本章小结

- **数据增强**：在不改变标签语义的前提下做翻转/旋转/裁剪/亮度对比度抖动/加噪/缩放，等于**免费扩充数据、提升泛化**。本章用纯 `image` + `imageproc` 实测：一张图轻松变 8 张，统计量的变化精确对应每种操作。
- **优化器**：SGD（老实下山）→ 加动量（惯性，少走冤枉路）→ Adam/AdamW（自适应步长，最常用默认）。**学习率是最重要的超参**，常配 **warmup + 衰减** 的调度。
- **正则化**对付过拟合：权重衰减、Dropout、早停、BatchNorm，核心都是"别让模型死记硬背"。
- **迁移学习**：小数据别从零训，拿 ImageNet 预训练模型的通用特征打底，冻结前面层、换/微调最后几层，又快又好——但**务必匹配它的预处理**。

## 动手练习

1. **改增强、看语义**：把 `ch41_augment.rs` 里的旋转角度从 `15°` 改成 `180°`，再想想：如果这张图是数字 `6`，这个增强还合法吗？把结论写进注释。
2. **组合增强**：把"先旋转、再加噪、再调亮"串起来作用到同一张图上（真实训练就是这么随机组合的），存成一张图，直观感受"一次多重扰动"的效果。
3. **量化对比度**：`contrast_jitter` 的 `factor` 分别取 `0.5` 和 `2.0`，观察打印出的标准差怎么变（提示：`<1` 压扁、`>1` 拉开），并解释为什么。
4. **想一想（迁移学习）**：你要做一个"区分 3 种螺丝合格/次品"的分类器，手上只有 300 张图。你会从零训练还是用预训练模型？最后一层要改成几类？为什么学习率要设得很小？

## 第七部分阶段验收：训练系统而非一次训练

把数据清单、划分、种子、配置、依赖、逐轮指标、最佳 checkpoint 和模型哈希作为同一实验
制品。先验证模型能过拟合 8 个样本，再进行至少三个种子实验；报告均值、标准差、每类指标
和校准。对增强、优化器、调度、权重衰减与预训练逐项消融。训练端与部署端用黄金输入比较
logits；注入 NaN、坏标签和中断，要求定位样本并可恢复。第 40 章的专家补强是本阶段必做项。
