# 第 11 章 点运算：亮度、对比度、Gamma 与查找表

> **本章导读**
> - 认识**点运算（point operation）**：输出像素只由**同一位置**的输入像素决定，是最简单也最高频的一类图像处理。
> - 亲手实现调**亮度**、调**对比度**、做 **Gamma 校正**，并搞懂它们背后一行公式的含义。
> - 吃透 u8 的**溢出坑**，学会用**饱和运算**（`saturating_add`/`clamp`）稳稳兜底。
> - 掌握**查找表（LUT）**这个"空间换时间"的经典优化——把逐像素计算加速几十倍。💡

## 场景引入：一张灰蒙蒙的照片

你手机相册里一定有这样的照片：逆光拍的，人脸黑成一团；或者阴天拍的，整张灰蒙蒙、没精神。点一下"自动优化"，照片瞬间通透了——暗的地方提亮、亮的地方压住、灰的地方拉开层次。

这背后最基础的操作，就是本章的主角：**点运算**。它的特点是——**新图上每个像素的值，只取决于原图上同一个位置的那个像素**，跟旁边的像素一点关系都没有。

这正好和上一章的几何变换、以及下一部分要学的卷积形成对照：

```text
点运算：  out(x,y) = f( in(x,y) )              ← 只看自己
卷积  ：  out(x,y) = f( in 在 (x,y) 周围一圈 )  ← 要看邻居
几何变换：out(x,y) = in( 变换后的坐标 )          ← 换位置不换值
```

因为"只看自己"，点运算特别好理解、好实现，也特别好加速（后面的 LUT 就靠这一点）。

## 原理：三个最常用的映射

点运算的本质是给每个可能的输入灰度值 \\( I_{in} \\)（0~255）规定一个输出值 \\( I_{out} \\)。不同的映射函数 \\( f \\) 就对应不同的效果。

### 亮度：整体加一个常数

想让图更亮，就给每个像素**加**一个正数 \\( b \\)；想更暗，就加负数：

\\[ I_{out} = I_{in} + b \\]

这会把整条灰度曲线**平移**。加得太多，亮的部分会一起"顶到" 255 糊成一片白（过曝）。

### 对比度：绕中点做拉伸

对比度是"亮暗差距"。想拉大差距，就让亮的更亮、暗的更暗。做法是**绕中间灰度 128 做缩放**，乘一个系数 \\( a \\)：

\\[ I_{out} = a \times (I_{in} - 128) + 128 \\]

- \\( a > 1 \\)：对比度增强（差距拉大）；
- \\( 0 < a < 1 \\)：对比度减弱（画面变灰、变平）；
- \\( a = 1 \\)：原样不变。

为什么要减 128 再加回来？因为我们想让**中灰保持不动**，只把偏离中灰的部分往两头推。如果直接乘 \\( a \\) 不减中点，整幅图会连带被提亮或压暗，那就变成"亮度 + 对比度"混在一起了。

```text
灰度轴:  0 ────────── 128 ────────── 255
对比度↑:      ◀── 暗更暗  中点不动  亮更亮 ──▶
```

### Gamma 校正：非线性地调中间调

亮度和对比度都是**直线**变换（一次函数）。而 **Gamma 校正**是一条**曲线**，能在几乎不动黑（0）和白（255）两端的前提下，专门调整**中间调**的明暗：

\\[ I_{out} = 255 \times \left( \frac{I_{in}}{255} \right)^{\gamma} \\]

先把像素归一化到 0~1，做 \\( \gamma \\) 次幂，再乘回 255：

- \\( \gamma < 1 \\)（如 0.45）：中间调被**提亮**，暗部细节看得更清（常用于提亮欠曝照片）；
- \\( \gamma > 1 \\)（如 2.2）：中间调被**压暗**；
- \\( \gamma = 1 \\)：直线，不变。

> 📖 **术语**：**Gamma** 这个词来自显示器——显示器的亮度和输入信号本身就是非线性（约 2.2 次幂）关系，所以图像编码时常预先做一次 \\( 1/2.2 \\) 的"反 Gamma"来抵消。你现在只需记住：**Gamma 是一条调中间调的曲线，指数小于 1 提亮、大于 1 压暗**。

## 溢出坑：u8 加法会"回绕"

动手之前，必须先讲一个新手必踩的坑。灰度像素是 `u8`，范围只有 **0~255**。如果你写 `200u8 + 100`：

- **debug 模式**：程序直接 panic（溢出报错）；
- **release 模式**：悄悄**回绕（wrapping）**成 `300 - 256 = 44`——本该更亮的像素反而变暗了！

```text
   期望:  200 + 100 = 300  → 应该封顶到 255
   回绕:  200 + 100 = 44   → 亮变暗，画面出现诡异黑斑！
```

正确做法是用**饱和运算（saturating arithmetic）**：超出范围就"贴着边界停住"，不回绕。Rust 内置了 `saturating_add`/`saturating_sub`；做乘法或带负数的运算时，则先转成更大的类型（`i32`/`f32`）算好，最后用 `clamp(0, 255)` 夹回来。

```rust
let a: u8 = 200;
assert_eq!(a.saturating_add(100), 255); // 封顶，不回绕
assert_eq!(a.wrapping_add(100), 44);    // 回绕（错误示范）
// 带负数/浮点时：先放大类型，算完再 clamp
let v = 200i32;
let out = (v - 250).clamp(0, 255) as u8;  // -50 → 0
```

## 动手写代码

依赖同前几章：

```toml
[dependencies]
image = "0.25"
```

我们先合成一张水平灰度渐变图（从左黑到右白）当"标尺"，任何点运算作用在它上面，效果都一目了然。

```rust
use image::{GenericImageView, GrayImage, ImageBuffer, Luma};

/// 合成一张从左(0)到右(255)的水平灰度渐变图
fn make_gradient(w: u32, h: u32) -> GrayImage {
    ImageBuffer::from_fn(w, h, |x, _y| {
        let v = (x * 255 / (w - 1)) as u8;
        Luma([v])
    })
}

/// 调亮度：每个像素加 delta（可正可负），用 i32 中转再 clamp 防溢出
fn adjust_brightness(img: &GrayImage, delta: i32) -> GrayImage {
    ImageBuffer::from_fn(img.width(), img.height(), |x, y| {
        let v = img.get_pixel(x, y)[0] as i32;
        Luma([(v + delta).clamp(0, 255) as u8]) // 关键：clamp 兜底
    })
}

/// 调对比度：绕中点 128 缩放，factor>1 增强、<1 减弱
fn adjust_contrast(img: &GrayImage, factor: f32) -> GrayImage {
    ImageBuffer::from_fn(img.width(), img.height(), |x, y| {
        let v = img.get_pixel(x, y)[0] as f32;
        let out = (v - 128.0) * factor + 128.0;
        Luma([out.clamp(0.0, 255.0) as u8])
    })
}
```

### 用查找表（LUT）实现 Gamma 加速

Gamma 里有个 `powf`（浮点幂运算），比加减乘慢得多。一张 1920×1080 的图有 200 多万个像素，若每个都算一次 `powf`，开销可观。

关键洞察：**输入灰度只有 256 种可能取值（0~255）**！与其对 200 万个像素反复算，不如**预先**把这 256 个输入分别算好、存进一张表 `[u8; 256]`，之后每个像素只需"查表"——一次数组索引，快到飞起。这张表就叫**查找表（Look-Up Table，LUT）**，是典型的"空间换时间"。

```rust
/// 预计算 Gamma 查找表：把 0~255 每个输入的输出值算好存起来
fn build_gamma_lut(gamma: f32) -> [u8; 256] {
    let mut lut = [0u8; 256];
    for i in 0..256 {
        let normalized = i as f32 / 255.0;              // 归一化到 0~1
        let corrected = normalized.powf(gamma) * 255.0; // 幂运算后放大回来
        lut[i] = corrected.round().clamp(0.0, 255.0) as u8;
    }
    lut
}

/// 应用任意 LUT：每个像素只做一次数组查表，没有浮点运算
fn apply_lut(img: &GrayImage, lut: &[u8; 256]) -> GrayImage {
    ImageBuffer::from_fn(img.width(), img.height(), |x, y| {
        let v = img.get_pixel(x, y)[0] as usize;
        Luma([lut[v]]) // 查表：O(1)，无 powf
    })
}
```

LUT 的美妙之处在于**通用**：亮度、对比度、Gamma、反相、阈值……任何"输入到输出"的点运算，都能预先烘焙成一张 `[u8;256]` 表，然后共用同一个 `apply_lut`。多个点运算还能**合并成一张表**一次搞定（见练习）。

### 串起来跑

```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let g = make_gradient(256, 64);
    g.save("gradient.png")?;

    adjust_brightness(&g, 60).save("brighter.png")?;   // 整体提亮
    adjust_brightness(&g, -60).save("darker.png")?;    // 整体压暗
    adjust_contrast(&g, 1.6).save("contrast_up.png")?; // 对比增强
    adjust_contrast(&g, 0.5).save("contrast_down.png")?;

    let lut = build_gamma_lut(0.45);                   // γ<1，提亮中间调
    apply_lut(&g, &lut).save("gamma045.png")?;
    let lut2 = build_gamma_lut(2.2);                   // γ>1，压暗中间调
    apply_lut(&g, &lut2).save("gamma22.png")?;

    println!("完成，对比查看各 PNG 的渐变变化。");
    Ok(())
}
```

打开输出：`brighter.png` 整体变亮且右侧一片纯白（顶到 255）；`contrast_up.png` 左黑右白之间的过渡变陡；`gamma045.png` 则是中段明显提亮、但两端黑白基本不动——三种映射的差别一眼可辨。

> 💡 **提示**：处理**彩色图（`RgbImage`）**时，最常见做法是对 R、G、B **三个通道各查一次同一张 LUT**（用 `enumerate_pixels_mut` 遍历，对 `px[0]`、`px[1]`、`px[2]` 分别映射）。但要注意：单纯"三通道同增同减"调亮度可能让颜色发灰，专业调色更常在亮度通道上做（回顾 [第 9 章 颜色空间](ch09-color-spaces.md) 的 HSV/Lab）。

## 常见坑与提示

> 🕳️ **坑**：`u8` 直接加减会溢出。debug 下 panic、release 下**静默回绕**（亮变暗、暗变亮），后者尤其阴险，因为编译不报错、只在成品里出诡异色块。凡是可能越界的运算，一律走 `saturating_*` 或"转 `i32`/`f32` → 运算 → `clamp`"。

> ⚠️ **注意**：浮点转 `u8` 时先 `round()` 再 `clamp` 再 `as u8`。直接 `as u8` 是**截断取整**（`3.9 → 3`）而非四舍五入，长期累积会有可见偏差；而对超范围的浮点直接 `as u8` 在 Rust 里是饱和转换（`300.0 as u8 == 255`），但负数 `-5.0 as u8 == 0`——行为容易记混，显式 `clamp` 最稳妥、最易读。

> 💡 **提示**：只要一个操作是"逐像素、输出只依赖当前像素值"，就**优先考虑 LUT**。256 个值的表构建成本几乎可忽略，却能把每像素的复杂计算降为一次数组访问；批量处理视频帧时收益尤其明显。

## 本章小结

- **点运算**：输出像素只依赖同位置的输入像素（`out = f(in)`），与邻域无关，因此简单、快、易加速。
- 三个常用映射：**亮度**（加常数，平移曲线）、**对比度**（绕中点 128 乘系数）、**Gamma**（幂函数曲线，专调中间调，\\( \gamma<1 \\) 提亮）。
- `u8` 溢出会**回绕**，必须用 `saturating_add` 或"放大类型 + `clamp`"兜底；浮点转 `u8` 记得 `round` + `clamp`。
- **LUT（查找表）**把 256 个输入的输出预计算进 `[u8;256]`，用一次数组查表替代逐像素的复杂运算，是"空间换时间"的经典手法，且对任意点运算通用。

## 动手练习

1. **图像反相**：写一个 LUT 实现"底片效果"（\\( I_{out} = 255 - I_{in} \\)），作用在渐变图上验证黑白互换。
2. **合并 LUT**：把"先 Gamma 0.5，再对比度 1.3"两步**合并成一张** `[u8;256]` 表（对每个 `i` 依次套两个公式），用一次 `apply_lut` 完成，说说相比分两次跑省在哪。
3. **溢出复现**：故意用 `wrapping_add(100)` 给渐变图加亮度，观察 release 构建下出现的"黑斑"，再换成 `saturating_add` 对比修复效果。
