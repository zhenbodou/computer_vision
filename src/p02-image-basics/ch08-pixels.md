# 第 8 章 访问和修改像素

> **本章导读**
> - 学完你能：用 `(x, y)` 坐标**读取**任意一个像素，**修改**它，并高效地**遍历整张图**。
> - 认清三种最常用的像素类型 `Rgb` / `Luma` / `Rgba`，明白它们内部其实就是一个定长小数组。
> - 亲手做一个经典效果：把一张图**反色**（负片），再在角落**画一个红色方块**。
> - 知道越界为什么会 panic，以及追求性能时怎么绕过逐像素接口直接操作缓冲区。

## 场景：从"负片"说起

老照片时代，胶卷冲洗出来的底片是"负片"——亮的地方变暗、暗的地方变亮、颜色也反过来。这个效果在数字图像里怎么做？

答案朴素得可爱：**把每个像素的每个颜色分量，都用 `255` 减一下**。红色分量 `200` 变成 `55`，`0` 变成 `255`……全图扫一遍就完事了。

这就引出了本章的核心技能——**逐像素地读和写**。别看它基础，机器视觉里大量操作的本质都是"遍历每个像素，按规则算个新值"：调亮度、二值化、抠某种颜色……全是这个套路。把这一章练熟，你就掌握了图像处理的"一招鲜"。

## 原理：像素住在一张网格上

### 坐标系：原点在左上角

上一章我们把图读成了 `RgbImage`（也就是 `ImageBuffer<Rgb<u8>, Vec<u8>>`）。它在逻辑上是一张 `宽 × 高` 的网格，每个格子住着一个像素。定位一个像素用 `(x, y)`：

```text
      x 方向 (列) →
   ┌───────────────────────┐
 y │ (0,0) (1,0) (2,0) ...  │   ← 原点在左上角
 方│ (0,1) (1,1) (2,1) ...  │
 向│ (0,2) ...              │   x ∈ [0, 宽)
 ↓ │  ...                   │   y ∈ [0, 高)
   └───────────────────────┘
```

> ⚠️ **注意**：**是 `(x, y)`，不是 `(行, 列)`。** 这里 `x` 是**列**（水平方向）、`y` 是**行**（垂直方向），原点在**左上角**、`y` 向**下**增大。很多人习惯了数学里"y 向上"或矩阵里"先行后列 `(row, col)`"，一到图像就写反，画出来的东西全乱套。记牢：**先 x 后 y，y 向下。**

### 读写单个像素

```rust
let px = *rgb.get_pixel(x, y);   // 返回 &Rgb<u8>，解引用得到值
rgb.put_pixel(x, y, Rgb([255, 0, 0]));  // 写入一个红色像素
```

`get_pixel(x, y)` 有个脾气：**坐标越界会直接 panic**（程序崩溃），而不是返回错误。如果你不确定坐标是否合法，用它的安全版本 `get_pixel_checked`，越界时返回 `None`：

```rust
match rgb.get_pixel_checked(x, y) {
    Some(px) => { /* 用 px */ }
    None => { /* 越界，跳过 */ }
}
```

### 像素类型：本质是个定长小数组

`image` 用不同的类型表示不同色彩：

| 类型 | 内部数据 | 含义 |
|------|---------|------|
| `Luma<u8>` | `[u8; 1]` | 灰度，1 个通道 |
| `Rgb<u8>` | `[u8; 3]` | 红、绿、蓝，3 个通道 |
| `Rgba<u8>` | `[u8; 4]` | RGB + 透明度（alpha），4 个通道 |

它们都是**元组结构体**，内部就是一个定长数组，你可以用 `.0` 拿到整个数组，也可以像数组一样用下标取某个通道：

```rust
let px = Rgb([200u8, 30, 30]);
let arr: [u8; 3] = px.0;   // 拿到内部数组 [200, 30, 30]
let r = px[0];             // 也可以直接索引：红分量 = 200
let g = px.0[1];           // 绿分量 = 30
```

### 遍历整张图：`enumerate_pixels`

一个一个 `get_pixel` 太啰嗦。要扫全图，用迭代器：

```rust
// 只读遍历：拿到坐标和像素引用
for (x, y, px) in rgb.enumerate_pixels() {
    // px 是 &Rgb<u8>
}

// 可变遍历：可以就地修改像素
for (x, y, px) in rgb.enumerate_pixels_mut() {
    px.0[0] = 255 - px.0[0];   // 修改红分量
}
```

`enumerate_pixels_mut()` 是做"反色""调色"这类整图操作的主力——它一次给你 `(x, y, &mut 像素)`，遍历顺序是**从左到右、从上到下**（先走完一行再下一行）。

## 动手写代码：反色 + 角落红方块

把上面的知识点串起来，做一个完整例子：合成一张渐变图 → 整体反色 → 在左上角画一个 40×40 的红色实心方块 → 存盘。

`Cargo.toml`：

```toml
[dependencies]
image = "0.25"
```

完整代码（`examples/ch08_pixels.rs`，`cargo run --example ch08_pixels`）：

```rust
use image::{GenericImageView, ImageBuffer, Rgb, RgbImage};

/// 合成一张彩色渐变图（和上一章一样，让示例自包含）
fn make_gradient(w: u32, h: u32) -> RgbImage {
    ImageBuffer::from_fn(w, h, |x, y| {
        let r = (x * 255 / (w - 1)) as u8;
        let g = (y * 255 / (h - 1)) as u8;
        Rgb([r, g, 128])
    })
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut img = make_gradient(200, 150);

    // ① 读单个像素：get_pixel 返回 &Rgb<u8>，解引用得到值
    let p = *img.get_pixel(0, 0);
    println!("(0,0) 的 RGB = {:?}", p.0); // p.0 是内部数组 [u8; 3]
    println!("红分量 = {}", p[0]);         // 也可以像数组一样索引

    // ② 越界安全读取：get_pixel_checked 返回 Option，不会 panic
    match img.get_pixel_checked(999, 999) {
        Some(px) => println!("{:?}", px),
        None => println!("(999,999) 越界，返回 None"),
    }

    // ③ 反色：遍历每个可变像素，新值 = 255 - 旧值
    for (_x, _y, px) in img.enumerate_pixels_mut() {
        px.0[0] = 255 - px.0[0];
        px.0[1] = 255 - px.0[1];
        px.0[2] = 255 - px.0[2];
    }

    // ④ 在左上角画一个 40x40 的红色实心方块（注意别越界）
    let side = 40u32;
    for y in 0..side.min(img.height()) {
        for x in 0..side.min(img.width()) {
            img.put_pixel(x, y, Rgb([255, 0, 0]));
        }
    }

    // ⑤ 底层缓冲区：as_raw 拿到 &Vec<u8>，长度 = 宽 x 高 x 通道数
    let raw: &Vec<u8> = img.as_raw();
    println!(
        "缓冲区长度 = {}，w*h*3 = {}",
        raw.len(),
        img.width() * img.height() * 3
    );

    img.save("out_ch08_result.png")?;
    Ok(())
}
```

运行后终端会打印（数字真实可复现）：

```text
(0,0) 的 RGB = [0, 0, 128]
红分量 = 0
(999,999) 越界，返回 None
缓冲区长度 = 90000，w*h*3 = 90000
```

打开 `out_ch08_result.png`，你会看到原本的渐变被"反"了过来（原来偏暗的左上现在偏亮），而左上角端端正正扣着一个红色方块。恭喜，你已经会"改图"了！

注意最后一行：`200 × 150 × 3 = 90000`——这正好印证了[第 5 章](../p01-start/ch05-what-is-an-image.md)说的"图像在内存里就是一长条按 `R,G,B,R,G,B…` 排列的字节"。`enumerate_pixels` 只是帮你把这条"面条"按坐标切成了一个个像素而已。

> 💡 **提示**：画方块其实有现成轮子。`imageproc` 提供了 `draw_filled_rect_mut`，一行就能画一个实心矩形（见 [第 8 章之后的绘制相关章节] 与 `imageproc::drawing`）。这里我们用手写双重循环，是为了让你看清"画方块"本质上就是"把一片区域的像素挨个 `put_pixel`"——理解了原理，用不用轮子都随你。

## 常见坑与提示

> 🕳️ **坑**：**`get_pixel` 越界会 panic，不是返回错误。** 循环里如果坐标算错（比如写成 `get_pixel(x+1, y)` 却没检查右边界），程序会直接崩在那一行。画东西、做卷积这类"要看邻居"的操作，一定先想清楚边界；拿不准就用 `get_pixel_checked`。上面例子里我们用 `side.min(img.width())` 来夹住范围，就是防越界的常规操作。

> ⚠️ **注意**：**`u8` 相加会溢出。** 反色用的是 `255 - old`，`old` 最大是 255，永远不会溢出，很安全。但如果你想"提亮"写成 `old + 50`，当 `old > 205` 时结果超过 255，在 debug 模式下会 **panic**、release 模式下会**回绕**成一个小值（变成黑点）。正确做法是用 `old.saturating_add(50)`（超过 255 就停在 255）。亮度、对比度这些"点运算"我们放到 [第 11 章](ch11-point-ops.md) 专门讲。

> 💡 **提示**：**性能——逐像素接口有代价。** `get_pixel`/`put_pixel` 每次调用都要做边界检查和坐标换算。处理小图无所谓，但对着 4K 大图跑几十遍就能感觉到。追求极致速度时，可以用 `as_raw()`（或可变版 `as_mut()`）直接拿到底层的 `Vec<u8>`，按 `下标 = (y * 宽 + x) * 通道数 + 通道` 手动索引，省掉每次的检查开销；再进一步还能用 `rayon` 把各行分给多个线程并行处理（[第 108 章](../p21-mastery/ch108-performance.md) 细讲）。入门阶段先用 `enumerate_pixels_mut` 把逻辑写对，性能等真遇到瓶颈再优化。

## 本章小结

- 像素用 `(x, y)` 定位：`x` 是列、`y` 是行，**原点在左上角、y 向下增大**。范围是 `x ∈ [0, 宽)`、`y ∈ [0, 高)`。
- `get_pixel(x, y)` 读、`put_pixel(x, y, px)` 写；`get_pixel` 越界会 **panic**，安全版 `get_pixel_checked` 越界返回 `None`。
- `Luma`/`Rgb`/`Rgba` 内部就是 `[u8; 1/3/4]` 的定长数组，用 `.0` 取数组、用 `[i]` 取单通道。
- 整图操作用 `enumerate_pixels()`（只读）/ `enumerate_pixels_mut()`（可改），顺序是从左到右、从上到下。
- 反色 = 每通道 `255 - 旧值`；注意 `u8` 加法可能溢出，提亮要用 `saturating_add`。
- 追求性能可用 `as_raw()` 直接操作底层缓冲区，绕过逐像素接口的检查开销。

## 动手练习

1. **跑通它**：运行本章例子，对照原渐变图与结果图，理解"反色"到底把哪些像素变成了什么。
2. **换个角**：把红方块从左上角改画到**右下角**（提示：`x` 从 `宽-40` 到 `宽`，`y` 从 `高-40` 到 `高`，小心别越界）。
3. **只反一个通道**：改成"只反红色通道，绿蓝不动"，看看图变成什么色调，体会通道的独立性。
4. **画个十字准星**：不借助任何绘制库，用 `put_pixel` 在图正中心画一条水平线和一条垂直线（一个"＋"字），线宽 1 像素、颜色自定。
