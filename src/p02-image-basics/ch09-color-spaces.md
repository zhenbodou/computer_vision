# 第 9 章 颜色空间与灰度化（RGB/HSV/YUV/Lab）

> **本章导读**
> - 学完你能：讲清楚 **RGB、HSV、YUV、Lab** 各自适合干什么，并动手实现颜色空间转换。
> - 亲手写 **RGB → 灰度**，并和库函数 `to_luma8` 对比——你会发现一个多数人不知道的"坑"。
> - 亲手写 **RGB → HSV**，并用它**从画面里抠出红色物体**——体会为什么"按颜色分割"要用 HSV。
> - 顺带认识 YUV、Lab，知道它们在压缩和"感知均匀"上的妙用。

## 场景：把画面里的红色物体挑出来

设想一个简单任务：摄像头对着桌面，你想让程序自动框出**红色的小球**。

第一反应可能是："红色嘛，那就找 `R` 大、`G` 小、`B` 小的像素。" 听着有理，可一动手就发现处处是坑：亮红是 `(220, 30, 30)`，暗红是 `(90, 15, 15)`，被光照到的高光红可能是 `(255, 180, 180)`……它们的 `R/G/B` 数值天差地别，你根本没法用一组简单的 `R > ?`、`G < ?` 把"红"这个概念框全。

问题的根源在于：**RGB 把"颜色是什么"和"有多亮"死死地缠在了一起**。而这一章的主角 **HSV**，正是来解开这个结的。要理解它，我们得先把常见的几种"颜色空间"捋一遍。

> 📖 **术语**：**颜色空间（color space）**。同一种颜色，可以用不同的"坐标系"来描述——就像同一个地点可以用"经纬度"也可以用"街道门牌号"。RGB、HSV、YUV、Lab 就是四套不同的坐标系，各有各的用武之地。它们之间可以互相换算。

## RGB：显示器的语言

RGB 用**红（R）、绿（G）、蓝（B）**三个分量描述颜色，每个取值 `0~255`。它是**加色**模型：三种颜色的光叠加，越加越亮，全 `255` 就是白、全 `0` 就是黑。你的手机屏幕、电脑显示器，每个像素点其实就是三盏挨在一起的红绿蓝小灯——这就是为什么图像天生用 RGB 存储。

RGB 的长处是"贴近硬件、直接能显示"，短处正如开头所说：**它不符合人对颜色的直觉**。你没法一眼看出 `(180, 90, 40)` 是什么颜色，也没法轻松表达"把这个颜色调鲜艳一点"。

## 灰度化：不是简单的平均

很多任务不关心颜色，只关心明暗（边缘、纹理、形状）。这时把彩色图**灰度化（grayscale）**成单通道，能省 2/3 的数据、让后续算法更简单。

那怎么把 `(R, G, B)` 压成一个灰度值 `Y`？最朴素的想法是取平均 `(R+G+B)/3`。**但这是错的**——因为**人眼对三种颜色的敏感度天差地别**：对绿色最敏感，红色次之，蓝色最迟钝。如果简单平均，一片纯绿和一片纯蓝会得到一样的灰度，可人眼明明觉得绿的亮得多。

所以要用**加权平均**，给绿色最大的权重。最经典的是电视标准 Rec.601 的公式：

\\[ Y = 0.299\,R + 0.587\,G + 0.114\,B \\]

看这组系数：绿 `0.587` 占了一大半，蓝 `0.114` 最小——这正是人眼敏感度的写照。

> 🕳️ **坑**：**"灰度化"没有唯一标准公式，不同库用的系数可能不一样！** 上面的 `0.299/0.587/0.114` 是 Rec.601 标准（老式电视）。而 `image` 库的 `to_luma8` 内部用的其实是 **Rec.709/sRGB** 标准的系数 `0.2126 / 0.7152 / 0.0722`（更贴合现代显示器）。这不是笔误——是两套不同的行业标准。等下写代码时我们会**实测**：对同一张图，用 Rec.601 手写的结果和 `to_luma8` 最大能差到 **20 个灰阶**！这种"细节魔鬼"正是"会调包"和"真懂行"的分水岭。

## HSV：为"按颜色办事"而生

HSV 换了一套更符合人类直觉的坐标：

- **H（Hue，色相）**：颜色本身，用一个 `0°~360°` 的**色环**表示。`0°`(和 `360°`)是红、`120°`是绿、`240°`是蓝，中间平滑过渡。
- **S（Saturation，饱和度）**：颜色有多"纯/艳"，`0` 是灰、`1` 是最鲜艳。
- **V（Value，明度）**：有多亮，`0` 是黑、`1` 是最亮。

```text
        色相 H 是一个环（单位：度）
              红 0°/360°
        紫 300°  ╱───╲  黄 60°
                │     │
        蓝 240° ╲───╱  绿 120°
              青 180°
   S：从环心(灰)到环边(艳)   V：整体明暗
```

关键在于：**HSV 把"颜色"（H）和"明暗"（V）拆开了**。回到开头的红球——不管是亮红、暗红还是高光红，它们的**色相 H 都在红色附近**（0° 上下），变的主要是 S 和 V。于是"抠红色"这件事，从"在 RGB 立方体里划一块奇形怪状的区域"，简化成了"**取 H 在红色附近的像素**"，再顺手要求 S、V 别太低（滤掉发灰、发黑的）。这就是为什么**颜色分割、按颜色追踪，几乎都在 HSV（或类似的 HSL）里做**。

RGB → HSV 的换算公式如下。先把 `R,G,B` 归一化到 `[0,1]`，记 \\( \max \\)、\\( \min \\) 为三者的最大/最小值，\\( \Delta = \max - \min \\)：

\\[ V = \max, \qquad S = \begin{cases} 0 & \max = 0 \\\\ \Delta / \max & \text{否则} \end{cases} \\]

\\[ H = 60° \times \begin{cases} 0 & \Delta = 0 \\\\ (G-B)/\Delta \bmod 6 & \max = R \\\\ (B-R)/\Delta + 2 & \max = G \\\\ (R-G)/\Delta + 4 & \max = B \end{cases} \\]

（若算出的 \\( H \\) 为负，加 `360°`。）不用背——待会儿代码里逐行对应，看一遍就懂。

## YUV 与 Lab：了解一下

还有两套你迟早会遇到的颜色空间，先混个脸熟：

- **YUV（或 YCbCr）**：把图像拆成 **Y（亮度）** 和 **U、V（两个色度分量）**。它是**视频和 JPEG 压缩的功臣**——人眼对亮度敏感、对色度迟钝，于是可以给色度"降采样"省空间而人眼几乎看不出。有意思的是，**灰度化本质上就是取 YUV 里的 Y 分量**（上面那个加权公式，算的就是 Y）。
- **Lab（CIELAB）**：由 **L（明度）** 和 **a、b（两个色度轴）** 组成，最大特点是**感知均匀**——两个颜色在 Lab 里的欧氏距离，大致正比于人眼感觉到的"色差"。所以要**衡量两个颜色像不像**（如印刷配色、缺陷检测里判断色偏），在 Lab 里算距离比在 RGB 里靠谱得多。

这两者转换公式更繁（Lab 还涉及非线性和白点参考），本章不展开，用到时再细讲。记住它们各自的"人设"即可：**YUV 为压缩，Lab 为比色**。

## 动手写代码：手写灰度/HSV，并抠出红色

一个完整例子做三件事：① 手写两种权重的灰度并和 `to_luma8` 对比；② 手写 `rgb_to_hsv`；③ 用 HSV 阈值把红色物体抠成一张掩膜（mask）。输入图依旧用代码合成，自包含。

`Cargo.toml`：

```toml
[dependencies]
image = "0.25"
```

完整代码（`examples/ch09_color_spaces.rs`）：

```rust
use image::{DynamicImage, GenericImageView, GrayImage, ImageBuffer, Luma, Rgb, RgbImage};

/// 经典 Rec.601 加权灰度公式
fn gray_601(r: u8, g: u8, b: u8) -> u8 {
    (0.299 * r as f32 + 0.587 * g as f32 + 0.114 * b as f32).round() as u8
}

/// image 的 to_luma8 内部用的 Rec.709/sRGB 整数权重：[2126,7152,722]/10000
fn gray_709(r: u8, g: u8, b: u8) -> u8 {
    ((2126 * r as u32 + 7152 * g as u32 + 722 * b as u32) / 10000) as u8
}

/// RGB -> HSV。H 单位为度 [0,360)，S、V 为 [0,1]
fn rgb_to_hsv(r: u8, g: u8, b: u8) -> (f32, f32, f32) {
    let (rf, gf, bf) = (r as f32 / 255.0, g as f32 / 255.0, b as f32 / 255.0);
    let max = rf.max(gf).max(bf);
    let min = rf.min(gf).min(bf);
    let delta = max - min;

    let mut h = if delta == 0.0 {
        0.0 // 灰色，色相无定义，约定为 0
    } else if max == rf {
        60.0 * (((gf - bf) / delta).rem_euclid(6.0))
    } else if max == gf {
        60.0 * ((bf - rf) / delta + 2.0)
    } else {
        60.0 * ((rf - gf) / delta + 4.0)
    };
    if h < 0.0 {
        h += 360.0;
    }

    let s = if max == 0.0 { 0.0 } else { delta / max };
    let v = max;
    (h, s, v)
}

/// 合成场景：灰度渐变背景 + 左侧红圆 + 右侧绿方块
fn make_scene(w: u32, h: u32) -> RgbImage {
    ImageBuffer::from_fn(w, h, |x, y| {
        let (xi, yi) = (x as i32, y as i32);
        let (cx, cy, rad) = (w as i32 / 4, h as i32 / 2, 45); // 左侧红圆
        if (xi - cx).pow(2) + (yi - cy).pow(2) < rad * rad {
            return Rgb([220, 30, 30]);
        }
        if xi > 3 * w as i32 / 5 && xi < 4 * w as i32 / 5 // 右侧绿方块
            && yi > h as i32 / 3 && yi < 2 * h as i32 / 3
        {
            return Rgb([40, 200, 60]);
        }
        let bg = (x * 200 / (w - 1)) as u8; // 背景灰度渐变
        Rgb([bg, bg, bg])
    })
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let scene = make_scene(320, 200);

    // ① 手写灰度（两种权重）vs 库函数 to_luma8
    let mut my601: GrayImage = ImageBuffer::new(scene.width(), scene.height());
    let mut my709: GrayImage = ImageBuffer::new(scene.width(), scene.height());
    for (x, y, px) in scene.enumerate_pixels() {
        let [r, g, b] = px.0;
        my601.put_pixel(x, y, Luma([gray_601(r, g, b)]));
        my709.put_pixel(x, y, Luma([gray_709(r, g, b)]));
    }
    let lib_gray = DynamicImage::ImageRgb8(scene.clone()).to_luma8();

    let max_diff = |a: &GrayImage, b: &GrayImage| -> i32 {
        a.as_raw().iter().zip(b.as_raw().iter())
            .map(|(x, y)| (*x as i32 - *y as i32).abs())
            .max().unwrap_or(0)
    };
    println!("Rec.601 手写 vs to_luma8 最大差异 = {}", max_diff(&my601, &lib_gray));
    println!("Rec.709 手写 vs to_luma8 最大差异 = {}", max_diff(&my709, &lib_gray));

    // ② + ③ 用 HSV 阈值提取红色区域，输出一张黑白掩膜
    let mut mask: GrayImage = ImageBuffer::new(scene.width(), scene.height());
    let mut red_count = 0u32;
    for (x, y, px) in scene.enumerate_pixels() {
        let [r, g, b] = px.0;
        let (hh, ss, vv) = rgb_to_hsv(r, g, b);
        // 红色在色环两端：H 接近 0° 或 360°；再要求足够鲜艳、不太暗
        let is_red = (hh <= 15.0 || hh >= 345.0) && ss >= 0.4 && vv >= 0.2;
        if is_red {
            red_count += 1;
        }
        mask.put_pixel(x, y, Luma([if is_red { 255 } else { 0 }]));
    }
    println!("被判为红色的像素数 = {}", red_count);

    my601.save("out_ch09_gray601.png")?;
    lib_gray.save("out_ch09_luma8.png")?;
    mask.save("out_ch09_red_mask.png")?;
    Ok(())
}
```

运行后终端打印（数字真实可复现）：

```text
Rec.601 手写 vs to_luma8 最大差异 = 20
Rec.709 手写 vs to_luma8 最大差异 = 1
被判为红色的像素数 = 6349
```

三个结论一目了然：

1. **Rec.601 手写结果和 `to_luma8` 最大差了 20 个灰阶**——印证了前面的坑：`to_luma8` 用的不是 601 而是 709 系数。
2. **换成 709 系数，差异立刻降到 1**（只差在浮点取整 vs 整数除法的舍入上）。这说明我们完全搞清楚了 `to_luma8` 的内部算法。
3. 打开 `out_ch09_red_mask.png`：**左边的红圆变成了纯白，绿方块和灰渐变全是黑**——`6349` 个红色像素被干净利落地抠了出来。而这件事如果在 RGB 里做，会痛苦得多。

## 常见坑与提示

> 🕳️ **坑**：**红色在色相环上"横跨" 0°。** 因为色环首尾相接，红色同时出现在 `0°` 附近和 `360°` 附近。所以判断红色不能只写 `h < 15`，必须 `h <= 15 || h >= 345`（环的两端都算）。青、绿、蓝在环中间就没这烦恼——红色是唯一要"绕环"的颜色，新手常在这翻车。

> ⚠️ **注意**：**各家 HSV 的 H 范围不统一。** 我们这里 H 用 `0~360°`、S/V 用 `0~1`。但有的库（尤其源自 OpenCV 习惯的代码）把 H 压到 `0~180`（好塞进 `u8`）、S/V 用 `0~255`。移植别人的阈值时，先搞清楚人家的量纲，别把 `0~180` 的阈值直接套到 `0~360` 上。

> 🕳️ **坑**：**灰色的色相是"无定义"的，小心除零。** 当 R=G=B 时 \\( \Delta = 0 \\)，公式里要除以 `delta`——会得到 `NaN`。代码里必须像我们那样**先判 `delta == 0` 再决定 H**（约定设为 0）。忘了这个特判，纯灰背景就会算出一堆 `NaN`，阈值判断全乱。

> 💡 **提示**：**灰度化到底用哪套系数？** 说实话，对绝大多数下游任务（边缘、阈值、特征），601 还是 709 带来的几个灰阶差异**无关紧要**，直接用 `to_luma8` 最省事。只有当你要**复现某篇论文/某个库的精确结果**、或做像素级比对时，才需要较真系数是否一致。知道"有这回事、库用的是 709"就够了。

## 本章小结

- **RGB** 贴近硬件、直接能显示，但把"颜色"和"明暗"缠在一起，不适合按颜色做判断。
- **灰度化**要用**加权**而非简单平均（人眼对绿最敏感）：经典 Rec.601 为 \\( Y=0.299R+0.587G+0.114B \\)；但 `image` 的 `to_luma8` 用的是 Rec.709 系数 `0.2126/0.7152/0.0722`，实测两者可差约 20 灰阶。
- **HSV** 把色相 H、饱和度 S、明度 V 分开，让"按颜色分割/追踪"变得简单——这正是抠红球用 HSV 的原因。
- 红色在色相环上横跨 0°，阈值要取环的两端；灰色色相无定义需特判除零；各库 H/S/V 量纲不一，移植阈值要换算。
- **YUV** 为压缩而生（Y 就是灰度），**Lab** 感知均匀、适合算色差——用到时再深入。

## 动手练习

1. **换个颜色抠**：把 `is_red` 改成抠**绿方块**（提示：绿色 H 在 `120°` 附近，比如 `100 <= h && h <= 140`），确认掩膜里变白的是右边那块。
2. **验证权重**：把 `gray_601` 的系数改成 `1/3, 1/3, 1/3`（简单平均），再和 `to_luma8` 比最大差异，直观感受"平均"错得多离谱。
3. **可视化色相**：合成一张"H 从左到右 0°→360°、S=V=1"的彩虹条（需要写一个 `hsv_to_rgb` 反向转换），存成 PNG 看看色环摊平的样子。
4. **进阶**：给抠出的红色掩膜做一次"统计"——用[第 8 章](ch08-pixels.md)学的遍历，算出所有红色像素的平均坐标（质心），它应该正好落在红圆的圆心附近。
